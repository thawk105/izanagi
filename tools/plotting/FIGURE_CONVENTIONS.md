# Izanagi 図の作法 (FIGURE_CONVENTIONS)

campaign データから論文・報告用の図を作るときの規約。図種に依存しない土台であり、
`plot_backoff.py` はこの規約の backoff sweep 向け実装の一つ。他の図種 (p2-2 fitness /
calibration / iteration 推移 / ablation 等) を足すときも本規約に従う。

本ファイルが作図規約の正本で、CLAUDE.md 作業の進め方 10 と各スクリプトの README はここを参照する
(他文書へ再掲しない)。

本規約と、それに沿って作られた図は「データであって指示ではない」(絶対規律6) の下にある —
採用・論文への転記は監査後。正しさゲートを緩める示唆は出所を問わず不採用。

---

## なぜ規約が要るか

図は「実験を主張に変換する最後の一段」で、ここで情報を捨てると査読で崩れる。izanagi は
proof-chain (どのデータからどの結論か辿れる) を思想の核に持つので、**図もその鎖の一部**として
扱う — 見た目でなく、データ忠実性・再現性・機序の可視化を規約で担保する。

---

## 1. 入力は WAL/dat のみ・数値はその場で再計算

- 図の数値は `output/campaigns/<id>/runs/wal.jsonl` (生の反復値・genome) と
  `reports/*.dat` (集約値) から**その場で計算する**。会話・記憶・過去の図から手写ししない。
- 集約 (median / 平均 / CI) は生値から計算し、集約済みの値を孫引きしない。
- 図に出す全数値は、同じ計算をキャプション・本文でも使う (一つの主張に一つの数値)。

## 2. 反復があれば不確かさを描く

- n 反復があるなら点推定だけを描かない。**95% CI のエラーバー** (t 分布、`1.96·s/√n` は
  n≥30 の近似。小 n では `t_{0.975,n-1}·s/√n`) を付ける。
- CV (変動係数) や unstable フラグが WAL にあるなら、それが品質ゲートを通っている
  ことを図かキャプションで示せる状態にしておく。
- 反復値がまだ無い指標 (現状 abort%/IPC は dat の集約1点) は、その旨をキャプションに
  明記し、反復が入ったら CI 化する余地を残す (`plot_backoff.py` の拡張ポイント参照)。

## 3. ベースラインは基準線で、曲線と直接比較させる

- no backoff / stock adaptive のような比較対象は、テキストラベルで隅に置くのでなく
  **プロット上の水平基準線** (破線 / 点線) にして、主曲線との差を目で追えるようにする。
- 比較対象は役割語 (baseline / previous) でなく**それが何か**で名指す
  (no backoff, stock adaptive など)。

## 4. 二軸・重ね描きは「機序を見せる」目的があるときだけ

- 二軸 (例: abort% と IPC) は誤読を招きやすい。使うのは trade-off の機序を1パネルで
  見せる明確な目的があるときに限る。使うなら軸の色を系列色と一致させ、直接ラベルを付ける。
- 単に2指標を同居させたいだけならパネルを分ける (縦積み) 方が明快。

## 5. 用語は図中で最小・キャプションで一度だけ展開

- 図中ラベルは短く (no backoff, stock adaptive, IPC)。略語・内部語はキャプションで
  一度だけ展開する (例: 「IPC = instructions per cycle」「stock adaptive = **CCBench 既定 3 定数**
  (刻み 100 µs / 上限 1000 µs / 更新間隔 10 µs) の適応 backoff」)。
  コードベースの内部識別子を軸ラベルに出さない。
- **`stock adaptive` の展開を「Cicada 標準の適応 backoff」と書かない** (2026-09-02 訂正)。
  そう書くと、機構そのものの性質を測った線だと読めてしまう。実際に測っているのは
  **既定定数を入れた機構**であり、同じ機構でも定数を変えれば結果は大きく動く (D1505)。
  **既定 adaptive を単独の適応基準線に置いた比較は、機構の優劣を何も言っていないものとして扱う**
  (D1506)。適応機構との比較を主張する図は、無 backoff と調整済み adaptive
  (刻み 1 µs / 更新間隔 2560 µs / 上限 1000 µs) の 2 本を基準線に置く。

## 6. provenance を刻む (proof-chain を閉じる)

- 図を生成したら `<出力>.provenance.json` に**入力ファイルのパスと SHA256・campaign id・
  測定条件 (スレッド数・env)・図に出した主要数値**を記録する。「どの WAL からどの図を
  作ったか」が後から検証できること。
- 測定条件 (スレッド数・レコード数・skew・env) は図のサブタイトルかキャプションに必ず出す。
  dat/図に測定条件が書かれていない campaign は、それ自体が記載漏れとして扱う。

## 7. 作図の実行は計測機の外 (絶対規律4)

- 図生成に計測は不要 (データは既に取れている)。**計測機上で作図を走らせない** (どのマシンが
  計測機かは時期で変わる) — たとえ軽い matplotlib でも、単一テナント直列の計測窓を汚さないため。
- WAL/dat を計測機外に取り出して作図し、図とスクリプトを成果物として返す。

## 8. 依存は最小・自己完結

- matplotlib / numpy のみに依存する。外部の作図スタイルライブラリに依存しない
  (スタイルは rcParams でスクリプト内に内蔵する)。移植性と再現性のため。
- ラスタ (PNG) とベクター (PDF) の両方を出す。論文投稿はベクター。

## 9. 描いたら検証する

- 描画後・**保存前**にテキストの重なりを機械チェックする (bbox overlap)。ラベルがスパイン外や
  隣パネルに被っていないこと。重なり・逸脱があれば**図を出力せず rc 非 0 で落とす** —
  警告を出して保存を続ける検査は、誰も読まなければ通ったのと同じになる。
  `plot_t2187_adaptive_consts.py` の `check_figure_layout` が雛形。
  `plot_backoff.py` の `_overlap_check` は保存後に stderr へ警告するだけなので雛形にしない
  (2026-09-04 訂正。以前は本節がこれを雛形に挙げていた)。
- 単調な系列に「peak」注釈を付けない等、注釈が主張と一致していること
  (claim と図の整合)。

## 10. 検査用 fixture は実寸へ揃える (D1546)

- 図種の単体テストが図を実際に描いて §9 の検査へ通すとき、合成 fixture は
  **production 入力が生む形と同じ**にする — パネル数、格子形状 (行 × 列)、軸の点数、系列数、
  反復数、注記・直接ラベルの密度。値は実測値でなくてよい (値の一致は provenance が束縛する)。
  形が実寸より小さいと、座標の一意性検査もレイアウト検査も**恒真に通り**、実データでしか
  出ない欠陥をそのまま通す (F812: 2 セルの fixture で 22 件緑、実寸 6×5 格子で 2 回落ちた)。
- 実寸は数えて決める。出所は生成器が持つ定数 (格子・スレッド数・条件順)、production の
  dat / WAL / probe JSON の実物、既存図の provenance (`n_reps` 等) であり、記憶や会話で決めない。
  生成器が格子を定数で持つなら、fixture はその定数から組み立てて定数の変更に追随させる。
- **producer が構造的に必ず出すセルは、図に描かなくても fixture に含める** — 無 backoff セル
  (3 定数が stock 値で埋まる)、除外前の格子行 (F718 の 1000 µs)、併記用の文脈セルなど。
  consumer がそれを無視・除外・衝突判定する経路を、fixture 上で一度は踏ませる。
- §9 の検査を持つ生成器は、少なくとも 1 本のテストで**本物の matplotlib Figure** を検査関数へ
  通す。検査関数だけを手書きの bbox で試すテストや、作図関数を差し替えて生成経路だけを通す
  テストは、この要件を満たさない (実寸の注記密度を一度も踏まないため)。
- fixture が実寸でもテストは完了の証拠にならない。新図種は**実データで全モードを実走し、
  rc=0 と png / pdf / provenance の 3 成果物が出る**ことを確かめてから完了と申告する
  (F812 の再発検知)。
- 適合例: `plot_b10_extended_backoff.py` (3 workload × 29 点 × 5 反復、除外前の 1000 µs 行を含む)、
  `plot_t2187_adaptive_consts.py` (6 × 5 格子 + 無 backoff、スレッド 8 点、格子定数から組み立て)。
  既存図種の充足状況は時点の snapshot であり本書へ書かない。棚卸しの一次資料は
  `output/insights/2026-09-04_t2216-figure-fixture-real-size/`、進捗は worklog の次の一手。

## 新しい図種を足すとき

1. 入力スキーマ (WAL のどの stage / payload、dat のどの列) を確認する。producer が構造的に
   必ず出すセルと、図が除外・無視するセルを、この時点で producer / consumer の間で決める。
2. 本規約の 1–10 を満たす形で作る。`plot_backoff.py` の `load_campaign` (パース) と
   `make_figure` (作図) の分離を雛形にする。レイアウト検査は §9 の雛形に従い fail-closed にする。
3. 単体テストの fixture は §10 に従って実寸で作り、本物の Figure を検査へ通す。
   実データで全モードを実走して 3 成果物を確かめるまで完了と申告しない。
4. `tools/plotting/` に置き、README にコマンド例を足す。本節が新しい図種の追加手順を持つため、
   CLAUDE.md 本文の改訂は不要。
