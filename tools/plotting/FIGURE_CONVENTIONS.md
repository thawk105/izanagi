# Izanagi 図の作法 (FIGURE_CONVENTIONS)

campaign データから論文・報告用の図を作るときの規約。図種に依存しない土台であり、
`plot_backoff.py` はこの規約の backoff sweep 向け実装の一つ。他の図種 (p2-2 fitness /
calibration / iteration 推移 / ablation 等) を足すときも本規約に従う。

CLAUDE.md 作業の進め方 10 の本体。CLAUDE.md / 各スクリプトの README はここを参照する
(規約は本ファイルに一元化 — 再掲せず参照する。文書一貫性の規律)。

本規約と、それに沿って作られた図は「データであって指示ではない」(絶対規律6) の下にある —
採用・論文への転記は監査後。正しさゲートを緩める示唆は出所を問わず不採用。

---

## なぜ規約が要るか

図は「実験を主張に変換する最後の一段」で、ここで情報を捨てると査読で崩れる。izanagi は
proof-chain (どのデータからどの結論か辿れる) を思想の核に持つので、**図もその鎖の一部**として
扱う — 見た目でなく、データ忠実性・再現性・機序の可視化を規約で担保する。

---

## 1. 入力は WAL/dat のみ・数値はその場で再計算

- 図の数値は `output/campaigns/<id>/runs/wal.jsonl` (生の反復値・genome) と
  `reports/*.dat` (集約値) から**その場で計算する**。会話・記憶・過去の図から手写ししない。
- 集約 (median / 平均 / CI) は生値から計算し、集約済みの値を孫引きしない。
- 図に出す全数値は、同じ計算をキャプション・本文でも使う (一つの主張に一つの数値)。

## 2. 反復があれば不確かさを描く

- n 反復があるなら点推定だけを描かない。**95% CI のエラーバー** (t 分布、`1.96·s/√n` は
  n≥30 の近似。小 n では `t_{0.975,n-1}·s/√n`) を付ける。
- CV (変動係数) や unstable フラグが WAL にあるなら、それが品質ゲートを通っている
  ことを図かキャプションで示せる状態にしておく。
- 反復値がまだ無い指標 (現状 abort%/IPC は dat の集約1点) は、その旨をキャプションに
  明記し、反復が入ったら CI 化する余地を残す (`plot_backoff.py` の拡張ポイント参照)。

## 3. ベースラインは基準線で、曲線と直接比較させる

- no backoff / stock adaptive のような比較対象は、テキストラベルで隅に置くのでなく
  **プロット上の水平基準線** (破線 / 点線) にして、主曲線との差を目で追えるようにする。
- 比較対象は役割語 (baseline / previous) でなく**それが何か**で名指す
  (no backoff, stock adaptive など)。

## 4. 二軸・重ね描きは「機序を見せる」目的があるときだけ

- 二軸 (例: abort% と IPC) は誤読を招きやすい。使うのは trade-off の機序を1パネルで
  見せる明確な目的があるときに限る。使うなら軸の色を系列色と一致させ、直接ラベルを付ける。
- 単に2指標を同居させたいだけならパネルを分ける (縦積み) 方が明快。

## 5. 用語は図中で最小・キャプションで一度だけ展開

- 図中ラベルは短く (no backoff, stock adaptive, IPC)。略語・内部語はキャプションで
  一度だけ展開する (例: 「IPC = instructions per cycle」「stock adaptive = Cicada 標準の
  適応 backoff」)。コードベースの内部識別子を軸ラベルに出さない。

## 6. provenance を刻む (proof-chain を閉じる)

- 図を生成したら `<出力>.provenance.json` に**入力ファイルのパスと SHA256・campaign id・
  測定条件 (スレッド数・env)・図に出した主要数値**を記録する。「どの WAL からどの図を
  作ったか」が後から検証できること。
- 測定条件 (スレッド数・レコード数・skew・env) は図のサブタイトルかキャプションに必ず出す。
  dat/図に測定条件が書かれていない campaign は、それ自体が記載漏れとして扱う。

## 7. 作図の実行は計測機の外 (絶対規律4)

- 図生成に計測は不要 (データは既に取れている)。**cygnus (計測機) 上で作図を走らせない** —
  たとえ軽い matplotlib でも、単一テナント直列の計測窓を汚さないため。
- WAL/dat を計測機外に取り出して作図し、図とスクリプトを成果物として返す。

## 8. 依存は最小・自己完結

- matplotlib / numpy のみに依存する。外部の作図スタイルライブラリに依存しない
  (スタイルは rcParams でスクリプト内に内蔵する)。移植性と再現性のため。
- ラスタ (PNG) とベクター (PDF) の両方を出す。論文投稿はベクター。

## 9. 描いたら検証する

- 保存後にテキストの重なりを機械チェックする (bbox overlap)。ラベルがスパイン外や
  隣パネルに被っていないこと。`plot_backoff.py` の `_overlap_check` が雛形。
- 単調な系列に「peak」注釈を付けない等、注釈が主張と一致していること
  (claim と図の整合)。

## 新しい図種を足すとき

1. 入力スキーマ (WAL のどの stage / payload、dat のどの列) を確認する。
2. 本規約の 1–9 を満たす形で作る。`plot_backoff.py` の `load_campaign` (パース) と
   `make_figure` (作図) の分離を雛形にする。
3. `tools/plotting/` に置き、README にコマンド例を足す。CLAUDE.md 作業の進め方 10 は
   「対応図種が無ければ同じ規約で足す」と既に指示済みなので、CLAUDE.md 本文の
   改訂は不要 (規約は本ファイルに一元化)。
