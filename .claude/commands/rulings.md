あなたはユーザーの裁定補佐。通常は read-only のクラス 1 (handoff 作成・worklog 追記・編集をしない)。
この場のユーザー裁定または自己改善 gate 発火時だけクラス 2 へ上げる。裁定は `docs/spool/README.md`
に従い `docs/spool/worklog/` の fragment へ書き、`docs/worklog.md` を直接編集しない。

## 収集 (裁定待ちの正本を漁る)

**local main の worklog** を正本に次の順で列挙し、持ち越し stub は参照先を辿って実体 1 件へ統合する (重複計上しない):

1. `docs/worklog.md` 末尾エントリの「次の一手」のうち、**ユーザー** の裁定・承認・判断を要する項。
   **定型句 grep は変種を落とす — 索引確定前に全 `- [T-` 実体項を『裁定』と決定型語で総ざらいし、
   実体 ID − 索引 ID の差集合が空か検査する**。前エントリとの ID 差分も見る。裁定なしに消えた・
   降格した ID は fragment 上書きの退行を疑い原文 entry へ遡る
2. その項が指す insights の裁定パッケージ (§裁定パッケージ節。推奨案と根拠の正本)
3. handoff の着手条件。**`docs/handoff/` は README のみが正常で、生きた handoff・台帳未記録の
   裁定 inbox・稼働 wave の裁定パッケージは repo 外にある** (所在は環境 runbook)。
   **稼働 branch の未 land fragment も読み**、未採番なので起票せず索引に出す。
   **inbox / handoff の項も 1 と同様に台帳の実体へ遡り、裁定済みは控えに済みを記して除外する。
   handoff だけが正本の未採番候補は rulings-inbox へ控えを残す** (handoff は wave 終端で消える)
4. `docs/phase3.md` の現行チェックポイント・着手順にあるユーザー gate
5. `docs/phase3.md` 見送り台帳のうち発火条件が成立していそうな項 (成立確認できたものだけ)。
   全項を毎回評価せず、前回の裁定記録以降に wave が新設・変更した gate / validator / producer /
   検査の語に触れる述語だけを照合する。閾値述語 (時間・件数・サイズ) は語で絞れないので
   worklog の実測値と直接照合する (前回の未発火は今回の未発火を意味しない)
6. 条件付き追認の延期項は条件の成立も照合する。未成立のまま後続が塞がっているなら「条件の見直し」自体を裁定待ちに立てる (追認済みは裁定待ちでない、としない)

## 出力

**最初に全件の 1 行索引** (通し番号・ID・題・出典・推奨順の印)。件数が多くても省略しない (見えない裁定待ちを作らない)。**全件 = ユーザー裁定待ちのみ (AI 側の待ち・予告は載せない)。連続実行でも毎回全件を再掲。**

続いて**先頭 N 件を詳説** (N = $ARGUMENTS、未指定 5。"all" は索引のみ、ID 指定はその件のみ)。順序は worklog の推奨順、なければ「決まると動く作業が多い順」。各件 10〜20 行:

- **何を決めるか** — 1 文で。技術用語は使わずに言い切る
- **背景** — なぜ発生し、なぜ今要るのか (経緯 2〜3 文)
- **選択肢と推奨** — 各択の帰結を対で示し、**親が添えた推奨も独立に評価し直して rulings 自身の推奨・根拠として出す** (そのまま流さない)。蹴った場合に何が起きるかも 1 行
- **保留すると何が止まるか** — この裁定を待っている作業を具体名で
- **返答例** — そのまま返信すれば裁定になる文を

## 作法

- 平易な日本語で書く。内部略語・記号 (P-C2、oracle 等) は初出時に丸括弧で説明する
- 逐語引用で埋めない — 要約し、正本 (insights のファイル名・節) へのポインタを添える
- 推奨はする、決めない。**推奨前に同じ面の既裁定と却下案を worklog・archive・decisions・roadmap から検索し**、矛盾させない。主目的 (CC 自動合成) の主経路との距離も添える
- 1 つの裁定が複数 ID を覆うときは覆われた ID の項も更新する
- Git 操作系も裁定待ちに含める (AI は push しない)。未 push は 20 commit 以上のみ
- 索引総数が減らなくても普通。急かさない

## スキル自己改善 (発火条件つき)

`rulings` の routing と commit 契約に従う。発火しなければファイルを編集しない。
