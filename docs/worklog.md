# Izanagi 作業ログ (worklog)

セッションごとの進捗を時系列で記録する。git 履歴や各正本に入らない協議・異常・持ち越しを束ねる
「作業の索引」であり、commit 内容の再説明はしない。役割分担:

- 設計判断と却下案 → `docs/decisions.md`
- CCBench の構造的事実 → `docs/ccbench-anatomy.md`
- CCBench のバグ等の知見 → `output/insights/`
- タスク分解 → `docs/phaseN.md`
- **このファイル = それらを束ねる日誌 (各セッションの索引)**

## 新規エントリの書式 (D35)

過去エントリは凍結し、次の規約は新規エントリに適用する。

**新規エントリはこのファイルへ直接書かない。** `docs/spool/worklog/` へ fragment として書き、
land が lock 内で fold して本ファイルへ追記する (fragment 文法と fold producer 契約の正本は
`docs/spool/README.md`、**描画済み worklog の読み方と carry 書式の正本は本節**)。
エントリ番号・日付・carry 行 `- [T-NNN] (N)` の N・ローテーションはすべて fold が付ける。
以下の書式規約は、fold が生成する結果と、fragment に書く本文の両方に適用される。

- 本文化するのは、ユーザー承認・協議の決着、棄却 finding (refuted)、未コミット事象・セッション異常と
  救出、エージェント工数、人間判断待ち・持ち越し、次の一手など **git に入り得ない情報だけ**
- commit は「hash + 件名 (+ 位置づけ 1 行)」まで。連続群は「先頭..末尾 (N 本)」で表し、内容を再掲しない
- 監査の finding 全文と裁定は insight / audit JSON に凍結する。worklog はレンズ数、real/refuted 数、
  最重要 1〜3 件、一次資料ポインタの 10〜15 行に留める
- 論文素材になる段落は行頭に「素材:」を付ける。持ち越しは逐語再掲せず carry 行 `- [T-NNN] (N)`
  とする。N は**行内に明示された参照先エントリ番号**であり、実体本文は N を遡って読む。
  fold は、最初の fragment では現行 worklog の末尾エントリ番号を、同一 fold 内の後続 fragment では
  直前に生成したエントリ番号を入れる。**新エントリ番号 - 1 や全履歴の最大値から導出してはならない**
  (エントリ番号には欠番も非単調も起こりうる)。過去エントリの `- [T-NNN] 変わらず ((N) 参照)` は
  凍結した旧書式であり、fold は引き続き解決する
- docs(worklog) だけの commit は prose の body を付けず、件名 + 必須 trailer だけにする

### 次の一手の ID 規約 (D70)

「次の一手」の項目が黙って落ちる経路を塞ぐため、各項目に安定 ID を付け、`tools/check_docs.py` が
保存則を機械検査する。ID は角括弧で囲んだ `T-` + 連番で、**表記は 1 つに正規化する** —
1〜999 は 3 桁ゼロ埋め、1000 以上は先頭ゼロなしで書く。冗長なゼロ埋め (4 桁で 1 を表す等) は
同じ数値の二表記になるため**不正形式として赤にする**。

- **位置**: トップレベル list item (インデント無しの `1. ` または `- `) の**先頭**に置く。
  インデントされた子項目は原子として扱わない — **1 原子 = 1 トップレベル項目 = 1 ID** に平坦化する
  (子項目 `(a)(b)(c)` に原子を詰めると、その分は機械検査の網から外れる)
- **採番**: 現行 worklog (「ローテーション」節より後) + `docs/archive/worklog-*.md` + 見送り台帳に
  現存する有効 ID の最大値 + 1。並行セッションは番号を予約したとみなさず、統合直前に再走査して
  未統合側を振り直す (`landed` = main へ統合された時点)
- **不変性**: 一度 land した ID は変更・再利用しない
- **保存則 (機械検査)**: あるエントリの「次の一手」に現れた ID は、後続エントリのトップレベル項目
  (消化または継続) か、見送り台帳のトップレベル項目 (理由付き見送り) に現れなければ赤になる。
  ローテーション境界 (アーカイブ最新の末尾エントリ → 現行の先頭エントリ) も検査対象
- **この節と決定記録には有効 ID を書かない** (採番母集団と sink の自己汚染を避けるため、
  例示は `T-NNN` のようなプレースホルダで書く)

## ローテーション

知らせる) に、過去分を `docs/archive/worklog-<範囲>.md` へ**移動**し、現行ファイルを軽く保つ
(ブート時に読むのは末尾エントリのみ、の運用を軽く保つため。2026-07-05 導入、D35)。
アーカイブは凍結 (訂正注記のみ追記可)。既存アーカイブの一覧は `docs/archive/README.md`。

## 2026-08-19 (685) — 8c 条件 C03 / C08 の consumer と freeze-wide 事前割当 attempt registry を実装した — 親の裁定 1 件が成立不能と実装子に反証された (コード + テスト、branch worktree-dev-wave-t1353-c03-c08)

[T-1353] と 8c 条件 C03 / C08 を 1 wave で実装した。設計判断は D550、
段 6 で表面化した失敗型は F412 と F413。

**起動時の重複検査。** 引数の指示どおり `trial_registry.py` を触る稼働 wave を調べた。t822 は
land 済み (エントリ 656) で二重着手は無い。稼働中の t1333 が
`test_trial_registry.py` と `test_s8c_preregistration_predicates.py` を 12 行だけ触るが、
production 面の重複は無い。

**親の実測が引数の前提を 1 件訂正した。** 引数は「評価器を登録する」「契約 JSON の
machine_checkable 反転はしない」を同時に求めたが、`PredicateRegistry.evaluate_all` は
`machine_checkable` が真のときしか `_MACHINE_EVALUATORS` を引かない。さらに
`test_machine_checkable_contract_and_evaluator_registry_are_bijective` と
`test_satisfiable_predicate_requires_negative_control` が両者の exact 一致を pin している。
登録だけを行えば機械的に赤になる。よって評価器は `_evaluate_undefined` から委譲して live に結線し、
反転と凍結世代の発行は後続 wave へ残した。

**親の裁定が 1 件、実装子に反証された。** 段 6 で親は
「`prereg_content_commit` を manifest の `prereg_commit` と等値で束縛せよ」と裁定したが、
これは成立しない。`manifest.prereg_commit` は manifest blob を含まない anchor commit であり
(fixture では `seed.txt` だけの commit)、P は manifest blob を含む必要がある。manifest に自身の
commit を書けば自己参照になり、既存の禁止テストとも衝突する。実装子が両立不能と判断して
**止まって報告し**、親が実測で裏を取って撤回した。実装が元から持っていた「anchor が P の祖先」
という束縛が正しい。この撤回で赤は 85 件から 2 件へ落ちた。

**敵対レビュー 2 本が 19 所見 (blocker 7) を出した。** 親は 16 件を採用、2 件を scope 外にした。
緑のまま通っていた実穴は 3 件である。(1) 上記の等値束縛の欠落 (提案された修正形は成立しないが、
束縛が緩いという指摘自体は real)。(2) 予算不足時に attempt row と lifecycle が別の status を
要求し合い試行が stuck する。(3) live AST 検査が `if bool(0):` の deterministic false 分岐を
live と数えるため、厳密な比較を偽分岐へ隠した実装でも `EVIDENCE_UNDEFINED` のままになる。

**保証の言い方を狭めた。** CLI の `main()` は `competing_bench_pids()` を `run_trial()` より前に
呼ぶため、環境 probe は slot 予約より先に走る。予約の前倒しは予約前拒否と checkout 失敗時の
slot 管理まで変えるため採らず、保証を「最初の**性能**観測より前」へ限定して書き直した。
分類が性能出力を読む前に確定したことの**時点証明は本 wave の保証範囲外**である。実装したのは
capability 束縛と、性能出力を引数に取れない分類 API までで、これを恒真な保証として謳わない。

**親の判断が 1 件、レビューに訂正された。** 凍結 baseline
(`test_reflux_originless_compatibility.py` の `_PRE_WAVE_ORIGINLESS_BASELINE`) が commit SHA を
焼き込んでいて main 取り込みで赤くなったため、親は内容由来の 17 leaf を volatile 化させた。
レビュー B が「17 件とも fixture の日時固定と決定的 projection により pin 可能」と実測で反論し、
親はこれを採用して pin へ戻す裁定にした。**段 1 の凍結 pin 閉包検査で、test file 内に
埋め込まれた baseline を取りこぼしていた**ことも同時に判明した。

**scope 外として裁定パッケージへ回した 2 件。** (1) registration schema version を v2 のまま
必須 field を増やしている。version 昇格には既存テストが schema version 文字列を literal で
持っている点を先に直す必要があり、レビュー自身が「現行公式経路に silent misread は無い」と
実測しているため後続へ回した。(2) 歴史契約で C03/C08 が machine_checkable=true だった場合の
fail-closed reason が blob read error になる件は、新 ReasonCode 禁止と衝突するため見送った。

- [T-1353] freeze-wide の事前割当 attempt registry を実装し、8c の起動と受入から到達する
  consumer として結線した。genesis が全 slot を最初の観測前に閉じ、追記専用台帳を全 ref 走査で
  第二 root から守り、落ちた構成の同じ反復だけが次 slot を消費できる。
