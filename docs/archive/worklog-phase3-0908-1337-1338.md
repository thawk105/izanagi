## 2026-09-08 (1337) — [T-2090] 軸 1 OpenAlex の残量を消化し、窓ごとの継続取得を打ち切った — 完走で得られるものの上限が低く費用が見合わない (docs のみ、branch worktree-dev-wave-t2090-openalex-window4、実装面の差分ゼロ)

- **ユーザー裁定で、軸 1 OpenAlex の窓ごとの継続取得を打ち切った (D1760)。**
  裁定の要旨は「『先行研究は存在しない』と断言することにどれだけの価値があるのか、悪魔の証明では
  ないか」「そこにこだわって研究開発が進まないのは愚かに聞こえる」「web 検索は自分も AI もできる」。
  親は打ち切りに同意し、規則側も同じ結論を支持することを現物で示した — `docs/related-work/README.md`
  7.7.3 は `RW4` に達しても無限定の不在は使えず、完走で得られるのは「限定付きの未検出を人間の裁定へ
  提出する資格」だけだと明記している。**この仕掛けは悪魔の証明を成立させるものではなく、禁じるための
  ものである。**その資格 1 つのために 2〜3 日分の窓を専有する費用が見合わない。
- **親は打ち切り前に、続行の是非をユーザーへ 2 度提示していた。** 1 度目は進捗報告に添えた選択肢、
  2 度目は「主目的との距離を見ると畳むのを勧める」という明示の推奨である。D1624 が一度
  「続ける」と裁定した件なので、覆すには明示の指示が要ると書いて待った。
- **web 検索を登録索引に代える案は、規則の側から成立しない。** 7.7.4 は列挙可能・総件数既知の索引を
  要求し (「ひとつでも列挙不能・総件数不明・取得失敗があれば `RW3` を名乗らない」)、web 検索は
  総件数も再現可能な列挙も持たない。加えて送信 request が変わるため意味的 amendment となり、
  新 epoch・全枝の再実行を伴う。**関連研究を web 検索で調べて書くこと自体は `RW1` でも妨げられない** —
  禁じられているのは世界の不在の主張だけである。
- **無償枠の窓はまだ開いていなかった。** wave 起動時 (00:12 JST) の時点で 3 窓目の窓のリセットは
  09:00 JST で、残量 189 が未使用だった。リセットで捨てられるので待たずに使い切った。
  リセット時刻は rate limit header で 2 度確認した。
- **駆動 script を Codex `role=author` の実装子に書かせ、それが実測で報われた。** 窓 1〜3 は親が
  直接書き [T-317] の凍結境界を根拠にしていたが、[T-317] は**未裁定の択一**であり親自身の推奨は
  (b)「例外を作らず親は必ず子に書かせる」だった。本 wave は (b) に従った。親のレビューと 2 巡の
  fix で所見 3 件を閉じ、**うち 2 件は実データで発火した**。(1) 段 B が checkpoint の argv の
  run ID を書き換えており、検査器が証拠を checkpoint 自身の `run_id` へ束縛する
  (`validator.py` の `target_run_id` と `ledger.run_id` の 2 箇所) ため 2 走目の証拠が落ちるところ
  だった。(2) 429 で中断した leaf が `resume_action=continue_cursor` の checkpoint を残すが、
  page 証拠と `start_independent_pass` の 2 条件だけで計画を組むとどちらにも掛からず黙って消える。
  (3) 一過性の 429 で loop 全体が止まる。**(2) の修正は直後の走行で実際に `Q6-SY2015` を拾って
  完走させた。**[T-317] の択 (b) を支持する実測が 1 件増えた。
- **本 epoch で初めて `declared_total_drift` が出た。** 申告総数そのものが 1 回の取得 (数十秒) の
  最中に 1 件減る (`Q6-SY2014` 418→417、`Q6-SY2015` 492→491)。**返却データ自体は最終の申告総数と
  完全に整合しており** (重複 0・不足 0・distinct == 最終 `declared_total`)、食い違うのは頁 0 の
  header だけである。同じ枝の隣接年 `Q6-SY2016` (554 一定) と `Q6-SY2017` (678 一定) は
  `pass_complete` になった。窓 1〜3 の条件 5 (`distinct_work_id_total_mismatch`) は「申告総数は
  動かないのに distinct が届かない」であり**形が逆**である。完走条件が `meta.count` への到達に
  依存する以上、この観測は打ち切りの判断を補強する側の材料になった。**条件は緩めていない** —
  取得器の `blocked_on_ruling` をそのまま記録した。

  HTTP 200 と残量 147 を返した。OpenAlex の応答本文は「匿名検索がクラスタ負荷で一時的に絞られて

  `Accept: application/json` のみを送る設計で、**匿名アクセスである**。key を足すと送信 request が
  変わり意味的 amendment になるので採らなかった。取得器は 429 の attempt を捨てず
  `_p1.a01.json` (`actual_count=0`) として残し、再開後の成功を `_p1.a02.json` に置いた。
- **残量 57 で意図的に止めた。** 40 を切ると取得器の発行規範 (`remaining - 30 >= cost`) により
  1 request も出せなくなり、次窓で持続観測を更新する手動 1 本すら拒否されて自己施錠に入る。
