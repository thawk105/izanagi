## 2026-08-19 (671) — /rulings 全件 第 8 回 — 正式系列が起動できない真因を実測し、迂回口の新設を却下した (docs)

- **ユーザーが「正式 non-certifying 専用の起動口を新設する」案 ([T-1310] 択 (a)) を却下した。**
  逐語 = 「それじゃ新しい起動口作る価値ないだろ」「なぜ条件を迂回して意味のないものを
  作り出そうとする？それはやめろ」。**指示は「なぜ起動できないのかを出せ」**であり、
  親が返した択一 3 つはいずれも真因を測らずに組んだものだった。
- **真因を実測した。門の欠陥ではなく、事前登録がまだ完成していないだけである。**
  `activation_report_at(repo_root, "HEAD")` を library 経路で呼んだ (CLI は全条件を
  evaluator-exception へ潰すため一次資料にしない)。commit `392cabe0`、freeze 世代 6、
  `effective=False`。12 条件の内訳は **SATISFIED 0 / UNSATISFIED 5 / EVIDENCE_UNDEFINED 7**。
  - EVIDENCE_UNDEFINED = C02 `arm-binding-declared-only`、C03 `manifest-registry-proof-undefined`、
    C05 `schedule-schema-absent`、C06 `budget-consumer-contract-undefined`、
    C07 `floor-judge-contract-undefined`、C08 `prereg-binding-proof-undefined`、
    C11 `completion-proof-not-machine-checkable`。**何をもって充足とするかが未定義**である。
  - UNSATISFIED = C01 `workload-projection-mismatch`、C04 `crash-policy-cell-partial`、
    C09 `formal-acceptance-layer3-consumer-absent`、C10 `cross-binding-verifier-incomplete`、
    C12 `allocation-enforcement-consumer-absent`。**定義はあるが consumer が実在しない**。
  - `docs/phase3-8c-preregistration.md` §5 の数値欄は **9 件中 8 件が未記入**で、埋まっている
    1 件も `no_hypothesis_test` である。
- **したがって 2026-08-18 第 7 回の [T-1310] 択 (β) は対象がずれていた。** (β) が裁定したのは
  凍結データの**源**の受理水準であり、起動を塞いでいる 12 条件と §5 には触れていない。
  (β) を実装しても起動できないのは仕様どおりで、実装の欠落ではない。
  **残っているのは裁定ではなく実装である** (2026-08-16 の閂控え §5 と同じ結論に独立に到達した)。
- **迂回口の新設は絶対規律 2 / 3 への直撃**である。12 条件は正しさと証拠の門そのもので、
  「正式な認定ではない」と注記した別経路を作ることは、門を緩めて測ることに等しい。
  親がこれを推奨したのは誤りだった。
- **`/work` は lustre を `flock` オプションで mount している** (`localflock` ではない)。
  実測 = `mount | grep lustre` の `rw,flock,user_xattr,lazystatfs,encrypt`、`stat -f -c %T` = `lustre`。
  ユーザー指摘「lustre で計算ノードもファイル共有があるだろう？」のとおりで、
  排他はノード跨ぎで効く。[T-1162] と [T-565] が置いていた「保証は同一ホスト内のみ」という
  前提は、この計算機の `/work` については**誤り**である。
- **Codex の利用枠が切れた場合は Claude を使う。待たない。** ユーザー逐語 = 「codex が
  使えなかったら claude を使えば良い」。2026-08-18 13:00 の枠切れ控えが求めた
  「2026-08-20 12:58 まで待つ」は不採用。なお本裁定時点で Codex は再び使える。
- **luna レーンは max でしか使わない。** ユーザー逐語 = 「luna max 使えと言っているのに
  luna high を使っていたの？それは酷すぎる。二度とやるな」。これは [T-1362] の
  機械強制裁定の直接の根拠である。
