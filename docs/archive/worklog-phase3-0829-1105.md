### 機構の厚さについて (救出 scope 外、裁定送り)

依頼が疑った `size_` / `verify_..._sizing` の 2 tool と sizing certificate は、**すでに main 上にあり、
変異 matrix も通っている**。したがって本 wave の救出判定 (退避 copy の処遇) は厚さの結論に依存せず、
どちらに転んでも破棄で変わらない。厚さは main 側の別問題なので、観測だけ残して裁定へ送る。

観測: `size_` は反復数 (write-heavy 218 / balanced 564 / read-heavy 28) を決める生成器で、
campaign が実際に何回回すかを決める研究入力そのものであり載っている理由がある。certificate は
結果を見る前に n を凍結する事前登録物で、規律 3 の系にある。**厚みが際立つのは `verify_` で、
これは `size_` を source-separated に第二実装で書き直したものである** (40KB の生成器に対し 52KB の
検証器、両者を束ねる test が 80KB)。守っているのは算術結果であって CC variant の正しさゲートではなく、
生成器にバグがあっても帰結は「study の size を間違える」であり、区間の出方から後で気づける。
一方で撤去側のコストも小さくない — campaign module が両 tool の source path を pin し、
certificate が両者を記録しているため、撤去は凍結済み事前登録の書き換えになる (D1027 の趣旨に触れる)。
現時点の推奨は**据え置き**で、教訓は「sizing 計算が正しさゲートへ入らないなら
source-separated な第二実装を建てない」を次回の設計時に効かせる形にする。
