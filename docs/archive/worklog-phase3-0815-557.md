- [T-1115] **P1・新規**: 受入の単独再走が checkout へ bytecode を
  残すと非帰属判定が rc=2 になるが、これを起こしうる書き手は 1 箇所ではない。本 wave が塞いだ
  worker wrapper のほかに、checkout 内の CLI を `PATH` だけの環境で起動する既存テストが
  実在する (親が実コードで確認)。`orchestrator/` と `tools/` の `env=` 指定起動は 174 箇所あり、
  そのうち「checkout の module を import する子」かつ「抑止変数を渡さない」ものが対象になる。
  個別修正の積み上げでは再発を止められないので、機械検査 (checkout を `PYTHONPATH` に置く、
  または checkout 内の script を起動する subprocess は抑止変数を必須にする meta-test) を
  設計する。wrapper 環境と WorkerSpec の環境 allowlist に単一正本が無い点も同時に扱う。
  成果物影響 = 未対処だと、対象 node が赤になった wave は正しく非帰属でも判定不能で land
  できず、しかも判定器は汚れた path を報告しないため毎回この調査を最初からやり直すことになる。
- [T-1116] **P1・要裁定**: 非帰属 checker は単独再走が緑
  (`rerun_rc=0`) の赤を帰属に分類して land を止める。存在する receipt 10 件の全件走査では
  赤を持つ 9 件がすべて帰属判定、node 11 件すべてが `rerun_rc=0` で、本 wave の受入 1 走目を
  加えて 12 node すべてが帰属となり、非帰属経路は本番で一度も発火していない。本番発火 1 件では、
  エントリ 548 が人間の判断として非帰属と記録した signal handler フレークを機械が帰属と
  判定している。`DW-O18` は checker を「差分が到達しえない赤は再現しなければ帰属せず」の
  機械化と名指すが、checker は差分到達可能性を入力に持たない。受入は 48 worker の分散走、
  再走は単独 node 走なので、同時実行由来のフレークは構造上再現しえない。候補は
  (a) tested main での再走を N 回に増やし 1 度でも赤なら非帰属とする、
  (b) 差分到達可能性を入力に加える、(c) 批准済み既知赤 nodeid の registry を併設する、
  (d) 現状を仕様として受け入れフレークは再走で対処する。いずれも land gate の受理集合を
  変えるため裁定が要る。
  成果物影響 = 未裁定のままだと、受入が rc=1 になった wave は正しく非帰属でも受入と checker の
  時間を捨てて land できず、非帰属受理の機構が実運用へ到達しない。
