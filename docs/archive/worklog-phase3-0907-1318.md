## 2026-09-07 (1318) — [T-2367] B-4 事前登録へ D1694 の前提訂正と D1695 の標本数 62 を当てた — 依頼が指した §5 に対象は無く、規範側は §5.1 と §11 だった (docs、branch worktree-dev-wave-b4-prereg-errata-20260907)

D1694 と D1695 を `docs/phase3-b4-reflux-ablation-preregistration.md` へ当てた。既存の記述は
1 行も書き換えず、5 箇所すべて追記で入れた (絶対規律 7)。実装面の差分はゼロ。実施記録と
段 3 の逐語は `output/insights/2026-09-07_b4-prereg-errata/`。

- **依頼が指した「§5 の window ごとの標本数」は §5 に無かった。** §5 の表は 10 欄で標本数の行を
  持たず、`n = 201` の行は B-4 本体の block 数という別概念である。数値 `59` は §11.2 の
  3 行にしかなかった。依頼が併記した「1003 行付近」の側が実物と合っていた。
- **§5 の表へ行を足す読み方は採れないと確定した。** `p3_b4_admission_record.py` の
  `_SECTION5_LABELS` が exact 10 label、表の行数を `len(_SECTION5_LABELS) + 2` で固定しており、
  行を足すと実走前 admission が必ず赤になる。本文自身も「10 欄のうち 1 欄」と自己記述している。
  規範側への記入は §5.1 の floor 項へ置いた。
- **1003 行の 59 は書き換えていない。** 「95 パーセンタイルを信頼度 95% で覆うには標本 59 個」は
  真である (`n >= ceil(log 0.05 / log 0.95) = 59`)。62 に置換すると必要最小数について偽の主張になる。
  **必要最小標本数 59 と、欠測余裕込みの採用計画値 62 は別の量**として書き分けた。
- **段 3 が親の pin 閉包を訂正した。** 親は「pin は §5.1.1 の 2 hash だけ」と結論していたが、
  実際には §5 の表の exact 形状 pin と、admission record 発行後に効く全文 sha256 束縛がある。
  admission record は 3 つとも不在なので現時点で旧 bytes を束縛する発行済み pin は無く、
  編集面はいずれも pin の外だった。
- **段 3 が親の一般化を 1 件否定した。** 親は「n=62 なら 3 件落ちても 59 件残る」を設計意図として
  書こうとしたが、**5% の判定は campaign 合算であって pair ごとの閾値ではない。** 複数 pair では
  欠測が 1 stratum へ偏りうるので、この算術は 1 pair のときだけ成り立つ。95% 被覆の一般保証を
  文書へ書かず、限界を明記した。pair ごとの閾値は足していない (D1697)。
- **費用の目安は数値を更新したうえで条件付きと明記した。** D1699 が候補と参照を 1 つの低水準
  セッションで測る形へ設計を変えたため、旧構成の派生値を新しい *事実* として固定すると偽になる。
  数値更新の保留も採らなかった (失効値 59 が残る)。組み替え後の目安は D1699 の実装確定後に書き直す。
- **並行 2 wave と編集面を調整した。** §5 の floor 欄の発効手続きを持つ session は、D1695 が
  凍結項目 12 行の 1 項目を変えるため先に凍結 commit を作ると古い値を凍らせると判断し、自ら降りた
  (repo 変更・worktree とも無し)。D1699 の wave は driver 2 file のみを持ち、事前登録文書は編集しない。
- **子は 1 者だけ使った。** docs のみ・実装面ゼロなので既定の軽量版とし、段 3 の敵対相談を
  read-only で 1 本だけ回した。変異 matrix は `DW-S04` により免除、受入全走は免除していない。
