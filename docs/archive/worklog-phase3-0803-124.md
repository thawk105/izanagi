## 2026-08-03 (124) — [/rulings] ユーザー裁定 5 件を記録 — login ノードのメモリ上限は 16GiB、正例の再測定、旧 driver 閉鎖 (docs のみ、branch worktree-rulings-2026-08-02-e)

- 索引 26 件のうち第 2 陣 5 件を裁定した。[T-139] / [T-331] / [T-326] / [T-352] は推奨どおり、
  [T-300] はユーザーが具体値を与えた
- **[T-300] はユーザーが実値を与えた** — login ノードの利用者 (tanab) のメモリ上限は **16 GiB**、
  実運用の目標上限は **12 GiB**。算入対象は**プロセスのメモリ使用量だけでなく `/dev/shm` 等も
  含む**。**計算ノードにはこの制限は適用されない (メモリ量の制約なし)**。したがって admission gate は
  login 側 spawn 経路にだけ掛け、静的な同時数 N ではなく**算入対象の実使用量が 12 GiB を
  越えないこと**を判定にする
- **親の測定は制約を取り違えていた (erratum)。** 親は `free -g` で「総 250 GB / 利用可能 201 GB」を
  測り、「効いている上限はここから読めない利用者ごとの割当だろう」と報告した。方向は合っていたが、
  この数値は制約ではない。**`free` はノード全体を映すだけで利用者ごとの上限を映さない**ため、
  以後 login 側の余裕判定に `free` の値を使わない。実制約は上記 16 GiB であり、
  機体固有の事実として実装 wave が Pegasus runbook へ落とす (横断 docs へ書かない)
- **[T-139] は (a)** — O(1) stripe 計算 + cache line padding を備えた代替 X で probe を再走する。
  (b) (W1 のみへ縮小) は結果を見てから 2 workload 設計を縮める事後調整になるため採らない。
  ただし実行順は (121) の裁定どおり **[T-338] の統計設計 (floor の取り方) の裁定が先**であり、
  本裁定は「資料が出たら (a) で進める」ことの確定である
- **[T-331] は (a)** — 兄弟 driver / legacy caller の COMPUTE 閉鎖を、**凍結ソース閉包の再 pin を
  含む独立タスク**として立てる。閉鎖だけ先に入れると受入全走が 10 件赤になるため部分実装は採らない
- **[T-326] は (b)** — 新 verifier 経由の深い一致強化だけを残し、`layer3_report._assert_bijection`
  本体は所見として記録に留める。(a) は既存 7 件の層3レポートの再生成要否判断を伴う独立 wave になる
- **[T-352] は (a)** — `完了` の終端性を語の不在でなく**構造 field の必須化**で判定する。
  (b) (`更新` を既定にする) は完了の信号自体を失い active 一覧が縮まなくなるため採らない
