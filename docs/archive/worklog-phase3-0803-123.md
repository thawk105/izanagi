## 2026-08-03 (123) — [/rulings] land が構造的に不能な不具合を実測し、修正方針をユーザー裁定で確定する (docs のみ、branch worktree-rulings-2026-08-02-e)

- **本 wave の記録を land しようとして、fold が必ず拒否されることを実測した。** worklog が
  ローテーション閾値を越えたため fold の計画に「過去エントリを `docs/archive/` へ移す」が入るが、
  形検査は差分を rename/copy 検出つき (`diff-tree ... -M -C`) で取りながら、検出結果が `R` / `C` だと
  `path-status` で拒否する。worklog から archive へ大きな塊が移る形は copy と判定されるため、
  **ローテーションを伴う fold は構造的に land できない**。最小再現で
  `C074  worklog.md -> archive.md` を確認し、実 land も同一理由で 3 回とも失敗した
  (main は `e0b9073` から 1 byte も動かず、rollback は正しく効いた)
- **影響は本 wave に閉じない。** worklog が閾値を越えている間、canonical 台帳へ fragment を畳む
  経路が全 wave で塞がる。fragment 自体は wave branch に安全に残るが、台帳へは入らない
- **ユーザー裁定 = 択 (a) 採用** — 形検査の差分取得から移動検出を外す。追加・削除のパス制限
  (削除は fragment path のみ、追加は rotation path のみ、archive 追加は 1 件まで) が既に効いており、
  検出を外しても制約は緩まない。移動は「削除 + 追加」として現れ同じ制限で捕まる。
  択 (b) (worklog→archive の移動だけ例外的に許す) は例外面を増やすため採らない
- **実装は本 wave で行わない。** 実装面かつ正しさ防壁の変更であり、`docs/ai-provenance.md` の
  Codex author 契約と、防壁変更は裁定パッケージへ送る規律の両方が掛かる。
  修正 wave は述語 `validator_or_rejection_gate_changed` を成立させるため、[T-059] の真時 action
  (実装前の変異事前登録) を履行すること
- **land の committer identity は解消済み。** fold は global / system 設定を無効化して git を呼ぶため
  repo-local 設定しか読まない。repo にもホームにも identity が無く fold が停止していたが、
  ユーザーが `.git/config` へ `thawk105 <thawk105@gmail.com>` を設定して解消した。
  親は検証中だけ同値を一時設定し、終了時に未設定へ戻していた (現在はユーザー設定が有効)
- **land 順序の注意:** 本 branch の fragment 2 件は main (`e0b9073`) 基点である。修正 wave が先に
