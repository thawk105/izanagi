## 未完の作業と次の一手 (具体的に)

1. **書式拡張**: worklog 次の一手の各項目に安定 ID (例: `[T-042]`、単調増加の単一連番) を付ける規約を、
   書式の正本 = `docs/worklog.md` 冒頭「新規エントリの書式 (D35)」に追記。見送り台帳 (phase3.md) の
   項目にも同じ ID 体系を使う
2. **ID 付与**: B の裁定で生き残った項目 (次の一手継続分 + 台帳保留分) に最初の ID を振る
3. **機械検査**: `tools/check_docs.py` に保存則チェックを追加 — 「直前 worklog エントリの次の一手にある
   全 ID は、新しい末尾エントリ (本文で消化に言及 or 次の一手で継続) か見送り台帳のどちらかに現れなければ赤」。
   ID なし項目の新規追加は警告に留めるか赤にするかは実装時に check_docs の既存文化に合わせる
4. **テスト同梱**: `orchestrator/tests/test_check_docs.py` に正例・負例を追加。負例 (ID を黙って落とした
   worklog) が実際に赤くなることを確認 (恒真化禁止)
5. **記録**: 書式変更の判断を `docs/decisions.md` に 1 エントリ (D 番号は採番規約に従う)
6. 完了検査: 全テスト + check_docs 緑。worklog 1 エントリに吸収して本ファイルを削除
