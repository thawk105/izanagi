## 1. 論文の芯と要旨案

**CCBench の適応 backoff を理解するには、待ち量だけでなく、待ち量を更新する時間尺度と滞在分布を調べる必要がある。**
本論文の貢献は、この相互作用を診断し、既定値に勝つことと適応機構を改善することを分ける点にある。
新しい高速な CC の提案や、動的化の普遍的な優越を主張する論文ではない。

CCBench の Silo に組み込まれた Cicada 型 adaptive backoff は、窓ごとの throughput 差に応じて
待ち量を動かす。ところが既定の更新間隔では刻みへの感度が大きく、刻みを大きくするほど一様に悪くなるわけでもない。
3 定数の格子実測は、更新間隔を広げると刻みへの感度が大きく縮むことを示した。
後続の直接観測では、狭い更新間隔で大きな待ち量に長く滞在し、更新機会自体も減ることが分かった。
実測した滞在分布と既測の静的性能曲線を混ぜると、診断した各条件の throughput に近づく。
静的較正だけから歩行を予測した旧 model の失敗は、滞在を介した説明全体の反証ではなかった。

ただし、この説明は「勾配情報がすべてノイズである」ことを意味しない。保存された方向的中率には
独立な正解がなく、それを根拠にした旧解釈は撤回する。別の計数窓による反実仮想試験は、
限定された推定対象について推奨方向の局所的な利点を支持した。一方、計数窓・適応刻み・動的上限を
組み合わせる事前登録済みの試験では、調整済み定数を超える頑健な利得は得られなかった。
**有用な局所情報があることと、その情報を使う制御器全体が良くなることは別の実験命題である。**

これらは単一環境の機構診断として述べる。診断 throughput と局所 ITT を headline 性能、fitness、
variant 採用へ昇格させない。正しさは別ビルド・別走行の認証対象に限って述べ、
未実行条件や計装入り試験への認証転用はしない。

## 2. 読者へ示す順序

導入では、既定 adaptive に対する大きな差だけでは制御機構の優劣を識別できないという問題を置く。
方法では、刻み・上限・更新間隔、時間窓と計数窓、診断と正しさ検証の違いを定義する。
結果は、3 定数の応答面、同じ刻みで更新間隔だけを変えた直接観測、滞在分布による混合検算の順で示す。
その後に「勾配は必要か」を局所 ITT で、「さらに動的にすれば良いか」を全走行の対比較で問う。
最後に、認証の到達範囲と外的妥当性を明示する。この順なら、否定的結果を提案機構の失敗談で終わらせず、
**観測窓の是正で何が解消し、その先に何が残るか**という論旨へ結べる。

対象は `ycsb_silo.exe`、protocol は **Silo** である。「Cicada 型」は算法の出自を指し、
Cicada protocol 本体の測定とは書かない。主要実験は CCBench pin `511c9538e4e8efa54b45cda62e72389ed3b706ec`、
Pegasus 48 物理コア・HT 無効、YCSB、records 1,000,000、zipf 0.9、rmw 0、max_ope 10 を用いた。
patch stack・観測長・反復・計装は実験ごとに異なるので、以下で区別する。

## 3. 3 定数の診断が支持すること

既定値は刻み 100 µs、上限 1000 µs、名目更新間隔 10 µs である。T-2187 の格子は
刻み {0.1, 0.25, 0.5, 1, 5, 100} µs × 間隔 {10, 40, 160, 640, 2560} µs、
48 threads、3 workload、7 ノード反復、各 3 秒、trace-disabled の別走行である。
同じ job が全セルを回り、95% CI は反復に対する t 分布で算出された。

刻み 0.1〜5 µs の throughput 最大/最小比は、間隔 10 µs で write-heavy / balanced / read-heavy が
2.55 / 3.28 / 3.66 倍、40 µs で 1.37 / 1.05 / 1.06 倍へ縮んだ。
したがって「刻み 0.5 µs が最良」は狭窓での局所的事実であり、機構一般の最適定数ではない。
ただし write-heavy の感度が完全にゼロになったわけでもない。
10240 µs までの延長はほぼ横ばい、40960 µs は悪化したので、「長い窓ほど良い」とも書かない。
10〜40 µs の間の立ち上がりは、この格子では分解されていない。[S1]

刻み 1 µs・間隔 2560 µs で上限を 50 / 200 / 1000 µs とした差は最大 1.2% で、
資料は各 95% CI 内と報告する。これは検討した調整後の範囲の結果であり、等価性の一般証明ではない。
狭窓の刻み 2 µs では上限 1000→50 µs だけで 2.062 倍となる一方、刻み 0.5 µs では 1.015 倍だった。
上限の効果が更新間隔と刻みに依存することが、滞在説への最初の手掛かりである。[S1, S2]

スレッド軸では調整済み adaptive の write-heavy 対無 backoff 比は 6〜24 threads で
−1.7〜−0.4%、48 threads で +63.0% だった。read-heavy では無 backoff が全 8 点で最良で、
調整済みの最大損失は 1.4% だった。これは当該実測の性質であり、任意の静的定数では同じ性質を
実現できないという不可能性証明にはしない。[S1]

**基準線の結論は維持する。** D1506 に従い、機構を評価する対照は無 backoff と調整済み adaptive の
双方である。既定 adaptive は素の実装の実績や陽性対照として残せるが、それだけに勝っても
機構の優位は言えない。上の性能値は診断材料として記載し、認証付き headline にはしない。

## 4. 非単調性の説明は、未観測の候補から滞在分布の実測へ進んだ

### 4.1 直接観測による同じ刻みの対照

T-2188 は 2026-09-10 の job `989505.nqsv`、bnode002、write-heavy / 48 threads / 3 秒 / 1 rep で、
時間トリガの 6 セルを測った。ディレクトリ名の 09-09 と測定日を取り違えない。
従来の保存 trace 26 file はすべて計数窓であり、狭い時間窓の非単調性を直接観測したものではなかった。
新しい 6 セルは `count_window=0` で、全 event の trigger が time だった。[S5]

以下は **backoff 計装入り・非認証の診断値**である。throughput を性能 headline に使わない。

| 刻み / 名目間隔 (µs) | event 中央値 Backoff_ (µs) | 時間加重 P(>100 µs) | 診断 throughput (tps) |
|---|---:|---:|---:|
| 0.5 / 10 | 3.5 | 0.0000 | 3,783,069 |
| 1 / 10 | 88 | 0.6478 | 2,201,348 |
| 1 / 2560 | 6 | 0.0000 | 4,030,122 |
| 2 / 10 | 298 | 0.9652 | 1,644,868 |
| 25 / 10 | 550 | 0.9459 | 1,290,518 |
| 100 / 10 | 300 | 0.8625 | 1,361,749 |

同じ刻み 1 µs の対照では、更新間隔を広げると高域滞在がなくなり、中央値が 88→6 µs へ下がる。
刻み 25→100 µs の throughput 回復も、中央値が 550→300 µs に戻る滞在の非単調性と整合する。
「刻みが大きいほど常に高域へ行く」という単調な説明は採らない。

中央値は保持 event に対する分位点、滞在率は保持窓の時間による重み付き量で、重みが異なる。
記録欠落を伴うのは 0.5 µs と 1 µs の狭窓セルで、ring の取りこぼしは各 68.9% / 0.54%、
保持時間の被覆率は 0.293 / 0.988。最良点の分布は末尾 slice の記述であり、全走行の代表とは断定しない。
残る 4 セルは欠落ゼロである。計装なしの既知値に対する形の保存検査 J0 は登録条件を通ったが、
共通係数は 1.0393、残差もある。形の保存は観測者効果ゼロや未計装性能への外挿を保証しない。[S5]

### 4.2 静的曲線との混合が説明した範囲

実測した時間滞在分布を π_time(b)、既測の静的 throughput を T_static(b) とすると、
混合による検算は `T_mix = Σ_b π_time(b) T_static(b)` と書ける。
T-2188 の既存解析では 6 セルの予測/実測は 0.909〜1.047 だった。
刻み 25 µs の谷は実測 1,290,518 tps に対し混合 1,315,184 tps となる。[S5]

旧歩行 model は静的較正から滞在分布まで予測し、谷の throughput を約 2.86 M として外した。
その失敗と、**観測した滞在分布を入力する**混合の成立は両立する。
取り下げるべきなのは「旧 model が外れたので滞在を介した説明も反証された」という推論である。
混合の仮定はこの測定範囲では棄却されないが、滞在分布を事前に予測する理論が完成したわけではない。
また近似的な集計整合から、動的な各瞬間の性能が静的性能に等しいことまでは証明できない。[S2, S5]

更新の実効間隔も直接測られた。全走行の更新数から得た間隔は、刻み 1 / 25 µs の狭窓で
45.5 / 91.1 µs、刻み 1 µs の広窓で 2564.1 µs だった。
窓中央値が狭窓で 12〜13 µs でも平均は大きく、名目 10 µs の一定窓ではない。
leader の試行先頭でしか更新判定されず、leader 自身も abort 後に待つ構造と整合する。
これは高域滞在と更新機会減少を結ぶ説明を支持するが、leader 固有の全過程を因果分解した結果ではない。[S2, S5]

### 4.3 計数ノイズと切り捨て境界について残る限界

時間窓の commit 数の分散/平均は、最良点で 4.42、谷で 482.77 だった。
固定幅・均質 Poisson として相対誤差を `1/√40` だけで表す旧説明は、この分布を表さない。
ただし窓長も状態も動くため、過分散という記述だけで条件付き Poisson 過程一般を棄却しない。

J1 の低域共通辺 12 本での符号不一致率差は +0.0402 で、支持閾値 +0.10 に達せず、
時間三分割の向きも揃わなかった。**計数ノイズ支配の支持は得られなかった**が、高域には比較対象がなく、
ノイズの寄与ゼロとは言えない。閾値は事前登録、推定量 `2p(1-p)` は結果を見た後の指定であり、
この判定全体を盲検の確認試験とは呼ばない。[S5]

刻み 1 µs 未満での整数切り捨てと parity 分岐の構造的境界は残る。
崖と境界の位置は一致するが、これだけでは歩行の向きを定めず、独立な寄与の定量分離にもならない。
直接 trace を得たことをもって、旧候補をすべて因果同定済みとは扱わない。[S2, S5]

### 4.4 静的 tail は既測になったが、混合の高域処理は残る

旧版の「静的 tail は 0〜900 µs まで既測」は維持する。その後、正式系列 v1 の 999 µs、
v2 の 1000 µs も取得された。後者の 999 µs 比は 3 workload で −0.22 / −0.27 / −0.66% だった。
符号化も 9999 µs まで表現可能になっており、「1000 µs は現在も測定不能」とは書かない。[S8]

一方 T-2188 の混合は 900 µs 超を 900 µs の値で平坦に置いている。
これは**未入力高域への定数外挿**であり、元資料の「外挿していない」という表現は採らない。
D1936 項36 は対象時間比率を刻み 25 / 100 µs で **3.1% / 9.6%** と記録する。
T-2188 README §5 は前者を **15.1%** と書いており、出所間に不一致がある。
本版は裁定の 3.1% / 9.6% を限界の記録として示し、15.1% を黙って同一値に置き換えず、
どちらかを選んだ新たな誤差補正・定量結論は導かない。

旧歩行 model と tail 図の consumer は schema v1 に束縛され、v2 を拒否する。
**1000 µs の測定が存在することは、その点を旧解析や T-2188 の混合へ反映済みであることを意味しない。**
D1936 項36 に従い、移行と追加測定は後回しのまま、その限界を論文に残す。
静的 tail の形を適応歩行の生成機序そのものとはせず、単一冪則・代数減衰の確定主張にも使わない
(D1724 / D1857)。[S8]

## 5. 勾配情報の有用性は、局所 ITT の推定対象に限って支持された

動的化の初期診断が保存した `directional_success` は、action 符号と次窓 throughput 差の一致である。
次勾配も同じ差から作られるため、独立な正解に対する「勾配符号の的中率」ではない。
T-2188 が event 対を照合した一致率は 99.93% で、合計が同じでも個々の対には食い違いがあった。
この指標の 0.50 を硬貨投げと同一視し、「勾配情報がない」「適応刻みはノイズだけを増幅する」と
結論した初期診断の解釈は採用しない。性能上の劣化という観測事実は残す。[S4, S5]

T-2265 の cohort 1 は、計数到達または時間 cap で閉じる混合窓に対する割当 ITT である。
初回 event を位置で除外する v2 再解析を行っても、後続の 0 commit 窓により主判定は
**inconclusive のまま**だった。残る 11 run だけの集約や副次層の正の効果で救済しない。
v2 は outcome の一部を知った後の再解析計画であり、完全に前向きな試験とは呼ばない。[S6]

cohort 2 は、1 万 commit で閉じる窓と terminal event を導入し、初回を除いた割当ごとに後続窓を持たせた。
cohort 1 を pilot とする**新しい count-closed 推定対象**であって、同じ仮説の欠測だけを埋めたものではない。
計装入り、policy 2、write-heavy / 48 threads の主層、12 cluster で、推奨方向の割当対比は
+4.900%、95% CI [+3.316%, +6.509%]、判定は `recommended_direction_superior` だった。
下端と +3% 境界の差は約 0.32 ポイントで、効果の余裕は薄い。[S7]

これは当該制御履歴上の局所 ITT であり、policy 0 対 policy 1 の全走行 throughput 差ではない。
未計装 build、他 workload・thread、個々の窓への一般化はしない。
固定 LCG の割当整合性は実装どおりの記録を示すが、物理過程と同期しないという as-if 仮定は未検証である。
局所的な方向情報の有用性を支持する証拠として置き、狭い時間窓の非単調性の普遍的説明にも転用しない。

## 6. 動的化は実測済みで、調整済み定数を超える仮説は棄却された

動的化試験は事前登録 v1 / v1.1 の後、7 block、3 workload × 8 thread 点、各 3 秒、
7 腕の trace-disabled 別走行で行われた。基準線は none と tuned、stock は陽性対照である。
判定は block 内 log 比の平均と t 分布 95% CI を用いる。robust benefit は全 24 点で非劣性かつ
write-heavy/48 と balanced/48 の両方で実用優越、等価は CI 全体が ±3% 内に入ることを要求する。
非有意を等価と読み替えない。
追加機構は計数窓 cw (K=10,000、最小 2560 / 最大 10240 µs)、
適応刻み as (1→2→4 µs、反転で半減)、動的上限 dyn (下限 50 µs) の順に重なる。[S4]

| 問い | 登録済みの対比と結果 | 論旨への含意 |
|---|---|---|
| 計数窓で tuned を超えるか | cw/tuned は全 24 点が ±3% の等価域。robust benefit は棄却 | 広い更新間隔の平坦域で動かすだけでは利得を足さない |
| 適応刻みを足すと良いか | cw-as/cw の robust benefit は棄却。write-heavy/48 は −4.0% [−4.6, −3.4] | 局所情報があっても、この刻み拡大則の全体利益は成立しない |
| 動的上限が改善するか | full-on/cw-as は全 24 点等価。診断では上限変更ゼロ | 非発火条件での等価であり、発火したときの効果は未検証 |
| full-on が頑健に良いか | full-on/tuned の H1 は棄却。write-heavy/48 は −4.8% [−5.5, −4.1] | 本実装の動的化を優越手法として提案しない |
| read-heavy で害がないか | full-on/none の H2 は登録対象の 8 点で非劣性 | この環境・この負荷での限定的結果 |

別の診断走行では cw の更新は多コアで最小間隔付近に集まり、full-on の Backoff_ は最大 21 µs、
上限は 1000 µs のままだった。したがって「上限を動的化しても効かない」ではなく、
**今回の調整後 regime では上限へ到達しない**と説明する。
40 µs 付近の計数窓や、別の動的化則一般についての否定にはしない。
これらの性能値も診断材料であり、正しさ判定や headline の資格を付け足さない。[S4]

## 7. 正しさの証拠は増えたが、機序試験の認証にはなっていない

正しさ用の `CCBENCH_TRACE` と backoff 診断用の `BACKOFF_TRACE` は別である。
認証は前者を有効にした別走行で行う。後者が無効の認証を、後者と terminal define が有効な
反実仮想試験へ転用しない。terminal は記録だけでなく更新挙動にも関係する (D1866)。

| 認証対象 | 既着地の到達点 | 残る限定 |
|---|---|---|
| tuned、48 threads、3 workload | 24/24、anomaly 0。145,904,299 transaction | 固定条件の有限 trace。格子全セル・全 thread の認証ではない [S3] |
| cw-as-dyn full-on、48 threads | 24/24、anomaly 0。146,312,522 commit | cw / cw-as へ転用不可。動的上限の発火被覆も示さない [S4] |
| cohort2 p1 / p2 の既定 seed、48 threads | 各 24/24、anomaly 0 | 計装入り cohort2 の実行体の認証ではない [S7, S9] |
| p2 の登録 seed slot 00〜09、48 threads、および p1、24 threads | 11 group、各 24/24、anomaly 0 | BACKOFF_TRACE=0、terminal define なし [S9] |

後続認証はユーザーの費用判断で打ち切られた。p2 seed slot 10 / 11 の group receipt はなく、
p2 の 24 threads・policy 0 の全条件も被覆していない。個別 request の部分結果を完全 group と数えない。
D1936 項28 が見送るのはこの後の残余であり、既発行認証をなかったことにしない。
**未 land の T-2417 は本版の既着地成果へ算入しない。** policy 性能測定の存在を取り消すこともせず、
その 480 request 案を新しい実行計画としてここに復活させない。

静的非交差の T-2539 も、validationPhase の下向き閉包に対する補助証拠までである。
報告された backoff 族 5 patch を、動的・反実仮想 patch stack 全体の検証と読み替えない。
閉包は commit の制御や writePhase を含まず、実際に early-unlock の破壊例にも「交差なし」を返す。
