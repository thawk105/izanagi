# docs/paper-story-backoff/ — adaptive backoff 単独論文のストーリー

CCBench の Cicada 型 adaptive backoff について、**「何を主張し、どういう順で語り、何がまだ無いか」**の
横断合成を集約する 2 本目の論文ストーリー系列。`docs/paper-story/` (izanagi 本体の論文) と
同じ契約で、**凍結スナップショットを時点ごとに束ねる**。

## この系列の位置づけ

- **`docs/paper-story/` とは別の論文である。** 本体の論文は「AI が CC を合成する」ことを主題にし、
  backoff はその中の一事例 (P2-4) と基準線の話として現れる。本系列は backoff 機構そのものの
  診断を主題にする。2 つを 1 本の論文へ畳まない理由と、repo が複数の論文系列を持つことの
  裁定は `docs/decisions.md` (本系列を新設した wave の決定) が持つ。
- 各スナップショットは**特定時点の凍結物** (新規計測ゼロ・その時点の正典からの導出)。
  **書いた後は更新しない。** 更新したいときは上書きせず、新しい日付のスナップショットを追加する。
  **新しい日付の版は、その日付時点の正典全体からの導出でなければならない。** 一項目だけを
  直した差分改訂を新しい日付の版として置くと、更新しなかった項目の stale が「その日付時点で
  そう主張した」という新しい嘘に変わる。一項目の決着を届けたいだけなら、版を足さずに本 README の
  「最新スナップショット以後に確定したこと」で指す。
- 日付なしの入口はこの `README.md` (ポインタは腐らない・スナップショットは腐る、の原則)。
- **正典 (矛盾があればこちらが勝つ):** `docs/decisions.md` (設計判断)・`docs/worklog.md` (時系列)・
  `output/insights/` の一次資料 (測定・認証・再解析の記録)。本系列の文書はそれらの導出物であり、
  数値・日付・判定の出所にしてはならない。`docs/paper-story/` の版本文も数値の出所にしない —
  同じ一次資料を両系列がそれぞれ独立に引く。
- **論文図はまだ無い。** 診断の図の現物は `output/insights/` の下にあり、直列性の検査を通していない
  性能図なので論文図の場所へ昇格していない。本系列は `figures/` を持たず、昇格の条件は各版が書く。
  昇格したときに `figures/` を作り、`docs/paper-story/figures/README.md` と同じ凍結契約を敷く。

## 最新スナップショット以後に確定したこと (stale 注記)

スナップショットは凍結物なので腐る。ここは腐らない入口として、最新版の記述が既に古くなった箇所を
指す。**矛盾があればここが指す一次資料が勝つ。**

**現在この節に積んでいる項目は 1 つである。**

1. **§6 の A-4 (機序の直接観測) と B-1 (動的化の実測) は、どちらも「未取得 (0 件)」ではなくなった
   (2026-09-09 追記)。** これは**所在を指すだけのポインタ**であり、本注記は新しい一次資料の内容を
   評価していない。
   - A-4 が挙げた量 (`Backoff_` の時系列、実効の更新間隔、窓ごとの commit 数、勾配符号の的中率、
     parity 分岐率) を診断ビルドで直接記録した走行がある
     (`output/insights/2026-09-05_dynamic-backoff-mechanism/README.md`)。
     その診断ビルドを使った反実仮想の試験も 2 つの cohort まで進んだ
     (`output/insights/2026-09-08_t2265-itt-seq0/README.md`、
     `output/insights/2026-09-08_t2265-cohort2/README.md`)。
   - B-1 (更新間隔を走行中に決める backoff) の設計・実装・実測も、事前登録つきで 1 度走った
     (`output/insights/2026-09-05_dynamic-backoff-mechanism/README.md`)。
   - **`2026-09-05.md` の §3 の B4・B6、§5、§6 の A-4・B-1・B-3 はいずれもこの時点で古い。**
     どこまで言えるか (どの推定対象について、どの build で、何が認証されていないか) は、
     上の一次資料が自分で限定している。**この注記はその限定を要約しない。**
   - **次の版は差分改訂にしない。** この系列の契約により、新しい日付の版はその日付時点の正典全体
     からの全面再導出でなければならない。それは [T-2340] として登録済みの別作業である。

## `docs/paper-story/` との関係

- **共有するもの:** 一次資料 (同じ `output/insights/` と `docs/decisions.md`)、絶対規律
  (性能値と正しさの分離、certified の保証範囲、規律 7 の追記訂正)。
- **共有しないもの:** 数値と図。本体論文の P2-4 の値 (無 backoff 対照に対する利得) は分母も
  環境も CCBench の版も違うので本系列へ持ち込まない。本体論文の `fig2b` / `fig2c` は適応側に
  既定 adaptive しか持たないので、本系列の対照図として引かない。
- **本体論文側の入口は動かさない。** `docs/paper-story/README.md` の stale 注記 1 が本系列の
  出発点だが、本系列の新設によってその注記を書き換えたり移したりしない。本体論文の版・図・
  claim-evidence・results はすべて凍結物のままである。
- **同じ図・同じ表を 2 本の論文で新規として出さない。** どちらに置くかは、図が論文図へ昇格する
  時点の版が書く。

## 読み方

- backoff 論文の執筆・positioning 検討のときに読む。日常セッションのブートには不要 (D35)。
- 各版の過大主張チェックリストは執筆フェーズで消し込み式に運用してよい唯一の例外。
- 進行中の可変状態 (動的化の作業がどこまで進んだか、検索の成熟度が今どこか) の正本は
  `docs/worklog.md` の末尾エントリであり、本 README には書かない。

## 運用ルール (check_docs.py との関係)

- 本ディレクトリの文書は追記型の凍結記録なので `tools/check_docs.py` の `LIVING_DOCS`
  (現況主張 lint) 対象外。`docs/paper-story/` と同じ扱いである。
- 他文書からは**ファイル名 (basename) で参照**する (行番号参照は禁止・節名参照にする)。
