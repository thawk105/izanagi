# 未知条件への転移 — 生成・選択に使わない条件、比較対象、同等幅・信頼区間・別日別割当ての追試規則を結果を見る前に固定する事前登録

本書は、VLDB 向け差分分析の P4 (未知条件への転移と再現) を測るための規則を、結果を見る前に固定する
([T-2851]、D2212)。固定するのは次の 5 つである。

1. 生成・選択に使わない条件 (以下「留保条件」) の具体値 (§2)。
2. 留保条件を生成・選択へ入れない義務と、測定を始めてよい条件 (§3)。
3. 比較対象 (§4)。
4. 測定の単位、推定量、同等幅、信頼区間、分類の規則 (§5〜§9)。
5. 別日・別割当ての追試の規則 (§7)。

**本書は事前登録の作成だけを行う。** 計算投入、選択結果を使う評価走、runner の実装、gate・検査・台帳の追加は
含まない。本書が存在することは測定の認可にならない。

一次資料は `output/insights/2026-09-21/vldb-direction/gap-analysis.md` の §3 と §4 P4、同じ dir の
`codex-consult-1.md` の優先 3 と「起こり得る結果」の表である。書き方の先例は B-8 の事前登録
(`docs/b8-final-candidate-longrun-verify-preregistration.md`) と B-5 の事前登録
(`docs/b5-generator-contrast-preregistration.md`) で、同等幅の先例は
`docs/backoff-policy-performance-preregistration.md` と `docs/backoff-counterfactual-preregistration.md` である。
起草の経緯 (相談 2 本と裁定) は `output/insights/2026-09-22/t2851-transfer-prereg/README.md` に置く。

## 1. 主張の形と、主張しないこと

### 1.1 主張しうること

成立時に許す主張は、次の**操作的事実**に限る。

> protocol p の留保条件 c (§2) で、候補 k (課題 t・手法 m・独立探索 s が学習条件 W で選んだもの) の throughput は、
> 強い参照 r (§4) に対し [優越 / 退行 / 実用上同等] だった。2 つの cohort (別日・別割当て、§7) の両方で同じ分類で、
> 分類は cohort ごとの同時信頼区間 (主要族の比較数 M、§6) による。

- **勝者交代** は、同じ候補対 (k, r) について、錨の cell W で「優越」、留保 cell c で「退行」が、両 cohort で
  成立した場合だけを指す (§6.4)。
- 結論は**登録した点での局所的な転移**である。登録した 23 条件 (§2) の外への外挿、因子の一般的な予測力、
  因子間の交互作用は主張しない。因子別の集約 (§6.5) は記述に留める。
- 読み比率の留保は 2 点 (25 と 75) だけで、どちらも学習条件の読み比率 5・50・95 の間にある (内挿)。
  他の 4 因子は錨ごとに上下 (rmw は 1 水準) を置く。この非対称を結果の報告に添える。

### 1.2 主張しないこと

- **手法単位の優劣。** 手法の比較には独立探索の反復が推測の単位として要る。本書は候補単位の推測だけを持ち、
  手法別の集計は記述に留める (§6.5)。「手法 m は転移に強い」とは書かない。
- **日とノードの効果の分離。** 追試は「別日・別割当てで同じ分類が得られたか」の確認であり、日の効果と
  マシンの効果を分けない (§7)。
- **stock 比の大きな数字を主結果にすること。** Silo では強い参照 R1・R2 との比較を主要表に載せる。強い参照に
  優越しない結果を、stock 比の利得で置き換えて報告しない (§4)。
- **正しさの一般的な保証。** certified は観測した有限の trace に対する判定で、全実行の証明ではない。
  verifier は自前の mini-verifier で、predicate・phantom・fairness・未観測実行を保証しない。
- **性能値の trace 下での意味。** 性能は trace-disabled build だけで測る (絶対規律 1)。
- **同等幅の百分率としての対称性。** δ = ln(1.03) の比の範囲は [1/1.03, 1.03] ≈ [0.9709, 1.03] で、厳密な ±3% ではない。
- **他環境・他 protocol・TPC-C への転移** (§14)。

### 1.3 反例を作ったので書かない文

事前登録に統計の文を書く前に最小の反例を作った。作れた文は書かず、対応する事項を仮定または限定として置く。

1. **「両 cohort で同じ分類なら偽陽性率は二乗になる」** — 片方の cohort でだけ帰無仮説が偽 (真の効果がある)
   という状況では、誤った一致の確率を単純に二乗できない。また比較が数百あれば、二乗した率でも誤一致が
   どこかで起きる確率は小さくない (相談 A の算術では比較 624 個・独立の仮定で約 0.32、和の上界 0.39)。
   → 追試を多重性の補正の代わりにせず、cohort ごとの同時区間を使う (§6.3)。
2. **「1 因子ずつ動かせば、その因子の効果がわかる」** — 因子 A の効果が因子 B の水準で符号を変える
   (交互作用) なら、錨の周りの 1 点の応答は他の水準での効果を表さない。→ 局所的な応答として報告する (§1.1)。
3. **「別 hostname で再現すれば、マシンの効果は無い」** — 日とマシンを同時に替えているので、両方の効果が
   打ち消し合った一致とも区別できない。→ 分離を主張しない (§1.2)。
4. **「rmw を 1 にした差は読み書き集合の重なりの効果である」** — rmw を 1 にすると書き込みが
   read-modify-write になり、1 txn の読み出し数も増える (操作数 L・読み比率 r なら予定の読み出しは概ね L・r から L へ)。
   → 「書き込み方式 (blind write / read-modify-write)」の変更として報告する (§2)。

## 2. 学習条件と留保条件

### 2.1 学習条件 (錨)

本書が学習条件 (生成・選択に使う条件) として扱うのは次の 3 点 (以下「錨」) である。錨と違う学習条件を使う
探索群は §3.2 のとおり本書の対象外である。値は現行の campaign 定義
(`orchestrator/campaign/p2_2.py` の `WORKLOADS`・`RECORDS`・`THREADS`・`EXTIME`、`orchestrator/campaign/pipeline.py` の
`S2_FLAGS`) の静的確認による。

| 錨 | 読み比率 (%) | Zipf skew | thread 数 | 1 txn の操作数 | 書き込み方式 | レコード数 | extime |
|---|---:|---:|---:|---:|---|---:|---:|
| wh (write-heavy) | 5 | 0.9 | 48 | 10 | blind write | 1,000,000 | 3 s |
| bal (balanced) | 50 | 0.9 | 48 | 10 | blind write | 1,000,000 | 3 s |
| rh (read-heavy) | 95 | 0.9 | 48 | 10 | blind write | 1,000,000 | 3 s |

CCBench の引数名は、読み比率 = `ycsb_rratio`、Zipf skew = `ycsb_zipf_skew`、thread 数 = `thread_num`、
1 txn の操作数 = `ycsb_max_ope`、書き込み方式 = `ycsb_rmw` (偽 = blind write、真 = read-modify-write)、
レコード数 = `ycsb_tuple_num` である。いずれも Silo と MOCC が共有する YCSB 実装 (CCBench の `include/ycsb.hh`) と
各 protocol の `common.hh` にあり、指定した workload を表すための CCBench 改変は要らない (静的確認。runner・検証・
全候補での完走は実証していない)。

### 2.2 5 条件の操作的定義と水準

依頼の 5 条件を次のように置く。水準は結果ではなく設計理由で決めた。

| 依頼の条件 | 操作する引数 | 留保の水準 | 設計理由 |
|---|---|---|---|
| read/write 比 | 読み比率 | 25、75 | 学習条件 5・50・95 の間の内挿点。25 は wh、75 は rh に最も近い (差 20 対 25) |
| 競合 | Zipf skew | 0.7、0.99 | 学習条件 0.9 より低競合側と高競合側。skew はアクセス分布を変える引数で、競合の観測値ではない |
| スレッド数 | thread 数 | 12、24 | 並列度を 1/4 と 1/2 に縮める。Pegasus は 1 socket 48 物理コア・HT 無効なので、48 を非 oversubscription 方針の上限とする |
| トランザクション長 | 1 txn の操作数 | 5、20 | 学習条件 10 の半分と倍 |
| アクセス集合の重なり | 書き込み方式 | read-modify-write | txn 内の読み集合と書き集合を重ねる。読み出し数も増える複合変更である (§1.3 の 4) |

レコード数は 1,000,000 に固定し、留保の因子にしない。規律 4 により較正で決めた値であり、変えると cache の
状態も変わって「重なり」と分けられないからである。

### 2.3 留保条件の一覧 (1 因子ずつ動かす配置)

各錨の周りで 1 因子だけを動かす (OFAT)。読み比率だけは錨の周りに置かず、内挿 2 点をそれぞれ最も近い錨に結び付ける。
表にない引数は錨と同じ値である。

| cell | 錨 | 動かす因子 | 値 | 区分 |
|---|---|---|---|---|
| wh-base / bal-base / rh-base | 各錨 | — | — | 錨 (学習条件) |
| wh-rr25 | wh | 読み比率 | 25 | 留保 |
| rh-rr75 | rh | 読み比率 | 75 | 留保 |
| W-skew070 (W = wh, bal, rh) | W | Zipf skew | 0.7 | 留保 |
| W-skew099 | W | Zipf skew | 0.99 | 留保 |
| W-thr12 | W | thread 数 | 12 | 留保 |
| W-thr24 | W | thread 数 | 24 | 留保 |
| W-ope05 | W | 1 txn の操作数 | 5 | 留保 |
| W-ope20 | W | 1 txn の操作数 | 20 | 留保 |
| W-rmw1 | W | 書き込み方式 | read-modify-write | 留保 (Silo の bal-rmw1 だけ既知別枠) |

cell は protocol ごとに 3 + 2 + 3 × 7 = 26 個、うち留保が 23 個である。cell の名前は §5 の順序の鍵に使う。

**既知別枠:** Silo の bal-rmw1 は、stock と ability-probe 変種の性能測定が既に repo にある (§10)。この cell は
測定と解析を他と同じに行うが、主要族 (§6.3) に入れず「既知条件の前向き追試」として別の表で報告する。
MOCC の bal-rmw1 は既知結果が見つかっていないので留保として扱う。

**旧 8b 系列との関係:** 8b の holdout (読み比率 80 と 20、他は錨と同じ) は留保に使わない。8b の floor 較正で
既に測定があり、旧系列と実験条件が重なるからである。8b の holdout 機構は D2212 項 5 で論文の必須経路から
外れたが、記録は保持されている。本書はその機構を再開・変更しない。8b の三軸走査に本書が当たらないことは、
留保を守る証拠ではない (走査は書式と値の同時出現を見るだけである)。将来の転移測定の集約記録に、旧 8b の
値と他の cell の値が同じ file に入れば、走査に当たりうる。

## 3. 不使用義務と測定の解禁

### 3.1 不使用義務

本書の着地以後、生成・生成のための評価・選択に関わる全ての主体は、次の 3 つを入力に使ってはならない。

1. §2.3 の留保条件 (表の 1 行が表す引数の組) と、留保の設計 (どの因子をどちらへ動かすか)。
2. 留保条件での測定結果 (性能・検証・較正のいずれも)。
3. 1・2 から作った指示・要約・設定 (planner・critic への指示、BO の目的関数・探索範囲・超パラメータ、進化・
   random・sweep の分布や範囲、workload の記述、候補の手選別、選択のための較正)。

禁止するのは留保条件への適応であって、個々の引数値の使用ではない。例えば、検証用の小規模 workload
(`orchestrator/campaign/pipeline.py` の `CorrectnessWorkload`: 200 レコード・4 thread・操作数 5・read-modify-write・
extime 1 s) は操作数や書き込み方式の値が留保と重なるが、条件としては別であり、従来どおり使ってよい。

主体には LLM の子と role (coder・planner・critic・selector)、非 LLM の探索手順、候補を選ぶ人間と AI の親を含む。
本書を読んで留保条件の測定を行う評価担当は、留保に関わる情報を生成担当へ戻さない。

**本書そのものへの到達:** 本書は repo の docs にあるので、filesystem を読める生成器は本書を読みうる。対象探索群の
各 (課題, 手法) について、生成・選択に関わる主体が repo の docs を読めたかを記録する。tool を持たない構造化出力の
role は構造的に読めない。読めた手法の転移の結果には、全ての表で「留保値に到達可能だった」と付ける。
結果から除外はしない。本書は機械的な隔離を実装しておらず、隔離を主張しない。

### 3.2 対象探索群と候補の凍結

「対象探索群」は、選択結果を本書で評価する探索の一式 ([T-2850] の比較など) である。§7 の測定の「cohort」
(cohort 1・cohort 2) とは別の語として使う。対象探索群は発効の決定で名指しし、候補の性能を見て選ばない。

対象探索群の学習条件は §2.1 の錨の部分集合でなければならない (引数が全て一致すること)。一致しない探索群には
本書を適用せず、その探索群の生成が始まる前に別の登録を作る。

**候補の凍結記録** は次を全て含む: 全 (課題, 手法, 独立探索) → 選ばれた候補の identity の対応、選択規則、
選択できなかった系列、参照 R0〜R2 の identity、MOCC の扱い (§4)、各手法の到達可能性 (§3.1)。identity の書式は
発効束で決める。

### 3.3 解禁の条件

留保条件での実行 (stock を含む。性能・検証・較正・smoke を問わない) は、次の 2 つが揃うまで 1 走もしない。

1. 測定の発効の決定 (§0)。
2. 対象探索群の**全手法・全独立探索**について、候補の凍結記録が作られていること。一部の候補だけを凍結して
   留保条件を測り、その後に残りの探索や比較基盤を調整することはできない。

runner の smoke や動作確認は、錨または検証用の小規模 workload の引数で行う。

## 4. 比較対象

protocol p・錨 W ごとに、次を比較対象とする。identity が同じ候補は 1 つにまとめて測る (§5)。

| 記号 | 名前 | Silo | MOCC |
|---|---|---|---|
| R0 | stock | CCBench pin の上流既定の build。全 option が CCBench の `cmake/Options.cmake` の既定値で、Silo では BACK_OFF=1 (abort 時の指数 backoff 有効)・NO_WAIT_LOCKING_IN_VALIDATION=1・NO_WAIT_OF_TICTOC=0・WAL=0 (8b catalog の upstream defaults と同じ定義) | 同左 |
| R1 | 既知最良 `p2_2_flag_opt` | 錨ごとの P2-2 最良 flag genome: wh と bal は `5185ee5e6094` (B0-L-W0 = BACK_OFF=0・NO_WAIT_LOCKING_IN_VALIDATION=1・NO_WAIT_OF_TICTOC=0・WAL=0)、rh は `b971a1d9f80a` (B0-T-W0 = BACK_OFF=0・NO_WAIT_LOCKING_IN_VALIDATION=0・NO_WAIT_OF_TICTOC=1・WAL=0) (`orchestrator/campaign/s1_known_axes_freeze.py` の `EXPECTED_P2`、`output/s1-freeze/known_axes_freeze.json`) | 指定範囲で未発見・未確定 |
| R2 | 学習錨で事前に選んだ既知の静的設定 | wh は固定 backoff 10 µs、bal は固定 backoff 5 µs (いずれも BACK_OFF=1 で固定値を与える)、rh は無 backoff (BACK_OFF=0・固定値なし・他は既定) | 未確定 |
| sel | 各手法の選択結果 | 対象探索群の全 (課題, 手法, 独立探索) が錨 W で選んだ候補 | 同左 |

- **R0** は上流既定なので BACK_OFF=1 である。A-2・A-6 の記録が「stock」と呼ぶ arm (BACK_OFF=0・固定値なし・他は既定) とは
  別の build で、本書の R0 はその arm を指さない。
- **R1** は Silo の 8 flag genome の全探索 (P2-2、旧環境) による錨ごとの最良で、Pegasus で選び直していない。
  依頼どおり外さない。
- **R2** は、Pegasus の正式 protocol の記録 (A-2: wh の fixed 10 µs が +63.5485%、bal の fixed 5 µs が +14.4213%。
  A-6: rh の fixed 2 µs が −5.7841%、いずれも median 比) から、錨ごとに既知の 2 者のうち強い方を採った。比の分母は
  各記録が「stock」と呼ぶ無 backoff の arm (上の R0 の注) で、その flag の組は bal・wh の R1 (B0-L-W0) と同じである。
  Pegasus で静的 backoff の格子全体を測った argmax ではない。rh の R2 が無 backoff であることは既知 2 者の選択であって、
  他の静的値より強いことは示されていない。rh の R2 は R0 とも rh の R1 とも別の build である。固定 backoff は CCBench
  改変 patch (`patches/silo-backoff-fixed.patch`) による。留保条件では選び直さない。
- **MOCC** は R1・R2 に当たる参照が起草時点で無い。発効の決定で次の 3 つのどれかを選んで書く: (a) 参照を根拠付きで
  固定し、主要族に入れる。(b) 記述専用として、測る候補集合を固定して測る (主要族は空、結果は全て記述)。(c) MOCC を
  測定に含めない。どれを選ぶかは留保条件の結果を見る前に決める。
- **sel** は、対象探索群の選択規則が錨 W で選んだ候補である。候補 k の比較は、k を選んだ錨 W に結び付いた cell
  (W-base と W の留保 cell、wh には wh-rr25、rh には rh-rr75) だけで行う。identity が参照と同じ候補は、その参照との
  比較を行わない (同じ build の比較になるため) と記録する。
- 留保条件で失格した候補 (§8) を次点の候補で置き換えない。留保条件で最も速かった候補は事後の oracle であり、
  運用で選べた候補の成績と分けて報告する。
- 本書が扱う protocol は、対象探索群の protocol のうち Silo と MOCC だけである。他の protocol は別の登録を要する。

## 5. 測定の単位と順序

- **build:** 性能は trace-disabled build だけで測る (絶対規律 1)。候補ごとに build は 1 つで、両 cohort で同じ identity の
  build を使う。
- **1 走:** CCBench の YCSB binary の 1 process の実行 1 回。extime 3 s、内部の反復なし。値は binary が報告する
  throughput (tps) とする。
- **block:** cell の全候補 (重複除去後 K 個) を 1 走ずつ実行したもの。
- **job:** 1 job = (cohort, protocol, cell) の 1 組で、1 node 上で n = 32 block を連続して走らせる。job の最初に
  stock を 1 走して捨てる (静定)。job の開始時と終了時に、Pegasus runbook の手順で node の単独性を確かめる。
- **順序:** block b の実行順は、候補の identity 文字列を辞書順に並べた列を、次の手順で並べ替えて決める。
  鍵を `t2851-order-v1|<cohort>|<protocol>|<cell>|<b>` とし、i = K−1 から 1 まで、
  j = (SHA-256(鍵 + `|` + i の 10 進表記) を big-endian の整数とみた値) mod (i + 1) として、位置 i と j を入れ替える。
  順序は結果を見て選び直さない。順序は block ごとの鍵から導出するが、block 間で順序が違うことも、位置や持ち越しの
  均衡も保証しない。
- **区間の意味:** 1 job の 32 block から得る区間は、その割当て (その日のその node) の中での条件付きの区間である。
  node や日をまたぐばらつきは含まない。それを見るのが §7 の追試である。

## 6. 推定量・区間・分類・主要族

### 6.1 推定量

候補 k と参照 r の、cell c・cohort h での効果を θ = E[ln(tps_k / tps_r)] とする。期待値は、その割当て (§5) で
両者が正常に走った場合の block についてとる。推定値は block ごとの ln(tps_k,b / tps_r,b) の平均 d_avg で、
使った block 数を n_eff、標準偏差を s_d とする。

**主要族の資格:** 組 (k, r) が主要族で分類されるのは、その cohort の job で k と r の 32 block の走が全て使える
(§9) 場合だけである (n_eff = 32)。1 走でも使えない走があれば、その組は主要族では判定不能とする。使えない走は
候補の性能と無関係に起きるとは限らず (遅い候補ほど時間切れになりやすい等)、使える block だけで推定すると θ が
偏りうるからである。その場合も、使えない走の件数と理由、使えた block だけの d_avg と無補正の 95% 区間を
記述として添える。

### 6.2 同等幅と分類

同等幅は δ = ln(1.03) = 0.029559 とする。先例 2 本 (`docs/backoff-policy-performance-preregistration.md`、
`docs/backoff-counterfactual-preregistration.md`) と同じ値で、採否 floor (`orchestrator/campaign/p2_2.py` の
`BETWEEN_RUN_CV` = 0.030、D19) と揃う。結果を見た後に δ を広げない。

区間 [L, U] に対して、次の 4 つに分類する。

| 分類 | 条件 |
|---|---|
| 優越 | L > δ |
| 退行 | U < −δ |
| 実用上同等 | −δ < L かつ U < δ |
| 判定不能 | 上のいずれでもない |

区間が真の θ を含むなら、この分類は誤らない (優越なら θ > δ、退行なら θ < −δ、同等なら |θ| < δ)。
したがって誤分類は区間が θ を外したときにだけ起きる。「有意差なし」を結論にしない — 同等は区間が同等幅に
収まったときだけ言う。

### 6.3 主要族と同時区間

**主要族** は、全 protocol × 全 cell (錨を含み、Silo の bal-rmw1 を除く) × 候補 k ∈ sel × 強い参照 r の組である。
強い参照は Silo では R1 と R2、MOCC では §4 の (a) で固定した参照である。R0 (stock) との比較、参照どうしの比較、
Silo の bal-rmw1 は主要族に入れない。rh の R2 (無 backoff) は R0 と別の build なので、rh でも R2 比は主要族、
R0 比は記述である。族の大きさ M は候補の凍結記録から決まり、測定の前に記録する。

cohort ごとに、主要族の各組について、自由度 31 の t による両側の同時区間
d_avg ± t(1 − 0.025/M, 31) × s_d / √32 (Bonferroni) を作り、§6.2 で分類する (§6.1 の資格を満たす組だけ。
資格を満たさない組は判定不能)。

誤りの率は次の仮定の下での近似である: block ごとの ln 比が互いに独立で近似的に正規に従うこと。厳密な保証ではない。
θ は割当て (§5) に条件付きなので、cohort 1 の θ₁ と cohort 2 の θ₂ は違いうる。

- cohort h の族のどこかで区間が θ_h を外す確率は 5% 以下である (Bonferroni)。
- 主要結果 (下記) のどれかの分類が θ₁ について誤るなら cohort 1 の区間のどれかが θ₁ を外しており、θ₂ について
  誤るなら cohort 2 の区間のどれかが θ₂ を外している。したがって、主要結果のどれかが θ₁ または θ₂ について
  誤る確率は 10% 以下である。θ が割当てに依らない (θ₁ = θ₂) なら 5% 以下である。
- 仮定 (独立・正規) は検査しない。block 間の自己相関や外れ値があれば、この率は保証されない。

**主要結果** は、両 cohort で同じ分類 (優越・退行・実用上同等のいずれか) になった組である。判定不能どうしの一致は
主要結果に数えない。両 cohort の値を統合した推定は、記述として添えることはできるが主張には使わない。

主要族に入らない比較 (R0 との比較、参照どうし、bal-rmw1 の既知別枠) は、無補正の 95% 区間で同じ 4 分類を付け、
「記述」と明記して報告する。

### 6.4 勝者交代と転移の差

- **勝者交代:** 同じ (k, r) について、錨の cell (W-base) の主要結果が「優越」で、留保 cell c の主要結果が「退行」の
  とき、c で勝者交代が起きたと書く。
- **転移の差:** d_avg(c) − d_avg(W-base) を、2 つの job の独立な推定の差として Welch の 95% 区間で示す。記述に留める。

### 6.5 記述の集約

- **因子別:** 因子 f の各水準について、その水準の cell (錨ごとに 1 つ) の d_avg を錨について等重みで平均する。
  読み比率は 2 cell をそのまま並べる。
- **手法別:** (課題, 手法) ごとに、独立探索の系列を等重みにして分類の件数と d_avg の分布を示す。同じ identity の測定を
  複数の系列が共有しても、独立な標本に数えない。選択できなかった系列も件数に入れる。
- いずれも推測の対象にしない。

### 6.6 精度の計画値 (保証ではない)

対内の標準偏差 s_d は未測定である。n = 32 のとき、同時区間の半幅 h = t(1 − 0.025/M, 31) × s_d / √32 は次のとおりである
(t 分位点は不完全ベータ関数から数値計算し、t(0.975, 7) = 2.3646 で照合した)。

| M | t | s_d = 0.02 | s_d = 0.03 | s_d = 0.04 |
|---:|---:|---:|---:|---:|
| 1 (無補正) | 2.040 | 0.0072 | 0.0108 | 0.0144 |
| 100 | 3.887 | 0.0137 | 0.0206 | 0.0275 |
| 400 | 4.382 | 0.0155 | 0.0232 | 0.0310 |
| 1000 | 4.705 | 0.0166 | 0.0249 | 0.0333 |

- 実用上同等を言うには h < δ に加え |d_avg| < δ − h が要る。s_d = 0.04 で M ≥ 400 なら h > δ となり、主要族では同等を言えない。
- 単 cohort・標本 SD を固定した正規近似で、優越を約 80% の確率で検出できる真の比は、M = 400 のとき s_d = 0.02 で
  約 1.049、0.03 で約 1.059、0.04 で約 1.069 である。主要結果は両 cohort の一致を要するので、2 つの cohort が独立で
  同じ条件なら、その比で主要結果が得られる確率は約 0.8² ≈ 64% である。
- 起草中の案 n = 8 は、各腕の CV 2.28%・腕間相関 0 の仮定 (s_d ≈ 0.032) で、真値 0 のとき無補正の 95% 区間でも
  同等と判定できる確率が約 18% に留まる (正規近似) ので採らなかった。δ を広げる代わりに n を増やした。

## 7. 別日・別割当ての追試

- **cohort:** 全 cell を 2 回測る。cohort 1 と cohort 2 で候補・build・規則・n は同じで、cohort 2 で cell を減らしたり
  規則を変えたりしない。cohort 1 の結果は cohort 2 の前に見てよい。
- **別日:** cohort 2 の最初の job の開始は、cohort 1 の最後の job の終了から 24 時間以上後とする。
- **別割当て:** cohort 2 の各 job は別の scheduler request とし、同じ (protocol, cell) の cohort 1 の job と違う hostname
  の node で測る。job は測定の前に自分の hostname を cohort 1 の記録と比べ、同じなら測定せずに終わる。この再投入は
  (protocol, cell) ごとに 2 回までとし、3 回目は hostname が同じでも測定して「別割当て不成立」と記録する。
  別割当て不成立の cell の組は主要結果に数えない。
- **不一致:** 両 cohort の分類が違う組は「追試で不一致」とし、両方の推定値と区間を主要表に残す。第 3 の cohort で
  決着させない (結果を見ながら測定を足す停止規則を持たない)。不一致のまま終える。
- **主張の範囲:** 追試は「2 つの異なる日・割当てで同じ分類になった」ことの確認である。日の効果とマシンの効果の
  分離は主張しない (§1.2)。

## 8. 正しさ

- 性能と別に、(protocol, cell, R0 以外の候補) ごとに trace-enabled build で検証を 1 本行う (別 build・別 run、
  絶対規律 1)。workload の引数は性能と同じ (thread 数・レコード数・読み比率・skew・書き込み方式・操作数) で、
  extime は 3 s とする。cohort 1 の期間に行う。verifier の版は発効時に固定する。
- 結果は 3 値とする: **certified** (verifier が完走し serializable、anomaly 0)、**失格** (anomaly 1 件以上、
  または serializable でない verdict)、**未確定** (完走しない、trace の完全性の検査に落ちる、資源不足)。
  anomaly の無い未確定を certified と数えない。
- 失格は候補ごと: anomaly が 1 件でも出た候補は、全 cell・両 cohort の主張から外す (絶対規律 2)。anomaly の種別と
  依存の構造を報告し、「正しさが転移しなかった」ことを主要な所見として扱う。既に取った性能の測定値は測定事実として
  残し、主張に使わないことを追記で示す (絶対規律 7)。
- 未確定は別 node で 1 回だけ再検証してよい。なお未確定なら、その (候補, cell) の性能には主張の資格が無い
  (記述だけ)。
- R1・R2 も R0 以外なので検証する。R1 または R2 が失格すれば、その参照との比較は全て主張から外す。

## 9. 欠測と例外

- **使えない走:** 異常終了 (rc ≠ 0、crash、時間切れ)、throughput が 0、非有限の値。これらは ln 比に入れず、
  候補・cell・cohort ごとに件数と理由を残す。throughput が小さくても正の値なら除かない (区間が広がって判定不能に
  なることを受け入れる)。
- **組の資格:** 使えない走が 1 つでもある組は、主要族では判定不能とする (§6.1)。block を落として主要族の分類に
  進めることはしない。記述としては、使えた block だけの推定と使えない走の件数を並べる。
- **単独性違反:** job の開始時または終了時に node の単独性の確認 (§5) が不成立なら、その job は block 数によらず
  主要解析に使わない。その (cohort, protocol, cell) の job を丸ごと 1 回だけ再投入してよい。再投入の job も
  単独性が不成立なら、その (cohort, protocol, cell) の全ての組を主要族で判定不能とする。不成立の job の値は記録に
  残し、記述にだけ使う (その旨を付ける)。
- **job の失敗:** node の故障・walltime 切れで 32 block に届かなかった job も、丸ごと 1 回だけ再投入してよい。
  失敗した job の値は記録に残すが解析に使わない。再投入も 32 block に届かなければ、その (cohort, protocol, cell) の
  全ての組を主要族で判定不能とし、届いた block を記述にだけ使う。
- 再投入の判断は、失敗・違反の事実だけで行い、比較の結果を見て行わない。

## 12. 費用の試算 (仮定付き)

cohort ごとの性能の走数は n × Σ K(p, c) で、K(p, c) は cell c の重複除去後の候補数 (stock を含む) である。
候補数は未確定で、6 を上限としない。次の 2 例で試算する。2 protocol × 26 cell とする。

- 例 1: 全 cell で K = 6 (差分分析 P4 の例と同じ候補数) → 32 × 6 × 52 = 9,984 走 / cohort。
- 例 2: 5 手法 × 3 独立探索の選択がすべて別 identity で、参照 3 → K = 18 → 32 × 18 × 52 = 29,952 走 / cohort。

1 走の所要には 2 つの出所がある。どちらも上下限ではない。

| 出所 | 1 走 | 例 1 (1 cohort) | 例 2 (1 cohort) |
|---|---:|---:|---:|
| 実測 1 例: Silo の 1 process の wall (`silo_ladder_rung1` の run receipt、extime 3 s) | 3.42 s | 約 9.5 node 時間 | 約 28.5 node 時間 |
| 換算: Codex 見解の「30 run ≈ 0.62 node 時間」(準備込み) | 約 74 s | 約 205 node 時間 | 約 616 node 時間 |

- 2 cohort ではそれぞれ 2 倍になる。3.42 s の行は 1 process の wall だけで、job の準備 (build・hydrate)、捨て走、
  再投入、queue 待ちを含まない。74 s の行は旧い梱包での準備を含む換算で、本書の job の形での準備費ではない。
- 検証は Σ (K(p, c) − 1) 本で、例 1 は 260 本、例 2 は 884 本である。1 本の所要を D2160 の 3 s 検証の実消費
  (約 256〜263 s / 本、錨の 3 workload での fixed 5 µs・10 µs の記録) と仮定すると、例 1 は約 19 node 時間、例 2 は約 64 node 時間になる。
  留保条件での検証の所要は未測定で、条件によって増えも減りもしうる。
- いずれの例も D2212 項 4 の確認ライン (1 タスクの job 合計 2 node 時間) を大きく超える。発効時に、凍結した候補数で
  見積りを出し直してユーザーの確認を取る。1 cell の job が小さいことを理由に確認を省かない。
- LLM の直列時間は本書の測定には無い (生成は対象探索群の側で済んでいる)。

## 13. 発効束と改訂契約

### 13.1 発効束

測定の発効の決定に、次の実値を写す。1 つでも欠ければ発効できない。

- 認可の日付、決定 (D) 番号、承認対象の commit、本書の raw bytes の SHA-256。
- 対象探索群の名指しと、候補の凍結記録の所在 (§3.2)。M の値。
- MOCC の扱い (§4 の (a) 参照と根拠 / (b) 記述専用と測る候補集合 / (c) 含めない、のどれか)。
- CCBench pin、patch の bytes と sha256、configure、toolchain の版。
- 候補ごとの identity の書式と値。
- verifier の版 (module の file 別 sha256)、runner の bytes と sha256。
- 環境 (Pegasus gen_S、node の種類、単独性の手順)、trace の保全先と空き容量。
- 凍結した候補数での費用の見積り (§12) とユーザーの確認。
- §10 の既知結果の差分 (着地から発効までに増えた測定)。

### 13.2 改訂契約

- **着地から測定の発効まで:** 本文の既存 bytes を書き換えない。留保の効力が着地で生じているからである。
  発効束の実値は本文でなく発効の決定と insight に置く。意味を変えない誤記の訂正と、発効束の項目の補足だけを、
  末尾に日付付きの追補として足してよい。留保条件の削除・変更、不使用義務の緩和、既知別枠の変更、§5〜§9 の
  規則の変更はできない。条件の追加は「追加枠」として別の節に置き、v1 の主要族に入れず別に報告する。
- **留保条件の結果を 1 つでも見た後の規則の変更** は、発効前でも事後改訂である。有利・不利の向きを問わない。
  当初の規則による結果を本書の結果として報告し、事後改訂の下の結果は別欄に分ける。
- **測定の発効後:** 既存本文の bytes を書き換えない (D1789)。訂正は末尾に `## N. Erratum` として足し、理由・日付・
  適用する cohort・判定への影響を書く。Erratum を足すと file 全体の SHA-256 が変わるので、発効時に記録した版と
  追記後の版の対応を Erratum に書く。
- 本書の中の「未発効」「未着手」などの状態の記述は、起草時点の記述として読む。

## 14. 本書が閉じないもの

- **TPC-C の留保 (必須の未完項目)。** TPC-C は D2212 項 2 で必須に入ったが、verifier が TPC-C の直列化可能性を
  まだ認定できないので、v1 は YCSB だけを扱う。TPC-C の留保条件は、**TPC-C の生成・探索・選択が始まる前に**
  別の登録で固定する。v1 の着地で P4 全体が完了したとは書かない。
