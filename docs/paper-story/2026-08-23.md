## 1. 何のプロジェクトか (一言)

CCBench (10 プロトコル × 最適化フラグ群) を素材コーパスに、**AI がワークロード特化の
並行性制御 (CC) を自動合成するシステム**を作りながら、その過程自体を研究記録として残す
プロジェクト。成果物は 3 点:

1. **certified な選択結果** — 証拠が支持すれば新しい variant、支持しなければ stock または
   「差なし」を正直に選ぶ。**新しい CC が必ず出てくる契約ではない。**
2. **なぜそれが速いかの説明** — 数値と判定と参照からなる事実層は自動生成できる。
   機序を言語化する層は設計凍結のみで未実装であり、現時点の機序説明は
   アブレーションで分離できた範囲か、手作業のケーススタディに依る。
3. **試行錯誤の記録** — どれをやるとどうだったかを再現可能な台帳として残す。

**差別化の核は 2 番目 (説明可能性) である。** 先行の Polyjuice / CCaaLF は policy table という
数値の塊を出すだけで「なぜこの CC が速いか」を言語で説明できない。Izanagi は各主張を WAL の
run 値まで辿れる証拠連鎖で裏づける。ただし「因果」と呼べるのはアブレーションで分離できた効果に
限り、それ以外は仮説と表示する、というのが正典の規定である。

**2026-07-27 のユーザー裁定でスコープが狭まった。** 対象は **Silo ベースに固定**し、
「複数プロトコルから選ばせる」問題設定は当面採らない。最適化・組み換え・軽い書き換えの範囲で
まず成果を出す方針である。したがって「10 プロトコルから選ぶシステム」という書き方は、
現在のスコープを実際より広く見せる。

## 2. ストーリー (3 幕構成)

### 第 1 幕 (Phase 1) — 信頼できる評価器を先に建てる

前版から変化なし。要点だけ再掲する。

- **trace verifier (Adya DSG / G2 検出) の検出力を二重に実証。** わざと壊した Silo で 1,310 件の
  G2 赤、無改変の本物 si で 3,576 件の G2 赤、素の Silo は緑。逆側は P2-0 の 8 genome 全緑で
  「緑を取りこぼさない」も対で実証した。
- **verify-the-verifier (敵対的検証)** が「不正な trace で赤を隠せる」false-green の穴を検出し、
  verdict の 3 値化 (`indeterminate` 追加) で fails-closed に硬化した。
- **calibration の前提崩壊。** 「cache miss 率の飽和点を探す」当初前提が masstree の実測で崩れ、
  下限基準 (working set が L3 の K 倍以上) へ方法論を書き換えた (D15)。

**この文書で「certified」と書くときの意味 (重要)。** verifier が担保するのは
**YCSB の point read / write に限った、実際に観測できた trace 上の直列化可能性**である。
述語や phantom、公平性や starvation、観測されなかった実行までは保証しない (roadmap §3.1)。
「正しさゲートを一度も緩めなかった」という言い方も、**設定したゲートを通過し続けた**という
工程上の事実であって、一般的な正しさの証明ではない。

### 第 2 幕 (Phase 2) — 当初仮説の反証と、価値の所在の発見

論文の心臓部。**対になる 2 つの結果**がある。この幕の内容は前版から変わっていない。

#### 否定的結果 (P2-5, D21/D29) — 「賢い探索は自明空間では役に立たず、有害ですらある」

![Phase 2 の否定的結果 (P2-5)。探索コスト (最良構成に到達するまでの評価回数、低いほど速い) を、LLM 誘導・機械的勾配 (貪欲、LLM なし)・random/oracle 参照線で比較。balanced では両者に有意差なし (A=0.58)、write-heavy (deceptive 構造) では誘導が貪欲より有意に有害 (A=0.23, exact permutation p=2.5×10⁻⁴) で 8/12 が誤収束。](figures/fig1_phase2_negative.png)

当初の絵「LLM 誘導探索は全探索より速く収束する」は反証された。silo のフラグ空間は実質
`BACK_OFF=0` の 1 ビットで決まる自明空間で、「誘導が速い」図は評価器の優位を評価器の定義で
論証する循環になると設計段階で判明した。確定した数値 (`p2-5-summary.json`、replay = 新規計測ゼロ):

- **balanced:** LLM 誘導は機械的勾配 (貪欲) と有意差なし (確率優越 A=0.581, p≈0.16)。
- **write-heavy (deceptive 構造):** 誘導は貪欲より**有意に有害** (A=0.230、厳密 permutation
  p=2.52×10⁻⁴、全 50,268 構成を列挙した exact 検定)。誤収束 8/12 =「自信ある早期停止の負債」。
- これは reward hacking の**鏡像** — 評価器側の過信が deceptive 信号下で負債になることの定量実証。

**統計方法論の誠実性の実装:** `p2-5-summary.json` はトップレベルに再校正と訂正の履歴を機械可読で
残している。**「訂正の訂正まで成果物に残る」= 誠実性の物理的実装。**

#### 肯定的結果 (P2-4 backoff ケーススタディ, D18/D20) — 「価値は空間の外への合成にある」

![Phase 2 の肯定的結果 (P2-4)。左: 合成した静的 backoff (固定遅延) が stock の適応 backoff を write-heavy で +38% 上回る。stock は grid 刻み 100µs のせいで sweet spot 5–10µs に到達不能。右: 機序 — backoff 増で abort が減り spin が増えるトレードオフ、その中で有用 IPC はほぼ不変 (純 spin 希釈の除去として効いた)。](figures/fig2_backoff_mechanism.png)

critic の指標帰属 (「適応 backoff は abort を潰せているが IPC 崩壊 = 過抑制」) が、
フラグ空間の**外**の新軸「backoff 量の静的固定」の合成を駆動した。

- 利得は write-heavy で **+38.5%** (`backoff_profile_t48_skew0p9_rr5.json` 由来、stock 1,867,747 →
  10µs 2,586,112 tps)。旧文書系の **+38.3% / balanced +11.3%** との一本化は**この版の時点でも
  未解決**である (§8 の B-1)。
- **正しさの但し書き。** certify したのは別の検証 workload (tuple200 / thread4 / rmw=true) 上で
  あり、性能を測った workload (1m / thread48 / rmw=0) そのものは直接検証していない。
  正しさは「backoff は正しさに影響しない (correctness-inert)」という機序論証による外挿である。
  **同一 workload での certification は今も未実施。**
- **測定契約の但し書き。** これは 2026-08-17 の D496 より前の測定である。現在の正典は
  「比べる構成を同じ campaign の中で測る」ことを求めており、**この利得を現在の契約で
  測り直した確認は取れていない。**
- stock の適応 (Cicada 型 hill-climbing) が grid 刻み 100µs のせいで sweet spot 5–10µs に
  **物理的に到達不能**で 約 560µs に駐車する構造欠陥まで実測で特定した。計装 run の一例では
  spin が 87.3% を占めたが、この単発値には ±5〜7 ポイントの再現ばらつきがある。
  **頑健なのは「約 560µs への駐車」と grid 刻みによる到達不能性の構造論証**であって、87.3% ではない。
- **機序として閉じた範囲 (D20 の限定をそのまま引く)。** 言えるのは **0〜10µs の帯**で
  「abort が stock 0.815 から 10µs で 0.494 へ約 4 割減り、その間 有用 IPC はほぼ一定 =
  total IPC の低下は純粋な spin 希釈」まで。**帯の外は別である** — 25〜100µs の過抑制域では
  有用 IPC 自体が下がり、stock の約 560µs 点の有用 IPC は sweep 範囲外の外挿である。
  「有用 IPC で積モデルが定数として予測的になる」は**不成立**と明記されている。

**この対比が第 2 幕の結論を確定させる:** 「フラグ探索は自明で LLM の出る幕がない。価値は
空間の外への合成にある」。否定的結果は薄い結果ではなく、「なぜコード合成 (Phase 3) が要るか」を
定量的に動機づける要石である。

**S-1b はどう扱うか。** 同一コードで gate 述語だけを恒真化した対照との比較 3 対は

**主張 S-1 全体の性格 (誤読しやすい点)。** 事前登録の HARKing 境界の記述により、

## 9. まとめ — 実証状態の非対称な整理

**AI に CC を合成させたら、賢い探索は自明空間で役に立たず有害ですらなかった。価値は指標の機序帰属が
探索空間の外に新軸を開くことにあり、それは設定した正しさゲートを一度も緩めずに、旧測定契約下の
一事例として stock 超えを達成した。だが「その新軸が既知の最適化最良を超える」ところまでは、
縮小した形で測って届かなかった。**

前版との違いは 3 文目である。以下に、実証状態を種別ごとに分けて置く。読者が「機構が進んだから
科学的主張も順調」と読まないよう、意図的に非対称に並べている。

| 種別 | 内容 |
|---|---|
| **実証済み (科学的主張)** | P2-5 の否定的結果 (誘導探索は自明空間で無効・deceptive 構造では有害)。verifier の検出力の双方向実証。P2-4 の空間外合成が旧測定契約下で stock を上回った一事例 |
| **測って届かなかった** | S-1a (合成軸が既知軸最良を超える) = 不成立。S-2 (発見の再現性) = 不成立。S-3 (帰属の寄与) = 棄却。したがって縮小主張 S' 全体が不成立 |
| **登録追試として成立** | S-1b (trigger-gating 軸の on/off 効果は再現する)。新発見ではない |
| **運用上の証拠 (科学的主張ではない)** | 8a の軸提案ループ内化、層3 事実層の双射検査 (対象 campaign 群)、8c の無人 iteration 運搬と bench 到達、床値 protocol の凍結機構、mocc trace-hook の certified 到達 |
| **未取得 (§8)** | 対測定データ、新 protocol の床値、descriptor 条件付き合成の因果証拠、8c 正式系列、還流 ablation、LLM 固有性の対照ほか |

現時点で誠実に書ける論文は、**第 2 幕の否定的結果と肯定的結果の対比を主軸に据え、
第 3 幕を「機構は成立したが、測ってみると性能主張は届かなかった」という報告と、
そこに至るまでの運用方法論として書く**形である。
