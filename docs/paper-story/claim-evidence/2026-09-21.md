## 1. この表を読む前に — 読み違い防止の 9 条と、欄の規則

§8 が繰り返し警告している読み違いは、表という形式にするとかえって起きやすい。注意書きを冒頭に置くだけでは効かないので、
**欄の規則として固定し、書けない文を明示的に列挙する。** 2026-08-26 稿の 4 条 (G1〜G4) と前稿の G5〜G8 はそのまま残し、
この稿で増えた読み違いの型 (裁定を実施と読む型) を G9 として足した。

### 1.1 読み違い防止の 9 条

**G1 — (e) 欄の件数を「準備完了度」として読まない。** (e) 欄はその行の (a) に書いた exact claim に紐づく条件である。
**claim を強くすれば B 群の項目が A 群へ移り、claim を弱くすれば逆が起きる。** (e) 欄は距離の目盛りではなく、
**いま書こうとしている文に紐づいた条件のリスト**である。

**G2 — A-3 を「実証で穴が 1 つ閉じた」と読まない。** A-3 (P2-4 利得値の一本化) は 2026-08-25 に決着したが、決着したのは
**どの値をどの分母で報告するかという規則**であって、新しい測定でも certification の更新でもない (`L21`)。

**G3 — A-4 の B 群への移動を「証拠が揃った」と読まない。** A-4 (新しい床値 protocol による official 実測) が A 群から外れたのは、
**claim の但し書きを外すのに必要でなくなったから**であって、証拠が取れたからではない。official 走行は 2026-09-16 に完走して
floor 案の実値が出たが、**その値は配線下限で決まっている。床は 2026-09-20 に凍結 v2 g1 の床として発効したが (D2166 / D2180)、
runbook §2 P3 は `allowed: false` のままで oracle 実走の前提は未達であり、「発効した」と「走れる」は別である** (`L43`、`L57`)。

**G4 — `fig2b` を現行契約の測定結果として扱わない。** 後継図のデータは D496 より前の記述的結果であり、図の点推定は標本平均、
本表 C1 の論文値は同じ WAL の各側 median の比である。図は論文の利得率の出所ではない (`L27`)。

**G5 — protocol の status (`observed-positive` / `reject` / `accepted` / `not-observed`) を研究の成功・失敗の宣告として読まない。**
これらは事前登録した判定式が出した札であり (D12)、研究の成否宣告ではない。A-2 / A-6 / [T-1998] の効果には信頼区間も有意差判定も無い (`L29` / `L32` / `L33`)。右 tail の `not-observed` は事前登録した Bonferroni 同時区間 (`[qL, qU]`) を使う判定式の出力であり、その区間の射程を一般化しない (`L37`)。

**G6 — 符号が旧環境と 3 workload とも一致したことを「再現した」と読まない。** 環境・CCBench の版・測定契約・推定対象が違い、
どの走行も有意差判定を持たない。記述的な照合であって再現判定ではなく、旧値と新値を pool しない (`L31` / `L35`)。

**G7 — 「A-1 の attempt-0001 / attempt-0002 が完走した」を「A-1 の値がある」「再現した」と読まない。** どちらの出力も
`formal=false` / `promotion_prohibited=true` の非認証 lane の descriptive 出力であり、事前登録と policy がその反転を文書編集で行うことを
禁じている (`L34`)。**2 attempt の並記は「同一配置の反復で分類と符号が一致した観察」であって再現判定ではなく、attempt 間の比較の
事前登録は存在しない。L-A1S-4 は「2 attempt の観察に基づく限定」として読み、解除とは書かない** (`L54`、D2194 項 6)。

**G8 — 正しさの緑を性能の主張へ染み出させない。** A-2 / A-6 / [T-1998] / A-1 (2 attempt) / B-10 cohort / B-7 fixed5 の correctness
`certified`、採用候補 2 genome の検証相 (30 verify / 候補、anomaly 0)、B-5 の上限付き試走の 318 verify 走は、いずれも**性能の判定では
ない**。逆に性能の `reject` は正しさ証拠を取り消さない (`L40` / D1993 項 2)。

**G9 — 裁定・承認を実施と読まない。** 第 27 回 /rulings (D2194、2026-09-21) は B-8 の発効と校正・本走の投入を承認し、K2 4 巡目の
入力元・B-4 の耐久 carrier と参照点定義・enforcement source closure の次段・凍結 v2 g1 の未発効候補文書の削除を裁定したが、
**いずれも本稿の起点では未実施であり、結果も判定も無い。決定自身が「裁定は実装・測定・commit・送信の完了を意味しない」と明記する**
(`L56`)。逆に、裁定より前に実行済みだった項 (掃除の候補 2) もあるので、「裁定の日付 = 実施の日付」とも読まない。

### 1.3 欄の規則

**表は claim の種別ごとに 3 つに分けてある** (§2.1 科学的主張 / §2.2 運用・方法論の証拠 / §2.3 文献 guardrail と副産物)。
**科学的主張と運用上の証拠を同じ表に並べない** — 並べると「機構が進んだから科学的主張も順調」と読まれる。

**(a) は論文へそのまま置ける文とし、条件を文の中に持たせる。** workload・構成・反復数・TRACE の有無・集約方法は (a) か (d) に必ず書く。
(c) の値は成熟度の分類であって、保証範囲を保持しない。

**(b) は 2 段に分ける。** `[権威 bytes]` はその値・判定が実際に書かれている成果物 (WAL、`campaign.lock`、receipt、certification JSON、
result JSON、calibration JSON、凍結 policy JSON、事前登録の blob、生成器のソース)。`[導出索引]` はそこから読み取った insight /
results 稿 / D 本文で、**`authority: none` を自ら宣言している文書はここにしか置かない。** `results/` 系列の単独稿は権威 bytes から
作られた統制稿であり、本表では `[導出索引]` に置く (値の権威はそれが指す成果物にある)。同じ走行主体が書いた投影どうしの一致は、
独立な裏取りとして数えない (D920)。

**(c) は 7 値の閉じた語彙しか取らない。** 前稿は 6 値だったが、2026-09-19 版 §9 が「固定条件で certified な correctness (性能の判定
ではない)」を独立の種別として置いたので、本稿はそれに一致させて 7 値にした。**種別を 1 つ増やしたのは、正しさの緑を性能の行から
分離するためであり、実証状態が進んだからではない。** この種別に置いた行は C2 (A-2 / A-6 の correctness) と C25 (検証相) である。

| (c) の値 | 意味 |
|---|---|
| 実証済み (科学的主張) | 測って成立し、報告できる |
| 測って届かなかった | 登録した複合主張が測って不成立・棄却で確定した |
| 登録追試として成立 | 事前登録した追試として成立。新発見ではない |
| 限定付きで取れた観測 | 正式 protocol の status、非認証 lane の descriptive 出力、非 certifying の観測など。正式・非正式を行ごとに明記し、headline 主張に数えない |
| 固定条件で certified な correctness | 正しさゲートの判定。性能の判定ではなく、保証範囲は `L01` |
| 運用上の証拠 (機構・準備) | 機構が動いた事実、材料の整理。測りたい量が測れたことではない |
| 未取得 | 証拠が無い |

**(d) は末尾に必ず `✗` で始まる禁止推論を 1 つ以上書く。** その行だけを抜き出して読んだ執筆者が書いてしまう文を、あらかじめ潰すためである。
恒久的な表現規律は §3 の限定レジストリへ `L01`〜`L64` として登録してあり、(d) から ID で参照する。

**(e) は 2 行に分けて書く。** `外せる項目:` は**その行の (d) を実際に外す**証拠、`後続別主張:` は**その行の (d) は外さないが、
別の新しい主張を可能にする**証拠である。

| (e) の行 | 意味 |
|---|---|
| `外せる項目: なし (恒久)` | 追加の証拠では外れない。表現規律・区別の規律・スコープの規律である |
| `外せる項目: <ID>〔被覆〕` | それを取ると (d) が**実際に外れる**。被覆をセル内に必ず書く |
| `後続別主張: <ID>〔…〕` | 取っても (d) は外れず、**別の新しい主張が 1 つ増える**だけである |
| `将来scope: C-n` | C-n は現在の論文の必要条件ではない |
| `要裁定` | 何を満たせば外れるかが、まだ研究方針として決まっていない。裁定待ちの T 番号があれば書く |

`<ID>` は §4 の A / B 群の ID を取る (`A-1`〜`A-6`、`B-1`〜`B-10`)。**`A-4` は §4.3 の B 群にあるが、前稿との対応を辿れるよう
ID を A- のまま据え置いている。A-2 / A-6 は取得済みで §4.1 にある。**

**`後続別主張` を型として分けたのは、A-1 の性質のためである。** A-1 を取っても、C1 が報告する測定が「D496 以前に行われた」という事実は
変わらない。外れるのではなく、**現行契約下の別の主張が新しく 1 つ書けるようになる**だけである。**これを混ぜると、A/B 項目を取った時点で
過去の行から但し書きを削除する retroactive な過大主張が、この表を根拠に書けてしまう。** `該当なし` と書くと「追加証拠が不要になった」と
読まれるので、この語は使わない。

**(a) の文頭には、抜粋しても残る `〔役割〕` を置く。** 節見出しは行を抜き出すと失われるため、表の分割 (§2.1 / §2.2 / §2.3) だけでは
行単体の防護にならない。

### 5.1 測定契約の限界

本論文が報告する静的 backoff の利得 (write-heavy +38.3%、balanced +11.3%、read-heavy −6.6%) は、旧 `linux-baremetal` 環境の trace-disabled
inline sweep における**記述的な結果**である。条件は records 1,000,000 / threads 48 / zipf skew 0.9 / rmw 0 / extime 3 秒 / `CCBENCH_TRACE=0` /
反復 5 で、集約は各側 TPS の median 比である。分母は**同一 sweep 内の無 backoff 対照** (`BACK_OFF=0`) であって、stock の適応 backoff ではない。
適応を分母に取れば write-heavy の利得は +147.4% になるが、これは過抑制の大きさを示す診断値であり本論文の利得ではない。

これらは現在の対測定契約 (D496) より前の測定であり、**A-1 が定める配置と推定対象の下で測り直したものではない。** ただし「同じ campaign の
中で比べる」という形そのものは、現行環境の走行がいずれも満たしている。取れていないのは、均衡 5-rep ブロック交互と AB/BA 均衡、対差平均の
estimand、検出力から導いた n = 30 と登録済み区間推定による、**formal な lane での**測定である。A-1 の本走 policy は非認証 lane
(`formal=false` / `promotion_prohibited=true`) のまま凍結されており、その attempt-0001 (2026-09-18) は 3 workload とも完走して descriptive な
出力 (対差平均 write-heavy +1,591,948.50 tps、balanced +448,830.17 tps、read-heavy −576,749.77 tps、分類はいずれも「区間が床の外」) を出した。
attempt-0002 (2026-09-20、同じ policy・同じ root seed・同じ物理順の独立再現) も 3 workload とも完走し、+1,538,451.47 / +548,138.23 /
−560,565.60 tps で分類は同じく「区間が床の外」、`variance_plan_breach` は write-heavy と read-heavy で真だった。
**「A-1 の値がある」とは書けず、3 行は並記であって集計ではなく、分類は有意差判定ではない。2 attempt の並記は「同一配置の反復で分類と
符号が一致した観察」であって再現判定ではなく (attempt 間の比較の事前登録は無い)、attempt-0001 稿の限定 L-A1S-4 は「2 attempt の観察に
基づく限定」として読む (解除ではない)。****したがって当該 study の attempt が増えても、本節の限界は解消しない** — 解消するのではなく、現行契約下の
別の主張が 1 つ増えるだけである。

現行 Pegasus 計算ノード・CCBench pin `511c953` では、採用静的 backoff を測った正式な走行が 3 つある。A-2 protocol (write-heavy と
balanced の exact 4 cell) の outer status は 2 workload の論理積として `observed-positive` (median 比 rr5 +63.5485%、rr50 +14.4213%)、
A-6 protocol (read-heavy の 2 cell) は `reject` (rr95 −5.7841%)、balanced の別の事前登録に基づく stock-inline 対は `accepted`
(improvement_percent 11.225375361916456) である。**これらは protocol の status であって、研究の成功宣告でも失敗宣告でもない。** A-2 と
A-6 は 2 点 protocol で信頼区間も有意差判定も持たず、[T-1998] の `accepted` も有意差の判定ではない。**3 つは独立した protocol であり、
1 つの横断実験ではない。** 符号が旧環境の 3 値と 3 workload とも一致したことは記述的な照合であって再現判定ではなく、旧値と新値を pool しない。
同一候補 fixed 5 µs を 3 workload で同時期に測った descriptive な走行 (write-heavy +67.8968%、balanced +12.6717%、read-heavy −11.3787%) では
read-heavy だけが走行間ばらつきの下限 (0.2228%) を超える退行であったが、これは全 workload の退行込み報告 (B-7) の材料であって
要件充足そのものではなく、有意差判定でもない (**この測定と結果図 fig10 を根拠に、後続の裁定が B-7 を限定付き — 単一 attempt・descriptive・
非認証・反復間安定性は未判定 — で充足と判定した。充足したのは報告要件であって採用・認証・性能主張ではない**)。**利得側だけを引用することはしない** — 旧 3 値の read-heavy −6.6% も、A-6 の `reject` も、fixed 5 µs の
read-heavy 退行も落とさない。

旧 A-2 attempt の `reject` (2026-08-28) は当時の事実として残るが、測っていたのは CCBench 内蔵の適応 backoff の有効/無効であり、
新 attempt は identity を直した別の走行であって条件を 1 つだけ変えた対照ではないので、**旧 `reject` の原因は書かない。**
機序主張は「利得は abort baseline が高いほど大きい」までであり、「backoff は常に有害」とも「常に有益」とも読めない。機序説明として
`BACKOFF_NOINLINE` 下の +38.5% を引く場合は、それが別 CCBench revision の perf sampling 診断値であり headline 値ではないことを併記する。
**+38.5% と +38.3% を同じ測定の丸め違いとは言わず、逆に別 regime が効果量を変えた実証とも言わない。**

論文採用値には、計算機を別に起動し直して取り直した証拠が無い。Pegasus で取った結果はこの充足にならない (D1525)。

### 5.2 正しさの保証範囲

verifier が担保するのは、YCSB の point read / write に限った、**観測できた trace 上の**直列化可能性である。述語・phantom・公平性・starvation・
未観測の実行は対象外である。「正しさゲートを一度も緩めなかった」は工程上の事実であって、証明ではない。verifier の書き込み隔離についても、
ツール権限による隔離は成立していない — 正確な形は「専用書き込みツールの除去、prompt 規律による禁止、verifier 入力側の性能数値隔離」である。
検証構成の被覆にも限界があり、trace を有効にすると commits が 44% 減るため、**S2 verify が踏む競合レートは性能計測時の約 56% 相当**である。

採用静的 backoff は、**性能を測った workload そのもの**で certified である。A-2 の 4 cell と A-6 の 2 cell が、いずれも
`source_binding_status=bound` の下で、trace-enabled の別走行における legacy 1 回 + performance 条件 5 回の検査を通った。**これは性能の認証
ではない。** そして限定が 5 つ残る。(i) 保証範囲は上のとおり point-key trace に限る。(ii) correctness 側の run argv は既存 pipeline では
独立に記録されておらず、workload の束縛は campaign lock と pipeline constructor による。(iii) 成果物自身が「artifact hash 単独では
compile-out の証明にならない」と宣言している。(iv) 条件関門について成果物が保存しているのは admission record と record の ID までで、
元の record の本体は残らない。(v) `src_token` の一致だけでは実翻訳単位全体の意味の一致を保証しない — 前処理指令が include 先や別 file に
及ぼす効果を identity が捉えない範囲は 2026-09-17 の修正で塞がれたが、指令と include の相対位置と `push_macro` / `pop_macro` は限界として
残り、A-2 / A-6 の判定は修正前の identity 層の下のものとして残る (修正によって遡って強くならず、取り消されもしない)。
**この certification は旧 `linux-baremetal` の 3 値へは遡らない** — 旧 3 値の正しさは今も「backoff は正しさに影響しない」という機序論証による
外挿である。certified は実際に build された bytes についての判定であり、要求した構成が build されたことを含意しない。

採用候補 2 genome (fixed 5 µs / fixed 10 µs) の各候補について、trace-enabled build の独立 8 反復 × 3 workload (extime 3 秒、計 24 verify) と
校正で完走した 6 verify の計 30 verify (候補ごと) すべてで verifier は `serializable`・certified を返し anomaly は 0 件だった。校正の extime
10 秒の走は各候補 2 件 (balanced、write-heavy) が verifier の完走に至らず verdict を持たない。**これは操作的事実であって確率主張ではなく、「信頼度 1−εⁿ」とは書かない。
性能値を含まず、上の certification と性能判定を昇格も降格もしない。** S-1 事前登録の「検証相の拘束数値」を準用した追加検証であって
S-1 の充足ではなく、「種を変えた長時間実行による最終候補の検証」(B-8) の取得でもない。B-8 は事前登録 v1 の下で対象・定義・試走が段階認可され、
試走 (build と identity の導出のみ) が完走して発効束が揃い、発効と校正・本走の投入が承認されたが、**発効・校正・本走は未実施で判定は無い。**
仕分け (2) の限定の明記は発効 commit の wave が行う。

[T-1998] の 2 arm、A-1 attempt-0001 の 6 arm、B-10 右 tail の 2 cohort (各 120 記録) の correctness も certified・anomaly 0 だが、
いずれも `legacy` 条件の小設定 (4 thread・200 tuple・rratio 50・rmw 有効・1 秒・max ope 5) の別走行であり、性能を測った
48 thread・1,000,000 records・workload 別の条件そのものの認証ではない。fixed 5 µs の 6 cell (B-7 の材料) は A-2 / A-6 と同じ形式で
legacy 1 回 + performance 条件 5 回 (計 36 記録) を通ったが、これも性能の認証ではなく、correctness の実引数が独立に記録されない限定 (ii) が
掛かる。**「直列性の検査を通していない」とは書かない — 書くのは「性能値が
未認証である」である。** 正しさの緑を性能の主張の中へ置くと、緑が性能へ染み出す。

mocc については同じ強さの検出力の実証が無い。stock mocc の G2 signal は、witness を切った producer でだけ再現し (2/40・3/40・2/40、
通常条件 5/120)、witness on では 0/40・0/60 だったが、片側 Fisher は非有意で、読み値の出所照合は未達、hook / verifier 仮定の分岐が残る。
**0 件は不在証明でなく、非有意は同等性証明でない。** 根因は未同定であり、上流向けには観測事実と限界の報告までとする。

### 5.3 合成能力についての限界

合成した軸 (trigger-gating) は、既知軸の一部である書込ロック順並べ替えには 3 workload とも floor 超で優越した (相対中央値差
+55.5%〜+98.4%、n = 8 / セル、certified 標本)。**ここでいう certified は、性能標本そのものを検証したという意味ではない** — 性能実行は
`CCBENCH_TRACE=0` で、`certified` は同じ campaign が別に通した `legacy` tag の trace 検証を指す。**したがって「3 workload で certified
serializable のまま既知軸に勝った」とは書けない。** しかし**既知軸最良を上回るという事前登録した主張 (S-1a) は、測って不成立だった**
(family p = 1.0)。これは新しい否定的発見ではなく、登録した複合主張の失敗報告である。同一コードで gate 述語だけを恒真化した対照との比較
(S-1b) は成立したが、この効果は先行する機械 sweep 偵察で既知であり、confirmatory な新発見ではない。族 4 のうち S-2 は不成立 (名目 p = 0.115)、
S-3 は非有意 (名目 p = 1.0) で「退化を示せる」という主張の側を棄却した。**適格率次元の発見再現性は未実証のままである。**

**現行環境の走行 (A-2 / A-6 / [T-1998] / A-1 / fixed 5 µs) は、いずれも採用静的 backoff と無 backoff の比較であって、合成軸と既知軸最良の
比較ではない。** A-6 の `reject` は「合成した軸が負けた」ではない。

**旧・主実験の事前登録に書かれた headline 比較 4 対照は、「4 対照が揃えば headline が出る」という見通しとしては再利用しない。**
主張 S から S' への縮小を経て S' が不成立で確定した以上、その経路はそのままでは使えない。

これらの判定について「統計的に裏打ちされた」と書けるのは S' の族補正込みの厳密検定と、B-10 待ち方 grid の 3 族 Holm の exact 符号反転
permutation までであり、他の性能比較の主防壁は対測定と反復単位の対比である。反復数 5 程度の順位和検定は完全分離で常に同じ p を返すため、
有意性検定として一般化しない。

**ワークロード特化の合成ができたとは書けない。** descriptor を条件にした生成の因果証拠 (on/off、必要なら入替えの対照) が無く、selector
実験・dry-run・既知 workload の pilot・非認証の登録経路で走らせた対照はこの証拠に数えないと設計文書自身が宣言しているためである。

**LLM でなければ到達できないとも書けない。** この形の必要性は対照を取っても言えないと裁定されており、主張は固定予算・固定編集面の下での
条件付き優越へ狭まっている。その対照の事前登録 v1 は作られたが未発効で、本走は認可されておらず、対照自体が未取得である。

safe variant loop は現行 pin の下で certified の terminal verdict へ 4 度到達したが、評価したのは固定 backoff の初期値 (`20` / `25` / `10`)
であって新しい CC 構造ではなく、3 走は非同時刻で改善・退行の根拠にならない。critic の診断が次生成の型付き入力へ届いたことと「効いた」ことは
別であり、同 job の stock 対照は未達である。

本システムの出力契約は certified な選択結果であり、証拠が支持しなければ stock または「差なし」を返す。**成果物を「新しい CC」とは書かない。**

### 5.4 探索についての否定的結果の射程と、機序説明の帯域

LLM 誘導探索が自明な探索空間で機械的勾配を超えず (balanced: A = 0.5813、p ≈ 0.16)、deceptive な構造では有意に有害だった (write-heavy:
A = 0.2304、厳密 permutation p = 2.52e-4、Holm ×6 でも p ≈ 1.5e-3) という結果は、3 workload のうち 2 つについてのものである。残る read-heavy は
到達判定が情報を持たない構成 (k = 4) であり、この結論の一般化には使えない。主指標は tie 半加算の確率優越へ再校正済みで、旧指標での読みは
否定的結果を実態より強く見せる方向であった。誘導と random の比較は未到達試行の扱いに依存する (感度幅 0.23〜0.39) ため、**単体では headline に
しない。**

backoff の機序について閉じているのは **0〜10µs 帯だけ**である。この帯では total IPC の低下が純 spin 希釈であることを示した。25〜100µs の
過抑制域では有用 IPC 自体が低下し、stock の約 560µs 点は外挿である。abort 率はそもそも単一指数の冪則に従っておらず、**「単一冪則」と
「代数減衰」を確定主張として書かない** — 書けるのは 6 点の直線回帰の傾きが −0.44〜−0.52 の帯に入るという記述的な要約までである。
**spin 87.3% のような単発値を代表値として引用しない** — 再現ばらつきは ±5〜7 ポイントで、頑健なのは「約 560µs への駐車」と grid 刻みによる
到達不能性までであり、どちらも既定 3 定数についての事実である。

待ち方 grid (`constant` 対 `symmetric-modulo`、μ = 2〜100 µs) は 3 族すべて Holm で `different` だったが、判定が及ぶのはこの 1 つの対比だけで、
36 cell の効果量が等価域 ±3.0% の外へ完全に出た区間は 0 である。静的 backoff の右 tail (境界参照 1000 µs + 1250〜9999 µs の 7 点) は、
事前登録に束縛された正式格子の本走 cohort 1 (2026-09-15) と独立再現の cohort 2 (2026-09-19) のそれぞれについて、**「この事前登録の
述語では、表現可能域である 9999 マイクロ秒までに飽和を観測しなかった」**という結末だった (3 workload とも `not-observed`、18 区間すべて
`declining`)。**「飽和しない」「飽和点が存在しない」「再現されたので飽和しない」とは書かない** — 9999 µs は符号化の上限であって物理的な限界
ではなく、2 つの cohort は合成せず、統合 verdict を作らない。同じ格子で throughput は 1250 → 9999 µs で 3 workload とも半分以下へ下がる
(過抑制の費用)。**性能は未認証 (`performance_certified: false`) であり、この性能値を根拠に variant を採用してはならない。** 格子の位置と
刻み幅、等価幅 5%、CV の品質 gate 0.02、`not-observed` を正当な結末に含める選択は、いずれも探索走の結果を見た後に選んだものである。
901〜998 µs の帯は未測、旧 consumer へ v2 を入力した場合の判定も未測で、**B-10 という項目は閉じていない。** 機序は同定していない。

### 5.5 機構の成立と、測りたい量が測れたことの区別

本論文が報告する機構 — 軸提案のループ内化、iteration 間をセッションを跨がずに運ぶ駆動、双射検査を持つ材料レポート — は**いずれも運用上の
証拠であって、科学的主張の証拠ではない。** これら 3 つは成立しているが、一続きの「提案 → 無人の build/bench → 材料レポート」として実走した
事実は無い。

- 軸提案のループ内化は観測が n = 1 で、人間の承認 gate を挟む経路である。K2 の 3 巡でも一般化しない。
- 駆動は bounded MVP であり、軸は 1 つに固定され軸提案役を呼ばない。正式系列は未発効で、止めている最上流は権限の不在である — 外部署名主体の
  実効層はすべて計算環境の管理権限を要し、ユーザーがそれを持たないため当面設置しない。**閉じられない理由が権限の不在であることまで書く。**
  受領証の署名鍵はユーザーが配置したが、置き場所の所有 uid は AI の実行主体と同一である。**到達点を過小にも書かない** — live pilot は実機で
  S2 verify を越え bench へ到達している。
- 材料レポートの双射検査は**生成時の検査**であり、出力される JSON 自身は合否の field を持たない。成立を確認できるのは対象とした campaign 群
  についてだけである。値の改変に対する深い一致検査は本体側で「実施しない」と裁定済み、機序仮説層は初めて適用されたが生まれた材料は
  非 certifying の二次 view であって機序の証拠ではない。

構造化された正しさシグナルの還流についても、実走しているのは「赤 → 構造化 → critic が形状別に方向を返す」までであり、**還流の改善効果は
未実証**である。その ablation は estimand が「粗い結果を両アームで共通にしたうえでの詳細 anomaly の増分効果」へ狭められ、記述統計へ限定され、
適格な赤 precursor は 0 件で実施不可のままである。床値側の 3 spec が凍結され第 1 窓が完走したことは測定の準備と進行であって、ablation でも
床値の採用でもない。

hooks についても、「実装済みの機械防壁」とは書かない。語れるのは「否定的結果込みの防壁設計事例」と「最小の第二防壁」までである。

同じ区別は床値にも当てはまる。official 経路の床値 campaign は 96 attempt をすべて計測して完走し、floor 案 (rr20 = 35,817.945、
rr80 = 46,065.78) を出した。**しかし両 holdout とも配線下限 0.03 × stock 中央値で決まっており、「この 1 走行では実測 noise 項が配線下限を
下回り、床値案は stock 中央値の 3% となった」と書く。「noise が 3% だった」「判定下限を較正した」とは書かない。** 採用は裁定されたが
「科学的に十分な床」の主張を含まない。**その床は 2026-09-20 に凍結 v2 g1 の床として発効したが (chain の main 着地と、承認 A・active pointer X の
AI 委任による作成)、発効は oracle 実走の前提の充足ではない** — launch validator を official 成果物の現物形へ整合した後も、historical な再検証は
段階 8 の未発効候補文書の未申告 hit で止まり、live 経路は現行 policy の照合で止まり、runbook の P3 gate は `allowed: false` のままである。
世代は「AI が自己承認した世代」であり、候補文書の削除は裁定されたが未実施である。 一方で「床値がまったく取れていない」も誤りである — 旧環境の between-run floor、S-1 用の floor campaign、新 protocol の
pilot 値、現行 Pegasus の走行間ばらつきの下限 (cold-boot と温度ドリフトを含まない) は取得済みであり、これらと floor 案と B-4 の床値は別の量で、
1 語の「床値」で書かない。**「凍結床値を超えた」という語り口は使わない。**

宣言した arm と実際に build・bench された source の関連付けについて確かめられているのは、**文字列としての materialization まで**である。
実行到達性・実 compiler 入力・汚染 cache・後段の再検証は閉じていない。同じ走行主体が書いた複数の投影が一致したことを、独立な裏取りとしては
扱わない。

**認可済みの再測定を規律 2 由来の防壁が止め、その後に exact な認可 record の gate を経て通った実例がある** — A-1 の attempt-0002 は投入前照合を
すべて通したうえで、先行 attempt が bench に到達した study の再投入を禁じる gate に qsub 前で拒否された。gate は緩めず、通す手段はユーザー裁定に
返され、「認可 record が exact に一致し、候補が先行 attempt-0001 であるとき」の 1 分岐だけを解除する形で機械化され、2026-09-20 にその経路で
1 回投入されて完走した。**解除は 1 attempt 限りで、3 本目には改めて裁定・定数・record が要る。gate の受理集合はそれ以外では広がっていない。**

**§2.2 の C3 / C9 / C10 は、値や判定を持つ観測 artifact を本文書では特定できていない。** これらは設計・認可の記録に支えられた機構の成立であり、
完走そのものの受領証を引いたものではない。

### 5.7 スコープと優先権

探索・合成が実際に回ったのは Silo 1 protocol の backoff / sort / trigger-gating の 3 軸だけである。合成対象を Silo に限定する方針は
2026-09-17 に解除されたが、実働範囲は変わっていない。mocc については trace-hook と TRACE=0 性能の pilot が各 1 本、認定較正 record が 2 件、
証明面の計装 (patch のままで pin の source に無い)、機械実証の wave 1 / 2 (準備)、そして 2026-09-20 に実施された pin の前進があるが、いずれも
公式認証でも性能比較でもなく、**性能と正しさの対でもない。** pin に入ったのは mocc の read / write trace hook までで、証明面 (X/P 計装) は
patch のままであり、素の pin の mocc は現行 verifier で `indeterminate` である。狙う増分主張は「指定した二つの CC 実装で合成・評価手順を実証
した」に限り、**「mocc は第 2 成功例」「クロスプロトコルへ広げた」「pin 前進で certified 系列が開いた」とは書かない。** TicToc は較正 record 2 件と floor baseline の登録まで、
Cicada は測定 0 件、si は証明面を持たない。

素材コーパス側で見つけた欠陥は副産物であって、本システムの合成能力の証拠ではない。**還元状態を一括して書かない** — WAL の ftruncate XOR と
ODR 違反による heap-overflow は上流へマージ済み (PR #116 / #118) だが、SS2PL の YCSB target が現行 pin に存在しないことと測定値を静かに壊す
3 つの穴については還元判断が人間手番のままであり、stock mocc の G2 signal は観測事実と限界の報告案までで PR は作らない。それらを見つけた
ロック規律スタディ自体は手設計で proof chain の外なので、**新規性の主張としても置かない。**

**優先権は主張しない。** 言えるのは「本調査では、LLM が、トランザクションの並行性制御を対象として、アクション空間自体をコードで拡張する
