## 1. この表を読む前に — 読み違い防止の 4 条と、欄の規則

§8 が繰り返し警告している読み違いは、表という形式にするとかえって起きやすい。
注意書きを冒頭に置くだけでは効かないので、**欄の規則として固定し、書けない文を明示的に列挙する。**

### 1.1 読み違い防止の 4 条

**G1 — (e) 欄の件数を「準備完了度」として読まない。**
(e) 欄はその行の (a) に書いた exact claim に紐づく条件である。
**claim を強くすれば B 群の項目が A 群へ移り、claim を弱くすれば逆が起きる。**
(e) 欄は距離の目盛りではなく、**いま書こうとしている文に紐づいた条件のリスト**である。

**G2 — A-3 を「実証で穴が 1 つ閉じた」と読まない。**
A-3 (P2-4 利得値の一本化) は 2026-08-25 に決着したが、決着したのは
**どの値をどの分母で報告するかという規則**であって、新しい測定でも certification の更新でもない。

**G3 — A-4 の B 群への移動を「証拠が揃った」と読まない。**
A-4 (新しい床値 protocol による official 実測) が A 群から外れたのは、
**claim の但し書きを外すのに必要でなくなったから**であって、証拠が取れたからではない。

**G4 — `fig2b` を現行契約の測定結果として扱わない。**
後継図のデータは D496 より前の記述的結果であり、図の点推定は標本平均、
本表 C1 の論文値は同じ WAL の各側 median の比である。図は論文の利得率の出所ではない。

### 1.2 この表を守っていても書けない文 (拒否文)

上の 4 条は、次の 4 文が「表を守ったまま書けてしまう」ことを防ぐために置いている。
**この 4 文はいずれも誤りである。**

- ✗「A 群の残件は 2 件なので、論文はほぼ準備完了である。」→ G1。件数は準備完了度ではない。
- ✗「A-3 が決着したので、実証の穴が 1 つ閉じた。」→ G2。決着したのは報告規則である。
- ✗「A-4 が B 群へ移ったので、床値の証拠は揃った。」→ G3。official 実測は今も未取得である。
- ✗「Fig 2b により、現行契約の下で +38.3% を確認した。」→ G4。図は現行契約の測定結果ではない。

### 1.3 欄の規則

**表は claim の種別ごとに 3 つに分けてある** (§2.1 科学的主張 / §2.2 運用・方法論の証拠 /
§2.3 文献 guardrail と副産物)。**科学的主張と運用上の証拠を同じ表に並べない** —
並べると「機構が進んだから科学的主張も順調」と読まれる。

**(a) は論文へそのまま置ける文とし、条件を文の中に持たせる。**
workload・構成・反復数・TRACE の有無・集約方法は (a) か (d) に必ず書く。
(c) の 6 値は成熟度の分類であって、保証範囲を保持しない。

**(b) は 2 段に分ける。**
`[権威 bytes]` はその値・判定が実際に書かれている成果物 (WAL、`campaign.lock`、receipt、
calibration JSON、凍結 policy JSON、生成器のソース)。
`[導出索引]` はそこから読み取った insight / report / D 本文で、
**`authority: none` を自ら宣言している文書はここにしか置かない。**
同じ走行主体が書いた投影どうしの一致は、独立な裏取りとして数えない (D920)。

**(c) は 6 値の閉じた語彙しか取らない** (§9 の分類に一致)。

| (c) の値 | 意味 |
|---|---|
| 実証済み (科学的主張) | 測って成立し、報告できる |
| 測って届かなかった | 測って不成立・棄却が確定した |
| 登録追試として成立 | 事前登録した追試として成立。新発見ではない |
| 限定付きで取れた観測 | formal / official ではない観測。正式な証拠に数えない |
| 運用上の証拠 (機構・準備) | 機構が動いた事実。測りたい量が測れたことではない |
| 未取得 | 証拠が無い |

**(d) は末尾に必ず `✗` で始まる禁止推論を 1 つ以上書く。**
その行だけを抜き出して読んだ執筆者が書いてしまう文を、あらかじめ潰すためである。
恒久的な表現規律は §3 の限定レジストリへ `L01`〜`L28` として登録してあり、(d) から ID で参照する。

**(e) は 2 行に分けて書く。**
`外せる項目:` は**その行の (d) を実際に外す**証拠、`後続別主張:` は
**その行の (d) は外さないが、別の新しい主張を可能にする**証拠である。

| (e) の行 | 意味 |
|---|---|
| `外せる項目: なし (恒久)` | 追加の証拠では外れない。表現規律・区別の規律・スコープの規律である |
| `外せる項目: <ID>〔被覆〕` | それを取ると (d) が**実際に外れる**。被覆をセル内に必ず書く |
| `後続別主張: <ID>〔…〕` | 取っても (d) は外れず、**別の新しい主張が 1 つ増える**だけである |
| `将来scope: C-n` | C-n は現在の論文の必要条件ではない |
| `要裁定` | 何を満たせば外れるかが、まだ研究方針として決まっていない |

`<ID>` は §4 の A / B 群の ID を取る (`A-1`〜`A-4`、`B-1`〜`B-10`)。
**`A-4` は §4.3 の B 群にあるが、前版との対応を辿れるよう ID を A- のまま据え置いている** (§4.3 の注記)。

**`後続別主張` を型として分けたのは、A-1 の性質のためである。**
A-1 を取っても、C1 が報告する測定が「D496 以前に行われた」という事実は変わらない。
外れるのではなく、**現行契約下の別の主張が新しく 1 つ書けるようになる**だけである。
**これを混ぜると、A/B 項目を取った時点で過去の行から但し書きを削除する
retroactive な過大主張が、この表を根拠に書けてしまう。**
`該当なし` と書くと「追加証拠が不要になった」と読まれるので、この語は使わない。

**(a) の文頭には、抜粋しても残る `〔役割〕` を置く。** 節見出しは行を抜き出すと失われるため、
表の分割 (§2.1 / §2.2 / §2.3) だけでは行単体の防護にならない。

### 5.1 測定契約の限界

本論文が報告する静的 backoff の利得 (write-heavy +38.3%、balanced +11.3%、read-heavy −6.6%) は、
旧 `linux-baremetal` 環境の trace-disabled inline sweep における**記述的な結果**である。
条件は records 1,000,000 / threads 48 / zipf skew 0.9 / rmw 0 / extime 3 秒 / `CCBENCH_TRACE=0` /
反復 5 で、集約は各側 TPS の median 比である。分母は**同一 sweep 内の無 backoff 対照**
(`BACK_OFF=0`) であって、stock の適応 backoff ではない。適応を分母に取れば write-heavy の利得は
+147.4% になるが、これは過抑制の大きさを示す診断値であり本論文の利得ではない。

これらは現在の対測定契約 (D496) より前の測定であり、**同一 campaign 内の対測定として
測り直したものではない。** 測り直しに要する反復数と判定規則は凍結済みだが、
その study の contrast は `static10 − adaptive` であり、本論文が報告する contrast
(`fixed10 / fixed5 / fixed2 − no-backoff`) と一致しない。**したがって当該 study が完走しても、
本節の限界は解消しない** — 解消するのではなく、現行契約下の別の主張が 1 つ増えるだけである。

3 workload のうち read-heavy は退行しており、**利得側 2 つだけを引用することはしない。**
機序主張は「利得は abort baseline が高いほど大きい」までであり、
「backoff は常に有害」とも「常に有益」とも読めない。
機序説明として `BACKOFF_NOINLINE` 下の +38.5% を引く場合は、それが別 CCBench revision の
perf sampling 診断値であり headline 値ではないことを併記する。
**+38.5% と +38.3% を同じ測定の丸め違いとは言わず、逆に別 regime が効果量を変えた実証とも言わない。**

### 5.2 正しさの保証範囲

verifier が担保するのは、YCSB の point read / write に限った、**観測できた trace 上の**
直列化可能性である。述語・phantom・公平性・starvation・未観測の実行は対象外である。
「正しさゲートを一度も緩めなかった」は工程上の事実であって、証明ではない。
verifier の書き込み隔離についても、ツール権限による隔離は成立していない —
正確な形は「専用書き込みツールの除去、prompt 規律による禁止、verifier 入力側の性能数値隔離」である。
検証構成の被覆にも限界があり、trace を有効にすると commits が 44% 減るため、
**S2 verify が踏む競合レートは性能計測時の約 56% 相当**である。

合成した静的 backoff が certified であることを確認したのは、**性能を測った workload とは
別の検証 workload** (tuple200 / thread4 / rmw=true) の上である。判定の権威は campaign WAL の
`verify_done` レコード (verdict `serializable` / `certified` 真 / anomalies 0) にあるが、
**そのレコード自体は検証 workload のタグを持たない** — 検証 workload の同定は別の記録に依存する。
性能 workload そのものについては、現在の根拠は「backoff は correctness-inert である」という
機序論証による外挿にとどまる。

対象 4 cell の**各 1 回**の trace はすべて `serializable` / `certified` / `total_cycles` = 0 だったが、
正式 protocol が要求する 5 反復 × 4 cell と小構成 correctness との AND は未完走であり、
**read-heavy はそもそもこの 4 cell に含まれない。** この 4 cell の所要として報告している
約 58 分は、1 反復の実測合計 695.95 秒を 5 倍した線形換算であって実測ではなく、
build・小構成 correctness・反復間 cooldown・反復間のばらつきを含まない。
なお正式 protocol を走らせるうえで余裕が薄いのは walltime ではなく検証器のメモリで、
最も重い cell (balanced × 無 backoff) のピーク RSS は 20.29 GB (判定閾値 32 GB の 63%) である。
**記録数や測定時間を増やす変更は、walltime より先にこちらの天井に当たる。**

### 5.3 合成能力についての限界

合成した軸 (trigger-gating) は、既知軸の一部である書込ロック順並べ替えには
3 workload とも floor 超で優越した (相対中央値差 +55.5%〜+98.4%、n = 8 / セル、certified 標本)。
**ここでいう certified は、性能標本そのものを検証したという意味ではない** — 性能実行は
`CCBENCH_TRACE=0` で、`certified` は同じ campaign が別に通した `legacy` tag の trace 検証、
すなわち観測できた YCSB point read / write trace 上の直列化可能性を指す。
**したがって「3 workload で certified serializable のまま既知軸に勝った」とは書けない。**
しかし**既知軸最良を上回るという事前登録した主張 (S-1a) は、測って不成立だった** (family p = 1.0)。
これは新しい否定的発見ではなく、登録した複合主張の失敗報告である。
同一コードで gate 述語だけを恒真化した対照との比較 (S-1b) は成立したが、
この効果は先行する機械 sweep 偵察で既知であり、confirmatory な新発見ではない。
族 4 のうち S-2 (発見再現性の適格率次元) は不成立 (名目 p = 0.115)、S-3 は非有意 (名目 p = 1.0) で「退化を示せる」という
主張の側を棄却した。**適格率次元の発見再現性は未実証のままであり、S-1b の成立はこの限界を
解消しない。**

**旧・主実験の事前登録に書かれた headline 比較 4 対照は、文書としては残っているが、
「4 対照が揃えば headline が出る」という見通しとしては再利用しない。**
主張 S から S' への縮小を経て S' が不成立で確定した以上、その経路はそのままでは使えない。

これらの判定について「統計的に裏打ちされた」と書けるのは S' の族補正込みの厳密検定までであり、
他の性能比較の主防壁は対測定と反復単位の対比である。反復数 5 程度の順位和検定は
完全分離で常に同じ p を返すため、有意性検定として一般化しない。

**ワークロード特化の合成ができたとは書けない。** descriptor を条件にした生成の因果証拠
(on/off、必要なら入替えの対照) が無く、selector 実験・dry-run・既知 workload の pilot は
この証拠に数えないと設計文書自身が宣言しているためである。

**LLM でなければ到達できないとも書けない。** 機械 sweep やランダム変異との同一予算対照が
未取得である。

本システムの出力契約は certified な選択結果であり、証拠が支持しなければ stock または
「差なし」を返す。**成果物を「新しい CC」とは書かない。**

### 5.4 探索についての否定的結果の射程と、機序説明の帯域

LLM 誘導探索が自明な探索空間で機械的勾配を超えず (balanced: A = 0.5813、p ≈ 0.16)、
deceptive な構造では有意に有害だった (write-heavy: A = 0.2304、厳密 permutation p = 2.52e-4、
Holm ×6 でも p ≈ 1.5e-3) という結果は、3 workload のうち 2 つについてのものである。
残る read-heavy は到達判定が情報を持たない構成 (k = 4) であり、この結論の一般化には使えない。
主指標は tie 半加算の確率優越へ再校正済みで、旧指標での読みは否定的結果を実態より強く見せる
方向であった。誘導と random の比較は未到達試行の扱いに依存する (感度幅 0.23〜0.39) ため、
**単体では headline にしない。**

backoff の機序について閉じているのは **0〜10µs 帯だけ**である。この帯では total IPC の低下が
純 spin 希釈であることを示した。25〜100µs の過抑制域では有用 IPC 自体が低下し、
stock の約 560µs 点は外挿である。「有用 IPC で積モデルが定数 K で予測的になる」は不成立と
記録されている。**spin 87.3% のような単発値を代表値として引用しない** — §7 は
その再現ばらつきを ±5〜7 ポイントと記録しており、頑健なのは
「約 560µs への駐車」と grid 刻みによる到達不能性までである。

### 5.5 機構の成立と、測りたい量が測れたことの区別

本論文が報告する機構 — 軸提案のループ内化、iteration 間をセッションを跨がずに運ぶ駆動、
双射検査を持つ材料レポート — は**いずれも運用上の証拠であって、科学的主張の証拠ではない。**
これら 3 つは成立しているが、一続きの「提案 → 無人の build/bench → 材料レポート」として
実走した事実は無い。

- 軸提案のループ内化は観測が n = 1 で、人間の承認 gate を挟む経路である。
- 駆動は bounded MVP であり、軸は 1 つに固定され軸提案役を呼ばない。正式系列は未発効で、
  止めているのは述語の欠陥ではなく、certifying 経路では承認権限ただ 1 つ、
  どちらの経路でも事前登録 artifact 3 件の不在である。
  **到達点を過小にも書かない** — live pilot は実機で S2 verify を越え bench へ到達している。
- 材料レポートの双射検査は**生成時の検査**であり、出力される JSON 自身は合否の field を
  持たない。成立を確認できるのは対象とした campaign 群についてだけで、
  bench-first screening campaign は対象外である。値の改変に対する深い一致検査は未強化、
  機序を言語化する仮説層は設計凍結のみで未実装である。

構造化された正しさシグナルの還流についても、実走しているのは
「赤 → 構造化 → critic が形状別に方向を返す」までであり、**還流の改善効果は未実証**である。
その ablation は estimand が「粗い結果を両アームで共通にしたうえでの詳細 anomaly の増分効果」へ
狭められており、事前登録が広い主張を自らの本文で禁じている。前提条件の一部は実体化したが、
**それを ablation の完走とも、critic 役の能力遮断の証明とも書かない** — 受領証の
空の道具イベント列は観測ではなく定数であり、拒否記録の不在は「記録が無い」までしか意味しない。

hooks についても、「実装済みの機械防壁」とは書かない。敵対検証が
「テキスト検査に完全性を負わせる設計は原理的に破れる」を実証し、一次防壁へ責務を再配置している。
語れるのは「否定的結果込みの防壁設計事例」と「最小の第二防壁」までである。

同じ区別は床値にも当てはまる。新しい床値 protocol は 96 attempt が全件 valid で完走したが、
得られたのは pilot 出力の `scalar_alt` (全 5 pair の max) であって official 経路の値ではなく、
発効していない。**「床値がまったく取れていない」も同時に誤りである** — 旧環境の
between-run floor と S-1 用の floor campaign は取得済みである。
**「凍結床値を超えた」という語り口は使わない。**

宣言した arm と実際に build・bench された source の関連付けについて確かめられているのは、
**文字列としての materialization まで**である。**実行到達性・実 compiler 入力・汚染 cache・
後段の再検証は閉じていない。** また、同じ走行主体が書いた複数の投影が一致したことを、
独立な裏取りとしては扱わない。独立と呼べるのは、権威ある byte 列から計算し直した値だけである。

**§2.2 の 3 行 (軸提案のループ内化、bounded MVP による駆動、材料レポート) は、
値や判定を持つ観測 artifact を本文書では特定できていない。** これらは設計・認可の記録に
支えられた機構の成立であり、完走そのものの受領証を引いたものではない。

### 5.6 図と数値の出所

後継図 `fig2b` は本論文の利得率の出所ではない。図の点推定は標本平均であり、
本文の利得率は同じ WAL の各側 median の比である。両者は同じ生値の別の要約であって、
一方が他方の丸め違いではない。またこの図のデータは現行の対測定契約より前の
記述的結果 (`HISTORICAL_RAW`、verifier epoch E0) である。
縦軸は workload ごとに独立なので、パネル間で線の高さや傾きを直接比較しない。
**旧図 `fig2_backoff_mechanism.png` は使わない** — 横破線に `stock adaptive backoff` と
label されているが、その値は無 backoff である。

### 5.7 スコープと優先権

対象は Silo ベースの 1 protocol であり、**複数プロトコルから選ばせる問題設定は採っていない。**
探索・合成が実際に回ったのは backoff / sort / trigger-gating の 3 軸だけである。
mocc については trace-hook (TRACE=1) と TRACE=0 性能の pilot が各 1 本あるが、
いずれも公式認証ではなく、**性能と正しさの対でもない** (TRACE=0 の走行では verifier は
実行しておらず、2 本は CCBench source も異なる)。TicToc / Cicada は未移植である。

素材コーパス側で見つけた欠陥は副産物であって、本システムの合成能力の証拠ではない。
**還元状態を一括して書かない** — WAL の ftruncate XOR と ODR 違反による heap-overflow は
上流へマージ済み (PR #116 / #118) だが、SS2PL の YCSB target が現行 pin に存在しないことと
測定値を静かに壊す 3 つの穴については、還元判断が未了である。
**この target 不在は現行 pin の source tree について確かめた事実であって、
「過去一度も SS2PL を YCSB で測っていない」という履歴の主張ではない** — 履歴監査はしていない。
それらを見つけたロック規律スタディ自体は手設計であり、評価パイプラインを経由しない
proof chain の外の記述的スタディなので、**新規性の主張としても置かない。**

**優先権は主張しない。** 言えるのは「現行の related-work 調査では該当例を未発見」までであり、
系譜の中で何本目かを数える書き方も採らない。
