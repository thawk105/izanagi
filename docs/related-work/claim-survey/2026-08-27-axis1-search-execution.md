### 4.1 `predicate-defect` — 述語側の欠陥 (条件 3)

契約 §7 の条件 3 は「各ページについて、要求件数・索引が宣言した件数
(`itemsPerPage` / `meta.per_page` / `@sent`)・実際の要素数が一致する。
最終ページだけは、宣言件数と実要素数が一致し …」と書く。

**実測: arXiv の `itemsPerPage` と OpenAlex の `meta.per_page` は要求値をそのまま返す。
頁の実要素数ではない。**

| 索引 | 最終頁の要求 | 最終頁の宣言 | 最終頁の実数 |
|---|---|---|---|
| arXiv (`AX1-Q3@arxiv`) | 200 | **200** | 105 |
| OpenAlex (`AX1-Q1@openalex`) | 200 | **200** | 124 |
| DBLP (`AX1-T01@dblp`) | 100 | **36** | 36 |

DBLP の `@sent` だけが実要素数である。したがって条件 3 は、宣言総件数が頁サイズの倍数でない限り
arXiv と OpenAlex では満たされない。**予算をいくら積んでも変わらない。**

**観測の範囲。** 本 wave が実行した arXiv の全 6 枝と OpenAlex の全 4 枝で例外なくこうなった。
**API の仕様書は読んでいないので、恒久的な API 契約としては断定しない。**

条件 3 の目的は §7 が明記するとおり切り詰めの検出である。**その目的は
「要求件数 == 実要素数、ただし最終頁は 位置 + 実要素数 == 総件数」で達成できる。
しかし述語は凍結物であり、本文書は書き換えない。** 可否はユーザー裁定へ返す (§8 の U1)。

### 4.2 `index-property` — 索引側の性質 (条件 4・5、OpenAlex)

`AX1-Q1@openalex` の重複 6 件の実体は次のとおりである。

### 4.5 `transport` — DBLP の切断

DBLP は連続取得で接続を切る。2 秒間隔では 24 リクエスト目付近から、15 秒間隔でも 7 リクエスト
程度で `RemoteDisconnected` が 3 回の再試行 (契約 §8 の 3→6→12 秒) を通り抜けた。
**45 分の冷却の後、30 秒間隔で再走したところ回復した。**

契約 §8 は再試行上限の到達をその走行の `未完走` と定める。**失敗した走行の証拠も
