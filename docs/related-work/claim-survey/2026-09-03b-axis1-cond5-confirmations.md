### 2.3 `申告総数 − distinct` を非返却件数と読んではならない

この差を「その走が取りこぼした件数」と読むには、その走の申告母集合が固定されていて、
返却 ID がすべてその母集合に属することが要る。**頁内重複 0・非隣接重複 0 はそこまで言わない。**

`Q1` と `Q2` については、別の走が `distinct == 申告総数` ちょうどに到達している。
しかしそれが示すのは**その件数が別の時点には到達可能だった**ことだけで、
失敗した走で stale な件数・削除・統合・同数の入れ替わりが無かったことは示さない。
`Q4` と `Q5` は走が 1 本しかなく、申告総数に幻の件数が含まれる可能性を排除できていない。

## 5. 観測された機序 — 有力な説明であって、確定した機序ではない

**次の説明は観測と整合するが、本文書はこれを単一の原因として確定しない。**

> 関連度順の cursor 走査中にスコアが動くと、cursor の鍵より上へ動いた record は
> 次の頁でもう一度返り (= 頁境界の重複)、下へ動いた record は飛ばされる (= 非返却)。

### 5.1 実測が否定できるのは「三つ組が変わらない単純な再送」だけである

- 頁境界で再出現した **32 occurrence すべてが、前頁と異なる三つ組を持っていた**
  (三つ組が同一のまま再出現した例は **0 件**)。変わっていたのは `relevance_score` である
- **32 件のうち 23 件は、前頁の cursor 鍵が指す record そのもの**だった

したがって **「cursor 位置の record が、内容を変えずにそのまま再送される」という説明は否定できる** —
再出現した record は 1 件残らずスコアが変わっている。

**一方、cursor の境界規則そのものは否定できない。** 重複の 3 分の 2 以上が cursor 鍵の record
自身であることは、境界が包含的に振る舞う説明とも整合する。
両者を切り分けるには、その走の各時点で索引側がどの値を持っていたかが要るが、証拠に無い。

**この節の初版は「cursor 鍵の ID と一致は 0 件」と書いていた。これは誤りである。**
親の probe が cursor を復号しきれておらず (base64 の中が二重に包まれた文字列であるため、
1 度の解釈では配列でなく文字列が返る)、比較が常に偽になっていた。
段 6 のレビューが出力の明細を数えて食い違いを見つけ、親が probe を直して測り直した。

### 5.2 それでも単一機序とは言えない

欠落が起きた走の、その時点における当該 ID の索引側スコアも、
全頁に共通する snapshot 識別子も、証拠に残っていない。索引の内部更新履歴も取れない。
**新規に取得しても過去時点の状態は復元できない。**
頁ごとに異なる replica を引いた、record の追加・削除・統合が起きた、といった説明を排除できない。

### 5.3 非返却 record の位置

非返却の 2 件は、どちらも返した走で頁境界にあった。

- `W7168152262` — 頁 2 の 199/200 (**その頁の最終行そのもの**、= その走の cursor 位置)
- `W7161158986` — 頁 7 の 1/200 (cursor 再開の 2 行目)

## 7. 本文書が決めていないこと

### 7.1 登録された独立第 2 走の安定性は未観測である

どの leaf が独立第 2 走を要求されるかは catalog の `independent_pass_required` で決まる。
実測すると OpenAlex の 80 論理 query のうち **76 件が `True`** (Q3 / Q6 の全 shard leaf と
2 つの aggregate) で、**`False` はちょうど 4 件 — `Q1` / `Q2` / `Q4` / `Q5`** である。

**現在 条件 5 が不成立なのは 3 leaf — `Q1` / `Q4` / `Q5` である** (判定器は最後の attempt を
採るので、`Q2` は 2 走目が 1606 = 申告総数に到達しており通っている)。
この 3 leaf は上の `False` 4 件に含まれる。
**すなわち条件 5 で落ちている leaf は、いずれも独立第 2 走を要求されていない。**
§3 で測った digest 不一致は、登録上の pass 1 と pass 2 の比較ではない。
