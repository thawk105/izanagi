## 1. Phase 3 着手前に閉じる(blocking / 着手と同時)

LLM が C++ を合成し始める Phase 3 の最初の非 stock variant で顕在化する一群。今がちょうどその境界。

- [ ] **[HIGH]** loop の recovery/dedup/abort キーが `src_token` 非対応 — `orchestrator/campaign/loop.py:63,76`
  `run_campaign` は skip 判定・例外 abort の両方で `v = variant_id(g)`(`src_token` を渡さない=常に
  `"stock"` id)を使う。一方 `pipeline.evaluate` は `variant_id(genome, src_tok)`
  (`orchestrator/campaign/pipeline.py:135`)で WAL を書く。coder が working-tree を書き換えると
  WAL 終端 id は src-token id になり、loop の `done` 集合(stock id で seed)と永久に一致しない
  → 評価済み coder variant の再評価(冪等リカバリ = ACID の **D** 破綻)+ 例外 abort が別 id に付き
  src-token id の `BUILD_START` が孤児化(**A** 破綻)。D23 が identity を「コードの差」まで覆ったのに
  消費側(loop)が旧キーのまま取り残されている。**3 次元(再現性/テスト品質/規律横断)から収束。**
  **修正:** id 確定を `evaluate` に一元化し loop は WAL/evaluate の返す `v` を信頼する(identity 確定点の
  二重化=偽 hit 源を減らす)、または loop でも `src_token` を計算して揃える。Phase 2 は全 genome が
  stock 正規化されるため**潜伏中**。

- [ ] **[MED]** 非 stock(coder)variant 経路の回帰テストが無い — `orchestrator/tests/test_campaign.py:475`
  loop テストの fake evaluate も stock id を使うため両者一致で緑になり、上記 HIGH を CI で捕まえられない。
  **修正:** `src_token != "stock"` を `run_campaign` に通す回帰テストを追加(HIGH とセットで)。

- [ ] **[MED]** online_digest のリーク検知 assert が実呼び出しでは恒真で発火しない —
  `orchestrator/critic/online_digest.py:33-38`
  唯一の本番 caller(`orchestrator/campaign/guided.py:_print_state`)が渡す `iterations` も assert 側の
  `d.genomes` も**同じ誘導 WAL の `STAGE_COMMIT` を数える二つの式**なので、真のリークでも両方が等しく
  増え `n > iterations` が成立しない。P2-5 の中立性(D14 / 規律6)を担保すると謳う「WAL 分離だけに頼らない
  二重の関所」が実際には WAL 分離のみに依存。**修正:** `iterations` を WAL commit 由来でない独立カウンタ
  (検疫を通過した evaluate 回数等)から取る。
  ※ コメントのファイルパス誤記(`critic/guided.py` → `campaign/guided.py`)も併せて訂正。

- [ ] **[LOW→要対応]** `assert_worktree_within_allowlist` の untracked 死角 + EVOLVE-BLOCK の生 `#include`
  禁止 hook が未実装 — `orchestrator/campaign/source_digest.py:198`
  allowlist 検査は untracked(`??`)を build 生成物として無視し、digest は `#include` を剥がすため、coder が
  新規 untracked ヘッダを作り `backoff.hh` から include すると allowlist と digest の両方をすり抜けて
  **偽 cache hit**(正しさゲートを通っていない variant を緑として再利用)になりうる。下記 hooks 未実装の系。
  **修正:** Phase 3 hook で (1) EVOLVE-BLOCK 内の生 `#include` を reject(D23 道Y)、(2) designated patch
  以外への Write 拒否。digest 側の安価な硬化として「submodule に untracked が 1 つでもあれば停止」も検討。

- [ ] **[NIT→着手と同時]** hooks/ の規律1・2 機械防壁が未実装・settings.json 配線 0 件 — `hooks/README.md:7-13`
  CLAUDE.md は「hooks/ に規律1・2 の自動執行を置く」と現在形で書くが実体は README のみ。README/CLAUDE.md
  現在地とも documented gap だが、防壁(`#ifdef TRACE` 越境検出 / verifier 迂回検出)は LLM が C++ を書く
  Phase 3 で load-bearing 化する。**修正:** Phase 3 着手 PR に hooks 実装 + settings.json 配線を同梱
  (kickoff prep のチェック項目に固定)。
