# 探索の独立反復の試走 — 5 手法の費用・成果曲線を取り、本比較の規模を探索間の分散から決める規則を結果を見る前に固定する事前登録

本書は、VLDB 向け差分分析の P3 (探索の独立反復で費用と成果の曲線を取る) の**試走**の規則と、その試走から
**本比較の規模を決める規則**を、結果を見る前に固定する ([T-2850]、D2212)。固定するのは次の 6 つである。

1. 試走の規模 — protocol・空間・課題・手法・独立探索数・候補数 (§2・§3)。
2. 予算と費用上限 — B・A・初期点の数 k・N_eval・系列数・試走の費用上限 (§3・§9)。
3. 記録項目 — 有効候補率・観測上の改善閾値への初到達時間・検証時間・node 時間・人間の介入。複製候補と compile 失敗も費用に含める (§5)。
4. 候補評価数を揃えた比較と、経過時間を揃えた比較の分離 (§6)。
5. 比較の族・推定量・同等幅・分類 (§7)。
6. 本比較の系列数を試走の探索間の分散から決める規則 (§8)。

**本書は事前登録の作成だけを行う。** 実走、runner の実装、計算投入、gate・検査・台帳の追加は含まない。本書が存在する
ことは測定の認可にならない。試走の投入は、比較基盤 [T-2849] の実装が着地した後に、別 wave が node 時間と LLM の
直列時間の見積りを示してユーザーの計算確認を取ってから行う (D2212 項 4)。

一次資料は `output/insights/2026-09-21/vldb-direction/gap-analysis.md` §4 P3 と、同じ dir の `codex-consult-1.md` の
優先 2 である。比較基盤の設計は D2220 と `output/insights/2026-09-22/t2849-comparison-harness-design/README.md`
(以下「基盤設計」) が正本で、本書は基盤設計が「[T-2850] の事前登録へ残す」とした値 (基盤設計 §5.6 の末尾) を決める。
生成器の操作的定義・費用の計上単位・endpoint の規則は基盤設計の §3〜§5 をそのまま使い、本書へ再掲しない。

## 1. 主張の形と、主張しないこと

### 1.1 試走が出すもの

試走は**記述だけ**を出す。検定も優越・同等の分類もしない。出すものは次の 3 つである。

1. 課題ごと・手法ごとの費用・成果曲線と §5 の記録項目 (記述)。
2. 本比較の規模を決める入力 — 探索間の分散、1 系列の費用、LLM の直列時間、経過時間の checkpoint T_c、失敗の種類 (§8)。
3. 実行上の不具合の一覧 (実装が本書・基盤設計と食い違った点)。

### 1.2 本比較で許す主張の形 (本書が規則を固定する)

> 課題 t (protocol・空間・workload) で、固定した予算 (評価数 B、または B ≤ 10・A ≤ 30 の探索を共通の時刻 T_c で切った時点) の下、
> 手法 m の探索系列が選んだ endpoint の score は、手法 m′ のそれに対し [優越 / 退行 / 実用上同等] だった。分類は、登録した
> 独立・近似正規の仮定の下での族ごとの同時区間による (§7)。

- 比べるのは基盤設計 §1.3 の意味での**構成** (空間・支持集合・情報構成 R0・初期点・予算を含む) であって、LLM 単体・
  critic・知識の因果効果ではない。
- 評価数を揃えた結果と、経過時間を揃えた結果は別の主張で、一方を他方の根拠にしない (§6)。
- 結論は本比較で選んだ課題に限る (§8.4)。

### 1.3 主張しないこと

- 試走の値を本比較の標本・予測的再現・効果の推定に使うこと (§8.4)。
- 基盤設計 §1.3 の「主張しないこと」の全項 (LLM の必要性、有限空間の結果のコード合成一般への拡張、K0 を
  「事前学習知識なし」と読むこと、certified を全実行の証明と読むこと、S1 の結果の headline 化など)。
- 経過時間の比較を「同じ時間を自由に使わせた手法の比較」と読むこと。どの手法も B = 10 で止まる (§6.2)。
- 未知条件への転移 (転移登録の範囲)。他 protocol・他環境での成立。
- 金額としての費用。token 数を金額へ換算しない。サブスクリプションで動く CLI が示す費用の値は請求額ではない。

## 2. 課題 — 試走は Silo の S1 で 2 workload

### 2.1 用語

- **空間:** 基盤設計の S1 (silo の backoff 値 1..1000 µs)・S2 (MOCC の backoff 値)・S3 (policy IR、D2214)。
- **課題:** (protocol, 空間, workload) の組。workload は転移登録 §2.1 の錨 wh・bal・rh のどれか。
- **cell:** (課題, 手法)。
- **系列 (独立探索):** 1 つの cell で、fresh context・固有の seed preimage で始め、系列開始 stock から endpoint の再計測までを
  1 回やり通す探索。候補を測り直すことは系列を増やすことではない (一次資料の原則)。統計単位は系列である (基盤設計 §5.6)。

### 2.2 試走の課題

| 課題 | protocol | 空間 | workload | 選んだ理由 |
|---|---|---|---|---|
| S1-wh | Silo | S1 | wh (読み比率 5) | 既知の記録で backoff 値への感度が最も大きい錨で、探索間の分散が大きいと見込む (§11) |
| S1-rh | Silo | S1 | rh (読み比率 95) | trace の commit 数が最も多く検証費が最も大きい錨で、本比較の費用見積りの最大の不確かさを実測で置き換える |

- bal は試走に入れない。本比較に bal を入れるときは、§8 のとおり試走した課題の最大値を流用する。これは**未検証の外挿**で、
  bal での精度を保証しない。bal は E_T の族にも入らない (§6.2)。探索差を見る機会を優先するなら wh・bal の組もありえたが、
  rh の検証費を実測する利点を採った。
- **一次資料の案 (2 protocol × 2 課題) から縮めた理由:** 起草時点 (2026-09-23) で走らせられる空間は S1 だけである。S2 は、MOCC の pin 候補が
  /rulings 第 32 回 (2026-09-23) 項 1 で承認され更新 wave を起こす段階で、gitlink・pin の更新、loop の genome の protocol 化と MOCC の
  動作点の較正 (基盤設計 §9.3) が済むまで無効である。S3 は段階 C が着地し段階 D が起票された段階で、S3 上の BO・進化の方式も未定である
  (基盤設計 §6.4・§10)。
- **空間を足すとき:** S2 または S3 を試走に足すには、その空間の最初の生成より前に追補で、課題・手法の定義・初期点・支持集合の扱い
  (基盤設計 §10)・その空間の予算・費用上限・checkpoint を登録する。その空間の分散はその空間の試走からだけ推定する。S1 の分散を
  他の空間へ流用しない。

### 2.3 学習条件と留保条件

- 試走と本比較の学習条件は、転移登録 §2.1 の錨の部分集合である (S1-wh と S1-rh は錨 wh・rh と引数が全て一致する。
  レコード数 1,000,000・thread 数 48・extime 3 秒・Zipf skew 0.9・操作数 10・blind write)。
- 転移登録 §3.1 の不使用義務に従い、転移登録 §2.3 の留保条件・その測定結果・それらから作った指示や設定を、
  生成器・生成のための評価・選択に入れない。runner の smoke と動作確認は、錨または検証用の小規模 workload
  (`CorrectnessWorkload`) の引数で行う。
- 各 cell について、生成・選択に関わる主体が repo の docs を読めたかを記録する (転移登録 §3.1)。起草時点の見込みは次の
  とおりで、試走の記録で確かめる: planner と coder の role は tool を持たないので読めない。critic の role は file を読む
  道具を持ち、LLM の親 session も filesystem を読めるので「読めた」と記録する。非 LLM の 4 手法は、実装が読む入力を列挙して記録する。
- 対象探索群の名指し (転移登録 §3.2) は転移登録の発効の決定が行い、本書はしない。

## 3. 手法・予算・系列数

### 3.1 手法

手法は基盤設計 §3 の 5 つ (random・sweep・BO・進化・LLM (K0)) で、情報構成は主構成 R0 (参照値を生成器へ渡さない、
基盤設計 §4.4) だけとする。R1 は試走でも本比較でも走らせない。LLM (K2 知識つき) は本書の手法に入れない (B-5 の構成、§12)。

手法の定数は基盤設計の案の値を本書で確定する: random の log-uniform 重み、sweep = `EXTENDED_SWEEP_US` の 29 点から 0 を除いた
28 点 (B-5 の格子) からさらに初期点の 5 と 10 を除いた 26 点を preimage の SHA-256 昇順、BO = x = ln v・Matérn 5/2・雑音分散 (ln 1.03)²・
追加 design 0、進化 = (1+1)・λ = ln 4、初期点 = 静的 5 µs → 10 µs の順 (k = 2)。本書が値を書いていない実装の定数 (BO の超パラメータの格子・
jitter など) は、発効束 (§10) で固定する。

**試走で調整する定数は無い。** 試走の結果を見て手法の定数を変えない。性能を理由とする変更は、どの手法についても行わない
(1 手法だけを調整すると構成の比較が崩れる、基盤設計 §8)。実装の修正は、本書・基盤設計・発効束との具体的な食い違いを示せる
場合だけ追補で行い、影響を受けた試走の系列を列挙する。修正前の系列は、修正後の構成の分散の推定 (§8) に混ぜない。

## 4. 配置と順序

- **block:** 試走は 3 block、本比較は n block (n は §8 の系列数) に分け、block b には全 cell の系列番号 b を 1 本ずつ置く。
  block 間は、前 block の最終測定から次 block の初回測定まで少なくとも 1 時間空ける (B-5 §7.1 と同じ。独立性の証明ではない)。
  §7 の対は同じ block の系列どうしで、共通の時間帯に揃えるための対づけである。探索の seed の共有や正の相関は保証しない。
- **job:** 1 系列 = 1 job = 1 node。block stock と参照点 (`p2_2_flag_opt`) は (workload, block) ごとに別の 1 job とする。
  job の開始時と終了時に `docs/pegasus-runbook.md` の手順で node の単独性を確かめる。
- **投入順:** block 内の job の投入順は、job 識別子 `<課題>|<手法>|s<b>` と `<課題>|block|s<b>` を辞書順に並べた列を、鍵
  `t2850-trial-order-v1|<b>` (本比較は `t2850-main-order-v1|<b>`) から転移登録 §5 と同じ Fisher–Yates の手順で並べ替えて決める。
  LLM の同時系列は親の本数 p = 4 以下 (D2216)。試走は 3 block それぞれに LLM 系列が 2 本で、この上限に当たらない。
- **seed preimage:** 系列の preimage は `t2849-harness-v1|<arm>|<workload>|t2850-trial-s<b>` (本比較は `t2850-main-s<b>`) とする
  (基盤設計 §3 の名前空間の案に系列 id を入れる)。試走と本比較は重ならない。
- **walltime:** 探索系列の job は全 arm 同じ W とする。D2217 から継承するのはこの「全 arm 同一」だけである。試走は、本書の手法の
  実測の最大所要がまだ無いので、LLM 系列の試算の上側 (rh で A = 30 を使い切る場合 26,526 + 15,600 = 42,126 秒) を覆う gen_S の上限
  86,400 秒 (24:00:00) とする。block job は試算の上側 10,670 秒の 3 倍の 32,010 秒とする。どちらも試算に基づく値で、完走を保証しない。
  本比較の W は試走の実測の最大所要から、本比較の計算確認で決める。walltime の不足は系列の定義や正しさの条件を下げる理由にしない。
- 順序・配置・preimage は結果を見て選び直さない。

## 5. 記録項目

基盤設計 §4.1・§5.5・§5.6 の記録 (slot の種別・候補・結果の分類・fitness・CV・leading indicators・anomaly の digest・
3 つの時刻、job Elapse、slot の wall の内訳、生成器の計算時間、LLM の役割呼び出し、親の待ち、人間の介入) に加え、
系列ごとに次を集計する。**複製候補と compile 失敗は、下のどの費用からも除かない。**

| 項目 | 定義 |
|---|---|
| 有効候補率 (A 基準) | certified・品質正常の探索評価の数 / 消費した A |
| 有効候補率 (B 基準) | certified・品質正常の探索評価の数 / pipeline へ投入した B。A の枯渇で B が 10 に届かない系列もその B で割り、B = 10 で割った「予算あたりの有効評価数」を併記する |
| 一意な候補の数 | 系列内の一意な identity の数 (基盤設計 §5.2 の重複の集計) |
| 失敗の内訳 | 提出機会ごとの結果の分類 (空出力・schema・文法・検疫・Tier0 の compile / smoke・pipeline の build・anomaly・品質欠測・機械故障の retry と上限超え) の件数 |
| 複製候補 | 同じ系列で評価済みの identity の再提案の件数と率。A と B を消費し、費用に入れる |
| 観測上の改善閾値への初到達時間 | 探索 slot のうち、certified・品質正常で、探索時の session median が自系列の初期点の最良 (certified・品質正常のもの) を ln 差で δ = ln 1.03 を超えて上回った最初の slot について、t0 から結果が使えるようになった時刻までの経過時間と、その時点の B・A。該当が無ければ系列の終了時刻での打ち切りとして記録する。1 session の値の比較なので、雑音で偶然成立しうるし、真の改善の発見を意味しない。cell ごとに**未到達の系列の数を必ず併記**し、到達した系列だけの平均を代表値にしない。初期点がどちらも不成立の系列は、比べる相手を系列開始 stock にした別集計に入れる |
| 同 (副) | 比べる相手を系列開始 stock にしたもの |
| 最初の certified 候補までの時間 | 探索 slot で最初に certified・品質正常になった slot の時刻と B・A |
| 検証時間 | slot ごとの correctness の build と verify の wall の和 (基盤設計 §5.5 の内訳)。Tier0 の compile / smoke の wall は別の欄。正しさ確認の総費用ではなく内訳の値である |
| node 時間 | 系列の job Elapse (job ごとに 1 回)。block job は系列へ割り付けず別に集計する |
| 経過時間 | t0 (系列開始 stock の開始) から各 slot の結果が使えるようになった時刻まで。queue 待ちは別欄 |
| LLM の直列時間 | LLM 系列で driver が提案を待った時間 (handshake の待ち) の和。役割呼び出しの回数と wall は内訳として残し、足さない (待ちの間に行われるので二重に数えない)。token 数は報告値を残すが金額にしない |
| 人間の例外の介入 | 定めた運用の外の手作業 (再起動・再投入・手での修復・判断) の回数・時刻・内容。0 件も記録する。定めた LLM の親運用の作業は含まないので、人間の総労力ではない |
| docs への到達可能性 | §2.3 の記録 |

- **曲線:** 系列ごとの「探索時の最良値」(結果が使えるようになった certified・品質正常の候補の session median の最大) を、B (0〜10) と
  経過時間の 2 つの軸で描く。B = 0 は初期点だけの時点である。系列の値は階段関数で、結果が使えるようになった時点から次の更新まで保ち、
  探索が正常に終わった後 (B 完走・A の枯渇) は最後の値を軸の終わりまで保つ。まだ certified・品質正常の候補が 1 つも無い点と、機械故障の
  上限超えで探索が途中で終わった系列の、終わった時点より後の点 (経過時間の軸では終了時刻より後、B の軸では最後に投入した B より先) は
  「値なし」とする。曲線は探索時の値だけで作り、endpoint の再計測の結果 (score 欠測を含む) は曲線に当てない。主図は (課題, 手法) ごとに、各点で値のある系列の中央値と最小〜最大の帯を示し、
  その点で値のある系列の数を併記する。
  **探索時の最良値は再計測していない 1 session の最大で、評価数が多いほど上に偏る。** 曲線は記述に使い、比較の分類には §6 の
  再計測した endpoint だけを使う。
- 欠測・A の枯渇・fallback は系列の結果として残し、系列を差し替えない。

## 6. 候補評価数を揃えた比較と、経過時間を揃えた比較

2 つの比較は同じ系列から作るが、endpoint も族も別にする。

### 6.1 評価数を揃えた比較 (族 E_B)

- endpoint は基盤設計 §4.6 の規則による B = 10 時点の endpoint (初期点を含む資格ある候補のうち、探索時の session median が最大の
  もの) で、N_eval = 5 の fresh session の median を score とする。欠測・fallback・判定不能の優先は基盤設計 §4.6 のとおり。

### 6.2 経過時間を揃えた比較 (族 E_T)

- **checkpoint T_c(t):** 課題 t の試走で、非 LLM の 4 手法の系列のうち B に達したものについて、「B 番目の探索評価の結果が使えるように
  なった時刻 − t0」の中央値をとり、秒へ切り上げた値。B に達しなかった系列 (A の枯渇・機械故障の上限超えなど) の数を併記する。
  B に達した系列が 0 本なら、課題 t の E_T は定義しない。T_c は性能の値を使わず所要の記録から式で決まるが、所要そのものは候補の性能に
  依存しうる (throughput が trace 量と verify 時間を変える)。T_c は試走の後・本比較の前に追補へ書く。
- **試走では E_T の endpoint を再計測しない。** 試走は T_c を決めるだけで、E_T の score を作らない (試走の系列が終わるまで T_c が
  決まらず、系列の job の中で再計測できないため)。本比較の系列数は E_B の分散だけで決め (§8)、E_T は同じ系列数で走らせて、
  得られた精度をそのまま報告する。E_T について計画精度を約束しない。
- **本比較の endpoint:** 各系列で、t0 から T_c までに結果が使えるようになった候補 (初期点を含む) のうち、§6.1 と同じ資格と同値規則で
  選んだ候補。T_c をまたいで走っている候補は入れない (基盤設計 §5.6)。
- **本比較の score:** その候補の N_eval = 5 の fresh session の median。候補が §6.1 の endpoint と同じ identity なら、同じ再計測の session を
  使う (選択は再計測の前に確定しており、2 つの独立な再現とは数えない)。違う identity なら、同じ job の中で別に 5 session 測る。
- **欠測・fallback の範囲:** E_T の欠測・fallback は、T_c までの履歴と E_T の endpoint の再計測だけから基盤設計 §4.6 の優先で決める
  (T_c より後の機械故障で E_T を欠測にしない)。T_c の時点で**単に走っている途中の候補**は、機械故障の未解決とは扱わず「T_c までに結果が
  出ていない候補」として endpoint の候補から外すだけにする。したがって基盤設計 §4.6 の優先を T_c までの履歴に当て、次の順で決める:
  (1) stock (系列開始 stock または block stock) の正しさか測定が成立しない → 基盤設計 §4.6 の 1 のとおり当該比較は判定不能。系列開始 stock が
  T_c までに終わらなかった系列は E_T の score 欠測。(2) T_c までに機械故障が retry 上限を超えた、または機械故障による結果の未解決がある
  (単に走っている途中の候補は除く) → endpoint の有無を問わず score 欠測。(3) T_c までに結果が出た資格ある候補が 1 つでもある → その最良が endpoint。(4) 資格ある候補が無く、T_c までに結果が出た slot に品質欠測がある →
  score 欠測。(5) それ以外 (T_c までに結果が出た候補が無い、またはすべて候補起因の失敗) → block stock の fallback。endpoint の再計測の anomaly・
  品質欠測・機械欠測は §6.1 と同じ扱い。anomaly による endpoint の資格の喪失は、時刻によらず全系列へ波及させる (基盤設計 §4.6)。
- **追加の評価はしない。** T_c より後に終わる系列 (多くは LLM) は T_c までの候補で比べ、T_c より前に B を終えた系列 (多くは非 LLM) は
  B までの候補で比べる。E_T は「B ≤ 10・A ≤ 30 の探索を、非 LLM の手法が B を終える典型的な時刻で切った比較」であり、非 LLM の手法に
  B を超えて評価させた場合の比較ではない。全手法が T_c までに B を終える、または T_c の後に最良が更新されない課題では、E_T は E_B と
  ほぼ同じになる。
- E_T の checkpoint は試走した課題にだけ定まる。本比較の試走していない課題 (例: bal) は E_T の族に入れず、経過時間の曲線を記述として
  示すだけにする。

### 6.3 分離の規則

- E_B と E_T は別の族で、それぞれ family-wise 5% で区間を作る (§7)。報告では族を明示し、片方の族の結果をもう片方の族の主張として書かない。
- node 時間 (job Elapse の和) の軸は記述だけにし、族を作らない (経過時間と node 時間を混ぜない、基盤設計 §5.6)。

## 7. 比較の族・推定量・分類 (本比較に適用する)

試走は §1.1 のとおり分類しない。本節は本比較の規則である。

- **族:** 課題ごとに 5 手法の全 10 対。族 E_B の大きさは M = 10 × (E_B に入る課題数)、族 E_T は M_T = 10 × (E_T に入る課題数)。
  LLM を含む 4 対だけに絞らない (本研究の問いは、空間の構造によってどの探索法が効くかであり、非 LLM どうしの対も問いの一部である)。
- **推定量:** 同じ block の系列どうしを対にし、対差 d_b = ln(score_m,b / score_m′,b) の平均 d̄ と標準偏差 s_d を使う。fallback の score は
  候補を採用できなかった運用の score として含める (B-5 §6 の意味。fallback を含む対の数を添える)。
- **資格:** 比較 (t, m, m′) が族で分類されるのは、予定した n 対のすべてで両方の score が得られた場合だけである。score 欠測 (機械故障の
  上限超え・品質欠測・再計測の不成立) を含む対が 1 つでもあれば、その比較は判定不能とする。欠測は候補や手法の性能・所要と無関係とは
  限らず、残った対だけで推定すると対象が「両方の score が得られた系列」に変わるからである (B-5 §7.4、転移登録 §6.1 と同じ)。その場合も、
  欠測の件数と理由、残った対の d̄ と無補正の 95% 区間を記述として添える。残った対が 0 なら平均も区間も算出不能、1 なら対差だけを示す。
- **区間:** 族ごとに Bonferroni の両側の同時区間 d̄ ± t(1 − 0.025/M, n − 1) × s_d / √n。仮定は対差の独立と近似的な正規性で、検査しない。
  最大値の選択と fallback を含む score は混合分布になりうるので、系列数が少ないほどこの近似は強い仮定になる。同じ block の対に共通に入る
  時間の揺らぎは対差の相関を生みうる (B-5 §7.3 と同じ限界)。主張には「登録した独立・近似正規の仮定の下で」を添える。
- **同等幅と分類:** δ = ln(1.03) = 0.029559 (転移登録 §6.2 と同じ値)。区間 [L, U] で、優越 L > δ、退行 U < −δ、実用上同等
  −δ < L かつ U < δ、それ以外は判定不能。結果を見た後に δ を広げない。
- 族に入らない量 (stock 比、`p2_2_flag_opt` 比、有効候補率、初到達時間、曲線) は記述で、区間を付けるなら無補正と明記する。
- endpoint が初期点か探索点か、探索点の最良が初期点の最良を超えたかを、系列ごとに数えて cell ごとに併記する (基盤設計 §4.5)。

## 8. 本比較の規模を決める規則

### 8.1 入力

試走の後、次を計算して追補に書く。**入力に使ってよいのは分散・費用・所要・失敗の種類だけで、手法間の差の値 (どの手法が
勝ったか) と曲線は使わない。**

- **cell の標準偏差 s_{t,m}:** 課題 t・手法 m の試走の系列のうち、E_B の score が得られたものの ln score の標本標準偏差 (分母 n − 1)。
- **計画の対差標準偏差:** s_plan = 試走したすべての課題 t と手法対 (m, m′) にわたる √(s_{t,m}² + s_{t,m′}²) の最大値。対の 2 系列の相関を
  0 とみた値で、正の相関があれば大きめになる。上側信頼限界の係数は掛けない (各 cell の自由度は 3 本の score が揃っても 2、2 本なら 1 で、
  その上側限界は規模を決める情報にならない)。本比較の区間は本比較の標本だけから作るので、s_plan の誤りは誤分類の率ではなく達成される精度に効く。
- **算出しない場合:** 次のどれかに当たれば n を自動で出さず、観測値 (各 cell の score の数・fallback の数・欠測の数・s_{t,m}) と理由を
  添えて §8.2 の 3 のとおりユーザーへ返す: (a) score が得られた系列が 2 本未満の cell がある、(b) s_{t,m} が 0 の cell がある、
  (c) 試走が費用上限 (§9.2) で未完に終わった。3 系列が同じ値だったことは、探索間の変動が 0 だという証拠にならない。
- **試走していない課題:** 本比較に試走していない課題 (例: bal) を入れるときは、s_plan をそのまま使う。これは未検証の外挿で、その課題での
  精度を保証しない。
- **1 系列の費用 c(t, m):** 試走の cell (t, m) の系列の job Elapse の中央値に、課題 t の block job の job Elapse の中央値の 1/5 と、
  E_T の再計測 5 session 分 (試走の課題 t の session 所要の中央値 × 5) を足した値。計画用の値なので、E_T の再計測は全系列に足す
  (実際に要るのは E_T の endpoint が E_B と違う系列だけ)。試走していない課題 t′ は、**手法ごとに** c(t′, m) = max_t c(t, m) (試走した課題の
  同じ手法の最大値) とする。
- **LLM の直列時間 ℓ(t):** 試走の LLM 系列の §5 の LLM の直列時間の中央値。試走していない課題は、試走した課題の ℓ の最大値とする。
- **系列の所要:** 試走の cell ごとの系列の job Elapse の中央値 (§8.3 の暦の見積りに使う)。試走していない課題は、手法ごとに試走した課題の最大値とする。
- 試走していない課題への c・ℓ・系列の所要の代入は、s_plan の流用と同じく未検証の外挿である。
- **T_c(t):** §6.2。

### 8.2 規模の式

本比較の課題の集合を Q、族の大きさを M = 10 × |Q| とする。系列数 n の計画半幅を

  h(n) = t(1 − 0.025/M, n − 1) × s_plan / √n

とする。本比較の費用は C(n) = n × Σ_{t∈Q} Σ_m c(t, m) (1 block あたりの block job の費用は c に含めた)。

1. **第 1 段 (同等を言うための計画精度):** h(n) ≤ δ/2 を満たす最小の n を n₁ とする (下限 5)。C(n₁) ≤ C_max なら n = n₁。
2. **第 2 段 (差を分類するための計画精度):** 1 が上限を超えるなら、h(n) ≤ ln(1.05) を満たす最小の n を n₂ とする (下限 5)。
   C(n₂) ≤ C_max なら n = n₂ とし、「計画精度の上では、実用上同等の分類はほとんど得られない」と本比較の追補と報告に書く。
3. **上限内に収まらない場合、または §8.1 の算出しない場合:** n を縮めて走らせない。課題の集合 Q を減らす・上限を上げる・本比較を行わない、の
   択一を、各案の h と費用を添えてユーザーへ返す。Q を減らす案は、費用・分散・実行可能性で並べる (§8.4)。

- h(n) は計画上の半幅であって、得られる区間幅や分類の確率を保証しない。
- **C_max** は本比較の計算確認でユーザーが決める。本書の提案値は一次資料の本比較の試算 510 node 時間である。
- n は結果を見て増減しない。本比較の途中で分散が試走と違うと分かっても n を変えない。

### 8.3 LLM の直列時間と日程

- LLM 系列の総時間を n × Σ_{t∈Q} ℓ(t) とし、これを親の本数 p = 4 で割った値は暦の所要の**理想の下限**である (D2216 の「理想割算」と同じ)。
  暦の所要は、block の配置 (§4) と、各 block で最も長い job の所要の試走での実測から見積もる。
- D2219 項 6 の再提示条件 (本比較の規模を決める時点で LLM の直列時間が律速、または第 2 モデルでの一般性が研究上必要) は、規模を決める時点で
  評価し、結果を計算確認の提示に書く。本書はその条件を狭めない。律速を示す例の 1 つは、本比較の暦の見積りが 2027-01-10 (D2219 項 3 の
  「1 月上旬に結果が要る」を本書は 1 月 10 日と読む) を超え、かつ試走の各 block で最も長い job が LLM 系列だった場合である。成立したら
  H100 の open-weight LLM の案の再提示を添える。成立は実装の許可ではない (D2219 項 6)。

### 8.4 試走の標本の扱いと課題の選択

- 試走の系列は本比較の標本に入れない。本比較の系列は新しい preimage (§4) で fresh に走らせる。
- 本比較の課題の集合 Q は、費用・分散・実行可能性・失敗の種類だけで選ぶ。試走の手法間の差と曲線は使わない。選んだ理由を、本比較の最初の
  系列を走らせる前に追補へ書く。結論は選んだ課題に限り、候補の課題全体を代表する結果とは書かない。
- 試走の値を報告するときは「試走 (各 cell n = 3、分類なし)」と明記する。

判定する) で、§8.2 の第 1 段はもちろん、s_plan が 0.02 を超えれば第 2 段も
上限を超えうる。その場合は §8.2 の 3 でユーザーへ返す。

### 9.2 試走の費用上限

- **試走の上限 = job Elapse の総和 200 node 時間。** 上の試算の上側 145.4 node 時間に、A = 30 の使い切り (約 26 時間) と Tier0・retry・品質再測定の
  余裕を足した値である。
- 上限に達する見込みになったら、新しい job を投入せず、走っている job は終わらせる。系列の定義 (B・A・N_eval)・正しさの条件は下げない。
  未完の cell は「未完」と記録し、§8.1 (c) により n の自動算出はしない。
- 上限はユーザーの計算確認で変えうる。変えた値は発効の決定に書く。

## 12. B-5・転移登録との関係

- **B-5** (`docs/b5-generator-contrast-preregistration.md`) は、知識つき K2 の LLM と random・sweep-matched の 3 生成器を、S1 で初期点なし・
  B = 10・n = 12 で比べる確認的な登録である。本書は K0 の LLM と非 LLM の 4 手法を、共通の初期点と R0 の下で比べる別の構成である。
- 標本を混ぜない。B-5 の系列を本書の系列として数えず、本書の系列を B-5 の系列として数えない。block stock・参照点の測定も
  登録をまたいで共有しない。B-5 の判定規則 (LLM 対 2 対照の permutation・Holm・6 比較の族) は本書で使わない。
- 「同等」の意味が違う。B-5 の同等 (失敗条件 (c)) は判定に使う対で |median(d)| ≤ δ の観測差の判定で、本書の実用上同等は同時区間が
  (−δ, δ) に収まる判定である。並べて報告するときは、この違いと、LLM の構成 (K2 / K0)・初期点の有無・arm の集合 (sweep の格子は §3.1)・
  系列の数の違いを添える。B-5 の結果を本書の手法の結果の予測や再現と呼ばない。
- B-5 の試走 (53 session) は、本書では費用の単価にだけ使い、性能の値は使わない。
- **転移登録:** 本書の試走と本比較は、その学習条件が錨の部分集合なので、転移登録の対象探索群になりうる。名指しは転移登録の
  発効の決定が行う。本書は §2.3 の不使用義務と到達可能性の記録を守る。
