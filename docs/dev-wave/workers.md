# dev-wave worker 契約

この文書は `/dev-wave` の codex plan、敵対相談、実装、レビュー・fix worker の正本である。
入口が指定する leaf 節を、worker を起動する前に読む。

## DW-S02 — 段 2 プラン起草

brief と関連コードの所在を渡し、codex `gpt-5.6-sol`、`reasoning=max`、`sandbox=read-only` で
file:line 粒度のプランを起草させる。read-only 固有のテスト帰属は `DW-O05` に従う。

## DW-S03 — 段 3 敵対相談

codex `gpt-5.6-sol`、`reasoning=max`、`sandbox=read-only` を異なるレンズで並列起動し、
プランを守る側に回らせず攻撃させる。正しさ境界と整合・実効性を分け、親 brief 自身も
攻撃対象だと明記する。brief の file:line、前提、所有範囲、変異の帰属不成立を探させる。
gate・検査を新設する wave では、成果物が実際に効く全層が scope に含まれるかを必ずレンズに入れる。
scope 外の層を実装したふりにせず、裁定パッケージ候補として返させる。

## DW-S05-A — 段 5 所有と投入

実装単位は編集ファイル所有が素集合になるよう分割し、worktree を分ける。
単位間に依存があれば先行単位を完了させ、所有パス限定 patch
（`git add -A && git diff --cached -- <所有パス>` から作り `git apply`）だけを展開してから並列投入する。
codex は `reasoning=high`、`sandbox=workspace-write` とする。

## DW-S05-B — 段 5 権限と赤

入口の凍結境界どおり、実装子はコードとテストだけを編集し、docs 編集と commit をしない。
親・他単位の成果物が land するまで意図的に赤になるテストを xfail 化してはならない。
赤の内訳を完了報告に明記する。

## DW-S05-C — 段 5 実装子の検査・報告

実装子のプロンプトに次をすべて入れる。

- 緑を主張するなら走らせた nodeid・範囲を必ず併記する。子の実走は親の全走を代替しない。
- 新しいテストファイルを作る単位は、テストファイル自体を制約する meta-test も走らせる。
- fixture への現行 hash 差し込みなど、テストを甘くして緑にしてはならない（F27）。
- 期待値に working tree の hash 等の揮発する診断 payload を焼き込まない。理由と件数を固定し、
  揮発部分だけを外す。修正後は揮発源を実際に編集しても緑か確認する。
- 完了報告に、所有外の caller、共有 fixture、consumer test への波及可能性を静的に列挙する。
- 指示にない受理集合の拡大・縮小をしてはならない。scope を書く前に現行の受理・拒否挙動を明記する。
- 親 docs が未 land なら期待して赤くなる finding 集合を事前指定し、それ以外は回帰として報告する。

## DW-S06-A — 段 6 敵対レビュー

実装 wave は、異なるレンズの敵対レビューを必ず 2 本並列で行う。
親が直接書いたハンクがあれば、所在を名指しして両レビューの対象に含める。
所見ゼロは変異で裏取りするまで緑と数えない。

## DW-S06-B — 段 6 fix の分割と継承

real 所見へ fix を投じる前に統合 snapshot patch を退避する。所見を編集対象ファイル集合で分け、
所有が素集合なら `DW-S05-A` と同じ worktree・所有・限定 patch 契約で並列投入する。
一枚岩にするなら、相互依存など単一化の理由 1 行を handoff に残す。横断所見は一単位へ寄せるか親が直す。

fix を codex へ再投する子は、段 5 の実装子契約 `DW-S05-A`、`DW-S05-B`、`DW-S05-C` を
全文継承する。特に権限、reasoning/sandbox、テスト弱体化禁止、受理集合、期待赤、波及報告を省略しない。

## DW-S06-C — 段 6 統合後の再検証

並列 fix を統合した後、焦点再レビューは全体へ 1 本行えばよい。fix 単位ごとの個別レビューは不要とする。
親が変異 matrix と受入を再走する。焦点再レビューには所見ごとの closed / partial / regressed 表を要求する。
成立した条件の operations と `DW-G05` を適用し、成果物影響を書けない所見を must-fix にしない。
