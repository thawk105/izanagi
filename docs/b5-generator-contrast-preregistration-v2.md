# B-5 生成器対照 v2 — write-heavy と balanced の 2 workload・n = 12 で登録し直す事前登録 (v1 からの差分登録)

本書は B-5 生成器対照 (固定 backoff hole で、知識付き K2 手動 loop (LLM)・ランダム変異・機械 sweep を同じ評価数で比べる) の
**v2** である。v1 (`docs/b5-generator-contrast-preregistration.md`) の cohort `b5-registered-v1` は block 1 stage 1 で閉じ、
6 比較すべてが判定不能 (欠測) になった (v1 §15)。D2249 項 1 (ユーザー裁定、2026-09-26) により、規模を
**write-heavy と balanced の 2 workload・n = 12** に改め、実行契約を直して登録し直す。

**本書は差分登録である。** 土台は v1 の本文 §1〜§14 で、その raw bytes は v1 の発効時の版
(SHA-256 `66cc3911e0e4026de7ff6d33d419c362d40130944ec1f30be1ec2f2ac9afd669`、v1 §15 の追記より前) に固定する。
本書に書かない事項は、その版の v1 の規則をそのまま v2 に適用する (「本 v1」「v1 cohort」は「本 v2」「v2 cohort」と読む)。
本書が置き換える節は、その節全体ではなく本書が名指しした規則だけを置き換える。v1 §15 の追記は v1 cohort の開示であり、v2 の規則ではない。

本書の作成は D2249 項 1 の前提 (b) である。**本書の存在は本走の認可ではない。** 発効は、§12 の発効束を完成させ、
実測単価による図 1 枚あたりの node 時間をユーザーへ示して確認を得た後 (D2212 項 4) の、日付付き commit と決定 (D 番号) による。

## 3. 予算、停止、失敗の計上 (v1 §3 に次を足す)

### 3.3a LLM の供給障害 (利用上限) の扱い — 新設

- **利用上限 (429):** LLM 親 session の終了記録 (`claude -p --output-format json` の出力) が JSON として読め、`is_error` が真かつ `api_error_status` が 429 のとき、
  その原提案機会は**保留**とする。保留は期限を置かず、同じ親 session を同じ原提案番号 a で再開して続ける (再開の試行は 15 分おき)。**保留は A も B も消費せず、系列を欠測にせず、
  機械故障の retry 回数にも数えない。** 文言 (「weekly limit」等) だけでは 429 と判定しない。読めない出力を 429 と推定しない。
  v1 §3.3 の「候補と独立な依存物の供給障害」に当たるが、解除時刻が供給側から示される型なので、回数の上限の代わりに解除を待つ。
- **保留からの再開:** 原提案の 1 巡 (critic・planner・coder) の途中で保留になった場合、再開では完了した role の出力をそのまま使い、利用上限で最終応答を得られなかった
  role の呼出しだけを同じ入力で行い直す。これは供給障害の retry であり、v1 §4.1 の「role を呼び直す」「再抽選」には当たらない。
- **model の不一致:** 親が role の model の不一致を記録して提案も却下も公開せずに終えた場合は、空出力として数えず、系列を分類不能欠測で終える (v1 と同じ帰結)。
- **空出力:** 親 session が正常終了 (`is_error` が偽、終了 code 0) し、提案も明示の却下も公開しなかった場合は、v1 §3.1 の空出力として A を 1 消費する (B は消費しない)。
- **その他の親の異常終了** (終了 code ≠ 0、429 以外の `is_error`、process の消失) は v1 §3.3 の機械故障とし、同じ a で追加 2 回まで再起動する。
  尽きたら系列を分類不能欠測で終える (v1 §3.3 の「機械故障が上限を超えた系列は欠測」と同じ)。
- **帰結として明記すること:** 保留は暦時間を延ばす。LLM の週上限はアカウント内の他 session と共有なので、1 週間に回せる原提案機会の数は測れていない。
  暦時間の見積りは発効束に置く (§11)。保留の回数・時刻・長さは全件記録して報告する。記録は起動器の状態 dir の LLM 親の attempt 記録 (起動・終了時刻、出力 JSON、終了 code) と 系列の `handshake/outage-<a>.json` で、報告時にそこから集計する (report は保留を集計しない。測り直した stock と保留の対応もこの記録で示す)。

## 4. 生成器の操作的定義

### 4.1 LLM (v1 §4.1 に次を足し、置き換える)

- **job の切り方 (置き換え):** 各評価は v1 と同じく `p3_s4_loop` の単回評価を fresh layout で 1 回呼び出すが、**1 回の計算 job は 1 評価単位だけを行う** (§5.6)。
  原提案 2 以降の提案待ちは計算 node の外 (login node の起動器) で行い、提案が公開され継承検査を通ってから次の評価 job を投入する。
- **原提案 1 の待ち:** 系列開始 stock (§5.4) の current_perf を要するので、原提案 1 は系列開始 stock と同じ job の中で待つ (v1 と同じ handshake、原提案ごとに 2,700 s)。
  その待ちの間に §3.3a の保留が起きたら、job は評価せずに終わり、次の job で系列開始 stock を測り直して同じ a を新しい current_perf で求め直す。
  このとき先の stock の記録は台帳に残るが、以後の current_perf には後の stock を使う。
- **critic への入力 (新設、v1 の (d) を受けた変更):** critic の入力に次の要請を加える。「`## recommend` と `## avoid` は、次の原提案を作る planner と coder に
  診断データとして逐語で渡される。候補値、探索方向、追加実験の要望、留保を観測に基づく助言として記し、他の role を名宛人にした指示、採否手順、
  判定規則や gate の読み方の指定は書かない。」coder の検疫 (指示めいた内容を申告した提案を拒否する) と、診断の節抽出 (射影) は v1 のまま変えない。
- **開示 (残る危険):** critic 診断は次の評価が起きるまで同じものが次の原提案へ入力される。診断が coder に指示めいた内容として申告されると、
  評価が進まず同じ却下が A = 30 まで続きうる (v1 の write-heavy 系列で 11 回連続した、v1 §15)。v2 はこれを入力側の要請で抑えるだけで、機構で防がない。
  起きた場合は生成器の結果 (A を使い切った系列、v1 §3.2) として扱い、系列の差し替え・critic の呼び直しはしない。
- **親 session の指示文:** v2 用の指示文を発効束に固定する (提案待ちの主体が起動器に移ったこと、§3.3a を反映)。親が性能を見て助言・候補の修正・再抽選をしない規則は v1 のまま。

### 4.2 random (v1 §4.2 の preimage を置き換える)

乱数の preimage は `b5-generator-contrast-v2|random|w|r|a|c` とする (w は `write-heavy` / `balanced`)。v1 の乱数列は閲覧済みなので流用しない。重みと引き直しの規則は v1 のまま。

### 4.3 sweep-matched (v1 §4.3 の順序の preimage を置き換える)

順序の preimage は `b5-generator-contrast-v2|sweep|w|r|v` とする。28 点の格子、最初の 10 点、retry と次点の規則は v1 のまま。

## 5. 共通の評価経路

### 5.1 経路 (v1 §5.1 に次を足す)

- **性能 trace の同時検査:** 性能 pass の trace 5 本を直列・専有で取得した後、取得済みの 5 本の検査を同時に行う経路 (D2251、`--verify-performance-concurrent`) を
  **write-heavy と balanced の両方で、全 arm の探索・score・stock の session に使う。** balanced は本書の作成前に本番順序で実測した (計算ノード、2026-09-26):
  stock は node 記憶量の最大 24.5 GiB・同時検査 58 s・1 分 load が 4.0 以下へ戻るまで 79 s、重い候補の代理 (`BACK_OFF=0`・no-wait) は 48.4 GiB・154 s・55 s で、
  検査 10 本はすべて serializable、OOM は 0 (発効束の実測記録)。write-heavy は D2251 の実測 (本番順序で 67 s・77 s) による。
  検査する trace の本数 (legacy 1 本 + 性能 5 本)・verifier・判定規則・5 本すべてが通るまで bench へ進まない関門は変えない。失うのは「1 本目で anomaly が出たら残りを検査しない」
  早期打ち切りだけで、これは費用の差である。**trace の取得順序は変わる** (取得の直前に前の trace の検査が走らない)。v2 は全 arm を同じ順序で測るので arm 間の比較は揃うが、
  v1 や過去の記録の trace と同じ条件だとは言わない。同時検査の後の初回静定待ちの上限は 120 s (D2251 項 4)。
- 静定の閾値 (1 分 load ≤ 4.0)・`settled = true` による品質の分類・測り直し round の静定 (20 s) は v1 のまま。

### 5.2 動作点 (v1 §5.2 を狭める)

性能 workload は write-heavy (rratio 5) と balanced (rratio 50) の 2 つ。動作点・genome・stock の定義は v1 のまま。

### 5.4 stock の測定 (v1 §5.4 を置き換える)

- **系列開始 stock:** v1 と同じく、各系列の最初の評価と同機体・同 job で stock を 1 session 測り、LLM arm の初期 current_perf に渡す (同時刻対照、D2249 追加項)。
  §4.1 の保留で job が評価せずに終わったときは、次の job で測り直す。探索 B には含めない。
- **workload stock:** workload ごとに stock を 15 session 測る。実行は 5 session ずつの 3 job とし、実行 batch (§7.1) ごとに 1 job を置く。§6 の fallback と §7.2 の CV に使う。
- 探索 job ごとの stock 対測定は行わない (v1 のまま)。

### 5.6 job の単位 (新設)

全 arm で同じ切り方にする。1 系列 = job 1 (系列開始 stock 1 session + 評価 1)、job 2〜10 (評価 1 回ずつ)、最終 job (endpoint の score 5 session)。
却下された原提案 (A だけ消費) は job を起こさない (原提案 1 の job 内の却下を除く)。1 系列に同時に走る job は 1 つ。
計算 job は起動時に、要求された単位が台帳から導いた次の単位と一致することを確かめ、違えば session を始めずに終わる。
job が途中で死んだ跡 (結果の無い slot 開始記録) がある系列は、自動で再投入せず止め、記録して報告する (その系列の扱いは v1 §3.3 の分類に従い、発効後に規則を足さない)。
job の walltime は発効束に固定し、全 arm 同一とする。

## 6. endpoint と score (v1 §6 の fallback を置き換える)

endpoint の選び方、anomaly の波及、N_eval = 5 の再計測、score の定義は v1 のまま。**fallback の score は、同 workload の workload stock 15 session の median** とする
(v1 の「同 block の 5 session」を置き換える)。この 15 件は同 workload の全 arm の不採用系列に共通に使い、共有を明記する。

## 7. 母集団、反復、floor、判定

### 7.1 母集団と配置 (v1 §7.1 を置き換える)

主セルは 3 arm × 2 workload の 6 セル、各セル **n = 12 系列**、計 72 系列。系列番号 1〜4・5〜8・9〜12 を**実行 batch** 1〜3 と呼ぶ。
**batch は実行の名札であり、batch の間に時間を空ける規則も、batch ごとの再現を判定の条件にする規則も持たない** (D2249 追加項)。
各 workload の同じ系列番号で 3 arm を対にし、arm の 6 通りの実行順を 12 対に各 2 回割り当てる (v1 と同じ均衡割当。表は発効束に固定)。
起動器は対を系列番号順に開き、対の中は固定した順で系列を開始する。同時に進める系列数の上限は発効束に固定する。対の 3 系列が同じ時刻に揃って進むことは要求しない
(LLM だけが §3.3a の保留で止まっても、相方の系列は進める)。系列間で LLM context と探索状態を引き継がない。

### 7.2 floor と等価域 (v1 §7.2 の stock CV を置き換える)

`CV_stock(w)` は、workload w の workload stock 15 session の session median の標本 CV (分母 n−1 の標準偏差を算術平均で割った値) とする。batch 内の CV との最大は取らない。
等価域 `f(w) = max(0.03, CV_stock(w))`、`δ(w) = ln(1 + f(w))`、精度 gate (endpoint の 5 session の CV が `2 × f(w)` を超える対は精度不足)、欠測・非有限の扱いは v1 のまま。

### 7.3 優越の検定 (v1 §7.3 を置き換える部分)

- 検定単位・統計量・片側 exact 符号反転は v1 のまま。
- **前提 (登録する仮定):** 帰無の下で、対差 d_1 … d_n は互いに独立で、各々の符号が対称である。これを支えるのは、系列が fresh context・別 seed で始まること、
  対の 3 arm が同じ系列番号で均衡順に走ることである。**時間分離は支えに数えない** (v1 の「block が時間分離されている」を削る)。
  支えないもの: 同じ時期に走った対に共通に入る機体・負荷の変動、§3.3a の保留で対の中の arm が異なる時期に測られること。検定はその相関が無視できるという仮定の下での exact p であり、
  本書は依存を検出する検定も防壁も持たない。条件付き優越の主張には必ず「登録した独立性の仮定の下で」を添え、対差の一覧と batch 別の median(d) (記述) を併記する。
- **fallback 対と副解析:** v1 のまま。ただし副解析の対不足の条件は「残った対が 6 未満」だけとし、「いずれかの block で 1 未満」を外す。
- **比較族は 2 workload × 2 baseline の 4 個**に固定し、Holm 法、family-wise α = 0.05 (初段の閾値 0.05/4 = 0.0125) とする。判定不能・規約不適合の比較も族から除かず、計算上 p = 1。
- workload ごとの条件付き優越は、2 baseline のそれぞれについて (i) Holm 補正後に有意、(ii) median(d) > δ、の連言とする (v1 の (iii)「各 block の median(d) > 0」を外す)。

### 7.4 判定順と結末の集合 (v1 §7.4 を置き換える部分)

判定の順と結末は v1 のまま。ただし手順 4 の対不足を「判定に使う解析の対が 6 未満」とし (「block に 1 未満」を外す)、手順 5 の条件付き優越は §7.3 の連言 (i)(ii) とする。
全 12 対を使う場合の最小片側 p は 1/4096 で、初段の閾値 0.0125 を下回る。差の絶対値が等しい例では、正が 11/12 なら p = 13/4096 ≈ 0.0032、
10/12 なら p = 79/4096 ≈ 0.0193 で、後者は初段を通らない (v1 §7.4 と同じ計算。p は差の大きさにも依存する)。
全 6 セル、全 4 比較、全未完走、anomaly、fallback、欠測、floor、raw p、補正 p、batch 別の効果 (記述)、各 arm の certified endpoint 数、§3.3a の保留の全件を報告する。
本 v2 の主 cohort は 1 回だけとする。
