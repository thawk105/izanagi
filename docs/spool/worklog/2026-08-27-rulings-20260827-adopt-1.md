## 本文

- `/rulings all 説明つき` に対するユーザー裁定。**「推奨通りで。main land までよろしく」** =
  索引した 52 件を rulings の推奨どおり確定し、記録を main へ着地させる。
- **収集の欠陥を 1 つ実測し、索引に影響した。** 裁定待ちの抽出が語彙で漏れる。
  `sweep_pending.py` の PENDING 正規表現も親の初版も、**素直な決定動詞
  (`を裁定する` / `かを裁定` / `裁定が要る` / `裁定を伴う` / `裁定境界`) を拾わない。**
  既存 script の 35 件、状態 marker の不在による親の 1 次抽出で 45 件、
  さらに 2 回の絞り込みで **12 件**を追加発見した。**この漏れに P1 が 1 件含まれる** —
  非標本 probe の設計 ({{D:nonsampling-probe-reverse-closure}}) で、
  B-4 事前登録が発効しない直接の原因である。**script への語の追記は本 wave では行っていない**
  (収集は読み取り専用で走らせたため)。
- **持ち越しの解決は 938 件・未解決 0 で完了した。** carry 表記 2 形式を両方辿り、
  実体まで解決してから抽出した。前回 (F668) の再発は無い。
- **相談で親の推奨が 5 件覆った。** D898 が定める別系統モデルへの相談を 2 本実施した
  (推奨の当否 / 索引の網の穴)。**既裁定の誤引用は 0 件**だったが、
  **後発かつ対象固有の裁定を、一般的な見送り方針で上書きした推奨が 4 件**あった。
  型は「防御的堅牢化は既定で見送り」「bytes 級 provenance は不要」の過剰適用である。
- **とくに重い誤りが 3 件あった。** (1) 着地受領証の外部署名主体について「今は実装しない」を
  推したが、D906 が明示的に要求した機構を、旧い脅威モデルを扱う D387 で見送っていた
  ({{D:landing-receipt-needs-external-signing-authority}})。
  (2) build 中の材料差し替えを「防御的堅牢化」として受理しようとしたが、
  **D966 が閉じる対象として逐語で名指ししていた** ({{D:source-swap-aba-must-be-closed}})。
  (3) 非認証成果物型について署名付き identity 束縛を不要としたが、D1038 の逐語は
  「鍵・記録・schema・consumer の**全層**で固定できること」であり、鍵層を省くと型自体を作れない。
- **相談 2 本とも出力検査を通過した** (`check_codex_output.py` rc=0)。
  引用された D は親が原文で裏取りした。
- **索引の網の穴が 4 件見つかった。** うち 2 件は **decisions 側にしか実体が無い型**である —
  後発の決定が「ユーザー裁定へ返す」と本文に書いても、worklog の「次の一手」に項目が無ければ
  D70 の保存則の対象にならず、**worklog 側の走査では構造的に見つからない**。
  床値試行台帳の 2 軸がこれに当たった。もう 1 件は**段階条件が成熟した後の再昇格漏れ**で、
  先行段の着地により再裁定の条件が成立していたのに、台帳は次段を「実装待ち」と書いていた
  ({{D:runner-binding-rerule-before-stage-q}})。
- **既裁定 12 件を索引から落とした。** うち 2 件は**本日の裁定**である —
  変異 harness の node 抽出契約 (D1081) と、未採番の新種赤の hold 登録 (D1160)。
  ほかに手順書の byte 予算 (D961 / D1046 / D1180)、受入の既定分割数 (D1047)、
  worktree 登録の競合 (D1079)、待ち量の分布を測る診断ビルド (D1097)、
  fold 後 tree の関門 (D752)、既知赤の除外配線 (D679 / D670)、承認 bytes の置き手 (D1174)、
  D1054 の免除路 (D1158) である。
- **収集の途中で 3 wave が着地し、索引の前提が動いた。** Web 検索の件は、収集時点では
  「無条件禁止が既裁定より広い」という未採番の裁定待ちだったが、**提示から裁定までの間に
  当該 wave が着地し、子の Web 検索を許可する形で決着した。**
  未採番だった 2 件にも実番号が付いたので、本 fold は実番号で裁定を記録している。
- **収集後に現れた項目は裁定していない。** 実行器を変える wave の受入の取り方と、
  末尾 append で `.pth` の path が復元されない件の 2 件は、索引提示より後に着地した
  エントリ由来なので、**ユーザーが見ていない。次回の /rulings へ回す。**
- **ユーザーの手番が 3 件残る。** 救出物の二次保管先の指定 (D1162)、床値 official の
  予算承認文書 (D1161 / D1174)、未 push commit である。`origin/main..main` は 300 本ある。
  AI は push しない。**予算承認は前回の索引が落としていた項で、相談 B が摘出した。**
- **未採番の裁定 7 件は T 番号を起こしていない。** 稼働 branch の未 land fragment にしか
  実体が無く、採番はその branch が行う (二重在籍を避けるため)。裁定本文は本 fold の
  decisions fragment に在り、控えを repo 外の裁定 inbox へ置いた。
- **エージェント工数**: codex 子 2 本 (consult 2、いずれも採用基準を通過)。実測はすべて親が行った。
