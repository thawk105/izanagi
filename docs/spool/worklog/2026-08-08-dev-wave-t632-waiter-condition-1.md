## 本文

- **裁定どおり 4 要素で land した。** 入口の条件 dispatch 表 24 行目の発火条件セルだけを
  `…通知処理の直前` → `…通知処理、待ち条件作成の直前` にした。参照先 (`DW-C00`)、`DW-C00` 本文、
  `tools/check_docs.py` の `CONDITION_DISPATCH_CONTRACT["24"]` はいずれも 1 byte も変えていない。
  入口は 9,035 → 9,056 bytes (上限 9,500)、当該行は 82 → 89 文字 (上限 140)。予算は引き上げていない。
  起票時の見積り `+21 bytes` と実測が一致した。
- **F158 の再来ではないことを一次資料で確認してから着手した。** [T-625] wave では
  裁定要約 (3 要素) と提案本文 (4 要素) が食い違い、親が本文を優先して 1 巡手戻りした。今回は
  裁定 inbox §43 の逐語「**[T-632] = 4 要素目を含める**」と worklog の裁定記録が一致しており、
  食い違いが無い。段 1 で両方を開いて突き合わせた上で着手した。
- **この変更は検出力を 1 も増やしていない。これが本 wave で最も正直に書くべきことである。**
  発火条件セルの文言は `check_docs.py` が保持も比較もしないため、追加した `、待ち条件作成` を
  消しても全検査が緑のままである。文言を機械 pin するか否かは [T-634] として**未裁定**であり、
  ここで literal pin を入れると未裁定の設計択一を既成事実にする。よって**テストは足さなかった**。
  記録上「発火条件が守られるようになった」とは書かない — 守るのは規律であって機械ではない。
- **したがって変異 matrix は対象外とした。** 無効化したときに赤が一つに絞れる gate が存在せず、
  `DW-M01` の単一理由性を満たす変異を登録できない。これは [T-634] 未裁定に由来する既知の穴で、
  本 wave が新たに開けたものではない。
- **軽量版を採り、codex 子を 1 本も起動しなかった。** `DW-C00` の 3 条件 (設計択一が割れる /
  正しさ防壁に触る / 受理集合が変わる) はいずれも成立しない — 裁定は確定済み、防壁に触れず、
  `check_docs` の受理集合はセル文言を含まないため変わらない。さらに変更が `.md` 1 ファイル 1 行で、
  `docs/ai-provenance.md` の実装面定義 (`orchestrator/` `tools/` `hooks/` `.github/` `.codex/`
  `external/` 配下の非 md、`patches/`、所在不問の実行可能資材) のどれにも当たらないため、
  **docs-only として親が直接編集した**。段 2・3・5・6 の子はゼロである。
- **凍結 bytes の pin が無いことを着手前に実測した。** `.claude/commands/dev-wave.md` を key にする
  sha256 pin は repo 全体で 0 件で、`check_docs.py` が持つ skill hash pin は cleanup-branches の
  ものだけである (`DW-O09` / `DW-O10` 不成立)。

  7228 passed / 1 failed / 20 skipped で、赤 1 件は `test_codex_worker_launch.py` の 1 node が
  launcher rc=1 / stderr 空で落ちたもの。同 file の単独再走 (request `895588`) は

  (2026-08-01 とメッセージまで同一)。F66 の恒久対応にある `DW-O20` への導線追記は
  7 日経っても未着手で、`docs/dev-wave/operations.md` は 8,301 / 8,400 bytes (残り 99) と
