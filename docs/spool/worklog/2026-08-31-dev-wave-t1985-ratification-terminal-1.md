## 本文

- 依頼は「D1039 / D1070 に従い、既存 lock の resume と certified artifact consumer が署名 gate を
  素通りする穴を塞ぐ」であり、**方向は裁定済みなので裁定へ返す必要はない**という但し書きが
  付いていた。段 1 の裁定前提実測 (`DW-S01`) で、その但し書きの前提が覆っていると判明した。

- **D1139 (ユーザー裁定、2026-08-27) が批准突き合わせそのものを廃止しており、D1039 と D1070 は
  実効を奪われている。** D1139 本文は実効を奪う既裁定として D905 / D1039 / D1070 / D1071 を
  名指しし、D1039 と D1070 については「批准 verifier が無くなるため実装不能になり、実効を失う」と
  明記している。したがって**塞ぐべき署名 gate が main に存在しない**。裁定は
  {{D:ratification-bypass-terminal}}。

- **裏取りは 4 本の独立した一次資料で取れた。** (a) D1139 本文による名指し。(b) 判定器
  `orchestrator/campaign/enforcement_source_ratification.py` (627 行) と試験 (929 行) が commit
  `b4ff38f6b` で main から削除されている実測。(c) D1308 (2026-08-29) が同機構の救出候補 7 file を
  全件破棄と裁定していること。(d) `docs/failures.md` の該当エントリが「2026-08-27 の main 以降は
  発火しない」「D1139 は D905 / D1039 / D1070 / D1071 を明示的に上書きしている」と記録していること。

- **依頼の但し書きは worklog の持ち越し本文をそのまま写したものだった。** [T-1985] の本文は
  entry 1031 (2026-08-27) で書かれた「P1・裁定済み (D1039 / D1070) → 実装待ち」のまま、D1139 の
  着地後も entry 1111 まで無変更で運ばれていた。F428 の再発として記録した。

- **子は 1 本も起動していない。** 実装面の差分がゼロの docs-only wave であり `DW-C00` の軽量版に
  該当する。段 2・3 は省き、段 5・6 は `DW-S04` の「実装しない」経路で飛ばした。設計択一が割れず、
  正しさ防壁に触れず、受理集合も変えないため敵対検証子の省略条件を満たす。

- **[T-1984] も同じ廃止済み機構を前提に残っている。** 本文は「判定器が判定対象の内側にある
  構造的限界を閉じる設計。D906 の『署名対象に実行器と検査器の bytes を含める』をどう実装するか」
  であり、D1139 が「命じられた実行主体は今後も作らない」と定めた対象そのものを指す。本 wave の
  scope 外につき本文は変えず、裁定パッケージとしてユーザーへ返す。
