## 本文

- `/rulings all 説明つき` に対するユーザー裁定。**「推奨通りで。main land までよろしく」** =
  索引した 40 件を rulings の推奨どおり確定し、記録を main へ着地させる。
- **収集の欠陥を 2 つ実測し、どちらも索引に影響した。** 持ち越し表記が 2 形式あることを
  解決器が知らず 69 件が未解決のまま裁定待ち判定から落ちていた
  ({{F:rulings-carry-stub-has-two-forms}})。収集が snapshot であることを手順が明示しておらず、
  走査後に稼働 wave が commit した裁定を取りこぼしていた
  ({{F:rulings-collection-is-a-snapshot}})。後者の是正として索引確定の直前に再走査したところ、
  未 land fragment が 9 → 24 件へ増え、**3 branch から 7 件の裁定待ちが追加で出た。**
- **相談で親の推奨が 10 件覆った。** D898 が定める別系統モデルへの相談を 3 本実施した
  (推奨の当否 / 索引の網の穴 / 追補の検算)。**親の初版推奨は 27 件中 10 件で誤っていた。**
  型の内訳は、既裁定と逆向き 3 件、受理集合を広げる側へ倒れた 2 件、消費者の居ない場所へ
  gate を置いて休眠 capability を作る 2 件、従属関係の捏造 3 件である。
- **とくに重い誤りが 2 件あった。** (1) 診断計装下の試行に正しさ検査を通さない案を推したが、
  待ち時間由来の値が機序結論へ直接入っていることを現物のコードで確認して撤回した
  ({{D:b10-diagnostic-genome-correctness}})。(2) テストだけが呼ぶ解決器について
  「実運用 adapter を作らない」を推したが、production の呼び手がゼロで**現状こそが休眠**であり、
  親は D1028 を逆向きに引用していた ({{D:condition18-adapter-or-removal}})。
- **既裁定 3 件を索引から落とした。** 手順書の byte 予算引き上げ (D961 / D1046 が個別裁定を
  明示的に禁止)、新しい作業コピーで落ちる検査の三択 (D1045 が択一を確定済みで、親の推奨は
  却下された案と同じだった)、受入環境の一時領域 admission (別 ID で据え置き裁定済み) である。
- **相談 3 本とも出力検査を通過した。** 引用された D / F は親が全件原文で裏取りし、
  親が誤って引用していた D758 / D906 / F79 と、裁定済みでない項目を既裁定として引いた 1 件を
  訂正した。
- **索引提示から裁定までの間に、同じ壁の 4 例目が main へ着地した。** 手順書の予算に阻まれた
  収容を「裁定へ返す」と書いた fragment である。**これは D961 が書き換えを命じた古い文言を
  読んだ結果**であり、当該書き換えを載せた branch は 32 branch のいずれにも存在しない。
  D1046 が「その書き換えの着地を予算案件より先に扱う」と定めているが担い手が不在である。
  D782 の独立 3 例の閾値はこの 4 例目で完全に超えた。
- **land が全 wave で止まっていることを reflog で確定した。** 同じ夜に 4 本の wave が
  local main を ff-only して全部巻き戻されている。真因は archive 名の分類器が entry 番号を
  日付として先に読むことで、親が特定して 3 セッションが独立に一致した。壊れるのは単一 entry を
  rotation する 2 token 形だけで、複数 entry 形は現行でも採番される。
  **本記録自身も同じ fold を通るため、修理が着地するまで land できない。**
  親の fold 計画にも当該 rotation path がそのまま現れ、5 例目の確認になった。
  真因は実装の逸脱ではなく **D445 の理由文の穴**である ({{F:archive-name-entry-number-collides-with-mmdd}})。
  **修理は同 file を既に触っている並行 wave が D445 の改訂とあわせて所有し、失敗台帳の記録は
  本 fold が持つ**と調整した (wave を跨いだ placeholder 参照ができない spool 規約の下で、
  同一欠陥の二重登録を避けるため所有をどちらか一方へ寄せた)。
- **未採番の裁定 13 件は T 番号を起こしていない。** 稼働 branch の未 land fragment にしか
  実体が無く、採番はその branch が行う (二重在籍を避けるため)。裁定本文は本 fold の
  decisions fragment に在り、控えを repo 外の裁定 inbox へ置いた。
- **ユーザーの手番が 4 件残る。** 救出物の secondary 保管先の指定 (D1030)、床値実測の実施時期、
  B-4 の実行責任者の指名、未 push commit である。`origin/main..main` は 330 本ある。AI は push しない。
- **エージェント工数**: codex 子 3 本 (consult 3、全て採用基準を通過)。
