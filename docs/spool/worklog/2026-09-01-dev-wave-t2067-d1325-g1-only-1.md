## 本文

ユーザー裁定 D1325 に従い、床値選択の残余のうち設計択一 2 件 (削除された earlier run を戻す
authority、g2 以降の選択・投影) を「戻さない・g1 のみ」で固定した。**実装差分は不要と裁定し、
実装子は起動していない。** 測定は commit `24014bdb259d971571f22b54a8f10a49352b825f` の静的検査で、
過去の成果物を再判定も certified 昇格もしていない (規律 7)。

**D1241 / D1313 の advisory / non-certifying 上限は維持する。** 追加で主張してよいのは D1313 の
(a)(b)(c) の 3 点だけで、本 wave はそのいずれも広げていない。規律 2 は緩めていない。

**「戻さない」の成立範囲を限定して記録した。** 選択規則は検査時点で存在する namespace を列挙する
だけで、削除済み run の復元も、削除が無かったことの証明も行わない。削除は通常の campaign API には
無いが、当該 namespace は guard の防護 tree の外にあるため generic な file 削除では消せる。
**D1325 はこの残余を閉じずに受容する裁定であり、削除経路を塞いだのではない。**

**「g1 のみ」も同様に限定した。追加保証は g1 の範囲に限る。本記録は g2 の受理・拒否・選択・投影を
何も定義しない。** 親は当初「選択規則が g2 へ伝播し、投影だけ伝播しない非対称がある」と実測したが、
これは**誤りだった**。呼出しの手前に launch certificate の世代 scope 拒否があり、公開経路は呼出しへ
到達しない。plan・独立レンズ 2 本・親の 4 者が別々に同じ結論に達した。**ただしこの拒否枝を
「g1 のみ」の成立点に数えなかった** — 数えると「将来 g2 は拒否する」という仕様の先取りになり、
D1325 の「g2 が実在してから設計する」に反する。この非対称は新しい次の一手にも裁定事項にもしない。

**現時点でこれらの検査は静的に存在するだけで、発火していない。** 現 HEAD の tree には v2 世代文書・
承認・有効 pointer・candidate・official な床値 run がいずれも 0 件で、予算承認 hash は未設定である。
本 wave は active な g1 も official な床値も予算承認も生成しない。

**実装面を触らなかった理由を訂正した。** 親の当初の理由「コード変更は成果物の値を変えない」は
誤りである。床値凍結の実装 file は自分自身の blob hash を将来の candidate の generator 記録へ
入れるため、docstring 1 行の編集でも成果物の値が変わる。正しい理由は「現行の到達可能な挙動が
既に D1325 と一致し、必要な実装差分が無い」である。

**残余の母集合を訂正した。** load-only consumer への選択強制は s8c の judge 1 件ではなく 3 群
(oracle manifest、s8c の床値 verifier / publish、s8c C06 予算) である。

**依頼文の前提を 1 点訂正した (抵触なし)。** 稼働中の別 wave が触るのは 4 file ではなく 8 file
(production 4 + 対応 test 4) だった。全 worktree の未 commit 差分と全 branch 差分を再走査したが、
本 wave の編集面との交差は 0 件である。

工数は子 3 本 (plan 1、独立レンズ 2)。いずれも rc=0 で成果物検査も緑。実装子と fix 子は起動して
いない。実装面の差分がゼロのため変異 matrix は `DW-S04` の免除に当たる。受入全走は免除せず実走した。
逐語は `output/insights/2026-09-01_t2067-d1325-g1-only/`。
