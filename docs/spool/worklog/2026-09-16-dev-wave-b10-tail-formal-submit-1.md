## 本文

- ユーザー依頼は「B-10 残件『静的 backoff 右 tail の本走』を Pegasus へ投入し、3 workload を 1 集団
  として判定まで出す。投入前に submission §1 の 5 条件を 1 つずつ実測で確かめ、満たさないものが
  あれば投入せず理由を insight へ書く。判定式・閾値・格子は事前登録が持つので本 wave で決めない」。
- **段 1 の実測が依頼の前提を覆した。本走は 2026-09-15 に既に完走し、集団判定まで出ていた。**
  現行 `docs/worklog.md` に `T-2500` / `t2500` は 1 件も無く、残っているのは下流項目だけだった。
  依頼が根拠にした投入手順書 §5 の「本走を実際に投入した実績は本書の作成時点では無い」は、
  2026-09-14 時点の限定付き記述であって現在の状態を述べた文ではない。
- **submission §1 の 5 条件は不成立ではなかった。**条件 2〜5 は本日の実測で成立し、条件 1 は
  投入しなかったため未実測である。**投入を止めたのは 5 条件ではなく、済んでいたという事実である。**
- **新しい測定を作らず、本番 CLI で集団判定を再導出した。**投入手順書 §4 の argv をそのまま使い、
  09-15 の 3 campaign から report を再生成した。**終了コード 0、生成された 3 成果物すべてが
  09-15 の成果物と byte 単位で一致した。** 同 §4 は invalid なら終了コード 1 と定めているので、
  rc=0 は invalid でないことを意味する。`failures` は空、3 workload とも `not-observed`、
  18 区間すべて `declining`、平坦区間 0、`performance_certified` は false のまま。
- **親が段 1 brief に書いた不投入の理由 3 つは、段 3 のレンズ A が壊し、親が取り下げた。**
  (1) 事前登録 §8.2 の「初回の本格投入時に」は束縛の記録要求であって 2 度目の禁止条項ではない。
  (2) 絶対規律 2 を統計的多重性へ広げたのは射程の拡大である。(3) 規律 7 はむしろ
  「新しい測定はいつでも開始できる」と明記しており、「初回が有効だから次を始めない」を支えない。
  **結論として「事前登録が 2 本目を禁じている」とは書かない。禁じていない。**
- **投入しなかった理由は次の 3 点に絞った。** (a) 依頼の成果物は既に存在する。(b) 2 本目を正しく
  走らせるには、その地位 (再現か置換か) を結果より前に決める必要があるが、事前登録は複数 cohort の
  合成規則も選択規則も持たない。結果を見てから決めるのは正しさシグナルの後付け (絶対規律 3) と
  同じ形になる。(c) その決定は依頼が本 wave から明示的に外した領域である。{{D:tail-formal-second-cohort-status-first}}。
- **段 3 の 2 レンズは結論が割れた。**レンズ A は「投入せよ」、レンズ B は「再投入せず既存 cohort の
  確認を完了させよ」。親は B 寄りに裁定しつつ、A の中核の指摘を real として採用した。
  B が求めた「現証拠だけで valid と確定するな」は、再導出の実測に置き換えて閉じた。
- **refuted にした攻撃。** 探索走 campaign が v1 であることを理由に 09-15 の cohort を §7-18 違反と
  する攻撃は成立しない。2026-09-10 追補の主語は T-2418 の新走とその loader であって本走 driver では
  なく、本走 driver は明示的に渡された campaign を歴史的 raw として読むだけである。実測として
  探索走 3 本の mode はいずれも `legacy` で一致し、どれを渡しても mode 比較の結果は変わらない。
- **real だが本 wave で閉じない所見。** 事前登録 §0 は「発効後の変更は…変更理由と変更時点を本節へ
  明記する」と要求するが、2026-09-10 の追補は末尾にしか無く §0 に記載が無い。**文書自身の更新契約
  違反である。**ただしこれを失敗条件 §7-12 へ読み替えない。3 件の束縛記録は追補込みの
  commit / blob / spec で一致しており、§0 の記載場所違反を §7 のどれかへ当てる規定は無い。
- **記録しておく不在。** 09-15 の job 成果物のどれにも投入時の `B10_EXPLORE_CAMPAIGN` の値が
  残っていない。どの探索走 campaign を渡したかは保存物から特定できない。mode 一致により本件の
  判定は変わらないが、事実として残す。
