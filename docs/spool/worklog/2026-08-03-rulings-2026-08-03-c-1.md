## 本文

- 索引 11 件のうち詳説した 5 件をユーザーが**すべて推奨どおり**採用した。索引 6〜9
  ([T-296] / [T-369] / [T-373] / [T-376]) は親が推奨を出していないため裁定対象外とし、次回へ回す
- **[T-338] は Q1 / Q2 のみ裁定した。Q3〜Q11 の 9 問は未裁定である**
  - **Q1 = (a) 総回復率 `E[N]/E[D]`** — 劣化幅が大きい session を重く数える。RF は「劣化を
    埋め戻した割合」を系全体の量として述べる指標だという理由による。session 間の異質性を
    等重みにしたい場合は (b) `E[N/D]` が正しく、**目的から決まる裁定**である点は記録に残す。
    採用に伴い「事前登録した session 母集団が node・時刻・allocation のどの分布を指すか」も
    同時に固定する必要がある
  - **Q2 = `δ_D` を置く。stock 比の相対量として workload 別に事前登録する。**
    絶対 tps は workload 間で 2 桁違う (実測 W1 は 10 万台、W2 は 100 万台) ため共通の絶対値が
    意味を持たない。**primary endpoint は trace-disabled の `throughput_tps` 1 本**に固定し、
    abort 率等は説明用の副次指標として RF の family へ入れない
  - **paired を採る場合は roadmap §3.6 の改訂と D19 の適用前提の限定を同じ変更単位で行う**
    (協議改訂の手続き)。Q3 以降でこれが確定する
- **[T-367] は (b)** — fresh な rc=0 の qstat が QUE/HLD/STG を示したときだけ取り消しを許し、
  UNKNOWN・error では走行中ジョブを殺さない。(a) (`run_seen` 後の自動 qdel を全面禁止) は
  孤児ジョブを増やすため採らない。[T-360] の前提
- **[T-365] は (b)** — fold 署名 2 条件は **heuristic と明記して現状維持**する。
  意味検証 (FoldPlan delta の保存または決定的 replay) は **[T-347] が単独で所有**する。
  (a) をここで採ると [T-347] と二重所有になる。(c) は canonical 直接編集契約の廃止を同時に
  要するため採らない。**保証していないものを保証すると書かない規律**に沿って、
  署名が十分条件でない旨を実装・テスト名まで通すこと
- **[T-366] は (a)** — receipt schema へ tested main cutoff を別 field で永続化・binding し、
  supervised runner (checker / daemon) を land CLI と揃える。(b) (supervised 経路では main
  取り込みを禁じる) は長時間 wave の合流遅延を招き、16 commit 遅れで 3 度止めた前例がある
- **[T-371] は許可リスト側 ([T-189] 系) へ所有を寄せる** — model×reasoning の非対応組の
  事前検査は、本 wave で実装された許可リスト機構が所有する。組み合わせ表を足すのが最小変更で
  あり、既存 2 項目に寄せると二重管理になる。[T-183] / [T-184] は本件について参照へ降格する
  (各項の本来の scope は変えない)
