## 本文

- D1266 の条件どおり、`docs/phase3-b4-reflux-ablation-preregistration.md` の §5.1「対象 driver と軸」
  bullet へ、記入者・レビュー者の指名 (いずれも `thawk105`) とレビュー者の役割定義文を追記した。
  詳細と実測は `output/insights/2026-09-01_t1769-b4-reviewer-role/README.md`。
- **段 2 の plan は採らず、置換から追記へ変えた。** plan は (i) の要求文そのものを指名入りの文へ
  置換する案だったが、段 3 の敵対相談が「6 項目すべてが一つの述語の目的語のまま残り、この commit が
  (i) の freeze 完了なのか末尾 2 項目の先行指名なのか、置換箇所だけを読んだ人には判別できない」と
  指摘した。要求文を 1 byte も変えずに追記へ変え、「この指名が固定するのは (i) の項目のうち
  記入者とレビュー者だけであり、(i) の充足を意味しない」を明記して閉じた。
- **相談の対案のうち 1 件は意図的に採らなかった。** 相談は「事前登録の要求」の指し先が一意でないとして
  (i) へ限定する文面を出したが、限定はレビュー者の確認義務を狭める向きであり正しさ側を緩める。
  D1266 の逐語 (最も広い読み) を採った。
- **軽量版にしなかった。** 本変更は事前登録の規範節を書き換え「誰がレビュー者たりうるか」の受理集合に
  触れるため、`DW-C00` の「受理集合が変わる段では独立の敵対検証子を省かない」に該当すると裁定し、
  段 2 の plan 子 1 本と段 3 の敵対相談 2 本を回した。実装面はゼロなので段 5・6 の子は起動していない。
- **親 brief の一般化 1 件が相談に覆された。** brief は「§5.1 本体の編集は pin を破らない」と書いたが、
  安全なのは「`### 5.1` より後、H4 `#### 5.1.1` の開始 byte より前」かつ「新見出し・fence・
  HTML コメントを足さない」場合に限る。採った差分はこれを満たす。
- **相談が射影内で確認できなかった 2 点は親が閉じた。** (a) 文書全文を束縛する admission record は、
  production module が record path を driver 種別ごとの exact 3 path に固定しており、その 3 path が
  HEAD tree にも作業木にも無いことから不在と確定した。(b) analysis consumer が受け取る全文 bytes は
  §5.1.1 の切り出しにしか使われず、文書の全文 hash はどこにも作られない。
- **段 3 相談 A は初回が出力検査で不採用になった。** 内容は完成していたが最終見出しを 1 段浅く
  書いており、`## 総括` を要求する検査 (F43) に掛かった。原因は親の prompt が見出し階層を混ぜて
  いたことで、階層を明示した prompt で再投入して採用した。初回出力は
  `verbatim/s3-consult-a1-rejected.md` に保全した。工数は receipt に残る (初回 wall 289 秒)。
- **ユーザーの裁定へ返す real 所見が 2 件ある。** (1) §10 の残件記述は本変更後に部分的に古くなる —
  「(i) の先行 freeze が残る」という主張自体は真だが、「人間の指名を含むため AI が確定できない」と
  いう理由の説明が不完全になる。ユーザーが対象を §5.1 と明示したため触っていない。
  (2) レビュー者の履行を観測可能にするか — 相談は確認時点・項目別確認・確認事実の記録を足すべきだと
  主張したが、D1266 は役割定義文の中身を裁定済みで、追加は非同値な義務の新設になる。
  足さない現状ではレビュー者の履行は外形上観測できない。
- 本変更は文書を発効させない。(i) の残り 4 項目は未固定のままで、§5 の「対象 driver と軸」欄も
  `未記入` のままである。
