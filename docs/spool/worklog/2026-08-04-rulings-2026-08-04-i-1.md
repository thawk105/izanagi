## 本文

- **[T-088] = 8 request 案の新規 infra (約 1500 行) は建てない。** ユーザー判断は
  「外乱を見極めるツール作りにコストをかけるのはナンセンス」。
  **縛り「足りなければ拡大せず裁定へ返す」の適用先は測定規模**であり、実装規模はそれとは別の
  費用判断としてここで決めた
  - **前提を 1 点訂正して記録する。** ユーザーの理由づけは「ジョブ管理システムで制御されているから
    外乱はほとんどない」であったが、**スケジューラは専有を保証していない** —
    `qstat -Qf gen_S` の実測で **`Exclusive submit = OFF`** (runbook §1)。
    外乱が低く保たれているのは**計測前の pgrep 確認**による (F3 の恒久対応、
    「pgrep・load average の監視で外乱を避け、外乱を検知したら測り直す技法系が第一線であり捨てない」)。
    **結論は変わらず、むしろ訂正後の方が強い** — 外乱は既に安価な per-measurement 確認で
    押さえられており、between-run floor はその道具ではない
  - **floor が測る量は外乱だけではない点も記録する。** fresh build / 別 allocation / 別 node を
    跨ぐ再現性には **node 間のハードウェア差と build 差**が含まれ、これらは専有でも消えない。
    ただし本 wave が出す値は設計上 `evidence_class: lower-bound-only` であり
    **`compare` の `noise_cv` へ配線しない**ため、**いま 1500 行を建てる根拠にはならない**
  - **測定規模の縛りは既に満たしていた** — 8 request × 5 rep = 40 rep は、現行 driver の
    1 点 50 rep / 3 点 150 rep より**少ない**。縛りに抵触していたのは実装規模だけである
  - **進め方:** 既存 driver の最小 env 化で**安価な測定を先に取り、ばらつきの大きさを見てから**
    infra の要否を判断する。**ただしその値を品質ゲートに使ってはならない** — 単一 allocation 内の
    測定は allocation / build / node を跨ぐ変動を含まず、**揺れを系統的に小さく見積もる**
    (規律 4 の「小さすぎる測定は楽観的に歪む」)。scoping の測定であって floor ではない、と明記する
- **[T-244] 択一 1 (予算値) = (a) 下限式から再導出する。** `Imax` (総 iteration) /
  `Qmax` (総 candidate query = 漏れるビット数の上限) / `Kmax` (seal 後に公開できる class) の
  候補値 2 / 2 / 1 を、**`Q >= 1 + 32R + E_min` の下限式から導き直す**。
  R は最小の 1 でも **Q は 33 以上**となり候補値 2 とは 1 桁以上違う
  - **これは U3 (帰納段を踏む) の代償であることを明示的に受け入れた裁定である。** 座標 cut を
    主張する条件が「半空間 32 点すべてで同じ anomaly class を実測」であるため、
    **踏むと決めた時点で 32R 回の測定と同数の query が要る**。したがって origin あたりの
    accept/reject 漏洩は 2 bit から 33 bit 超へ広がる。**軸 (i) の「理由は 0 bit」は保たれるが、
    1 bit/query の面が約 16 倍になる**
  - (b) 据え置きは P6 が永久に発火せず U3 の裁定が実質無効になるため採らない
    (その場合は「還流は実現しない」と結論して閉じるべき、と設計本文が書いている)。
    (c) R を下げる案は R=1 が既に下限なので不可
  - **静的導出経路なら 32 点測定は不要**だが、現行の trigger / sort には静的写像が無いことを
    3 者が一致確認している。将来そういう軸を作れば下限は下がる
  - これで **P10 (予算値・origin authority・軸 (iii) がユーザー裁定で確定) の 3 点が揃った**
- **[T-413] = (d) 運用に委ねる。** 「索引・記録が実装状態を断定するときは一次資料で裏を取る」を
  入口へ書き足さない。**理由は検出の仕組みが既に働いているため** — 本日の親の記録誤り 2 件
  (pegasus env-tag / 前提 gate) はどちらも稼働 wave の前提実測が拾い、親が追認した。
  是正済みの収集経路 (repo 外 handoff を読む) がその検出を親側へ届ける。
  (a) 縮約は意味等価性の担保コストが 1 行の価値を上回り、(b) reference 新設は dev-wave 側で
  同型が D94 却下案 (a) として却下済み、(c) 予算引き上げは方針に反するため採らない
