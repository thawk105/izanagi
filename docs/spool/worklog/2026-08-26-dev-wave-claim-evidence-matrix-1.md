## 本文

- ユーザー依頼は「新規測定なしで論文執筆を前進させるため、claim-evidence matrix を材料として作る。
  主張 1 行につき (a) exact claim の文 / (b) 一次資料のパス / (c) 実証状態 / (d) 但し書き /
  (e) 但し書きを外すのに要る A/B 項目 ID を並べた表と、そこから直接書き起こした limitations 節の原稿」。
  入力の正本は `docs/paper-story/2026-08-26.md` の §3 / §6 / §7 / §8 / §9。
  **数値・日付・判定は一次資料からのみ取り、paper-story の版を数値の出所にしない**という制約つき。
- 成果物は `docs/paper-story/claim-evidence/2026-08-26.md` (新規) と、系列の運用規則を足した
  `docs/paper-story/README.md`。**新規計測はゼロ。実装面の差分もゼロ**なので D95 の Codex author は
  非発火、変異 matrix は免除 (`DW-S04`)。受入全走は免除せず実施した。設計判断は
  {{D:claim-evidence-series-namespace}}。
- **段 3 の 2 レンズは、親の provisional 裁定 5 件のうち 3 件を拒否した。**
  拒否されたのは (P1) 同一ディレクトリへ suffix 付き filename で置く案、(P2) README にポインタ
  1 行を足すだけの案、(P5) §9 の 6 分類だけを閉じた語彙として使う案である。
  **(P5) への反証が最も有用だった** — 6 分類は成熟度しか表さず、読み違い防止 4 条の事故面は
  claim 表ではなく A/B/C の現在地表の側にあるので、分類語彙だけでは 4 条を構造的に閉じられない。
- **親が最初に書いた (e) 欄の設計は、防ごうとしていた誤読を自分で可能にしていた。**
  列名を「解除条件」にしたまま「後続別主張」という型を入れたため、
  「A-1 を取れば C1 の但し書きが外れる」と読める。実際には A-1 を取っても
  「この測定は D496 以前に行われた」という事実は変わらず、現行契約下の別の主張が 1 つ増えるだけである。
  段 6 のレンズがこれを「A/B 項目を取った時点で過去行から限定を削除する retroactive な過大主張が、
  この表を根拠に書けてしまう」と指摘した。(e) を `外せる項目:` と `後続別主張:` の 2 行構成へ
  分けて閉じた。**誤読防止のために作った欄が誤読の経路になる型は、今回が 1 例目である。**
- **段 6 のレンズが、親の持っていなかった一次資料の事実を 2 件出した。**
  (1) S-1 直接比較 campaign の WAL は `verify_done` の workload tag が `legacy` で、性能側の
  configure は `CCBENCH_TRACE=0` である。つまり **S-1 の「certified 標本」は性能実行そのものを
  検証したものではない。** 親は WAL を開いて裏取りした。
  (2) S-2 / S-3 の 0.115 / 1.0 は **名目 p (片側 Fisher 正確検定)** であって family p ではない。
  親は `output/insights/2026-07-13_s6-report-language.md` で裏取りし、初稿の誤記を訂正した。
  S-1a / S-1b の `family p` は一次資料自身の用語なので据え置いた。
- **親が制約を 1 箇所破っていたのをレンズが見つけた。** 初稿の「SS2PL を ycsb-a で測ることが
  一度も行われていなかった」は履歴の主張だが、一次資料が示すのは現行 pin の source tree に
  `ycsb_ss2pl.exe` target が無いことまでである。**この履歴の主張は paper-story の版にしか
  根拠が無く、依頼が禁じた経路そのものだった。** 現在形へ狭め、禁止推論として明記した。
- **`authority: none` を宣言している文書を一次資料に据えかけていた。** A-3 の利得統合 report は
  冒頭で `authority: none` を宣言し、値の権威を campaign の WAL / `campaign.lock` へ戻している。
  段 3 の指摘を受けて (b) 欄を `[権威 bytes]` と `[導出索引]` の 2 段に分け、
  `authority: none` の文書は後者にしか置かないという欄の規則にした。
  同じ規則で C13 / C14b の証拠 path を repo 外の完全 path へ直し、C14a は raw artifact を
  特定できなかったので `[権威 bytes]` を「未特定」と明記した。
- **親の自己記述が 2 箇所、事実と食い違っていた。** (1)「limitations は (d)(e) 欄だけから
  起こしている」と書きながら、実際には (a) 欄由来の条件を書いていた。(2)「claim 行に紐づかない
  限定は L05 と L09 の 2 件」と書いたが、実際は L21 と L27 も紐づかず 4 件だった。
  どちらも段 6 のレンズが指摘し、規則の側と対応表の側を実態へ合わせた。
- 成果物の構成: 読み違い防止 4 条と**書けない 4 文の明示**、claim 表を種別で 3 分割
  (科学的主張 / 運用・方法論の証拠 / 文献 guardrail と副産物) して計 22 行、
  「いま書けない主張」12 行、§7 の 28 項目を全数保持した限定レジストリ `L01`〜`L28`、
  A/B/C 項目の現在地 (各項目に `evidence_delta`、群を移った項目に `move_reason`)、
  limitations の日本語統制稿 8 小節。
- **表の分割だけでは行単体の防護にならない**ので、全 22 行の (a) 文頭に抜粋しても残る
  〔役割〕タグを置き、(d) の末尾に `✗` で始まる禁止推論を必須にした。
- **§7 の 28 項目のうち 4 件 (L05 / L09 / L21 / L27) は claim 行に紐づかない。**
  紐づかないまま保持し、対応表で「どこで効くか」を示した。
  claim 行の (d) を追うだけでは limitations が書けないことを本文に明記してある。
- **本 wave が確かめていないこと:** C3 / C9 / C10 / C16 の (b) は `[導出索引]` だけで
  `[権威 bytes]` を持たない。機構の成立や調査の状態を述べる行であり、完走そのものの観測
  artifact は特定していない。英語版は作っていない。A-1 の estimand 不一致は `要裁定` のままとし、
  二択 (案 A = 分母を組み直す / 案 B = 別 claim として採る) と帰結だけを固定した。

- **段 8 の自己改善は候補 2 件を記録し、command / reference は編集しなかった。**
  (1) `tools/dev_wave_wait.py acceptance --help` は `--` delimiter が必須のため単独では rc=2 になり、
  argv は `docs/pegasus-runbook.md` §7.3 を読まないと分からない。正本が既に持っており実害ゼロなので、
  事故を伴わない明確化として入口・reference の編集理由にしない。
  (2) **docs-only でも一次資料から数値を再抽出する wave ではレンズを省くべきでない** —
  本 wave は `DW-C00` の既定なら段 3・段 6 を省けたが、レンズが親の制約違反 1 件と
  一次資料との食い違い 4 件を出した。族への一般化は `DW-G03` が独立 2 例を要求し、
  **本 wave が 1 例目**なので制度化しない。
