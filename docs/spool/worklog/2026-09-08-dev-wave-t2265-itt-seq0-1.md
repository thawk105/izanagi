## 本文

- **除外規則を、改訂後の推定値を計算する前に凍結した。** 事前登録 v2
  (`docs/backoff-counterfactual-preregistration.md`、bytes の sha256
  `526d9384d8a8c62f82b132c41672aa2eff32722788ad06858c09f80185ca495a`) を docs のみの commit
  `1c977a218` で固定し、その後で解析器を合わせ (`1c482bf6f`)、その後で解析した。
  **commit 順が凍結の順序である。ただし証明できるのは「v2 の bytes が解析器 commit と結果
  commit の祖先にある」ことまでで、「別経路で先に計算していない」ことは証明できない。**
  一次資料は `output/insights/2026-09-08_t2265-itt-seq0/README.md`。
- **再測定していない。** 新しい `analysis-result.json` の `inputs[].sha256` は、前 wave の同 field と
  **12 件すべて一致**する。計算ノードへ 1 件も投入していない。
- **主判定はなお `inconclusive`。ただし原因が変わった。** 前 wave は 0 commit event 57 件のうち
  55 件が走り出しの `seq = 0` で発火していた。位置除外でその 55 件は落ちたが、**主層 12 run の
  うち 1 run** (seed `13467815584134101060`) に `seq >= 1` の 0 commit が残っており、そこで
  規則が発火した。残る 11 run は推定値を出した。
- **事前登録 v2 §7 は、この事態の扱いを結果より先に定めていた** —「`seq >= 1` の 0 commit を落とす
  改訂を結果を見た後に行わない。再び inconclusive になった場合はそのまま報告し、同じ 12 成果物に
  ついて本書を再改訂しない」。**そのとおりにした。**
- **副次の 5 層 (workload x threads) は v2 で判定可能になった** (v1 では全滅)。ただし事前登録が
  「探索的な記述であり主判定を置き換えない」と定めた層である。**11 run で集約した推定値は出して
  いない** — 欠落理由が outcome の 0 である以上、complete-case 選択は outcome 依存であり、
  12-run の推定対象を別の 11-run の推定対象へ無断で変えることになる。
- **v2 を「完全に前向きな事前登録」とは呼ばない。** 除外規則は v1 の主判定と欠測の内訳を見た後に
  選んでおり、`window_commits` は outcome の分子そのものである。名乗れるのは「outcome を部分的に
  開示した後に、改訂後の推定値を計算する前に凍結した、事前指定の再解析計画」までである。
  この限定は事前登録 §0 自身にも書いた。
- **段 3 の敵対相談が親の草稿の誤りを 2 件見つけ、どちらも凍結前に直した。** (1)「推定対象を 1 字も
  変えていない」は誤り — §4 の添字域を書き直さないと §4 と §7 が食い違い、凍結した推定量が
  一意にならない。(2)「`seq = 0` の event は処置と無関係」は言い過ぎ — event 0 は最初の割当を持ち、
  位置除外はその直接対比も落とす。除外が処置前だと言えるのは選択規則が位置だけに依るからである。
- **段 6 のレビューが、事前登録した変異 2 件の帰属不成立を実証した。** 片方 (row pin を v2 固定に
