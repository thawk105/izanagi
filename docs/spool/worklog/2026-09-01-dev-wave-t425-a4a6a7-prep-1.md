## 本文

- 依頼は「D1339 に従う AI 側工程 (準備と検証) を実施し、承認 record の発行と有効 pointer の
  発効は行わない。人間手番を 1 画面で読める形にまとめて返す」。scope どおり発行・発効はしていない。
- **軽量版を使わなかった。** 対象が activation の正しさ関門であり `DW-C00` の
  「正しさ防壁に触る段では独立の敵対検証子を省かない」に該当する。F 台帳の 2026-09-01 再発項が
  「停止で終える wave を軽量版の根拠にしてはならない」と定めたのと同じ発火点である。
  同項の再発検知策どおり、段 3 の 1 レンズを親の実測結論の反証専任にした。これが効いた。

- **親の実測結論が 2 件、段 3 で反証された。**
  - **A4 の検証経路が誤っていた。** 親は `_is_valid_activation_successor_with_artifact`
    (replay 用) で候補 bytes を検証していたが、発行器 `issue_env_contract_activation.py` は
    `_is_valid_activation_successor_for_issue` を使い、未 active successor に現行
    `EFFECTIVE_CLOCK_METHOD` との一致を追加要求する。**発行時経路で測り直したところ通った。**
    結論は変わらず根拠が正しくなった。診断 state は両経路とも
    `398b192013e0e3996ca225454049a14cb2866ef256b581fc3dfbfda02476bed8` で、
    2026-08-25 の記録値と exact 一致。record は発行していない。
  - **「A6 の AI 側準備は実行不能」は誤りだった。** 親は `build_v2_g1_candidate()` が
    `BUDGET_APPROVAL_SHA256 = None` で `budget-approval-not-ratified` に落ちることを実測し、
    そこから「A6 の準備は今日できない」と一般化した。D1391 が凍結側下位実装の exact 正本適合と
    「人間承認直前までの successor 準備」を既に解禁している。**候補文書の生成**は今日も
    到達不能 (D589 と同じ 3 条件) だが、**着手可能な準備作業は別に在る**。
- **その作業は本 wave の scope 外とした。** D1391 が解禁した作業は `T-2105` という別 ID の
  carry (P2・裁定済み・着手可) に立っている。依頼は [T-425] に限定されており、
  別 ID の実装を取り込むのは scope 拡大にあたる。readiness index の
  `FREEZE-AX-TOPOLOGY` 行の owner も `lower-impl-wave` で T-425 ではない。
  代わりに A6 行と最終報告へ明示的に handoff し、「AI 準備完了」とは書かなかった。
- **人間手番の順序が既裁定から確定した。** D437 が環境世代と凍結世代の lockstep を定め
  片側交代を却下しているため、**A4 の activation record を単独で先に発行することはできない。**
  D1398 は budget 承認が走行の前提ではなく凍結昇格の閂だと定め、
  D1396 は床値 official が staged transport の不適格で起動できないと確定している。
  順序は 床値 official → budget 承認 (人間) → 凍結 g1 候補 (AI) → 承認 record と pointer (人間)
  → activation record と reviewed head (人間) となる。

  contract hash / 較正 hash、段 0 の 7 数値と gate ID 3 件、繰越 fixture 5 件の ID、
