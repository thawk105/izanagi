## 本文

- `/rulings all 説明付き` (2026-08-22) で提示した判断待ち3件について、ユーザーが裁定した。
- **[T-1461] (floor campaignのmasstree配線修正のscope):** 推奨 (a) どおり進める。
  ユーザーは「測定に影響しうるコードをしばらく開発できない、という規律は存在しない。測定とは
  『このコミットIDで測った』という記録であり、そういう予定を立てた時点で開発を止める話ではない」
  と明確化した。「測定ロジックへの変更を特別に許可する」という rulings 側の説明枠組みが不正確
  だった — 実際には T-1461 起票時の command が「shell 2 file だけ直せばよい」という狭い前提を
  置いていただけであり、調査でその前提が誤りと判明した以上、必要な production 変更を通常の
  実装プロセス (実装面の変更のため Codex role=author、敵対レビュー、変異 matrix、受入) で
  進めればよいだけだった。特別な許可枠は不要。
- **[T-1472] (C04 の crash 定義に provider-init 失敗を含めるか):** 推奨 (a) どおり進める。
- **[T-901] (床値run の途中死に対する救済経路、`docs/phase3.md` 見送り台帳):** 推奨どおり進める。
  rulings 収集時の追加調査で、`docs/decisions.md` の D510 (2026-08-18) が T-901 の再訪条件
  そのもの (`8b §9 項 8 の再走全拒否よりD496決定3を優先する`) を既に裁定し、事前割当
  attempt registry の具体設計まで定めていると判明した (D510 決定4)。D510 は正式 H1/H2
  campaign 向けの再凍結として書かれているため、床値 (8b v1 freeze) 系にも同じ設計・優先順位を
  そのまま適用してよいかは技術的に未確認だったが、ユーザーはこれを追加の設計裁定を待たず
  適用する前提で実装 wave を起票してよいと裁定した。
