## 本文

- ユーザー依頼は (1186) が残した「655 万件超で所要が頭打ちになる観察は未確認で、トレース
  切り捨ての可能性がある」の決着である。**本題の実測だけ**とし、仮想リスク向けの gate・検査・
  台帳・一般化の追加は scope 外だと最初に確定していた。実装面の差分は 0 で終わった。

- **判定: トレース側だけで件数が減る切り捨ては起きていない。** B-10 正式走系列 4 campaign の
  verify 反復 287 件すべてが `certified=true` だった。`certified` は「検査器が読んだ committed txn 数
  = CCBench 自身の commit counter」「txid に欠番なし」「取引 frame が宣言どおり閉じている」
  「orphan read なし」を同時に要求する連言なので、検査器自身が 287 回すべてで完全性を表明していた。
  `abort` stage は 0 件で、検査が拒否した走行は 1 件も無い。

- **敵対相談 2 本 (正しさ境界レンズ / 数量的主張の整合レンズ) の所見 14 件を全部 real と裁定した
  (refuted 0)。** 判定の向きは変わらなかったが、書き方の限定が 12 件入った。子が出した数値は
  すべて親が独立に検算して一致した。主なものは次の 3 つ。

  1. **親の数え直しは独立な第二の証拠ではない。** `serializable` verdict が integrity clean を
     要求し、clean が `observed==expected` と `dup_txids==0` を要求するので、WAL 上の C 行数の
     一致は verdict から導ける。確かめられるのは「WAL の投影が判定と食い違っていない」までである。
  2. **判定の射程を限定した。** D295 が明記する非検出限界 (trace と counter は同じ実行体から
     出るので common-mode failure と個数を保存する破損は検出しない) は今回の走行で閉じていない。
     「独立 witness」「切り捨て一般の否定」とは書かない。
  3. **`abort=0` から「異常終了なし」は導けない。** `build_start` 49 / `commit` 47 で、
     予定 294 反復に対し観測 287、**7 反復は実行されずに終わっている**。外側 job の壁時計
     打ち切りによるもので、検査の拒否ではない。その 2 変種は 45 cell に含まれない。

- **親自身の誤りを 2 件記録する。** (a) 655 万件の帯を mu=100 と誤帰属していた。成果物の
  variant_id→point 対応表で確認したところ正しくは **mu=25 の 2 点 (10 反復)** である。
  (b) 最大 commit 数と最大所要を組にして書いていたが、両者は別の反復である。

- **refuted 1: 「所要は取引試行数の関数」。** cell 間で所要を説明するのは commit 数で、
  相関は r=0.9991、試行数とは r=0.4044 だった。両方を入れた回帰では試行数の係数が
  -0.309 マイクロ秒 (実質 0) になる。write-heavy では commit 数が 2.5M 付近で飽和する一方
  試行数は 21M まで伸びるので、試行数を横軸に取ると平らな帯ができる。それが「頭打ち」だった。
  ただしこれは cell 間の予測関係であって機構上の限界費用ではない。**所要は混合区間**で、
  ベンチ本体・トレース書き出し・C 行の数え直し・検査・一時 dir 操作・WAL 書き込みを含む。

- **refuted 2: 「read-heavy の検査対象の合計は write-heavy とほぼ同じ約 2000 万件」。**
  それは試行数の合計で、所要を決めていた量ではない。同じ段落の「commit が 1690 万件」の方が
  正しい。起票元の「約 25.6 マイクロ秒/件」「175 秒」「655 万件」は単一の測定からは再現できず
  (`6.55M x 25.6us = 167.7 秒`で 175 秒と 4.4% ずれる)、近傍の複数行をまとめた読みである。

- **絶対規律 7 に従い、当時の判定は昇格も降格もさせない。** 45 cell の
  `correctness_certified=true` はそのまま維持される。その意味も変わらない — 15 変種 × 6 反復の
  trace 有効走に由来し、同一 point の 3 block が 1 変種の認証を共有する。

- **純増は実測だけである。** 機構は D295 (trace 外 counter による個数の裏取り) と D540
  (末尾欠番 false-green は本番 2 経路で緩和済み) が既に定めていた。誰も数えていなかったのは
  「その機構がこの走行で実際に clean だったか」であり、本 wave はそこだけを埋めた。
