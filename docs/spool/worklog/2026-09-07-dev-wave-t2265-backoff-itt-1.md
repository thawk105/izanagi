## 本文

- **事前登録を結果より先に凍結した。** `docs/backoff-counterfactual-preregistration.md`
  (sha256 `ee7617f57bf6816fd8bfb42b5830926be1174ebcca617ed122c3fbca62f127a6`、commit `a27543ab2`)。
  固定したのは主推定量の定義式と符号、outcome、対称 log 等価域 `±ln(1.03)` と TOST、主層、
  副次層、除外規則、12 seed の逐語一覧、run cluster の分散、検出力の条件、停止規則、
  記録する束縛、主張してよい範囲である。一次資料は
  `output/insights/2026-09-07_t2265-backoff-itt/README.md`。
- **12 seed の実測を完走した。** 12 job すべてが完走し、成果物 12 件すべてが事前登録の sha256 を
  `counterfactual_preregistration` に記録している。1 job あたり 18 run。**投入経路の契約は
  1 byte も変えていない** — 既存の投入スクリプトが反実仮想の 3 腕を既に受理形として持っていた。
  新規 Pegasus 実行体は作っていないので F660 は本 wave を止めなかった (判定は段 1 で済ませた)。
- **主判定は `inconclusive`。事前登録した規則が発火した結果である。** 窓の commit が 0 の event が
  1 件でもあれば主判定全体を判定不能にする規則 (処置後除外を避けるため) が効いた。
  policy 2 の全 72 run・51,748 event のうち該当は 57 件 (0.110%) で、**うち 55 件は seq 0**、
  すなわち最初の割当が当たる前に閉じる走り出しの窓である。副次 14 層も同じ理由で判定不能。
- **規則を結果の後に変えなかった。**「seq 0 を位置だけで除く」は筋の通る処置前の規則だが、
  結果を見た後に採るのは後付けである。**seq 0 を除いた推定値は計算していない** — 計算すれば
  次の事前登録がその値を見た後のものになり、追試の価値が失われる。
- **次の一手は測定のやり直しではない。** 12 の成果物は束縛ごと凍結されている。次 wave は
  seq 0 の除外を結果より先に事前登録し、この 12 件をそのまま解析するだけで確認的判定を出せる。
- **段 3 の敵対相談が親の草稿の誤りを 2 件見つけ、どちらも親が現物で裏を取って直した。**
  (1) 比の域 `[0.97, 1.03]` の log は対称ではない (`ln(0.97) = -0.030459`、
  `ln(1.03) = +0.029559`)。対称な `±ln(1.03)` へ直した。
  (2) 「write-heavy 48 以外は勾配 0 が 39〜51%」は親自身の表と矛盾する (balanced 48 は 2.1〜8.1%)。
  主層は維持しつつ「唯一腕が届く層」という一般化を撤回した。
- **段 6 のレビュー 2 本が独立に同じ恒真ゲートを見つけた。** 判定の定数 (90% の t 値・等価域) を
  テストが実装 module 自身から取っていたため、定数と実装を同時に変えると緑のまま通り、
  事前登録した変異 2 件を検出できなかった。逐語の期待値で固定し、90% と 95% で判定が変わる
  合成 cluster を足して挙動でも赤くなるようにした。**この修正の効果は本走で実測されている** —
  probe では該当変異が MISMATCH 止まりだったが、本走では完全一致の KILLED になった。
- **認証要求の受理集合が広がっていた (絶対規律 2)。** seed の引数を共通の引数解析へ足したことで、
  driver を直接呼ぶ認証要求が seed 付きでも受理され、seed が黙って無視されていた。明示拒否させた。
- **scope を 1 つ絞った。** trace 無効の性能 7 block は実施しない。依頼が名指しした推定量ではなく、
  7 block とも腕の測定順が固定で job 内時刻と完全に交絡し、腕は未認証だからである。
- **子はどの段でも pytest を 1 件も走らせられなかった** (sandbox の投入失敗)。実装子も fix 子も
  同じで、実測はすべて親の焦点走である。修正前 803 passed、修正後 820 passed / 1 skipped、赤なし。
- **受入全走が赤 1 件を返し、それは自分起因だった (F42 の 7 回目)。** 新設した
  `orchestrator/tests/test_backoff_counterfactual_analysis.py` が自走 harness を持たず、
  `test_plain_runner_coverage.py` のメタテストが弾いた (21,309 passed / 68 skipped / 1 failed)。
  **防壁は設計どおり機能している。** 抜けていたのは親の焦点走の集合で、`DW-O26` が
  「新規 test file を足す走は file 集合列挙のメタテストも焦点走に含める」と逐語で書いており、
  条件 18 で必読に指定されていたのに適用しなかった。fix 子が `_run()` と `__main__`、
  import bootstrap の計 11 行を足し (assertion は 1 つも変えず、allowlist へも逃がさず)、
  親の焦点走がメタテストを含めて 24 passed・赤 0 を確認した。
- **段取りのつまずきを 4 件記録する。** (1) 生死確認の `pgrep` が別 session の変異走行に一致し、
  止まっているのに実行中と誤報告した。DW-M05 の「worktree path で一意化する」を守っていなかった。
  (2) 期待 node 名が parametrize の接尾辞 `[overflow]` を欠いて preflight で止まった。
  (3) 変異 spec の内側 timeout が、混雑対策で入れた投入待ち契約より短く fail-closed で拒否された。
  (4) 変異走行中に親が repo へ notes を書き、untracked file 検出で走行が止まった。
  詳細は `output/insights/2026-09-07_t2265-backoff-itt/mutation-notes.md`。
