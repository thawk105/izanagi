## 本文

- `/rulings` セッション中にユーザーと [T-1316] (受入 lease 取得後・受入 command 投入前に main が
  進んで lease を失う型の回復策) を検討した。裁定パッケージの P1 (運用ルールのみ) / P2
  (ファイル必須化) / P3 (自動生成、却下) という枠組みに対し、ユーザーから「merge を実行して
  いる当人が自分の身元を名乗れば足りるのでは」という指摘を受けた。
- コードを実測して指摘を検証した結果、的確だった。`tools/dev_wave_wait.py` は呼び出し元の
  製品を判別する手段を持たない一方、`tools/check_ai_provenance.py` の Codex `role=author`
  要求は「merge 結果が両親双方と食い違う実装面 path がある場合」だけに絞られており、
  `owned-path-overlap` 検査により実装面での真の衝突は構造的に稀となる。現行実装はこの
  分岐前に無条件でファイルを要求しており過剰だった。
- **ユーザー裁定:** 元の P1/P2/P3/現状維持は採らず、新しい方式
  ({{D:t1316-conditional-authorship-escalation}}) を次の実装 wave の本命として記録する。
  本 wave は実装せず、裁定の記録だけを行う。
