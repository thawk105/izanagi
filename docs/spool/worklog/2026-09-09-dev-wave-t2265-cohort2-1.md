## 本文

- **主判定が確定した。** `decision = recommended_direction_superior`、12 cluster 完備、
  判定を止める規則は 1 つも発火しなかった。効果 **+4.900%**、95% CI **[+3.316%, +6.509%]**、
  その下端が実用差の境界 +3.0% を上回る。TOST は等価を棄却しない。
  一次資料は `output/insights/2026-09-08_t2265-cohort2/README.md`。
- **cohort 1 の主判定を確定させたのではない。** 窓構成を変えたので推定対象が変わっている。
  cohort 1 の主判定は `inconclusive` のまま確定している。本試験は
  「cohort 1 を pilot とした、関連する新しい count-closed 推定対象への前向き確認試験」である。
  この位置づけは事前登録 §0.0 に凍結前から書いた。
- **同一の推定対象で決着させられない理由を計算した。** cohort 1 の主層は 12 run のうち 1 run が
  0 commit 窓で無効化された。同じ窓構成で測り直すと 12 run のどれかで再発する確率は
  `1 - (11/12)^12 = 0.648` である。規則を緩めて 0 commit の窓を落とす案は処置後 outcome による
  選択なので採らなかった。
- **余裕は薄い。** 95% CI の下端 +3.3157% に対し境界は +3.0% で、差は約 0.32 ポイントである。
  「大きな効果が確実にある」とは読めない。
- **事前登録を測定投入前に凍結した** (docs のみの commit、sha256 `8b4127f4…`)。
  cohort 2 は本 wave が初めて測ったデータなので、凍結前に計算しようがなかった。
  この点は cohort 1 v2 より前向き性が強い。設計に使った cohort 1 の開示情報 10 項目は
  事前登録 §0.1 へ数値ごと列挙した。
- **生死確認 (pilot) は凍結後・確認集合の前に 1 job だけ走らせ、別 namespace へ出力して
  確認集合から永久に除外した。** 見た項目は insight §3 に全開示した。theta / CI / decision は
  計算していない。
- **0 commit 窓が構成上生じないことを実測した。** cohort 2 の全走行で記録された窓の
  `window_commits` は最小 10,000、時間 cap の発火は 0 件。terminal event は各 run にちょうど 1 件、
  必ず末尾。**位置除外の後に残るすべての割当が後続窓を持つ。**
- **段 3 の敵対相談が親 brief の裁定を 3 つ実測で覆した。** (1) 巨大 cap は乗算で 64 bit を溢れて
  cap が即発火する。(2) 段 2 プランの terminal 設計は `common/runner.hh` を触るため
  `source_digest` の allowlist に拒否され、成果物が 1 件も出ない。(3) 12 job 同時投入で build cache の
  claim 衝突は起きない (t2187 は job 別 scratch で建てる)。親の「1 本先行 + 11 本」の段取りは不要だった。
- **段 6 のレビュー 2 本が独立に同じ最重要欠陥を指摘し、親の焦点走が実測した。** raw trace の版を
  無条件に上げたため、terminal を無効にした走行 (cohort 1 と legacy の全診断走行) が parser に
  拒否されていた。放置すれば既存の受理集合が縮み、事前登録が定める terminal 非閉鎖の
  `inconclusive` 経路も到達不能だった。詳細は {{F:cohort2-raw-version-bump-breaks-legacy-trace}}。
- **段 5 で 4 つ目の編集面が出た。** 新しい CMake define は条件レジストリへの登録が要り、
  A / B / C の所有外だった。unit A が検出し、親が unit D を立てて塞いだ。
- 段 4 裁定の 4 点を訂正した — terminal は期限経過に加えて count 閾値到達も要求する、
  「既存 cell の挙動は変わらない」は `clocks_per_us_ > 0` のときだけ正しい、unit は 3 でなく 4、
  認証 job 数は 49 でなく 48。
- **手順のつまずきを 2 件記録する。** (1) unit C を unit B の完了報告より先に投入し、必読不在で
  fail-closed 停止させた (子の挙動は正しい。親の順序付けの誤り)。(2) 変異 probe の走行中に
  親が insight を worktree へ書き、untracked 検出で中止した (F106 の再発)。
