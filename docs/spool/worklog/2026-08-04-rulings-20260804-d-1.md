## 本文

- **ユーザー裁定 3 件 (同日 /rulings セッションの 4 回目)。** 発話は「他は推奨通りで」—
  [T-444] = 条件付き採用、[T-448] = (b) harness 側機構、[T-186] = 条件付き見送り (見送り項)。
  一次控えは `/work/1/SFC/tanab/dev-wave-jobs/rulings-inbox/2026-08-04-rulings-session-5rulings.md` §8
- **[T-443] は裁定でなく質問が返った** — 「Lustre で login/計算ノードは /home・/work を共有して
  いるので、そこから解決できないか」。回答: 共有 FS は必要条件であって十分条件ではない。
  検証済みキャッシュは計算ノードから見えるが、当該 5 campaign は configure 時に
  `-DFETCHCONTENT_SOURCE_DIR_*` を渡さないため、CMake の FetchContent はディスク上のキャッシュを
  参照せず宣言済み外部 URL へ向かう (この override を渡すのは rung1 driver と T-139 probe のみ、
  `orchestrator/campaign/silo_ladder_rung1.py` で実測)。環境変数で代替する経路は CMake に無く、
  cache 変数として argv で渡すしかない。よって択 (a) の argv 配線は共有 FS があっても不要に
  ならない。裁定待ちのまま継続
