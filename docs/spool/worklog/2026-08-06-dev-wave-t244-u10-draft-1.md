## 本文

- **親の暫定裁定 4 件が誤りで、段 3 の敵対レンズが全部拾った。** 最も大きいのは
  floor 式の `rounds` と 8c V-3 の `R` を「別量」と書いた点で、**実際は同じ量**
  (P6 の独立 validation replicate 数) である。別軸なのは物理反復数 `reps` (2) と
  自動再測定 round 上限 (3) の方だった。他に `R=2` を parser 下限と誤読 (下限は 1、
  2 は `Bmin` の下限)、no-refund を全失敗へ一般化 (実際は予約受理後のみ)、
  V-2 evidence を現行 `drive()` 戻り値から導出可能と誤認 (戻り値に正本が無い) の 3 件。
  いずれも `s4-adjudication.md` §1 で撤回した。
- **段 2 の子が、親が見落としていた既裁定を掘り出した。** 2026-08-04 の /rulings が
  予算値の下限式 `Q >= 1 + 32R + E_min` を既に確定させており、親 brief の
  「8c が到達できる最小に置く」方針はその前で書き直しになった。一次資料
  (worklog archive と P6 契約 §3.10.1) で裏を取ってから採用した。
- **段 3・段 6 のレビューは 4 本すべて NO-GO を返した。** 段 6 で見つかった実在の誤りは
  (a) `Qmax` の会計で探索側のやり直し 2 query を数え落とし (66 → **68** に訂正)、
  (b) `Kmax = 1` を「導出」と書いたが実際は良い側で別 class が出ると封印不能になる
  **狭い policy の選択**である、(c) 単一 batch を「唯一の適合形」と書いたが実際は
  P6 の per-run iteration 会計の**改訂**である、(d) `candidate_min = 32` が
  「32 mask を実際に測った」ことを保証するという誇張、(e) 推奨 tuple が probe の
  576 組格子に含まれておらず追跡不能だった、の 5 件。すべて訂正した。
- **焦点再レビューを 4 巡要し、そのうち 3 巡は親の fix 由来の regression だった。**
  (1) 分類 C を批准対象外と書きながら択一 8 件すべてへの回答を批准方法とし、何を批准するのかが
  再び曖昧になった → 甲 (値が決まる) / 乙 (方向のみ) / 丙 (既裁定の変更) の 3 群へ分け直した。
  (2) 発行の分岐を「発行時期」だけの条件として書いたが、既裁定は
  「較正実測から起草し、批准で発行」という**一体の条件**であり、起草側の条件が崩れている以上
  発行可否は 2 条件の組合せで決まる → 分岐表にした。(3) §7 の手順 1 と 4 で provisioning の
  順序が食い違った。**「訂正が新しい訂正を呼ぶ」型で、docs-only でも焦点再レビューを
  1 巡で打ち切らなかったことが効いた。**
- **既裁定の方式からの逸脱 2 点をユーザーへ返す。** 2026-08-06 の裁定文は
  「calibrator 実測から根拠付き値案を起草し、ユーザー批准で authority 発行」だが、
  (1) 予算値は台帳の受理規則と P6 の証明義務から決まり**較正値は式に入らない**
  (新較正は未活性、旧較正は自己 attestation 不合格)、(2) `Qmax` / `Imax` は未決の
  producer topology に依存するため批准と同時の発行は作り直しの公算が高い。
  **親は不採用にせず、新事実付きで再裁定へ戻した。**
- **codec 包絡線は実測の結果、値を制約していなかった。** D189 / D198 が「狭まった」と
  記録した包絡線は、topology 格子 576 組が全て受理されたことから U-10 の値域では
  効かないと分かった。前提としては追認されたが、値を決める制約ではない。
  一方で `Kmax` の実効上限は **15,638** で、literal 定数 15,650 とは異なる
  (literal は SHA 配列単体の概算で、実際は `OriginSealed` frame 全体を 1 MiB gate に通す)。
  **批准資料に literal を実効上限として載せるところだった。**
- **本 wave は実装差分を持たない。** tracked な変更は `output/insights/` の docs と
  本 fragment だけで、コード・テスト・機械設定を 1 行も変えていない。したがって
  **変異 matrix と受入全走は射程外**である。検算 probe は Codex `role=author` が書き、
  repo 外 (job dir) に置いて land しない。probe は sandbox の制約で子自身は実走できず
  「実装済み・未実走」と正直に報告したため、**親が実走した**。
- **本番 authority (`reflux_origin_authority_v2.json`、71 bytes・entry 0 件) は 1 byte も
  変えていない** (D183 / D147 決定 4)。
- **段 8 自己改善は failures 台帳へ回した ({{F:fix-begets-fix}})。** `DW-S06-C` へ 1 文を足す
  案は `docs/dev-wave/**` の hard ceiling に **13 bytes しか空きがなく**入らなかった。
  [T-577] の既裁定 (予算上限は上げない、入らない分は台帳が担う) に従い、reference 編集は見送った。
- **main が `check_ai_provenance.py` で既に赤だった。本 wave の commit 由来ではない**
  (全件 ancestor 検査で確認)。land 起点 `5a322447` で 1577 件中 5 違反、取り込んだ
  `d60b3af0` で 1585 件中 6 違反。内訳は (a) `worktree-rulings-20260806-a` の merge commit
  5 件が `AI-Agent` trailer 欠落、(b) `b0a07672` (token-hygiene wave) が
  `output/insights/**` に置いた `.py` 2 本に対し Codex `role=author` 無し。
  **(b) は「insights 配下でも `.py` は実装面」という判定が効いた例**であり、
  逐語置き場に解析スクリプトを置くと author 要件が発火することを示す。
  既存履歴は書き換えない規約なので本 wave では触らない。異なる 2 wave の事故だが型が違うので
  DW-G03 の「同型 2 例」には当たらず、制度一般化はせず所在の記録に留める。
