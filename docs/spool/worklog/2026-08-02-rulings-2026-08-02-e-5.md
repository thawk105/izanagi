## 本文

- **[T-244] の §8 裁定表 7 件のうち 6 件をユーザーが推奨どおり採用した。**
  正本は `output/insights/2026-08-01_t244-reflux-design/README.md` §8
  - **択一 1 (予算値 `Imax/Qmax/Kmax`)** — 択一 3 の結論を待ってから再導出する。単独では
    origin 分割で回収されるため先に値を決めない
  - **択一 2 (承認上限の引上げを前提条件 P1〜P10 の充足検査へ機械束縛するか)** — 択一 1・3 の
    確定後に独立 wave で実装する。今実装すると未裁定の設計を既成事実にする
  - **択一 3 (軸 (iii) 候補 batch の事前凍結を多世代開放の必須前提にするか)** — **必須にする。**
    段 3 の両レンズが独立に oracle の残存を指摘した。採用に伴い batch cardinality・全候補の
    事前 commit・seal までの結果非公開を**セットで定義する**
  - **択一 5 (診断 run を予算の外に置く扱い)** — よい。予算に数えると配線確認だけで origin を
    使い切る
  - **択一 6 (origin authority の担い手)** — repo 内 tracked registry から始める。
    **「同一 UID の caller からの秘匿は不可」を残余として明示する**
  - **択一 7 (cut の適用範囲の正当化)** — **構造化 anomaly から禁止範囲を再導出する契約 (P6) を
    先に設計する。** これが無い限り本設計は規律 3 の還流を実現しておらず、[T-244] 本体は
    未解決のままである。exact-mask (安全だが封じ込め相当) と座標 cut (軸 (i) を満たすが根拠が要る)
    の中間の設計は、この契約の上で導く
- **択一 4 (critic を report-only にするか、reflux on/off ablation を維持するか) は未裁定のまま
  残した。** 裁定表は「両立しないため裁定が要る」とだけ書いており**推奨案を持たない**ため、
  「推奨どおり」を適用できない。親が独断で片側を選ぶのは裁定の逸脱なので、次回へ持ち越す。
  帰結は「report-only にすると 8c の on/off treatment label が意味を失う」対
  「bool を残すと critic は report-only でなくなる」である
- 択一 3 の採用により、択一 1 と 2 の着手条件 (択一 3 の確定) は**成立した**。値の再導出と
  機械束縛の独立 wave は着手可能になる
