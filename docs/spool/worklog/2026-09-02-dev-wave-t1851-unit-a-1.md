## 本文

- **単位 A を A1' と A2' へ割った。** 段 2 plan と段 3 の 2 レンズが独立に、単位 A 全体は
  1 wave に収まらないと実測した。production 差分 1,250-1,500 changed LOC、直接 test 面 153 node、
  consumer を含む回帰閉包 194 node である。本 wave は前半 A1' だけを積んだ。
  一次資料は `output/insights/2026-09-02_t1851-unit-a-registry-generation/`。
- **前 wave の見積りは「未測定」ではなく約半分だった。** 親 brief は「単位 A 単体の規模は
  未測定」と書いたが誤りで、前 wave plan v2 に `600-850 LOC / 35-55 node` が実在した。
  差の主因は `pytest.mark.parametrize` の未展開 (関数 94 に対し node 153) と、adapter の
  v1 型 hard-coded 参照 20 箇所の数え落としである。レンズ B が両方を指摘した。
- **親が「受理集合を狭める」と書いた変更は、実は広げるものだった。** 台帳専用理由語彙 4 語の
  固定について、現行の空集合が retryable terminal を恒真に拒否していたため、4 語を入れると
  これまで拒否していた形を受理する。段 2 plan が先に指摘し、段 3 の両レンズが裏を取った。
  この項目は sealed record の validator と同じ変更単位でしか有効にできないので A2' へ送った。
- **承認済み裁定に反する形の実装を止めた。** 段 2 plan の terminal projection は campaign の
  自己申告値を読み直すだけで、前 wave 段 4 が要求した「起動層が所有する生の事実から再導出し、
  自己申告 field は比較対象にだけ使う」を満たさない。生の事実の所有層は単位 C なので、
  A では API の形しか決められない。段 3 のレンズ A が blocker として実測した。
- **静的レビュー 3 本が揃って外し、親の実走だけが掴んだ赤があった。** 詳細は
  {{F:private-loader-return-type-breaks-facade}}。3 者とも公開 API の callable 経由 2 件は
  正しく数え、私有関数の直接参照 1 件だけが漏れた。
- **変異の事前登録 11 件のうち 4 件が現物で成立しなかった。** 詳細は
  {{F:pre-implementation-mutation-registration-misses-mask-layers}}。訂正して 13 件へ組み直し、
  本走は 13/13 が期待と完全一致した (KILLED 12 / 事前登録 SURVIVED 1 / MISMATCH 0)。
- **symlink 防壁の二層構造を実証した。** 片側変異 M5a は生存し、両層同時変異 M6 が kill した。
  fix 第 2 巡で「リンク先が完全な世代である symlink」の fixture と、防壁を外すと同じ台帳が
  実体と alias で二重に予算計上される (5 が 10 になる) ことを示す counterfactual node を足した。
- **M8a は kill でなく診断シグナルの pin として別枠にした。** adapter の digest 比較を消しても
  core が同じ入力を拒否し続け、test が落ちるのは文言検査のためである。受理集合は変わらない。
  実質の防壁は 11 件である。
- **段 6 レビュー A の唯一の must-fix は誤帰属だった。** 「実装差分 5 file が staged 状態にある」
  は、親の patch 抽出手順 (`DW-S05-A` 規定の `git add -A`) によるもので実装子の違反ではない。
  差し戻さず親が index を戻した。
- **A1' は最終成果物へ発火しない。** `launch_floor_attempt()` の production caller は 0 件、
  result はまだ v4 である。台帳束縛が効くのは B2 / D1 / C / D2 が揃ってからで、これは意図どおり。
- **セッション異常: Codex の利用枠が一時的に尽きた。** 段 8 の pin 追随を投げた子が
  `You've hit your usage limit ... try again at Sep 7th` で `f45_missing_output` になった。
  実装面を書ける子が居なくなったので、いったん `DW-O26` への統合を次 wave へ送り、予算に
  依らない `DW-O08` への統合だけを着地させた。D105 の「Codex 不可用時に親が書く」経路は
  ユーザー裁定を要するので通していない。**その後ユーザーから復帰の連絡があり、実測で子が
  起動できることを確認して同じ wave 内で pin 追随まで完了させた。**
- **pin 追随は 2 巡かかった。1 巡目の赤は親の折り返し位置が原因だった。** 正例 control が
  合成 fixture 中の「静的レビューが見落とした破れを」の 1 回出現を要求するのに、親の改行が
  「静的」と「レビュー」の間に入って連続文字列でなくなっていた。fixture を緩めず本文の
  折り返しを直して閉じた。
- **`dev_wave_submodule_init.py` の rc は submodule 状態の権威ではない。** fix4 の worktree で
  同 tool が 2 度とも rc=1 だったが、`git submodule status --recursive` は rc=0 で 3 階層すべて
  revision 付きだった。rc だけで「初期化できない」と判断しない。
- **工数:** codex 子 7 本 (plan 1、consult 2、author 1、review 2、fix 2。いずれも `gpt-5.6-sol` /
  xhigh)。plan と consult は read-only、author と fix は workspace-write。
  **codex 子は本環境で pytest を実走できず、実装子・fix 子とも「実装済み・未実走」と報告した。**
  検査はすべて親が login node で実走した。
- **人間手番:** 裁定パッケージ 1 件 (下記 T-1851 の更新に記載)。
