**裁定が要る理由は D703 である。** 自動削除が許される範囲は「同一 invocation の exact な wave
worktree path と wave branch ref だけ」で、「対象を特定したユーザー指示なしに AI が branch を

あり、**AI が単独で契約を作ること自体が射程拡大**になる。択一 8 件を裁定パッケージへ出した。

**親の主張が敵対レビューで 6 件倒れ、そのまま記録した。** 特に重いのは次の 3 つ。

1. **「[T-2641] の高速化を損なわない」は立証していなかった。** 一次照合が O(1) でも
   `hash-object` は内容 bytes を読む。**性能保証を撤回した。**
2. **「段 9 が正しい発火点」は限定が要る。** 子を作った後に記録を書く前に止まる経路、
   段 7 未到達、land 後 cleanup 前の終了、別 command 由来の木には届かない。
   段 9 は**正常終了時**の発火点であり、中断分は別担当を立てる。
3. **gate 全体を通る正例が 1 件も無い。** 止まる入力 2 型は実測したが、
   所有・終端・reflog・権限・非占有をすべて満たして撤去まで到達する例が無い。
   さらに既存 CLI の `_assert_clean_and_head` は HEAD == landing tip を要求するため、
   分岐元に留まる子の HEAD ではそのまま使えない。

**親が自分の計測器に欠陥を 2 度見つけ、1 度は作り直した。** 初版は
`git log --find-object` を着地判定に使ったが、**この command は既定で merge commit の差分を作らない**。
本 repo は `merge(main):` を多用するので、merge 経由で入った内容が「どこにも無い」と誤判定される
(実証: `-m` を付けると同じ blob が merge commit `9f2f8d3a3` に見つかる)。
初版の「着地していない」判定は全部取り下げ、`git rev-parse main:<path>` との直接比較へ直した。
敵対レビューは**修正版にもさらに 2 件**見つけた — 証拠 commit が blob を置いた commit とは限らない
(実例あり)、および検査不能を安全側・破棄側へ倒す作り (fail-closed でない)。
**本 wave では直さず、開示したまま凍結した。**

**依頼の前提に訂正が 1 つある。** 「差分の中身は再生成可能物ではなく実際の未コミットのソース編集」は
