## 本文

- **U-4 (最優先要件) を二入口 gate として実装した。** manifest 無しの起動は既定で拒否し、
  明示 opt-in のときだけ非認証で許す。holdout 束縛 workload は opt-in があっても無条件で拒否する。
  admission は unknown-workload 検査より前に走らせた — そうしないと `rr80` / `rr20` が
  `WORKLOADS` に無いせいで「未知 workload」として先に落ち、U-4 の検出力が恒真ゼロになる
  (段 3 レンズ A-1 / 段 6 レンズ B-3 が指摘、親が現物で裏取り)。
- **`certifying=true` は本 wave では構造的に発行しない**と裁定した。C02 の arm injective binding も
  T-295 approval record も存在せず、認証を主張できないためである。受入 receipt は常に非認証で
  `non_certifying_reason_codes` が非空 (`c02-arm-binding-unproven`,
  `t468-approval-authority-absent`) になる。したがって下流の accepted 入口は現状すべて拒否する。
  **合成条件 `certifying=true` の正例は作らなかった** — 作れば虚偽になるためで、機構単位
  (schema parse / tracked / bytes 一致 / 参照 hash) の正例だけを置いた。
- **段 4 で (P2)「production 関数名を evidence contract 名へ揃える」を撤回した。** 段 6 レンズ B-8 が
  「名前と文字列だけで述語 readiness が偽昇格し、配線済みと誤認させる」と指摘したのが real。
  `s8c_preregistration_evidence.py` と contract JSON は編集せず、12 述語の status を一切動かさない
  方針に変えた。SATISFIED は 0 件のまま。
- **段 1 の前提実測で N1 を発見した**: `python3 -m orchestrator.campaign.s8c_preregistration check` は
  12 述語すべてを `ERROR: evaluator-exception` として返す。`-m` 実行で core module が `__main__` と
  package の二重に読まれ、evidence module 側の `isinstance` が落ちるためで、API 直呼びは正常である。
  fail-closed なので誤受理は生じないが、**発効判定を CLI 経由で配線すると恒久的に閉じたままになる**。
  本 wave の配線は API (`effective_at`) に限定した。CLI 修復は {{T:s8c-check-cli-double-import}}。
- 段 3 は 2 レンズとも NO-GO (blocker 8 / 7)、段 6 レビューも 2 本とも NO-GO (blocker 5 / 2)。
  fix は 3 巡した。1 巡目の後の焦点再レビューで **fix 由来の regression 3 件** (generic Layer 3 が
  receipt 無しで `certifying_input:true` を出せる / lifecycle token が `dataclasses.replace` で
  全 field 差し替え可能 / F1 の再導出比較が前段に遮られ変異で kill されない) を検出し、3 巡目で閉じた。
- **変異は 16 件すべて KILLED、SURVIVED 0 件**。うち 8 件は事前登録 node と実赤が完全一致、
  6 件は実赤が上位集合 (過剰検出)。m13 は erratum を記録した — lifecycle 参照だけは全体 hash でなく
  prefix hash が守っており事前登録の照準が誤っていたため、補助変異 m13b で裏取りした。
  初回結果は消していない。逐語と両台帳は
  `output/insights/2026-08-05_t470-t327-wiring/`。
- 受入全走 (計算ノード) = **6253 passed / 19 skipped / 1 failed**。唯一の赤は
  `test_reflux_origin_ledger.py::test_v04_global_flock_race_reentry_and_public_signature` で、
  単独再走 27 passed の既知間欠 flake ([T-476] 所有、本差分と無関係)。merge 後に再走している。
- merge commit が provenance 監査で 1 件違反になった (両親のいずれとも異なる実装面 file が
  1 本あり Codex `role=author` を欠く)。merge を作り直し、統合結果の検証を Codex に回して
