## 本文

- **D1561 に従い択一は選んでいない。** 材料を集めて V-8 の裁定へ返すところまでで止めた。
- **「33 倍」は campaign run の本数比 (33 対 1) をそのまま実行費用の比と呼んだ数字だった。**
  現行コードで run の前置費と 1 行の費用を測ると倍率は 1.02〜1.11 倍になる。33 倍になるのは
  比較相手が物理行を 1 本しか実行しないときだけで、それは §5.3 自身が正しさの理由で退けた形である。
  全文と一次資料は `output/insights/2026-09-03_t2261-v8-cost-breakdown/README.md`。
- **費用より重い発見が出た。V-8 (a) は現行コードで実行形が成立していない。**
  `campaign_identity` は `CampaignConfig` だけから決まり `genomes` を含まないので、同じ cfg で
  33 回呼ぶと identity が 33 回とも同じになる。claim は identity を key に `O_EXCL` で作られ
  release API を持たないので 2 回目が拒否される。cfg を変えて 33 identity にすると、今度は
  `OriginBindingCapability/v1` が `campaign_id` を 1 つしか持たないことと衝突する。
  **裁定はこの衝突の解消と一体で行う必要がある。**
- **段 2 plan が親 brief の 4 前提のうち 3 つを訂正した。** (P1) 「(b) でも 33 行の物理実行がある」は
  誤りで、duplicate skip により 32 行になる。(P2) の固定費列挙は尽きておらず、存在しない
  「終端 seal」を数えていた。(P3) は検査器単体の 2.2 倍を行全体へ掛ける形になっていた。
  (P4) だけが real だった。
- **段 3 の 2 レンズが親の主張を 1 件 refuted にした。**「§11 の表の中で分母が入れ替わっている」は
  成り立たない。文面上の分母は一貫して (b) であり、誤りは分母の入替えではなく
  「run の本数比を費用比と呼んだこと」である。親はこの refutation を採り、成果物を書き直した。
- **親が測った 1.84 倍の因果は確定していない。** 同一変種・同一 commit 数 (差 1〜4%) で
  1672.789 秒 → 908.908 秒になったが、node が `bnode003` → `bnode015` と違い、検査器は worker
  起動に失敗すると無言で直列へ落ちる経路を持ち、WAL は worker 数を記録しない。
  ノード間の相対差は 1〜2% 台なので 1.84 倍を説明しないが、**「並列枝が発火した」は未証明**である。
  そう書いた。
- **`docs/phase3-8c-wiring-design.md` §11 の表は書き換えず、同 file の末尾へ追記訂正した**
  (絶対規律 7)。(a) 欄は「実行費用が 33 倍」のままである。
- **新規の測定投入はしていない。** 既存の B-10 正式走の成果物と、別 wave が現行コードで
  実行中の走行 (`974207.nqsv`) を read-only で読んだだけである。走行には触れていない。
- 実装面の差分 0 のため変異 matrix は免除。段 5・6 は飛ばして `4→7→8→9` とした。
- 子は段 2 plan 1 本と段 3 敵対相談 2 本。いずれも `check_codex_output.py` rc=0。
  段 3 の 2 本は codex sandbox の制約で pytest を実走できず、正しく静的検査だけと申告した。
