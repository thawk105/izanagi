## 本文

- **索引は 17 件。** 起草時は 16 件で、別系統モデル (Codex) への相談が誤載 3 件を指摘し、
  親が台帳の現物で確認して落とした。相談の走査範囲外で親が新エントリ 3 本から 4 件を足した。
- **相談が指摘した誤載 3 件はいずれも正しかった。** [T-2067] の (a) は D1526 が
  「oracle の report / verdict / judge へも選択強制を入れる」とユーザー裁定済み。
  [T-2355] は D1657 が「第三者生成 header の閉包は束縛しない」と裁定済みで、
  他 4 呼び手は D1666 の条件付き見送り (再訪条件は未成立)。[T-2393] は D1701 が
  「`not-consumed` は outer receipt へ運ぶ」と裁定済み。**いずれも worklog の項本文の
  「裁定待ち」表記が台帳より古い型** (D1335) で、項の字面だけを見ていたら 3 件とも誤って
  ユーザーへ返していた。
- **相談が挙げた索引漏れ 1 件は採らなかった。** [T-1998] を handoff の
  「最小欠落を実装するかをユーザーが判断する」を根拠に索引漏れとしたが、
  同項の実体は archive (`worklog-phase3-0902-1184.md`) にあり
  「裁定済み (D1244 の再確認) → 実装待ち: 最小 3 部品を実装する」である。
  相談の子は carry stub を実体へ遡れなかった (走査範囲を worklog.md 現行分に限ったため)。
  **handoff `2026-08-28-t1998-balanced-stock-inline-precheck.md` の「未完の作業」節が
  裁定前の記述のまま残っている**のが誤読の原因で、これは AI 側の整理対象である。
- **収集の語彙が変種を落とすことを実測した ({{F:rulings-collection-vocabulary-gap}})。** 入口が
  名指ししていた走査語では、エントリ 1327 の [T-2413]
  (「D1641 §11.1 が測定手順の**決定主体**をユーザーに置いている」) が 1 語も当たらなかった。
  ユーザー手番が「手番」「裁定」ではなく「決定主体を誰に置くか」の形で書かれると素通りする。
  {{D:rulings-scan-words-widened-within-budget}} のとおり、入口の走査語を
  『決める』→『決』、『ユーザー手番』→『ユーザー』へ広げた。**どちらも短くなるので byte 予算を
  増やさない** (5,619 → 5,607、上限 5,623)。予算値の引き上げは独立審査対象なので触っていない。
- **相談の子は 2 回投げ直した。** 1 回目は走査範囲を repo 全体に開いたため
  `stop_reason=max_model_calls` (既定 100) で出力ゼロ。2 回目は範囲を 4 点へ絞り 23 call で
  完走したが、read-only の子は file を書けないため launcher が `f43_fragment` と判定した。
  **中身は attempt events から回収できた。** 判定は launcher の受理形の問題であって
  子の失敗ではない。
- **走査中に main が 2 度進んだ。** 着手時 `645d0d663` → 相談中 `140f28f0b` /
  `0e02169b0` → 索引確定時 `80ece5897`。worklog がローテーションして行番号が別内容に
  なったため、索引を現行 main で取り直した。相談の子も同じ食い違いを自分で検出し、
  基準 commit を固定して再走査している。
