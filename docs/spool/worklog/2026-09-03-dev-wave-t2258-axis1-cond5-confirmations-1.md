## 本文

D1331 が要求した 3 確認を軸 1 について完了させた。**新規の OpenAlex 取得は 1 件も行っていない** —
2026-09-03 の走行が残した凍結 bundle に 14 run / 12 leaf / 93 頁の生応答があり
(`Q1` と `Q2` は attempt 2 本ぶん)、3 確認はすべてそこからオフラインで測れた。無償枠の窓は使っていない。

結果と改訂範囲の判断は {{D:axis1-cond4-cond5-unchanged}}。測定の正本は
`docs/related-work/claim-survey/2026-09-03b-axis1-cond5-confirmations.md`、
逐語証拠は `output/insights/2026-09-03_t2258-axis1-cond5-confirmations/`。

**実装面の差分はゼロである。** したがって変異 matrix は免除される (`DW-S04`)。受入全走は実走した。

- **段 3 の敵対 2 レンズが親の断定を 3 件崩した。すべて採用した。**
  1. 「`申告総数 − distinct` = 実際の非返却件数」は成立しない。この等式は失敗した走の申告母集合が
     固定されていることを要し、頁内重複 0・非隣接重複 0 ではそこまで言えない。
     別の走が申告総数へ到達した事実は、**その件数が別時点には到達可能だった**ことしか示さない。
     **裁定の依存を「同じ登録 request の独立 2 走で返却集合が違った」の 1 点へ組み直した。**
     この 1 点だけで、許容幅・重複吸収・distinct 化はいずれも食い違う 2 走の一方を `完走` として
     受理すると言え、条件 5 を緩める案の却下には十分である。
  2. 「多頁 leaf は独立第 2 走の digest も一致しない」は射程超過。catalog の
     `independent_pass_required` は OpenAlex 80 論理 query 中 76 件が真で、
     **偽はちょうど 4 件 = `Q1`/`Q2`/`Q4`/`Q5`** である。現在 条件 5 が不成立の 3 件
     (`Q1`/`Q4`/`Q5`) はこの 4 件の部分集合であり、
     **落ちている leaf はいずれも第 2 走を要求されていない。**
     登録上の第 2 走は 1 本も走っておらず、その digest 不一致は未観測である。
  3. 「機序は 1 つ」は判断不能。欠落時点の索引側スコアも共通 snapshot 識別子も証拠に無く、
     新規取得でも過去時点は復元できない。**有力な説明**として書き、確定と書かない。
- **段 6 のレビューが親の probe のバグを見つけた。** 親は「頁境界の重複のうち前頁の cursor 鍵の
  ID と一致するものは 0 件」と書いていたが、**実際は 32 件中 23 件**だった。
  cursor は base64 の中身が二重に包まれた文字列で、1 度の解釈では配列でなく文字列が返るため、
  比較が常に偽になっていた。レビューが出力の明細を数えて食い違いを指摘し、親が直して測り直した。
  **否定できるのは「三つ組が変わらない単純な再送」までで、cursor の境界規則そのものは否定できない。**
  事実として残るのは、再出現した 32 occurrence が**全件、前頁と異なる三つ組を持っていた**こと。
  2 走に共通する ID のうちスコアが変わったのは `Q1` で 45.4%、`Q2` で 51.7% である。
- **段 6 のレビューがもう 1 件、状態の誤記を見つけた。** 親は条件 5 で落ちている leaf を 4 件と
  書いていたが、**判定器は最後の attempt を採るので現在の不成立は 3 件** (`Q1`/`Q4`/`Q5`) である。
  `Q2` は 2 走目が申告総数に到達して通っている。4 件は `independent_pass_required` が偽の登録件数で、
  別の集合である (3 件はその部分集合)。
- **凍結実行記録 `2026-09-03-axis1-search-execution.md` §4 の記述が誤っていた。** 同節は判定反転の
  原因を「索引側の申告総数と返却集合が走査中に動くため」と書くが、**申告総数は動いていない** —
  1 走の全頁でも 2 走間でも同一である。凍結物は上書きせず新記録へ訂正として書いた。
- **親の probe が 1 度誤った。** 走の連続性検査で gzip 済みの bytes を hash し、93 頁全件を
  不一致と出した。evidence の `sha256` / `byte_count` は**非圧縮の応答 bytes** に対する値である。
  実測で確かめて直し、再走して **14 run 全件 OK** を得た (identity 一致・頁 0 が cursor 先頭・
  `parent_response_sha256` の鎖・`position_in`/`position_out` の鎖・status 200・body digest 一致)。
- **レンズ B が新事実を出した。親が実装で確かめた。** `validator.py` の `axis_complete` は
  `retrieval_complete` に加えて 5 つの component と `unimplemented_schema_layers == 0` を要求し、
  **設定しているのは test だけで production 経路に設定箇所が無い。**
  取得を全部終えても現実装では軸 1 は `完走` にならない。scope 外なので直していない。
- **U11 の解決と条件 4/5 の追認はユーザー裁定に残す。** レンズ B の指摘を独立に検証した —
  U11 は再改訂契約 §8 に未決として登録され、§13 が人間の裁定へ返している。
  完走述語は凍結契約の一部である。一方 `docs/decisions.md` は 1592 件中 324 件だけが
  ユーザー裁定であり、**台帳へ書くこと自体は wave の権限内**なので、主題の側で線を引いた。
