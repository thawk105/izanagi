## 本文

- **測定は一切していない。** F660 に従い機構の着地と実測を分けた。本 wave が主張できるのは
  「事前登録された反実仮想試験を次 wave で走らせるための機構が着地した」までである。
  一次資料は `output/insights/2026-09-07_t2265-backoff-counterfactual/README.md`。
- **段 2・3 をやり直した。** 段 3 の敵対相談が、診断走行の cell を exact に固定する述語
  (`_validate_backoff_trace_contract`) を改訂しないと反実仮想の腕がトレース経路に到達できないことを
  見つけた。これは既存 exact 述語の受理形を増やす = gate の新設に当たり、その条件の最遅読了段は
  段 2 より前だった。読み込み契約に従い段 2 の plan と段 3 の相談 2 本を invalidate し、
  実測 (述語が読む 6 field の現行実値、12 field cell が現行 parse で到達不能、
  投入 script 側の colon 数判定) を済ませてから brief v2 で回し直した。
- **設計が段 3 で変わった。** 当初案の「常に反転する腕」だけでは、両腕が別走行で最初の更新から
  軌跡が分岐するため測れるのは逆方策の総効果までであり、依頼文と材料が言う「同じ状態で逆の一歩」
  にならない。反転点は 1 箇所のまま「いつ反転するか」を 3 値の policy にし、更新ごとに 1/2 で
  割り当てる腕を足した。trace には割当の**前**に決まる `both_actions_feasible` を記録する
  (`inversion_realized` での層別は処置後選択になり偏るため)。
- **推定量は作らなかった。** 方向的中率の差は処置効果の推定量ではないという指摘を採ったが、
  等価域・検出力・除外規則を結果より先に凍結せずに推定量を実装すると誤ったものが焼き付く。
  driver に足した割当別の内訳は記述統計に留め、推定量 (割当についての ITT) は次 wave の
  事前登録の仕事とした。
- **「受理域を緩めていない」という表現を撤回した。** 正しさゲート (認証の exact 2 cell 契約、
  patch A の hard pin、既存の逐語 pin) は 1 byte も変えていないが、診断入力の受理集合は
  exact literal 1 本ぶん**拡張**している。集合論的に「緩めていない」とは言えないという指摘を採り、
  brief・README・本エントリでこの言い方に統一した。
- **子は 3 単位とも pytest を 1 件も走らせられなかった** (sandbox の `qstat -Q` 失敗で rc=16)。
  親の焦点走が本 wave の最初の実測であり、そこで赤 32 件が出た。内訳と帰属は insight §6。
  最も重かったのは patch が `#define` 本体でトークン貼り合わせを使い、`source_digest` の
  T-148 防壁が発火して認証経路が全停止していたこと。**防壁は正しく発火しており迂回していない。**
- **段 6 のレビューが「実装を赤に合わせて変えるな」を明記した。** 遷移テスト 5 件の赤は
  場面生成器が負勾配を作れていなかったことが原因で、反転点・割当・実行可能性・実現判定の位置と
  定義は裁定どおりであることが行単位で確認された。直したのはテスト側だけである。
- **親の帰属判断が 1 件覆った。** build sink の赤を「新 define が新しい sink を作った」と帰属したが、
  正体は deferred gate 台帳が sink を**行番号**で照合しており、driver の行数が変わるたびに
  失効することだった。実装 fix のたびに 2 度失効し、実装確定後に当て直して閉じた。
- **裸マクロ gate の直し方も訂正した。** patch を path 単位で allowlist へ載せるのは受理集合の拡大で
  あり、将来その patch に本物の裸マクロが入っても検出できなくなる。path ごとの許容 token の
  exact 集合に変え、既存の他 patch も同じ形へ固定した。
- **変異は probe → 本走の 2 段。** probe は KILLED 16 / MISMATCH 8 / SURVIVED 1 で、MISMATCH は
  すべて「事前登録した node は全部赤になった上でさらに赤が増えた」型だった (25 変異すべてで
  expected − observed が空)。観測された完全集合へ登録し直して本走し、24/25 KILLED +
  等価変異 1 SURVIVED、MISMATCH 0。台帳系 3 node は driver を書き換える変異で必ず付随発火する層
  なので、単独変異の独立証拠には数えない。
- **段取りのつまずきを 3 件記録する。** (1) 変異 spec は試験対象 checkout の外に置く必要がある。
  (2) spec の変異 entry は field 集合の完全一致を要求するので `note` を足せない。
  (3) 親が指示した「投入スクリプトを bash で走らせて分類を確かめよ」は機械防壁が
  計算ノード用実行体として拒否するため実行不能で、fix 子が 1 本不受理になった。
  「分類部分を逐語で抜き出して別名で実行し、抜き出しが現物の逐語部分列であることも固定する」
  形へ変えて解決した。
- 別 session から [T-2266] 系の実測が届いた (データとして受領、main の現物で裏取り済み)。
  格子の上端 999 µs でも abort の抑制が飽和していないので、次 wave が反実仮想の腕を
  効く領域で測る regime 選択の根拠になる。
