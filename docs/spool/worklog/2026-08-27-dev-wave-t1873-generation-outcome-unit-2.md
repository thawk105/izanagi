## 本文

- 依頼は D1066 の実装。1 arm の outcome は `G=2` の最終世代の canonical variant とし、判定 3 条件の
  うち入れ替え追従を「descriptor 条件付きの予測構成へ正規化した比較」へ読み替える。
  制約は絶対規律 2 (読み替えを判定が通りやすくなる方向へ緩めない。恒真でないことを負例で示す) と
  絶対規律 3 (判定は pass/fail でなく構造化して返す)。
- 8b 設計へ §8 手続きの再凍結節を追記し、8c §4 へ 8c 固有の 2 点を足して条件契約の第 11 世代を
  発行した。判定器の版は据え置き (受理集合・拒否理由・射影された判定入力の意味を変えていない)。
- **裁定が空けた範囲を狭い側へ埋めた。** D1066 は on/off 差と対比の扱いを定めていない。
  identity だけで on/off 差を見ると、独立に合成された variant の hash はほぼ常に異なるため
  条件がほぼ恒に成立する。これは D1066 が入れ替え追従について認定した恒真性の、向きを反転した
  同型である。成立側は連言、不成立へ倒す側は選言を採った。裁定は {{D:generation-onoff-contrast-narrow-reading}}。
- **段 3 の敵対 2 レンズが独立に同じ fail-open を指摘した。** 段 2 のプランは「selector の cell
  正規化が成功すればそちらを優先する」としていた。宣言 marker があり、かつ旧 selector 形の cell も
  持つ入力は、最終世代の outcome を一切見ずに成立へ到達できる。marker を最初に判定し、
  混合入力を判定不能へ倒す形へ変えた。
- **定数の正規形で入れ替え追従が構造的に成立する族をレンズ A が構成した。** 「on arm は常に構成 A、
  off arm は常に構成 B」を返す生成器は descriptor の中身に応答していないのに全条件を成立させられる。
  8b の判定基準に既にある文言を正規形比較へ適用する形で塞いだ。裁定は
  {{D:generation-swapped-constant-source-family}}。
- **再利用の転帰を正常と数える穴も塞いだ。** 既存 certified variant の再利用を正常 outcome に
  含めると、その再利用が指す証拠を判定器が再検証しない限り、証拠のない変異が certified な
  outcome として入る。受理を certified だけに閉じて機構を足さずに消した。裁定は
  {{D:generation-outcome-admissible-certified-only}}。
- **レンズ B が D1066 の射程を正しく読んだ。** 「正規化したのは入れ替え追従だけである」という指摘は
  そのとおりで、段 2 プランは on/off と対比まで正規形単独へ広げていた。ただし単独読みへ戻す案は
  上記のとおり別方向へ緩むため、連言・選言という第三の狭い形を採った。
- **段 6 のレビュー 2 本が 10 件を出し、8 件採用・1 件反証・1 件は親担当と裁定した。**
  反証したのは「同一 variant なのに正規形が異なる入力が判定不能へ倒れる」件で、意味のある収束
  (同一 identity かつ同一正規形、別 identity かつ同一正規形) は既に条件 1 の不成立へ到達しており、
  対応テストも実在して緑であることを現物で確かめた。残る象限は入力が自己矛盾しており、
  そこから負の主張を出す方が危険である。
- **実装子は M1 / M3 / M5 の単一理由性を「確認できない」と正直に報告した。** 前後の層による
  過剰決定が原因で、再照準 (世代列 gate 自体、入れ替え比較関数だけ、混入拒否の 1 種だけ) を
  親が局所の一時変異 + 即時復元で実測し、6 件すべてで落ちる node がちょうど狙った集合に
  なることを確かめてから本走へ登録した。落ちた node 集合は親の局所実測・焦点再レビューの静的導出・
  本走の 3 者で一致した。
- **親 brief の一般化を 1 つ訂正した。** 8b 設計 doc の bytes pin が保留中であることは、追記が
  凍結検査を赤にしないことを含意しない。同 freeze の未既知性 scan は保留中も走り、同一 file 内での
  三軸語の同居を拒否する。レンズ A の指摘で追記後に実走し、通ることを確かめた。
- **公開面が exact pin されている点が実装の閂だった。** 判定器の public 関数集合と `__all__` は
  8c の条件 7 評価器が exact 一致で pin する。public 名を 1 つ足すだけで拒否理由が変わり、
  判定器の版上げ議論に入る。追加はすべて private に閉じ、`judge()` の signature と
  出力 3 表の key・型・表名も変えていない。selector 経路の判定結果と 3 表 bytes は固定 hash で pin した。
- **段 8 の改善候補は 1 件出たが、byte 予算に収まらず入れられなかった。** 候補は「変異の単一理由性を
  静的に確定できないときは、登録前に一時変異と焦点走 1 回で落ちる node を実測してから登録する」を
  変異契約の該当節へ足すこと。本 wave はこの手順で 6 件中 3 件の判定を反転させた (実装子の静的検査は
  3 件を「確認できない」と報告し、実測はすべて単一理由性ありと確定した)。3 通りの言い換えで縮約を
  試みたが、最短形でも予算超過 22 バイトが残り、これ以上は安全義務の削除・弱化になるため中止した。
  予算値を上げる変更は自己改善の範囲外なので、独立審査へ回す。
- 本 wave が閉じていないことは insight `output/insights/2026-08-27_t1873-generation-outcome-unit.md`
  §8 に列挙した。提案から実現構成までの鎖の再検証、判定の詳細な不一致を凍結 3 表から復元すること、
  供給側の配線の 3 点はいずれも別タスクが所有する。
