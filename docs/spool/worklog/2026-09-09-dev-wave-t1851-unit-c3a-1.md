ユーザーは単位選択を親へ委任し「裁定 2 の結論に沿って単位を選ぶ」「迷う点は codex に相談して
決める」と指示した。親は前 wave の裁定 2 の結論 (a) に従って **C3** を選び、段 2 の実測を受けて
**C3a と C3b** に分けた。**D1341 により land しない。**

### 別系統モデルの相談が結論を変えた点

- 単位選択の相談は C3 を推奨し、依存順 `C → D2` を 6 単位分割の正本で裏取りした。
  D2 を先行させると供給元が無いまま fixture を固めることになる、という理由は採用した。
- 段 2 の plan は「現行契約と既存テストを保った実装は成立しない」と結論した。
  段 3 のレンズ 2 本はこれを別々の面から検査し、blocker 2 件を**両方 real** と判定した。
  一方で plan が提案した新 alias の追加は**不要** (既設 v5 で足りる) と反証し、
  親はこれを採って contract file を変更対象から外した。
- レンズ B は blocker 1 の 2 案のうち「inspector 側で許す」案が受理集合を広げると判定した。
  親はこれを採り、launcher 二段化を**既存 production 入口を変えない形**に小さくして実装した。

### 親の記述の誤りを敵対レビューが 2 件訂正した

どちらも**採用して記録と erratum を直した**。

- adapter の 3 遷移修正について親は commit message へ「受理集合を広げていない」と書いたが、
  正しくは「無条件拒否だった sealed terminal 後の遷移を、検証済み terminal 履歴に限って
  受理する限定解除」である。
- ordinal 訂正についても「緩和ではない」は無限定には誤りで、正しくは**受理集合の置換**である
  (旧誤軸の受理形を新規拒否し、契約が要求する形を新規受理する)。

### 棄却した finding

- 段 6 レビュー B が「adapter 修正が提供報告のどれにも無い」を real として挙げたが、
  これは**親の投げ文の不備**である。レビュー投げ文を fix 子の報告が出る前に書いたため、
  必読一覧に当該報告が入っていなかった。実体は commit と報告に存在する。
