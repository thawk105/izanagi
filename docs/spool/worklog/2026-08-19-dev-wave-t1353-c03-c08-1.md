## 本文

[T-1353] と 8c 条件 C03 / C08 を 1 wave で実装した。設計判断は {{D:two-stage-prereg-binding}}、
段 6 で表面化した失敗型は {{F:parent-adjudication-unsatisfiable}} と {{F:partial-merge-staging}}。

**起動時の重複検査。** 引数の指示どおり `trial_registry.py` を触る稼働 wave を調べた。t822 は
land 済み (エントリ 656) で二重着手は無い。稼働中の t1333 が
`test_trial_registry.py` と `test_s8c_preregistration_predicates.py` を 12 行だけ触るが、
production 面の重複は無い。

**親の実測が引数の前提を 1 件訂正した。** 引数は「評価器を登録する」「契約 JSON の
machine_checkable 反転はしない」を同時に求めたが、`PredicateRegistry.evaluate_all` は
`machine_checkable` が真のときしか `_MACHINE_EVALUATORS` を引かない。さらに
`test_machine_checkable_contract_and_evaluator_registry_are_bijective` と
`test_satisfiable_predicate_requires_negative_control` が両者の exact 一致を pin している。
登録だけを行えば機械的に赤になる。よって評価器は `_evaluate_undefined` から委譲して live に結線し、
反転と凍結世代の発行は後続 wave へ残した。

**親の裁定が 1 件、実装子に反証された。** 段 6 で親は
「`prereg_content_commit` を manifest の `prereg_commit` と等値で束縛せよ」と裁定したが、
これは成立しない。`manifest.prereg_commit` は manifest blob を含まない anchor commit であり
(fixture では `seed.txt` だけの commit)、P は manifest blob を含む必要がある。manifest に自身の
commit を書けば自己参照になり、既存の禁止テストとも衝突する。実装子が両立不能と判断して
**止まって報告し**、親が実測で裏を取って撤回した。実装が元から持っていた「anchor が P の祖先」
という束縛が正しい。この撤回で赤は 85 件から 2 件へ落ちた。

**敵対レビュー 2 本が 19 所見 (blocker 7) を出した。** 親は 16 件を採用、2 件を scope 外にした。
緑のまま通っていた実穴は 3 件である。(1) 上記の等値束縛の欠落 (提案された修正形は成立しないが、
束縛が緩いという指摘自体は real)。(2) 予算不足時に attempt row と lifecycle が別の status を
要求し合い試行が stuck する。(3) live AST 検査が `if bool(0):` の deterministic false 分岐を
live と数えるため、厳密な比較を偽分岐へ隠した実装でも `EVIDENCE_UNDEFINED` のままになる。

**保証の言い方を狭めた。** CLI の `main()` は `competing_bench_pids()` を `run_trial()` より前に
呼ぶため、環境 probe は slot 予約より先に走る。予約の前倒しは予約前拒否と checkout 失敗時の
slot 管理まで変えるため採らず、保証を「最初の**性能**観測より前」へ限定して書き直した。
分類が性能出力を読む前に確定したことの**時点証明は本 wave の保証範囲外**である。実装したのは
capability 束縛と、性能出力を引数に取れない分類 API までで、これを恒真な保証として謳わない。

**親の判断が 1 件、レビューに訂正された。** 凍結 baseline
(`test_reflux_originless_compatibility.py` の `_PRE_WAVE_ORIGINLESS_BASELINE`) が commit SHA を
焼き込んでいて main 取り込みで赤くなったため、親は内容由来の 17 leaf を volatile 化させた。
レビュー B が「17 件とも fixture の日時固定と決定的 projection により pin 可能」と実測で反論し、
親はこれを採用して pin へ戻す裁定にした。**段 1 の凍結 pin 閉包検査で、test file 内に
埋め込まれた baseline を取りこぼしていた**ことも同時に判明した。

**scope 外として裁定パッケージへ回した 2 件。** (1) registration schema version を v2 のまま
必須 field を増やしている。version 昇格には既存テストが schema version 文字列を literal で
持っている点を先に直す必要があり、レビュー自身が「現行公式経路に silent misread は無い」と
実測しているため後続へ回した。(2) 歴史契約で C03/C08 が machine_checkable=true だった場合の
fail-closed reason が blob read error になる件は、新 ReasonCode 禁止と衝突するため見送った。
