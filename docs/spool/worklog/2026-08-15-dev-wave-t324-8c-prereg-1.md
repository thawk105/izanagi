## 本文

- T-244 の 7 問全裁定 ((1) 追認 (2) G=2 (3) 起票のみ (4) 据置 (5) 入れない (6) 禁じない
  (7) 作らない) を前提に、事前登録文書へ G=2・還流・標本設計・正式起動形を書き込んだ。
  設計判断は {{D:prereg-registers-channels-not-closure}}、
  {{D:prereg-unlock-conditions-live-in-protected-body}}、
  {{D:prereg-launch-shape-is-registered}}。
- **段 1 の前提実測が裁定控えを超える事実を 3 件出した。** (a) 判定器 CLI を `-m` で起動すると
  12 条件すべてが `ERROR / evaluator-exception` を返す。同じ判定を package import 経由で呼ぶと
  正しく未定義を返す。二重 import で exact 型検査が弾かれる型で、発効値は両経路とも false のため
  受理集合は不変、壊れるのは診断だけである。(b) 条件別評価器 6 本が実装に存在するのに、
  証拠契約が 12 条件すべてを機械検査対象外と記すため 1 本も呼ばれない。
  (c) 裁定 (7) が作らないと定めた 2 件は、標本設計そのものの機械成果物を含む。
- **敵対レンズが親の provisional 裁定を 1 件倒した。** 親は「`master_seed` だけ今固定する」と
  していたが、同じ seed でも schedule generator の版・schedule の bytes・arm 順序を変えれば
  別標本になり、実行 payload に seed / schedule / arm は 1 つも存在しない。
  seed 単独の固定は束縛ではなく体裁である。**記入したのは検定欄 1 件のみ、残り 8 欄は未記入**に
  改めた。判定器実測で 1 記入 / 8 未記入を確認済み。
- **親が段 2・段 3 で 3 件の誤りを訂正された。** (i) 親 brief は正式系列の投入タスクを
  配線 pilot の後続と書いたが、pilot は別 workload 集合を対象とし arm も揃っていない別物で、
  文書自身が pilot を本系列へ昇格させないと定めている。正式投入は別タスクの起票が要る。
  (ii) 親は構造衝突を条件 11 の 1 件と見ていたが、条件 3 / 8 に commit 自己参照がもう 1 本あった。
  発効候補 commit の tree に入る manifest がその commit 自身の識別子を持つ必要があり、
  通常の commit 作成手順では構成できない。(iii) 親は「起動時に既定値を渡せば黙って短い世代数で
  走る」と述べたが、campaign 識別子が世代予算を hash に含むため、正しく束縛された manifest では
  そうとは限らない。既定値と検証の範囲が要求と食い違う事実自体は成立する。
- **還流の説明を情報量で数え直した。** 親は key 集合を見て「勝ち筋の値は運ばれない」と記述したが、
  レンズが数え直したところ結果依存チャネルは離散状態・真偽 2 値・浮動小数の診断値からなり、
  診断値を倍精度とみなすと数百 bit 規模になる。加えて勝ち筋の値は射影の直接値からは落ちるが
  critic の入力には渡り、真偽値を介して間接伝播しうる。文書は「閉じている」と書かず、
  運ぶチャネルの種別と結果依存性を登録する形に改めた。
- **発効を止めている構造衝突を 4 件に整理して文書へ列挙した。** 最も手前の閂は証拠契約の
  機械検査対象外記述であり、条件 11 の裁定衝突と条件 3 / 8 の自己参照はその後段にある。
  したがって禁止された 2 成果物を作っても現状の充足は 1 件も増えない。
- **12 条件が要求する証拠成果物の実在を全数確認した。** 不在は 6 種で、うち 3 種
  (schedule / 予算 / 判定の各 module) は新規実装が要る。条件 1・2・4・9・10・12 は
  要求 path が実在する (充足の意味ではなく置き場の存在)。
- **計測経路が両方とも塞がっており、テストと受入全走を実行できなかった。** 計算ノードの
  対象キューは 1 件も実行状態にならず、**3 回の投入がすべて待ち行列の上限で基盤失敗**になった
  (うち 1 回は受入 lease を取得したうえでの走行ゼロ失敗)。
  login 側の bounded local は cgroup の属性を実行中に確認できず同じく基盤失敗。
  いずれもテストの赤ではない。**受入受領証が無いため land しない。**
- **受入の 1 回目は別の原因で走行ゼロだった ({{F:worktree-nested-submodule-blocks-acceptance}})。**
  新規 worktree の入れ子 submodule が未初期化で前検査に拒否された。
  wave 開始時に初期化していたが非再帰だったため入れ子まで届いていなかった。
  再帰初期化して解消したが、**lease を 1 回取得したうえで走行ゼロ**になった。
- **段 8 の自己改善は候補 2 件を出したが、byte 予算に阻まれて実施できなかった。**
  該当運用節は 996 bytes で単節予算 1,000 bytes に対し残り 4 bytes しかない。
  意味等価な圧縮は同族 docs で exact pin を壊した実績があり、
  本 wave では検査を走らせられないため実施せず、裁定へ返した。
- 実行できた検査: 文書検査は違反なし。判定器による記入欄の状態実測で 1 記入 / 8 未記入。
  凍結範囲の hash 比較で規範本文と条件本文が変化し、欄名集合と証拠契約は不変。
