  とくに U1 は現行受理集合に実在する reward hack 経路であり開いたままである)
- **[T-407] は (a)** — `ruleops.py inventory` が**文字コードとして解釈できない blob を
  読み飛ばす**。同ツールは規約文書の検査が目的であり、測定の生出力は元々対象外である。
  読み飛ばす条件を「UTF-8 として decode 不能」に限れば検査の意味は落ちない。
  (b) (probe evidence の保存形式を変える) は commit 済み証拠の作り直しになり、
  証拠の同一性照合が 1 段増えるため採らない。
  **実装面なので Codex author 必須。** 該当は `tools/ruleops.py:201` の
  `raw.decode("utf-8", "strict")` → `RuleOpsError("non-utf8")` 経路。
  赤は `test_ruleops.py::test_real_checkout_independent_maximum_package_and_runner_preflight@real_repo`、
  受入全走 5430 passed / 19 skipped / 1 failed、単独再走でも再現しフレークではない
- **[T-328] は (c)** — **[T-313] (byte 予算を常時読量 gate へ置換) を先に実装する**。
  既に裁定済み・実装待ちであり、上限を上げずファイル分割もしないため **D94 のどの却下案にも
  当たらない**。(a) 陳腐化節の削除は D94 決定 (2) の routing 上さらに別のユーザー裁定を要し、
  (b) +2,000 bytes と D94 supersede は上限を上げない方針と衝突するうえ、条件 dispatch の
  発火条件逐語検査・前置きの dispatch 到達性・節 ID の全族一意性・consumer 閉包・failures の
  逆方向 pointer の是正がすべて scope に入る
  - **親の前回推奨 (外出し) の撤回を確定させる。** D94 却下案 (a)「ファイル再編・新規 reference
    ファイル — 読了削減 0 で総量予算と checker 改修だけ増える」と同一形だった。
    読み込み契約が leaf 節単位であり、workers 全 H2 の 96.3% / mutation の 97.1% が
    段 dispatch で必読という D94 の実測は今も成立する
  - **従属 4 件の行き先も本裁定で決まる** — [T-345] / [T-346] / [T-317] / [T-279] は
    外出し枠に相乗りする計画だったが、その枠は作られない。**[T-313] の実装後に、
    新しい読量 gate の下で各々書けるかを判断する**
- **[T-293] は (a)** — 3 因 (login に候補が無い / 計算ノードには在るが symlink で `_executable` が
  拒否 / `gcc-13` 不在で `prepare_toolchain` が `cc` で落ちる) を記録して閉じる。
  **値の書き換えは 3 因のうち 1 つも解かず**、凍結証拠 2 テストを赤にし T-126 series identity を
  変える代償だけを払う。**現時点の実損は 0** — `toolchain-manifest.json` /
  `submission-intent.json` / `series-identity.json` は repo 内 0 件で、この経路は一度も
  完走していない。(e) 値を広げる案は覆った前提の上に立つため採らない
  - **原因 2 は T-293 の枠を超える独立欠陥なので分離する。** `_executable` が
    `not Path(found).is_symlink()` を要求する一方、shell 側は `[[ -x ]]` で symlink を通しており、
    **同じ判定の受理集合が Python と shell で食い違っている**。緩めるのは受理集合の変更
    (D96 手続) であり、symlink 拒否が「pin したはずの path を差し替えられる」ことへの防御で
    ある可能性を確認せずに緩めてはいけない (規律 2)。{{T:executable-symlink-parity}} として起票する
- **[T-390] は (a) 残置** — D122 の opt-in 経路 (`--allow-pegasus-compute-transport`、既定拒否) は
  そのまま残し、「使わない」を運用規律とする。既定で拒否されているため実害がない。
  (b) 撤去は受理集合の縮小として D96 手続を要し landed 実装の巻き戻しを伴う
