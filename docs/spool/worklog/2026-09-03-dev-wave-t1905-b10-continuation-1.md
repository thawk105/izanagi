## 本文

- **依頼の前提を最初に実測し、2 件が既に片付いていた。** §6 の投入前必須修正 5 件は全て
  main へ着地済み。さらに**設計 §4 が「本 wave の範囲外」とした道 1 (検査の多重化) も
  T-2191 で着地済み**だった。設計 §4 が「未確認」とした 12 時間超の枠も D1489 が既に
  記録していた (gen_S の Per-Req 上限 86400S)。設計文書と decisions の食い違いで、F31 に従い
  decision を優先した。
- **§5.1 の律速測定は新しい job を 1 本も投げずに取れた。** 打ち切られた 965996 (read-heavy)、
  9/1 の balanced、走行中の balanced の 3 つの campaign 記録に、実規模の所要と commit 数が
  残っていた。**新しい job を投げるより安い。**
- **並列検査器の end-to-end 効果を production 経路で直接測れた** — 同一変種で
  逐次 313.9-330.7 秒に対し並列 16 が 163.2-172.7 秒、**1.94 倍**
  (campaign 集計では 1.90 倍)。T-2191 が合成 trace から出した 1.7-2.1 倍の中央に入り、
  **独立に裏づけた。**
- **balanced を投入した** (`974207.nqsv`、verify-perf、12 時間枠、source `c7ed56589`)。
  投入元は専用の clean worktree。主 checkout は `?? .codex/worktrees/` があり
  `--untracked-files=all` の clean gate を通らないためである。
- **read-heavy の道は道 2 (枠の延長) で確定し、契約値を 24 時間へ上げた** ({{D:b10-walltime-24h}})。
  ただし **D1509 決定 2 を形式的に閉じたとは書かない** — §5.1 の 5 量のうち 3 つは
  成果物に残らず取れていない。書けるのは「道 1 が着地して選択肢が 1 つに減り、
  その 1 つを採った」までである。**24 時間という値も実測から一意には出ない。**
- **「検査のピークメモリは取れない」という親の当初の判断は間違いだった。** 走行中の job は
  `qstat` で読める。読むと 115.29G まで跳ね、上限 115GiB のすぐ下だった。
  **しかしこれは物理メモリではない** — スパイクは隣接する定常値の 11.4-17.1 倍 (中心 13-14 倍) で
  並列度 16 と一致し、約 60 秒周期で 2 段に分かれる (fork する段が 2 つある)。
  fork した子が共有する copy-on-write ページの重複計上である。
  **T-2191 がこの誤りを名指しで警告していた型を、親が一度踏んで実測で解いた。**
  記憶量の risk は **refuted ではなく reduced** ({{F:qstat-job-memory-is-fork-sum}})。
- **段 3 のレンズ A が親の主張を 6 件削った。** 混合区間を「検査相」と呼べないこと、
  1.30G commit を上限扱いできないこと、記憶量を refuted と書けないこと、
  並列化率 89% を確定できないこと、§5.1 を満たしたと書けないこと、
  24 時間が実測から一意には出ないこと。**すべて採用して表現を落とした。**
- **段 3 のレンズ B が変異の帰属を 2 件訂正した。** 親が登録した m03 (複製禁止の検査から
  項を外す) は**必ず緑になる**形だった。レンズの代替案 (`print(walltime_s)` を
  `print(86400)` へ) は現在値での挙動を保ったまま複製だけを作るので、
  親の当初案より強い正例である。m01/m02 は同一 node 内の二重拒否なので冗長 gate と明記した。
- **m04 の生存を隠さない。** 「複製禁止の検査を狭める」変異は赤 node の完全集合が空になる。
  **検査自身の弱体化を検査自身は検出できない**という構造的限界 (規律 7 が D387 として明記) の
  実例であり、事前登録どおり SURVIVED で記録した。
- **非帰属赤を推測でなく再現で判定した。** 全走で 1 件赤になったが、変更を戻して同じ赤を
  再現したので非帰属。真因は迷子の `/tmp/.git` (空、並行 wave が漏らしたもの、F457 の型) で、
  台帳の指示どおり `rmdir` で除去したら緑。除去後 103 passed。
- **D1480 条件 2 (1 セル試し打ち) は現行実装のまま満たせないと判明した。**
  `verify-perf` は 15 変種 45 セルへ進み `report` は exact 135 セルを要求するので、
  1 セルだけ通す実行面が無い。**足すと driver の bytes が変わり、走行中 balanced の
  45 セルが最終集約から外れる。** 条件 2 を字義どおり満たすことと D1509 決定 3 が守ろうとした
  完走分を残すことが正面から衝突する。**ユーザー裁定へ返した** ({{F:d1480-cond2-unsatisfiable}})。
- **balanced が 45 セル完走した** (`driver_rc=0`、実所要 3.6 時間)。
  45 件すべてが測定成功かつ `correctness_certified=true` で、実行ノード名も 45 件に入った。
  前回の write-heavy が 45 セル全部「性能 binary の SHA 不一致」で終わった型は 1 件も出ていない。
- **受入全走が real な赤を 2 件出した。親の pin 閉包漏れである** ({{F:policy-bytes-pin-missed-by-key-and-value-search}})。
  `tools/pegasus/policy.json` の現行 bytes は sha256 で明示 pin されており、壁時計を変えたので外れた。
  **key 名と値の字面で閉包を取ったので、file 全体の hash を持つ pin に掛からなかった。**
  段 2 のプランと段 3・段 6 の 4 レンズも全員が同じ探し方をして誰も見つけず、
  20300 件の受入全走だけが見つけた。段 6 の焦点走も b10 の test file だけで、
  DW-O26 が求める consumer test を引いていなかった。
  直しは golden 1 行の更新で、歴史 binding と凍結 evidence は据え置き。test の緩和ではない。
- **read-heavy の投入は本 wave で行っていない。** 依頼は「§5.1 の測定・道の選択・balanced の
  投入」であり read-heavy の投入を含まない。段 3 の両レンズも現行裁定を保つ限り
  qsub の前に停止すべきと判定した。
