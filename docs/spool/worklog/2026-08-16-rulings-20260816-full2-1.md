## 本文

- **ユーザー裁定 (逐語)**: 「計算ノードへのキュー待ちっていうのは状況によって変わる。キュー待ちが
  起こるときはしょうがない。だからと言って並列投入を諦める理由にはならない。なぜなら使えるもんは
  使って効率化し、使えないもんは使えないからと言って一生使えないと決めつける必要はない。
  後は推奨通りで」。対象 = `/rulings 全件` が提示した索引 20 件。authority = ユーザー。
- **rulings の推奨 1 件が明示的に覆された。** [T-1177] に付けた「着手前に並列化の利得を実測し、
  出なければ (2) 凍結へ切り替える」という条件は撤回する。**利得の事前実測を着手条件にしない。**
  理由 (ユーザー): キュー待ちは状況依存の変動要因であって、支配項になる局面があることは
  並列投入を諦める理由にならない。使える局面で使って効率化すればよく、いま使えないことを
  恒久的に使えないと決めつけない。この一般則は今後の「支配項だから利得が無い」型の
  見送り推奨すべてに適用する。
- **収集の実測**: 末尾エントリ (収集開始時 581 → 完了時 583) の「次の一手」を機械解決し
  **未解決 0 件**。「裁定」1 語 + 選択肢の形で総ざらいして 161 件、既裁定・実装待ちを除いて
  19 件を索引に立て、稼働 branch t1131 の未 land fragment 1 件を加えて 20 件。
  **実体 ID − 索引 ID の差集合は空。** 収集中に 3 wave (t1157 / t936 系 fold / t1131) が land し、
  entry 583 で未採番項が [T-1195] として採番された。
- **`docs/handoff/` は README のみで正常。** 裁定 inbox は前回 (同日 07:29 の 43 件一括) 以降の
  増分ゼロ。見送り台帳を直近 wave の語で照合し、**[T-421] の再訪条件が成立**した (下記 [T-1174])。
  phase3 の未消化チェックボックスは 0 件、floor 実測前 gate は 2026-07-24 に受諾済み。

  粗い provenance で足りるという既定方針とも整合しない。
