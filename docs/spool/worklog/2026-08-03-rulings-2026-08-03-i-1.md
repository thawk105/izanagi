## 本文

- **別セッション (task-def) で下されたユーザー裁定 3 件を、一次控えから台帳へ取り込んだ。**
  控えは `/work/1/SFC/tanab/dev-wave-jobs/rulings-inbox/2026-08-03-task-def-rulings.md` (repo 外)。
  同ファイルは「稼働中の `/rulings` セッションまたは次の wave が fragment 化して land すること」と
  指示しており、本エントリがその履行にあたる。**着手は本 wave では行っていない**
- **[T-276] = 分割線を維持する。** 計算ノードでの role 実行は解禁せず、LLM は login node、
  build / verify / bench だけを計算ノードへ dispatch する。壁 1 (campaign の build/verify/bench を
  計算ノードで回す経路) の恒久実装は**この分割線を前提に設計する** — campaign driver は login、
  重い段だけ job へ出す形。理由は資格情報を計算ノードへ持ち込まないことと、外部 proxy を
  信頼境界へ入れないことであり、**proxy 到達性が実測で覆ったこと (D108 前提の否定) は
  解禁の理由にしない**
  - **D122 との読み合わせ (重要)。** D122 決定 (1) は既に「明示 opt-in の transport admission」
    として解禁を実装済みであり、**既定は拒否**、production CLI に
    `--allow-pegasus-compute-transport` が配線されている。本裁定は**その opt-in 経路の撤去を
    指示していない**と読んだ — 一次控えの「影響」節が壁 1 の設計前提だけを述べているためである。
    したがって **D122 の経路は既定拒否のまま残り、本裁定は「使わない・それを前提に設計する」
    という運用と設計の束縛**として記録する
  - **残る択一 (未裁定):** opt-in 経路そのものを撤去するか。撤去は**受理集合の縮小**なので
    D96 の手続きが要り、landed 実装の巻き戻しを伴う。本裁定に含まれないため
    {{T:d122-optin-retirement}} として起票する
  - 未了: 恒久実装は未着手。先に生死確認 (`--provider fixture` で LLM を外し、
    build → legacy+S2 verify → bench の 1 周が計算ノードで通るかの実測) を置く
- **[T-340] = 択 (a) 採用。** `tools/pegasus/` に **pin 検証つきの取得経路**を置く。置き場の
  規約化だけに留めない。対象は masstree / mimalloc / googletest
  (policy.json の `silo_ladder_rung1.third_party_sources` に url + pin がある)。
  背景は前回 job が worktree 配下へ staging しただけで worktree を畳んだ時点で実体が消えたこと。
  併記事項として `gflags_source_path` / `glog_source_path` が `/home/SFC/tanab/github/...` の
  絶対パス直参照である (実在は 2026-08-03 確認済み) — scope を広げるかは実装 wave が判断する
- **floor 実測 = 着手する。ただし 1 wave (ジョブ束 1 回) 規模に収める。**
  足りなければ拡大せず裁定へ返す。レコード数は calibrator が cache miss 率の飽和最小で決め
  (規律 4)、小さすぎて many-core の競合が再現されない罠も避ける。計測前にノード上で単独性を
  確認する (pgrep。割当てを専有の保証と見なさない)。取得値は env タグ付きで
  `output/env/pegasus/calibration/registered/` 系へ登録する。wave は「使った規模」と
  「この floor が 1 測定の品質ゲートとして使えるか」の判定を返す
  - **本日の [T-296] 裁定と接続する。** floor は roadmap §5 の**層 C** (環境束縛量) であり、
    [T-296] で裁定した **Pegasus 専用 env-tag の新設が登録の前提**になる。順序は
    env-tag 新設 → floor 実測 → env タグ付き登録
  - **前提 gate 2 件が未閉鎖である点を明示する。** phase3 の現行チェックポイントは floor 実測前の
    残 gate として **[T-088] の段階 3・4 (単一 admission predicate + CLI rc 翻訳、未着手)** と
    **実行 revision 束縛**を挙げている。1 wave 束縛と両立しない可能性があり、その場合は
    **裁定自身の規定どおり拡大せず裁定へ返す**
  - 現状の登録は certification 由来の 1 点のみ (`linux-baremetal` は 26 本、うち between-run
    noise は rr5/rr50/rr95 の 3 本)
- **取り込みにあたり照合したこと:** [T-276] は worklog 上 `完了` (D122) であり、完了項への
  追加裁定になるため D122 本文を開いて矛盾の有無を確認した (上記)。[T-340] は項の本文が
  提示していた択 (a)/(b) と裁定が一致する。floor は [T-011] と重複する旨が控えに明記されており、
  [T-088] / [T-296] / [T-011] の 3 項へ同じ裁定を反映した (代表 ID にだけ書かない規律)
