  あなたは裁定の存在すら教えてくれない」。**指摘は正しく、構造的な収集漏れであった**

    `/work/1/SFC/tanab/dev-wave-jobs/handoff/`** にあり (本実行時点で 5 本、更新は 30 分以内)、
    親は**このセッション中一度も読んでいなかった**。`docs/handoff/` は README のみが正常な状態
    なので、そこだけを見ると「handoff は無い」と誤って結論する

    `dev-wave-jobs/rulings-inbox/` にある。親は**ユーザーが path を貼るまで存在を知らなかった**。
    本実行での確認では未読の裁定は無かった (既処理の 1 件のみ) が、経路が無いこと自体が欠落である
  - **実測した欠落 3:** 各 wave dir に裁定パッケージ (`adjudication-package*.md` /
    `s4-adjudication.md` / `stage4-ruling.md`) が置かれるが、収集はこれも見ていなかった

    生きた handoff・裁定 inbox・稼働 wave の裁定パッケージが repo 外にあること (所在は環境 runbook)、
    稼働 branch の未 land fragment も読むこと、を明記した。

    **横断 docs にマシン固有 path を持ち込まない規律**に従い、command 側は「所在は環境 runbook」と
