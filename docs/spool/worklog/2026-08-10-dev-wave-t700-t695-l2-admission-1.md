- **親 brief の誤り 3 件を撤回した (すべて子の指摘を親が一次資料で裏取り)。**
  (i) 「項目 1 (関門契約) は land 済み」は誤り。親が `DW-O23` の fold 契約をそれと読んだが、
  fold 契約は別 commit 由来で、entry 344 の関門は D254 だった。正確には
  **「実装は land 済み、reference 同期が未 land」**である。
  (ii) 「項目 2 は `60314069` で land」も誤り。導入は `09c9f91a` (2026-07-26)、文言改訂が
  `3d5e399f` (2026-08-04)。`60314069` の「裁定済み 2 候補」は `DW-O01` の残留 `.done` 規則と
  `DW-C00` の待ち手規則で本件と無関係。結論 (裁定時点で既に充足) は変わらない。
  (iii) 入口 byte 増分「+88」は 20 bytes の過少計上。`_OPERATION_NUMBERS` へ番号を足すと
  `_ALL_OPERATIONS` 経由で段 5・段 6 の C 契約にも入るため、入口の C 行 2 本にも追記が要り +108 になる。
- **項目 1 (D254 の land 関門契約) は 4 案すべてが停止条件に触れたため実装しなかった。**
  (a) 既存 L2 節 `DW-O17` への統合は**到達性で棄却** — 段 9 の U dispatch は
  `DW-S09`/`DW-CTX`/`DW-STOP`/`DW-O23` だけで、`DW-O17` は「commit を作る直前」でしか読まれず、
  ff-only は commit を作らない。D254 自身が「`DW-O17` の注意書きでは防げなかったから land 関門へ
  移した」と記録している。(b) `DW-O23` への直接統合は**安全義務の弱化で棄却** — 原資の
  −211 bytes が `ff-only成功後` (fold の順序条件)、`同じlockを保持したまま` (連続保持)、
  `既存挙動を変えない` を落とす。D128 がこの語を逐語で決めており上位節に同等記述はない。
  加えて `DW-O23` は L1 なので裁定文「L2 として登録」に対する L2→L1 再分類になる。
  (c) 新規 L2 節は入口予算が 83 bytes 足りない。(d) 「実装が強制するから本文不要」は §54 と衝突する。
- **項目 3 (段 4 の rulings-inbox 再走査) も実装しなかった。** `DW-G03` を満たさない。
  発火実績 2 件 (2026-08-09 の取りこぼしかけ、2026-08-04 の着弾による前提差し替え) は
  producer (wave 中の裁定着信) と consumer (親の brief / 段 4 裁定) が同一で、
  「異なる producer/consumer で独立 2 件」ではない。**ここだけレンズ間で判断が割れた** —
  sol は「日時・ファイル・wave が別だから独立」、luna は「producer/consumer が同一」。
  親は `DW-G03` の文言に忠実な luna を採った。加えて条件節に置く動機が L1 余白 0 の回避であり、
  U/C を読了実態から導出する D255 の抜け道になる。予定していた `count(...) == 1` 型の pin は
  F170 と同型の恒真構造 (blockquote 化・別節移動で緑のまま無害化できる) だった。
- **項目 2 は充足済みとして再配置しなかった。** `DW-S01` (L1) に該当文が現存する。L2 へ移すと
  「検査を増やす wave が既存被覆検索を読まない経路」が増える。ただし「L2 登録済み」と
  無裁定では扱わず、部分 supersede の可否を裁定へ返す。
- **failures fragment は書かなかった。** 「wave 開始後に着信した裁定を段 4 で取りこぼす」型は
  既存 F 台帳に無く (grep hit 0)、新規 F の候補である。しかし `docs/spool/failures/README.md` が
  **恒久対応に実体ポインタを必須**とし宣言だけの対応を認めない。本 wave は恒久対応を実装せず
  裁定へ返したため、書けば恒真な対応欄になる。実装 wave が恒久対応と同時に起票する。
- **実装しないことで回避した再発型。** sol が挙げた F122 (説明と実装の不一致)、F149 (consumer
  取り残し)、F170 (恒真 pin)、F173 (予算目的の義務削除) は、実装を止めたため発生していない。
  F への再発追記はしない。
