## 本文

- **[T-244] の裁定パッケージ 5 件 (U1〜U5) をユーザーが裁定し、全件確定した。**
  設計本文 = `output/insights/2026-08-03_t244-p6-contract/README.md`、
  裁定表 = 同 dir `s4-adjudication.md` §5
- **U1 = 起票して独立 wave (推奨どおり)。** 現行 trigger-gating の受理集合に reward hack 経路が
  実在する。EVOLVE-BLOCK の hole は `TxExecutor::abort()` 内の任意 1 行で、機械 gate は
  **識別子 5 個の blacklist だけ**である。`pro_set_` (`transaction.cc` の
  `std::vector<Procedure>`) は blacklist に無く、`makeProcedure` は `RETRY:` の前で 1 回しか
  呼ばれない。したがって `abort()` で `pro_set_.pop_back()` すると**トランザクションが retry ごとに
  縮み、serializable のまま throughput だけ上がる**。現状の関所は auditor (LLM) だけである。
  **規律 2 に直接効くため、保留期間そのものがリスクである**点を記録に残す。
  AST allowlist 化の検討は {{T:evolve-hole-ast-allowlist}} が所有する。
  **受理集合の縮小になるので D96 手続が要る**
- **U2 = 推奨どおり。** D121 決定 (7)「非適用は cap-lift の失敗に数えない」を**二分する** —
  **「主張しないゆえの非適用」だけを免責し、「実装が無いゆえの非適用」は FAIL とする**。
  現文言は後者も免責するため、P6 を実装しないまま cap-lift を素通しできる。無条件必須にすると
  cap が永久解除不能になるという D121 の懸念は、この二分で回避される。
  **D121 決定 (7) の改訂は実装 wave が新 D として書く** (fold は既存 D を改訂できない)
- **U3 = 帰納段を踏む。** P6 が受理集合を実際に狭めるには「実測していない候補」を禁止する必要が
  あり、それは測定からは導けない帰納段である。**踏む。ただし「証明」と名乗らない** —
  仮説クラスの事前登録・反証テスト・有界な主張をセットで義務化する。
  **これにより [T-244] は「還流は実現しない」と結論して閉じる道は採らない**ことが確定した
  - 前提として確定した中心定理を記録に残す: **実測した候補だけを禁止する cut は受理集合への
    限界効果がゼロ**である。赤を実測した各 mask はそれ自体が exact-mask cut の 3 条件を満たすため、
    導出集合 `B` は受理集合に 1 点も足さない。座標 cut も、主張成立時点で 16 点すべてが
    exact cut 済みになる。よって**「exact-mask と座標 cut の中間」は存在せず**、
    測定を `32R` 回まで増やしても帰納段を踏まない限り効果はゼロのままである。
    この定理は段 3 の 2 レンズが**独立に**到達した (合議ではない)。D106 残余 1 から 9 wave に
    わたって本体が解けなかった構造的理由は、**健全性と実効性が両立しない要求だった**ことにある
- **U4 = 推奨どおり。** 座標 cut の予算下限は `Q >= 1 + 32R + E_min`。**draft v1 の候補値
  `Qmax=2` とは両立しない**。択一 1 (予算値) の裁定時にこの下限式を制約として使う。
  値そのものは本裁定では決めない
- **U5 = 推奨どおり。** sort 軸の構造化 integrity witness を新設する。現行は整数 counter と
  自然文 notes だけで**同値関係 (「同じ理由で危険」) が書けない**。P6 を sort 軸へ適用する
  前提条件になる。{{T:sort-axis-integrity-witness}} が所有する
- **[T-324] の待ちが解けた。** 8c 正式系列 H1/H2 は「[T-244] の裁定 → 複数世代・還流・標本設計の
  事前登録 → 実走」の順であり、本裁定で第 1 段が完了した。ただし **[T-244] 本体は未解決のまま**で
  ある — 契約の実装 (`reflux-control` stage、origin ledger、5-bit IR、正準 emitter、
  witness normalizer、validation runner、enforcer、非干渉検査) はすべて未着手であり、
  `MAX_APPROVED_GENERATIONS = 1` (D114) も変わらない
