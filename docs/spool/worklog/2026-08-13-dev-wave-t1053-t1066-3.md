## 本文

- 同 branch の受入全走 4 回が毎回**別の** 1〜2 件で赤になり land できなかったため、
  ユーザー指示により 4 件を直してから land を再試行した。4 件はいずれも本 branch の差分が
  到達しない file で、48 worker + 並行 wave の負荷下でだけ露出する。
- **機序 (段 2 プランが特定、親が diff で確認)**
  - launcher の終了確認は `/proc` 全走査中の**無関係 PID 1 件の一過性読取失敗**で
    `residual=None` になり、`while residual not in (0, None)` が即座に抜けて再観測せずに
    `termination_verified=False` を確定していた。これは production の欠陥である。
  - SIGHUP の descendant cleanup 試験は継承した signal mask を解除せず、固定 50 ms で子の
    `setsid()` 完了を推測していた。blocked のまま本文が終わると rc 0 になり偽の赤が出る。
  - signal reset launcher の試験は disposition だけ `SIG_DFL` へ戻して mask を戻さないため、
    blocked TERM が pending のまま `execve` 先の Bash が rc 1 で終わっていた
    (期待は 143)。`after-fsync` 固有の欠陥ではなく、ambient mask の悪い worker に当たった選択効果。
  - occupancy の負例はホスト全 PID を母集合にしており、他 wave の PID 消滅で `indeterminate`。
    production の fail-closed は正しく、誤っていたのは負例の母集合である。
- **直し方は「条件待ち化」「mask の正規化」「母集合の是正」に限り、期待値の反転・緩和・xfail・
  skip・再試行 wrapper は使っていない。** launcher は deadline 内で `residual == 0` を
  観測できたときだけ受理し、deadline 時点の unknown は従来どおり失敗させる。
  永続 unknown と一過性 `None → 1 → 0` の双方を検査する試験を新設した。
  signal reset launcher では初期 blocked / 最終 unblocked も exact marker へ加えたので、
  「disposition は正しいが mask は blocked」という従来未検出の破損も赤にできる (検出力は増えた)。
- 焦点走 = 修正 4 file 全体で **436 passed / 10.66 秒** (計算ノード)。
- 変異 matrix = **MUT-F2 / MUT-F3 とも KILLED、事前登録の期待 node と完全一致**
  (SURVIVED 0 / MISMATCH 0、baseline 緑)。生 ledger は
  `/work/1/SFC/tanab/dev-wave-jobs/2026-08-13_t1053-fixflakes/mutation/`。
- codex 子 2 本 (plan / author) は、成果物を書き終えた後に producer script が `.done` を
  書く前へ落ちた。receipt は `outcome=accepted / stop_reason=completed` で、
  成果物は artifact directory から回収した。**完了判定を `.done` だけに依存すると
  完走した子を落としうる**ため、artifact 側の receipt も併せて見る必要がある。
