## 本文

契約 v3.1 の 3 節・9 節が単位 C2 の射程と切った 4 点のうち **1〜3 を実装し、4 点目は
達成していない**。4 点目の未達成は 5 節に実測つきで記録した。**D1341 により land しない。**

### 敵対検査と変異が暴いた破れ 2 件

- **契約自身の本数式が誤りだった。** 契約 v3.1 の 1.4 節と 2 節は opened の不変条件を
  `len(throughputs) + nonfinite_count + exec_failures == reps_expected` と固定していたが、
  この式は `exec_failures` を欠格 rep すべての代理に使っており、契約 3 節が禁じた 2 量の
  再結合そのものだった。非 zero 戻り値だけの rep を持つ**正当な session を拒否**し、逆に
  **偽の実行失敗申告なら通す**。段 3 の敵対レンズ A が反例を出し、親が現物で裏取りした。
  規律 7 に従い契約本文は改変せず、erratum を追記した。
- **「実行失敗 rep を完備と数えない」保証が発火していなかった。** campaign の射影にある
  complete 述語から該当の連言を外しても、どのテストも赤にならなかった。
  **段 3・段 6 の敵対レンズ 4 本と静的読解では見つからず、変異を実際に走らせて初めて出た。**
  他の連言をすべて通す単一理由の負例を置いて閉じた。

### 実測で切り分けた赤

受入は 6 回投入した。**帰属した赤は 2 種**で、どちらも閉じた。

- **行番号 pin。** `test_ccbench_spawn_sites.py` の台帳が sink の行番号を期待値に焼き込んでおり、
  production から差し引き 8 行減らしたことでずれた。**識別子検索でも whole-file hash 検索でも
  掛からない型**で、段 1 の pin 閉包でも敵対レビュー 4 本でも検出できなかった。
  local main 単独で同 file が緑になることを実測して帰属を確定させた。
- **受入所要台帳の被覆率。** 新設 node が未登録だった。正本の生成器を `--add-only` で当て、
  2,142 件を追加した (削除 0・既存値変更 0 を検算)。

**非帰属だった赤は全走の負荷でだけ出る timeout 型**で、出る file が毎回変わった
(`git ls-files --others` の setup timeout、launcher の rc timeout)。いずれも単独走では緑で、
私の差分から到達経路がない。

### ユーザー裁定へ返す 2 件

- **診断 counter が 1 つの入力 class で変わるとき `FORMULA_ID` を改版するか。**

  **`FORMULA_ID` は変更していない。** 親の推奨は「改版しない」。
