  `PYTHONDONTWRITEBYTECODE` を 1 語足した。production の差分はこの 1 語と comment 1 行だけである。
  採用判断の基準と値の実測は {{D:dispatch-env-key-admission}}、
  指紋 gate を弱めない解き方の理由は {{D:fingerprint-residue-not-generated}} に置いた。
- **親の実測 (Python 3.10.12)**: `PYTHONDONTWRITEBYTECODE` は 未設定 / `""` / `"0"` で
  `sys.dont_write_bytecode=False`、`"1"` を含む任意の非空文字列で `True`。
  段 3 レンズ A は「値を拘束しないので監査の意味論が未束縛」を blocker として挙げたが、
  この実測により**伝播は単調** (追加前より残骸が増える値が存在しない) と判定し minor へ格下げした。
  値契約と receipt への environment 束縛は次の一手へ回した。
- **段 3 で裁定の前提を覆す事実が出た。** [T-1066] の「受入投入前に ignored file を撤去する 1 行」は、
  code 上どの検査の赤も防がない。`tools/check_acceptance_reds.py` の `--probe-root` は
  repo と全登録 worktree の外であることを起動時に強制し、指紋は毎回 `git worktree add --detach` で
  作る fresh probe worktree だけを見る。wave worktree 側の残骸はそこへ入らない。
  `run_tests.py` / `dev_wave_wait.py` / `dev_wave_land.py` の各検査も ignored file を見ない。
  さらに `output/pegasus-dispatch/` の無限定撤去は投入停止ラッチ `submission-disabled.json` と
  他 invocation の receipt を消しうる。`DW-S04` に従い親は不採用にせず、
  新事実を添えてユーザー再裁定へ返した (裁定控えを inbox へ置いた)。
- **段 6 レビュー B は NO-GO を出した**が、根拠は「checker は `tested_main` の checkout の
  dispatcher を使うので、未 land の差分は本 wave 自身の赤経路には届かない」であった。
  これは land 後に効くという順序の指摘であり、レビュー B 自身の修正案 (先行 wave で land する) が
  本 wave そのものであるため、blocker から格下げして記録に残した。
  **閂が外れるのは、`tested_main` に本 commit を含む次以降の wave からである。**
- 段 6 レビュー A の real 所見 1 件 (新テストが `request.json` までしか見ておらず、
  `child_env` から当該 key だけを落とす変異が生存する) を fix で閉じた。fix はテストのみで、
  production は無改変である。
- **関連控えの記述 1 件が現 HEAD と食い違っていた。** 「非帰属 checker を呼ぶ production consumer が
  無い」は既に偽で、`tools/dev_wave_wait.py` に caller が実在する (段 3 レンズ B が指摘)。
- 変異 matrix = **MUT-1 / MUT-3 / MUT-4 の 3 件すべて KILLED、事前登録と完全一致**

- 段 6 の焦点再走 1 回目は `rc=16 (queue-wait-timeout)` で落ちた。テストの赤ではなく計算ノードの
  キュー滞留であり、再投入で 141 passed になった。`run_tests.py` からは queue 待ち上限を渡せない。
- 本 session では背景の待ち手が、producer 生存かつ `.done` 未生成の状態で数分後に rc=0 復帰する
  事象を繰り返し観測した。当初 `tools/dev_wave_wait.py producer` 固有と書きかけたが、
  **素の `until [ -f <done> ]; do sleep; done` でも同じく早期復帰した**ため、
  共通因子は待ち手の実装ではなく背景 job の実行機構側である。ツールの欠陥と断定しない。
- **受入は 4 走したが receipt を発行できず、land していない。** 1 走目 2 赤、2 走目 1 赤、

  赤が 1 件でもあると非帰属 checker 経路に入るが、checker は `tested_main` (=本 commit を含まない main)
  の checkout で走るため必ず `probe worktree is not clean` で rc=2 になる。
