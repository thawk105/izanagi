## 本文

- **[T-813] の評価に効く設計入力 2 件を question セッションが提示し、rulings 側が一次資料で
  裏取りして記録した** (2026-08-11、控えは inbox §98 追記)。裁定は不要 (評価要件の追加であり、
  択の変更はない)。
- **入力 1 (裏取り済み):** `tools/run_tests.py` の `_is_acceptance_run` は受入の閉じた形を
  argv 形状 + `PYTEST_ADDOPTS` 空で判定し、4 箇所の受入専用事前検査が
  `if not _is_acceptance_run(...)` で黙って抜ける (rulings 親が該当行を実読して確認)。
  **シャーディングは定義上テスト集合を割るため、素朴な実装 (`-k` / nodeid / path 分割 /
  `PYTEST_ADDOPTS` のいずれでも) は全シャードで事前検査を無音で無効化する。**
  memory `acceptance-run-takes-no-extra-flags` (独立 2 例) と同族で、flag 追加より確実に踏む。
- **入力 2:** シャーディングはノード横断のため、wall-clock gate を持つテストの割付けが
  ノード間性能差に依存する。[T-810] (ノード間差の測定 protocol、wave 稼働中) の結果に
  [T-813] の評価が条件付きになる。
