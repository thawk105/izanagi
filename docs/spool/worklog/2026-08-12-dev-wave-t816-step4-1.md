`output/insights/2026-08-11_t816-fn2-trace-v2/verbatim/ruling-package.md` の Q2 は v1 拒否の
障害として SI (`cc/si/transaction.cc`) だけを挙げていた。親は段 1 で「SI trace を verify する
生きた経路は無いので今日の実損ゼロ」と provisional に裁定したが、**段 3 レンズ A がこれを反証した。**
実際の障害は SI ではなく (a) git tracked で SHA-256 pin された凍結 raw trace 4 本が v1 で、
現行 verifier がその実バイトを読み直すテストが生きていること、(b) 歴史 pin `dff0f1e` から
build して現行 CLI へ渡す再現経路 (`s2_verify_calibration.py`) が必ず v1 を出すこと、の 2 つである。

**親の実測 3 件** (詳細と file:line は insights が正本)。

1. gitlink + 承認定数 2 個 **だけ**を前進させた木で対象 5 ファイルを走らせ `10 failed, 76 passed,
   1 error`。赤 10 件は全部 `test_s8a_trigger_sweep` で、原因は校正 artifact 1 個の pin 束縛。
   error 1 件は `ModuleNotFoundError: No module named 'tests'` の偽赤 (DW-O18 の import path 未確立)。
2. S1 freeze 2 本の pin 不一致は**受入全走では緑のまま通り**、実行時の `s1_report.py` と
   `s8b_oracle_driver.py` だけが壊れる。テストで捕まらない型である。
3. 凍結 raw trace 4 本の先頭行が 5 token であることと、`test_silo_ladder_rung1_evidence.py` が
   その実バイトを現行 verifier に通していることを、レンズ A の報告を鵜呑みにせず親が直接確認した。

**段 3 が挙げた所見のうち 1 件は本依頼と独立の既存の穴である。** 負の txid を持つ trace
(`C -1 0 2 1 0 0`) は `expected = max(txid)+1` の式で欠番検査をすり抜け、false-green certified に
なりうる。v2 化とは無関係に**現行の v1 parser でも成立する**ため、裁定の結果によらず塞ぐ必要がある。

**前提実測は monkeypatch でなく実編集 + 即時復元で行った** (DW-S01/DW-O19)。
gitlink と定数 2 個を実際に進め、`git diff --stat` が意図した 3 行だけであることを確認してから復元した。
