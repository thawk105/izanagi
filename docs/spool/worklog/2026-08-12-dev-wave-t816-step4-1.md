## 本文

ユーザー依頼は手順 4 の 4 点 (gitlink を `d706650` から **`511c9538`** へ前進・承認定数 2 個・
**trace v1 拒否化**・`test_characterization_txn_tail_loss_is_false_green` の反転)。
**実装には入っていない。** gitlink は `d706650` のまま 1 bit も動かしていない。

**止めた理由は 2 つあり、片方は親の provisional 裁定の誤りである。**

**(1) 前提の乗せ直しが未実行で、依頼の pin 前進先が台帳と食い違う。**
親は段 1 で、控えファイルの mtime (裁定 01:08 < push 承認 01:16) から
「ユーザーの push が [T-837] Q1 (a) を上書きした」と provisional に裁定した。**これは誤りだった。**
main の `ef4d6737` (2026-08-12 01:18、push 承認より**後**に書かれた) が
「[T-837] Q1 (a) は不変。push 済み branch は承認済み作業の耐久化 (素材) として扱い、
**pin 前進の対象は乗せ直し後の新 SHA**、その push がもう 1 回ユーザー手番になる」と明記していた。
同 commit は手順 4 の順序も定めている — 乗せ直し (AI) → TRACE=0 同一検査の再走 1 回 (AI) →
乗せ直し後 SHA の push (ユーザー手番) → gitlink 前進 + 定数 + v1 拒否化。
**つまり依頼が指す `511c9538` は pin 前進の対象ではなく、手順 4 はまだ着手条件を満たしていない。**
さらに `c9c1a9c` は remote にも本 wave の worktree の submodule にも存在せず
(`git ls-remote` と `git cat-file -t` で確認)、**乗せ直しそのものが本環境では実行できない** —
`c9c1a9c` を持つのはユーザーの checkout だけである。
mtime を裁定の新旧判定に使ったのが誤りの機序で、正しくは台帳本文へ当たるべきだった。

**(2) v1 拒否化と gitlink 前進が、どの SHA で行っても凍結証拠に当たる。**
段 3 の敵対 2 レンズが両方 NO-GO を返し、親の独立実測がその主要主張を裏付けた。
既裁定 ([T-816] Q1〜Q3、[T-837] Q1・Q2) の時点で見えていなかった新事実なので、
DW-S04 に従い親が不採用にせず、新事実付きのユーザー再裁定待ちへ戻した。

**当時の裁定パッケージが挙げた障害は的を外していた。**
`output/insights/2026-08-11_t816-fn2-trace-v2/verbatim/ruling-package.md` の Q2 は v1 拒否の
障害として SI (`cc/si/transaction.cc`) だけを挙げていた。親も段 1 で「SI を verify する生きた
経路が無いので今日の実損ゼロ」と provisional に裁定したが、**段 3 レンズ A がこれも反証した。**
実際の障害は SI ではなく (a) git tracked で SHA-256 pin された凍結 raw trace 4 本が v1 で、
現行 verifier がその実バイトを読み直すテストが生きていること、(b) 歴史 pin `dff0f1e` から
build して現行 CLI へ渡す再現経路 (`s2_verify_calibration.py`) が必ず v1 を出すこと、の 2 つである。

   error 1 件は `ModuleNotFoundError: No module named 'tests'` の偽赤 (DW-O18 の import path 未確立)。
2. S1 freeze 2 本の pin 不一致は**受入全走では緑のまま通り**、実行時の `s1_report.py` と

3. 凍結 raw trace 4 本の先頭行が 5 token であることと、`test_silo_ladder_rung1_evidence.py` が
   その実バイトを現行 verifier に通していることを、レンズ A の報告を鵜呑みにせず親が直接確認した。

**段 3 が挙げた所見のうち 1 件は本依頼と独立の既存の穴である。** 負の txid を持つ trace
(`C -1 0 2 1 0 0`) は `expected = max(txid)+1` の式で欠番検査をすり抜け、false-green certified に
