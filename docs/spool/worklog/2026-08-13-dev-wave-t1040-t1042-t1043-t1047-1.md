## 本文

- 第 10 回裁定の 4 件を一つの wave で実装した。中断した親セッションを fresh context で resume し、
  段 3 の consult 2 本は再投入せず既存 job を待って回収した (再実測で稼働中と確認。
  luna はラッパのみ死亡し launcher が receipt と成果物を所有していた)。
- **段 4 の親裁定に誤りがあり、段 6 のレビューで訂正した。** 段 4 の走査は変数名 `reason` で
  拾ったため `diff_quarantine.py` の parser ローカル変数を quarantine reason と誤認していた。
  実際は `_mk_digest(..., evidence=self.parsed.reason)` で `evidence` field になる。
  `_mk_digest` 全 13 呼び出しを取り直したところ、`digest["reason"]` に入るのは
  **すべて producer 固定 literal** で、攻撃者制御の内容が到達する経路は 1 本も無かった。
  allowlist へ足すべきは `@`/`—` ではなく `・` (U+30FB) で、`@`/`—` の追加は撤回した。
- この訂正の帰結として、T-1047 を裁定文どおり `reason` だけへ適用すると**現行の脅威に対して
  一度も発火しない**ことが判明した。攻撃者制御の raw diff は `evidence` へ流れており、
  `diff_quarantine.py` 自身の既存規約 (`_line_evidence`: 拒否行を逐語再掲せず位置・byte 長・
  短縮 digest だけを返す) から逸脱した唯一の逐語経路だった。既存不変条件の回復として
  evidence の非逐語化まで含めた。**裁定文は `reason` を名指ししているため、この範囲判断は
  差し戻せる形で裁定パッケージへ返す。**
- **受入全走の赤 2 件は本 wave に帰属した。** s8b の承認 spec が `materializer` として
  `orchestrator/campaign/s1_direct_comparison.py` の bytes を pin しており、本 wave が
  そのファイルを編集したため golden の sha256 が古くなった。{{F:generator-pin-on-edited-source}}
  として記録する。前 wave と同一機構で、`DW-O09` の pin 閉包検索を contract ID 側だけで
  済ませ、**編集対象ファイルを pin している側**を数え落としたのが原因である。
- 変異は 13 件を事前登録し、正例 control 2 件 (非 oracle subtype の reject が失われないこと、
  実 producer の `・` を含む reason 4 分岐が原文保持されること) を含めた。
  途中 harness が 3 回 fail-closed で止まり、いずれも正しい停止だった —
  (a) 期待 node がパラメータ化テストの `[param]` 接尾辞を欠き collection に不在、
  (b) fix が allowlist literal を変えて anchor の old 逐語が消失 (`DW-M07` が発火)、
  (c) probe 巡で M7 が SURVIVED。
- **M7 SURVIVED の erratum ({{F:equivalent-mutation-on-anchored-parse}})**: 原因は gate の弱さでなく
  等価変異だった。正規表現の `^` を外し `match`→`search` にしても、構造化 prefix
  `session: index=N attempt=N status=X reason=` 全体の一致が必要なままで挙動が変わらない。
  wave 前の実コードの形 (部分文字列検索) を注入する M7r へ再照準したところ KILLED。
- 焦点再レビューが land 不可を返し、`evidence` へ検証を広げた際に allowlist を
  **evidence 側 producer で測り直していなかった**回帰を検出した。全数走査で外れ文字は
  `;` の 1 文字 (`auditor_gate.py` が violations と nits を `"; "` で連結) と確定し、
  正例の無い `[` `]` は撤回した。従来テストは producer 直後までしか見ておらず検出できなかったため、
  WAL・loader・renderer を通す統合正例テストを足した。
- 実測: 焦点走 367 passed / 1 skipped / rc=0。変異 matrix 13/13 KILLED
  (SURVIVED 0 / MISMATCH 0 / TIMEOUT 0、baseline PASSED)。
  受入全走 1 回目 10,833 passed / 2 failed / 65 skipped。
- `test_p3_s4_loop.py::test_checkpoint_direction_and_magnitude_domains_match_role_policy` の
  `ModuleNotFoundError: No module named 'codex_roles'` は file 選択走の import path 未確立による
  偽赤と判定し、本 wave 未 touch の `test_profiler_directive.py` を単独 file 選択走して
  同型 import が同じ赤になること (1 failed / 58 passed) で独立に実証した。受入全走では消えた。
