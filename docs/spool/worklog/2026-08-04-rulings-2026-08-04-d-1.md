## 本文

- **[T-389] は (d) 採用 — 当面は運用で回し、受入投入の直前に main HEAD を再確認する緩和だけ入れる。**
  あわせて (e) (再走免除の交差判定) の**実測**を行う。(a) 待ち行列 / (b) lock 内 main 取り込み /
  (c) 受入の増分化は、実測が 1 wave 分 (5 分の全走 × 5 回 = 25 分の空転) しかないため保留する。
  (d) は [T-328] 裁定 (c) の [T-313] 実装により `docs/dev-wave/operations.md` へ書けるようになる
- **段ごとの main 取り込みでは T-389 は解けないことを確認した。** ユーザーの提案 (dev-wave の各段で
  local main を確認し取り込む) は**既に運用規律として存在する** (2026-08-03 の是正、
  「land 直前にまとめない、16 commit 遅れで 3 回止めた」)。取り込み差分を小さく保つ効果は実在するが、
  land の可否を決めるのは `_is_ancestor` による「検査した main が現 main の祖先か」であり、
  **判定に効くのは最後の 1 回の取り込みだけ**である。したがって**受入全走 5 分の窓は同じ幅で
  開いたまま**残る。実際、当該規律が入った後の 2026-08-04 に 6 回のやり直しが記録されている
- **(e) の交差判定を「編集面の非交差」で定義してはならない (ユーザー指摘、採用)。**
  ユーザーの反例: 実装 a / b とそれらを覆うテスト a / b があるとき、**テスト b を変更した commit は
  テスト b を変更していない commit と編集面が重ならないが、テスト結果は赤になりうる** —
  赤の定義そのものが変わったためである。**免除述語は編集面の交差だけでなくテストとの相互作用を
  含めて定義しなければならない。** 一般化すると、編集面が交差しなくても verdict が変わる経路が
  少なくとも 3 種ある
  1. **判定基準そのものの変更。** incoming が test / checker / fixture / gate 定義に触れる場合、
     受入基準が変わっており、wave の tree は**新しい基準で一度も評価されていない**。
     編集面の交差の有無によらず再走が要る (ユーザー指摘の直接形)
  2. **テスト閉包の重なり。** incoming が実装だけに触れる場合でも、wave の変更面と incoming の
     変更面を**同じテストが通る**なら結果は変わりうる (共有 call path、共有 fixture、
     conftest、parametrize)。**ファイル単位の非交差はテスト単位の非交差を含意しない**
  3. **全体集計する制約。** 本 repo に実在する — `check_docs.py` の
     `DEV_WAVE_AGGREGATE_BYTES = 25_200` と `PROVENANCE_FAMILY_BYTES = 9_000` は**族の合計**を見る。
     `spool_fold._assert_active_conservation` の active 集合保存則も全体を見る。
     **各々単独では収まる 2 つの変更が、合算して初めて超える**ため、編集面は完全に非交差でも赤になる。
     [T-359] / [T-386] が個別ファイルではなく合計予算で塞がれた実例がこれにあたる
- **したがって (e) の免除述語は最低でも次の全成立を要求する:** incoming が test / checker /
  fixture / gate 定義に触れないこと、incoming と wave の変更面のテスト閉包が交わらないこと、
  incoming と wave が同一の全体集計制約 (族予算・保存則・閉包検査) に同時に寄与しないこと。
  **それでも免除は保証ではなく近似である** — 共有する不変条件を別々に壊す経路は残る。
  採用するなら**免除の根拠と限界を明記する** (保証していないものを保証すると書かない規律)
- **実測の設計も変わる。** 親は当初「破棄した 5 回の main 差分が wave の面と交差していたかを見れば
  追加計測は要らない」と述べたが、**これは誤り**である。上記 3 種を判定するには**ファイル差分では
  足りず、テスト閉包の写像**が要る。実測は「破棄 5 回のうち、上記 3 条件をすべて満たしたのは何回か」
  を測る形になる
- **予想と撤退条件を先に置く。** 上記の厳しさから**免除率は低い可能性が高い**。実測で低ければ
  **(e) は実装せず**、(d) の緩和と損失データの蓄積に留めて (b) を再検討する。
  免除率が低いこと自体が「窓を閉じる以外に手が無い」の根拠になる
