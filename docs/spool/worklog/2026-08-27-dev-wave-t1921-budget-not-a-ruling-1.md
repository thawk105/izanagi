## 本文

- D961 / D1046 が命じた `docs/skill-self-improvement.md` の書き換えを着地させた。
  「予算値を上げる変更は通常の自己改善に含めず、理由付きの独立審査対象にする」を、
  D782 の手順を指し「裁定へ返さず、上限引き上げに至った場合だけ報告する。一括増枠は不可で、
  層ごとの最小増分と収容表は親裁定が持つ」と読める形へ改めた。
- **書き換えは 1 文でなく 2 文が対象だった。** D961 が名指しした 1 文だけを直すと、
  直前の「それでも意味等価にできなければ変更を止めてユーザー裁定へ返す」が残り、
  誤って裁定へ送る経路が半分開いたままになる。段落として直した。
- **担い手不在を実測で確認した。** 着手時点の local branch 18 本すべてで
  `docs/skill-self-improvement.md` を走査し、書き換えを載せた branch は 0 本だった。
  親 brief は 32 branch と記していたが、着手直前の local branch は 18 本である。
  生きた文面の所在も 1 か所だけで、他の一致は archive・insights・他 worktree の履歴記録だった。
- **予算残 37 bytes が文面設計の律速になった。** D782 の 3 手順 (既存記述の削減 →
  独立 3 例以上なら例外収容 → 収容先を作れないと確かめられた場合にだけ上限引き上げ) を
  逐語で書き込む案は 24〜76 bytes 超過した。D961 の命令は「D782 の手順を**指す**形へ
  書き換える」なので参照形を採り、5,963 → 5,987 bytes (予算 6,000、残 13) に収めた。
  **既存記述の削減 (D782 手順 1) は不要になり、上限引き上げにも至らなかったので、
  D782 が課す報告義務は発生していない。**
- **T-1925 は T-1921 と同一内容の二重起票だった。** どちらも「D961 が命じた文面書き換えを
  D782 の手順を指す形へ改める」で、担い手不在の記述まで一致する。同時に閉じた。
  裁定控えの本文が指す ID は T-1925、command 引数は T-1921 で、主題は同一である。
- 段 4 で改めて裁定 inbox を走査したが、wave 開始後の更新はなかった。
  実装面の差分がゼロなので変異 matrix は免除される (`DW-S04`)。
- セッション異常: `git worktree add` が 15,995 file の checkout に 2 分以上かかり、
  前景実行が timeout して branch と directory だけ残る中途半端な残骸を 1 度作った。
  git 側の巻き戻しで directory は消え、branch を再利用して背景実行で作り直した。
- 着手中に local main が 30e7f8c41 → dd66213 へ進んだため、進んだ側から worktree を取り直した。
- **段 8 で書き換え後の文面を即座に自己適用した。** worktree 作成の作法を `DW-O20` へ足す
  候補が出たが、同節は 998/1,000 bytes で予算に阻まれる。新文面に従い裁定へ返さず D782 の
  手順で閉じた — 実測は本 wave の 1 例だけで、例外収容が要求する独立 3 例に届かないため、
  D730 の原則どおり「実施しない」へ落とした。上限引き上げには至っていない。
- 段 8 の他候補: T-1921 / T-1925 の二重起票は起票側の問題で、rulings の本文編集 gate は
  今回の実行で実測していないため記録のみとした。dev-wave 側の入口・reference は変更していない。
- 検査: `check_docs.py` 違反なし。`orchestrator/tests/test_check_docs.py` は
  計算ノードへ dispatch して 567 passed / 3 skipped。
