## 本文

- ユーザー起票 ([T-1892] と [T-1894])。前 wave の「TRACE=1 3 本中 1 本が G2 で fail-closed」が
  MoCC 実装の性質か trace hook の取り違えかを分けられていなかったので、同一 workload での
  反復により再現率を測った。**[T-1893] は裁定待ちなので触っていない。**
- **反復数・分母・判定規則を実走前に凍結した。** 事前登録は
  `output/insights/2026-08-26_mocc-g2-repro/pre-registration.md`
  (sha256 `182abe5cdad001d8ec799bbf33d097674ad7292cd8e5880826ca56654dd6e235`)、
  凍結時のソース内容は tree `f737e87dfadfadea6e76a4feb1d3d2219134dc70`。
  **結果 = k/m = 5/42 = 0.11905、Clopper-Pearson 95% = [0.039806, 0.256317]、除外 0 本。**
- **段 3 の敵対検査が N を 30 から 42 へ変えさせた。** N=30 では k=0 でも上側限界 0.1157 が
  p=0.10 を排除できず、「flake か低頻度の実在か」を分ける目的を達しない。42 なら 0.08408。
  **これは結果を見る前の変更である。**
- **除外規則を素朴に書くと分子が構造的に消えることを段 1 で先に発見した。** anomaly を出した run は
  anomaly のせいで job が rc=1 で落ちるため、「落ちた run を除外」とすると G2 が観測されるたびに
  母集団から消える。job が verifier JSON と rc を保存してから落ちることを実測し、
  `stage` と rc と JSON の中身の組で分母を決めた。段 3 の 2 レンズが独立にこの点を検査し
  refuted した (規則は成立している)。
- **段 6 のレビューが親の結果文の誤りを 5 件見つけた。** 実効検出力の算術誤り、
  「7 batch とも 6 本並行」という実行時には偽の主張 (実測 peak は batch により 2〜6)、
  副次解析への前 wave 1 件の混入、原因分岐への推論、provenance の過大主張。すべて訂正した。
- **段 6 のレビューが台帳生成器の閉包が恒真であることを見つけた。** 投入集合の閉包が正本の
  `attempts/submissions/` ではなく親が写した `runs/*` を列挙していた。正本 44 件 (42 本 +
  dry-run 1 + 生死確認 probe 1) を repo へ収録し、全列挙して `source_commit` で分割する形へ直した。
  詳細は {{F:closure-over-projection-is-vacuous}}。
- **段 6 のレビューが「一度も実行されていなかった assert」を見つけた。**
  `test_mocc_trace_pair.py` の再帰的な禁止 key 検査が `_nested_key_paths` 未定義で
  NameError になっていた。helper の正例・負例を別 node として追加させた。
- 待ち手が子の生存中に完了を報告する事象を **2 度**実測した。1 度目は
  `tools/dev_wave_wait.py producer` が rc=0・無出力で戻った件、2 度目は親が書いた
  Monitor 用 watch script の誤検知。いずれもイベント本文を信用せず `.done` の実在と
  `pgrep` で裏取りして回避した。詳細は {{F:waiter-reports-completion-while-child-lives}}。
- 実装は Codex `role=author` 3 単位 (job script / pair checker + anchor / 台帳生成器) と
  fix 6 本。親は実装面を直接編集していない。
- 実測した環境事実: TRACE=1 の 1 本は submit から完了まで約 101 秒。42 本を 7 batch × 6 で
  投入し、全 batch を通じた実測 peak 同時実行数は 6、batch 別では 2〜6 だった。
  **anomaly は高並行に偏っていない** (peak 2 の batch 6 で 2 件、peak 6 の batch 3 で 0 件)。
- 得た対は `official_certification=false` のままで、headline・certified な選択・floor・oracle・
  fitness の根拠に使っていない。**pair receipt の `prohibited_uses` は宣言であって強制ではなく、
  それを必須入力として読む consumer は repo 内に存在しない。**
- 設計判断は {{D:preregistered-repro-rate-study}} と {{D:anchor-externality-tiers}}。

### 新規

- {{T:mocc-g2-ground-truth-observation}} **P2・新規**: G2 の原因を「MoCC 実装の性質」と
  「izanagi 側の記録の取り違え」に分けるための観測を設計する。再現率では分けられず、

  同時実行数を制御した測定には同時開始 barrier が要る。
