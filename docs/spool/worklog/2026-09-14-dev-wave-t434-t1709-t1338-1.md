## 本文

- **依頼文と正本が逆を指していたので、着手前にユーザーへ照会した。** 依頼は「受入関門 2 件
  (…) を入れる」だったが、正本 (起票本文と D501 決定 8) は同じ 3 述語を「撤去する」と定めている。
  親が 3 述語すべて実装済みであることを現物で測り、新設が空作業になることを添えて照会したところ、
  **「撤去を scope に入れる」**の裁定を得た。以後はこの裁定に従った。
- **段 3 の敵対レビューが親 brief の編集面指定の誤りを見つけた。** 親は D501 決定 8 の
  「driver の測定 binary bytes 照合」を `floor_pair_driver` の build receipt 検査と同定していた。
  実際には同 module は B-4 床値の測定側で、その検査は spec 指定 binary と receipt の対応しか見ず、
  過去 campaign 由来であることを要求していない。決定 8 の性質に一致するのは oracle driver 側の
  供給経路 (過去床値 receipt の hash → `expected_perf_sha256` → 今回 build した perf binary との
  照合 → 測定前 abort) だった。**親が実コードで確かめて編集面を差し替えた。** 誤ったまま進めば、
  外すべき経路を残したまま無関係な検査を落としていた。決定は
  {{D:retire-floor-derived-admission-gates}}。
- **親 brief の不変条件を 1 つ裁定で外した。** brief は「supersede する既存述語を正例で示せない
  述語は撤去しない」と書いたが、D501 決定 8 の逐語は完全代替を主張しておらず、この条件を課すと
  撤去できる述語がゼロになる。授権は「D496 の下で不要になったこと」である。代替の有無は記録し、
  撤去の条件にはしない形へ改めた。
- **段 6 のレビューが must-fix 2 件を出し、どちらも親の実測で real と確認した。** (a) 行番号を
  frozen dataclass の辞書キーに焼き込んだ test があり、撤去で対象行が 10 行ずれて実際に赤になった。
  識別子検索にも hash 検索にも掛からない型の pin で、親の焦点走の当初範囲から外れていた。
  (b) 退役させた driver test 1 本が誤りだった — 撤去した経路ではなく、残存する
  「abort 理由 → terminal outcome」変換を検査していた (注入 helper が理由を WAL へ直接書くため、
  撤去した経路を通らない)。復活させ、テスト関数名集合が基底と完全一致に戻ることを親が
  突き合わせで確かめた。
- **[T-434] は実装しない。** 裁定は D1433 / D1434 として 2026-09-02 に着地済みであることを親が
  現物で確認した。実装は D1407 §1・§3 が内容 commit へ「実装一式」を要求し D1421 が部品の
  先行 land を禁じるため、意味的充足契約の本体に順序依存する。P6 は未実装で、正常な前段検査の
  後に無条件で `P6Unavailable` を返す経路が生きている。本 wave は記録の照合だけを行い、
  二段束縛の部品を land しなかった。共有 git 信頼境界の統一は D1433 のとおり起票しない。
- **[T-1709] は 8c 事前登録の前文へ未解決の明記を入れた。** 条件契約 (§5 の欄名、§6 の前提条件、
  規範本文、発効ポリシー) の bytes は変えていない。protected hash が前後で不変であることを、
  実 CLI (`s8c_preregistration.py check --commit`) の実測で確かめた。値は
  `1e325f9d9ce483b14d02e2c857f785007afa45005112127312b409d77cfee684`。独立した 3 つの読み手が
  メモリ上の parser 比較で同じ値を出しており、実機の値と一致した。`DECIDER_VERSION` の bump も
  次世代 record の発行も行っていない (D911 の据え置き)。
- **受理集合は広がる。** floor の pairs 欠落・余分・stock 混入、pair の 0 / 負値、`scalar_alt` の
  max 不一致、null 相関違反、床値が scalar 形の freeze は受理される。過去 campaign と別 binary での
  oracle 測定も測定前 abort を受けない。射程は公式 candidate 入口にも及ぶ。逆に
  `floor_budget_snapshot_sha256` を持つ旧形の文書は拒否されるようになる。**旧 key を持つ live な
  成果物は repo に 1 件も無いことを実測した** (hit は過去 insight の記録 1 件だけ)。
- **`pipeline` の generic な `expected_perf_sha256` gate は production の供給元を失った。**
  D501 決定 8 が名指していないので撤去せず、事実として記録する。
- **変異は 4 件を事前登録し、本走で 4/4 KILLED・MISMATCH 0・SURVIVED 0 だった。** 撤去 wave なので
  照準は「残す述語が本当に発火するか」に置いた。probe 走 (全件 SURVIVED 登録) で exact node を
  集めてから本登録した。段 6 レンズが指摘した 1 件の照準誤り (admission 例外の握り潰しを
  store hash 負例で kill できると書いていた) は、probe が別 test での kill を実測して訂正を裏づけた。
- 実測: 基底 318 件緑 → 撤去後、manifest 単独 97 件緑、driver 単独 127 件緑 6 skip、
  consumer 15 file で 1315 件緑、fix 後の焦点再走 6 file で 784 件緑 18 skip。
  全史 provenance 監査は 9750 件で新規違反なし。
- Codex 子 8 本 (plan 1 / consult 2 / author 2 / review 2 / fix 1)。段 5 の実装子 2 名と段 6 の
  fix 子 1 名は、いずれも sandbox に scheduler の実行 file が無く `rc=16` でテストを走らせられず、
  **3 名とも「実装済み・未実走」と正直に申告した**。実走はすべて親が行った。F964 と同じ型である。
