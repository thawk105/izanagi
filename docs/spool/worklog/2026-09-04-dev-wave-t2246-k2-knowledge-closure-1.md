## 本文

- **ユーザー裁定 D1570 の実装。** K2 を「宣言した外部取得と投入の範囲」として扱い、投入件数を
  条件にしない形へ直した。取得結果が正当に空である場合に限って空の source 集合を通す。
  緩和の条件は宣言と記録であり、実取得を証明する機構は作っていない (D1429 が許可リストや
  機械的 leak 判定の初手新設を絶対規律 5 違反として却下しているため)。非空要求は manifest・
  試行台帳・材料レポート schema・role 入力 schema の **4 層**に散っていた。

- **段 4 の裁定が段 6 で 2 度覆された。いずれも裁定そのものではなく、実装が裁定の目的を
  別の場所で壊していた型である。**
  1. 段 4 は「実績のある呼び方を守るため、K2 判定を role 契約の明示宣言で行う」と裁定した。
     実装は関数契約としてはそのとおりだったが、呼び出し側が知識射影を無条件に渡していたため、
     **その実績のある呼び方が「片側指定」として拒否されるようになった。**
     守ろうとした受理集合を、守るための機構の呼び出し側で壊していた。
  2. 段 4 は絶対規律 6 に従い「role が指示めいた内容を申告したら fail-closed」と裁定した。
     分岐は正しく置かれたが、proposal file を通常の JSON 読み込みで読むため、
     **同名 key を 2 回書けば後勝ちで前者が消え、新設した停止分岐を迂回できた。**
     repo には重複キーを拒否する parser が既に 2 つあり、使っていなかっただけだった。

- **本 wave の中心的な互換性主張が、段 6 まで一度もテストで証明されていなかった。**
  「旧 manifest の digest を 1 byte も変えない」が設計目的であるのに、テストは同じ module の
  定数と突き合わせるだけで、定数と生成側を同時に変える実装でも緑になった。段 6 のレンズ D の
  指摘で、実在 campaign の受領証 canonical bytes 全体を literal golden として固定した。
  同レンズは、`main()` の知識射影テストが検査対象を差し替えたうえ期待値も同じ生成器を
  呼び直して作る恒真テストであることも見つけた。

- **変異の期待 node は推測でなく probe で採った。** レンズ D が「事前登録 9 件のうち 6 件で
  期待 node が完全集合でない」と指摘したため、`DW-M07` に従い全件 SURVIVED 期待の probe を
  先に走らせて観測 node を採取し、その実測値で本走した。レンズ D の推測集合とは一部食い違い、
  推測で埋めなかったことが正しかった。本走は **9/9 KILLED・matching=9・baseline 緑**。
  `m05` (参照整合性検査) `m07` (論理 output schema 検証) `m08` (申告での停止) は
  **ちょうど 1 node** で、単一理由性を実測した。`m09` は承認外の過剰拒否の正例で、
  `m08` と対にして「必要なときだけ止まる」ことの両側の証拠にした。

- **main を 2 度取り込んだ。2 度目は 87 commit で、実装面の真の合成が生じた。**
  merge commit の本文に「両親を超える内容を導入していない」と書いたのは**誤り**で、
  `git diff-tree --cc` は非空だった。解消した行自体は wave 側の逐語と同一だが、周囲の自動 merge が
  main 側の分岐削除を適用したため、結果が両親のいずれとも異なる組合せになった。
  同 commit の Codex `role=author` trailer は正しく、合成監査も別途行って must-fix ゼロを確認した。
  履歴は書き換えず訂正を記録に残す。

- **非帰属赤 1 件は受入全走で偽赤と確定した。** 焦点走で `test_profiler_directive.py` の 1 node が
  `ModuleNotFoundError: No module named 'codex_roles'` で赤になったが、本 wave の当該 file への
  差分はコメント 2 行だけで、この例外を生む経路がない。`DW-O18` の file 選択走の型であり、
  受入全走 (20469 passed / 0 failed) で同 node が通った。

- **設計判断は {{D:declared-scope-is-the-allowed-range}} と
  {{D:k2-contract-selected-by-caller-declaration}} に記録した。** 前者は D1559 の 2 点
  (許可範囲の出所と receipt 世代) を更新し、同決定の恒真性の論拠と却下理由は維持する。

- **主張の境界。** 取得結果が空であることは呼び手の宣言であって取得行為の証明ではない。
  宣言範囲の selector は記録上の宣言であって包含を強制しない。参照整合性が照合するのは
  campaign が束縛した知識射影であって role が実際に読んだ入力ではない。既存 K2 campaign は
  digest と識別子を保つが replay / resume は主張しない。**K2 role の wrapper が proposal 経路を
  通った実成果物は 0 件であり、本 wave が作ったのは配線であって発火の実績ではない。**

- **エージェント工数。** 段 2 プラン 1 本、段 3 敵対相談 2 本、段 5 実装 1 本、段 6 敵対レビュー 2 本、
  段 6 fix 2 本、merge 適合 1 本、merge 合成監査 1 本の計 10 子。実装子・fix 子はいずれも
  投入 infra の `rc=16` で pytest を実走できず、実測はすべて親が行った。子の非実走を緑と数えていない。

- **運用の実測。** merge が `docs/dev-wave/` の文書を持ち込むと、merge 進行中は authority docs の
  未 commit 差分により Codex 子が段によらず起動できない。`DW-O17` の「競合解消してから commit」と
  D95 の「実装面の解消は Codex author」がこの場合に同時に満たせないため、
  merge を戻し clean な別ツリーで先回りの適合を書かせてから merge し直した。
  変異 harness は login node での local 実行を拒否し、計算ノード投入のみである。
  キュー混雑で 1 度 queue-wait timeout になり、D612 の上書き (900→3600 秒) で通した。
