## 本文

- 索引 4 件のうち 3 件をユーザーが**推奨どおり**裁定した。[T-338] Q5 (標本設計 = 費用の裁定) は
  「回復とは何か」の問い返しを受けて未裁定のまま残る
- **[T-369] と [T-386] は前提が消えたので選択肢ごと組み替えた。** 両項は「`docs/dev-wave/**` の
  合計 byte 予算が塞ぐ」を理由に保留されており、選択肢は (縮約 / 再配分 / 見送り) だった。
  しかし直前に裁定された [T-313] が**ノウハウ全体の固定文字数上限を撤廃**したため、
  この前提自体が成立しない。**ユーザー裁定 = 4 件とも条件読み層へ入れる。**
  いずれも段ごとの手順であって常時読む必要がなく、新しい剪定基準 (発火実績 + 機械検査での
  義務代替) から見れば**4 件とも実測事故という発火実績を持つ**ため、剪定対象にならない
  - [T-369](a) `DW-S05-C` の「緑を主張するなら走らせた nodeid を併記」は、計測機の runbook が
    子のテスト実走を禁じる環境で適用できない。`DW-O05` (read-only 子) と同じ「実測は親が行う」を
    workspace-write 子にも書く
  - [T-369](b) 凍結境界の「実装面は Codex が書く」が段 1 の前提実測 probe にも掛かり、
    `DW-S01` の「コード変更を伴う前提は実編集・即時復元で測る」を親が実行できない
  - [T-386](a) `DW-S05-A` の所有パス限定 patch は、前段適用済みの tree へ HEAD 差分を当てると
    二重適用で競合する。段が積み上がったら所有ファイルの直接反映にする
  - [T-386](b) `DW-S05-C` に計測機と実行ホストが分かれる環境の指示が無く、親が毎回 prompt で補う
- **[T-373] は分離記録 (択 b)** — `tools/task_runs/cli.py --reasoning` は不正値を拒否せず、
  `requested_reasoning` と validity を分けて記録する。**この台帳は失敗した起動も記録する
  観測台帳**であり、CLI で拒否すると「不正値で起動を試みた」事実そのものが残らない。
  拒否する案は観測台帳の目的に反するため採らない
- **[T-313] と [T-328] は互いを補強する関係にあると確認した。** [T-313] は「常に読まない層を
  予算対象から外す」構造変更、[T-328] は「入口の内容を条件読み reference へ外出しする」作業であり、
  外出しした内容がそのまま予算対象外になる。**片方だけでは効かない** — 外出ししても総量で
  縛られていれば枠は空かず、上限を外しても入口に積んだままなら常時読量が減らない
