## {{D:registry-proof-adds-trial-coverage}}. 試行台帳の束縛証明に試行被覆の全単射照合を足す

**決定 (ユーザー裁定):** D1337 が定めた proof の形 `{row_count=N, chain_head_at_N}` は変えず、
schedule と admission claim から独立に導出した「本来あるべき試行の集合」と台帳の生存行を
全単射で照合する検査を足す。実装は D1341 が定めた 1 commit 閉包の中で行う。

**理由:**

- 2026-09-01 の設計 wave で独立した 4 本の検査が、現行の proof の形だけでは
  genesis 1 行の台帳でも別 campaign の台帳でも検証が通ることを実測した。
  これは D1194 が却下した状態そのものである。
- 本決定は D1337 の proof の形の変更ではなく、D1194 が要求した束縛の実装である。
  発火しない保証を land することは、正しさシグナルを後付けにしない規律に反する。
- 実装量は増えるが、着手後に覆すと 2,650-4,000 行の作り直しになるため、着手前に確定させる。

**却下した選択肢:**

- 足さない (D1337 の字義どおりに留める) — 恒真な束縛のまま land することになる。
- 束縛の主張自体を落とす (表示をやめる) — 実装は最も軽いが、raw 試行記録の
  file-drawer を機械的に閉じるという台帳本来の目的が消える。親が rulings で第 3 案として
  提示し、ユーザーが採らなかった。

## {{D:classification-authority-constant}}. 分類権限を production 定数として新設し、値の権威は実測で決める

**決定 (ユーザー裁定):** 計測の起動層が「出力前に成否を分類する方針」を名乗るための
production 定数を新設する。現在この権限はテスト内の文字列としてしか存在せず、
台帳への試行記録を配線できない。

値の権威は次の順で決める。まず、既存の固定純関数から機械導出できる値かを実装前に実測する。
機械導出できるなら AI が閉じる。人間所有の凍結 policy を変える値だと判明したら、
そこで止めてユーザーへ返す。**この分岐の判定を待たずに実装を始めない。**

**理由:**

- D880 は同種の権限 (回復側) を意図的に空のままにした先例だが、これは fail-closed な
  権威 pin の先例であって「値をユーザーが与える」先例ではない。交差相談 (Codex レーン A)
  がこの区別を指摘し、親の初版が両者を混同していた。
- 権限の置き場所は本 repo でユーザー裁定の面として扱われてきたが、値の導出可能性は
  実測で決まる事実問題であり、事実問題を裁定で埋めない。

**却下した選択肢:**

- 新設しない — 台帳の権限欄が空のまま配線され、記録の意味が失われる。
- 値をユーザーへ無条件に上げる — 機械導出できる値なら人間の手番を無駄に増やす。

## {{D:same-remediation-triple-means-choice-identity}}. 「同一の是正 3 択」は選択の同一性を指し、効き方の同一までは求めない

**決定 (ユーザー裁定):** D1192 の「同一の是正 3 択」は「提示する選択肢が同一であれば足りる」と読む。
「効き方まで同一でなければならない」とは読まない。2026-09-01 に着地した根クラス 2 の実装は
差し戻さない。

**理由:**

- D1192 と D1322 が要求しているのは cache entry・拒否述語・descriptor・是正 3 択の同一性であり、
  効果の完全同一は本文に無い。
- 後者を追加条件にすると、D1322 が明示的に認めた 2 つの根クラスへの拡張を事後的に狭める。
- 親と段 3 の敵対相談 2 本で読みが割れたまま放置すると、同じ裁定を引く後続 wave が再び割れる。

**却下した選択肢:**

- 効き方の同一まで求める — 着地済み実装の差し戻しになり、拡張の射程も狭まる。

## {{D:silenced-guards-restore-inventory-first}}. 沈黙した防壁 21 件は入力要求の棚卸しから始め、歴史記録は復元しない

**決定 (ユーザー裁定):** 外部ツールの過去 rollout 消失で巻き添えになって沈黙した防壁 21 件について、
第一段として「21 件それぞれが何を入力に要求しているか」を読み切る。歴史 anchor そのものの
復元は行わない。合成入力で代替できないと実測済みの 1 件
(`test_real_rollout_collector_golden_is_source_bound`) は terminal として落とす。

hermetic 化の方法は発明しない。同 repo の兄弟 file に既に動く実装がある。

**理由:**

- 沈黙したのは sandbox 束縛・supervisor の git 環境洗浄・submodule object store の再帰性・
  stale commit graph の拒否・attempt 上限・material replay・symbolic HEAD 要求であり、
  いずれも実データを要さず有効な snapshot があれば成立する。
- 代表 1 件では合成可能と示せたが 21 件全部は未確認であり、一括で合成可能と仮定しない。
- 歴史記録の復元は、論文の主張に要るのは粗い provenance のみという 2026-08-12 方針と D1139 に反する。

**却下した選択肢:**

- 21 件を一括 skip する — 生きた防壁を理由なく落とす。
- 歴史 anchor を復元する — 超過した粒度の provenance を復活させる。

## {{D:b4-floor-activation-is-user-turn}}. B-4 事前登録の床値欄は AI が手続き案と測定計画を出し、発効はユーザーが行う

**決定 (ユーザー裁定):** B-4 事前登録 §5 の `floor` 欄について、AI は発効手続きの案と、
床値を得るために必要な測定計画を用意する。誰がどの証拠で発効させるかはユーザーが決める。
AI が既成事実として値を埋めることはしない。

**理由:**

- D1060 は既存値の流用を禁じ、床値には新しい測定 campaign が必要だと定めている。
  D1377 は AI による既成事実化を却下している。
- 発効するまで材料レポートの分析 verdict は `protocol_violation` にしかならず、
  §7.1 の 4 分類が実効化しない。材料レポートは Phase 3 の主経路の片翼であるため、
  ここが止まると主経路が止まる。

**却下した選択肢:**

- AI が測定して値を埋める — D1377 が却下済み。
- 発効を待たずに 4 分類を有効化する — 事前登録の意味が消える。

## {{D:acceptance-floor-next-axis-is-shared-cost}}. 受入床値の次の一手は全 shard 共通の report 外費用の調査とする

**決定 (ユーザー裁定):** 受入全走の所要時間の床について、次に調べるのは全 shard 共通の
report 外費用 (約 56 秒、wall の 26%) とする。最長単体 126.13 秒の短縮解禁、最遅 shard 固有の
約 21.9 秒の計測点追加、本項の台帳からの削除は、いずれも今回は採らない。

**理由:**

- D1369 の実測により、床が排他鎖だという D1035 の前提は消えた。閉包を細分化しても
  最悪 shard の worker occupancy は動かない。
- 約 56 秒は 3 shard すべてが払う成分であり、どの裁定も触れていない最大の未着手軸である。
  最遅 shard 固有の成分より全体への寄与が大きい。
- 本項を落とすと、開発するほど受入が遅くなる構造を放置することになる。

**却下した選択肢:**

- 最長単体の短縮を解禁する — 前提が消えた以上は再裁定に値するが、効きが小さい。
- 最遅 shard 固有の成分を測る — 診断としては有用だが単独では短縮しない。

## {{D:completion-proof-accepts-executable-evidence}}. 完了証明層は実行可能な証拠を一般規則として認め、新しい機械 gate は作らない

**決定 (ユーザー裁定):** 完了証明層の充足証明に、静的解析以外の実行可能な証拠を含めてよいことを
規範として一度だけ書く。条件ごとにユーザーへ問い直す運用は採らない。
D1364 の 4 点 (充足証明・負例・世代更新記録・裁定の先行着地) は維持する。

**この決定は規範本文への追記であって、機構の新設ではない。** 4 点の充足を強制する新しい機械 gate を
作る形になるなら、その時点で不採用に倒す。D1364 が同種の gate を「要求されていない仮想リスク向けの
機構」として既に却下している。

**理由:**

- 静的解析だけでは実行時の再束縛を塞げないことが実証済みである。
- D1026 は条件ごとに違う開け方が生まれることを禁じており、共通手続きの確立が裁定の内容である。
  条件ごとの問い直しはこの趣旨に反し、運用費用だけを増やす。

**却下した選択肢:**

- 実行可能な証拠を含めない — 実行時の再束縛に対して無防備なままになる。
- 4 点の充足を機械 gate で強制する — D1364 が却下済み。

## {{D:historical-purpose-migration-excludes-oracle}}. 歴史 purpose への移送は S-1 の epoch gate だけとし、replay と oracle は移さない

**決定 (ユーザー裁定):** 過去の測定を読む消費者のうち、歴史 purpose へ移すのは S-1 の epoch gate
だけとする。`replay.load_landscape` は移さない。oracle の epoch 証拠は今回の対象から外し、
その consumer 閉包を確かめてから改めて扱う。

**理由:**

- D1366 のとおり S-1 は可用性 gate と保存済み COMMIT 証拠検査が別関数であり、安全に分離できる。
  素朴な付け替えでは `E0 / v1-authority-absent` の拒否まで落ちるため、分離は関数単位で行う。
- replay は exact 型と証拠 capability に束縛されており、緩めると絶対規律 2 に触れる。
- oracle について、保存済み証拠と capability を維持したまま可用性だけ外せる根拠が一次資料に無い
  (交差相談 Codex レーン A の指摘)。根拠不足のまま移送しない。

**却下した選択肢:**

- 3 消費者すべてを移す — replay の緩和が規律 2 に触れ、oracle は根拠が無い。
- 1 件も移さない — 歴史参照が現行の正しさ主張と混ざったまま残る。

## {{D:source-binding-not-relaxed-for-resume}}. enforcement source closure の束縛は live resume の互換のために緩めない

**決定 (ユーザー裁定):** 判定器・評価器の bytes 変更で enforcement source closure の epoch が変わり、
旧 commit を束縛した campaign の live resume が drift になる件について、source binding を緩めない。
drift した campaign は再走で作り直す。

**理由:**

- 受理される範囲を広げる方向の変更であり、絶対規律 2 に触れる。
- 過去の測定の事実は現行コードとの差では無効にならない (絶対規律 7) が、
  それは古い判定器で測った結果を新しい世代の成果として通す理由にはならない。
- 実害は再走に要する時間だけであり、受理集合を広げる代償に見合わない。

**却下した選択肢:**

- 互換のため binding を緩める — 弱い判定器で測った結果が新世代へ混ざる経路が開く。

## {{D:oracle-cache-miss-confirm-before-terminating}}. oracle の cache 不成立は共有依存基底を作らず、既存裁定との同型を確かめてから終端する

**決定 (ユーザー裁定):** oracle の descriptor 経路で FetchContent 入力を持つ cache hit が失敗する件について、
共有依存基底を与える設計変更は行わない。ただし「新規退行ではない」ことだけを理由に終端しない。
この経路が、cache hit 不成立を限界として受け入れた D1220 と同じ surface なのか、
fresh build へ安全に落ちるのかを read-only の調査で確かめ、その結果をもって D1192 の未達を明記して終端する。

**理由:**

- v2 化の前も同じ経路が `external compiler input is unavailable` で落ちていたため新規退行ではないが、
  新規退行でないことは終端の根拠にならない (交差相談 Codex レーン A の指摘)。
- 設計変更の費用は oracle の実行頻度に見合わない。実害は所要時間だけである。

**却下した選択肢:**

- 共有依存基底を新設する — 実行頻度に対して費用が見合わない。
- 未達を明記して即終端する — 根拠が「新規退行でない」だけになる。

## {{D:root-commitment-not-introduced}}. 2 つの根クラスへ durable な root commitment を導入しない

**決定 (ユーザー裁定):** `dependency-prefix` 根と `fetchcontent-masstree` 根が、自己申告した根と
相対 path と hash しか持たず origin へ帰属を検証できない件について、durable な root commitment を
導入しない。既存の canonical 性検査の射程で止める。

**理由:**

- 両根クラス全体へ新しい bytes 級 provenance を導入する設計であり、論文の主張に要るのは
  粗い provenance のみという方針 (D1139 のユーザー逐語裁定を含む) に正面から当たる。
- 現行成果物への具体的な実害が示されていない。

**却下した選択肢:**

- 片方の根クラスにだけ入れる — 同じ弱さが残り、二度手間になる。
- 両方へ入れる — 上記の方針に反する。

## {{D:approval-record-preparation-unblocked}}. 承認 record の準備は解禁し、発行と pointer の発効だけ人間の手番として残す

**決定 (ユーザー裁定):** 凍結側の下位実装を上位権限束設計の exact 正本へ適合させ、
legacy v1 から凍結 g1 への承認可能な successor を人間承認の直前まで用意する作業を解禁する。
この作業の着手条件だった A6 の proof 定義は D1339 で確定済みであり、条件は解消している。
承認 record の発行と有効 pointer の commit は引き続き人間の手番とする。

**理由:**

- D1339 は A6 の proof を凍結 g1 の承認済み successor と定め、remediation owner を主体でなく工程で
  割った (準備・検証は AI、承認 record の発行と有効 pointer の発効は人間)。前提は解消している。
- ここが止まると上位権限束の完成が止まり、それを待つ下流が連鎖して止まる。

**却下した選択肢:**

- 着手条件を残したまま待つ — 既に解消した条件で止め続けることになる。
