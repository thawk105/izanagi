## {{D:cc-diagnostics-placement}}. CC 調査の診断手順は症状索引つきの単一 docs へ置き、発見経路は既存の参照方式だけで作る

**決定:** CC 調査で再利用する診断手順は `docs/cc-diagnostics.md` 1 file に置く。冒頭に症状索引を持ち、
手順が増えたら索引に行を足す。**発見経路は既存の参照方式 3 本だけで作り、dev-wave の読み込み契約
(`docs/dev-wave/` の leaf 節) へは足さない。**

1. `docs/README.md` の地図に、症状語を行内に含めた 1 行を置く。
2. `docs/glossary.md` の該当用語の項から手順書へ誘導する。
3. その手順が使う計器の `patches/README.md` の行から手順書へ誘導する。

**理由:**

- dev-wave の読み込み契約は L1 層が 10,624 / 10,625 bytes で**残り 1 byte** である。1 行足すには
  既存義務の bytes を空ける必要があり、それは予算と段構成に関わる裁定境界にあたる。
  自己改善契約は「予算のために安全義務を削除・弱化してはならない」「段構成・予算の変更は実装せず
  裁定パッケージへ送る」と定めている。
- 上記 3 本は izanagi が既に持つ参照方式である。`CLAUDE.md` は大きい文書を「見出しや用語を検索して
  該当範囲だけ読む」と定め、その地図を `docs/README.md` に委譲している。新しい routing 機構を
  足すより、既にある索引に載せるほうが安い。
- ディレクトリでなく単一 file にするのは、手順が 1 本しかないためである。族の機構を 1 例から作ると
  `DW-G03` が禁じる一般化になる。2 本目が来たら節を足し、file を割るかはそのとき決める。

**却下した選択肢:**

- **`DW-S01` へ 1 行足す** — L1 が 95 bytes 超過して文書検査が赤になる。既存本文を縮約すれば入るが、
  縮約対象は安全義務の本文であり、予算のために削ってはならない。
- **`.claude/commands/dev-wave.md` の dispatch 表へ行を足す** — 入口は 9,507 / 9,520 bytes で
  残り 13 bytes。入口編集条件 (実測で誤りと判明した命令の是正、意味を変えない縮約、
  常時読まれなければ dispatch が成立しない新規命令) のいずれにも当たらない。
- **新しい索引機構を作る** — 依頼が「既存機構を優先し、新しい汎用基盤は最小限」と定めている。
  地図と用語集で到達できるものに機構を重ねない。
- **手順書を `docs/dev-wave/` 配下へ置く** — そこは dev-wave の運用契約の正本であり、
  CC 調査のドメイン手順の置き場ではない。被覆不変条件と層予算の対象にもなる。

## {{D:diagnostic-prescreen-splits-value-from-readiness}}. 診断手順の事前選別は「調査価値」と「実行準備」を分け、調査価値を先に評価する

**決定:** 計算資源を使う前の事前選別は、対象ごとに 2 つを別々に返す。

1. **調査価値** — この機構を調べる価値があるか。根拠は実装事実だけに置く。
2. **実行準備** — いま何を実行できるか。足りない入力・計器は何か。

**調査価値を先に評価する。** 実行準備を先に見てはならない。

**理由:**

- 混ぜると、計器が配線されていないことが調査する価値が無いことにすり替わる。それは全対象が
  同じ結論になる恒真な手順であり、全件保留でも「手順を使った」と報告できてしまう。
- 初回の利用では、抽出元を除く対象 9 件すべてで計器が未配線だった。実行準備を先に見ていれば
  除外理由が 1 件も現れず、手順は何も言えなかった。除外理由は調査価値を独立に評価したときにだけ現れる。
- **判定値に「未確認」を置き、あり / なし の二値を強制しない。取得順序と解決機構については
  「未確認」を既定とし、機構の存在と全待ち経路の被覆を別の欄に書く。** 初回の利用は、
  9 件すべてを誤って除外した。内訳は、順序付けの呼び出しを見つけたことを「順序あり」へ変換したもの、
  保持したまま待つ経路を見落としたもの、対象外の経路を対象全体の除外へ広げたものの 3 種で、
  段 6 の敵対レビューと fix 後の焦点再レビューが 2 巡かけて反例つきで倒した。
  **二値を強制する手順は、覆いを確かめていない箇所に誤った確信を書かせる。**

**却下した選択肢:**

- **配線されていない対象を最初に落とす** — 安いが、落とした対象について何も言えない。
  次に誰かが同じ対象を調べるとき、同じ読解をやり直すことになる。
- **判定を あり / なし の二値にする** — 表は読みやすくなるが、読解で確定できなかった欄が
  断定に化ける。
