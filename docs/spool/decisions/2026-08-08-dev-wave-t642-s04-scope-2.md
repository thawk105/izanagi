## {{D:dw-s04-acceptance-not-exempt}}. 実装差分ゼロの wave で免除するのは変異 matrix だけとする

**決定:** `DW-S04` の射程を「免除は実装差分ゼロの『実装しない』裁定の変異 matrix だけ。受入全走は
免除せず、実 repo を読むテストがあれば段 7 の記録前に実走し、結果を worklog へ書く」に改める。
ユーザー裁定 (2026-08-08) の実装であり、docs のみの wave にも実 repo を読むテストの検出力がある
という実測に契約を合わせる。

**理由:**
- docs のみの wave でも `check_docs` / `spool fold` を実 repo に対して走らせるテストが実在し、
  旧射程どおり受入全走を省くと、台帳と成果物索引の赤を land 前に検出できない。
- 契約文を**義務の付与**でなく**免除の否定**として書く。義務形にすると、条件節の係り方次第で
  「この経路だけの義務」または「通常経路の義務の条件化」と読めてしまい、段 6 の敵対レビュー 3 巡で
  両方向の誤読が実際に発生した。免除の範囲だけを述べる形は、どちらの反対解釈も生まない。
- 「実装差分ゼロ」を免除対象の**必要条件**として名詞句に束縛する。譲歩の「でも」や副詞の
  「ときだけ」では、限定辞が条件でなく被免除物にしか係らず、免除が通常経路へ漏れて読める。

**却下した選択肢:**
- 旧文の意味圧縮で条件を落として byte を捻出する — 予算を理由に安全義務を削る論法であり、
  そもそも合計上限を超えて実現不能だった。
- 受入全走の免除判定を機械 gate 化する — 本 wave の裁定範囲外。判定証拠の記録義務と本文 literal pin は
  ユーザー裁定へ返した。
- 旧射程を precedent として引く既存 decisions を遡及改変する — 当時の契約と実行を示す歴史記録の
  改竄になる。前向きの上書きだけを記録する。

## {{D:dev-wave-reference-self-funding}}. dev-wave reference の増分は入口との重複削除で自弁する

**決定:** `docs/dev-wave/**` の合計 byte 予算が逼迫した状態で reference に契約文を足すときは、
入口 command が逐語で持つ重複散文の削除で自弁し、予算の余白を消費しない。予算値の引き上げも、
安全義務を削る意味圧縮も採らない。

**理由:**
- 余白は並行 wave が共有する希少資源であり、先着順に食えば後続 wave が自分の裁定済み変更を
  land できなくなる。本件では 3 本の wave が同時に同じ余白を必要としていた。
- 入口と reference に同じ規範を二重に書かないという既存規律に沿う。削除した散文の規範は
  入口の 9 段状態機械が逐語で保持しており、規範は失われない。

**却下した選択肢:**
- 予算値の引き上げ — 独立審査を行わないと既に決着している。
- reference から入口への文の移送 — 入口は常時読まれる層であり、leaf 節単位の読み込み削減が
  生じないため、規範 detail の逃がし先にしない。
