## {{D:t2851-transfer-reservation}}. 未知条件への転移の事前登録 v1 — 留保条件・不使用義務・解析規則は着地時点で固定し、測定の発効は計算確認の別の決定に分ける

**決定:** `docs/unseen-condition-transfer-preregistration.md` (v1、VLDB 差分分析 P4) を次の契約で置く。

1. **留保の効力は本書の local main への着地時点で生じる。** この時点で、§2.3 の留保条件 (錨 3 点 = 学習条件の読み比率 5・50・95 の周りで
   読み比率 25・75、Zipf skew 0.7・0.99、thread 12・24、1 txn の操作数 5・20、read-modify-write を 1 因子ずつ動かす 23 条件)、§3 の不使用義務、
   §2.3 の既知別枠 (Silo の balanced × read-modify-write)、§5〜§9 の解析規則を固定する。着地以後、生成・生成のための評価・選択に関わる全ての主体は、
   留保条件・その測定結果・それらから作った指示や設定を入力に使わない。
2. **測定の発効は別の決定による。** ユーザーの計算確認 (D2212 項 4) と §13.1 の発効束 (対象探索群の名指し、全手法・全独立探索の候補凍結記録、
   MOCC の扱いの 3 択、本書の raw bytes の SHA-256 ほか) を記録した決定が出るまで、留保条件では stock を含めて 1 走もしない。
3. **推論の規則:** 同等幅 δ = ln(1.03)、1 job = (cohort, protocol, cell) に n = 32 block、主要族 (選択候補 × 強い参照 R1・R2) は
   cohort ごとの Bonferroni 同時 95% 区間で優越・退行・実用上同等・判定不能に分け、別日・別割当ての 2 cohort で同じ分類のときだけ主要結果とする。
   その job で両者の 32 block 全走が使えない組と、単独性違反の job は主要族で判定不能にする。
4. **改訂:** 着地から発効までは本文の bytes を書き換えず、追補は誤記訂正と発効束の補足だけ。留保条件の結果を 1 つでも見た後の規則変更は、
   発効前でも事後改訂として別欄に報告する。発効後は Erratum だけ (D1789)。解析器の pin・機械 gate は置かない (文書上の契約)。

**理由:**

- 留保は、探索が留保条件を使う前にしか成り立たない。T-2850 (探索の独立反復) の探索が先に走ると、留保条件で試すことを止められず留保が空になる。
  一方、測定には全候補の凍結と計算確認が要り、それは T-2850 の後になる。2 つを同じ時点にすると、どちらかが成り立たない。
- 段 3 の相談 2 本と段 6 レビューの算術: n = 8 では同等を宣言できる確率が約 18% (各腕 CV 2.28%・腕間相関 0・無補正・正規近似)、
  追試一致だけでは比較数百で偶然一致の上界が 0.39 (多重性の代わりにならない)、欠測した block を落とすと遅い走を落とした候補が優越側へ偏る
  (下位 25% の欠測で平均が約 0.42σ 上がる)。
- 既存の事前登録の作法 (B-8・B-5 の 2 段の効力、D1789 の Erratum、D1790 の版の分離) と揃える。

**却下した選択肢:**

- **n = 8 の維持、または δ の拡大** — 同等をほぼ宣言できない。δ を広げると、結果を見る前でも同等を安く買うことになる。
- **cell 単位は無補正にして、追試一致を多重性の防壁にする** — 上の算術のとおり族の誤り率を抑えない。
- **使えた block が 24 以上なら主要族で分類する** — 性能に依存した欠測で推定が偏る。
- **留保値を hash commitment で伏せる** — 依頼は具体値を文書に固定すること。本書を読める生成器は到達可能性を記録して主張を限定する方が単純。
- **8b の holdout (読み比率 80・20) を留保に含める** — 8b の floor 較正で既に測定があり、旧系列と条件が重なる。
- **留保の効力を測定の発効まで遅らせる** — 探索が先に走り留保が空になる。
- **強い静的設定を「Pegasus での格子全体の最良」と呼ぶ** — 記録は各 workload で既知の 2 者の比較だけで、格子全体を測っていない。
  本書は「学習錨で事前に選んだ既知の静的設定」と呼ぶ。
