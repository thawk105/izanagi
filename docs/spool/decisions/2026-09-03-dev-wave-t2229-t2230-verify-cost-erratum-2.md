## {{D:verify-cost-mixed-interval-erratum}}. 「直列性検査 1 回 23 分」は混合区間の所要であり、観測帯の max でもない

**決定:** D1485 と D1489、および
`output/insights/2026-09-02_paper-story-a6-certification/README.md` が引く
「直列性検査 1 回 23 分」を、次の 2 点で訂正する。**訂正は追記でのみ行い、
D1485 と D1489 の本文は 1 バイトも書き換えない** (絶対規律 7)。

1. **帰属。** この 23 分は検査器そのものの費用ではない。WAL の時刻差による**混合区間**であり、
   ベンチマーク本体 (extime 3 秒)・トレースの書き出しとスレッド終了時の flush・C 行の数え直し・
   標準出力の解析・直列化可能性検査・一時ディレクトリの作成と削除・WAL への書き込みを含む。
   どれが律速かは、この時刻差からは分離できない。
2. **積み方。** 23 分は観測帯の max ではなく中ほどである。保存されている帯は、read-heavy の
   高 commit 3 変種で 1 反復あたり 1346.9-1465.6 秒 (約 22.45-24.43 分) である。
   上端 1465.6 秒で積み直すと、D1489 が書く full-scale 10 回は 3.83 時間ではなく**約 4.07 時間**、
   `12:00:00` の倍率は約 3.1 倍ではなく**約 2.95 倍**になる。

**D1489 が定めた A-6 の `scheduler.walltime` `12:00:00` は変えない。** 積み直した 4.07 時間は
12 時間枠の内側であり、D193 の「build 後の中断 attempt は自動回復しない」という非対称性が
枠を広く取る理由として残るからである。

**理由:**

- 一次資料は `output/insights/2026-09-02_b10-trace-truncation/README.md` の
  「所要の内訳と、並列化への入力」節である。同節は所要が混合区間であることを明記し、
  「『検査器そのものの費用』ではない」と書いている。帯 1346.9-1465.6 秒も同節にある。
  D1485・D1489・A-6 insight は、この混合区間を検査器単体の費用として引いていた。
- 検算は帯の上端 1465.6 秒から行った。1465.6 / 60 = 約 24.43 分、
  1465.6 x 10 / 3600 = 約 4.07 時間、12 / 4.07 = 約 2.95 倍である。
  帯の下端 1346.9 秒は約 22.45 分なので、23 分は上端ではなく帯の中ほどに位置する。
- 誤りは 2 つとも見積りを**小さい側へ**倒す向きに働く。max と書いた値が実際には中ほどであり、
  検査器単体の費用と読むと並列化で消せる分を過大に見積もる。walltime の結論は動かないが、
  同じ数字を別の判断へ流用するときに向きが問題になる。
- canonical 3 台帳の既存 bytes は fold だけが追記でき、書き換える経路が無い。
  既存 D の訂正は追記の新エントリで行うほかない。これは絶対規律 7 の
  「過去の判定は追記でのみ訂正する」とも一致する。

**却下した選択肢:**

- D1485 と D1489 の本文を直接書き換える — canonical の既存 bytes は不変で、
  当時の判定を遡って書き換えることにもなる。
- 帯の下端 1346.9 秒で積み直す — 枠の見積りとしては向きが逆で、余裕を減らす。
- walltime を積み直した 4.07 時間に合わせて詰める — D1489 の根拠は所要見積りだけではない。
  attempt 全損の非対称性が残るので、倍率が 3.1 から 2.95 へ下がっても結論は動かない。
- 検査器並列化タスクの射程を本エントリで再裁定する — 本題の訂正の外であり、
  混合区間のどこが律速かを分離する材料も無い。記録だけを残す。
