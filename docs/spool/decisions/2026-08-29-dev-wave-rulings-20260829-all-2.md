## {{D:overengineering-axis-applies-to-rulings}}. 過剰実装抑制の軸は防御的堅牢化にだけ適用し、正しさゲートには適用しない

**決定:** ユーザーが `/rulings` に付けた軸「過剰な実装やガードレールで論文執筆を目指す研究開発を
遅滞させない」は、**実害が観測されていない一般硬化・bytes 級 provenance・監査の便宜・恒真になりやすい
機構**にだけ適用する。絶対規律 2 (正しさゲートを緩める変異を許さない)、規律 3 (正しさシグナルを
後付けにしない)、実験計画の健全性 (best-of-N の封じ、帰属可能性、事前登録の効力) に触れる項は、
この軸を理由に見送らない。

**理由:**

- 2026-08-12 のユーザー方針 (研究最優先・プロトタイプ基準、防御的堅牢化は既定で見送り) と
  2026-08-28 の 584 件見送りは、いずれも同じ線引きを既に採っている。本裁定はその線を rulings の
  推奨生成へ明示的に持ち込むだけで、新しい緩和ではない。
- 別系統モデルへの相談で、親の初版が「軸の拡大解釈で正しさゲートを緩めている」と判定された項が
  1 件あった (成功・certified 受領証の correctness 三者比較)。軸だけを見て推奨すると規律 2 を
  削る方向へ倒れることが実測された。

**却下した選択肢:**

- 軸を全件へ一律適用する — 規律 2 / 3 を運用上の選好で上書きする形になり、憲法層を戦術層から
  変更することにあたる。
- 軸を採らず従来どおり全件を個別判断する — 実害未観測の一般硬化が受入枠を消費し続け、論文の主経路が
  進まない状態が続く。

## {{D:a1-estimand-realign}}. A-1 の凍結 contrast を論文採用値の estimand へ揃え直す

**決定:** A-1 (対測定) の凍結 policy を**新しい日付版で作り直し**、比較対を 3 workload とも
`static10 − adaptive` から、**各 workload の「固定 X − backoff なし」**へ揃えてから実走する。
旧版は上書きせず凍結物として残す。

**理由:**

- 論文が報告する利得は同一 sweep 内の無 backoff 対照を分母とした workload ごとの値であり、
  凍結された contrast はこれと別の量を測っている。現行の凍結は完走しても、論文の但し書き 1
  (現行の対測定契約で測り直していない) を外せない。
- A-1 は但し書き 1 を外すための唯一の証拠であり、estimand がずれた測定は反復数を増やしても
  主張へ到達しない。
- 費用は再凍結 1 回と 610 反復 (bench 約 34.2 分) で、論文の主張に直接効く。

**却下した選択肢:**

- 論文の但し書き 1 を外すのを諦め記述的結果として報告する — 性能節が最後まで「測り直していない」と
  書き続けることになる。
- 両方の contrast を測る — 反復数が倍になるだけで、論文の主張に加わるものがない。

## {{D:a2-holds-walltime-drops-rss}}. A-2 は walltime を据え置き、正式 run に無いメモリ余裕の主張を取り下げる

**決定:** 正式 A-2 fan-out の walltime は現行 06:00:00 のまま据え置き、右寸法化の実装も追加 job も
行わない。同じ正式 attempt に束縛された rr50-stock verifier の peak RSS は存在しないため、
**「同じ正式 run に対する 32GB 余裕」という主張を取り下げる**。

**理由:**

- 6 時間枠は正式 fan-out (rr5 Elapse 3671s / rr50 3594s) が既に完走しており、縮めないと論文が
  止まるという証拠がない。
- `20.29 GB` は別 request の 1-rep calibration 由来で、正式 run の値として採用すると provenance が
  偽になる。取り下げは記録の正直さの側である。
- 再測定の 1 job は共有計算資源を消費するが、得られる数字は論文の主張に効かない。

**却下した選択肢:**

- Elapse の実測から walltime を右寸法化する — 実害が出ていない量の最適化で、変更単位と受入枠を消費する。
- peak RSS を測り直す — 論文の主張に効かない数字のために計算ノードの枠を使う。

## {{D:env-activation-keeps-a4-a6}}. 環境世代 activation は A4 と A6 を必要条件として維持し、A5 と A7 だけを置換する

**決定:** g1→g2 activation の必要条件のうち、**A4 (発行時点の exact activation bytes) と
A6 (paired freeze successor の readiness) は維持**し、**A5 (上位権限束の段 0 が complete) と
A7 (上位束の pre-X 段 1〜5 の成立) の完成待ちだけを明示的に置換または非認証化する**設計を出す。
段 6 X が人間 lockstep であること (D437) は不変。A1〜A3 は充足済みのまま。

**理由:**

- A4 と A6 は証跡の儀式ではなく、activation 後に sanctioned 経路と測定が成立するかどうかを見ている。
  外すと切替後の測定の意味が保証されない。
- A5 / A7 は上位権限束という大きな機構の完成を待つ形で、これが H1 / H2 正式実験を無期限に止めている
  本体である。段 0 の開始順と owner は D778 で既に裁定済みなので、律速は開始順ではなく機構の規模である。
- A4 / A6 / A7 の remediation owner が `unassigned` のままである点は、A5 / A7 を置換する設計の中で
  併せて解消する。

**却下した選択肢:**

- A4〜A7 を一括で「開示して受諾」に切り替える — 親の初版推奨。A4 / A6 まで外れるため、切替後に
  測定が成立するかを誰も見ない状態になる。相談が反対し撤回した。
- 全条件の充足を待つ — 論文の主経路 (B-2 / B-3) が無期限に止まる。

## {{D:holdout-projection-lands-first}}. rr80 / rr20 の production projection は環境世代切替を待たずに先へ着地させる

**決定:** 正式 H1 / H2 が使う rr80 / rr20 の projection と、campaign / completeness の consumer を、

  順序を逆にすると activation 後にさらに実装待ちが積み上がる。

**却下した選択肢:**

## {{D:b4-reviewer-is-confirming-role}}. B-4 の記入者とレビュー者は同一 identity を許し、役割定義を同じ変更単位で明記する

**決定:** B-4 事前登録 §5.1 (i) の記入者・レビュー者はいずれも `thawk105` を指名する。ただし
**「レビュー者は独立検査者ではなく、記入内容が事前登録の要求を満たすことの確認責任者であり、
独立性を要求しない」という役割定義文を同じ変更単位で §5.1 へ足すことを条件とする**。

**理由:**

- 事前登録は 2 つの役割の先行 freeze を要求するが、同一 identity を許すとも独立 reviewer を要求するとも
  書いていない。定義せずに兼任だけ書くと、後から恒真な保証と読まれる。
- 現にこの計算機で作業しているのは実質 1 名で、独立検査者を要求すると B-4 が指名不能で止まる。
- 実行責任者は 2026-08-27 に同じ identity で確定済みで、その形と整合する。

**却下した選択肢:**

- レビュー者を独立検査者と定義し別主体を立てる — 指名できる相手がおらず B-4 が止まる。
- 役割定義を書かずに兼任だけ記入する — 相談が「契約が兼任を許すか不明」と根拠不足を指摘した形のまま残る。

## {{D:t1998-authorization-returns-after-landing}}. balanced stock-inline の正式測定認可は 3 部品の着地後に改めて諮る

**決定:** D1244 が採用した最小 3 部品の実装を進める。**3 部品の着地後、正式測定認可へは自動で進まず、
着地内容を見たうえで改めてユーザーへ諮る。**

**理由:**

- 事前登録は結果を見る前に作る必要があり、着地内容を確認してから認可の可否を判断する余地を残すべきである。
- 認可を先取りすると、3 部品が想定と違う形で着地した場合に事前登録の前向き性が損なわれる。

**却下した選択肢:**

- 着地と同時に自動で認可する — 前向き性の余地を失う。
- 対照そのものを見送る — D1244 が既に実装を採用しており、既裁定と衝突する。

## {{D:paired-pilot-fixes-delta-independently}}. 対計画 pilot は検出したい差を pilot と独立に先に固定する

**決定:** 対計画用 pilot は `n` と `sd_max` の導出だけに使い、`delta_min` は pilot と**独立に先に固定する**。
既存の n-pilot (R=11、目標 R>=32 未達) は既知結果台帳へ載せ、前向き導出から除外する。

**理由:**

- 導出関数を pilot の結果から作ると、pilot が「必要反復数はこれです」と自分を正当化する恒真な形になる。
- 反復数の根拠は論文の検定力に直結し、防御的堅牢化ではなく実験計画そのものである。

**却下した選択肢:**

- 経験的に反復数を決める — 事前登録の前向き性が成立せず、失敗条件の判定がどちらにも倒せる。

## {{D:experiment-unit-blocks-best-of-n}}. 実験単位を slot 組へ改め、best-of-N を最小形で封じる

**決定:** 実験単位を `(prereg_generation, holdout, arm, replicate_slot)` の組へ改め、承認 artifact が
全 slot と個数を固定し、下流が predeclared receipt の全列挙と消費を検査する**最小形**を採る。
全世代・revocation・expiry・check registry への一般化は採らない。

**理由:**

- 現行の「試行 ID ごとの一回性 + manifest ごとの受領証」では、別々の manifest を N 個登録して良い受領証
  だけを下流へ渡す形を閉じられない。これは実験計画に対する reward hacking であり規律 2 の面である。
- 「良い結果だけ選んだのではない」は論文が必ず問われる点で、実走してから気づくと測り直しになる。

**却下した選択肢:**

- 現状維持 — 上記の穴が残る。
- 恒久一般化まで広げる — 現在の実験に必要な範囲を超え、受入枠を消費する。

## {{D:b10-preregistration-discloses-probe}}. B-10 は上限を据え置き、probe 結果を開示した新しい事前登録を作る

**決定:** physical residual probe が 1.0% exclusive 上限を超えた件について、**上限は据え置く**。
probe の 18 cell を開示した新しい日付版の事前登録を作ってから正式投入する。凍結物は上書きしない。

**理由:**

- 上限を後から緩めると、結果を見てから基準を動かした形になる。
- probe を開示したうえで、独立した将来の標本に対して上限を据え置くなら事後の緩和にはならない。

**却下した選択肢:**

- 上限を緩める — 結果を見てから基準を動かす形そのもの。
- B-10 を諦める — 機序説明が 0〜10µs 帯に閉じたまま残る。

## {{D:sort-axis-authority-and-invisible-baseline}}. sort oracle の基準を候補から不可視な場所へ移し、権威集合と同じ変更単位で入れる

**決定:** sort SWO oracle の corpus 変異検出について、**基準 snapshot を候補 comparator から不可視な
親側へ移し、そこで比較する**最小実装を入れる。`sort_best.comparator` の閉じた権威集合 (trigger 軸と同形) も
**同じ変更単位**で実装する。

**理由:**

- 基準 snapshot が候補文と同じ翻訳単位の file-scope 変数であり、corpus を壊した後に基準を再計算する候補は
  変異 witness が消えて正常終了することを実測済みである。上流の副作用禁止表は host 側しか塞がず、
  この識別子は素通りする。これは規律 2 の直撃面で、防御的堅牢化ではない。
- sort 軸だけが閉じた権威集合を持たない非対称が受理集合の穴になっており、同じ面である。
- 別々の変更単位にすると受入枠を 2 回消費する。

**却下した選択肢:**

- 現状維持のうえ限界として明記する — 変異が実際に正しさゲートを緩められることが実測されている以上、
  明記は恒真な保証になる。

## {{D:certified-receipt-requires-correctness}}. 成功・certified な受領証にだけ正しさ証拠の非空を要求する

**決定:** 受領証 schema の `correctness_evidence.minItems:0` は残したまま、**成功・certified の受領証の
ときだけ非空かつ必要な三者比較ありを要求する条件付き最小 gate** を単位 5/6 の着手時に入れる。
失敗途中の受領証の空配列は維持する。

**理由:**

- 失敗 stage を許すための `minItems:0` 自体は妥当だが、成功・certified まで正しさ側の三者比較が
  0 回で成立するのは正しさゲートの穴である。
- 条件付きにすることで受理集合を必要以上に狭めない。

**却下した選択肢:**

- 実効性の限定として記録するだけ — 親の初版推奨。相談が「規律 2 を満たさない」と反対し撤回した。
- 無条件に非空を要求する — 失敗 stage の受領証が発行できなくなる。

**却下した選択肢:**

- 見送り — activation 後に、複数 env の結果が混ざった状態で certified 選択が成立しうる。

## {{D:commit-records-launch-context-digest}}. COMMIT へ起動 context の digest を 1 field だけ残す

**決定:** 関門が検証した起動 context の digest を COMMIT 側の成果物へ**1 field 残すところまで**とする。
受理側と B-4 consumer の両側での再検証は今は実装しない。

**理由:**

- COMMIT 後に campaign lock を書き換えて名乗り直すには、そのための操作者が要り、現在それはいない。
  実害は未観測である。
- 一方 digest を残しておかないと、後から遡って束縛することができない。1 field の追加で将来の
  両側検証へ広げる余地を残せる。

**却下した選択肢:**

- 両側再検証まで実装する — 実害未観測の段階で受理集合と consumer を増やす。
- 何もしない — 事後に束縛できなくなる。
- D1033 と同型として見送る — 親の初版が挙げた根拠だが、D1033 が却下したのは下流での名乗りだけの拒否で
  あり、起動 context の束縛とは同型でない。相談の指摘により撤回した。

## {{D:mutation-prereg-separates-live-gates}}. 変異事前登録は発火しない防御と実際に効く関門を分けて数え、変異 harness だけ ignored file を見る

**決定:** 前段の相互排他的分岐で値が固定されている防御的 invariant と、独立に発火する gate を、
変異事前登録の段階で**分けて数える規律**を文書化する。機械化はしない。あわせて、**変異 harness の
入場 gate にだけ** ignored file 検査を足す。

**理由:**

- 3 点の照合のうち 2 点が単独では発火しないことを実走で確認しており、区別しないと変異検出力を
  実際より高く見積もる。検出力は論文が報告する数字である。
- 変異 harness の入場 gate は `--ignored` が無いため `*.o` / `build/` / `*.so` のような生成物と
  skip-worktree entry に盲目で、汚染 tree で得た値がそのまま台帳へ載る。変異の結果は論文の検出力になる。
- third_party の pinned-clean 判定へ同じ検査を足す案は、既存 record schema の `clean` の意味を
  上書きして旧凍結 evidence の読み方を変えるため分離する。

**却下した選択肢:**

- 数え方の機構を作る — 規律だけで足り、機構は受入枠を消費する。
- ignored file 検査を pinned-clean 側にも同時に入れる — 影響半径が床値の外へ出る。

## {{D:once-key-consumption-recorded}}. 一回性 key の消費は記録に残し、投入権限の段階分割はしない

**決定:** セル確保の後に走る非計測検査 (live admission 再検査・host provenance・process identity) の
失敗で一回性 key が焼けたとき、**消費を journal へ記録として残す**。admission authority の段階分割による
順序変更は採らない。

**理由:**

- 現状は key だけ消費されて記録が残らず、床値の再投入で実際に 1 度踏んでいる。焼けた原因が追えない。
- 順序変更は失敗系列の受理と再試行可能性を変える大きな設計で、現在の主経路から遠い。

**却下した選択肢:**

- 権限を段階分割して順序を変える — 受理集合の意味を変える。
- 現状維持 — 再投入の判断材料が残らない。

**決定:** 受入の世代数検査が独立に再導出するための外部 immutable anchor は **WAL** とする。

- 「自己整合までしか見ていない」と明記する — D863 が却下した「意図的な限界として明文化する」と同型。

## {{D:c03-c08-investigation-precedes-promotion}}. C03 / C08 は契約側の食い違いを直してから昇格の可否を諮る

**決定:** 条件 3/8 の AST 検査と実行時ギャップの精査は AI が進めてよい。**machine_checkable への昇格と
実体 artifact の発行は、契約側の食い違い (C03 の producer 条件と証拠契約の不一致、C08 が挙げる
production に存在しない entrypoint) を直したうえで、調査結果を見てから改めて諮る。**

**理由:**

## {{D:runner-digest-scope-documented}}. runner の digest は外側 runner の bytes を束縛すると明記する

- 現状のまま放置する — digest 証拠なしの certified 選択が受理されうると読める状態が残る。
