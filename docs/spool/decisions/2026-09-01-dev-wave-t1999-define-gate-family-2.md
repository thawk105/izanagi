## {{D:effectuation-witness-is-preprocess-difference}}. 効いたことの正例は前処理後 bytes の差で取る

**決定:** 要求した define が効いたことの正例検査を、**所有 TU の前処理後 bytes の差**で行う。
要求値と既定値で前処理後 bytes が異なることを要求し、無効値では向きを反転して
pinned-clean stock との**一致**を要求する。binary hash の相異は補助証拠として残し、族の一般則にしない。

**理由:**

- binary hash 相異が成立するのは、値が code へ焼き込まれる macro だけである。attribute 選択・
  branch 選択・instrumentation 選択の macro では、最適化や stock 等価実装により同一 binary になりうる。
  族の一般則にできない。
- 前処理差は、define が**供給されない・綴りが違う・cache-to-TU 写像が欠ける・条件指令へ届かない**の
  すべてで bytes が同一になる。F707 の型をそのまま捕まえる。
- **cache option 経由と compiler flag 経由の両方で成立する。** 後者は cache-to-TU 写像を持たないため、
  写像の再導出では検査できない。前処理差なら検査できる。
- 無効値では「効いていないことが正しい」ので、差ではなく stock 一致が正例になる。
  ただし**「届いていないから一致した」を緑にしない**ため、TU 到達と stock 一致を別々に要求する。

**却下した選択肢:**

- **binary hash の相異を族の一般則にする** — 成立しない macro が多数残り、そこでは正例が無いままになる。
- **patch を当てた事実を正例にする** — F707 の恒久対応が逐語で禁じている。当て方の誤り
  (pin 不一致・部分適用・revert 漏れ) が再び黙って通る。

## {{D:promotion-requires-effectuation-not-meaning}}. 昇格の条件は実効化の緑であり、意味の緑ではない

**決定:** 成果物への昇格 (certified 選択・floor・oracle・paper) の条件を次の 3 つとする。

1. 供給・実効化の節が全 domain macro について **green** であること。これは緩めない。
2. 実行側の意味の節が **red でない**こと。
3. 意味が **`unestablished`** の macro があれば、その事実を成果物へ必ず持ち越す。
   `green` と同じ欄・同じ表現にしない。未確立なし (空) と未調査 (未設定) を構造で区別する。

**理由:**

- D1198 が driver 全体へ義務づけているのは**効いたことの正例検査**である。
  「意味が green でなければ昇格させない」は逐語のどこにも無い。
- 「意味 green を昇格の必要条件にする」と、意味 witness を持たない macro を使う昇格経路が
  永久に受理されない。実測で S1 の certified selection が停止した。
  witness の同時実装は scope 外と裁定済みなので、この 2 つは両立しない。
- **正しさ防壁の弱体化ではない。** 本 wave 以前には関門が 1 つも無かった。実効化の節も意味の節も
  新設であり、以前は通っていた「define が効いていない build」と「意味が赤の測定」を新たに拒否する。
  受理集合は本 wave 以前より狭いままである。
- F718 の実害は「別の意味の値が成果物へ黙って記録された」ことである。witness を持つ macro は
  意味の節が捕まえ、持たない macro は成果物に「未確立」と明記されるので、黙って通ることはない。

**却下した選択肢:**

- **意味 green を昇格の必要条件にする** — D1198 の要求を超えて campaign を止める。
- **未確立を成果物へ持ち越さない** — 「未確立」と「確認済み」が読み手に区別できなくなり、
  D1198 の「未確立を緑と読める欄に入れない」に反する。

## {{D:gate-adapts-to-build-not-build-to-gate}}. 関門を通すために測定条件を変えない

**決定:** 関門を緑にするために、実 configure / build コマンドの引数を変えてはならない。
driver が現に渡していない macro は、その走行の domain member ではなく、関門を呼ぶ必要もない。
同様に、関門を通すために事前登録・凍結成果物を書き換えてはならない。

**理由:**

- 測定条件の関門を通すために測定条件そのものを変えるのは、**検査を通すために検査対象を変える**行為で、
  本族が是正しようとしている型と同じ形である。
- 実測で 2 度起きた。関門を緑にするため実 configure へ define を追加して測定の記述 (`CMAKE_CXX_FLAGS`
  の完全一致) を壊した例と、事前登録が束縛する driver bytes を配線で変えようとした例である。
- 事前登録は「駆動系が後から変わっていないこと」を示すために bytes を束縛している。
  関門を足すために書き換えれば、その束縛が意味を失う。

**却下した選択肢:**

- **不要な define を削除して閉包から外す** — 掃除であって義務化ではない。無効値には
  inert の正例を与えられるので、除去する理由がない。
- **事前登録を repin して配線する** — 事前登録の目的を壊す。後継発行か凍結解除の裁定が要る。
