## {{D:prereg-registers-channels-not-closure}}. 8c 事前登録は還流を「閉じた」と主張せず、運ぶチャネルの種別と結果依存性を登録する

**決定:** 事前登録文書は、世代間で運ぶ情報を 3 群 (descriptor と binding、abstract whiteboard、
critic の第二層射影) に限る閉包を規範として書く。ただし **「還流を遮断した」「閉じている」とは
書かない。** 代わりに、運ばれるチャネルの種別が離散状態・真偽値・浮動小数の診断値からなり、
それらが結果依存であることを登録する。実走成果物は 3 群以外が世代を跨いだ形跡が無いことを
検査結果として報告する。

**理由:**
- D410 の閉包は**キー集合の閉包**である。敵対レンズが情報量で数え直したところ、`G=2` で
  次世代へ渡る結果依存チャネルは、診断値を倍精度とみなすと数百 bit 規模になる。
  キー集合が閉じていることと、情報が遮断されていることは別の主張である。
- 勝ち筋の値は第二層射影の直接値からは落ちるが、critic の入力には渡るため、
  射影が運ぶ真偽値を介して次世代へ間接的に伝播しうる。「運ばない」と書くと事実と食い違う。
- 事前登録の目的は自由度を消すことであって、実装より強い保証を名乗ることではない。
  名乗れない保証を書けば、材料レポートがどの結果依存情報を使ったかを後から判定できなくなる。

**却下した選択肢:**
- 「還流は白名単で閉じた」と書く — キー集合の話を情報遮断の話にすり替える。絶対規律 3 に反する。
- 情報量の数値そのものを規範本文へ固定する — 表現形式 (倍精度か否か) と
  descriptor の bytes 長に依存し、厳密な総ビット数は現状定義不能である。
  定義できない数値を凍結すると、後続の改訂がその数値の解釈で紛糾する。

## {{D:prereg-unlock-conditions-live-in-protected-body}}. 事前登録の解除条件は保護節に置き、記入欄の値セルへ書かない

**決定:** 「この欄をいつ・何が揃ったら埋めてよいか」という解除条件は、条件契約に凍結される
規範本文側へ書く。記入欄の値セルには、記入済みの canonical JSON か placeholder 語だけを置く。
説明文・条件・空でない container を値セルへ書かない。

**理由:**
- 記入欄の**値**は条件契約の凍結対象から明示的に外されている (値の束縛は実走 manifest の責務)。
  そこへ解除条件を書くと、次世代の条件契約を作らずに blocker 文言を緩められる。
  事前登録の中核である「後から条件を書き換えない」が成立しない。
- 判定器は値セルを 3 分類する。平文の説明は不正、空でない container は**記入済み**と判定される。
  つまり「まだ埋めていない」つもりの注記が、未確定のまま記入欄の関門を通す経路になる。
- 実測では、`{"status":"未記入"}` のような一見無害な注記が記入済み判定になる。

**却下した選択肢:**
- 値セルに解除条件を書いて可読性を上げる — 凍結されない場所に規範を置くことになる。
- 解除条件を書かない — どの欄が何待ちかが失われ、次の担当が閂を取り違える。

## {{D:prereg-launch-shape-is-registered}}. 正式系列の起動形を事前登録し、配線 pilot の完了を起動条件と見なさない

**決定:** 事前登録文書は正式系列の起動形 (発効候補 commit の要件、起動側の再計算義務、
世代数の明示、manifest の全数実行、受入の順序) を規範として定める。ここに書かれていない形で
起動した実行を本系列の試行として数えない。配線 pilot の再投入は operational な別作業であり、
その完了をもって本系列の起動条件が満たされたと見なさない。正式系列の投入は別タスクとして起票する。

**理由:**
- 実測で、起動側の世代数既定値は本系列が要求する値と異なり、検証もその値を強制しない。
  文書に世代数を書くだけでは、起動時に別の値を渡す経路が残る。
- 配線 pilot は本系列とは別の workload 集合を対象とし、arm も揃っていない。
  pilot を本系列の前段と誤読すると、pilot の試行 id・結果・材料が正式 6 cell へ混入する。
- 起動形を書かないと「どの実行が本系列か」が事後の解釈になり、事前登録の意味が消える。

**却下した選択肢:**
- 起動形を runbook 側だけに置く — runbook は凍結対象でないため、結果後に書き換えられる。
- pilot の完了を起動条件に含める — 対象 workload も arm も異なるため、条件として成立しない。
