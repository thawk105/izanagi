## {{D:b4-analysis-contract-frozen}}. B-4 の分析契約は規則を凍結し、実体の生成だけを後へ残す

**決定:** D1082 の一括凍結を、次の形で実施した。

- **今この変更単位で確定するもの:** 最小重要効果の値、必要 block 数、primary outcome の演算と
  実験 verdict の関数、母集合を決める適格性述語・順序・選択関数・完全性要件・割当無作為化。
- **後に残るもの:** 母集合の実体と、それが依存する他欄 (対象 driver と軸、校正済み設定、floor)。
  実体の生成は凍結済み規則の機械適用であって、新たな凍結判断ではない。
- **禁じるもの:** 規則の外で母集合を選び直すこと、項目ごとに別の時期へ凍結を先送りすること、
  実体を見てから規則を変えること。

**理由:**
- 対象 driver が未確定であることは D1060 が既に逐語で記録しており、D1082 はその事実を
  知ったうえで一括凍結を命じている。裁定時の未見事実ではないので、実施を止める理由にならない。
- 「裁量の凍結」と「凍結済み規則の機械適用による具体化」を区別しないと、D1082 が許した
  「後から導出する」形そのものが実現不能になる。
- 段 3 の 2 レンズと段 6 の 2 レビューが、この区別を独立に支持した。

**却下した選択肢:**
- 母集合が具体化できないことを理由に凍結ごと見送る — 既知事実を理由に承認済み裁定を止める。
- 母集合の欄を規則への参照文字列で埋める — 実走前検査は値の意味も参照先も検査しないため、
  他の欄が揃った時点で中身の実在なしに関門が開く。

## {{D:b4-mie-and-block-count}}. B-4 の最小重要効果は 0.60、必要 block 数は厳密検定から 201

**決定:** 最小重要効果を確率優越 `0.60` とし、pilot を設計から外し、必要 block 数を
厳密符号検定の検出力から直接 `201` とする。最小重要効果は必要数の導出にだけ使い、
判定の閾値にしない。

**理由:**
- 対象の主張は狭い機序主張であり、大効果を主張する実験ではない。慣用的な大効果の閾値を
  この主張の重要性へ流用しない。値は既知結果・予算・算出した必要数のいずれからも導いていない。
  要求 block 数が多くなる側であり、実行可能性で選んでいない。
- block の得点は 3 値しか取らないため、pilot が供給しうる分散上限は必要数を小さくする自由度
  そのものになる。D1082 が最小重要効果を pilot から切り離した理由がそのまま必要数にも当たる。
- 標本値が最小重要効果に届いたことを成立条件にすると、真値が境界のとき成立確率が半分で
  頭打ちになり、必要数をいくら増やしても目標検出力に到達しない。
- 正規近似は厳密検定の検出力を保証しない。また tie 率 0 を最悪と決め打つと、棄却境界の
  離散性による谷 (tie 率 約 0.009 で検出力 約 0.795) を見落とす。許容する tie 率の全域を
  細かい格子で走査し、最悪で目標を満たす最小値を採った。

**却下した選択肢:**
- 大効果の閾値を採る — 必要数は減るが、主張の型と合わず、実行可能性で選んだと読まれる。
- pilot で分散上限を測る — 必要数を小さくする自由度が残る。
- 正規近似の値をそのまま使う — 厳密検定の検出力が目標に届かない。

## {{D:b4-verdict-total-function}}. B-4 の判定は入力検証を先に済ませる全域関数とする

**決定:** 実験 verdict を全域関数とし、入力検証をすべて済ませてから分岐評価を始める。
分類は既存の全件報告規則の 4 分類へ写す。事前条件違反と台帳上の違反は protocol violation、
汚染と treatment 未発火と数不足は判定不能とし、成立には片側の厳密検定だけを要求する。

**理由:**
- 検証前に値を読んで分岐すると、負の件数や不正な型が有意性の分岐まで流れ込む。
- 汚染の分類は既存の全件報告規則が「判定不能」と定めており、そちらが正本である。
- 台帳側の違反行を分析対象から外せると、違反を後続の適格行で置き換えて成立を得られる。
  違反件数を判定関数の入力に含め、1 件でも実験全体を失格にすることでこの経路を塞ぐ。

**却下した選択肢:**
- 汚染を protocol violation とする — 既存規則と食い違う。
- 違反行を分析対象から外すだけにする — 置き換えによる成立取得が残る。

## {{D:b4-primary-cell-needs-executable-path}}. 演算の欄は実行経路が実在するまで埋めない

**決定:** primary outcome の欄は、演算を実行する経路と適合検査が実在し、その所在と hash を
値として書けるまで埋めない。同じ内容を実走の前提条件へも加える。

**理由:**
- 実走前検査は値セルの型・意味・参照先の実在を検査しない。定義への参照だけで埋めると、
  他の欄が揃った時点で実装が無いまま関門が開く。
- 文面だけの分析契約で実走すると、集計の実装が文面と違っても検出できない。

**却下した選択肢:**
- 定義への参照で埋める — 上の経路が開く。
- 検査器を意味検査へ拡張する — 別の実装作業であり、この変更単位の外。
