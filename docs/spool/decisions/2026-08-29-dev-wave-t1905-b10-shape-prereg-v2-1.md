## {{D:b10-shape-eligibility-symbolic-criterion}}. 待ち方の形の登録可否は記号導出の基準で決める

**決定:** B-10 の待ち方 grid に登録する形は、**指示待ち量の期待値の μ からのずれを記号で展開したとき、
撹拌語の最上位 bit の出現率 `p` に対する `(p − 1/2)` の係数が μ そのものにならない形だけ**とする。
判定は式からのみ行い、probe の実測値も `p` の推定値も参照しない。除外できる粒度は**形の単位**だけとし、
cell の単位では判定しない。仮定 `E[r | H = 0] = E[r | H = 1] = m` は事前登録に明記する。

適用結果は次のとおり。`constant` は `E[X] − μ = 0`、`symmetric-modulo` は `(p − 1/2)(μ − m)` で
係数が抑制される、`binary` は `μ(p − 1/2)` で抑制されない。よって `binary` は登録しない。

**この基準が主張しないこと:** `p ≠ 1/2` であるとは主張しない。物理残差 probe は待機ループの
経過サイクルだけを保存しており最上位 bit の出現数を記録していないので、`p` は測っていない。
主張するのは (a) `binary` の平均が `(p − 1/2)` に無防備であること (式) と
(b) `binary` の実現平均が 4 cell で上限 1.0% を超えたこと (実測) の 2 点だけであり、
(b) の原因が (a) であるとは認証しない。

**この基準の定式化時点:** probe の結果を**見た後**である。したがって `binary` を落とす判断自体を
事前登録とは呼ばない。前向きに固定したと言えるのは、shape grid の throughput を一度も観測していない
時点で本基準と grid を固定したことだけである。事前登録では「観測済みの事実」「事後改訂」
「前向きに固定した規則」の 3 段に分けて書き、順序を入れ替えない (D1137 と同じ書き分け)。

**理由:**
- 上限 1.0% を緩めずに満たす設計を、実測値を見て cell を選ぶ形にせずに得る必要があった。
  形の単位でしか除外しないと決めれば、cell ごとの事後選択が構造的にできない。
- 基準を式の性質として書けば、`binary` の名指しではなくなる。平均 `μ/2` と `3μ/2` の 2 群を
  偏りうる 1 bit で混ぜる形は全般に落ち、`binary` はその 1 例にすぎない。
- probe が実際に測ったのは実現平均だけである。原因を bit の偏りだと認証すると、
  測っていない量を根拠にすることになる。

**却下した選択肢:**
- 上限を緩める / cell 単位の免除を作る — 結果を見てから基準を動かす形そのものである。
- 実測 deviation の値が大きい cell を落とす — 同じ理由で採れない。
- 呼び出し回数を増やして解決する — 偏りは決定論的で標本ゆらぎではないと推定されるが、
  probe は bit 数を記録しておらず決定的な証拠を持たない。設計根拠にしない。

## {{D:b10-binary-premise-scope-correction}}. 撹拌器の全単射性は有限な実行時 start 列の半々性を含意しない

**決定:** D1057 が 3 形族の根拠に挙げた「撹拌器が奇数で全単射だから最上位 bit はちょうど半々」という
論拠は、**全 2^64 の入力に対しては正しいままとし、反証されたとは記録しない。**
無効になったのは、その性質を**有限で非一様な実行時の `start` 列へ転用して物理平均の一致を保証する**
という運用上の推論だけである。この区別を記録に明記し、「全単射の定理が反証された」とは書かない。

**理由:**
- 物理残差 probe は経過サイクルだけを保存しており、最上位 bit の出現数を記録していない。
  したがって probe は `p` の値についても、`p ≠ 1/2` についても何も測っていない。
- probe が示したのは `binary` の実現平均が上限を超えたことだけである。
  そこから原因を bit の偏りに帰属させると、測っていない量を認証することになる。
- 数学的命題と、その命題を実験設計の保証として使う推論は別物である。前者は無傷で、後者だけが崩れた。

**却下した選択肢:**
- 「probe が premise を反証した」と記録する — 測っていない量を反証したことにしてしまう。
- D1057 をそのまま残す — 3 形族の根拠が現行 grid と食い違ったまま台帳に残る。

## {{D:b10-space-version-retained-on-subgrid-shrink}}. 登録 subgrid の縮小では符号化空間の版を上げない

**決定:** B-10 の登録 grid を 3 形から 2 形へ縮めるにあたり、campaign の `SPACE_VERSION` と
`TRIAL` は**据え置く**。C++ の式と符号化空間そのものは不変であり、identity の分離は
事前登録 spec の SHA と search config が担う。

**理由:**
- 式 (`EXPECTED_HOLE_LINE`)、`FORMULA_SHA256`、patch、符号化規則 `BACKOFF_FIXED=shape_code*1000+mu`
  はいずれも変更していない。変わったのは driver が発行・受理する部分集合だけである。
- 完全な spec SHA と search config が campaign identity に入るため、2 形版と 3 形版が
  同じ space version を指しても既存 campaign と衝突しない。
- 版を上げると既存の凍結成果物の指紋固定に触れる作業が増える。

**却下した選択肢:**
- `SPACE_VERSION` を上げる — 受理集合の縮小を空間の変更と同一視することになり、
  凍結成果物側の張り替えを誘発する。

## {{D:b10-preregistration-new-version-at-pinned-path}}. 事前登録の新しい版は固定 canonical path 上に作る

**決定:** D1270 が求める「新しい日付版の事前登録」は、**別 path の日付入り file を新設せず、
D1058 が固定した canonical path 上の新しい版**として作る。版の日付と改訂内容は文書の §0 に書き、
版の束縛は commit hash に持たせる。旧版の bytes は改訂前の commit に残す。

**理由:**
- D1058 は canonical な文書 path を固定し、任意の文書を指せないようにすると定めている。
  日付入りの別 file を作ると、driver がどの file を見るかを新たに pin し直すことになり、
  「任意の文書を指せない」という保証の面が増える。
- 版の識別は driver が既に commit hash と spec SHA で行っている。file 名に日付を入れても
  識別力は増えない。
- 凍結物の非上書きは満たしている。旧版は placeholder のまま発効しておらず、
  旧版を束縛した実走成果物は存在しない。probe 成果物にも触れていない。

**却下した選択肢:**
- 日付入りの別 file を新設する — canonical path の固定と両立させるには pin の追加が要る。
- 旧版を残さず上書きする — 改訂の履歴が追えなくなる。
