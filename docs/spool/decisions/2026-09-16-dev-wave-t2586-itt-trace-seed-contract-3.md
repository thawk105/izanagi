## {{D:frozen-prereg-does-not-freeze-implementation-predicates}}. 凍結事前登録が書く「この契約は変更しない」は、実装述語を永久に締められなくする条文ではない

**決定:** 凍結した事前登録文書が「投入経路の契約は変更しない」「既存の検査を改訂せずに通る」と
書いている場合、それは**その試験の実施方針の記述**であって、将来その実装述語を**狭める**ことを
永久に禁じる条文ではない。次の 3 条件をすべて満たすなら、errata を出さずに述語を狭めてよい。

1. **登録済みの入力集合が引き続き通る。** 事前登録が実際に許した値で走った run は、変更後も
   同じ受理・同じ束縛値・同じ schema を得る。
2. **凍結文書の bytes を変えない。** consumer が sha256 で束縛しているので、文書側は不変のままにする。
3. **狭める方向にだけ動かす。** 従来拒否していた入力を新たに受理する経路を作らない。

逆に、**推定量・等価域・臨界値・判定語・仮説・層・欠測規則・seed の一覧・停止規則**を変える場合は
従来どおり errata が要る。これらは文書上の要求そのものであり、実装述語ではない。

**理由:**
- 凍結の目的は、結果を見た後に判定を都合よく動かせなくすることである。登録集合の外にある入力を
  拒否する述語を足しても、登録した試験の判定は 1 つも動かない。
- 同じ文書が、改訂後の再解析を別 hash で束縛し、発効後の producer 実行と将来 cohort の別解析を
  明示的に想定している。当時の実装の可変性まで永久に凍結したとは読めない。
- 既存の正誤表は**文書上の要求を変えるとき**に errata を使った先例であって、
  「実装述語なら errata なしで何でも変えられる」という先例ではない。上の 3 条件はその区別を固定する。
- 「投入経路」を producer 全体への永久拘束と読むと、同じ producer の中の別関数だけを例外にする
  根拠が別途要る。関数名が文書に列挙されていないことは、非対称な扱いの根拠にならない。

**却下した選択肢:**
- **文言どおり読んで実装述語を一切締めない。** producer が事前登録に無い入力を受理して束縛を付け、
  offline consumer がそれを拒否する食い違いを放置することになる。正しさ証拠の一貫性を、
  凍結文書の副次的な一文のために犠牲にする。
- **errata を出してから締める。** 成果物側は文書の bytes を sha256 で束縛しているので、
  文書を触れば既存の束縛が壊れる。文書上の要求を何も変えていないのに文書を改版するのは、
  凍結の意味を薄める。
- **束縛付与だけを締め、投入は通す。** 誤った入力が build と測定を消費してから拒否される。
  実投入経路に非登録入力が到達する実例がある以上、投入前に止められるものは止める。
