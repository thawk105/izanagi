## {{D:claim-evidence-series-namespace}}. paper-story の執筆者向け作業表は別 namespace の系列にし、版と filename で混ぜない

**決定:** `docs/paper-story/` に、版 (時点ごとの凍結スナップショット) とは別の系列として
`claim-evidence/` を置く。同系列は次の規則で運用し、規則の正本は
`docs/paper-story/README.md` の「claim-evidence 系列」節とする。

1. **append-only。** 版と同じ凍結物で、書いた後は更新しない。
2. **新しい日付を足すときは、その作成時点の最新版の入力 5 節 (§3 / §6 / §7 / §8 / §9) 全体から
   作り直す。** 一項目だけを直した差分改訂を新しい日付として置かない。
3. **「版の履歴」表には登録しない。** どちらが全面再導出された版かは**ディレクトリで判別する。**
4. 数値・日付・判定の出所は一次資料だけとし、版の記述を数値の出所にしない。

**理由:**

- 版と同じ日付が既に存在する日に作業表を足すと、filename が衝突する。suffix を付けて
  同一ディレクトリへ置く案は、**「これは版ではない」を文書の自己申告だけに負わせる**ため、
  同形式の部分導出物が増えたときに「どれが全面再導出された版か」を filename から判別できなくなる。
- 版の運用契約は「新しい日付の版は、その日付時点の正典全体からの導出でなければならない」と
  定めている。作業表は主張ごとの対応表であって時点の物語ではないので、この契約をそのまま
  適用すると意味が合わない。かといって「別種だから規則外」と自己申告で例外化すると、
  例外の射程が文書ごとに変わる。ディレクトリで分けて系列ごとの規則を README に持たせれば、
  例外を作らずに両方の契約が成立する。
- 規則 2 を系列側にも課すのは、版と同じ理由による。更新しなかった項目の stale が
  「その日付時点でそう主張した」という新しい嘘に変わるのを防ぐ。

**却下した選択肢:**

- 同一ディレクトリに suffix 付き filename (`2026-08-26-claim-evidence-matrix.md`) で置く —
  版か否かを本文の自己申告に負わせることになり、上記の判別不能を招く。
- `output/reports/` へ置く — 同ディレクトリは campaign の成果物と材料レポートの場所であり、
  論文の主張と一次資料の対応表は `docs/paper-story/` の入力 5 節に強く依存する。所在が離れると
  「入力の最新版から作り直す」という規則 2 の運用が保てない。
- README にポインタを 1 行足すだけにする — pointer は生きるが、指し先がどの契約で正しいかが
  定まらない。新しい artifact 種別を足すときは lifecycle を同時に定義する。

**研究状態への影響:** なし。certified 選択・材料レポート・3 台帳の値・受理集合・参照を
1 つも変更しない。変わるのは論文執筆時に参照する導出物の置き場所と、その系列の凍結規則だけである。
