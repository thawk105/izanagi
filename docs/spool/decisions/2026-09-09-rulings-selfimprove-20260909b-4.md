## {{D:r17-origin-trial-caller}}. 起点試行の公開呼び手は置かず、report が完了しない分岐だけ先に直す

**決定:** `run_origin_trial` の production 呼び手を今回は置かない。completeness の origin 分岐
(物理 search config の origin key を exact key gate が許さず、rejected build が完了条件を満たさない件)
だけを先に直す。fixture provider の real build 拒否の解除、`--no-build` 経路の変更、世代制約との整合の
3 件は、D114 が定めた承認済み generation 予算 1 と、未解決のままの還流設計 (D106 残余 1) の整合が
決まるまで着手しない。

**理由:**

- 呼び手を置いても発行器へ到達する経路が無いことは実測済みである。分岐だけ直しても呼び手は到達しない
  ので、呼び手の追加自体を後段へ送る。
- 起草推奨は承認上限を D106 の所在としていたが、`MAX_APPROVED_GENERATIONS = 1` を定めたのは D114 で、
  D106 側は実装上限である。別系統モデルの相談が誤引用を指摘し、現物で確認した。
- 残る 3 件はいずれも測定 build の経路か承認上限に触る。1 つの変更単位で両方を動かすと変異の帰属が取れない。

**却下した選択肢:**

- 4 件すべてを scope に含める — 測定経路と承認上限を同時に動かす。
- 分岐だけ直して呼び手も置く — 到達しない呼び手を production へ置くことになる。

## {{D:r17-group-receipt-reaccept}}. 公開済み group receipt の再受理は exact にせず非保証として明記する

**決定:** published group receipt の再受理検査を exact 化しない。現状 (`certified_requests` だけを見て
件数・claim limitations・未認証 marker・各 row の状態・`trace_dir` を確認せずに削除へ渡す) を維持し、
**保証しない範囲として明記する**。

**理由:**

- 実害の観測がない。認証の受理形を 2 cell から 4 cell へ広げたことで露出は増えたが、事故は起きていない。
- 同型の D1656 (認証 probe の既発行 receipt 再検証と trace 削除) が「直さず非保証として明記」で決着している。
- 「仮想リスク向けの gate 追加は scope 外」というユーザーの立っている指示に当たる。

**却下した選択肢:**

- 再受理を exact にする — 実害の観測がないまま防壁を足す。

## {{D:r17-untracked-scan-timeout}}. 未追跡走査の時間切れは負荷に見合う値へ上げる

**決定:** `orchestrator/tests/test_t1259_qsub_env_delivery_probe.py` の setup が使う
`git ls-files --others --exclude-standard -z` の 30 秒 timeout を、混雑時の実所要に見合う値へ上げる。
値は据え置きの推測でなく、混雑下の完了時間を測って有界に決める。fixture の共有範囲は変えない。

**理由:**

- 単独走は緑で、他 wave の受入 session でも同じ file が赤になる。変更に帰属しない負荷の問題である。
- fixture の untracked 走査を session 単位へ寄せる案は、受入の並行性に新しい交絡を作る。
- hold 登録は赤を隠すだけで「混雑時に受入が取れない」を解かない。

**却下した選択肢:**

- 走査を session 単位へ寄せる — 設計変更で交絡が増える。
- 専用 F を起こして hold 登録する — 赤は消えるが受入は取れないまま。

## {{D:r17-k2-coder-role}}. K2 宣言 manifest の sources が非空なら coder-role を必須にする

**決定:** driver の `--run-iteration` について、`--knowledge-manifest` の `sources` が**非空のときだけ**
`--coder-role` を必須にする。空取得 (`completed_empty` / `sources: []`) の経路は現状のまま通す。

**理由:**

- K2 として記録された候補が K2 consumer (schema・anomaly・参照 index) を通らずに WAL の BUILD_START と
  certified 選択へ入りうるのは、記録と検査の齟齬である (規律 3)。
- 単純な相互必須化は、`retrieval_result.status = "completed_empty"` の既存正例を壊す。条件付き必須化は
  正例を 1 件も壊さずに閉じられる。
- Pegasus の production 経路は job body 側で既に閉じており、残るのは driver 直接起動だけである。

**却下した選択肢:**

- 現状維持 (job body だけで守る) — driver 直接起動で誤記録が作れる状態が残る。
- 無条件の相互必須化 — 空取得の正例を壊す。

## {{D:r17-static-backoff-scope-out}}. 静的 backoff が範囲外として返した 4 件のうち、語の整理だけ実施する

**決定:** 探索走が範囲外として返した 4 件のうち、**runbook の環境変数が指す「exploration campaign」と
D1813 の「探索」が別語である件の整理だけ**を実施する。B-10 job 本体への working bytes 拘束の追加と、
既存の正式 consumer への `run_kind == "extended"` 必須化は**採らない**。
**正値 `BACKOFF_FIXED` の意味 witness については、本裁定の提示後に D1859 が production 経路で
確立したため、本項の「見送り」は適用しない。**

**理由:**

- working bytes 拘束は D1658 が「B-10 job の HEAD 束縛は運用制約で閉じ、恒久修正は入れない」と
  裁定済みの同じ面である。
- `run_kind` の必須化は既存の正式 consumer の受理集合を動かす。探索走に固有の弱体化ではない。
- 語の整理は受理集合に触らず、読み手の誤解だけを消す。

**却下した選択肢:**

## {{D:r17-b4-population}}. formal B-4 の母集合は解析 manifest の 201 行とする

**決定:** formal B-4 の母集合を analysis manifest の 201 行に固定する。scheduled attempt registry の
全行は母集合にしない。manifest 外の registry 行は、hash が一致しても実行しない。

**理由:**

- 事前登録が名指した集合が母集合でなければ、「hash が一致すれば manifest 外でも実行できる」= 事前登録の
  外で標本を作れる形になる (規律 3)。
- raw record producer が後から拒否するまで build と WAL が進むのは「拒否が遅い」という別問題であり、
  母集合の定義で解くべきではない。

**却下した選択肢:**

- registry 全行を母集合にする — 事前登録の母集合が実質無効になる。

## {{D:r17-b4-publication-root}}. B-4 の事前公開は事前登録が場所を 1 つ名指しし、発行器がそれ以外を拒否する

**決定:** B-4 の prerun publication について、**事前登録が publication root を 1 つ名指しする**。
発行器はその root 以外での発行を拒否する。呼び手が実行時に root を選ぶ現状は改める。

**理由:**

- 呼び手が選べるままだと、任意の提案に対しその hash を持つ registry を別 root へ発行すれば
  bootstrap 束縛も通る。束縛が恒真になり、恒真な保証は監査対象そのものである (規律 6)。
- 現在の検査が拒否するのは「指定された組の不一致」であって「事前固定した集合であること」ではない。
- 事前登録に 1 行足すだけで閉じるので、新しい機構を作らない。

**却下した選択肢:**

- 現状維持 — 「事前固定した集合であること」を主張できないまま束縛を主張し続ける。

## {{D:r17-injected-coverage}}. 閉包検査の注入経路は、弱い一致を被覆済みに数えない

**決定:** 閉包検査の `injected-*` 特殊経路について、「sink の直後に名前の suffix が一致し第 1 引数が
sink の代入名である call が 1 つある」だけでは**被覆済みに数えない**。この形を fail-closed 側へ寄せる。
族全体に効く共有機構の変更なので、`{{D:r17-minimal-form}}` に従い名指しした判定だけを変える。

**理由:**

- 起草推奨は「被覆済みと数える」という文言を「被覆の候補が 1 つある」へ弱めるだけだったが、
  F918 は拒否を握り潰す変異が閉包検査を通ることを実測しており、仮想リスクではない。
  文言を弱めても、deferral を外せる穴はそのまま残る。別系統モデルの相談が指摘した。
- 恒真に近い判定を「被覆済み」と名乗るのは規律 6 が疑えと定めた形である。

**却下した選択肢:**

- 文言だけ弱める (起草推奨) — 実測された穴が残る。
- import の真正性・shadow・支配関係まで静的に検査する — 族全体へ及ぶ新機構で、最小形を超える。

## {{D:r17-condition-evidence-binary}}. 条件 evidence は binary 同一性へ束縛せず、保証限界として明記する

**決定:** 条件 evidence を実行 binary の同一性へ束縛する新しい関門を作らない。
「条件 evidence は要求した測定条件が供給され実効化したことだけを言い、その条件で建った binary で
あることは言わない」を保証限界として成果物へ明記する。

**理由:**

- 注入 seam を持つ driver 全体に共通する性質で、配線前から存在する。実害の観測がない。
- D1674 (evidence writer の権限分離は作らず運用前提を保証限界として明記する) と同型である。

**却下した選択肢:**

- binary 同一性へ束縛する関門を作る — 注入 seam を持つ driver 全部へ波及する。

## {{D:r17-source-closure-transitive}}. enforcement source closure は推移閉包へ向けて段階実装を続け、保証の文言は閉じるまで広げない

**決定:** enforcement source closure の収載範囲を現行 63 で終端しない。**D1075 が定めた推移閉包
(発行器起点を含む候補 165) を目標として段階実装を続ける**。同時に、閉包が閉じるまで
「certified 経路が source-bound である」を推移閉包の意味では名乗らない。段階のどこまでを次の
変更単位に含めるかは実装 wave が決めてよいが、名乗りを先に広げてはならない。

**理由:**

- **起草推奨は「現行 63 のまま据え置く」だったが、これは D1075 の「certified 経路が束縛する材料の
  集合を、委譲先まで含む推移閉包へ広げる」というユーザー裁定と正面から矛盾する。** 別系統モデルの
  相談が指摘し、D1075 の本文で確認した。D1075 は「実装は段階的でよいが、保証の文言は閉包が
  閉じるまで広げない」とも定めており、本決定はその継続である。
- 実測 (反実仮想 10 か所で受理判定が変わった例 0 件) は据え置きの根拠にならない。手元の 50 campaign は
  すべて拒否され、受理へ抜ける経路が実行されていないため、0 件は弱い証拠である。
- 候補集合が収載 tuple 起点で作られているため、認証成果物を発行する module 自身が集合の外にある。
  発行器を束縛しない限り D1075 が挙げた穴 (正しさ防壁自身が束縛されていない) は閉じない。

**却下した選択肢:**

- 現行 63 で据え置き、名乗りだけ実態へ合わせる (起草推奨) — D1075 の既裁定を実質的に取り消す。
- 一度に 165 へ広げる — 段階実装を認めた D1075 の枠を超え、全 wave の段 1 閉包検査を一度に重くする。

## {{D:r17-wal-gaps-disclosed}}. WAL の欠落・読取例外・未終端 tail は fail-closed にせず開示のまま扱う

**決定:** WAL の欠落・読取例外・未終端 tail を fail-closed 化しない。現行どおり
`incomplete_slots` または `wal_read_error` を立てて開示する形を維持する。

**理由:**

- D1839 が実測で「これらの経路では見て分かる別物の report になる」と確定しており、D1772 が名指しした
  「件数と tag が揃って同じ判定の report が出る」穴には当たらない。
- fail-closed 化は受理集合をさらに狭め、欠測を含む正常な部分結果まで捨てる。

**却下した選択肢:**

- fail-closed 化する — 誤判定の危険は下がるが B-10 の標本が落ちる。
