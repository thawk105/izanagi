## {{D:knowledge-rich-synthesis-default}}. 合成の既定を「プロジェクト蓄積を含む知識あり」にし、知識の遮断を防壁から実験条件へ移す

**決定 (ユーザー裁定):** 合成・選択に関わる各段が参照してよい知識の範囲を、workload descriptor
とも人間の方針ヒントとも別の入力条件として宣言し、**既定を K2 (プロジェクト蓄積を含む知識あり)
にする。** Web、公開文献、他の CC の設計と実装、Izanagi 自身の roadmap・設計判断・進捗文書・
insight・過去 variant・評価結果・失敗と差なしを含む試行台帳を、宣言した範囲で合成と選択に
使ってよい。水準は次の 3 段とする。

- **K0 — 外部取得の遮断:** その実験の実行に必要な最小射影だけを渡す
- **K1 — 外部一般知識あり:** Izanagi 自身の過去の試行結果に依存しない知識を参照してよい
- **K2 — プロジェクト蓄積を含む知識あり:** 自分の過去の試行錯誤であることを理由に除外しない

水準が指すのは知識の量ではなく、**宣言した外部取得と投入の範囲**である。LLM が学習済みに持つ
一般知識はどの水準でも消えないので、K0 を knowledge-free と呼ばない。

**リーク制御を 2 つに割る。** 評価の中立性を守るもの (評価器へ判定や online 情報を渡さない。
D12・D21) は防壁として不変である。合成側が知識を見ないことを守るものは既定の防壁ではなく、
宣言した知識水準で決まる実験条件とする。リーク制御が固定するのは「常に知識を遮断すること」
ではなく、各アームが宣言した知識水準と入力集合の外から情報が入らないことである。

**既存の構造遮断は撤去しない。** D39 決定 7 の内容契約 (coder は filesystem を辿る経路を持たず、
勝ち筋の literal を読めない — 実装は `tools: []` と射影入力)、D45 の planner Read 剥奪、
D47 の軸提案側の入力境界、C5 の帰属遮断は、K0/K1 と既存事前登録が要求するアームでそのまま用いる。
K2 で変えたのは、この遮断を**全アームの既定**として課すのをやめ、宣言した知識水準で決まる
実験条件にした点だけである。

**主張の境界。** 知識を参照してよいことと、参照した知識で何を主張してよいかは別である。

- 候補を **de novo / 既知結果に条件づけられた派生 / 再現・選択** の 3 つに分類し、後の 2 つを
  新しい軸の発見と LLM 固有成果の受理集合から外す。**別の bytes であることは de novo の証拠に
  ならない** — 既知の勝ち筋は S-1 凍結台帳に値ごと収録してあり、意味を保った書き換えは別
  identity を持つ。D47 が「既出軸名や骨格を入力して再提案させたものを発見に数えない」と定めた
  境界は、K2 でも解除しない。
- 「参照を許した範囲」と「実際に投入した知識源」を分けて記録する。repo 内資料は commit と path
  または artifact identity で、Web は URL と取得時点に加えて取得内容の digest または snapshot
  identity で proof chain に結ぶ。Web の内容は可変なので、URL と時刻だけでは後から再検証できない。
- **certified を 2 段に分ける。** 個々の候補が正しさ・identity・性能のゲートで得た判定は、
  知識源が束縛されていなくてもそのまま有効である。一方、**K2 を条件とする certified な最終選択**は、
  宣言した知識水準と実際に投入した知識源が campaign と材料レポートの proof chain に結ばれるまで
  主張しない。何を見て選んだかを再検証できない選択は evidence-bound ではないからである。
- 最初に回す K2 は pilot として比較集合から除外する。K0/K1 との比較を主張するときは、新しい
  holdout で K2 を含む全アームを事前登録して再走する。pilot の結果を見てから対照の設計を決めない。
- 階層 3 (LLM 固有の主張) の比較は、同じ知識水準・同じ corpus・同じ retrieval 結果・同じ試行予算で
  行い、既知候補をそのまま引く lookup 対照を置く。

**凍結事前登録との関係。** `docs/phase3-main-experiment.md` は bytes を変更せず、**射程も縮めない。**
同文書は後続段 4 以降の coder の性能主張すべてを拘束する事前登録である。K2 の性能主張はこれに従うか、
別実験として新たに事前登録して旧登録の主張としては報告しないかのいずれかとする。同文書が凍結した
主張 S と S-3 の C5 帰属遮断は、当時の操作変数と判定を含めて歴史的記録として保存し、既定が K2 に
なったことから遡って読み替えない。C5 は凍結された diagnostics の束全体 (数値だけでなく文章の
機序帰属を含む) を空にする単一差分であり、K0 一般と同一視しない。

本決定は roadmap の協議改訂 (§1 の入力契約と主張の階層、§2 の入力図とシステム合成要件) を伴う。
`docs/roadmap-history/README.md` の類型判定では協議改訂に当たるので、版は上げず history へ凍結せず、
本エントリは改訂の追跡ではなく独立した設計判断の記録として書く。

**理由:**

- ユーザーが 2026-09-02 に、Web 検索および repo に蓄積された試行錯誤の知識を見てよい形へ変更し、
  知識なしより容易な知識ありの側から実現するよう直接指示した。知識を断つほど自動合成は難しく
  なるので、到達可能な側から取るのが段階導入 (絶対規律 5) に沿う。
- D568 は同じ論法で人間の方針ヒントを許可したが、roadmap の全面再定義は「まず最小拡張 1 本を
  実装・観測してから」として却下していた。実装 (`policy_hint`) と投入経路は存在するが、
  `output/campaigns` 配下に記録は 1 件も無く、context 出力と実 iteration の provenance 束縛も無い。
  観測は未達のままだが、今回のユーザー直接裁定がこの待機条件を supersede する。未達である事実は
  隠さず、上の主張境界で扱う。
- 知識の利用可否は、評価器・システム・LLM 固有寄与・無人自律という主張の強さではなく、各主張を
  得た入力条件である。既存 4 階層を保って知識水準を付記すれば、到達目標を壊さずに比較可能性を保てる。
- 遮断を一律に「防壁」と呼んでいたことが、既定と実験条件の混同を生んでいた。評価の中立性と合成側の
  知識遮断は守る対象が違うので分ける。
- 外部由来の知識をデータとして扱い、出典を付けて渡す形は D1215 に先例がある。K2 の知識入力の信頼
  境界はこれを引く。絶対規律 6 は解除しない。

**却下した選択肢:**

- **K0 を既定のまま残し K2 を任意拡張にする** — 容易な側から実現するというユーザーの直接指示に反する。
- **roadmap の究極目標と主張の階層を hint-conditioned synthesis へ全面的に書き換える** — 知識水準は
  入力条件であって新しい主張階層ではない。書き換えると評価器・システム・LLM・無人自律の切り分けを失う。
- **既存の構造遮断と C5 を撤去する** — 対照を失い、凍結済み事前登録にも反する。
- **知識源の許可リストや機械的な leak 判定、既知候補との類似度 gate を初手から新設する** — 効果が
  未実証の段階で分類機構を足すのは絶対規律 5 に反する。まず provenance と主張境界を必須にし、
  実測で曖昧さが律速になった場合にだけ追加機構を判断する。**D568 を同型の先例として引かない** —
  同 D が却下したのは信頼される人間の方針ヒントに対する leak 判定・許可リストであって、
  外部由来の知識源や類似度 gate は対象外である (段 6 レビューが一次資料との食い違いを指摘した)。
- **束縛が実装されるまで K2 の走行を一切 certifying でないと宣言し、個々の候補が得た gate verdict
  まで無効とする** — 正しさ・identity・性能のゲートは知識水準に依存せず働くので、候補単位の判定を
  無効にする理由がない。無効にすると、到達可能な側から実現するという今回の裁定を実質的に塞ぐ。
  **止めるのは K2 を条件とする certified な最終選択の主張**であり、これは上の「主張の境界」で
  proof chain 束縛まで保留すると決めた (候補単位の判定と最終選択を分けたのが本決定の要点である)。
- **凍結事前登録を「その実験固有」と再分類する** — 同文書は自らの射程を後続段 4 以降の coder 性能
  主張すべてと定めており、bytes に触れないまま意味だけ狭めるのは事前登録の差し替えに当たる。
