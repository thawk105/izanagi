## {{D:b4-reference-tps-finite-decimal}}. 非有限十進の `reference_tps` は、凍結側改訂を証拠不在で却下し、registry を狭める実装はユーザー裁定を待つ

**決定:** D1344 の実測を行った結果、次を確定する。

1. **凍結された消費側を改訂して exact ratio を受け取れるようにする案は採らない。**
   これを支持する production 証拠が 1 件も無い。正当な非有限十進の upstream 出力は、
   実在せず、記録されておらず、記録から再構成もできない。
2. **registry の受理値域を有限十進有理数へ狭める実装は、本裁定では発効させない。**
   D1344 が文面で求めた「予定されている scheduled input の列挙」は、production では
   母集合が空だからである。空である理由は、`B4ScheduledAttemptInput` を祖先 certified
   snapshot から構成する producer が存在しないことであり、これは D1344 の裁定時に
   見えていなかった。狭めるか待つかはユーザーが決める。
3. **丸めて受理する案は引き続き採らない** (D1344 が絶対規律 2 違反として却下済み)。
4. 狭める実装を行う場合の拘束を先に固定する。
   - 述語は「既約分母から 2 と 5 を除いた残りが 1」とし、raw-record producer の
     十進 token 化が受理する数値集合と一致させる。
   - 置く層は「registry の封印時のみ」か「registry と manifest の codec も含む」かの
     択一であり、実装 wave が明示して裁定する。**前者と説明しながら後者を実装しない。**
   - 事前登録 §5.1.1 の純関数契約・判定順序・`reference_value_domain_error` の意味は
     変えない。有限十進の制約は実走前 registry admission の別層として書く。
   - adapter と contract が共有する単一変換権威へは述語を置かない。
     置くと分析入力の値域の意味までずれる。
   - **既存の変異検査 M12 を registry 拒否期待へ単純に移設してはならない。**
     registry で先に拒否すると producer の十進 token 化へ到達しなくなり、
     丸め禁止の分岐を一切検査しない恒真な保証になる。producer 側の直接検査へ
     再定義して防壁を維持する。絶対規律 2 に直接触れる。

**理由:**

- 択一を決める材料は production の値域であり、それは測れた。`reference_tps` が指す量
  (certified snapshot の session-level throughput) の記録を、この user が読める
  data filesystem の全域で数えて 443,911 観測、非有限十進 0 件。実在する封印済み
  registry の exact 比を wire 形のまま数えても 2,010 値で 0 件だった。
- 凍結側を改訂する費用は、何も生産しない値のために払うことになる。
  受理集合を広げる変更でもあり、狭める側が受理集合を縮めるだけなのと対称ではない。
- 一方で、D1344 が指定した母集合そのもの (予定された scheduled input) は production では
  空であり、空集合を「0 件」と数えるのは恒真化である。狭める実装を実測の結論として
  自動発効させると、測っていない集合を根拠に受理集合を縮めることになる。
- M12 の扱いを先に固定するのは、受理集合の縮小が別の層の防壁を静かに恒真化しうるためである。
  縮小そのものは規律 2 に反しないが、防壁の消失は反する。

**却下した選択肢:**

- **凍結側を改訂して exact ratio を受理する** — 支持する production 証拠が 0 件。
- **実測の結論として狭める実装を自動発効させる** — D1344 が指定した母集合は空であり、
  その空集合を根拠にできない。
- **丸めて受理する** — 受理集合を広げ、凍結側が受け取る値を元の値と別物にする。
- **producer が実装されるまで一切記録せずに閉じる** — 測れた値域と、凍結側改訂に
  証拠が無いことは、producer の有無に依存しない確定事実である。
