## {{D:r17-budget-tiny-positive}}. 8c 予算 consumer の極小正値の領域は閉じない

**決定:** 総上限・arm 上限・holdout 上限・予約が極小の正値でも `held` になる領域を閉じない。
最低予約量の導入も、正式 workload の事前コスト計画との結合も行わない。

**理由:**

- どちらも事前登録の規範に無く、実装が決めると D1832 が避けた「権威のない仕様」になる。
- 極小正値が `held` になること自体は事前登録の述語を満たしている。実害の観測もない。

**却下した選択肢:**

- 最低予約量を実装が定める — 事前登録より強い条件を実装が発明する。

## {{D:r17-prereg-11-3}}. 事前登録 §11.3 は D1641 が覆う範囲を追記訂正で反映し、覆いを確かめられない 2 点だけ授権を要する

**決定:** 事前登録 §11.3 が担当者の指名と採用証拠の受理をユーザー手番として列挙している部分は、
**D1641 決定 1・2 の反映として AI が追記訂正してよい**。追加の授権は要らない。
対象集合と統計関数の 2 点については D1641 が覆っているかを確認できていないため、
確認の結果覆っていなければ、その 2 点だけを改めて裁定へ返す。決定の効力は変えず追記でのみ訂正する。

**理由:**

- D1641 が担当 3 者を `thawk105` 名義の AI 委任とし、採用裁定も委任下の AI が行うと既に決めている。
  §11.3 が古い文言のまま残ると、同じ書面の中で担当が 2 通りになる。
- 起草推奨は 4 点すべてに追加授権を求めていたが、別系統モデルの相談が「D1641 の既裁定の反映であり
  新規授権ではない」と指摘した。範囲を確認できた 2 点についてはその指摘を採る。
- 確認できていない 2 点まで既裁定として扱うと、覆っていない場合に無授権の変更になる。

**却下した選択肢:**

## {{D:r17-cleanup-allowlist}}. 掃除実行の変更許可一覧は機械強制せず、規律と敵対監査のまま運用する

**決定:** `/cleanup-branches` 実行中の変更許可一覧を機械で強制する経路を作らない。
信頼できる非モデル起動器・OS 水準の閉じ込め・attestation のいずれも新設しない。

**理由:**

- 成立には lifecycle を開始終了する信頼できる起動器と、Bash・Write 系・MCP・子・既存 process を
  同じ閉じ込めへ入れる基盤が要る。主目的 (CC 自動合成) の主経路から最も遠い層である。
- それを作っても D387 / D1128 の限界 (検証器と被検証対象を同じ主体が変更できる) は残る。
- 逸脱の実害が示されていない。

**却下した選択肢:**

- 機械強制を実装する — 過剰実装であり、限界も残る。
- モデルの自己申告 marker で代替する — 同じモデルが申告を省けるため恒真になる。

## {{D:r17-no-gitignore-codex-worktrees}}. `.codex/worktrees/` は除外設定へ足さず、対象 path を明示する規律で守る

**決定:** `.gitignore` へ `.codex/worktrees/` を足さない。主 checkout で `git add -A` を打たず、
対象 path を明示して stage する規律で再発を防ぐ。

**理由:**

- D1797 が理由を明記している。除外設定で隠すと、変異 harness が走行前後で bytes 一致を要求する
  共有 checkout の `?? .codex/worktrees/` 行が消え、F599 の既裁定と衝突する。
- 2026-09-08 の gitlink 混入は実害だったが、原因は除外設定の不在ではなく主 checkout での `git add -A`
  である。原因側の規律で塞ぐのが最小形である。
- 2026-09-08 に一度「足す」で承認が出たが、その後 D1797 が観測面との衝突を理由に手番を戻していた。
  本決定はその差し戻しに答えるものである。

**却下した選択肢:**

- 除外設定へ足す — 変異 harness の観測面を同時に設計変更しないと全 wave の変異走行が止まる。

## {{D:r17-next-tasks-boundary}}. repo 内 command になった next-tasks の編集境界を 4 点で確定する

(2) 本文の「本ファイル (repo 外)」という文言を消し、`/work/1/SFC/tanab/scripts/` の絶対 path 依存は

## {{D:r17-guard-heavy-interpreter}}. 重い実行の検出は、既存 parser が取り出した内側の実行対象へ再帰的に当てる

**決定:** `hooks/guard_bash.py` の重量 interpreter 検出について、**既存の script-executor parser が
抽出した内側の実行対象へ、同じ重量判定を再帰的に適用する**。wrapper module の列挙追加はしない。

**理由:**

- 起草推奨は `cProfile` / `profile` / `coverage` などの列挙追加だったが、これらは既に
  `_SCRIPT_EXECUTOR_MODULE_OPTIONS` と `_script_executor_targets` に列挙されている。列挙は問題ではなく、
  抽出した内側の対象へ重量判定を当てていないことが問題である。別系統モデルの相談が指摘し、現物で確認した。
- 列挙追加では次の wrapper で再発する。再帰適用は既存の抽出結果を使う局所修正で、新しい判定軸を作らない。
- 2026-09-09 に login node で 172 秒の走行が 1 回素通りした実測がある (load 17/96 で実害はなし)。

**却下した選択肢:**

- wrapper module の列挙を足す (起草推奨) — 既に列挙されており、素通りは列挙の不足ではない。
- 判定軸を allowlist へ反転する — 正当な `python -m` の利用を広く拒否する側へ受理集合が動く。

## {{D:r17-remote-check-timeout}}. 遠隔検査へ追加の時間切れは入れず、実際の停止例を再訪条件にする

**決定:** 遠隔検査の ssh 呼び出しへの個別 timeout と head 側の総 timeout を**入れない**。
現状の hard bound が割当時間だけであることを保証限界として明記する。
再訪条件は、遠隔検査が実際に停止して資源を占有した例が観測されたときとする。

**理由:**

- 起草推奨は「入れる」だったが、ハングや資源占有の実例が無い。別系統モデルの相談が
  「実害の観測がないのに防壁を足す側」と指摘し、これは本回の判定基準に反する。
- 割当時間という上限は現に存在しており、無限ではない。

**却下した選択肢:**

- 個別と総の 2 段 timeout を入れる (起草推奨) — 実害の観測がないまま防壁を 2 つ足す。

## {{D:r17-research-gate}}. 開発手順の研究前進関門は 2 件を採り、変異義務の限定は定義し直してから採る

**決定:** dev-wave 研究前進関門の 3 候補のうち、**段 3・6 のレンズ 1 本を過剰・削除レンズに固定する案と、
研究前進か実測欠陥の根拠が無い範囲外所見は起票せず記録のみとする案を採る**。
変異 matrix の義務を防壁・台帳・受入判定の実装面に限定する案は、**そのままでは採らない** —
「正しさ・受理・記録の証拠を変えうる実装」をすべて義務の対象に残す形へ定義し直してから採る。

**理由:**

- 採る 2 件は、過剰実装・過剰防壁を避けるという立っている指示を工程へ落とす形である。両レンズが
  「レンズ 1 本だけでは段内の土台増殖を止めない」と指摘しており、片方だけでは空回りする。
- 限定案は、別系統モデルの相談が「科学的 producer などの実装面まで変異義務から外しうる」と指摘した。
  変異義務は規律 2 の面に触るので、免除の射程を先に閉じる必要がある。

**却下した選択肢:**

- 3 件をそのまま採る (起草推奨) — 変異義務の免除が正しさ側の実装まで及びうる。
- 3 件とも見送る — 土台増殖の実害 (「次の一手」が 567 項) が残る。

## {{D:r17-b5-run-as-registered}}. 軸 B5 は登録どおり走らせ、走行前に語彙を緩めない

**決定:** 軸 B5 の実行器について、包含枝がすべて C を要求する構造を**登録どおりのまま走らせる**。
走行前の語彙 amendment は行わない。走行後に構造的不成立 (member 0 など) が出た場合は、
凍結後の事前登録は追補でしか直さない手順に従って改める。

**理由:**

- 走行前に語彙を変えるのは、結果を見る前とはいえ「都合の悪い構造を先に消した」形になる。
- 包含枝の構造は事前登録が意図したものであり、走らせて出た結果がその構造の帰結である。

**却下した選択肢:**

- 先に語彙を追補する — member は増えるが事前登録の意味が下がる。

## {{D:r17-continuation-binding}}. 継続側の提案は束縛対象外と明示する

**決定:** 実行ループの提案束縛について、**継続 (continuation) 側の提案は束縛対象外である**ことを
事前登録と成果物へ限界として明記する。耐久 carrier の新設もリーク遮断の設計変更も行わない。

**理由:**

- 登録値が指すのは block 共有の初期 proposal で、継続の提案はアームごとに異なる次の合成である。
  同じ等式を当てられないことは一次資料が示している。
- 耐久 carrier の新設は whiteboard の永続化契約を変える設計変更、リーク遮断は D39 / D45 の構造遮断に
  触る。どちらも段 4 の実験そのものを動かす。

**却下した選択肢:**

- 耐久 carrier を新設する — 段 4 の記憶構造を変えて実験の意味を動かす。

## {{D:r17-journal-schema-version}}. 自律試行 journal の `run-start` は schema 版を上げる

**決定:** 自律試行 journal の `run-start` に field を足したときに `SCHEMA_VERSION` を上げていない件は、
**版を上げて解消する**。版を上げる差分は、その版を出すが新機能を使わない構成の出力を consumer へ通す
正例を持つ。旧版の decoder は D1669 の条件 (実在成果物を確認できたとき) が成立した場合だけ作る。

**理由:**

- 起草推奨は「上げない」だったが、D1851 の却下欄が「版を上げない — 新旧 event の schema が同じ版で
  2 通りになり、consumer が区別できない」と明示的に退けている。本件はまさにその形である。
  別系統モデルの相談が指摘し、現物で確認した。
- D1849 の「schema 版は上げない」は閉じた reader を持つ t316 固有の判断であり、本件へ一般化できない。

**却下した選択肢:**

- 版を据え置き、記録済み artifact を fixture に使わない規律で防ぐ (起草推奨) — D1851 が退けた形である。
