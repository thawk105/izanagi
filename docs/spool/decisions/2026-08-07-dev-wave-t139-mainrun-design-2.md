## {{D:t139-mainrun-design}}. 本走の実験計画は起草するが投入せず、11 件の裁定へ分解して返す — 受理条件は 3 条件、区間と同時領域は同一構成、pilot 自身を D162 発火条件の充足計測にする

**背景:** 代替 X の生死確認が両 workload で成立した (D187、request `892042`、J=1 の
engineering screen)。ユーザー裁定「次は RF 統計設計に準拠した本走の設計」を受けて dev-wave を回した。
段 2 の起草子と段 3 の敵対レンズ 2 本 (統計的妥当性 / 手続き整合と実行可能性) が独立に NO-GO を
返した。一次資料 = `output/insights/2026-08-07_t139-mainrun-design/`
(裁定パッケージ本体は `package.md`、事前登録草案は `preregistration-draft.md`)。

**決定 (1): 本 wave では実装しない。** 実装差分はゼロであり、変異 matrix と受入全走は射程外である。
コード・テスト・gate・schema・artifact・凍結 bytes・certified 選択・材料レポート・proof chain・
受理集合はいずれも不変である。

**決定 (2): 受理条件は 3 条件であり、2 条件に縮めない。** primary は workload ごとに
`回復量 N > 0` かつ `劣化幅 D > 閾値` かつ `元の版までの残り G > 0` の同時信頼領域とし、
両 workload の連言 1 本を primary とする (intersection-union なので多重補正は不要)。
親 brief は `G > 0` を書き落としていた。`D = N + G` であるため 2 条件では `G ≤ 0`、すなわち
`RF ≥ 1` の stock 超過候補を排除できない。**この受理条件の正本は worklog (142) と Q9 であり、
D162 ではない** — 段 2 の引用も同じ誤りであり、段 3 レンズ B が両方を訂正した。

**決定 (3): 区間推定は同時信頼領域の ratio projection として導出し、別構成の Fieller を
二重に課さない。** 同じ標本共分散と同じ臨界値から構成すれば、Fieller 集合の `r=0` 検査は `N` の検査、
`r=1` 検査は `−G` の検査であり、「有界集合が `(0,1)` に含まれる」ことと `N>0 ∧ G>0` は**同値**である。
したがって段 2 が提案した「両者を独立に再計算し不一致を `statistical_inconsistency` として拒否する」
形は、受理集合を 1 つも縮めない**恒真な検査**になる。別々の臨界値や片側/両側規則を使えば正当な
不一致が起きるが、それを raw 破損として拒否すると偽陰性経路になる。

**決定 (4): 状態は 2 軸の閉表に分ける。** 区間の形 (`bounded` / `unbounded_connected` /
`disjoint` / `empty`) と適格性の状態 (`partial_recovery` / `below_degraded` /
`stock_exceeding_unattributed` / `boundary_ambiguous` / `weak_denominator_not_certifiable` /
`not_certifiable`) を別軸にする。段 2 は 1 軸に混ぜたため、裁定済みの状態名
`weak_denominator_not_certifiable` が他の状態と競合して exact-one にならなかった。
**空集合は有効な raw からも生じる** (分母が恒等的に 0、分子が正のとき Fieller 係数は
`A=0, B=0, C>0` となり解なし) ため、表現不整合と同じ扱いにしない。

**決定 (5): 目標効果量 `d` は 1.0 に固定し、pilot の結果で引き下げない。** 段 2 は
pilot の下側効果が小さければ `d` を下げて標本を増やす規則を提案したが、これは裁定 (142) の
「d=0.5 の約 42 cluster を最初から払う必要はない」と逆方向であり、**結果を見て費用裁定を
書き換える経路**である。下回る場合は `design_not_feasible` を候補・親系列の終端状態として終える。
また、正規近似の `J≈11` (成分ごと検出力 80%) と `J≈13` (全体 80%) はいずれも sanity 値であって
本走値ではない。単一の scalar `d` から `J` を一意に決めない — 6 成分の相関と区間形状で
受理確率が変わるため、pilot 母数の共同信頼集合上の最悪検出力で評価する。

**決定 (6): 着手順序は `producer → pilot → validator/consumer → 本走` とし、D162 を supersede しない。**
段 2 は「9 層を原子的に許可」、段 3 レンズ B は「新しい probe を先に取るか D162 決定 (10) を明示的に
書き換えるか」を求めたが、**どちらも不要である**。`orchestrator/qualification/contract.py` が
`env_tag: "pegasus"` と `attestation_mode: "required"` を exact 契約として既に持つため
(`[T-296]` は (162) で閉じている)、**pilot 自身を発火条件 (i)(ii) を満たす計測にできる**。
これにより `DW-G04`「条件が揃ってから機械化する」をそのまま守れ、記録項目の変更 risk も
pilot に閉じる (pilot の推定値は数値なので記録様式が変わっても使える)。
残る risk は「段階 A の記録項目が validator の要求を取りこぼすと pilot をやり直す」ことであり、
記録項目の確定を単独の裁定 gate にすることで緩和する。

**決定 (7): 実装被覆の見積りを訂正する。** 段 2 は 9 層すべてを新規と見積もり「0/9」としたが
過大である。`orchestrator/qualification/` に T-126 環境適格性のための試行台帳
(create-only・series-global)・系列 FSM・投入束縛・原子公開・identity が既に存在し、
Q10 が要求する「計測開始受領証・全 attempt の双射・親系列 ID」に構造的に対応する。
**D162 決定 (8) が禁じたのは T-126 の *artifact* を 3 arm 正例と読み替えることであって、
*コード* の再利用ではない。**再利用するか複製するかは producer 実装段の設計択一とする。

**決定 (8): 受理述語に自己申告根を残さない。** 段 3 レンズ B が、数学的には恒真でないが
**入力集合を producer 自身が選べるため意図した保証に対して恒真相当**になる項を 3 件挙げた。
受理述語には環境 attestation・allocation accounting・liveness・単独性検査を明示連言で入れ、
correctness は boolean の申告を信用せず raw evidence から再計算する。
実装時には「失敗した投入を台帳と raw の双方から落とす」「新しい親系列 ID を自己申告して
累積有意水準をリセットする」「anomaly を clean と申告する」の 3 変異を必須 kill とする。

**決定 (9): 11 件をユーザー裁定へ返す。** 分母条件の母数 (総量の比か比の平均か)、閾値 `κ_w` の値、
roadmap 例外の記録手続き、検出力目標、pilot 本数と非 pool、cluster 内反復数と実行順序、
arm 代表値、有意水準の family 割当てと候補上限、着手順序、point 総額上限、待機の数値と時間予算。
**分母条件と `κ_w` が先である。**いずれも費用を変えるか受理集合を変えるため親が独断で決めない。
特に分母条件は、`(元の版, 劣化幅) = (100, 10), (1000, 50)`、`κ = 6%` のとき比の平均は合格・
総量の比は不合格になり、**同じ raw から受理が反転する** (親が検算した)。

**却下した選択肢:**
- **裁定済みの `δ_D` を probe の実測劣化幅から導く** — 候補の結果を見てから閾値を決めることになり、
  本走を独立確認と呼べなくなる。段 2 と両レンズが独立に棄却した。
- **段 2 の `d_plan` 規則をそのまま採る** — 決定 (5) のとおり費用裁定の結果依存変更にあたる。
- **9 層 vertical slice を原子的に許可する** — 決定 (6) のとおり不要であり、
  発火条件を満たさないまま機械化する形になる。
- **D162 決定 (10) を明示的に書き換える** — 同じく不要である。条文を変えずに条件を満たせる。
- **arm 代表値を中央値で固定する** — 段 2 の推奨だが、中央値には平均用の分散式が使えず、
  段 2 自身が出した反復数と標本数の交換条件が成立しない。裁定へ返す。
- **point 単価を残高照会の差分で測る** — 照会は group 単位で、親の実測時点で gen_S に
  104 request が併存していた。差分を当該 study に帰属できない。総額上限の先行裁定へ返す。

**研究状態への影響:** certified 選択、材料レポート、proof chain、凍結 bytes、既存 gate、
受理集合はいずれも不変である。変わるのは、本走の状態が「設計待ち」から
**「起草済み・11 件のユーザー裁定待ち + 4 段階の実装待ち」**へ分解されたことと、
D162 決定 (10) の発火条件について記録されていた事実認定が **(i) のみ成立**へ訂正されたことである。
