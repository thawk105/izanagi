## {{D:lease-generation-degrade-direction}}. 解釈できない排他権 payload は空きでなく利用不能へ倒れる

**決定:** D1400 項目 11 の機序の記述を訂正する。排他権の payload に解釈できない field があるとき、
現行の helper は「誰も保持していない」へ縮退**しない**。`unavailable` を返して fail-closed する。
訂正の射程は「基準 commit の現行 helper の fresh 経路」に限る。

**理由:**
- production 入口 (`tools/wave_land_window.py` の CLI) を使い捨ての lease directory に対して実走し、
  世代 field を 1 つ足した fresh な payload に対して claim / release / status / renew の 4 操作が
  すべて `unavailable` / `lease-unavailable` を返すことを観測した。`free` は
  `acceptance.lease` が存在しないときだけ返る。
- 受入は `unavailable` を受理集合にも非ブロッキング集合にも入れていないため、旧実装は止まる。
  production 入口の受入を実走し `rc=70`、`classification=claim-state`、
  `reason=terminal-claim-state`、受領証と log の不生成、lease bytes の不変を観測した。
- 既存テストが「解釈できない fresh payload は `unavailable` を返し bytes と mtime を変えない」を
  pin しており、この挙動は偶発でなく設計である。

**却下した選択肢:**
- **記述をそのままにする** — 保留の根拠が実体と逆向きのままになり、次に読む作業者が
  移行設計を実際の失敗形と噛み合わない前提で組む。
- **「排他が開く懸念は解消した」まで広げて訂正する** — 混在しうる過去版 reader と着地ツールを
  測っていない。着地ツールは renew の失敗では止まらない。system 全体の主張には足りない。

## {{D:lease-generation-open-exclusion-by-relocation}}. 排他が実際に開くのは固定名を動かす置き方である

**決定:** 排他権の世代を、固定名 `acceptance.lease` 自体を世代付きの名前や世代 directory へ
動かす形で持たせる案は採らない。旧 reader が固定名を見つけられず 2 本目の排他権を取るため、
絶対規律 2 に触れる。

**理由:**
- 実走で、改名した場合と世代 directory へ移した場合のいずれも、他 wave の claim が
  `acquired` を返して新しい lease を取ることを観測した。
- 同じ配置でも、固定名を残したまま別 file・hardlink・companion directory・拡張属性を
  併置する形は、旧 reader の 4 操作すべてが baseline と完全に同値だった。
  **開くかどうかを決めているのは「世代を持たせたこと」ではなく「固定名を動かしたこと」である。**

**却下した選択肢:**
- **改名案を移行費用の問題として扱う** — 費用ではなく正しさの問題である。
  移行が終わっても、固定名を見る実装が 1 つでも残れば排他は開き続ける。

## {{D:lease-generation-granularity-first}}. 排他権の世代は候補より先に粒度を裁定する

**決定:** 排他権の世代の候補を比較する前に、世代が何の単位かを裁定する。単位は
取得ごと・wave ごと・main の進みごと・lease directory ごとの 4 つを比較対象とする。
D906 は署名対象に世代を含めることを求めるだけで粒度を決めていない。

**理由:**
- 粒度を先に固定すると、その粒度に合わない候補が自動的に落ちる。実測では、payload を
  1 byte も変えない導出値 (現行 payload の hash、保持者と main の hash、wave 単位、
  main 単位、lease directory の inode) はいずれも renew 間で不変かつ**再取得でも同値**だった。
  取得ごとの粒度では恒真だが、wave 単位・main 単位・directory 単位を選ぶならそれぞれの
  粒度の正しい表現である。可否は粒度の裁定で決まる。
- payload を変えずに取得ごとの粒度を満たすのは lease file の inode だけだった。ただし
  測定機では `st_birthtime` が取得できず、inode の再利用を区別する手段が無い。
  観測値は連番で振られていた。

**却下した選択肢:**
- **取得ごとを既定として候補を並べる** — 上記のとおり比較前に選択肢を狭める。加えて
  取得ごとを選ぶと、取得を持たない走行の世代が定義できなくなる。

## {{D:lease-generation-nonholding-run-undefined}}. 取得ごとの粒度を採るなら非保持走行の世代を同時に定める

**決定:** 排他権の世代を取得ごとの粒度で定めるときは、排他権を保持しない走行の世代を
同じ裁定の中で定める。定めないまま署名 schema へ値を入れることはしない。

**理由:**
- 待ち行列を廃止した現行運用では、他 wave が排他権を保持していても受入は進む。その走行には
  取得が無い。
- 保持している走行は受領証を出す前に保持状態を再確認し、保持者と main の一致と最小残量を
  要求する。**保持していない走行はその確認が丸ごと飛ぶ。**
- しかも受領証へ載る保持者の識別子は、排他権から読むのではなく wave 名の hash として
  その場で合成される。着地ツールも同じ関数を独立に計算して等しいかだけを見る。
  したがってこの識別子は wave 名の純関数であり、**排他権を保持したかどうかの情報を持たない。**
  着地側の照合は保持に関して恒真である。
- 世代を受領証へ足しても、wave が手元で合成できる値である限り同じ構造が再生産される。
  D906 が却下欄で名指しした「署名だけを足して恒真になる」形に当たる。
- 非保持走行を着地不可とする方向は既に不採用と裁定されているため、非保持走行は残る。
  残る以上、その世代を定義しない意味論は完成しない。

**却下した選択肢:**
- **非保持走行には既定値を入れる** — 自己申告であり、恒真な関門を 1 つ増やすだけになる。
- **非保持走行では live な排他権の世代を読む** — 他 wave の取得を自分の走行の証拠として
  署名することになる。

## {{D:lease-generation-migration-cost-unbounded}}. payload 変更の移行費用は時間で上限を置けない

**決定:** 排他権 payload の schema 変更の移行費用を「TTL の 2400 秒で自動回復する」と見積もらない。
回復は他 wave による剥奪という形でのみ起き、保持者自身は回復しない。新しい実装が更新を続ける限り
旧実装の停止は無期限に延びる。

**理由:**
- 実走で 4 つの経過を測った。0 秒と 2399 秒では status / 保持者の release / 他 wave の claim が
  すべて `unavailable`。2401 秒では status が `stale`、他 wave の claim が `acquired` になる一方、
  **保持者自身の release は `unavailable` のまま**だった。2401 秒経過後に mtime を現在へ戻すと
  3 操作とも `unavailable` へ戻った。
- 影響を受ける wave の絶対数は、移行時に稼働している旧実装の数に依存するため測れない。
  時間でも件数でも上限を置けないことを、そのまま裁定の前提にする。

**却下した選択肢:**
- **TTL を上限として見積もる** — 上記のとおり保持者は回復せず、更新が続けば期限も来ない。
