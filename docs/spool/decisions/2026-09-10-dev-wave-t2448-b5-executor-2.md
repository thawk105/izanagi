## {{D:b5-executor-scope-is-leaf-only}}. 軸 B5 の実行器は leaf に閉じ、軸全体の完走を返さない

**決定:** 軸 B5 の実行器が返せるのは、leaf (1 query / 1 control / 1 venue stream) 単位の
6 完走条件の可否と証拠だけとする。**軸全体の完走述語 (部分登録 §5.2 の論理積) を評価する API を
持たせない。** `完走` / `RW3` / 軸の成熟度を返す関数を公開面に置かない。
registration preflight が作る seal は `seal_scope` に **暫定であること**を機械可読に書く —
checkpoint / resume を後から runner へ足すと runner の bytes が変わり、seal を取り直す必要がある。

**理由:**

- §5.2 の論理積は 1622 主 query・演算子 control・anchor 包含 control・補助探索・感度監査・分類・
  未解決 `要裁定` ゼロの積である。leaf 実行器はそのごく一部しか担わない。
- 「実行器ができた」と名乗れる範囲を実装の公開面で示せば、後続 wave や読み手が leaf の完走を
  軸の完走と誤読する経路が構造的に無くなる。scope の宣言だけでは同じ保証にならない。
- 段 3・段 6 の敵対検証 4 本がいずれも「この範囲を軸 B5 の実行器と名乗るのは不可」と独立に指摘した。

**却下した選択肢:**

- 軸集約器・全走入口・checkpoint まで同じ wave で作る — 先例の軸 1 実装は約 1.3 万行で、
  1 wave の実装子 2 単位では実装よりレビューと負例の整合が先に破れる。
- 範囲を狭めたまま「実行器完成」と書く — 成果物の名乗りが実態と食い違う。

## {{D:b5-unregistered-run-policy-fails-closed}}. 凍結文が定めていない運用値は既定値で埋めず、本走発行を fail-closed にする

**決定:** 期待 content type の exact 集合・timeout・User-Agent・request 間隔・retry 対象の失敗集合・
redirect の扱いは、軸 B5 の事前登録が定めていない。**実行器はこれらを既定値で埋めない。**
本走の HTTP request を発行しようとすると専用の例外を上げ、未登録の項目名を機械可読に列挙して返す。
6 条件の評価そのものは保存済み応答に対して完全に実装する。
live preflight の content type だけは閉包登録 §2.4 (b) から導けるので発行可能な実装とし、
timeout・User-Agent・間隔は既定値を持たせず呼び手が明示した値を記録へ逐語で残す。

**理由:**

- 実装子が便宜値を選ぶと、凍結後に実装者が選んだ実行契約になる。事前登録の意味が実装の都合で決まる。
- 走行の認可は人間の手番であり、認可の時点でこれらの値が決まる。それまで実行器が先に決めない。
- 通らないように作ったのではない。**登録が沈黙している面を、沈黙のまま可視化する**構造である。

**却下した選択肢:**

- 妥当に見える既定値を実行器に置く — 事後登録になる。
- 実行器側で何も検査せず呼び手任せにする — 呼び手ごとに別の契約が生まれる。

## {{D:b5-lookup-unclassified-not-rounded}}. 索引の 3 値に入らない応答は丸めず、走行を開始しない

**決定:** anchor の ID lookup 応答が `収録` / `非収録` / `不達` のどれにも当たらない場合、
**3 値のどれかへ丸めない。** `unclassified` として観測した形をそのまま記録し、
`passed=False`、`may_start_run=False` を返す。該当例は DBLP が HTTP 200・`application/json`・
`result.hits.@total > 0` を返しながら当該 DOI を持つ record が無い形である。

**理由:**

- 閉包登録 §2.4 (b) の 3 形はこの応答を覆っていない。実装が黙って丸めると、
  登録が定義していない状態が登録済みの状態を名乗る。
- どちらへ丸めても走行は止まる (fail-closed) が、**記録に残る事実が変わる。**
  実行記録は「何が観測されたか」を持つ文書であり、分類できなかったことも観測事実である。

**却下した選択肢:**

- `非収録` へ丸める — 索引は正常に応答しており、記録が「record が無い」と誤って述べる。
- `不達` へ丸める — 索引の可用性の失敗ではないので、同じく誤った記録になる。

## {{D:b5-no-unregistered-blocking-gate}}. 登録された述語に無い阻止条件を実行器へ足さない

**決定:** live preflight で観測した OpenAlex work ID が登録値と食い違った場合、
**登録値と観測値を並べて記録するだけとし、走行開始を阻止する条件にしない。**
`capacity_echo` の一致要求、control の「発火」判定など、事前登録が持たない拒否条件も同様に足さない。

**理由:**

- D1895 は「登録どおり走らせ、走行前に語彙を緩めない」と裁定した。**緩めないことと、
  登録に無い条件を足すことは別である。** 後者は受理集合を登録から動かす点で前者と同じ問題を持つ。
- 識別子の食い違いは人間が認可の時点で見るべき事実であり、記録に残せば見える。
- 規律 2 を緩めるものではない。anomaly を検出した対象を即 reject する契約は不変で、
  本決定が禁じるのは**登録に無い拒否条件を実行器が独自に足すこと**である。

**却下した選択肢:**

- drift を検出したら走行不可にする (段 2 プランの推奨) — 登録に無い阻止条件を足すことになる。
