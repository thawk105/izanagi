## {{D:stranded-artifact-triage-by-observed-breakage}}. 止まった wave の残骸は「壊れた実例」で裁き、既存 commit があるなら再実装せず回収する

**決定:** 止まった wave worktree に残った未着地差分を裁くとき、次の 3 つを順に適用する。

1. **要否は観測された破壊で決める。** 「これが無いとどの wave が実際に壊れたか」に一次資料で
   答えられないものは破棄する。着地させるものには「これが無いと何の測定・主張が立たないか」を
   1 行で書く。書けなければ破棄する。
2. **未着地の判定は commit だけでなく worktree の未 commit 差分まで見る。** branch tip が main の
   祖先で `git rev-list --count main..<branch>` が 0 でも、未着地 bytes は worktree に残りうる。
   逆に file が main に実在することは、その差分が着地していることを意味しない。
3. **同内容の commit が既にあるなら再実装せず cherry-pick で回収する。** 実装子を起こして
   同じ変更を書き直すと、原著者の provenance trailer と測定記録を失い、
   稼働 branch との二重実装を作る。

**理由:**

- 7 件の残骸を裁いた実測では、破棄 5 件のうち 4 件までが「壊れた実例なし」で決着した。
  残る 1 件は実例の有無ではなく、機構自体が偽緑の経路を持つことで決着した。
  着地した 1 件だけが、別 session root の受入全走 2 走で 18382 件中の唯一の赤という
  一次資料を持っていた。**判定基準は 7 件すべてで一意に効いた。**
- 依頼が「main が触っていない 5 file」と述べた前提は、7 file すべてが main に実在するため
  成り立たなかった。file path の有無で未着地量を測ると、判定の母集合そのものを間違える。
- 着地させる 1 件は、cherry-pick 後の blob が元 commit の blob と byte 同一で、
  main の blob が元 commit の親 blob と同一だった。**合成の余地がゼロ**なので、
  実装面の取り込みに要求される合成監査の対象となる合成が存在しない。
  再実装していれば、原著者が記録した測定と AI-Agent trailer を捨てて同じ 4 行を書き直し、
  稼働中 branch に同内容の commit を 2 本作るところだった。
- 破棄する差分にも生きている価値が混じる。midflight の文面差分は D1179 の未履行部分を
  埋めようとしており、文面が壊れているので差分は破棄したが、義務そのものは残る。
  **差分の破棄と、その差分が指していた義務の完了を混同してはならない。**

**却下した選択肢:**

- **未着地なら逐語 land する** — D720 が既に却下している。本件でも 5/7 が現況で妥当でなかった。
- **完成度で裁く** — 破棄した 365 行の差分は 5 本の正例を備えた最も完成度の高い成果物だったが、
  別解が着地済みで、かつ偽緑の経路を持つため最も明確な破棄対象だった。完成度は要否を決めない。
- **判定基準だけで機械的に閉じる** — 「壊れた実例なし」だけで T-2032 を完了にすると、
  ユーザーが既に命じた明記義務が未完のまま台帳から消える。基準は差分の要否を決めるが、
  その差分が指していた義務の生死は決めない。

## {{D:midflight-disclosure-remains-open}}. D1179 が課した midflight の保証範囲の明記は、肯定形の 2 点が未履行のまま残る

**決定:** `tools/check_wave_startup.py --mode midflight` の `--help` と `NOTE:` 行について、
D1179 が課した明記義務のうち次の 2 点は**未履行**であると確定し、別の一手として登録する。
救出差分は文面が壊れているので採用しない。

1. midflight が保証するのは「段 5 直前に乖離が再測され、gate 自身が測った実測値が提示されること」
   **だけ**であるという肯定形の記述。
2. 「古い anchor のまま実装子を投入しないこと」は保証しないという限界の記述。

履行済みは、段 5 実装子 dispatch 直前専用であること、開始 gate の代用ではないこと、
HEAD/main 関係・clean tree・handoff を検査しないこと、main 乖離量が関門でないことの 4 点である。

**理由:**

- 現行の `--help` と `NOTE:` は非保証事項の列挙だけを持ち、保証範囲の肯定形を持たない。
  D1179 の本文は肯定形と限界の両方を明記せよと課している。
- 救出差分の文面
  「「midflight は段 5 実装子 dispatch 直前専用で、開始 gate の代用になる」という保証はしない」
  は、A かつ B の否定であって A を肯定しない。直後の「midflight が開始 gate の代用ではない」は
  B を正すが、A の規範性を回復しない。D1179 の「専用の mode とする」という決定より後退している。
- 添付されていた 73 行の検査が守るのは、docstring・help・NOTE に列挙文字列が存在し、
  help と成功時 NOTE が同じ語を含むことだけである。midflight の実際の 6 検査と除外集合は
  既存 test が固定済みで、新しい挙動 oracle を足していない。文字列の存在だけを守る検査は、
  研究最優先・プロトタイプ基準では過剰である。

**却下した選択肢:**

- **壊れた文面のまま着地させて義務を閉じる** — 意味が後退した文面で義務を満たしたことにすると、
  台帳は履行済みと記録するのに実物は後退している状態になる。
- **義務ごと破棄する** — 明記は承認済み裁定の一部であり、親が不採用にできる対象ではない。
- **73 行の検査だけ残す** — pin する対象の文面が壊れているので、壊れた文面を固定するだけになる。
