## {{D:cap-lift-two-stage-binding}}. 上限引き上げの発効は内容 commit と発効 commit の二段束縛にし、発効 commit は認定記録と受領証を同時に導入する

**決定 (親裁定。2026-09-01 にユーザーが「codex に相談して決めて」と委任した範囲で確定した):**
計算資源の上限引き上げを表す受領証の発効 topology を、次の形で確定する。

1. **内容 commit `G`** が実装一式 (P6 の意味的充足契約の本体・calibration・admission 結線、
   受領証機構、新 manifest、全 consumer 結線) を導入する。`G` は自分自身の識別子も
   自分の digest も持たない。
2. **発効 commit `A`** は `G` の直子とし、**親集合が exact `{G}`** であることを要求する。
   `A` が create-only で導入してよいのは、**exact `G` を対象とする認定記録と、それを
   path + hash で束縛する受領証の 2 件だけ**である。`A` は自分自身の識別子を持たない。
   非 merge、`AI-Agent: none` を逐語でちょうど 1 本という既存の要求は不変とする。
3. `G` と `A` は分割して main へ入れず、**同一の land transaction** で取り込む。

**これは新機構ではなく D438 決定 (4) が既に裁定した二段束縛の適用である。** 同決定は
「内容 commit `P` が bytes を導入し manifest は `P` の識別子も自分自身の digest も持たない。
発効 commit `C` は `P` の直子で binding record だけを導入し `C` 自身の識別子は持たない。
祖先代用の禁止は `is-ancestor` ではなく『`C` の親集合が exact `{P}`』で維持する」と定めている。

**あわせて次を確定する。**

- **受領証だけを先に発行する形は引き続き採らない** (D841 は不変)。
- **現行 manifest の exact 世代数 2 と 8c 事前登録は変更しない。** 受領証で開く上限は
  新しい manifest 版にだけ置く。これにより D882 が別の変更単位へ予約した条件 11 の locus と、
  凍結済みの事前登録本文に触れずに済む。
- **P6 の認定を実装より先に行う順序は採らない。** 認定記録は `subject_revision_sha` に束縛され、
  後続の実装で対象 revision が変われば認定は失効するためである。認定は `G` の確定後に行う。

**理由:**

- 認定記録は対象 revision に束縛されるが、その revision は実装を含む `G` が確定するまで
  決まらない。一方で先行設計 v2 は発効 commit が受領証 1 ファイルだけを追加すると書いていた。
  この 2 つを同時に満たす場所が存在せず、**認定記録を置ける commit が無いという循環**になる。
  発効 commit の追加可能 path を 2 件にすると、この循環だけが解ける。
- 緩む範囲は「発効 commit が create-only で追加できる path が 1 件から 2 件になる」ことだけである。
  merge の禁止、親集合の exact 一致、それ以外の変更・削除の禁止、trailer の逐語一致、
  前提条件 10 件の要求、認定記録と独立検査者 attestation の要求はいずれも不変であり、
  D121 決定 (7)・D150 決定 (4)・D156 のどれも supersede しない。
- 受領証で開く上限を新しい manifest 版へ隔離すると、現行系列の受理集合は 1 bit も動かない。
  現行の事前登録は当該系列を exact 世代数 2 と規範化しており、そこを触らずに拡張できる。

**却下した選択肢:**

- **先行設計 v2 の「発効 commit は受領証 1 ファイルだけ」を維持する** — 上記の循環が閉じず、
  認定記録を repo のどこにも置けない。
- **前提条件の機械再導出要求を外し、発効 commit の形式検査だけで上限を開く** —
  D121 決定 (7)・D150 決定 (4)・D156 の逐語 supersede を要し、承認ゲートを実質的に緩める。
- **到達不能と承知で受領証の入口だけを land する** — 実正例を持たない枝を増やす。
  同型の到達不能な入口が既に 1 件あり、その正例は封印型と検証器の差し替えで作られている。
- **現行 manifest と事前登録の世代数契約を receipt 条件付きへ改訂する** — 凍結済みの
  事前登録本文と、別の変更単位へ予約済みの locus に触れる。新 manifest 版への隔離で足りる。
