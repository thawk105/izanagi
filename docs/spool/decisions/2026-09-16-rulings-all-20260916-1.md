### 項 1 — 床値の消費 3 経路の撤去要求を取り下げる

対象: T-1338。

**決定:** 撤去要求そのものを取り下げる。3 経路 (driver の null 拒否、budget の凍結数値 loader、
report の解決経路) は撤去せず現用のまま残す。本項はこれで閉じる。

**理由・採らない案:** D2024 が 3 者とも撤去授権が無いことを確定している。1 つ目は D1985 が
「残すもの」に名指し、2 つ目は凍結予算を今回の資源上限へ射影するもので過去値比較ではなく、
3 つ目は D1984 が現用挙動を記録し既存 consumer test が拒否を要求する。
新しい撤去裁定を出す案は、1 つ目について D1985 と正面から衝突するため採らない。

### 項 2 — 起点試行の証拠発行器は受理型だけ先に決める

対象: T-2293。

**決定:** Q1 (証拠発行器の受理型に探索 layout を加えるか) だけ先に決め、加える。加えるときは
維持する拒否述語と負例を同時に確定する。Q2〜Q4 は D1875 が定める整合が決まってから諮る。

**理由・採らない案:** 起草は 4 問すべてを即時実装可としたが、**別系統モデルの相談が既裁定の
誤引用を指摘した。** D2018 が拒むのは検疫と auditor veto を通さない直呼び経路であって、
安全な起点入口そのものではない。さらに D1875 が関連する実行経路を「整合が決まるまで着手しない」
としている。4 問を一括して実装可にする案は、この順序裁定と抵触するため採らない。

### 項 3 — 全 workload 退行込み報告は未了のまま置く

### 項 6 — 監査結果の受領証による使い回しは認めない

### 項 7 — 到達不能な 30 件は既存の形式で記帳して閉じる

**決定:** 3 択のうち、(b) 既存の collection gate の式を合わせる案は**採らない** (受理集合を
緩める方向である)。(c) 拒否でなく理由付きの早期診断に留める案は**採る** (受理集合を動かさない)。
(a) 契約そのものの定義は D1910 項 1 のとおり実測先行の保留を維持する。

**理由・採らない案:** entry (1527) が「D1910 項 1 は択一への回答ではなく実測先行の保留であり、
3 択はそのまま残る」と明記した。本決定はそのうち実測に依存しない 2 択に答える。
式を合わせる案は過剰拒否を消す代わりに取りこぼしを受理側へ寄せるため採らない。

### 項 30 — 受入の担当表は新設せず、今回必要な観測だけ採る

対象: T-1933 (見送り台帳)。

**決定:** nodeid から worker への対応表は新設しない。今回必要な観測だけを採る。
見送りは維持し、再訪が発火した事実を台帳へ追記する。

**理由・採らない案:** 再訪条件 (受入 wall の実害と構成変化) は発火した — 112 走中 106 走が
300 秒超、最遅の担当が 2 番から 112 走中 103 走で 0 番へ変わった。しかし対応表そのものは
新しい仕組みで、D1602 が以前の再訪を「支配的な 2 file の分割」で閉じている。

### 項 31 — 受入と着地で検査の実行環境は揃えない

対象: 未採番 (所有 wave の未 land fragment が持つ)。

**決定:** 受入と着地で checker の実行環境を揃えない。受領証が跨がらない状態のまま置く。

**理由・採らない案:** 環境は trailer の解釈に効きうるため、揃えることは受理集合を変える変更である。
温めるのは費用の改善であって正しさの要件ではなく、D1996 が着地の窓を既に直している。

### 項 32〜33 — 相乗り再訪条件が成立した 2 件は相乗りさせる

対象: T-385 / T-736 (いずれも見送り台帳)。

**決定:** どちらも「同一 file を触る wave への相乗り」という再訪条件が成立したので、
次に同 file を触る作業単位へ相乗りさせる。専用の作業単位は立てない。
見送りは維持し、発火した事実を台帳へ追記する。

**理由・採らない案:** 元項が名指す file を、受入改善と静的 tail の登録がそれぞれ変更している。
節や変更行の一致を追加条件にすると、記録された再訪条件を狭めることになる。
今回同じ赤が再発したという主張はしない。

### 項 34 — 反例の分類は現行維持で設計文へ追記する

対象: T-2456。

**決定:** 現行 (D1768) の定義を維持し、設計 §3.4 へ「class = SCC 代表 witness」を追記する。
検査器の出力へ SCC 内 cycle 数や uniqueness proof を足す案も、構造同値類を定義する案も採らない。

**理由・採らない案:** 機構を追加せずに設計文の記述を実際の意味へ合わせる最小の手である。
出力を増やす案は検査器の出力 bytes が変わり、凍結した束縛を焼く。
**なお D1768 は本項が前提として引いている決定であって本項の回答ではない** (D1809 の却下欄が
uniqueness の再定義をユーザー裁定へ返すと明記している)。entry (1527) が同じ確認をしている。

### 項 35 — 古い引き継ぎ書は畳む

対象: T-2422。

**決定:** 該当の handoff を畳む。固有の引き継ぎ情報の行き先だけ先に確認する。

**理由・採らない案:** 記述が D1874 と D1993 で進んだ状態と一致せず、独立に読むとユーザー裁定待ちに

### 項 36 — ライセンスの著作権者表記は具体的な指定を待つ

対象: T-2605。

**決定:** `LICENSE.md` の必要表示と README の商用窓口が指す著作権者表記は、ユーザーの具体的な
指定を待つ。現在の git author identity を根拠なく置換しない。

**理由・採らない案:** D1992 のライセンス選択から個人の公表表記は導けない。

### 項 37 — 説明文は実測に合わせる

対象: T-2628。

**決定:** `__has_include` の挙動についてのコメントと拒否診断の本文を、実測 (angle 形式では
前処理エラーになる) に合わせて訂正する。

**理由・採らない案:** どちらも fails-closed 側なので受理集合は変わらず、誤った説明だけを除く。

### 項 38 — 後始末の失敗による例外置換は直さない

対象: T-2631。

**決定:** create-only writer の close 失敗が元の例外を置換しうる件は直さず、限界として明記する。
実害が確認された時点で局所修正を再評価する。

**理由・採らない案:** 既存経路であり、成果物の値・受理集合・参照への影響が立証されていない。
診断の質だけを理由に追加実装を採らない。

### 項 39 — 未送信の変更の送信を承認する

対象: 運用。項目番号は持たない。

**決定:** 手元にしかない変更の外部保管先への送信を承認する。
**承認の対象は提示時点の先頭 `61e0e9c4a` までとし、それ以降に増えた分へ自動的に広げない。**
送信操作はユーザーが行う。AI は送信しない。

**理由・採らない案:** 取得済みの外部参照は手元の祖先であり、巻き戻しなしで送れる。
承認範囲を提示済みの識別子へ固定するのは、提示後に着地した内容を黙って含めないためである。
D1986 項 16 が同じ形を採っている。
