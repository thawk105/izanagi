## {{D:floor-compiler-input-root-relative}}. compiler input manifest は根の分類と相対 path を持ち、使用時に現在の canonical base へ束縛して再検証する

**決定:** manifest が job-local な FetchContent base 配下の絶対 path を保存する形を改め、
**根の分類と根からの相対 path** を持たせる。cache hit と receipt 発行の時点で現在の canonical base
へ束縛し直し、hash を再検証する。run 間の cache 再利用は失わない。

**同じ赤を報告している別 wave の項目と、選択肢集合を照合するまで 1 件へ束ねない。**
同じ本文の失敗であることは同一性の根拠にならない (F151 の再発防止)。
両経路で同一の cache entry・同一の拒否述語・同一の descriptor と是正 3 択になることを実測できた
場合にだけ統合する。

**理由:**

- 床値実測の主経路が現に止まっている。base が消えた後の cache hit が
  `external compiler input is unavailable` で落ちる形を 31 件実測した。
- D424 は oracle と build を job-local な base で同一 tree へ束縛すると定めた。本決定はその束縛を
  外すのではなく、**記録する値を絶対 path から根相対へ変える**だけである。同一 tree の要求は不変。
- D1136 が定めた snapshot 内外の扱いの境界に触れるため、扱いを変える側 (使用時の再束縛) を
  明示して記録する。

**却下した選択肢:**

- **base の絶対 path を descriptor-bound cache identity へ入れ、base が違えば必ず fresh build にする**
  — run 間の cache 再利用を失う。測定時間が伸びるだけで、記録の正しさは改善しない。
- **旧 external path が消えた entry を cache miss へ降格する** — 競合・隔離・回収規則の新設を伴い、
  受理集合の変更が是正の副作用として入る。

## {{D:floor-attempt-registry-namespace-composite}}. 床値試行台帳は予算を凍結単位に残したまま、台帳だけを世代ごとに分ける

**決定:** 床値 campaign を試行台帳へ配線するにあたり、**予算の集約単位は凍結単位のまま残し、
台帳の名前空間だけを protocol 世代ごとに分ける**複合形を採る。
**予算の置き場所は新しい設計判断なので、設計に入る時点で改めて諮る。**

**理由:**

- 現用の床値 protocol が 2 つあり、どちらも同じ凍結 hash を共有する。配線すると、先に走った世代が
  genesis を作り、後の世代は binding が食い違って拒否される。止まるのは測り直しではなく campaign
  全体である。
- 台帳を世代ごとに分けるだけでは、測り直し予算が世代ごとにリセットされる。予算の集約は
  「protocol を版上げして同じ cell を測り直し、良い床値を採る」経路を塞ぐ防壁であり、
  これを緩めるのは絶対規律 2 の面にあたる。
- 凍結単位のまま後続世代を拒否する案は防壁を保てるが、新しい pin で床値 campaign を走らせられなく
  なる。運用上の後退を正しさの代償として受け入れる理由がない。

**却下した選択肢:**

- **台帳を世代ごとに分け、予算もそれに従わせる** — 予算防壁が世代ごとにリセットされる。
- **凍結単位のまま据え置き、後続世代を拒否する** — 新しい pin で走らせられない。

## {{D:floor-attempt-registry-forward-binding}}. 試行台帳の proof chain 束縛は新規成果物へ前向きにだけ掛ける

**決定:** 試行台帳を certified 成果物の proof chain へ束縛する範囲は、**新規の成果物だけに
前向きに掛ける**。既に certified 済みの成果物の受理面は変えず、遡って再検査の対象にしない。

**理由:**

- 現在、certified の検証は台帳を一切読まない。台帳を削除・不正化した状態でも検証が通る。
  書き手だけを作っても「測り直しを追跡している」とは言えない。
- 遡及して掛けると、既存の certified 選択を後から無効化しうる。測定は当時の事実として残る
  (絶対規律 7) ため、後発の束縛要求を過去の判定の有効性の条件にしない。
- 束縛しない案は、台帳の欠落を許したまま追跡を謳う状態を作る。謳うだけで発火しない保証にあたる。

**却下した選択肢:**

- **台帳の chain head を result へ pin し historical reverify も対象にする** — 既存 certified の
  受理面を遡って変える。
- **束縛しない** — 追跡の目的が達成されない。
- **書き手だけ land して束縛を後続へ送る** — 恒真な保証を作る。

## {{D:nonsampling-probe-reverse-closure}}. 非標本 probe の生成遮断は権威点からの逆到達閉包で導き、完全性は主張しない

**決定:** 事前登録 §5.1 (ii) が要求する「結果を生成しない配線調査」は、**権威点からの逆到達閉包**で
生成経路の不在を導く形で設計する。**完全性は主張せず**、閉包の外に経路が残りうることを明記する。

**理由:**

- 対象と軸の欄が埋まらない限り事前登録は発効せず、実走に入れない。この欄は計測に依存しないので、
  計測待ちを空欄の理由にしない。
- D1171 が非標本 probe の生成遮断について同じ形を既に採っている。同じ面に別の導出法を新設すると、
  どちらが権威かが曖昧になる。
- 完全性を主張すると、閉包の外の経路が見つかった時点で主張全体が崩れる。範囲を明示した主張は
  経路が増えても訂正で済む。

**却下した選択肢:**

- **生成経路の不在を全称で主張する** — 証明できない範囲まで保証したことになる。
- **probe を作らず事前登録の欄を空のままにする** — 実走が永久に開かない。

## {{D:runner-binding-rerule-before-stage-q}}. 実行器束縛の再裁定は段階 Q の設計より先に行う

**決定:** 受入の実行器を tested main の blob へ束縛する要求について、**先行段の着地をもって
束縛の可否を再裁定する**。段階 Q (等値要求の除去) の設計はこの再裁定より後に置く。
既定の分割数を 3 へ上げる件も、この再裁定と同時に決める。**その際、分割数の据え置きが求めていた
「ノードを揃えた対測定」を実際に取る。**

**理由:**

- 先行する裁定が「材料を運ぶ変更を先に通し、その後で束縛の可否を再裁定する」と定めており、
  その先行段は着地した。**再裁定の条件は成立している。**
- 台帳の側は先行段の完了を終端と読み、次段を「実装待ち」として直ちに着手可能と書いていた。
  先段完了を終端と誤認すると、約束された関門が記録から消える。
- 分割数の据え置きは同じ裁定に従属しており、独立に再提示すると据え置きの根拠を二重に評価する
  ことになる。

**却下した選択肢:**

- **次段へ進んでから再裁定する** — 等値要求を外した後では、外す前の可否を判断できない。
- **分割数だけ先に決める** — 従属関係を無視して据え置きの根拠を分割する。

## {{D:landing-receipt-needs-external-signing-authority}}. 着地受領証の真正性は外部の署名主体で閉じ、閉じるまで未閉鎖と書く

**決定:** 判定器が判定対象の内側にある限界について、**署名鍵と発行権限を候補および AI が書ける
領域の外に置く外部署名主体を実装する**。着手できない間は、着地受領証を根拠にした正しさ主張を
**未閉鎖と明記**し、閉じたと書かない。

**理由:**

- D906 が署名対象と発行権限の所在を既に決めている。適用範囲の違う一般則で、対象固有の後発裁定を
  上書きしない。
- 「限界を明記すれば足りる」は、明記が主張の強度を下げる場合にだけ成立する。着地受領証は
  現に受理判断の根拠として使われており、明記だけでは受理の意味が変わらない。
- 検証器と被検証対象を同じ主体が変更できる限り完全な防壁にならないことは変わらない (D387、D1128)。
  外部主体はその限界を消さないが、**書ける領域の外へ鍵を出す**という一段は実際に効く。

**却下した選択肢:**

- **限界の明記だけで足りるとする** — D906 が明示的に要求した機構を、旧い脅威モデルの一般則で
  見送ることになる。
- **署名を repo 内の鍵で行う** — 候補が書ける領域に鍵が残り、主体の分離にならない。

## {{D:measurement-semantics-gate-family}}. 測定条件は「供給されたか」と「実行側で同じ意味を持つか」を独立した関門として設計する

**決定:** 要求した測定条件についての関門を族として設計し、**供給と実効化を見る節**と
**実行側での意味を見る節**を**独立した必須節と負例**として持たせる。単一の関門へ潰さない。
patch 供給の define を build へ渡す driver 全体に、効いたことの正例検査を義務化する。

**理由:**

- 独立 2 例がある。一方は条件が供給されず別の条件を測った型、もう一方は**供給され適用され
  供給検査も通ったのに、値が別の意味に解釈された**型である。
  **「供給されたか」を見る関門は後者を構造的に捕まえない。**
- 族の射程を供給ではなく意味に置く。単一の関門に統合すると、供給が緑であることが意味の緑と
  読める形になり、後者の型が再び通る。
- **絶対規律 7 が守る型とは別である。** 規律 7 は「測定は当時の事実として残る」を守るが、
  この族は最初から別のものを測っているので、時間と無関係にその場で誤っている。
  混同すると規律 7 が「測定は何でも残る」の口実になる。

**却下した選択肢:**

- **供給検査だけを義務化する** — 独立 2 例のうち 1 例を構造的に見逃す。
- **単一の統合 gate にする** — 片方の緑がもう片方の緑と読める。

## {{D:oracle-evaluate-seam-closed}}. build 0 回の評価を確定にできる seam は塞ぎ、契約を固定している既存テストごと変更する

**決定:** oracle の評価関数の差し込み口が build 0 回の評価を確定扱いにできる形を**塞ぐ**。
その完走を契約として固定している既存テストの所有を移し、契約変更を認める。

**理由:**

- build を 1 回も行わない評価が確定になるのは、正しさの関門の空洞化である (絶対規律 2)。
- 既存テストがその完走を契約として固定していることは、機構を残す理由にならない。
  **テストが固定しているのは現状であって、正しさではない。**

**却下した選択肢:**

- **seam を残しテストを維持する** — 空洞を契約として恒久化する。
- **テストだけ消して seam を残す** — 検出力を下げたうえで穴も残る。

## {{D:proposal-consumption-recorded-after-stop}}. 消費記録は入口停止の判定より後に確定させ、停止時は取り消しを記録する

**決定:** 提案の消費記録が入口の停止判定より先に公開される順序について、
**順序は変えず、停止した回には取り消しの記録を残す**形を採る。

**理由:**

- 消費を停止判定の後ろへ動かすと、停止した回の受領証が後から再利用できる窓が開く。
  受理集合を広げる変更であり、記録の正確さのために正しさの窓を開ける取引になる。
- 取り消しの記録は受理集合を変えず、実行されなかった提案を消費済みと数える誤りだけを消す。
- 3 つの駆動系すべてが同じ順序を持つため、族としてまとめて扱う。

**却下した選択肢:**

- **消費を停止判定の後ろへ動かす** — 停止した回の受領証の再利用窓が開く。
- **現状のまま集計側で補正する** — 記録が誤ったまま、読み手ごとに補正の有無が分かれる。

## {{D:source-swap-aba-must-be-closed}}. build 中の材料差し替えは閉じ、不変であることの実証を正式受入の前提にする

**決定:** 所有者自身による A→B→A の差し替えを**閉じる**。読み取り専用の束縛または同等の
実効的な不変 snapshot を計算ノードで実証するまで、正式な受入を成立させない。

**理由:**

- D966 が閉じる対象として「非到達化、別変数による実効分岐、build 中の source 差し替え、
  汚染 cache binary の再利用」を**逐語で名指し**している。
  対象固有の後発裁定を、一般的な見送り方針で上書きしない。
- 差し替えは測定が何を測ったかを直接変える。防御的堅牢化ではなく、測定の意味の面である。

**却下した選択肢:**

- **閉じないことを正式に受理する** — 名指しで閉じると決めた対象を、範囲の違う方針で開ける。
- **検出だけ入れて拒否しない** — 検出後の扱いが呼び手の裁量になり、関門にならない。

## {{D:unreachable-verifier-kept-and-marked}}. 到達不能な検証枝は残し、到達不能であることを台帳へ書き、発火する保証に数えない

**決定:** 正規の待ち手では生成できない受領証を検証する枝を**残す**。到達不能である理由を実装で示し、
台帳へ書く。**発火する保証としては数えない。**

**理由:**

- 削除すると受理集合が縮み、将来の改修に対する多重防御を失う。
- 残したまま保証に数えると、発火しない assert を守っている性質として数える誤りになる。
- D1173 が mutation-surviving assert について同じ形を採っている。**ただし本件は選択肢集合が
  異なる** (対象が land の検証枝であり、変異が生存した assert ではない) ため、
  D1173 の適用ではなく同じ形を独立に採る。

**却下した選択肢:**

- **削除して受理集合を縮める** — 多重防御を失う。
- **残して保証に数える** — 恒真な保証を作る。

## {{D:ai-authored-strictness-returned-individually}}. ユーザー裁定の印を持つ AI 起草の厳密さは、候補が揃った時点で個別に裁定へ返す

**決定:** ユーザー裁定の印を持つ決定のうち、具体的な機構が AI 起草でユーザーが要求していない
厳密さを含むものは、**候補が具体的に揃った時点で 1 件ずつ裁定へ返す**。まとめて撤廃も、
まとめて維持もしない。**撤廃の可否はユーザーの判断であり、AI が勝手に緩めない。**

**理由:**

- 実測で 4 件の候補が既に名指しで揃っている。うち 1 件は研究の主経路を 5 日間止めていた。
  候補が揃った後も「洗い出しは AI 作業」として返さないでいると、AI が起草した拘束が
  ユーザーの裁定として残り続ける。
- 一括で撤廃すると、実際にユーザーが要求した厳密さまで巻き込む。一括で維持すると、
  要求されていない拘束が恒久化する。**個別にしか判定できない。**
- 判定材料は「その機構が一括承認で確定したか」「機構の前提が実測されているか」の 2 つとする。

**却下した選択肢:**

- **一括で撤廃する** — ユーザーが実際に要求した厳密さを巻き込む。
- **候補が揃うまで返さない方針を維持する** — 候補は既に揃っており、返さない理由がない。

## {{D:prereg-artifacts-follow-ordering-rulings}}. 権威の導出方法を決めた裁定は、着手順序の裁定を上書きしない

**決定:** 事前登録 3 成果物の発行は、**共有批准凍結の発効を先に片付けるまで保留**する。
権威の導出方法を決めた後発の裁定は、先行する着手順序・従属関係・前提条件の裁定を
**上書きしない**。一括裁定の案は排他ではないので、順序の前提が満たされた時点で改めて扱う。

**理由:**

- 導出の権威が実在しないため、現状では 3 成果物を発行できない。
- 先行する 3 件の裁定が、当該成果物を「権威の実体配線完了まで scope 外」「上流に従属する
  下流症状であり順序を入れ替えない」「共有批准凍結が発効するまで着手しない」と定めている。
  後発の裁定の本文にも、それを記録した記帳にも、これら 3 件への言及がない。
- **抵触が判明したのは、着手した wave が 2 時間かけて実装を試みた後だった。**
  順序裁定と抵触する裁定を確定すると、それを実行しようとした wave が空振りする。

**却下した選択肢:**

- **一括裁定を先に行う** — 前提が未充足のまま下流を決めることになる。
- **次世代の schema を設計する** — 順序の問題を設計の問題へ置き換えるだけで、前提は満たされない。

## {{D:minimum-effect-not-raised-for-feasibility}}. 最小重要効果は実行可能性を理由に上げず、検出力が足りなければ記述統計に留める

**決定:** 事前登録の最小重要効果は**宣言した値のまま発効させる**。必要な標本数が総計測予算を
超える場合は、**記述統計に留めて有意性を主張しない分岐に入る**。実行可能性を理由に閾値を
上げ直さない。

**理由:**

- 凍結本文が実行可能性を理由とする閾値の引き上げを禁じている。
- 値を通しやすくするために基準を緩めるのは、事前登録の意味そのものを壊す。
  緩めた事実が記録に残っても、緩めた後の有意性主張は事前登録された主張ではない。
- **発効前にしか変えられない**という時間的制約は、変える理由にならない。制約は「今なら
  正当に変えられる」ではなく「今を過ぎたら事後変更になる」を意味する。

**却下した選択肢:**

- **必要標本数が収まる値へ上げる** — 実行可能性で基準を動かす形そのもの。
- **発効を遅らせて予算がつくのを待つ** — 発効しない限り実走に入れない。

## {{D:index-version-substitute-provenance}}. 索引が版番号を返さない場合は代替の来歴で固定してよい

**決定:** 文献索引が API や export の版番号を返さない場合、**接続先・応答の field 名・
応答 header・生データの digest** を組にして版の代わりに固定してよい。
ただし**「版番号」と呼ばず「版が取得不能な場合の代替来歴」と明記**し、改訂手続きの中で固定する。

**理由:**

- 対象の 3 索引はいずれも版番号を返さない。代用を認めないと、当該軸は最上位の証拠水準に
  到達できない。
- 代用を「版番号」と呼ぶと、他所の版番号と同じ強度の主張に読める。呼び名を分けることで、
  主張の強度の違いが読み手に伝わる。
- 固定する 4 つ組は、いずれも取得時点に観測できて事後に改変できない。

**却下した選択肢:**

- **代用を認めない** — 当該軸が構造的に到達不能になる。
- **代用を版番号と同じ名前で記録する** — 主張の強度を実際より強く見せる。

## {{D:literature-contract-amended-not-waived}}. 完走述語の構造的な不成立は宣言的除外でなく契約の改訂で閉じる

**決定:** 文献検索契約の完走述語が索引側の性質で構造的に満たせない面は、**契約を改訂して**閉じる。
改訂は手続きに従い、新しい日付の文書・新しい query ID・全枝の再実行・独立レビューを伴う。
壊れた述語のまま既存の枝を継続しない。**D1155 型の宣言的除外へ倒さない** — D1155 は索引の
構文能力による不可能についての裁定であり、射程が違う。

面ごとの扱いは次のとおり。

- **宣言総件数と実要素数の一致** — 要求値のこだまを実件数として扱う現契約は恒真なので、
  索引ごとの実要素数の定義へ改める。
- **正規化主キーの重複** — 取得完全性は索引固有の文献 ID で数え、主キーの重複は文献の族の層で扱う。
- **結果窓の上限** — 結果を見る前に固定した、重ならない日付分割と新しい query ID で取り直す。
- **旧契約のままの継続** — 行わない。改訂を先に決め、新しい query ID で取り直す。
  中断した取得には機械可読な再開点を残す (D1183)。

**理由:**

- 恒真な述語を満たしたと記録すると、完走の判定そのものが意味を失う。
- 宣言的除外は、索引が構文として表現できない場合にだけ成立する。**取得できるが数え方が違う**面へ
  適用すると、取れるはずのものを取らずに済ませる口実になる。
- 無償枠は有限であり、壊れた述語のまま消費すると改訂後の再実行の余力を失う。

**却下した選択肢:**

- **述語を満たせない枝を宣言的に除外する** — 射程の違う裁定の型を流用する。
- **旧契約のまま完走させてから改訂する** — 改訂後に全枝再実行が要るので二重に枠を使う。

## {{D:frozen-artifact-annotation-via-successor}}. 凍結物への注記は後継物で行い、届かない残余は限界として明記したうえで充足と認める

**決定:** 凍結した表への注記について、**全行を持つ後継物・規則の正本への記載・README の導線**の
3 つをもって、注記の要求を**充足したと認める**。原表だけを開いた読者へ届かない残余は
**限界として明記**する。凍結物は 1 byte も書き換えない。

あわせて、軸ごとの凍結物に散っている一般規則 (主キーの正規化・完走の条件・改訂の規則) は
**手順書の本体へ集約**する。集約も凍結物には触れず、後継物と規則の正本の形で行う。

**理由:**

- 凍結物を注記のために書き換えると、以後の凍結物が信用できなくなる。
- 3 つの経路で届く読者の範囲は実際に広い。届かない残余があることを理由に充足を認めないと、
  凍結規則を守る限り永久に充足できない。
- 手続きの正本を軸ごとに複製すると、改訂のたびに乖離する (D1015)。

**却下した選択肢:**

- **凍結物へ追記する** — 凍結規則を破る。
- **充足と認めない** — 凍結規則の下で到達不能な要求を残す。

## {{D:evidence-tier-aggregation-ban-generalized}}. 判定資料の階層が行ごとに違う属性欄は、集計と行間比較を一般に禁じる

**決定:** 「行ごとに判定資料の階層が違う属性欄は集計・行間比較を禁じる」を、
特定の pilot の外へ**一般規則として広げる**。**別途妥当化した階層別の解析は禁止対象に含めない。**

**理由:**

- 一次資料に基づく行と、監査前の要約に基づく行を同じ列で足すと、合計の意味が行ごとに違う。
  この危険は特定の表に固有ではない。
- 階層別の解析は、階層を明示したうえで層内で比較するので、混同の危険がない。
  一般化の文言がこれを巻き込むと、正当な解析まで塞ぐ。

**却下した選択肢:**

- **元の pilot に限定したままにする** — 同型の表が増えるたびに同じ判断を繰り返す。
- **階層別解析も含めて禁じる** — 正当な解析を塞ぐ。

## {{D:acceptance-lock-moves-to-shared-filesystem}}. 並行受入の排他は共有 filesystem 上で取り、成立しなければ双方を隔離する

**決定:** 並行する受入の排他を、**共有 filesystem 上の lock** で取る。成立しない場合は
**親 tree と共有ベンチマークの双方を隔離**する。現行の同一 host 前提の排他のままにしない。

**理由:**

- 現行の排他は同一 host・同一 filesystem までしか効かない。別 host から同じ共有資源へ触れる運用は
  D1008 が明記する保証範囲の外にある。
- 実害待ちにすると、**受入の正しさを競合の有無に委ねる**ことになる。受入は正しさの関門であり、
  関門の成立を偶然に依存させない。
- 頻度が低いことは、起きたときに受入結果が信用できないことを補わない。

**却下した選択肢:**

- **現行運用を維持し限界を明記する** — 明記しても受入の判定は変わらない。
- **並行受入を禁じる** — 所要が線形に伸び、並行 wave が待ち行列になる。

## {{D:cli-misuse-closed-by-contract-not-attestation}}. 呼び出し時点を観測できない検査器の誤用は、入口契約と診断で閉じ、自己申告の申告を増やさない

**決定:** 起動時に mode を明示することで一部の検査を飛ばせる形について、
**保証範囲を明記して閉じる**。段の申告を新設して機械的に塞ぐ案は採らない。

**理由:**

- D822 が確定したとおり、検査器は自分が呼ばれた時点を観測できない。
- 申告を必須にする案も、mode を非公開にする案も、**最終的に「呼び手が正直である」ことに依存する**
  (起動器を直接呼べる)。防壁を増やした見かけの割に迂回の余地が残る。
- 見かけの防壁は、実際の保証より強い保証があると読み手に思わせる分だけ有害である。

**却下した選択肢:**

- **段に束縛した申告を必須にする** — 呼び手が生成する値なので偽造できる。
- **mode を内部関数としてだけ持つ** — 内部関数を直接呼べる経路が残る。

## {{D:runbook-is-authoritative-over-precedent}}. 登録規則と先例が食い違う場合は手順書の規則を正とする

**決定:** ログインノード実行体の admission 分類について、**手順書の規則を正**とする。
規則の閉集合に入らないまま実測なしで登録されている先例は、**実測待ちへ戻す**。

**理由:**

- 先例を正にすると、実測なしの登録が既成事実として広がる。規則が閉集合を定めている意味が消える。
- 実測待ちへ戻す費用は実測 2 本分であり、規則の実効性を保つ費用として妥当である。

**却下した選択肢:**

- **先例を正として規則を書き換える** — 実測の要求が事実上消える。
- **両方を併存させる** — どちらに従えばよいかが呼び手ごとに分かれる。

## {{D:mechanism-ban-needs-negative-controls-first}}. 族一般化の独立 2 例は必要条件であって、機械的禁止の自動承認ではない

**決定:** 独立 2 例が揃った族について機械的な禁止を新設する前に、
**(a) その禁止が実際に捕まえる負例 2 件**と **(b) 正当な用法を誤って拒まない境界の試験**を
実測する。実測が揃ってから禁止の可否を決める。

本決定は、モジュール自体を差し替えるテスト書法の禁止、certified な出口一般への起動由来の権能要求、
上流に残る一回性の主張の撤去、凍結文面の食い違いの訂正に適用する。

**理由:**

- 独立 2 例 (DW-G03) は族一般化を**許す**条件であって、特定の exact な gate を承認する条件ではない。
  2 例から導かれるのは「族として扱ってよい」までで、「この述語で塞げ」までは導かれない。
- 負例を実測しないまま入れた禁止は、恒真か、正当な用法を巻き込むかのどちらかになりやすい。
  どちらも変異でしか暴けない。
- 凍結文面の食い違いを「実装済みだから正」とするのは事後追認である。凍結された中身と全ての
  使い手から独立に導出し、結論が変わる境界例を実測してから訂正を選ぶ。

**却下した選択肢:**

- **2 例をもって禁止を入れる** — 恒真な gate または過剰拒否を作りうる。
- **禁止を見送る** — 族として扱ってよいという結論まで捨てることになる。

## {{D:vacuous-guard-kept-but-not-counted}}. 挙動に影響しない防護は明記して残し、発火する保証や検出力に数えない

**決定:** 全ての呼び出し点で常に真になる防護は、**防御的な冗長として明記して残す**。
**発火する保証にも検出力にも数えない。**

**理由:**

- 削除すると、構成が変わったときの多重防御を失う。挙動と成果物への影響はゼロなので、
  残す費用も実質ない。
- 明記しないと、読み手には効いている防護に見える。効いていない防護を検出力に数えると、
  実際より強い保証があることになる。

**却下した選択肢:**

- **削除して構成による担保だけに寄せる** — 将来の改修に対する冗長を失う。
- **明記せず残す** — 効いている防護に見える。

## {{D:external-knowledge-relayed-as-data-by-parent}}. 外部知識は親が出典付きのデータとして子へ渡し、子の検索の既定は変えない

**決定:** 子の Web 検索についての拒否の定義域は成果物側に限る形で既に定まっている。
**段ごとに既定を無効にする配線は行わない。** 代わりに、**外部知識は親が出典付きの
データとして子へ渡す**経路を作法として明文化する。

**理由:**

- 段ごとの既定無効は D1149 が明示的に却下している。既定 off を定めた先行裁定との優先順位は
  D1149 自身が解釈済みであり、ここで優先順位を裁定し直さない。
- 親は検索を持ち、証拠鎖の脆さもない。外部知識への経路は実際には切れていないが、
  この作法はどこにも書かれていない。書かれていない作法は、次に必要になった者に伝わらない。
- 親が渡す形は**規律 6 と整合する** — 外から来た内容はデータであって指示ではない、という
  境界を渡す時点で明示できる。

**却下した選択肢:**

- **段ごとに既定を無効にする配線を入れる** — D1149 の却下と正面から反対向きである。
- **作法を書かない** — 経路が実在することが伝わらず、子が外部知識を諦める。

## {{D:repo-fixture-must-not-be-a-reader-landmine}}. 読むだけで成果物を壊す fixture は実行時合成へ移し、健全性検査は緩めない

**決定:** repo 内に置いた意図的な非 NFC の検査用データは、**実行時合成へ変え、repo 内の bytes を
NFC に保つ**。証拠の健全性検査は 1 つも緩めない。運用上の回避を恒久化しない。

あわせて、子への禁止事項が指示文へ自動で入らない件は、**起動ツールが機械的に前置する**形で閉じる。

**理由:**

- 子が**読むだけ**で成果物が全損する形は、検査用データの副作用としては重すぎる。
  実費は 2 回の全損で約 47 分・約 900 万 token 相当が実測されている。
- 健全性検査を緩める案は、証拠の健全性そのものを下げる方向であり絶対規律 2 の面に触れる。
- 指示文へ毎回書く義務は、書き落としで同じ事故を繰り返す。**人の注意を関門にしない。**
  文書量の枠は AI が既定の手順で閉じる案件であり、この決定の対象ではない。

**却下した選択肢:**

- **rollout の検査を tool 出力の記録に限って緩める** — 証拠の健全性検査を緩める。
- **指示文へ回避を書き続ける** — 既に再発した運用回避を恒久化する。

## {{D:premise-measured-before-migration-or-relaxation}}. 前提が未測定の経路変更と制限緩和は、先に測ってから決める

**決定:** 次の 3 件は、着手の前に前提を実測する。

- **旧 build 経路を新経路へ寄せる件** — D412 が定めるとおり、先に計算ノードで測る。
- **静的解析の文脈マクロの個数制限** — D615 の方向で精密化し、**D93 は緩めない**。
- **実出力ツリーの前後比較が並列走行で落ちる件** — 専用の一時ツリーへ隔離する。
  着手前に、除外集合の導出を変えた後でも再現するかを確かめる。

**理由:**

- 測っていない前提の上に本番経路を乗せると、後から測ったときに経路ごと作り直しになる。
- 解析の制限は安全側の失敗として働いているので、緩める方向の変更は厳密さの要求 (D93) と
  衝突しないことを示してから入れる。
- 除外集合の導出を変えた裁定が同日に着地しているため、古い観測のまま隔離を設計すると
  不要な隔離を作りうる。

**却下した選択肢:**

- **測らずに寄せる・緩める・隔離する** — 前提が変わっていた場合に作り直しになる。

## {{D:defensive-mechanisms-deferred-with-limits-recorded}}. 実害と頻度が観測されるまで作らない機構は、限界を書いて据え置く

**決定:** 次の機構は**作らない**。いずれも限界を台帳へ明記し、発火条件を書いて据え置く。

- **鍵の紛失・交代・信頼根の入れ替えを表現する schema 拡張** — 固定鍵の限界を明記する。
  外部署名主体の設計に着手する時点で併せて見る。
- **批准から正式起動までの非介在を強制する lease** — 現状は変更を安全側に拒否している。
- **プロセス列挙の不完全性を理由に走査全体を失敗にする形** — 完全な列挙を保証しない限界を
  明記し、実環境で欠落を観測した時点で再裁定する。
- **到達性検査を必ず到達する検査またはデータの流れの検査へ厳密化する形** — 承認の権限が
  閉じている間は現状維持とし、**開放の条件に厳密化を置く**。

一方、**到達不能になった記録の期限付き台帳と通知は作る**。記録と通知だけの軽い形とする。

**理由:**

- 研究最優先・プロトタイプ基準の下では、実害が観測されていない堅牢化は既定で見送り側にある。
- ただし**不可逆な消失**は別扱いである。自動回収の窓が閉じると復旧できず、今回間に合ったのは
  偶然だった。軽い記録と通知で窓の内側に気づける。
- 据え置く機構は、限界を書かないと「無い」ことが「効いている」と読まれる。

**却下した選択肢:**

- **全部作る** — 必要性が未測定の機構が増え、保守の対象だけが広がる。
- **全部作らない** — 不可逆な消失を偶然に委ねる。

## {{D:scan-predicate-and-duration-ledger-updated}}. 走査述語の既知の盲点は対象へ加え、所要台帳は性質と同一性を分けて更新する

**決定:** 期限を設けて繰り返し確認する書き方 (実測 29 か所) を**走査対象へ加える**。
受入所要台帳は D1152 が定めた形に従い、**所要値は性質の述語として更新し、対象集合は基準時点に
対する exact な同一性を保つ**。

**理由:**

- 29 か所は無視できる数ではない。盲点を残したまま走査したと書くと、走査の意味が弱まる。
- 所要値の exact な pin は測定機の個体差を assert する型であり、陳腐化が分母の大きさに隠れる。
  一方、対象集合まで緩めると、件数を保存する入れ替えや消えた対象の復活を検出できなくなる。

**却下した選択肢:**

- **盲点を限界として留める** — 対象へ加える費用は述語 1 本であり、留める理由が弱い。
- **所要値と対象集合へ同じ緩め方を当てる** — 性質が違うものへ同じ扱いを当てることになる。
## {{D:cache-identity-keeps-source-root}}. 正式測定の cache 同一性から source root を外さない

**決定:** 正式 S8b の cache 同一性に絶対 source root が入り cache hit が起きない件について、
**root-neutral 化しない**。cache hit が起きない事実は限界として記録する。

**理由:**

- root-neutral 化すると cache の受理集合が広がる。同じ入力と見なす範囲が変わるので、
  再利用された成果が「同じ条件で測った」と言えるかが別問題になる。
- 測定時間の短縮は、測定の意味の互換性が独立に証明されてから受け取る利得である。
  順序を逆にすると、短縮した後で互換性が否定されたときに測り直しになる。

**却下した選択肢:**

- **root-neutral 化して cache hit を起こす** — 受理集合を広げる変更を、測定時間を理由に入れる。
- **materializer が毎回一意 worktree を作る形をやめる** — 隔離の性質を変える別の面へ波及する。

## {{D:decision-proposal-causality-rides-unforgeable-receipt}}. 決定と proposal 本文の因果は偽造不能受領証の機構へ相乗りさせる

**決定:** 決定と proposal 本文の因果束縛は、**偽造不能な受領証の機構が着地した時点でそこへ
相乗りさせる**。生成前の依頼を封じて応答を provider 受領証で束縛する独立の機構は新設しない。

**理由:**

- hash 鎖では閉じないことが D1146 で確定している。
- 独立に作ると、同種の外部権威が二重になる。D1099 が偽造不能受領証の機構を方針として定めており、
  因果束縛はその上に載る性質である。
- 生成前の依頼を封じる案は D39 決定 7 の supersede と実験対象の変更を伴う。
  因果を記録するために実験そのものを変えるのは代償が大きい。

**却下した選択肢:**

- **生成前の依頼を封じ応答を provider 受領証で束縛する** — 実験対象の変更を伴う。
- **hash 鎖を延長する** — 閉じないことが既に確定している。

## {{D:noncertifying-artifact-type-four-answers}}. 非認証成果物型は鍵層まで固定できる形で再設計し、それまで作らない

**決定:** 非認証成果物型について 4 点を確定する。

1. **終端を「作らない」で確定させず、稼働 wave の land 後に一体で再設計する。**
2. **再開 scope の 8 項目への拡大を認める。**
3. **昇格不能性に、署名された identity 束縛を要求する。**
4. **恒真だった既存 marker を実効化する。**

**理由:**

- 現行の所有制約下では当該型を作れないことを親 probe が再現し、段 3 の子と同値の結論を得た。
  これは停止条件の発火であって、当該型を不採用とする裁定ではない。
- **(3) は署名機構の新設を既定で見送る方針と向きが違うが、D1038 の着手条件が
  「鍵・記録・schema・consumer の全層で固定できること」であり、field の除去や付け替えで
  昇格できる作りしか取れないなら作らないと定めている。** 鍵層を省くと、この型は着手条件を
  満たさないまま存在することになる。見送り方針は、対象固有の着手条件を上書きしない。
- (4) 恒真な marker を残したまま実効化しないのは、謳うだけで発火しない保証にあたる。

**却下した選択肢:**

- **署名された identity 束縛を要求しない** — 着手条件を満たさないまま型を作ることになる。
- **終端を「作らない」で確定させる** — 稼働 wave の land 後に成立しうる設計を先に捨てる。

## {{D:post-commit-relabel-closed-by-context-digest}}. COMMIT 後の名乗り直しは起動 context の digest を成果物へ残して閉じる

**決定:** COMMIT の後に campaign lock を書き換えて識別語を名乗り直す経路を**閉じる**。
関門が検証した起動 context の digest を COMMIT 側の成果物へ残し、成果物の受理と consumer で
再検証する。

**理由:**

- 現在の関門は COMMIT の時点で識別語があった経路だけを閉じており、後から名乗る経路が開いている。
  certified な主張の起源の同一性に直結する。
- D1033 が却下した「下流での名乗り拒否」とは形が違う。あちらは下流が名前だけを見て拒む案で、
  こちらは**上流の関門が実際に検証した事実の digest を運んで再検証する**案である。
  運ぶ値が「名前」か「検証済みの事実」かで、偽造可能性が変わる。

**却下した選択肢:**

- **下流で名前だけを見て拒む** — D1033 が却下済み。名乗りは偽造できる。
- **開いたまま限界として記録する** — 起源の同一性が主張できなくなる。

## {{D:author-prompt-expectation-clause-added}}. 既存テストの期待値を変更しない義務は実装段の契約にも置く

**決定:** 「既存テストの期待値を変更しない」という義務を、修正段だけでなく**実装段の契約にも
置く**。**明示的に裁定された契約変更を除く**、と限定して書く。

**理由:**

- 実装段の契約に同じ文言が無く、実際に実装子が既存テストの期待値を書き換えて壊した実例がある。
- 限定を付けないと、裁定を経た正当な契約変更まで塞ぐ。裁定の有無を条件にすれば、
  変更したい者は裁定を取る経路へ誘導される。
- 収容先の byte 予算は AI が既定の手順で閉じる案件であり、本決定の対象ではない。

**却下した選択肢:**

- **修正段の契約だけに置いたままにする** — 実装段で同じ事故が再発する。
- **無条件で禁じる** — 裁定を経た契約変更まで塞ぐ。

## {{D:oracle-npilot-identifier-kept}}. 未実行の事前登録が bytes を pin している識別子は撤去しない

**決定:** oracle / n-pilot 側に残る承認引数の識別子を**撤去しない**。
ただし**反復を拒否する実効的な関門としては使わない。**

**理由:**

- 当該 protocol の事前登録が driver と job script の bytes を pin しており、現に一致している。
  未実行のため、撤去には後継の事前登録の発行が要る。
- **事前登録の再発行はユーザーの手番であり、AI が勝手に発行しない。**
  識別子 1 つの整理のために、ユーザーの手番を発生させる費用に見合わない。
- 残す以上、それが何を保証しないかを明示する。反復の拒否を担っていると読まれると、
  別の場所で反復が通ったときに保証が破れたと誤読される。

**却下した選択肢:**

- **撤去して後継の事前登録を発行する** — ユーザーの手番を識別子の整理のために使う。
- **残したまま反復拒否の関門として数える** — pin されているのは bytes であって反復の可否ではない。

## {{D:review-effort-pin-wording-fixed}}. 採用 pin は残し、文言を実装に合う形へ直す

**決定:** 検査段の設定値が採用 pin として exact 照合されている件について、**pin は残す**。
節の文言を「**docs 権威から exact 値を導出し、呼び手の指定を拒否する**」という実装に合う形へ直す。

**理由:**

- pin を対象から外すと、値が docs 権威から導出されることの束縛が消える。
  守っている性質は値そのものではなく、値の出所である。
- 現行の文言は実測と食い違っており、実測を同じ節へ書けない。文言を実装に合わせれば、
  pin を保ったまま実測を記録できる。
- 実際に呼び手が指定を渡すと即座に失敗することは実測済みである。文言はその挙動を書けばよい。

**却下した選択肢:**

- **pin の対象から外す** — 値の出所の束縛が消える。
- **文言を変えず実測を別の場所へ書く** — 同じ性質の記述が 2 か所へ分かれる。
