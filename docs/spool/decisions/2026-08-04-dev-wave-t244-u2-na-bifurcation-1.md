## {{D:t244-u2-na-bifurcation}}. D121 決定 (7) の「非適用」を二分する — 実装が無いゆえの非適用は cap-lift の失敗に数え、択一 3 の裁定により P4 は無条件義務へ移る

**背景:** D121 決定 (7) は多世代開放 (承認上限 `MAX_APPROVED_GENERATIONS > 1`) の前提条件 10 件を
固定し、そのうち P4 と P6 を条件付き義務として「非適用は cap-lift の失敗に数えない」と書いた。
D138 決定 (5) は、この文言が **P6 を 1 行も実装しないまま承認上限の引上げを通せる恒真化**である
ことを指摘し、`NOT_IMPLEMENTED` は失敗・`NOT_CLAIMED` だけ免責という二分を提案したが、
記録済み決定の改訂にあたるため裁定パッケージへ返した。ユーザー裁定は
**「主張しないゆえの非適用」だけを免責し、「実装が無いゆえの非適用」は FAIL とする**であった。
本 D はその改訂を書く。

ユーザー裁定の正本 = `docs/worklog.md` の 2026-08-04 エントリ「T-244 の裁定 5 件が全件確定した」の
U2 の項。軸 (iii) 必須化の裁定の正本 = `docs/archive/worklog-phase3-0803-125-126.md` の
2026-08-03 エントリ (126) の択一 3 の項。本 wave の裁定 = `output/insights/2026-08-04_t244-u2-na-bifurcation/s4-adjudication.md`。
同 dir の `brief.md` は誤った前提の erratum を含む履歴であり、規範ではない。

**決定 (1): supersede は D121 決定 (7) の 2 文に限る。** 置き換えるのは次の 2 文だけである。

- 「**P4 と P6 は条件付き義務**であり、(iii) を採らない場合の P4、座標 cut を主張しない場合の P6 は
  **非適用**として扱い、cap-lift の失敗には数えない (無条件必須にすると cap が永久に解除不能になる)。」
  → 本 D の決定 (2)〜(4) が置き換える。
- 「**無条件の義務 (P1・P2・P3・P5・P7・P9・P10) は現時点で 1 件も満たされていない。**」
  → 「**無条件の義務は P1・P2・P3・P4・P5・P7・P9・P10 の 8 件である。**」へ置き換える。
  列挙に P4 を加え、**充足件数を D 本文へ凍結するのをやめる** — 件数は裁定の進行で変わるため、
  現況は本 D の決定 (5) と worklog が持つ。

この 2 文の間にある「P8 の射程は runbook 3.1 / 3.2 とし、現在の Pegasus 運用で実行不能な 3.3 は
含めない。」は**そのまま残る**。前提条件を 10 件とする列挙と D121 の他の決定も残る。
本 D は D121 全体を supersede せず、D138 も supersede しない
(D138 決定 (5) が P6 について定式化した二分を、ユーザー裁定によって確定させたものである)。

**決定 (2): 既裁定の帰結として、P4 は条件付き義務ではなく無条件義務である。**
D121 決定 (7) は P4 に「択一 3 で軸 (iii) を採る場合のみ」という発火条件を付けたが、
その択一 3 は 2026-08-03 のユーザー裁定で**必須にする**と決着した
(batch cardinality・全候補の事前 commit・seal までの結果非公開をセットで定義する)。
撤回・上書きした後続裁定は無い。よって P4 の発火条件は恒真であり、
「(iii) を採らない場合の P4 は非適用」という句は**到達不能な空文**である。

これは新しい実体裁定ではない。ただし **cap-lift の規範上の受理集合を狭める**変更ではある。
D96 が要求する 2 点のうち (1) 新しい設計判断の記録は本 D が満たす。(2) 境界テストの同時更新は、
現時点では追随すべき境界テストが存在しない (承認上限が 1 に固定されており、機械受理集合は不変で
ある) ため空である。**cap-lift を機械へ結線する変更単位は、P4 充足の正例と、P4 を非適用として
外す申請を拒否する境界テストを同時に更新しない限り land してはならない。**

**決定 (2-b): P4 の無条件性を将来ゆるめる裁定には遷移契約を課す。**
軸 (iii) の必須化を撤回または特定構成へ限定する裁定は、本 D の決定 (2)・(3)・(5) を明示的に
supersede し、P4 の代替状態を定義し、D96 の新しい設計判断の記録と境界テストを同じ変更単位で
定めない限り、cap-lift の判定には効力を持たない。裁定文の存在だけで P4 を非適用へ戻せない。

**決定 (3): したがって条件付き義務は P6 ただ 1 つであり、非適用の二分は P6 にだけ適用する。**
**非適用の理由を表す状態語**は D138 決定 (5) の 2 語を継承し、`NOT_IMPLEMENTED` と `NOT_CLAIMED`
以外を新設しない。これは非適用理由についての語彙であって、D138 決定 (3) が定めた **P6 実行結果の
4 値型は変更しない** (二値へ畳まない)。第三の非適用状態語 (先行裁定で発火条件が否定されたことを
表す語) は置かない — 唯一の用途であった P4 が決定 (2) で無条件義務になったため、
残る用途は「座標 cut は採らない」と裁定して P6 を免責する抜け道だけになる。

**決定 (4): `NOT_IMPLEMENTED` は cap-lift の失敗に数え、`NOT_CLAIMED` だけを免責とする。**
`NOT_IMPLEMENTED` = P6 の契約 (handler、全 witness-kind adapter、正負 calibration、
未知 kind の fail-closed) が実装されていないため、そもそも主張し得ない状態。
`NOT_CLAIMED` = 契約が実装済みで、その運転構成では generalized cut を主張しない状態。
判定は cap-lift を承認する人間が承認上限を 1 より大きくする前に行い、申請側の宣言は入力にすぎず
状態語を申請側に選ばせない。**状態を決められない場合は、状態を再分類せず cap-lift の承認を
保留する** (fail-closed。決定 (4-b) を見よ)。
D121 決定 (7) の「無条件必須にすると cap が永久に解除不能になる」という懸念は、
この二分で回避される — 免責の道が `NOT_CLAIMED` として残るからである。

**決定 (4-b): 状態の分類と承認の可否を分ける。**
状態語は事実の分類であり、承認判断の道具ではない。

- **現時点の P6 は事実として `NOT_IMPLEMENTED` である** — D138 決定 (5) が列挙する実装要素が
  現行 tree に 1 つも存在しないからである。
- 将来 `NOT_CLAIMED` を主張する申請が来たとき、承認者は「実装済み」を認定する基準を持たない。
  意味的充足契約 (何をもって実装済みと認めるか) も cap-lift receipt も未裁定・未実装だからである。
  **この場合は状態を `NOT_IMPLEMENTED` へ再分類せず、承認そのものを保留する** (fail-closed)。
  基準の不在は実装の不在ではない。承認を可能にする基準の定義は裁定パッケージに属する。
- 申請者の宣言、実装 path 名、test node 名だけを実装済みの証拠に数えてはならない。

この分離により、ユーザー裁定が残した `NOT_CLAIMED` の免責経路は状態語として保存される。
塞ぐのは「基準が無いまま承認する」ことだけである。

**決定 (5): 無条件義務に非適用の経路は無い。** 二分の定義域は P6 に限る。
無条件義務 (P1・P2・P3・**P4**・P5・P7・P9・P10 の 8 件) は充足か失敗の二値であり、
「非適用」を宣言して cap-lift の失敗から外す経路を持たない。決定 (2) により P4 がこの集合へ
移ったため、無条件義務は 8 件になった。

**本 D 執筆時点の充足状況 (決定ではなく事実の記録):** P10 (予算値・origin authority・軸 (iii) の
扱いのユーザー裁定) は 2026-08-04 の予算値裁定で 3 点が揃い**充足した**。残る 7 件
(P1・P2・P3・P4・P5・P7・P9) は満たされていない。以後の充足状況は本 D ではなく worklog が持つ。

**決定 (6): 本 D が塞がないことを明示する。** 塞ぐのは「実装が無いゆえの非適用」だけである。
(a) **「実装のふりをした非適用」の判定基準は無い** — 空の handler と恒真な assert でも決定 (4) の
列挙は形式的に埋まる。意味的充足の契約 (正負 calibration の具体反例、非空の限界効果を示す変異、
独立検査者) は本 D では定義しない。決定 (4-b) はこれを塞ぐのではなく、
基準が無い間は承認を保留するという fail-closed の既定にすぎない。
(b) **`NOT_CLAIMED` 構成の還流は限界効果がゼロである** — D138 決定 (1) より、generalized cut を
主張しない運転の禁止集合は exact-mask cut と一致し、受理集合を 1 点も狭めない。
「実装済みで主張しない」構成に多世代を許してよいかは、免責の話 (本裁定) と帰納段を踏む裁定の
境界であり、**本 D は決めない**。P6 が未実装である現在は発火しない論点なので、P6 実装の裁定と
同時に決める。
(c) **承認 receipt が無い** — 本 D は人間 gate の判定規則であって機械 gate ではない。
cap-lift 申請は実成果物として存在せず、判定入力を持つ field も 1 つも無い。したがって判定結果を
runbook・事前登録文書・proof chain・試行台帳・機械 gate のどこからも再検証できない。
(d) **段 8c の事前登録文書は cap-lift の証拠にならない** — 同文書は多世代化の条件を
「還流設計の裁定」とだけ書いており、本 D と P6 実装の評価を含まない。同文書は再事前登録の手続を
持つため、その改訂は専用の裁定と変更単位で行う。
(a)〜(d) はいずれも裁定パッケージへ返す。

**決定 (7): 変えない境界。** 本 wave と本 D では承認上限 `MAX_APPROVED_GENERATIONS = 1` (D114) を
変えず、cap-lift を機械 gate として結線せず、新しい機械検査・status field も新設しない
(`DW-G04` の発火 gate を満たす既存 artifact path も計測 ID も 1 件も書けない)。
**これは択一 2 の既裁定 (択一 1・3 の確定後に独立 wave で承認上限の引上げを前提条件の充足検査へ
機械束縛する) を却下・延期するものではない。** P6 の機構は 1 行も実装しない。事前登録文書
`docs/phase3-main-experiment.md` は S-1 freeze が bytes を pin するため変更しない。

**却下した選択肢:**
- 単一の `NA` のまま残す — 未実装と実装済み非主張を区別できず、恒真化がそのまま残る。
- 非適用の状態語を 3 つ以上に増やし、先行裁定による非発火を表す語を置く — 決定 (2) により P4 が
  無条件になった以上、その語の残る用途は P6 未実装を裁定文だけで免責する別名の抜け道だけである。
- 「還流の限界効果 > 0」を cap-lift の新しい必要条件に加える — 証拠となる field が存在せず、
  自己申告か永久 FAIL のどちらかになる。加えて前提条件 10 件の集合を変え、
  ユーザー裁定が明示的に残した `NOT_CLAIMED` の免責を実質無効化する。裁定パッケージへ返す。
- 「実装済み」の判定に revision 束縛の path・検査 ID・検査結果の完全な package を必須にする —
  機構が実装済みでも packaging の不足を `NOT_IMPLEMENTED` と誤記でき、
  D121 が避けた cap の人質化を別の形で作る。意味的充足契約は裁定を経て定義する。
- 依存する裁定が未了であることを個々の義務の失敗として数える — P10 (予算値・origin authority・
  軸 (iii) の扱いのユーザー裁定) の二重計上になる。未裁定は P10 の未充足として数える。
- D121 本文を in-place で編集する — 台帳は fragment + fold の追記契約で更新するため、
  既存 D の本文は改訂できない。新 D で置換範囲を逐語アンカーとともに示す。

**この決定が確定していないこと:** 決定 (6) の (a) 意味的充足契約、(b) `NOT_CLAIMED` 構成での
cap-lift の可否、(c) cap-lift receipt とその consumer 結線、(d) 段 8c 事前登録文書の改訂。
いずれも裁定パッケージへ返した。

**研究状態への影響:** production の挙動、実験の**機械**受理集合、certified 選択、材料レポート、
proof chain、凍結 bytes はいずれも不変である (承認上限 1 は変えず、実装差分もゼロである)。
変わるのは cap-lift の**規範上の**受理集合であり、決定 (2) で P4 が無条件義務へ移り、
決定 (4)・(4-b) で P6 の未実装を免責できなくなるぶん**狭まる**。
実装差分が無いため変異 matrix と受入全走は対象外である。
