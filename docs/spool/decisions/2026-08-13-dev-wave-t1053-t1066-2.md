## {{D:dispatch-env-key-admission}}. dispatch の env allowlist へ key を足す条件

**決定:** `tools/pegasus/dispatch_compute.py` の `TASKS[*].env_allowlist` へ key を足すときは、
次の 3 つを追加時に実測して記録する。(1) その key を実際に設定する consumer が repo 内に実在すること、
(2) 値の意味論 — 未設定・空文字・任意値それぞれで計算ノードの挙動がどう変わるか、
(3) 追加が挙動を**単調**にするか (最悪でも追加前と同じ挙動にしかならないか)。
単調でない key は値契約 (受理する値の集合) を同時に決めない限り足さない。
allowlist は key だけを検査し値を検査しないため、この判定は追加者の義務として残る。

**理由:**
- 列挙が閉じていること自体は「何を許すか」の判断を与えない。exact 集合 pin は追加を検知するだけで、
  追加が安全かどうかは何も言わない。
- `PYTHONDONTWRITEBYTECODE` の実測 (Python 3.10.12): 未設定 / `""` / `"0"` は
  `sys.dont_write_bytecode=False`、`"1"` を含む任意の非空文字列は `True`。
  したがって伝播は単調で、追加前より出力 (bytecode 残骸) が増える値は存在しない。
  これが「出力を減らす方向の変数だから安全」という主張の実体である。
- 子側は request の environment を string mapping かだけ検査して環境へ混ぜる (D117 の既知の恒真保証)。
  親側の追加判断が最後の関門であり、判断の根拠を記録に残さないと次の 1 語を許す論理が曖昧になる。

**却下した選択肢:**
- 追加ごとに値契約 (exact value) と receipt への environment 束縛を必須にする — 単調な key にまで
  producer と receipt schema の変更を課すことになり、1 語の追加に見合わない。
  非単調な key を足す必要が生じた時点で改めて設計する。
- 指紋 gate 側で派生物を許容して受理集合を広げる — 正しさ防壁を弱める方向であり採らない。

## {{D:fingerprint-residue-not-generated}}. probe 指紋の残骸は「消す」のでなく「作らせない」

**決定:** 非帰属 checker の probe worktree 指紋 (ignored file を含む完全一致) が
自分の dispatch した子の副作用で破れるとき、指紋の受理集合を広げたり残骸を事後削除したりせず、
**そもそも生成させない**方向で解く。指紋の最終状態 predicate (空 tree の hash だけを受理) は不変に保つ。

**理由:**
- 事後削除は、node が作った ignored file を必ず拒否するという既存契約と正面衝突する。
  一括削除も `!!` 行の除外も、明示的に書かれた異物の検出力を落とす。
- 生成させない解では、監査の意味論 (何を異物とみなすか) が 1 bit も変わらない。
  変わるのは「暗黙の import が bytecode を副産物として置かなくなる」ことだけである。
- 副作用として、暗黙 import を汚染の観測チャネルとして使う検出力は減る。これは意図した取引であり、
  明示的に書かれた ignored file・tracked 改変・pytest cache・dispatch artifact の拒否は残る。

**却下した選択肢:**
- 指紋から派生物を宣言除外する再設計 — 受理集合を広げる方向で、規律 2 に反する。
- checker が自分の残骸を消す — 既存の fail-closed テストを壊す。
  所有 nonce が確定している dispatch artifact だけは既存経路が限定削除しており、そこは変えない。
