## {{D:b4-descriptive-erratum-scope}}. B-4 の記述統計追補は人の報告主張の上限だけを限定し、機械の受理集合と実走可否を変えない

**決定:** D1936 項 8 の追補を B-4 還流 ablation 事前登録の §5.1 へ足すにあたり、
追補が確定させる範囲を次のとおり限定して本文へ明記する。

1. 限定するのは、**人が本書に基づく B-4 について報告に書いてよい主張の上限だけ**である。
   機械が生成する材料レポートの値・分類・参照は 1 つも変わらない。§7.1 の 4 分類も変わらない
   — 「有意性を主張しない」は観測された非有意ではないので、機械の判定を「判定不能」へ
   畳む根拠にはならない。
2. **追補は実走の許可ではない。** §5.1.1 の選択関数 (適格行が n 未満なら
   `design_not_feasible` として実走しない)、§5 の未記入欄、§6 の前提条件はいずれも残る。
3. 発火した条件は §5.1.1 の「適格な block を 201 件確保できない場合」であり、
   §5.1 の「予算上 n を確保できないなら」ではない。総計測予算欄は未記入で予算不足は
   確認していない。
4. 母集合の供給源と §5.1.1 の適格性述語・順序・選択関数・完全性要件、D1880 の 201 行、
   §5 の n、現行の解析 consumer が要求する block 数は変えない。
5. 「適格な少数の赤 precursor を使う」方針は維持するが、**その利用は本追補では実現していない。**
   適格 0 件であることに加え、少数を得たときに項 2 の選択関数とどう両立させるかが未解決である。
   この未解決点は裁定へ返し、AI が受理集合を単独で変えない。
6. 置き場所は §5.1 内の「n と検定単位」bullet 直後とし、凍結済みの §5.1.1 には 1 byte も触れない。

**理由:**
- 事前登録を読む consumer は §5.1.1 の bytes、§5 の固定表、floor セルしか見ず、追補の意味を
  解釈する経路が無い。実効性を機械側に期待する書き方は事実に反し、材料レポートが
  「報告型が機械的に変わった」と誤って読まれる余地を作る。
- 同じ凍結節が「適格行が n 未満なら実走しない」と「記述統計を宣言して実走するか、実走しない」を
  同時に持つ。両方を満たす読みは「宣言はするが実走しない」だけである。宣言を実走許可と
  読ませない明記が要る。
- D1936 項 8 は「本記録だけで現行 201 件 consumer が変更済みになるわけではない」と明示しており、
  項 4 はその逐語の反映である。
- 絶対規律 2 — 追補は主張の強さを下げるだけで、正しさゲートと受理集合を 1 つも緩めない。

**却下した選択肢:**
- 追補で少数行の manifest を受理可能にする — 受理集合の緩和であり、凍結節の選択関数と
  D1880 に反する。裁定も「固定 201 だけの無言の削減」を不採用としている。
- 追補を §10「本書が閉じないこと」へ置く — 同節は未閉鎖事項の説明であり、報告規範の正本に
  ならない。§0 は規範の配置先を §5.1 と §7 に限っている。
- 実効性を出すために追補を読む consumer を新設する — 依頼が gate・検査・台帳・一般化の追加を
  scope 外と明示しており、母集合を作るための追加基盤も裁定が不採用としている。
- 追補で admission record の全文 hash 束縛を更新する — 本 wave の scope 外であり、
  admission record は 3 driver 分いずれも不在で無効化される対象が存在しない。
