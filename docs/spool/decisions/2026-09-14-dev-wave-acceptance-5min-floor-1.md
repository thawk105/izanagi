## {{D:acceptance-cost-is-judged-by-value}}. 受入の費用は検出力の有無ではなく価値で判定する

**決定:** 受入全走に含めるかどうかを判定するとき、**「消しても検出力が落ちないか」を唯一の基準に
しない。** 検出力がゼロでないことと、毎走その費用を払う価値があることは別である。
価値の物差しは本プロジェクトの成果物 3 つ — certified な選択結果、proof chain 付き材料レポート、
再現可能な試行台帳 — への寄与とする。開発・運用の便宜と別研究の支援はゼロではないが、
この 3 つとは桁が違うものとして分けて数える。

同様に、**「死んでいない = 生きている = 残す」も判定にしない。** 生死は機械的な性質であって
価値の判断ではない。問うべきは「この検査は何を守っていて、それは払う費用に見合うか」である。

**理由:**
- ユーザーの指摘が正確である。「100 円投資して 1 円だけリターンがある投資をやりますか。
  1 円でもリターンがあればそこへ無限の資源を投下すると言っている」。
  検出力の有無だけで残す判定は、費用が無限大でも残すことを含意する。
- 実測が裏付ける。受入 1 走の直列和 25,745.5 秒 / 351 file のうち、**292 file (83%) は合計
  1,782.3 秒 = 全体の 6.9%** しか使っていない。安い file をいくら数えても判断材料にならない。
  **上位 35 file が 81.4% を占める。** 判定はここでしか意味を持たない。
- 価値で判定し直した結果、上位 35 file のうち相当量が CC 合成研究の成果物ではなく、
  AI の開発道具と別研究を検査していることが分かった。これは検出力の有無では見えない。

**却下した選択肢:**
- **所要秒だけで削除候補を決める** — D747 が却下したとおり、subsume を証明できない削除は
  検出力を落とす。本決定は所要秒を**候補の選定**には使わず、**価値と並べた判定**にだけ使う。
- **「安いテストを消しても wall に効かない」を理由に価値判定そのものを見送る** —
  効かないのは安い側であって、上位 35 file の判定を免除する根拠にならない。

## {{D:runner-omission-detection-stays-every-run}}. 受入の欠落検出を守る検査は毎走から外さない

**決定:** 「AI の開発道具だから毎走でなくてよい」という分類を、**受入自身が検査を黙って落とすのを
防ぐ検査には適用しない。** 具体的には、限定走・collect-only を受入扱いすることの拒否、
未 stage 削除による検査脱落の検出、前検査の拒否が実行入口で握り潰されないことの検査、
観測母集合・閉包・完了一致の負例、fallback 禁止、失敗時の証拠出力禁止である。

**理由:**
- 絶対規律 2 の本文は CC variant の正しさ判定と、その判定を弱める変更を対象とする。
  git trailer や文献検索応答の整合検査をすべて同じ意味の「正しさゲート」と同一視する根拠はない。
  **しかし「実行されなかった核心検査を実行済みとして受け入れる経路」は無関係ではない。**
  D1728 は collection 欠落の自己証明を「正しさ防壁を弱める側の変更」と明記している。
- 敵対レンズが具体的な連鎖を示した。削除前検査が回帰すると、CC の負例テストが作業木から
  消えたまま collection され、login と全 shard が同じ縮小集合を観測して集合等式を満たし、
  緑になる。**全員が同じ file system 上の欠落を観測する場合、shard 間照合では救えない。**
- したがって「runner という分類」だけを根拠に、その欠落検出の回帰検査を外すことは認めない。

**却下した選択肢:**
- **受入の道具を検査するテストは一律に毎走必須とする** — 敵対レンズがこの一般化を攻撃したが
  成立しなかった。道具の検査すべてが規律 2 の射程に入るわけではない。
- **費用が混在することを根拠に file 全体を外す** — 費用の混在は**分割の根拠**であって
  全移動の根拠ではない。

## {{D:separate-series-requires-mechanism-first}}. 別系列化は、完走証跡と期限検査が成立してから行う

**決定:** 受入の毎走から別系列へ移す変更は、**移す前に**次の 4 つを成立させる。
成立するまでは 1 file も毎走から外さない。

1. **起動と完走の分離。** 対象 commit、系列版、期待 node 集合、実際の selected / finished、
   terminal 結果、開始・完了時刻を記録する。**job ID や投入成功を完走として扱わない。**
   rc=0 だけでも成功にせず、集合一致を確認する。
2. **独立した期限検知。** 最後の適格な完走から 24 時間を期限とし、
   **起動側の記録に依存しない経路**で判定する。未起動・queue 停止・途中死も期限超過とする。
3. **未検証状態での利用防止。** 期限切れ・失敗・関連変更後未完走の間は、
   その道具の新版の有効化と、その別研究の結果の検証済み利用を拒否する。
   診断・修理・系列自身の検査経路は利用停止と分ける。
4. **関連変更時の実行。** 明示した実装・test・schema・共有 helper の変更で、
   その系列を焦点走へ加える。依存抽出だけに任せない。

**理由:**
- F485 の問題は「任意実行という名称」ではなく、**11 日間の未実行が何も止めず誰にも
  露見しなかったこと**である。「日次に走らせる」という散文は再発防止にならない。
- 現物の確認では、repo 内に CI workflow / cron / timer と、その完走・未実行監視は
  いずれも存在しない。`orchestrator/test_selection_contract.py` の `SANCTIONED_EXCLUSIONS` は
  空だが、検証実装は空集合か特定 cleanup の exactly-one に閉じており、
  **汎用の除外リストではない。** 本案の受け皿にはできない。
- 外部 scheduler に依存する部分と repo 内で完結する部分は分ける。外部が止まっても、
  **次の利用時に拒否する**ことは repo 内で保証できる。

**却下した選択肢:**
- **先に毎走から外し、機構は後から足す** — F485 の再演である。外した時点から腐り始め、
  腐ったことを誰も知らない期間が生じる。
- **外部 scheduler の日次起動だけを保証とする** — 起動成功は完走ではない。
  scheduler が止まれば検出も止まる。利用時の拒否を repo 内に置くことが最低条件である。

## {{D:acceptance-universe-split-keeps-full-collection}}. 別系列化は collection を縮めず実行母集合を分ける

**決定:** 別系列化を実装するときは、**全 collection の集合を縮めない。**
既定 suite root を全 collection した集合を `C` とし、別系列の対象 node 集合を `M` として、
毎走受入の実行母集合を `U = C − M`、別系列の実行母集合を `M` とする。

- D711 の gate 2 (全 shard の `observed_universe` 完全一致) と gate 3 (独立 login collection との
  一致) は、**引き続き `C` 全体について要求する。**
- 毎走受入では `Σ selected_i == U`、各 count = 1、file / group / affinity の閉包、
  各 shard の `finished_i == selected_i` を要求する。他の gate と失敗後の fallback 禁止も維持する。
- 各集合は**親が観測した `C` と記録された系列定義から再導出**し、
  子が報告した選択集合を権威にしない。
- **別系列の後日の完走を、毎走受入で `M` を実行した証拠として扱わない。**
  受領証に検査範囲を明記する。

**理由:**
- D1728 は「自 shard の file だけを collection する変更は採らない」「gate 2 の代替述語も
  新設しない」と定める。collection を縮めるとこの禁止に触れ、かつ
  **縮めた集合の緑は、除外した検査の実行を証明しない。**
- collection を保てば、欠落は従来どおり gate 2 / gate 3 で検出できる。
  分けるのは実行だけである。

**却下した選択肢:**
- **`U` を維持したまま実行だけ省く** — `Σ selected_i == U` の完全分割か
  `finished_i == selected_i` のどちらかが破れる。
- **全員が縮小した `C` を観測するように変える** — 等式は成立するが、
  その緑が何を証明しているかが変わる。D1728 が名指しで却下した自己証明の形である。
- **collection の短縮による固定費削減を同時に狙う** — 別の判断であり、
  混ぜると「何を証明した緑か」が曖昧になる。
