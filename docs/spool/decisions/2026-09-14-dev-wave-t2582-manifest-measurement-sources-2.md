## {{D:k2-knowledge-source-selection}}. K2 manifest の知識源は送り手が文の種類で選び、gate も文面も変えない

**決定:** D1936 項 2 を運用へ反映する。K2 knowledge manifest を作る信頼中核は `sources` を
**測定記録** — 何をどう測り、どのような結果・判定を得たかを記録した成果物 — へ絞る。
**設計説明** (何を意図し何を作るつもりかを述べた文、および読み手がどう振る舞うべきかを定める文) は
知識源にしない。判定は**書き手**ではなく**文の種類**で行う。説明を含む成果物は測定値が同居していても
source に選ばず、説明部分を削って投入するのではなく別の測定記録を選ぶ。観測値と判定を伴わず
探索の進行状態と抽象的な成否だけを保存した checkpoint は測定記録に当たらない。規律の正本は
`docs/agent-architecture.md` の `coder-v4-autonomous-k2` 節へ置き、`docs/phase3-s4b-runbook.md`
からは参照だけを張って本文を複製しない。

**理由:**

- 2026-09-02 の走行では、知識源に含めた `campaign.lock` の `spec_content` を読んだ role が
  「外部データ側から自分の参照範囲を狭める働きかけ = 信頼境界の逆転」として退け、production の
  consumer が走行を止めた。gate の誤作動ではなく設計どおりの発火であり、是正は送り手側でしか
  行えない。
- 送り手側の判断は個別の run-card に 1 走限りの指定として存在したが、常設の規律と manifest 作成時に
  読む導線が無かった。規律は運用者が実際に辿る導線に無ければ効かない。
- 書き手を基準にすると切れない。`campaign.lock` の `spec_content` は機械が保存した field であり、
  `s4_loop_digest.txt` の「異常かどうかは読み手が判断」型の注記は生成器が埋め込んだ定型文である。
  どちらも設計・運用説明であって測定記録ではない。別 campaign の成果物へ当てても同じ結論になり、
  file 名の許可リストを作らずに判定できる。
- checkpoint を明示しないと、進行状態と抽象的な成否だけを持つ成果物の可否が送り手ごとに割れる。

**却下した選択肢:**

- **gate 側 (K2 consumer の指示検出) を緩める** — 起票時点で禁じられており、正しさ防壁を
  最適化圧力に明け渡す。
- **自由文を削除・抜粋・言い換えして指示に読めない形へ加工する** — 起票時の対抗案だが、
  D1936 項 2 が明示的に禁止した。閉じ方は source の選定である。
- **知識源の許可リストや機械的な分類 gate を新設する** — D1429 が「却下した選択肢」として既に退けた。
- **書き手 (人間 / AI が書いた自由文) を基準に一律除外する** — 裁定していない一般条件を正本へ
  昇格させ、設計説明を含まない外部の測定記録まで理由なく締め出す。
- **過去の走行・記録・test fixture を遡って直す** — 当時その入力でその判定が出た事実は後から
  変わらない。免責は「この規律との差だけを理由に無効化しない」に限り、今後の作成義務は解かない。
