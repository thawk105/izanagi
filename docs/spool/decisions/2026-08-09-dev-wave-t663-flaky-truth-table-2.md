## {{D:flake-instrument-before-widening}}. 負荷依存フレークは計装が先、予算拡大は実 artifact の後

**決定:** 受入全走でしか出ない負荷依存フレークに対して、テスト側の時間予算を広げる変更を
先に入れない。まず失敗時に判定材料を残す計装を入れ、実負荷で 1 件でも artifact を得てから、
その値を根拠に予算を裁定する。本 wave では wall 3 秒 / evidence 1.0 秒 /
termination 0.05 秒 / poll 0.01 秒 / harness の外側 timeout 10 秒をすべて据え置いた。

**理由:**
- 予算拡大は**テストの受理集合を実際に広げる**。独立レンズが 4 つの拡大それぞれについて
  「拡大後だけ通る具体的回帰」を構成した (終了猶予 0.05→0.2 秒は SIGTERM 応答の
  50ms→100ms 劣化を、外側 timeout 10→20 秒は receipt 公開の 10〜20 秒級停滞を隠す)。
  根拠なき拡大は絶対規律 2 の「検証を甘くして緑にする」に当たる。
- 予算値の推定に使える実測は静穏なログインノードのものだけで、フレークが起きる
  数千件・数十並列の計算ノードの分布ではない。母集団が違う。
- 計装の目的は「どの条件が落ちたか」を実負荷で観測することである。先に予算を広げれば、
  観測したい発火機会そのものを潰す。

**却下した選択肢:**
- 余裕を一律 2 倍にする — 上記のとおり検出力を落とし、値の根拠も無い。
- 失敗時に再走して緑なら通す — フレークを隠す。真の回帰も隠す。
- production 側に時計注入の seam を作る — 正しさゲートの迂回路を作ることになる。

## {{D:flake-instrumentation-must-not-depend-on-the-flake}}. フレークの計装は、そのフレークの発火条件に依存してはならない

**決定:** 実プロセスを起動して失敗診断を発火させる meta-test は、そのプロセスの終了コードが
特定の値になることに依存して書かない。**起こりえない期待値を渡して不一致を必ず成立させ**、
assert は注入した障害が保証する内容とメッセージ構造だけを検査する。

**理由:**
- 「正常なら 0 を返す」前提で不一致を作る書き方は、観測対象のフレークが発火した瞬間に
  不一致が消え、`DID NOT RAISE` で落ちる。**フレークを観測するための計装が、
  観測したいフレークで壊れる。**
- 実測で決定的に再現した。時間予算を縮めて負荷条件を模した走行で、
  この書き方の meta-test だけが `DID NOT RAISE` を出した。
- 起こりえない期待値へ変えると、同じ走行で診断 meta-test の赤はゼロになった。

**却下した選択肢:**
- 期待値を「0 または 1」の集合にする — 不一致が成立しない場合が残り、同じ穴が開く。
- meta-test を負荷の少ない環境限定にする — 受入全走で走らないなら検出力がない。
