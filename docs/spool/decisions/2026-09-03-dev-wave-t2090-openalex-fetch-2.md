## {{D:openalex-quota-expiry-needs-ruling}}. 無償枠の発行規範を緩める実装は、窓の設計が裁定されるまで行わない

**決定:** 持続化した無償枠の観測に失効を入れて発行を許す実装は、U12 が裁定されるまで行わない。
窓に収める運用は、実行器を変えずに**呼び手が leaf の起動と起動の間で残量を読み、
窓を使い切る手前で新規起動を止める**ことで達成する。

**理由:**
- 発行規範 `remaining - reserve >= 直近観測の cost` は 2026-08-29 の改訂契約 §4.1 が凍結した
  条項である。`observed_at + reset_seconds` を期限として発行を許す式は、この規範の受理形を
  広げる。同節は**窓が明ける瞬間を観測していない**と明記しており、この式は有力な仮説であって
  観測に裏打ちされた規範ではない。意味を誤れば、期限を早く見積もる場合は予約を割って発行し、
  別の意味なら永久に停止する。
- 自己施錠は「窓を使い切ったとき」にしか発火しない。実行器は残量だけを見るので、
  最後の観測が残量 40 以上なら次窓でも素通りする。**呼び手が窓を使い切らなければ施錠は起きない**
  と 2026-09-03 に実測した (94 request 使用、終了時残量 60、施錠なし)。
  したがって凍結条項を緩めなくても、依頼が求める「窓に収める」は達成できる。
- 独立した敵対検証が、この実装を凍結契約の改訂に当たると判定した。改訂を要する変更を
  wave の裁量で既成事実にすると、正しさ防壁を緩める変異を検証なしに通す経路になる。

**却下した選択肢:**
- 失効判定を実装して同じ wave で取得も行う — 凍結条項の改訂を裁定なしに既成事実にする。
  加えて実装 commit が登録 commit になるため、証拠の鎖が main の祖先でない commit へ固定される。
- 持続化された観測を読み出し時に破棄する — 「観測なし」と「古い観測あり」を潰し、
  失敗時に最後の枠観測の証拠が消える。
- `state/runtime.json` を人手で書き換えて施錠を解く — 証拠の改竄である。

## {{D:axis1-bundle-root-outside-repo}}. 軸 1 の生 bundle は repo 外の恒久 path に置く

**決定:** 軸 1 検索の生証拠 bundle は、worktree の中ではなく repo 外の恒久 directory
(`/work/1/SFC/tanab/axis1-bundles/<日付>-<主題>/bundle`) を `--bundle` に渡して作る。
repo には URL・取得時点・digest・再開点を含む部分 mirror だけを置き、
取得が完了した時点で bundle 全体を commit する。

**理由:**
- checkpoint は `bundle_root` を絶対 path で記録し、`verify_bundle` は検証先 path との一致を
  要求する。worktree 内に置くと、その worktree を撤去した後は同じ絶対 path を作り直して
  bundle を復元しないと検証も再開もできない。2026-08-29 の走行はこれを踏み、
  2026-09-02 の調査 wave が消えた worktree path を作り直す作業に費やされた。
- 共有 main checkout の中に書くと、並行して走る変異 harness が要求する
  「走行中は共有木の観測 bytes が不変」を破り、他 wave を巻き添えにする。
- 走行途中の bundle は窓ごとに成長する。100 MB 規模の artifact を窓ごとに commit すると
  repo が膨らみ、同じものの複数世代が履歴に残る。

**却下した選択肢:**
- worktree 内に置いて撤去時に復元手順を記録する — 復元が要る設計を再生産する。
- 共有 main checkout の作業木へ直接書く — 並行 wave の変異走行を壊す。
- 部分 bundle をそのまま `verify_bundle` にかけて緑を主張する — path 集合が一致せず通らない。
  通らないものを通ると書かない。
