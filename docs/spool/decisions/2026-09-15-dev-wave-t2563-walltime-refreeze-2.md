## {{D:certify-walltime-allocation-not-bound}}. 認定較正の予約式は配分であって逐次上限ではないと明記し、数値は据え置く

**決定:** 認定較正 job の walltime 予約式について次を確定する。

1. 予約項 `1080` は**予約配分**であり、build 段の逐次上限ではない。旧表記
   `build_cap(CCBench=900 + gflags=60 + glog=120)` は job script の実体と一致しないので
   `reservation_allocation(1080)` へ改め、一致しない理由を文面へ書く。
2. `frozen_required_s` の値 6610、要求枠 7200、各 command の `timeout`、標本数、
   cooldown の各値、`finalize_reserve_s=600` は**変更しない**。受理集合は 1 mm も動かさない。
3. 計測前の `timeout` 指定値の和 3250、`3250 + 4990 + 600 = 8840 > 7200`、および
   **最大経路の完遂を保証しないこと**を、冒頭コメントと receipt へ凍結される formula 文字列の
   両方へ書く。8840 自体も `timeout` を持たない処理を含まない部分和であることも書く。
4. 本変更を「時間式の再凍結の完了」とは扱わない。D1971 の「時間式再凍結を完了扱いにしない」を
   維持し、最大経路を収容する再凍結は未解決のまま残す。

**理由:**

- 偽の内訳が新規 receipt すべてへ凍結され続けていた。実体は gflags が 3 command で 180 秒、
  glog が 3 command で 360 秒、CCBench が configure+build の 2 command で 1800 秒であり、
  third-party copy 360・pristine 検証 120・attestation probe 240・qstat 30・binary hash+nm 120・
  perf 40 の計 910 秒はこの項に 1 秒も含まれていない。値を変えずに名と説明を正すのは、
  新しい機構を 1 つも足さずに偽の主張を止める最小の手である。
- 閉じるのに新しい関門・台帳・汎用化が要る場合に**閉じず保証の限界を成果物の文面へ出す**のは、
  D1884・D1896・D1986 が採ってきた形である。本件では文面の訂正だけで足り、機構を足さない。

**却下した選択肢:**

- **要求枠を 7200 から 10800 へ増やす** — 3250 は各 command の打ち切り上限の和であって所要では
  ない。実測の計測前は 35〜39 秒であり、実績 186 秒の job のために共有クラスタへ 3 時間を要求するのは
  絶対規律 4 の「無造作に大きくしない」に反する。加えて、旧窓で打ち切られていた実行が新窓で完走して
  受理される集合が広がる。D1936 の該当項は増枠を指示していたが、後続 D1971 が既定解から外しており、
  積極的に認める根拠にならない。
- **`required_s` を配分 5590 (CLI 予約 4990 + 後処理予約 600) へ再定義する** —
  `reservation_budget()` が返す値は点数 `p` に対し `3190 + 360p` であり、既定以外の点数を渡す
  CLI 直接呼び出し (例: 開始 50 万・上限 1600 万レコードで `p=6`、必要値 5950) を新たに拒否する。
  **受理集合を狭める**ため採らない。D1986 の限定開示はこの意味変更を授権していない
  (同 D の各項は別対象であり、前文は「名指しの変更に限定」と定める)。
- **依存物のコピーや build の並行化で実時間を縮める** — D1971 で 1 対比較の実測により
  効果を帰属できず全撤回済み。再提案しない。
- **打ち切り時の公開物を撤去する関門を足す** — 下記の限界は実在するが、既存の限界であって
  本変更が作ったものではない。仮想リスク向けの関門追加に当たるため足さない。

**保証しない範囲 (文面へ出した内容):**

- 8840 は選んだ予約項の部分和であり、job の実時間上限ではない。`timeout` を持たない
  `git status`・`git worktree add`・`/proc` 全走査・worktree 削除・receipt I/O と `fsync`・
  submit receipt 待ちの最大 60 回の `sleep 1` は含まない。
- CLI 予約式の `2*sweep_reps*120` は certify では走らない予約定数である
  (`orchestrator/calibrator/sweep.py` が `certify=True` で scale 測定前に return する)。
- 計測完了前に打ち切られた attempt が部分標本から新たに `accepted` を組み立てる経路は無い。
  **ただし公開の後・正常終了の前に TERM を受けると、`accepted` な公開物が残ったまま
  wrapper が非ゼロ終了しうる。** 下流の検証は wrapper の終了コードを必須にしていない。
