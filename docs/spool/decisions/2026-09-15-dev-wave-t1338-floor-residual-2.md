## {{D:floor-residual-no-authorization}}. 8b oracle に残る床値消費 3 経路は撤去授権が無く、撤去要求の取下げはユーザー裁定へ返す

**決定:** 床値由来の受入関門 3 述語を撤去した後に持ち越されていた 3 経路 — driver の
floor/budget null refusal、budget の凍結数値 loader (`load_oracle_limits`)、report の解決経路 —
を**本 wave では撤去しない**。3 者はいずれも現用経路であり、撤去を授権する裁定が存在しない。
**撤去要求そのものを取り下げるかは、AI が裁定せずユーザーへ返す。**

**残置の根拠を経路ごとに分ける。**

1. driver の floor/budget null refusal — D1985 が「残すもの」に「floor/budget の null 拒否と
   外形・budget 値・共有性の検査」を名指ししている。D811 の却下選択肢「床値を空のまま
   `floor-null` の拒否だけを個別に解く」も同じ向きだが、**その却下が禁じるのはその案に限られる。**
2. budget の凍結数値 loader — freeze の budget を**今回の走行の資源上限**へ射影して台帳へ渡す
   経路であり、過去 throughput との比較ではない。呼出しだけを消せば limits 供給が壊れる。
   これは受理集合の拡大ではなく実行の破壊である。
3. report の解決経路 — D1984 は同経路の現用挙動を事実として記録しただけで、撤去禁止の逐語では
   ない。撤去授権も存在しない。既存 consumer test が g1 選択規則不一致の拒否理由と出力不在を
   要求している。

**同時に、先行する 2 つの記述を訂正する。**

- **D501 決定 7 の留保は既に解決している。** D510 決定 1 が最終判定から対象別 between-run floor
  との比較を撤去し、決定 3 が消える保証 4 件 (床値超・scale adequacy・oracle の一意最大・
  両構成の eligibility) を名指しで記録した。現行の判定器は床値を選択条件の値比較に使わない。
  以後、床値依存の残件を「条件 3 が逐語凍結のままだから動かせない」と説明しない。
- **「撤去はいずれも受理集合を広げる」は成立範囲を混同していた。** 局所述語の削除、経路の破損、
  最終受理集合の拡大は別の効果である。撤去案を定義しないまま受理集合への影響を断定しない。

**理由:**

- D501 決定 8 が名指した 3 述語と、持ち越し文が併記していた 3 経路は別の集合である。前者の撤去
  授権 (D1985) を後者へ流用できない。持ち越し文は 2026-08-18 に書かれ、その後の D811 と D510 を
  知らない。
- 撤去要求を書いた時点と現在では、床値の位置づけが変わっている。D496 決定 1 が外したのは
  **床値を比較の基礎として使うこと**であって、床値という概念ではない。D1758 以降の系列は
  権威 floor を exact な有理数で凍結し直す方向にあり、床値の消費経路は「やめる対象」ではなく
  「正しく充填する対象」になっている。ただしこの事実だけでは古い撤去要求の失効を証明できない —
  D1985 自身が同じ系列と共存しながら 3 述語を撤去している。**根拠は具体的な残置文・現用
  consumer の実在・追加授権の不在に置く。**
- null 拒否が保証するのは「freeze の floor/budget が null でない」ことだけである。official 由来・
  正値・pair 内部整合・性能差が床値を超えることはいずれも検査していない。門が守る性質の射程を
  これより強く書かない。

**却下した選択肢:**

- **持ち越し文どおりに 3 経路を撤去する** — 1 つは明示的な残置決定と衝突し、1 つは実行を壊し、
  1 つは撤去範囲が一意に定まらない。いずれも授権が無い。
- **依頼の破線節どおりに受入関門を作り直す** — 既に撤去した述語の再導入であり、依頼自身の
  「新しい受入条件を増やさない」とも衝突する。
- **持ち越し項目をこの wave で閉じる** — scope 外だった事実は、不要と裁定された事実ではない。
  撤去要求の取下げは人間の裁定事項である。
- **`pipeline` の generic な期待 hash gate を供給元 0 件を理由に撤去する** — D1985 が名指しを
  避けて残した対象であり、本依頼にも新たな授権が無い。既存テストが拒否・続行・不正値・省略時の
  4 挙動を検査しており、削除は API 破壊か受理拡大のいずれかになる。
