## {{D:axis3-registered-search-not-run}}. 軸 3 の登録済み検索は走らせず、軸 3 を `RW0` に据え置く

**決定 (ユーザー裁定):** 軸 3 (説明可能性) の登録済み文献検索を**走らせない**。live preflight も
本走も開始しない。軸 3 の成熟度は `RW0` のまま据え置き、**世界の不在を主張しない**。
D1760 が軸 1 OpenAlex について下した判断を、同じ理由で軸 3 へも及ぼす。

**理由:**

- **完走して得られるものの上限が低い。** `docs/related-work/README.md` 7.7.3 は、最上位の `RW4` に
  達しても無限定の「先行なし」は使えず、得られるのは「母集合と cutoff を併記した限定付きの
  未検出を人間の裁定へ提出する資格」だけだと定める。D1760 が軸 1 について述べた費用対効果の
  非対称は、軸 3 でも変わらない。
- **費用は軸 1 の残りより大きい。** 軸 3 の live preflight だけで外部 request 1929 本、
  最小間隔から導く所要は約 19 時間 26 分 (全 attempt 30 秒仮定で 22 時間 25 分)。
  そのうち 1533 本が DBLP で、末尾 1415 本が連続する。本走はさらに大きい。
- **主目的 (CC 自動合成) を 1 歩も進めない。** 軸 3 は文献の不在を主張する仕掛けであって
  合成機構ではない。B-1 (合成軸が既知軸最良を超える) は実験で埋める主張であり
  (`docs/paper-story/2026-09-02.md`: 「S-1a で測って不成立。新しい軸か、既知軸を組み合わせた
  構成でしか埋まらない」)、そこでの既知軸は CCBench に実装された軸であって文献ではない。
  **文献検索では B-1 は動かない。**
- **登録から 1 索引だけ外すことはできない。** 契約は arXiv・OpenAlex・DBLP の 3 索引を登録し、
  完走判定は全行の論理積である。OpenAlex を落とすと該当行が `unavailable` のまま残り、
  軸は構造的に `未完走` へ固定される。索引集合の変更は新しい日付の意味的 amendment と
  全枝の再実行を要する (D1207)。したがって「OpenAlex 抜きで走らせる」は選べない。

**射程 (取り消さないもの):**

- 既存の凍結物 (旧登録・索引実測・amendment・2026-09-01 の registration preflight 記録) の bytes を
  1 byte も変えない。登録 seal と catalog もそのまま残す。将来走らせると決めたときは
  同じ登録から再開できる。
- 事前登録・凍結・意味的 amendment の規律 (D1207) は不変。
- 7.7 の規則そのものを緩めない。`RW0` で許される表現の範囲は変えない。
- 直前の wave が着地させた実装 (host 別 pacing、通信失敗の再試行と冷却、未確定 attempt の
  materialize、予算検査の前倒し、N3 の記録) は残す。**走らせる決定が将来出たときに、
  接続切断 1 回で走行ごと死ぬ欠陥が無い状態から始められる。**
- **軸 3 の外部 request 数は 0 のままである。** この決定は取得済み証拠を持たない。

**却下した選択肢:**

- **live preflight だけ走らせて B2・B5 を測る** — 予算と到達性が分かっても、その先の本走を
  走らせない以上使い道が無い。1929 本と約 1 日を情報だけのために払うことになる。
- **resolver と control 評価器を実装してから 1 回だけ走らせる** — 完走しても得られるものの
  上限が低いという理由は実装しても解消しない。
- **OpenAlex を外して arXiv と DBLP だけで走らせる** — 上記のとおり構造的に `未完走` になる。

**再訪条件:** 論文が軸 3 について限定付きの未検出表現を実際に必要とし、かつ CC 合成側の
前進が塞がっていないとき。
