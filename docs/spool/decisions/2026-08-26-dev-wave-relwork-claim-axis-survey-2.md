## {{D:absence-two-kinds}}. 不在主張は内部と世界に分け、世界の不在だけを段階で縛る

**決定:** 先行研究についての不在主張を 2 種類に分ける。**内部の不在** (自分の索引・自分の調査
記録に無い) は母集合が列挙可能なので実測でき、母集合と走査に使った語を同じ文または同じセルへ
置くことを条件に、いつでも書いてよい。**世界の不在** (先行研究が存在しない) は全件検索でしか
成立せず、`docs/related-work/README.md` 7.7.3 の検索記録の成熟度 (`RW0`〜`RW4`) が
段階ごとに許す表現だけを使う。**この 2 つを 1 つの語彙で扱わない。**

**理由:**

- 内部の不在を世界の不在として読ませることが、この領域で最も起こりやすい過大主張である。
  実際に `docs/paper-story/` の初期 2 版が「先行なし」「系譜の 3 本目」と書き、
  後の版で撤回された。凍結物なので撤回済みの主張は今も読める。
- 内部の不在まで禁じると、棚卸しそのものが書けなくなる。段 6 の敵対レビューは
  「棚卸し結果を書くと不変条件違反、書かなければ依頼未達」という矛盾を指摘した。
  母集合と走査語の併記を条件にすることで両立する。
- 成熟度は調査の網羅率ではなく検索記録の再現可能性の段階であり、**主張の強さとは独立**である。
  段階が高いことは主張が正しいことを含意しない。

**却下した選択肢:**

- **不在方向の表現を段階に関わらず一律禁止する** — 内部の不在も書けなくなり、
  棚卸しが成立しない。
- **成熟度を「調査網羅性」と呼ぶ** — 序列名が「厚い = 主張が強い」「薄い = 先行が少ない」の
  両方向の誤読を誘う。実際に測っているのは検索記録の再現可能性である。
- **`RW4` 到達をもって優先権表現を認可する** — 完走で得られるのは、母集合と cutoff を
  併記した限定付きの未検出を人間の最終裁定へ提出する資格までである。
  無限定の断定の禁止は完走では解消せず、表現規律として残る (D12 の境界と同方向)。

## {{D:procedure-canon-into-existing-authority}}. 手続きの正本は新規文書でなく既存正本の節へ置く

**決定:** 母集合・検索式・除外規則・判定語彙・許可表現といった**手続きを定める文書は、
その手続きについての正本になる。** したがって新しい正本を増やしたくない場合は、
新規文書を作って「非正本」と宣言するのではなく、**既に正本である文書の新しい節として置く。**
時点ごとの実測値だけを日付付きの凍結スナップショットとして別ファイルに分ける。

**理由:**

- 「非正本」とヘッダに書いても機能上の正本性は消えない。手続きが 2 か所にあると、
  食い違ったときにどちらが優先するか決められない。
- 既存正本は `tools/check_docs.py` の `LIVING_DOCS` に登録済みで、行番号参照・現在 Phase の
  再掲・pin literal・存在しない D 番号・存在しない path 参照の検査が届く。新規文書は
  登録しない限り届かない。密な参照台帳を持つ文書ではこの差が実害になる。
- 登録のために checker を編集すると実装面が発生し、Codex author と変異 matrix が必要になる。
  既存正本へ置けばその編集自体が不要になる。**検査を避けるために形式を選ぶのではなく、
  検査が既に届く場所を選ぶ。**

**却下した選択肢:**

- **新規文書を作り `LIVING_DOCS` へ登録する** — 目的は達するが、正本の競合が残り、
  checker の編集という実装面も発生する。
- **新規文書を作り登録しない** — 上記の検査が消える。非登録でも一般的な内容の陳腐化は
  検出できないが、壊れた path 参照と D 参照は現実に起こる。

## {{D:full-text-scan-not-header-scan}}. 索引と見出し行の走査を全件走査と呼ばない

**決定:** repo 内の文書集合について「N 件だった」「0 件だった」と書くときは、
**本文全体**を走査する。索引の列、各エントリ冒頭の要約行、見出しだけを走査した結果を
「全件列挙」と称してはならない。**走査に使った語を必ず併記する。**

**理由:**

- `docs/related-work/README.md` の逆引き索引は各エントリ本文の `接地:` 行の部分集合であり、
  その `接地:` 行はさらに本文の部分集合である。実測で 2 段とも取りこぼしが確認された —
  索引が本文の接地を落とす例と、`接地:` 行が本文の接地を落とす例の両方がある。
- これは D350 / D351 が code 検索について既に裁定した内容と同型である。絞り込んだ経路の
  結果を、絞り込まない経路の結果として扱ってはならない。
- 走査語を書かない不在の記述は、後から範囲を確かめられない。有限の語彙で走査した以上、
  語を変えれば結果は変わりうる。

**却下した選択肢:**

- **索引を権威として扱う** — 索引は読み手の導線であって完全な射影ではない。
  索引が本文を落としても、索引側は赤にならない。
