## {{D:vhash-story-v3-hp-not-appendix}}. VHash 論文ストーリーの 3 版目は、止まった thread への代行による前進 (HP) を限界の節にだけ書き、付録に置かない。比較相手に ro-gcflag 修正を入れるかと題名・主張の重心は、択一と親の推奨を版に並べてユーザーの判断に返す

**決定:** (一次資料 `output/insights/2026-09-29/vhash-helper-forwarding-model/README.md` §7・§8、版 `docs/paper-story-vhash/2026-09-30.md` §0.3・§6.4・§7.1)
1. D2298 項 1 が次の版に委ねた「HP を付録に置くか」は、置かないと決める。論文の限界の節に md_16 §7.3 の文案を逐語で置き、必要条件の表 (同 §8) は一次資料に残して、同 §7.4 の再審の条件が成り立ったときに持ち込む。
   SP を CCBench 自身の長い tx で評価するには CCBench の待機ループ (`clock_delay`) に要求の確認を入れた安全点が要ることを、限界の節に併記する。
2. 比較相手の Cicada に read-only の commit でも GC flag を立てる修正 (`patches/cicada-ro-gcflag-variant.patch`) を入れるかは、版に 3 択 (入れる / 入れない / 両方並べる) と親の推奨 (両方並べる: 主比較の相手は修正を入れた Cicada、stock は修正の効果を分ける対照) を置き、決定はユーザーに返す。
3. 論文の題名と主張の重心 (VHash を名前に残す / 保持の側を中心にする / どちらも名前にしない) は、版に 3 案と親の推奨 (保持の側を中心にし、cold 契機は同じ論文に残す) を置き、決定はユーザーに返す。
4. 記録の水準 (certified 化) はこの版の判断事項に入れない。D2305 項 4 で中間案 M に決まっており、残るのは実装 (AI の手番) である。

**理由:**
- HP には C++ 試作も評価も無く、付録に置くとモデルの結果が論文の主張の一部に読まれる。Cicada の GC は全 thread の静止を待つので HP の前進は回収を進めず、評価の図に対応する量が無い。本文の U0 は SP に限る (D2298)。
- ro-gcflag 修正を入れるかは比較相手の定義を変え、論文の主比較の数値を変える。md_22 §13 は「入れるべき」と書くが、T-2933 は入れる場合に 30 秒の走行を要求しており、計算と比較相手の選択の両方がユーザーの判断に属する。
- 題名の択一を書いた一次資料は無く、構成 B は Cicada の中で上がらず (md_23)、U0 は偏りが中程度までなら実物で効いた (md_14・md_21)。重心の選択は論文の構成と次の実装の優先を変えるので、親が既成事実にしない。

**却下した選択肢:**
- HP を付録に設計候補として置く (md_16 の段 3 で判断役が推した案) — 付録の HP は本文のどの図・表とも対応せず、再審の条件も成り立っていない。
- 版の中で ro-gcflag 修正を比較相手に入れると決める — 比較相手の定義の変更で、30 秒の走行の計算を伴う。ユーザーの判断を先取りする。
- md_30 の指示どおり certified 化の案を「ユーザー判断待ち」と書く — 起点の正典では D2305 項 4 で裁定済みで、偽の状態語になる。
