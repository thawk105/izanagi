## {{D:trigger-freeze-bytes-not-semantics}}. EVOLVE-BLOCK の凍結領域は bytes の隣接だけを保証し、gate の意味論は保証しない

**決定:** trigger-gating 軸の build admission が保証するのは「凍結 template と逐語一致する block が
1 つあり、その END 行末の直後に凍結 epilogue が隣接する」ことだけである。**gate 述語が実際に
backoff の発火を決めることは保証しない。** 凍結領域をこれ以上広げる案は、閉じる攻撃面を名指しし、
過剰拒否の実測とセットで個別に裁定する。

**理由:**
- 独立した敵対検証が、block と epilogue を逐語一致させたまま gate を無効化する差分を 4 通り
  実際に書いた — 変数の再宣言 (型差し替え)、宣言と block の間の制御流変更、epilogue 直後への
  dangling `else` の付加、呼出先と引数の名前解決の差し替え。凍結領域の端をどこへ動かしても、
  隣接する未凍結領域に同型の攻撃が残る。
- 意味論まで保証するには C++ の字句解析・前処理・名前解決の再実装が要る。D48 系の先行 wave は
  自前字句解析が偽受理と過剰拒否を**両方向**に生むことを実証しており、過剰拒否は正当な build を
  止めるため fail-open と同等以上に有害である。
- したがって「どこまで凍結したか」ではなく「何を保証しないか」を書けることが、この gate の
  価値の半分である。保証しない範囲は実装 docstring に列挙し、記録では「閉じた」と無限定に書かない。

**却下した選択肢:**
- 正確な C++ 字句解析器の再建 — 上記の両方向の誤りを再導入する。
- 凍結領域の端に置く形だけの sanity 検査 (例: 凍結 bytes の直結重複だけを拒否する) —
  隣接する未凍結領域に同じ結果を生む形が受理として残るため、成果物の値の差として
  効果を書けない。守っていない範囲を守っているように読ませる分だけ有害である。
- source 全体での凍結 bytes の出現回数検査 — コメントや raw string 内の同一 bytes まで拒否し、
  実証済みの過剰拒否を再導入する。
