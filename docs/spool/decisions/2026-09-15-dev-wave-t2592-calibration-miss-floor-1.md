## {{D:calibration-records-miss-floor}}. 較正のレコード数は、既存の候補条件に加えて品質検査の取りこぼし率下限も満たす最小の値を選ぶ

**決定:** `orchestrator/calibrator/analyze.py` の選択規則を次のとおり定める。これは D1986 項 1 の
ユーザー裁定を実装したものであり、**同裁定の条件「走らせ直す前に規則を登録する」を満たすための
登録そのもの**である。較正を走らせ直すのは本決定が main へ着地した後に限る。

1. **候補集合は既存の規則が admit する集合のままとする。** 飽和基準では「その点から末尾まで
   全ステップが閾値未満」を満たす点、下限基準 (D15) では「working set が L3 の `l3_multiple` 倍
   以上」を満たす点である。飽和基準は従来どおり系列の最終点を候補から外す (後続が無く
   平らであることを確認できないため)。下限基準は従来どおり最終点も候補に含む。
2. **その候補集合の中で、LLC miss 率が `cache_floor` 以上である最小のレコード数を採る。**
   「最小」はレコード数 N の最小であって miss 率の最小ではない。走査は N 昇順とする。
3. **下限を満たす候補が 1 つも無いときは、従来どおりの採用点と従来どおりの警告を保つ。**
   飽和基準から下限基準へ乗り換えることはしない。`cache_floor_warning` を下げることもしない。
   したがって品質検査は従来と同じ点を却下する。
4. **規則は workload に依存しない。** read/write 比率や workload tag による分岐を持たない。
5. `cache_floor` (0.50%)、飽和判定の閾値、`l3_multiple`、`saturated` と `lower_bound_selected` の
   意味、結果 schema はいずれも変えない。採用点が動いたときだけ、旧点・新点・閾値を既存の
   `notes` へ書く。

**理由:**
- 書き込み主体の workload では working set の代理指標 (maxrss) と実際の LLC miss 率が食い違い、
  下限基準が選ぶ点の miss 率が品質検査の下限を割る。選択器が品質検査の却下する点を提案し続ける
  状態になっていた。下限の値を動かさないので検査は緩まず、直るのは選択器の側である。
- 候補集合を系列の全点へ広げる読みは採らない。裁定の文言は「**も**満たす最小の値」であり、
  既存の候補条件に追加する形を指す。最終点を飽和候補に含めれば、飽和を確認できていない点に
  `saturated=True` を付けることになり、下流が読む選択根拠の意味を偽装する (絶対規律 2)。
- 適合候補が無いときに従来の採用点と警告を保つのは、規則の変更が**却下の解消を目的に
  警告を消す**方向へ働かないことを構造で保証するためである。

**却下した選択肢:**
- `l3_multiple` を引き上げる案 — 実測表を見てから通る値を選ぶ形であり、絶対規律 2 が禁じる
  正しさゲートの事後緩和に当たる (D1986 項 1 が不採用とした)。
- 現状維持 — 別系統モデルの相談は「選択器と判定器を合わせた挙動が却下から受理へ動く以上、
  受理範囲は変わっている」として現状維持を推した。両論を提示したうえでユーザーが本案を採った。
  相談の論点は却下ではなく、記録として残す。
- 結果に field を足して適合の有無を表す案 — 結果 schema の key 集合は完全一致で検証されるため、
  key を足すと既存の登録済み較正成果物が検証に落ちる。既存 `notes` で足りる。

**射程の限界 (謳わないために書く):**
- 飽和候補が全て下限未満で、系列の最終点だけが両条件を満たす系列では、本規則でも却下が残る。
  候補集合を広げない判断の帰結であり、現行コードと同じ挙動である。正しい応手はスイープを
  上へ延ばすことである。
- 倍々スイープの早期停止は警告を条件に含めないため、「未観測の点まで含めて下限適合点を
  必ず得る」保証は無い。本決定の前後で変わらない。
- 既に登録済みの較正成果物を**再解析**すると `notes` の文言が変わる。採用点は動かないが
  bytes と SHA の同一性までは保たれない。既存成果物を再生成する経路は本実装に無い。
