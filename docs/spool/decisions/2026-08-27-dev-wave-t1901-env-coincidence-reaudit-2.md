## {{D:f-materiality}}. F の判定には materiality を必須とし、8 クラスの排他条件を手続きへ書く

**決定:** 環境の偶然を assert する検査の分類で、クラス F (決定的な床) を付けるには
**床の実在に加えて「上限との余裕がその床で決まっている」ことまで示す**。床と上限の比を必ず計算し、
記録する。D1055 の 2 段手続き (production 側に seam があるか、この site は渡しているか) は
この materiality 条項を持たないので、**そのまま使うと F を過剰に判定する。**

同時に、8 クラスを排他にするための必須条件を判定手続きへ書く。

- **F** — materiality。床が在るだけでは足りない。
- **T** — production への値伝播。その数値が production の締切・猶予・poll へ**到達**しなければ
  T ではない。test-local な `threading.Event` の上限や、mock の `side_effect` 内の同期上限は
  production へ到達しない。
- **H** — 別 assertion の名指し。「上限は診断と hang 回収のためだけ」と主張するなら、
  検査対象の性質は別の場所で assert されている。その `file:line` を挙げられなければ H ではない。
- **D** — 実際に待っていない場合。実時計・実 process・実 thread が関与せず、mock された
  呼び出しの引数一致を見ているだけなら D。実 thread や実 process があるなら D ではない。

materiality の**数値境界は本決定では定めない。** candidate と床/上限の比までを機械で出し、
materiality は未確定として止める。境界定数は実例を集めたうえで別途裁定する。

**理由:**
- 全数分類で候補 10 行を検分したところ、床と上限の比は最小でも 100 倍だった。
  D1055 が根拠にした実例は比 1.0015 (床 10.015 秒に対し上限 10 秒、余裕 15 ミリ秒) で、桁が違う。
- 余裕を決めない site へ F の処置を当てると空振りする。seam を渡しても余裕は変わらず、
  既に hang guard である上限を「判定から降ろす」処置も実質的に何も変えない。
  むしろ production API の不要な拡張と、内部 poll 実装をテスト契約として固定する保守負担を生む。
- 「床あり → F」「戻り値を assert → T」のような手続きだけで判定すると、同じ行が複数のクラスに
  一致する。排他でないクラス表は、分類のたびに判定者ごとに違う答えを生む。
  独立した 3 系統の検査が同じ 10 行について食い違ったのはこれが原因である。
- 数値境界を今決めると、実例 1 件からの外挿になる。同じ誤りを 2 度繰り返さないため、
  境界だけを分離して未確定のまま残す。

**却下した選択肢:**
- materiality 条項を説明とみなし手続きを変えない — F の処置 3 段 (seam を渡させる、上限を
  判定から降ろす、降格を守る control) はいずれも「床が上限をほぼ消費している」ことを前提に
  設計されている。条項は規範である。
- 比の閾値をこの決定で置く — 実例 1 件では決められない。根拠なき定数は、それ自体が
  「登録すれば通る gate」になる。

## {{D:classification-blind-decoy}}. 分類の再検証は class を隠し decoy を混ぜた盲検で行う

**決定:** 分類結果を再検証するとき、疑わしいクラスの行だけを reviewer へ渡さない。
**同数の別クラス行を decoy として混ぜ、すべての class を隠して再分類させる。**
親は答えを保持し、後から照合する。

**理由:**
- 「これらは全部 H です、検査してください」と渡すと reviewer も H を前提に読むため、
  誤りが相関する。独立した検査になっていない。
- 実測では、H 主張 28 行に非 H 28 行を混ぜた盲検で **H 主張の 26/28 (93%) が独立に再現**し、
  非 H 側は 18/28 (64%) だった。一致率の差そのものが、どちらの判定が安定しているかの情報になる。
- 食い違った行を集めて 3 本目の検査へ回せば、割れた理由を現物で決着させられる。
  多数決で決めないことが条件である。

**却下した選択肢:**
- 疑わしいクラスだけを渡して「反証してください」と依頼する — 反証を求めても、
  選択された集合であること自体が前提を与える。
- 一次分類と同じ子へ再確認させる — 同じ判断文脈が残る。
