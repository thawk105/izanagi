## {{D:tuned-adaptive-is-the-baseline}}. 既定値のままの adaptive backoff を単独の基準線に使わない

**決定:** backoff 系の性能比較で、CCBench 既定の adaptive backoff
(`kIncrBackoff = 100µs` / `kMaxBackoff = 1000µs`) を**唯一の適応側基準線として使わない**。
適応機構との比較を主張する報告は、**調整済み adaptive を対照に含める**。
調整済みの定義は「刻みと上限を、その環境で実測された静的最適点を表現できる粒度に設定したもの」で、
本測定の実績値は刻み 0.5µs / 上限 50µs である。

既定 adaptive を測ること自体は禁じない — 「CCBench を素のまま使うとこうなる」は有効な事実であり、
上流への還元判断にも要る。禁じるのは、**既定 adaptive に対する優位だけを機構の優位として報告すること**である。

**理由:**

- 既定の定数では、適応機構が到達できる状態が `{0, 100, ..., 1000}` の 11 個しかない (D1106)。
  実測される静的最適点は 3 workload とも 10µs 以下で、**この格子上に一つも存在しない**。
  既定 adaptive は機構の性能ではなく、格子と最適点の食い違いを測っている。
- 刻みを 0.5µs にすると 48 スレッドで write-heavy +159.5% / balanced +241.4% / read-heavy +329.6%
  になり、最良の静的 backoff に対して −8.2% / −1.0% / **+2.6%** まで詰まる。
  **既定 adaptive に対する優位は、定数の選択だけで消える量である。**
- 2026-07-04 の docs 整合監査が同じ穴を名指ししていた
  (「デフォルトの下手な適応にしか勝っていない、と言われたら現 docs では返せない」)。
  対処は「sweep 1 本で埋まる」と書かれたまま 2 か月未実施だった。実測が揃った以上、
  基準線の側を直す。
- 調整済み adaptive は**負荷を知らされずに負荷ごとの正解へ寄る** (read-heavy では無 backoff の
  2.3% 落ちに留まり、write-heavy では無 backoff を 52.1% 上回る)。単一の静的定数では
  この 2 つを同時に満たせない。合成の目標水準はここへ上がる。

**却下した選択肢:**

- **既定 adaptive を基準線から外す** — 上流の素の挙動は還元判断に必要で、
  測らなくなると「CCBench をそのまま使うとどうなるか」が言えなくなる。外すのではなく併記する。
- **静的最良だけを基準線にする** — 静的最良は workload ごとに別の定数であり、
  workload を知らずに選べない。適応側との比較を落とすと、合成の価値が過大に見える。
- **調整済み adaptive の定数を環境に依らない固定値として決め打つ** — 最適点は環境と負荷で動く。
  「表現できる粒度」という条件で定義し、値は環境ごとに実測する。
