## {{D:echo-ast-not-literal}}. 索引が解釈後クエリを正規化して返す場合、期待値は literal でなく typed AST で登録する

**決定:** 文献検索の事前登録において、索引が返す解釈後クエリ (echo) を完走判定に使うときは、
**期待値を literal 文字列として登録してはならない。** 索引が echo を正規化して返す場合、
**typed AST として登録し、可換 sibling の順序だけを無視して構造を照合する。**
AST が保持するのは検索フィールド名、引用句の原子性、語幹標識、AND / OR の grouping、
比較演算子と値、項の重複度である。**raw echo も全ページ保存する。**

**順序を無視して落ちる検出力は、echo とは独立した request 側の gate で補う** —
送信 request の正規形 (位置パラメータを placeholder へ置換した完全 URL) の digest 一致を
別条件として課す。D1123 が「echo の一致だけを根拠にしてはならない」と定めるとおり、
echo 照合は request 照合を代替しない。

**理由:**

- **OpenAlex は echo を正規化して返す (2026-08-27 実測)。** ブロック内の語は送信順ではなく
  辞書順へ並べ替えられ、節の順序も query の形によって変わる (括弧つき複数語では日付節が先、
  括弧なし単一句では後)。同一 request の再送には決定的である。
- **したがって literal 比較では、正しい走行が解釈照合で無効と判定される。**
  完走述語がこの形だと、その索引は原理的に完走できず、成熟度が到達不能になる。
- **粗い集合正規化も採れない。** 集合化すると field の drift (`title/abstract` → `title`)、
  句境界の消失 (`"data lineage"` → `data AND lineage`)、比較演算子の変更 (`<=` → `<`)、
  重複項の消失を見逃す。**構造は保ち、可換順序だけを捨てるのが正しい粒度である。**
- **順序を無視する向きは安全側である** — 正しい走行を誤って無効にしない。
  弱まるのは検出力だけであり、それは request 側の gate と raw echo の保存で補える。

**却下した選択肢:**

- **literal 文字列で登録する** — 正しい走行が無効になり、成熟度が到達不能になる。
- **echo を完走条件から外す** — 誤設定した query が静かに別集合を返すのを検出できなくなる。
  0 件と誤設定は索引側から同じ形 (200 + 0 件) で返るため、解釈照合は偽陰性検出の要である。
- **全 query の echo を事前に実測して literal 登録する** — 索引のレート制限では
  1543 本の事前実測が現実的でなく、実測できても正規化規則が変われば同じ問題が再発する。

## {{D:pilot-equivalent-query-disclosure}}. 事前登録の pilot が登録枝と query-equivalent なら、露出した件数を全件開示し不在の証拠に使わない

**決定:** 検索の事前登録を作る過程で、索引の構文や取得量を確かめる pilot を実行してよい。
ただし **pilot の query が登録する枝と query-equivalent である場合、次を必須とする。**

1. **該当する pilot を全件列挙し、対応する登録 query ID と露出した件数を開示する。**
2. **その件数を、対応する枝の未検出の証拠として使うことを禁じる。**
   **とくに 0 件を「そのような文献は無い」と読んではならない。**
3. **文書の性格を「cardinality pilot 後の登録」と明記し、
   純粋な pre-result preregistration であると称さない。**
4. **「本検索を 1 本も実行していない」と書かない。** 正しくは
   「正式な完走記録を 1 件も作っていない」である。

**理由:**

- **pilot は登録設計を変えるために実行する。** 実行しなければ、取得不能な設計や
  期待値の誤った登録を凍結してしまう。pilot 自体は禁じられない。
- **しかし pilot の query が登録枝と同一なら、その枝については結果を見た後に登録している。**
  2026-08-27 の軸 3 登録では、DBLP の取得設計を選ぶために測った 16 組の連言のうち
  **8 組が登録枝と query-equivalent であった。** 親は当初 1 件も開示しておらず、
  さらに 1 件の 0 件を本文へ「実測」として書いていた。段 6 の敵対レビューが検出した。
- **成熟度が低い軸では、この露出が直接の規律違反になる。** 7.7.3 は `RW0` / `RW1` の軸に
  新しい不在方向の表現を禁じる。登録枝相当の 0 件を本文へ書くことは、
  外部索引に対する未検出を先取りすることであり、この禁止に触れる。
- **開示すれば pilot の価値は失われない。** 失われるのは「結果を見る前に固定した」という
  性質の一部だけであり、それを正確に述べれば下流の主張は正しく限定できる。

**却下した選択肢:**

- **pilot を禁じる** — 実行不能な設計を凍結する危険の方が大きい。軸 3 では
  1 語で 1884 request を要する語の存在が、pilot なしには分からなかった。
- **露出した件数を伏せる** — 開示しなければ、下流の読者が登録の性質を誤解する。
- **露出した枝だけを登録から外す** — 結果を見てから枝を削ることになり、
  事前登録の意味をより深く壊す。
