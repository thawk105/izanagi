## {{D:nonenum-axis-two-walls}}. 非列挙のコード片軸は現行 hole では実体化できない — 有限幅と代理の二重の壁を確定し、条件の定義をユーザー裁定へ返す

**決定:** D48 決定 2 末尾が予約した「構文契約のメンバ読取拡張」を段階 B で消化しようとしたが、
**条件付き採用を凍結しない。** 軸オンボーディング §3-B の出口 gate (3 レンズ全員 adopt) を満たさず、
5 レンズ中 4 レンズが reject を返した。実施記録・シート記入・裁定パッケージは
`output/insights/2026-09-01_t1871-nonenum-axis-stage-b-package.md`、
逐語は `output/insights/2026-09-01_t1871-review-verbatim/` に置く。
`docs/phase3-main-experiment.md` は改訂しない。

**確定した事実 (二重の壁):**

1. **有限幅の壁 (条件の定義の問題)。** C++ の観測はすべて有限幅であり、入力空間が有限なら
   そこから boolean を返す述語の集合も必ず有限になる。`unsigned` の counter を足しても
   幅 w に対し入力点は最大 R×2^w で頭打ちになる。**したがって「非列挙」を厳密な意味的無限として
   要求する限り、コード片軸は原理的にどれも不適格である。** これは個別 hole の欠陥ではない。
2. **代理の壁 (設計の問題)。** 述語空間を広げるために hole から見える量を増やそうとすると、
   候補はいずれも D48 が明示禁止した代理になる。生の `Tidword` word は上位 32 bit が epoch
   (大域の進捗時計)、`mrctid_` / `backoff_` / epoch timer / GC・WAL 残量は run 自身の fitness 信号、
   アドレスの整数化はワーカー識別、`pro_set_` / `is_ronly_` はトランザクション種別による公平性の犠牲、
   新設した連続 abort 数は `local_abort_counts_` を絞り込んだ fitness 信号である。
   安全側へ倒し切ると残るのは派生 boolean 2 つで、到達点は対象 workload で 10、全要因でも 18 に留まり、
   うち片方は lock 系要因で恒真になる。**空間の広さと reward hack の遮断が正面から衝突する。**

**副次的に確定した事実:**

- 実行器は worker スレッド自身のスタック上に構築されるため、hole から見えるメンバに
  並行して書く主体は存在しない (単一所有は段階 B で閉じた)。
- `abort()` / `begin()` / `writePhase()` はいずれも既開通の編集面にあり、骨格が commit と abort を
  またぐ状態を信頼境界を触らずに保持すること自体は技術的に可能である。採否は別問題である。
- 既存シート path の参照は 8 ファイルで、bytes hash pin は無い。

**ユーザー裁定へ返す事項:** (1) 復活条件の「非列挙」を
「固定予算の下で操作的に列挙し尽くせない」へ定義し直すか、厳密な意味的無限を維持して条件自体を
撤回するか、保留するか。(2) 骨格が新しい状態を持つ案をこの軸で追うか — 追うなら D48 の
proxy 禁止に対する明示裁定が要る (規律 2 に触れる判断であり親の裁量で決めない)。
(3) (2) を追う場合、段階 A の人間承認 gate をやり直すか。親の推奨は (1) が定義し直し、
(2) はまず追わない。

**理由:**

- D1067 は主張を「固定予算・固定編集面の下で、事前登録した非 LLM 生成器より高い score」へ
  既に狭めている。この主張に意味的無限は要らず、必要なのは「事前登録した生成器の試行予算では
  到達 truth-vector を覆い尽くせない」ことだけである。壁 1 は条件の書き方の問題であり、
  hole を替えても消えない。
- 壁 2 の「連続 abort 数は fitness 信号ではない」という区別を、実装で保証する手立てが見つからなかった。
  規律 2 に触れる判断を、証拠の裏付けなしに親が採るべきでない。
- 拘束力ある事前登録への追記は、発火条件の成立とユーザー承認を伴う日付付き commit の時点で行う
  (D1012 の作法)。設計段階のシート単独で既裁定の射程を変えない。

**却下した選択肢:**

- 段階 B の条件付き採用を凍結する — 出口 gate を満たさない。さらに親が段 4 で中心設計を
  差し替えたため、段 3 の 2 レンズは差替え後の版を見ていない。
- 骨格所有の連続 abort 数を親の裁量で採用する — D48 が予約した「既存メンバ読取の拡張」を越えた
  新しい状態機構であり、同一軸の契約改版か新しい複合軸かの人間裁定を飛ばすことになる。
- 「非列挙」の定義を親が決めて先へ進む — 拘束力ある事前登録の意味を変える判断である。

**申し送り:** 本 wave では、親が段 4 で中心設計を差し替えた結果、段 3 の 2 レンズが差替え後の版を
見ていない状態が生じた。これを一般規則 (ドメイン正本がレンズ本数を課す設計レビューでは、
差替え後の版を要求本数のレンズが検査するまで出口 gate を満たしたとしない) にするかどうかは
**裁定境界の変更**に当たるため、本エントリでは採用せず裁定パッケージへ送る。
