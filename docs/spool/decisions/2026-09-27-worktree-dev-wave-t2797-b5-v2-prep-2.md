## {{D:b5-v2-shelved}}. B-5 v2 (backoff の値 1 個での LLM 対 非 LLM 生成器の対照) は発効せず見送り、「なぜ LLM か」の対照は関数単位のコード空間の軸で取り直す

**決定 (ユーザー裁定):** D2258 の投入準備の後、親が発効の確認 (図 1 枚 約 89〜111 node 時間、LLM の週上限で暦時間は数週間以上になりうる) を求めたところ、
ユーザーは「トップ会議に論文を通すのに重要な図になりそう？そうでないなら時間の無駄だと思う」と問い、親の見送りの推奨に対し「見送りで良い」と回答した (2026-09-27)。
B-5 v2 (`docs/b5-generator-contrast-preregistration-v2.md`) は発効しない。v1 cohort は閉鎖済み (v1 §15) のまま。D2258 の実装 (1 評価 1 job、429 の保留、LLM 親の起動器、
balanced の同時検査、report の v2 判定) は main に残し、別の軸で同種の対照を取るときに流用できる。

**理由 (親の推奨):**
- 比べる空間が backoff の値 1 個 (整数 1〜1000 µs) で、LLM が勝っても「総当たりで済む」、引き分けなら「LLM は要らない」となり、査読で決め手になりにくい。
- 値 1 個の探索では LLM 誘導が機械的探索と差が無い・write-heavy では有害という既存の否定的結果 (Phase 2、P2-5) があり、事前登録自身も同等 (失敗条件 (c)) を十分ありうる結末としている。
- backoff 軸は headline の候補から外れている (D52)。B-5 の主張も条件付き優越に狭められている (D1067)。
- 「なぜ LLM か」という査読の問いに効くのは、全部は列挙できない空間での対照で、関数単位の軸 (silo-function-policy、D2214・D2243 項 1 で段階 E) がその場所である。

**却下した選択肢:** v2 を発効して走らせる — 約 100 node 時間と数週間分の LLM 枠に対し、論文の中心主張への寄与が小さい。
