## {{D:b4-report-to-selection-deferred}}. B-4 材料レポートと certified 選択の接続は再開条件を固定して見送る

**決定:** B-4 の材料レポートを certified 選択へつなぐ接続は、本 wave では実装しない。
production / test code を 1 行も足さず、起草した設計は**却下した案**として凍結し、
再開条件を台帳へ固定する。曖昧な「上流待ち」にはしない。

再開条件は次の論理積とする。

1. 実物の材料レポート (`report.complete`) の安定した所在、または計測 ID。
2. レポート生成後の正規の呼び出し元と、その持ち主。
3. 耐久化した判定の保存先と、sink からの参照。
4. 順方向 (許可枝) を含める場合のみ — 事前登録 §5 の floor 発効と、発行可能な approval authority。

将来の実装が満たすべき設計条件も併せて固定する — fail-closed であること、caller が書いた
レポートの field を単独で権威にしないこと、対象・発行者・配置を束縛すること、sink の
**必須入力**にすること、判定を耐久化して sink から参照できること、実 artifact を実呼び出し元から
sink まで通す end-to-end の変異を持つこと。

**理由:**
- **Layer3 の正方向は構造的に閉じている。** `certifying_input` を真にする production の唯一の
  経路は、`certifying` が偽でない受領証を要求する。その受領証を作る唯一の parser は
  「どのバイト列もこの受領証を certifying にはできない」と明記して拒否する。承認権限が
  未解決であることを構造として記録している。既存テストはいずれも parser を差し替えて初めて通り、
  実 receipt のまま gate を越えるものは 1 件も無い。
- **ただし certified 側が全面的に閉じているわけではない。** D1236 の支配点は WAL の COMMIT
  合流点にあり、そちらは実際に発火する。しかし材料レポートを作るより前の sink なので、
  「レポート → certified 選択」の接続先にはならない。閉じているのは正方向であり、
  欠けているのは**レポート生成後**の呼び出し元・実 artifact・耐久参照である。
- **接続を発火させるために何かを certifying にすることは規律 2 の緩和である。** やらない。
- 起草した validator は呼び出し元を持たず、実装しても certified 選択の受理集合・材料レポート・
  台帳は 1 bit も変わらない。DW-G05 の成果物影響を書けない。
- 発火条件を満たす既存 artifact path も計測 ID も書けない。tmp に pair を作る pytest node は
  入力生成条件であって接続の発火条件ではない。DW-G04 は「書けなければ設計メモに留める」と定める。
- **起草した設計は上流解決後にそのまま使えない。** §5 未発効・floor 不在・現行の exact field 群
  という閉鎖状態そのものを検査する設計であり、floor が発効すれば前提が反転して作り直しになる。
  再利用できるのは具体案ではなく上記の設計条件だけである。したがって「プランを実装候補として
  抱えたまま上流を待つ」形は採らない。

**却下した選択肢:**
- **孤立した validator として実装し、接続とは名乗らない** — 呼び出し元が無い public API と
  拒否語彙だけが保守対象として増える。DW-G04 も満たさない。
- **scope を拡張して呼び出し元・耐久判定・sink の必須入力まで同一 wave に含める** — 実在する
  呼び出し元も実 artifact も無いため、発火証明のためだけに sink を新設することになる。
  それは仮想経路向けの gate 追加であり、別 wave が所有する file の編集も要る。
- **許可判定を型で `False` に固定して実装する** — 決して偽にならない恒真の保証になる。
  実装するなら阻害理由の集合が空かで計算し、理由集合が到達入力で実際に変わる形にする。
- **再開条件を書かずに見送る** — 実質無期限の持ち越しになり、「接続済み」という誤記も防げない。
