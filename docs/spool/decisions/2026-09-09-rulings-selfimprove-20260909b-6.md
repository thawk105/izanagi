## {{D:r17-issuer-failure-tombstone}}. 終端後の発行失敗は自動の無効化記録へつながない

**決定:** terminal 後に issuer が失敗して terminal WAL と部分 content artifact だけが残る状態を、
自動 tombstone へ接続しない。受理側が fail-closed で拒否する現状を維持し、残骸は運用で掃除する。

**理由:**

- 誤った成果物が受理へ通る経路は無い。観測された正しさ欠陥がない。
- 自動無効化は失敗経路に新しい書き込み主体と権限を作る。D1674 が権限分離を作らないと決めた面に近い。

**却下した選択肢:**

- 自動 tombstone を接続する — 失敗経路へ書き込み権限を増やす。

## {{D:r17-proposal-binding-scope}}. 提案束縛の保証範囲は正式起動器限定と明記する

**決定:** 提案束縛の保証境界を **formal launcher 限定**と明記する。B-4 marked config を受ける
すべての sink へ広げる型変更は行わない。

**理由:**

- 束縛は proposal loader 内に閉じており、`drive_iteration` / `run_one_iteration` の型には載らない。
  D1343 の文言は「実行ループ側」だが、実装の射程は loader である。
- すべての sink へ広げるには束縛を型に載せる設計変更が要る。実害の観測はない。

**却下した選択肢:**

- 全 sink へ広げる — B-4 marked config を受ける全経路の型を変える。

## {{D:r17-receipt-shard-wall}}. 受入時間の測定面は受領証へ shard 別 wall を足して満たす

**決定:** 受入全走 5 分の測定面について、**受領証 schema へ shard 別 wall の field を足す**。
D1620 の文言 (receipt が記録する最遅 shard の wall、collection 開始から teardown 終了まで) は変えない。

**理由:**

- **起草推奨は「D1620 の文言を junit 側の面へ訂正する」だったが、これは D1620 が意図して固定した
  測定面を書き換える向きである。** D1620 は「面を変えると過去の実測と比べられない」を理由に挙げており、
  文言の訂正はその理由を無効にする。別系統モデルの相談が指摘し、D1620 の本文で確認した。
- junit の `time` が D1620 の区間と右端で 2.8〜7.1 秒ずれることは実測済みで、junit 側は代替にならない。
- D1620 自身が「receipt のどの field が区間と K を示すかの文書化は AI 手番として残す」と書いており、
  field を足す方向は同決定の枠内である。

**却下した選択肢:**

- D1620 の文言を junit 側の面へ訂正する (起草推奨) — 固定した測定面を後から動かし、過去の実測との
  連続性を失う。

## {{D:r17-cleanup-two-defects}}. 掃除コマンドの既存 2 欠陥は塞がず、到達しない実測を限界として記す

**決定:** `/cleanup-branches` の裸 ref の曖昧性と `git branch -d` の判定基準について、文面での修正を
行わない。どちらも現 repo では到達しないという実測を限界として 1 行記す。

**理由:**

- tag は 1 本だけで branch 名と衝突せず、upstream を持つ local branch は削除対象外の main だけである。
- 裸 ref の修正は +22 bytes 要り、現在の余りは 2 bytes である。予算のために既存の安全義務を削るのは
  自己改善契約が禁じている。

**却下した選択肢:**

- 文面で塞ぐ — 実害の観測がないまま予算を割る。

## {{D:r17-cli-outer-catch}}. 判定器 CLI の外側の受け止めは、診断と同じ制限へ揃える

**決定:** 判定器 CLI の外側 catch が `print(str(exc))` で標準エラーへ出している値を、D1837 が診断へ課した
制限 (固定 literal か、型・文字種・長さを検査して通した値か、検査に落ちた場合の sentinel) へ揃える。
標準出力・report digest・受理集合には触らない。

**理由:**

- repo path や環境依存の git エラー文が出るのは、D1837 が「診断は外部由来の値をそのまま運ぶ経路に
  なってはならない」と定めた理由と同じ面である。
- 標準エラーは D1837 が既に診断の出口と定めた場所で、そこの規則を揃えるだけの局所修正である。

**却下した選択肢:**

- 現状維持 — 環境依存文字列が出続け、再現性の主張に穴が残る。

## {{D:r17-materialize-canonical-compare}}. 認証成果物の再導出一致は canonical JSON で比較する

**決定:** A-2 certification の materializer の再導出一致検査を、partial (v2) と full (v4) の両側で
`_canonical_json(report) == _canonical_json(expected)` へ変える。

**理由:**

- Python の `dict ==` は `True == 1` を同一視するため、JSON 型だけ違う偽造 report が certified 成果物として
  通る。`materialize` は認証成果物を作る唯一の関数であり (D1841)、そこの一致判定が型を見ないのは
  恒真に近い保証である (規律 6)。
- 既存 helper を使う局所修正で、受理集合を狭める側である。

**却下した選択肢:**

- production CLI からは到達しないので現状維持 — 直接呼出し境界の穴が残る。

## {{D:r17-no-replace-objects}}. 凍結 spec の git object 問い合わせに差し替え無効の指定は付けない

**決定:** 凍結 spec の全 git object query へ `--no-replace-objects` を付けない。
`refs/replace` が本 repo に存在せず作る運用も無いことを前提として明記する。

**理由:**

- 対象が存在せず、実害の観測がない。全 query へ引数を足すのは変更面が広い。
- 「仮想リスク向けの gate 追加は scope 外」という立っている指示に当たる。

**却下した選択肢:**

- 全 query へ付ける — 実在しない危険への広い変更になる。

## {{D:r17-issuer-loaded-head}}. 発行器は転記の前に読み込み済みの先頭と照合する

**決定:** issuer が `summary["loaded_head"]` を検証せず成果物へ転記している件を、
load 済み spec の `loaded_head` との 1 比較で塞ぐ。

**理由:**

- 検証せずに転記するのは、成果物が申告値をそのまま名乗る形であり恒真な保証である (規律 6)。
- 既に load 済みの値との 1 比較で、新しい機構を作らない。
- 「本 wave 以前からある形」であることは直さない理由にならない。

**却下した選択肢:**

- 現状維持 — 成果物の値が実際に load した head と違っても検出できない。

## {{D:r17-genome-flag-grammar}}. 遺伝子表現の flag 名は区切り 3 文字を拒否する

**決定:** `Genome.canonical()` で、flag 名に `|` `,` `=` を含む値を拒否する。
protocol の許可リストや CCBench source 束縛へは寄せない (D1696 の再訪条件が未成立)。

**理由:**

- 正準形が壊れると identity が別物を同一視しうる。認証の入口にある実在の表現欠陥である。
- 3 文字の拒否は共有 helper 内の局所修正で、許可リストより射程が小さい。
- issuer は共有 helper の解釈に従うので、issuer 側だけでは締められない。

**却下した選択肢:**

- 許可リストや source 束縛と併せて裁定パッケージにする — D1696 の再訪条件が未成立で、範囲が膨らむ。

## {{D:r17-dw-o26-checker}}. 受入前に repo 全体を走る検査を叩く義務を手順書へ足す

**決定:** 焦点走が参照関係で対象を引くため repo 全体を走査する checker 系 test を集められない件について、
**受入前に `--repo` を取る checker を叩く義務を `DW-O26` へ足す**。byte 予算に収まらない場合は
D782 が委任した D730 の手順 (既存記述の削減 → 独立 3 例なら例外収容 → それでも無理なときだけ上限引き上げ) で
閉じ、上限引き上げに至った場合だけ報告する。

**理由:**

- F521 型を 2 回踏んでおり実害の実測がある。恒久対応が failures 台帳にしかないのは「読まれない場所に
  しか無い」型で、3 回目を踏む。
- docs と checker の byte pin を一緒に変える手順は確立している。

**却下した選択肢:**

- failures の記録に委ねる — 読み経路に義務が無いまま再発する。

## {{D:r17-formula-id-bump}}. 診断カウンタが動く算出式は版を上げる

**決定:** 診断カウンタ (`rep_integrity_failures`) が「rc=0 で終了したのに stdout 解析で例外を捕捉した rep」
1 件で 0 から 1 に変わる場合、`FORMULA_ID` を**改版する**。旧版の測定時点の意味は遡及変更せず、
新版の successor として再発行する。着手前に「診断も算出式に含む」という契約側の明記を現物で確かめる。

**理由:**

- 起草推奨と単位 C2 の親推奨はいずれも「改版しない」だったが、別系統モデルの相談が
  「`s8b_floor_stats` は診断も算出式に含むと明記しており、0→1 は実測済みなので据え置きは版契約違反」と
  指摘した。版契約に照らすと改版側が正しい。
- 凍結済み成果物の bytes を変えないという要請は、旧版を据え置き新版を successor として出すことで満たせる。
  旧版の測定時点の意味は変えない (規律 7)。
- **相談が引用した「診断も算出式に含む」の明記を、本 /rulings では現物で確認していない。**
  実装 wave が着手前に確かめ、明記が無ければ本決定を追記で訂正する。

**却下した選択肢:**

- 改版しない (起草推奨・親推奨) — 算出式の版が実際の算出内容と食い違ったまま残る。
- 凍結成果物の bytes ごと差し替える — 測定時点の事実を後から動かす。

## {{D:r17-holds}}. 3 件は実測を取ってから決める

**決定:** 次の 3 件は、必要な実測が揃うまで裁定しない。実測後に改めて索引へ載せる。

1. **変異 harness の外側監視の契約区間。** 監視が queue 待ち・RUN 後・cleanup のどこまでを覆う契約かを
   決める前に、区間別の所要と、既存 artifact を混雑下で走らせたときの実際の発火を測る。
2. **認証系列 A-2 の並列数を 5 にするか。** A-6 の実走資料自身が nodes=5 の結果を A-2 へ一般化しないと
   明記している。A-2 固有の 5-node 実走か同等の probe で、出力同値性・所要短縮・queue 費用を確かめる。
3. **未配線の関数の配線をどの作業単位へ割り当てるか。** 「同梱すると受入が 5 分を超える」は未確認である。
   単位を延長した場合の追加 node と wall を測ってから分割の可否を決める。

**理由:**

- 3 件とも起草推奨は方向を決めていたが、別系統モデルの相談がいずれも根拠不足と判定した。
  実測で決まる問いを推測で決めると、後から覆る。
- 実測はいずれも既存の道具で取れ、新しい機構を要しない。

**却下した選択肢:**

- 起草推奨のまま決める — 実測で覆りうる判断を既成事実にする。

## {{D:r17-ratify-seven}}. 第 16 回が収載を命じた 7 件は追認し、新しい判断を加えない

**決定:** D1836 が索引へ収載すると裁定した 7 件 (公表層の残り実装の保留終端、直接投入経路の保護範囲、
凍結済みレポートの認証範囲、本番の受入不成立の原因調査、受領証のソース閉包、関門の失敗理由の第 2 成果物、
旧形式の機械導出) を**追認する**。いずれも論点は決着済みで、残るのは実装・調査である。
ただし直接投入経路の保護範囲については、D454 本文と 2026-08-16 の裁定のどちらが優先するかを
実装前に正本で確かめる。

**理由:**

- 個別に再裁定すると決着済みの論点を毎回ユーザーへ返すことになり、D1704 の却下欄が禁じた形になる。
- D1836 が収載を命じているので索引からは落とさないが、新しい判断は要らない。
- 保護範囲の 1 件だけ、別系統モデルの相談が「D454 本文と後続 worklog が食い違う」と指摘した。
  優先関係を確かめるまで実装済み裁定として扱わない。

**却下した選択肢:**

- 索引から落とす — D1836 の収載裁定に反する。
- 7 件を個別に再裁定する — 決着済みの論点を返し直す。
