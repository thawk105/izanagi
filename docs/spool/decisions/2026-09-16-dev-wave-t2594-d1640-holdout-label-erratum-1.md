## {{D:d1640-holdout-label-erratum}}. D1640 の保持群ラベルを H1 = rr80、H2 = rr20 と訂正し、他の決定内容は維持する

**決定 (D1986 項 2 の追補、AI 実施):** D1640「値」の末尾にある
**「H1 = rr20、H2 = rr80 で別々に持つ。」を「H1 = rr80、H2 = rr20 で別々に持つ。」と訂正する。**
H1 の `R_h` は rr80 の凍結済み `PerfConfig` で測る stock 参照、H2 の `R_h` は rr20 の凍結済み
`PerfConfig` で測る stock 参照である。各 holdout の `delta_min = 0.03 × R_h` は、**その holdout 自身の
`R_h`** から定める。他方の holdout の参照値を割り当てない。

**訂正の射程 — ラベルと workload の対応だけを正す。** 係数 0.03、向き (on − off)、単位 (毎秒
トランザクション数の絶対値)、`R_h` の測り方 (records 1,000,000 / threads 48 の凍結済み `PerfConfig`
で stock silo を pilot の最初の block より前に 5 反復・trace-disabled・同じ env_tag で測った
session-median throughput)、create-only の参照 artifact への記録と絶対値の機械的転記、記入の時期
(8b descriptor 設計 §10.2 の検証 consumer の条件と D1326 の順序) は、いずれも D1640 のまま変えない。
**本追補は参照測定の投入・値の記入・実装着手のいずれも新たに認可しない。**

**凍結の権威と、それが正であることの確認 (本追補の起草時に実測):**

- `orchestrator/campaign/s8b_holdout_freeze.py` の `HOLDOUTS` は rr80 を H1、rr20 を H2 と定義する。
  `orchestrator/campaign/trial_registry.py` の `HOLDOUT_BINDINGS` はその定義から導出される。
- 凍結成果物 `output/s8b-freeze/holdout_freeze.json` も rr80 = H1 (rratio 80) / rr20 = H2 (rratio 20)。
- 当該定義の 4 行は `31426fb9a` (2026-08-29) と起草時点で byte 一致する。
- **2026-07-16 の 8b 設計発効でユーザー自身が「holdout = H1 (rr80) + H2 (rr20)」を選択している。**
  `docs/phase3-8b-descriptor-design.md` の承認記録と §3.1 の表も同じ対応を書いている。
- したがって誤りは決定側の記述にある。**凍結側のコードと成果物は本追補で 1 byte も変えない。**

**理由:**

- D1986 項 2 が「決定側の記述を追補で正す。凍結側は触らない」と確定した。過去の裁定は追記でのみ
  訂正する (絶対規律 7)。決定を書き換えて遡らせない。先例は D1694 (D1641 の理由文を追記で訂正し、
  決定の効力は維持した)。
- 逆対応のまま逐語適用すると、各 holdout の実質効果境界が**他方の** workload の参照値から作られる。
  参照値に差があれば、高い参照値を持つ側の境界が過小になり、その holdout の成立集合は広がる。
  **ただし他方の境界は過大になるので、両 holdout を合わせた受理集合が単純に広がるとは断定しない。**
  どちらが過小になるかは rr80 と rr20 の参照値の大小に依存し、その参照測定はまだ取得していない。
  読み比率だけから大小を決めることはできない。
- 追補を残さず運用上の読み替えだけで済ませる案を D1986 項 2 が却下している。決定側に誤った逐語が
  残れば、次に D1640 だけを読む者がそれを適用する。

**本追補が主張しないこと (保証の限界):**

- **機械的な再発防止を足していない。** 既存の検査は主体で分かれる。事前登録側は holdout の key 集合・
  workload 束縛・値の型・有限性・符号を見るが、**単位と向きについては空でない文字列かを見るだけ**で、
  凍結値との一致を照合するのは判定器の側である。**どちらの主体も、各値が指定された holdout の
  stock 参照から算出されたことは照合しない。** F965 の再発検知も目視である。
  本追補はこの照合を新設しない。
- **現行経路での誤受理を実証したものではない。** 判定器が受け取る対比パラメータは現状 1 組で、
  holdout ごとに別の `delta_min` を渡す接続は確認していない。上の向きの議論は判定述語からの
  条件付き導出である。
- **D1640 の旧節だけを切り出して読む consumer へ、本追補の存在を機械的に通知する経路は作らない。**

**却下した選択肢:**

- 凍結側を作り直す — D1986 項 2 が却下済み。正しい側を動かし、下流の束縛を焼く。
- 追補を残さず読み替えで済ませる — D1986 項 2 が却下済み。誤った逐語を適用する余地が残る。
- D1640 の効力ごと失効させる — 誤りはラベル 1 点であり、係数・向き・単位・測り方は独立に成り立つ。
- 割り当てを照合する gate をこの追補と同時に新設する — 本件の裁定は記述の訂正であり、
  gate の新設は別の裁定を要する。残件として worklog へ置く。
