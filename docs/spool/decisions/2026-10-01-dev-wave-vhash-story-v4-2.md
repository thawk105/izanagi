## {{D:vhash-story-v4}}. VHash 論文ストーリーの 4 版目は、書き始める前に着地した md_42 を着地済みの入力として扱い、§0 で方針「条件 C で最高水準より大きく速い」の証拠が起点で無いことを隠さずに書く。本文第 3 稿は依頼の範囲どおり md_42 を本文に入れず、冒頭の地位の欄に書く

**決定:** (版 `docs/paper-story-vhash/2026-10-01.md`、第 3 稿 `output/insights/2026-10-01/vhash-manuscript-draft-v3/README.md`)
1. 依頼は md_42 を稼働中として「未着地」と書くよう求めていたが、wave が利用上限で止まっている間 (2026-10-01 00:4x〜09:4x JST) に md_42 が着地した (04:57 JST の commit `17c8e0e78`、D2337)。
   書き始める前だったので、版の起点を `74029b18f` から `63378acb8` へ ff-only で進め、md_42 を着地済みの入力として扱う。依頼の「先取りしない」は、推測で結論を書かない趣旨と読む。
   起点の後に着地したもの (md_43、D2340、10:03 JST) は本文に入れず、README の stale 注記に積む。
2. §0 は D2322 項 1 の案 2 で書く。芯は U0 (実行中の前進を確認 → 確定 → 公開の順で保護下限へ反映する機構)。U1 は、実在する構成 C (論理 K 境界、throughput の差なし) と未実装の構成 D (hot の外れで前進し GC へ反映) を分けて書く。
   題名の案は副題を目的の句でなく機構の句にし、回収を縮める目的・境界の規則・前進そのものを新規と読ませない。どの題名を使うかは本文の改版で決める。
3. §0.2 に方針との照合表を置き、親の読みとして次を書く: (a) 方針の形の証拠は起点で無い (U0 の throughput の差は stock に対しても未検出、修正済みの最良 Cicada とは未比較)、
   (b) md_42 は hot 配置と構成 C の判定材料で、U0 は欠測、(c) 確認段 S2 の主指標は回収境界の遅れと生存版数で、方針の問いに直接は答えない、(d) 長い読み手の費用は今の U0 の対象外。
   D2337 の推奨を受け入れるか、長い読み手を攻める機構の天井を測るか、S2 を発効するかはユーザーの判断に返す。
4. 第 3 稿は、第 2 稿の付録 C の空欄のうち md_33・md_35・md_37 を埋め、md_44 を §2.3・§8 に足し、埋めたことで食い違う記述 (中間案 M の「未実装」など) だけを直す。md_39 は空欄のまま残す。
   md_42 は冒頭の地位の欄に、要点と本文に入れない理由を書く。第 2 稿は書き換えない。

**理由:**
- md_42 は一次資料と決定として着地しており、版の起点を進めずに「未着地」と書くと、書き始める前に手元にあった判定材料の結論を欠いたまま版が凍結される。依頼の目的 (結論を推測で先取りしない、完了条件にしない) は、着地済みとして扱っても損なわれない。
- README の契約は、版を起点の正典から導出し、起点の後の着地を stale 注記で指すと定める。執筆後の着地まで追って起点を進め続けると版が閉じない。
- ユーザー方針 (論文は大きな性能向上が出たものだけ) に照らすと、throughput の材料が無いことは論文の成否を左右する事実で、§0 に置かないと読み手が見落とす。
- 依頼が第 3 稿の範囲を名指しで限っているので、範囲外の着地 (md_42) を本文へ入れると依頼を超える。地位の欄に書けば読み手は取り違えない。

**却下した選択肢:**
- 起点を `74029b18f` のままにし、md_42 を「未着地」と書いて stale 注記で指す — 契約の形は保てるが、書き始める前に着地した判定材料の結論が §0 から欠け、依頼の「md_42 がその判定材料であることを §0 で隠さない」を満たしにくい。
- md_43 も取り込むために起点を再び進める — 執筆後の着地で、版が閉じなくなる。stale 注記で足りる。
- 第 3 稿の本文に md_42 を入れる — 依頼が名指した範囲を超える。
- §0.2 で「U0 も方針を満たさない」と書く — md_42 で U0 は欠測で、方針に照らした U0 の判定材料は起点に無い。
