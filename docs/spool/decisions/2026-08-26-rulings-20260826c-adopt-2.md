## {{D:b2-generation-outcome-unit}}. generation/search arm の出力単位は最終世代の canonical variant とする

**決定 (ユーザー裁定):** generation/search 実験で 1 arm の outcome とするのは、`G=2` の
**最終世代の canonical variant** である。proposal sequence 全体を outcome にしない。
合成の後に決定論的 selector を置いて現 judge を流用する案も採らない。
判定 3 条件のうち入れ替え追従は、生成された variant の bytes 一致では恒に不成立になるため、
descriptor 条件付きの予測構成へ正規化した比較へ読み替える。全 proposal は 8b 設計が定める
全件報告義務の対象として残し、outcome 単位とは区別する。

**理由:**
- 全案の保存は file-drawer 防止の報告義務であって成果物の単位ではない。8b 設計が両者を別条項で
  定めている。
- 世代 1 の情報は 8c 事前登録が凍結した閉じた集合を通じて次世代へ運ばれるため、最終世代を
  採っても世代を跨いだ改善を捨てることにならない。
- selector を後置する案は合成効果と選択効果を交絡させ、8b §1 が置いた「selector 実験は
  descriptor 条件付き合成の証拠に数えない」境界を実質的に壊す。

**却下した選択肢:**
- proposal sequence 全体を outcome にする — 失敗 proposal の扱いと sequence 同士の一致の意味が
  未定義で、受理規則を作り直すことになる。
- 合成後に決定論的 selector を置く — 交絡する。

## {{D:b5-claim-scope-conditional-superiority}}. B-5 の主張を凍結対照に対する条件付き優越へ狭める

**決定 (ユーザー裁定):** B-5 の主張は「LLM でなければ到達できない」という必要性ではなく、
**固定予算・固定編集面の下で、事前登録した非 LLM 生成器より高い score だった**という
条件付き優越へ狭める。論文素材 §8 の B-5 欄の文言も同じ範囲へ揃える。
D52 の系レベル設計へ戻す案は、適格軸が 1 本も実体化していない現状では採らない。

**理由:**
- 段 3 の敵対相談 2 本が独立に同じ識別上の行き止まりへ到達した。対照相手を有限の型に閉じ
  LLM を閉じないと空間の広さの比較になり、両方を閉じると完全列挙器が構成できて非列挙条件と
  衝突する。実装を足しても消えない。
- 証拠が支える範囲を超えた主張を残すことは、正しさシグナルを後付けにしない規律と同じ面に触れる。

**却下した選択肢:**
- 必要性のまま残す — 現設計の証拠が支えない。
- D52 の系レベルへ戻す — 走らせる対象の軸が無い。

## {{D:main-merge-single-commit-restore}}. 実装面が重なる main 取り込みを 1 commit へ戻す

**決定 (ユーザー裁定):** 両親が同じ実装面 path を触る main 取り込みを 2 commit へ分ける
D770 を supersede し、mid-merge の author 起動を使う 1 commit 手順へ戻す。次の 3 条件を課す。

1. mid-merge capability の stage / sandbox 限定を緩めない。
2. 1 commit 化した merge commit が Codex author trailer を持つことを provenance 検査で確認する。
3. 正本を書き換える前に、mid-merge の live 起動を実データで 1 回通す。

**理由:**
- D770 が分割を要した原因は authority 文書の working bytes と HEAD blob の不一致だけであり、
  D785 がその原因を直接除去して実装も着地している。根拠が消えた規則を残す理由がない。
- 取り込みは全 wave が毎回通る経路であり、現行手順の費用が最も大きい。

**却下した選択肢:**
- 2 commit のまま据え置く — 原因が消えた後も費用だけが残る。
- 3 条件を付けずに戻す — 実データでの成立を確認しないまま正本を変えることになる。

## {{D:resume-authority-surface-unusable}}. 終了コードを根拠にした復帰 authority は登録しない

**決定 (ユーザー裁定):** 処理系の終了コードを根拠にした復帰 authority は**登録しない**。
D1006 の「値と理由の対応表が確立するまで登録しない」という条件文は、後続の実測で
**どの値も事由を名指ししない**ことが確定したため成立しえない。条件文を撤回し、
「この surface は根拠として原理的に成立しない」という確定形へ改める。

**理由:**
- 成立しえない条件を台帳に残すと、永久に発火しない再訪条件として滞留する。
- 別の証拠源を探す案は、候補を名指しできない段階で開くと終端の無い待ちを作る。

**却下した選択肢:**
- 別の証拠源を選ぶ — 探索対象が名指しできていない。
- D1006 の条件文をそのまま残す — 前提が偽であることが確定している。

## {{D:ratification-gate-scope-widen}}. 批准検査を artifact 受入と dispatch へ広げる

**決定 (ユーザー裁定):** 批准検査を新規 lock 作成経路だけでなく、**artifact 受入と dispatch でも
発火させる**。既存 lock を読む経路が記録 commit blob と記録 digest の一致しか見ないため、
正しい blob map を持つ未批准 lock が受入を通りうる穴を塞ぐ。
D1028 が批准 gate の定義域の外へ意図的に出した非認証成果物型は、対象に含めない。

**理由:**
- 受理集合を狭める方向であり、穴は現物で確認されている。
- 中断再開時にも批准を再検査すると既に裁定されており (D1039)、同じ主題で方向は確立している。

**却下した選択肢:**
- D906 の受領証の着地を待って寄せる — D906 が束縛する対象に enforcement closure digest は
  含まれておらず、代替にならない。
- 現状維持 — 未批准 lock が受入を通る経路が残る。

## {{D:ratification-revocation-record}}. 批准の撤回を正当操作とし、行削除でなく撤回記録で表す

**決定 (ユーザー裁定):** 人による批准の撤回を**正当操作として認める**。ただし批准行の削除では
表現しない。**対象 digest と、AI が偽造できない人間権限の双方を束縛した撤回記録の追記**で表す。
批准台帳が既存行を落とさない追記のみの規則 (D994) は不変とする。

**理由:**
- 批准は closure 版ごとに効くが、台帳は追記のみで古い digest が残り続けるため、
  誤った批准は新しい版へ批准し直しても無効化されない。永久側は誤批准を永久に効かせる。
- 行削除を撤回の表現にすると、台帳の追記のみ規則と正面から衝突する。

**却下した選択肢:**
- 批准を永久とし現行の拒否を確定する — 誤批准を取り消す手段が無くなる。
- 行削除を許す — 追記のみ規則を壊し、履歴から撤回の事実が消える。

## {{D:synthesis-audit-projection-terminate}}. 合成監査の事前射影は実装しないで終端する

**決定 (ユーザー裁定):** 合成監査の事前射影を決定的に生成する機構は**実装しないで終端する**。
D1011 が付けた 3 前提のうち「必須経路への配線」は、正規の main 取り込みが待ち手の自動処理で
行われ間に停止点が無いため満たせない。再訪条件を
**「必ず通る経路に停止点ができたとき」**へ書き改める。

**理由:**
- 停止点の無い経路へ足した機構は、親が思い出したときだけ通る位置にしかなく、恒真な関門になる。
- 速度の主張は現物 2 件で既に反証されており、主目的からも遠い。

**却下した選択肢:**
- 取り込み手順の変更に従属させる — 待ち手の自動処理は分割手順でも同じく存在するため、
  従属関係が成立しない。
- 前提未成立のまま裁定待ちに置き続ける — 発火しない待ちが滞留する。

## {{D:prohibited-uses-no-dormant-gate}}. 禁止用途の宣言に consumer gate を今は置かない

**決定 (ユーザー裁定):** pair receipt の禁止用途宣言を機械的に拒否する consumer gate は
**今は置かない**。当該成果物を正式入力として読む消費者が 1 つも存在しないためである。
代わりに (a) 当該欄が権威でないことが名前から分かる形へ改め、(b) 実際の ingestion 経路が
できる変更と**同じ単位で、単一の受入口に拒否を置く**。

**理由:**
- 消費者の居ない場所へ拒否を置くと、拒否対象が到達しない休眠 capability になる。
  型と consumer を同一変更単位で作る D1028 の趣旨と同じ面である。
- 5 面へ同時に触ると proof chain 全体の再検証が同時に来る。

**却下した選択肢:**
- 2 consumer から段階的に置く — 消費者が居ない以上、段階の最初から休眠である。
- 宣言のまま何もしない — 権威でない欄が権威に見える状態が残る。

## {{D:figure-frozen-verdict-exception}}. 作図規約に凍結済み判定値の限定例外を置く

**決定 (ユーザー裁定):** `tools/plotting/FIGURE_CONVENTIONS.md` §1 に、
**凍結済みの判定値と p 値に限り、hash 束縛された検証済み凍結 report を権威としてよい**という
限定例外を書き足す。条件は 3 つとする。(a) 参照先が hash 束縛され検証済みの凍結 report である、
(b) 例外の対象は凍結済みの判定値と p 値に限り、生の測定値と集計値は WAL/dat から再計算する、
(c) report 自身の自己申告 hash だけを検証済みと数えない。

**理由:**
- 作図側で判定を作り直すと判定器が 2 つになり、正しさゲートを緩める面に触れる。
- 例外を書かないと、以後の図が部分適合を再生産し続ける。

**却下した選択肢:**
- 部分適合のまま据え置く — 同じ状態が積み上がる。
- 例外を無条件で書く — 自己申告 hash を権威にする経路が開く。

## {{D:certified-source-closure-transitive}}. certified 経路の source closure を推移閉包へ広げる

**決定 (ユーザー裁定):** certified 経路が束縛する材料の集合を、委譲先まで含む**推移閉包**へ広げる。
実装は段階的でよいが、保証の文言は閉包が閉じるまで広げない。

**理由:**
- 現行の 8 path には verifier / calibrator / buildcache が入っておらず、**verifier だけを弱めても
  既存 lock の照合を通り、誤った variant が certified になりうる。** 正しさ防壁自身が
  束縛されていない穴であり、最適化圧力が最初に攻撃する面である。
- 親が当初これを粗い provenance の問題へ分類したが、敵対レビューがその分類を覆している。

**却下した選択肢:**
- 現行範囲に限定し記録後の drift 検出だけを保証と名乗る — 委譲先の差し替えが成果物のどの値
  からも検出できないまま残り、「source-bound」と名乗れない。

## {{D:masstree-build-tool-authority}}. 事前ビルド道具の身元は独立した期待権威で照合する

**決定 (ユーザー裁定):** 依存ライブラリの事前ビルドが使う道具の身元は、検証済み絶対 path への
束縛ではなく、**生成物に対する独立した期待権威**で照合する。期待値の入手経路を設計と同時に決める。

**理由:**
- 現行は環境から素の名前で道具を解決し、生成後の archive hash を初めて観測してそれ自身を権威に
  するため、細工した道具が pin 一致する `config.h` を残したまま悪性 archive を作れる。
- 絶対 path への束縛は環境ごとに壊れるうえ、「その path の道具が正しい」ことの保証が別途要り、
  信頼の根を 1 段ずらすだけである。

**却下した選択肢:**
- 検証済み絶対 path へ束縛する — 信頼の根が移動するだけで閉じない。
- 現状維持 — 因果鎖を閉じたと主張できないまま残る。

## {{D:formal-series-artifact-authority}}. 正式系列の 3 artifact は設計文書を権威として導出する

**決定 (ユーザー裁定):** 正式実験系列を止めている 3 つの設定 artifact は、**設計文書を権威とし、
そこから機械的に導出した値として発行する**。導出であることを機械で照合できる形にする。

**理由:**
- 人が値を確定する形は、値を変えるたびに承認の手番が発生して系列が止まる。
- 設計文書の承認 1 回で発行できる形なら、人間の権限は保ったまま滞留が消える。

**却下した選択肢:**
- 値ごとにユーザーが確定する — 実験のたびに承認待ちが再発する。
- 権威を決めずに暫定値で起動する — 事前登録の意味が消える。

## {{D:condition18-adapter-or-removal}}. 実運用 consumer と同じ単位で結線するか、解決器ごと撤去する

**決定 (ユーザー裁定):** 条件 18 の 2 点発火を担保する解決器は、**実運用の consumer と同じ変更単位で
結線する**。結線できないなら解決器ごと撤去する。現状のまま残さない。

**理由:**
- 当該解決器を呼んでいるのはテストだけで、production の呼び手が 1 つも存在しない。
  現状こそが休眠 capability であり、型と consumer を同一単位で作る D1028 の趣旨に反する。
- テストだけが呼ぶ仕組みを残すと「条件 18 が担保されている」という外見だけが積み上がる。

**却下した選択肢:**
- adapter を作らず現状維持 — 休眠状態を温存する。

## {{D:worktree-registration-fail-closed}}. 生きた worktree 登録の競合は現行の即時拒否を維持する

**決定 (ユーザー裁定):** 登録一覧の読み取り中に登録が変化した場合の処遇は、**現行の即時 fail-closed を
維持する**。有界な取り直し・欠落許容・開始時 snapshot はいずれも採らない。

**理由:**
- 3 案とも受理集合を広げる方向であり、矛盾した一覧を受理して撤去判定を誤る損害は、
  待たされる不便より大きい。相対 path を渡して 22 本すべてを偽の撤去可と判定した事故がある。
- 即時拒否は偽陽性を出すが偽陰性を出さない。

**却下した選択肢:**
- 有界な取り直し / 欠落許容 / 開始時 snapshot — いずれも受理集合を広げる。

## {{D:worktree-registration-aba-hardening}}. 列挙後の置換と追加を検出する hardening を独立に入れる

**決定 (ユーザー裁定):** 登録を列挙してから中身を開くまでの置換と、列挙後に増えた登録を
**検出して拒否する hardening を入れる**。前項の処遇方針とは**別の変更単位**として扱う。

**理由:**
- 「矛盾のない 1 枚を読んでいる」という現行の暗黙の前提が成立していないことが実測されている。
  前提が偽のまま撤去判定を行う方が危険である。
- 前項は検出済み競合の処遇、本項は未検出領域の観測範囲であり、片方だけでも成立する。

**却下した選択肢:**
- 前項と同じ変更単位にする — 決定も実装も互いに独立しており、束ねる根拠がない。
- 現状維持 — 検出できない churn が残る。

## {{D:mutation-extraction-error-lines}}. 変異 harness の node 抽出契約を setup 失敗行まで広げる

**決定 (ユーザー裁定):** 変異 harness の node 抽出器が読む対象を、テスト本体の失敗行だけでなく
**setup / fixture 段で落ちた行まで**広げる。広げた後、既存の変異一覧が同じ結果を出すことを確認する。

**理由:**
- 分類できない変異を登録から外す回避は、変異検査の網を人手で狭める操作であり、繰り返すと
  「全件 KILL」の意味が薄れる。
- setup 段の失敗も変異が効いた証拠として正しく数えられる。

**却下した選択肢:**
- 現状維持し登録から外す回避を続ける — 人手で検出力を落とす運用が恒久化する。

## {{D:b4-analysis-contract-split-effect-size}}. B-4 の分析契約は一括凍結し、最小重要効果だけ独立に固定する

**決定 (ユーザー裁定):** 赤 precursor 母集合・最小重要効果・n・primary outcome の純関数は
**一括で凍結する**。ただし**最小重要効果は pilot と独立に固定**し、pilot は n と分散上限の導出に
限定する。

**理由:**
- 母集合・効果量・n を同じ pilot から一括導出すると、形式を満たしたまま都合の良い境界を
  結果から選べる。同型の悪用手順が別系列の敵対検証で具体的に示されている。
- B-4 事前登録自身が、n を凍結済み母集合と事前固定した効果量から導出すると規定している。

**却下した選択肢:**
- 4 項目すべてを pilot から導出する — 導出関数が恒真化する。
- 項目ごとに別々の時期に凍結する — 分析契約としての一体性が失われる。

## {{D:b4-nonsampling-probe-approval}}. B-4 の適格性は結果を生成も閲覧もしない配線調査で測る

**決定 (ユーザー裁定):** B-4 事前登録 §5.1 が要求する非標本 probe は、**結果を生成も閲覧もしない
配線調査**として設計・実装してよい。生成しないことは出力経路を構造的に持たせない設計で保証する。

**理由:**
- 出力経路を構造的に持たせない遮断は、既に複数の role で採用され実証されている形である。
- より強い保証を要求すると、実行主体の新設という別の未解決問題に従属し B-4 全体が止まる。

**却下した選択肢:**
- 別プロセス / 別権限での実行を要求する — 未解決の実行主体設計に従属する。

## {{D:frozen-evidence-current-only}}. 凍結証拠の照合は現在値との一致に固定する

**決定 (ユーザー裁定):** 凍結証拠を検証する経路は**現在値との一致だけを認める契約**として固定し、
その境界を直接テストで押さえる。歴史 artifact を受理する scope 拡張は行わない。

**理由:**
- 拡張は実処理経路の再設計と上位凍結規約の再裁定を伴い、費用が大きい。
- 現状固定なら直接テスト 1 本で境界が守られる。歴史 artifact を読む実需が出た時点で再訪できる。

**却下した選択肢:**
- 歴史 artifact も受理する — 再設計と再裁定を伴う。
- 境界テストを置かずに現状維持 — 次の変更が黙って挙動を変えても検出できない。

## {{D:consult-lane-unbind-from-model}}. 相談 lane 識別子と model の束縛を外す

**決定 (ユーザー裁定):** 相談 lane 識別子と model の束縛を**外し**、識別子は単なる lane 名とする。
過去 receipt の旧値は**読み取りのみ**受理する。

**理由:**
- 現行の権威行は全段同一モデルのため束縛は発火せず、model 名との衝突だけが残っている。
  発火しない束縛の保守費用を払い続ける理由がない。
- 束縛を外せば衝突が消え、跨 wave の工数台帳は旧値をそのまま読める。

**却下した選択肢:**
- 束縛を残して名前だけ変える — 動かない仕組みを保守し続ける。

## {{D:lf-only-split-scope-widen}}. 行分割を改行だけに限る修理を名指し 6 箇所の外へ広げる

**決定 (ユーザー裁定):** D971 が明示列挙した 6 箇所の外にある同型の行分割も、**改行だけで割る形へ
直す**。負例テストを同じ変更単位で置く。

**理由:**
- 同型の欠陥が一部だけ残ると、次に踏む者が毎回「なぜここだけ違うのか」を調べることになる。
- 受理集合が変わるため、負例を同時に置かないと発効が確認できない。

**却下した選択肢:**
- 6 箇所に限定して残す — 意図的に残す理由を別途台帳へ書く必要が生じる。

## {{D:cr-only-blank-line-reject}}. 復帰文字だけの空行を拒否する

**決定 (ユーザー裁定):** 行分割直後の空行 skip が復帰文字だけの行を捨てる点を是正し、
**拒否分岐を足す**。現に通っている出力が落ちないことを確認してから入れる。

**理由:**
- 当該系は復帰文字を不正と宣言しており、一部を通す実装は宣言と食い違う。
  この食い違いは過去に繰り返し事故になっている。

**却下した選択肢:**
- 現状維持 — 宣言と実装の食い違いが残る。

## {{D:invisible-markdown-detection-fix}}. 文書検査器の不可視判定を是正する

**決定 (ユーザー裁定):** inline code span 内のコメント開始記号を実際のコメント開始と誤認する
文書検査器を**検査器側で直す**。下書き実行へ canonical validation を足す案は、下書きの目的を
変える副作用があるため、費用を見積もってから別途判断する。

**理由:**
- 誤認は本物の欠陥であり、実際に着地を止めている。
- 手前の道具だけを直しても、検査器の誤認そのものは残る。

**却下した選択肢:**
- 下書き実行への検証追加だけで済ませる — 検査器の誤認が残る。

## {{D:cache-configure-argv-is-recipe}}. キャッシュが返す設定引数列は作り方として明示する

**決定 (ユーザー裁定):** ビルドキャッシュが返す設定引数列は、**現在の生成器が示す作り方**として
明示する。歴史記録として扱わない。受理集合は変えない。

**理由:**
- 歴史記録にすると現在許している一致の範囲を狭める変更を伴うが、この値を歴史として読む
  消費者は存在しない。
- 名前と説明を作り方と明示するだけなら誤読の危険が消え、費用がほぼゼロである。

**却下した選択肢:**
- 歴史記録として保存 argv を読む — 受理集合を狭める割に消費者が居ない。

## {{D:oracle-n-pilot-out-of-canonical}}. 補助 pilot は canonical 保証の対象外と宣言し、消費側で拒否する

**決定 (ユーザー裁定):** 補助 pilot を canonical 保証の対象に含めず、**対象外と宣言する**。
宣言を文面だけにせず、**実際の canonical consumer で pilot 成果物を機械的に拒否する**。
別系列の pilot 非算入強制とは artifact も consumer も別であり、同じ変更単位に束ねない。

**理由:**
- 権威でない成果物へ canonical 保証の費用を払う理由がない。
- 宣言だけでは、承認権限が開いた時点で正式入力へ紛れ込む経路が残る。
- 登録簿への登録が downstream の拒否や consumer 束縛を保証しないことは、登録簿自身が明記している。

**却下した選択肢:**
- 直して canonical 保証の対象に含める — 非 authoritative な成果物に費用を払う。
- 別系列の非算入強制へ同梱する — artifact も consumer も別で、穴は閉じない。

## {{D:failures-duplicate-cross-reference}}. 台帳の重複登録は統合せず、両方へ相互参照を追記する

**決定 (ユーザー裁定):** 同一欠陥が失敗台帳に 2 件登録されている状態は、**統合しない**。
先に登録された側へ**再発**を、後の側へ**重複登録である旨と正本の参照**を追記する。

**理由:**
- 台帳は追記のみで、同型再発は新しい項目を作らず既存項目へ追記するのが定めである。
- 後の側だけへ追記すると、先の側に再発の記録が残らず履歴が失われる。

**却下した選択肢:**
- 2 件を 1 件へ統合する — 既存 bytes を動かし、両 F への全参照の書き換えを伴う。
- 片方だけへ追記する — 再発履歴が片側に残らない。

## {{D:b10-diagnostic-genome-correctness}}. 診断計装下の試行は正しさ検査を通すか、機序主張から外す

**決定 (ユーザー裁定):** 診断計装を入れて走らせた試行は、**正しさ検査を通す**。費用が許さない
場合は、**診断由来の機序判断を成果物から外す**。現状 (未検査の診断値が機序結論に入る) のままは
選べない。

**理由:**
- 診断値は性能判定には入らないが、待ち時間に由来する値が機序の結論へ直接入っていることを
  現物のコードで確認した。正しさが確認されていない試行の数値が機序主張を支えている。
- 計測が約 4 割伸びる費用は、正しさの検出力を捨てる理由にならない。

**却下した選択肢:**
- 対応点への束縛と明示記録だけで足りるとする — 未検査の値が機序主張を支える状態が残る。

## {{D:b10-requested-wait-instrumentation-defer}}. 待ち時間の直接計装は機序主張へ昇格する時点まで作らない

**決定 (ユーザー裁定):** 適応的な待ち方が要求する待ち時間を直接計装する診断改造は**今は作らない**。
当該値を load-bearing な機序主張の柱へ昇格させる時点で再提案する。作る場合は、計装が性能計測用
ビルドからコンパイル時に完全除去されることを必須条件とする。

**理由:**
- 当該実験の主張範囲は記述的な形状に限定されており、論文利得にも非適格である。
- 外部コードの改造を伴う計装を、主張範囲が記述的な段階で足すのは段階導入の原則に反する。

**却下した選択肢:**
- 今すぐ作る — 主目的から遠い割に外部コードの改造を伴う。

## {{D:b10-noise-floor-remeasure}}. 判定下限は現環境・workload 別に、結果を見る前に測り直す

**決定 (ユーザー裁定):** 性能低下の判定に使う下限値を、**現環境・workload 別に測り直す**。
**結果を見る前に取得**し、判定器と成果物へ**版を付けて束縛**する。

**理由:**
- 現在の下限は旧環境の 2 workload 由来で read-heavy を含まず、判定器自身がそう自認している。
  根拠のない下限で判定すると判定そのものが無意味になる。
- 結果を見てから下限を決めると、都合の良い下限を選べる。

**却下した選択肢:**
- 旧環境由来の下限を流用し続ける — read-heavy の判定に根拠がない。

## {{D:b10-order-effect-design}}. 逆順 1 本は感度確認に限定し、順序効果の否定に使わない

**決定 (ユーザー裁定):** 測定順序を逆にした走行 1 本は**感度確認に限定**し、成果物へ
「順序効果を否定した」と書かない。順序効果を否定するなら、事前登録した往復設計または独立な
複数の並べ替えを用いる。

**理由:**
- 現設計は workload ごとに 1 個の固定した並べ替えを 1 回使うだけであり、逆順 1 本では
  2 走の一致が偶然か順序効果の不在かを区別できない。

**却下した選択肢:**
- 逆順 1 本で順序効果を否定したと書く — 設計上その結論を導けない。

## {{D:b10-bytes-hold-keep-and-split}}. 凍結成果物の bytes 照合は解除せず、保留の可視化と切り離す

**決定 (ユーザー裁定):** 凍結成果物の bytes 照合の保留は**解除しない**。解除の判断は
呼び手が bytes を実際に要求しているかで決め、現時点でその要求はない。
**保留の可視化**は既裁定の別項目が持つ変更として進め、bytes 照合の解除とは別に扱う。

**理由:**
- bytes 級の一致それ自体を関門にしない方針であり、消費者の要求がない解除は意味を持たない。
- 保留中と検査消失を呼び手が区別できない状態は別の欠陥であり、混ぜると片方だけ直して
  もう片方を閉じたことにしてしまう。

**却下した選択肢:**
- 保留を解除する — 呼び手の要求がない。
- 可視化と解除を同じ変更で扱う — 別の欠陥を 1 つに畳む。

## {{D:b10-wait-distribution-defer}}. 待ち量の分布を測る診断ビルドは作らず、主張を指示値の平均に限定する

**決定 (ユーザー裁定):** 実走行での待ち量の分布を測る診断ビルドは**作らない**。主張は
指示値の平均に限定する。分布に依存する主張を立てる段階で、待ち時間の直接計装と**同じ変更単位**で
再提案する。

**理由:**
- 主張範囲が記述的である段階で外部コードの改造を伴う計装を足すのは段階導入の原則に反する。
- 同じ計装面なので、必要になった時点で 1 つの単位として扱う方が安い。

**却下した選択肢:**
- 今すぐ作る — 分布に依存する主張が現時点で存在しない。

## {{D:b10-legacy-consumer-freeze-by-name}}. 旧 backoff 消費者は別名で凍結し、既存の凍結成果物に触れない

**決定 (ユーザー裁定):** 待ち方の改造が新版になったことへの対処は、**旧版を別名で凍結する**。
旧消費者の実験識別子を移す案は採らない。既存の凍結成果物は 1 バイトも動かさない。

**理由:**
- 識別子の移行は既存の凍結成果物の指紋固定に触れる作業であり、凍結物を動かす操作は事故率が高い。
- 別名で凍結すれば旧消費者はそのまま動き、新版は別の名前で積み上がる。

**却下した選択肢:**
- 実験識別子を移行する — 凍結成果物の指紋固定に触れる。
- 未対処のまま旧消費者を新版で再実行する — 同じ実験に新しい識別子が入り指紋固定を壊す。

## {{D:b10-preview-attestation-stay-in-path}}. 事前非閲覧の保証は処理経路内に留め、偽造不能受領証へ相乗りさせる

**決定 (ユーザー裁定):** 「commit 前に性能を一度も見ていない」ことの保証は**正規の処理経路内に
留める**。repo 外の権威による機械証明は今は作らず、偽造不能な受領証の機構が着地した時点で
そこへ相乗りさせる。

**理由:**
- 外部権威は、AI が書ける領域に置けば恒真になり、書けない領域に置けば人間の手番を増やす。
  同じ論点は既に受領証の裁定で扱われている。
- 今独立に作ると、受領証の着地後に二重になる。

**却下した選択肢:**
- 独立の外部権威を今作る — 受領証と二重になる。

## {{D:paper-value-separate-boot-reproduction}}. 論文採用の性能値は別 boot で取り直す

**決定 (ユーザー裁定):** 論文へ採用した 2 つの性能改善値は、**計算機を別に起動し直して取り直す**。
既存の走査手順をそのまま 1 回回す形でよい。対外主張を「1 回の起動でのみ確認」へ狭める案は採らない。

**理由:**
- 見送り台帳の発火条件 (当該値を対外主張へ採り別 boot 成果物が無いとき) が成立している。
  論文素材の最新版で 2 値とも採用済みであり、参照している一次資料は別 boot 証拠を持たない。
- 起動を跨いだ再現は、測定環境に起因する見かけの改善を否定する最も安い手段である。

**却下した選択肢:**
- 別 boot 証拠が不要な範囲へ主張を狭める — 論文の中心的な値の主張が大きく弱まる。
