## {{D:cap-lift-topology-not-landed-alone}}. 上限引き上げの発効機構は、二段束縛の部品だけを先に land しない

**決定:** D1407 が定める発効 topology を検査する cap-lift 固有の部品を、内容 commit `G` の
実装一式より先に単体で land しない。実装面の差分をゼロのままとし、設計と実測を insight へ残す。

理由は独立に 4 本あり、1 本でも成立すれば単体 land は採れない。

1. **D1407 決定 (1)・(3) に正面から反する。** (1) は「内容 commit `G` が実装一式を導入する」、
   (3) は「`G` と `A` は分割して main へ入れず、同一の land transaction で取り込む」と定める。
   部品を先に land すると、後続の `G` は「実装一式を導入する commit」ではなくなり、
   発効参照の根拠が偽になる。
2. **D1407 の却下選択肢と同じ欠陥型である。** 同決定は「到達不能と承知で受領証の入口だけを
   land する — 実正例を持たない枝を増やす」を却下している。提案部品は受領証を parse しないため
   字義上の「受領証の入口」ではないが、**production の呼び手が無く一度も評価されない**点で同型である。
3. **発火条件を書けない。** cap-lift 固有の認定記録 path も受領証 path も存在せず、
   `run_origin_trial` には repo 内の呼び手が無い。識別子検索ではなく性質で全件確認した。
4. **D841 の positive control 要求を満たさない。** 受領証と consumer 結線を伴わない部品を
   上限引き上げの実装成果として数えることはできない。D1407 は D841 が不変であると明記している。

**あわせて次を確定する。**

- **実装差分は先行設計の見積りより小さい。** D1407 が発効 commit へ要求する述語は、
  親集合 exact 一致・追加 path が exact で他 status ゼロ・`AI-Agent: none` の逐語ちょうど 1 本・
  内容 commit との非同一性のいずれも、既存の 2 module に相当物が実装済みである。
  さらに親集合側の負例は実 git で既に網羅されており、実装時に足す必要が無い。
  正例も実 repo に実 commit を作る既存の作法で、依存先を stub せずに書ける。
- **独立述語は 4 つでなく 3 群である。** 親集合が exact 単集合であることは非 merge を論理的に含む。
  4 つと数えると同じ parent guard を二重計上する。
- **rename と mode 変更のみの負例は登録しない。** 既存の追加 path 判定は `diff-tree` に `-M` を
  渡さないため rename は `A` と `D` に分解され、削除の負例と同じ理由で拒否される。
  `diff.renames` を config でも `-c` でも与えても plumbing の出力は変わらない。
  mode 変更のみも内容変更と同じ `M` で拒否される。いずれも冗長 gate であり、
  追加 path 判定へ rename 検出の抑止を足す必要も無い。

**理由:**

- 発効 topology の循環は D1407 が解いたが、それは設計の循環であって実装の順序ではない。
  受領証を発行できるようになる前提 (意味的充足契約の本体実装) は別タスクの所有のまま未実施であり、
  そこが解けない限り `G` は完成しない。
- 部品だけを先に置くと、後から実装一式を導入する commit が「実装一式を導入する commit」で
  なくなる。これは形式検査で検出できず、台帳の参照だけが静かに偽になる型の欠陥である。
- 実装差分が小さいことを確定した価値は残る。次の実装 wave は棚卸しからやり直さずに済む。

**却下した選択肢:**

- **部品だけを到達不能な将来の入口として land する** — 上記 2 のとおり同決定が却下した欠陥型である。
- **共有 git 呼出しの信頼境界の統一を本変更単位に含める** — 実在の差分ではあるが、
  まだ誰も踏んでいない経路への防御的堅牢化であり、本題の実装ではない。
  受理集合を狭める向きの変更を本題の名前で行うと、承認外の過剰拒否を本題の成果として台帳へ残す。
  別タスクとして起票し、そちらで成果物影響と正例・負例を独立に立てる。
- **発効 commit の形式検査だけで上限を開く** — 前提条件の機械再導出要求を迂回する。
  D1407 が supersede しないと明記した既裁定群に触れる。
