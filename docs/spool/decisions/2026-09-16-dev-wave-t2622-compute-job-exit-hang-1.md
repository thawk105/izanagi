## {{D:job-exit-delay-attribution}}. 計算ノード job の終了遅延は「子孫の出力 fd 保持」に帰属させない

**決定:** 計算ノード job が pytest 完了後に終わらない事象について、次を現行の帰属とする。

- **確定:** 直接の子より長生きした子孫が存命する間、job の会計終了が遅れる。
  **子が job の stdout / stderr を保持していることは、この遅延の必要条件ではない。**
- **未確定として明示する:** NQSV が request を RUN に留める判定方式 (session / process group /
  scheduler の追跡集合)。分離実験の全記録で `sid == pgid` であり分離できていない。
- **未確定として明示する:** F853 当時の機序と、D1684 の是正の各要素 (所属分離 / 子孫終了) の寄与。
- 台帳への反映は `docs/failures.md` の運用規則に従い **supersede 追記**とし、再発件数に数えない。
  D1684 の是正は撤回しない。

**理由:**
- 4 条件の分離実験 (統制 = 子孫なし、fd 解放を即時 / 30 秒 / 解放なしで動かす) で、
  解放時刻を動かしても job の終了時刻が 0.285 秒しか動かず、子孫の有無では約 70 秒動いた。
  fd 保持を必要条件とする説明は、この観測と両立しない。
- 判定方式まで断定すると、次の担当者が誤った前提で対策を設計する。所属を変える条件を
  実験に入れていない以上、帰属は「存命する子孫」までで止めるのが証拠に見合う。
- 「再発」ではなく supersede にするのは、新たな同型事象が起きたのではなく、
  既存エントリの**記述だけ**が後続の実測で古くなったためである。

**却下した選択肢:**
- 機序を session と断定する — 全記録で `sid == pgid` であり、実験に分離処置が無い。
  断定すると `docs/failures.md` に二次の誤りを足すことになる。
- F853 の根本原因を「誤り」と断じる — 当時の構造 (FIFO の open で止まった孫) を再現しておらず、
  反証ではない。是正が効いた理由の断定も同じ理由で採らない。
- 本 wave で回収処理・防壁を実装する — 依頼が scope 外と明示し、F973 は同型の対策が
  44 走緑だった正しさテストを赤にした実績を持つ。原因同定と対策は別 wave に分ける。
- 判定方式の分離実験を本 wave で続ける — 所属を変える条件は新しい事前登録と安全水準の
  再設計を要する。結論の範囲を明記して次へ渡す方が安い。
