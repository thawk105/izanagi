## {{D:dev-wave-docs-budget-governed-by-d782}}. 手順書の予算に阻まれた収容は D782 の手順で AI が閉じ、契約文面をそれに合わせる

**決定 (ユーザー裁定):** `docs/dev-wave/**` の層予算に阻まれた収容案件は、案件ごとに裁定へ返さず
D782 が定める手順 (既存記述の削減 → 独立 3 例以上なら例外収容 → 収容先を作れないと確かめられた
場合にだけ上限引き上げ) を AI が適用して閉じる。`docs/skill-self-improvement.md` の
「予算値を上げる変更は通常の自己改善に含めず、理由付きの独立審査対象にする」は D782 と
食い違って各 wave を止めているため、**D782 の手順を指す形へ書き換える**。

上限引き上げに至る場合は次の 2 つを親裁定が持つ。**一括の増枠は認めない。**

1. **層ごとの最小増分。** L1 / L1.5 / 単節のどれをいくら上げるかを別々に書く。
2. **収容表。** その枠へ入れる義務と、各義務の終端条件を 1 行ずつ列挙する。

**理由:**
- 予算を守るために安全義務を落とすのは絶対規律 2 の面に触れる。撤回された記述は
  実測で誤りと判明した安全義務の是正であり、削ってよい種類のものではない。
- 予算の目的は子エージェントへ射影する文書量の抑制である。memory への routing は
  子へ射影されないので抑制目的を達成しないまま知見だけを失う。
- 圧縮は逐語 pin の閉包を壊す実績がある。予算を理由にした縮約が
  exact literal で固定された 2 行に触れて復元を要した例が 2026-08-26 にある。
- 同じ壁での撤回は 3 度記録されており (F217)、案件ごとの裁定は費用に見合わない。

**却下した選択肢:**
- 契約文面を正として D782 を撤回する — 安全義務が入らない状態が恒久化する。
- 一括で増枠する — どの義務がどの枠へ入るかが追えなくなり、次の満杯まで同じ議論を繰り返す。

## {{D:prereg-request-body-definition-unchanged}}. 送る依頼の本体の定義は変えず、通信 bytes を観測できていないことを限界として書く

**決定 (ユーザー裁定):** 8c 事前登録 §4 の「provider へ送る request の本体」の定義は変えない。
argv / stdin は D833 どおり launch contract の証拠とだけ呼び、remote serialization bytes を
捕獲できない間は当該条件を open に保つ。**引数と標準入力を「本体」と再定義して条件を
閉じたことにしてはならない。**

**理由:**
- 定義変更で未検証領域を消すのは、測っていないものを測ったことにする形である。
- D833 が領域ごとに「閉じた」「閉じていない」を分けて書くと定めており、
  領域 (ii) の主張は launch contract の範囲に限定されている。定義変更はこの限定を無効化する。
- 捕獲の仕組みを作る案は独立した設計であり、本裁定は塞がない。

**却下した選択肢:**
- argv / stdin を本体と定義する — 論文の主張が定義の書き換えで水増しされる。
- 通信 bytes の捕獲を本裁定で必須化する — 設計が未着手で、条件を open に保つだけで足りる。

## {{D:dangling-seven-rescue-indeterminate-only}}. 判定不能な到達不能 commit だけを親子関係ごと救出する

**決定 (ユーザー裁定):** 2026-08-25 深夜の branch 削除で到達不能になった 7 commit のうち、
**判定器が `indeterminate` を返した 3 件だけを救出し、`landed` の 4 件は救出しない**。
救出は file 単位の複製ではなく、親子関係を含む形でまとめて取り出し、
**別の場所で復元できることを確認してから**破棄する。

**理由:**
- `landed` と判定できた 4 件は内容が main に残っており、二重保管の価値がない。
- `indeterminate` の 3 件は内容が main にあるか確かめられていない。
  自動 gc の窓は 2 週間で、放置は不可逆である。
- file 単位の複製は親子関係を落とし、復元できない写しを作る。

**却下した選択肢:**
- 7 件すべて救出 — 着地済みの重複を増やすだけで、救出物の管理費用が上がる。
- 全件破棄 — 判定不能な 3 件の内容が永久に失われる。

## {{D:staged-payload-not-default-until-evidence-closure}}. 依存物の staged 運搬は証拠閉包へ組み込み、同等性を示してから既定にする

**決定 (ユーザー裁定):** 依存物の staged 運搬を driver の既定にする変更は**承認しない**。
既定化は `eligible_for_refreeze` を不適格から適格へ反転させ、D446 の
「受理集合は縮む方向にしか動かさない」と衝突する。先に staged 運搬を canonical transport の
証拠閉包へ組み込み、**明示引数の経路と同等であることを示してから**適格性を再裁定する。

**理由:**
- 計算ノードが offline で既定経路が動かないのは運用上の必要だが、
  それだけを理由に適格判定を緩めるのは正しさの関門を都合で動かす形であり、絶対規律 2 に触れる。
- 適格性の反転は「動く構成なら適格」へ意味を薄める。判定の意味を保ったまま
  同じ結果を得る経路 (証拠閉包への組み込み) が存在する。

**却下した選択肢:**
- 整合する変更として承認する — 一度不適格としたものを運用都合で適格へ戻す前例になる。
- offline 環境を適用外にする — 実行場所によって適格判定が変わる形は D446 の趣旨に反する。

- 証拠設計は変異 harness の受理集合を変える。射程限定の運用を止める理由が現時点でない。

**却下した選択肢:**
- 本経路の改修として証拠を足す — 受理集合の変更を運搬の改良に紛れ込ませる形になる。

## {{D:acceptance-must-prove-predicate-execution}}. 正式受入は宣言した述語が実行されたことまで証明する

**決定 (ユーザー裁定):** 正式受入は、宣言した述語が source に文字列として実体化していることに
加えて、**その述語が実際に build と実走へ届いたこと**を証明できるようにする。手段は
(a) 変更不能な snapshot からの build、または (b) compiler input manifest の保存のいずれかとする。

閉じる対象は次の 4 経路である。非到達化、別変数による実効分岐、build 中の source 差し替え
(A→B→A)、汚染 cache binary の再利用。

**理由:**
- 文字列の実在だけでは、宣言した処理が build と実走へ因果的に届いた証拠にならない。
  正しさシグナルを後付けで補う形に近く、絶対規律 3 の面に触れる。
- D863 の宣言 arm と実走 arm の同一性は、現状の検査では文字通りには満たされない。
- 「宣言した条件で測った」という主張は本プロジェクトの成果物そのものである。

**却下した選択肢:**
- 現状の限界を明記して据え置く — 主張の中核を自己申告と同じ強さで支えることになる。

## {{D:prereg-contract-field-paths-widened}}. 事前登録契約の検査対象 field を広げ、既存 campaign の失効は正直な移行として扱う

**決定 (ユーザー裁定):** 事前登録契約 C10 の `field_paths` を新規 field まで**広げる**。
凍結の再発行と判定器版の bump を行い、既存 campaign が `E1-stale` になることは
**正直な migration として記録する**。契約の記述が実装より弱い状態を残さない。

**理由:**
- 契約が新しい証拠 field を要求しないなら、後から実装を弱めても正式 gate が検知できない。
  これは正しさゲートを緩める方向の変更を通す形であり、絶対規律 2 に触れる。
- 失効は既存の値を捨てることではない。旧契約で取った値は旧契約の値として残り、
  正式系列へ入る前に契約を整えるほうが後戻りが小さい。

**却下した選択肢:**
- 広げず、契約が実装より弱いことを明記する — 形骸の契約で正式系列を守ることになる。

## {{D:jsonl-line-split-ratified}}. JSONL の行分割を改行だけに限る修理を追認する

**決定 (ユーザー裁定):** JSONL を `str.splitlines()` で切っている 6 箇所を
`split("\n")` へ変える恒久修理を**追認**する。`str.splitlines()` は改行に加えて
U+2028 / U+2029 でも分割するが、この 2 文字は JSON 文字列内では escape 不要の正当な文字である。
そのため子が該当文字を含む file を読むだけで**完成した成果物ごと破棄される**。
正常入力への挙動は不変で、壊れていた入力だけが直る。
U+2028 / U+2029 を含む event 行を受理する負例テストを同時に置く。

**理由:**
- 実害が独立に 2 件記録されている (F540 supersede、F609)。
- 変更は行分割の 1 手法の置換であり、受理集合は壊れていた入力の側にだけ広がる。
- 当該裁定も repo 外の inbox 控えにしか無く、台帳に届いていない。

**却下した選択肢:**
- 拒否分岐を足して U+2028 / U+2029 を含む行を弾く — 正当な入力を壊す側に倒れる。

## {{D:admission-needs-trusted-writer-boundary}}. 試行受付の記録は AI が自己発行できない書き手境界で守る

**決定 (ユーザー裁定):** admission の marker / journal / ledger が同一 UID から書き換えられる件は、
**trusted writer 境界を設計して閉じる**。境界の要件は、**AI が自分で発行できないこと**とする。
consumed marker を消して同じ attempt を無制限に測り直せる経路を塞ぐ。

**理由:**
- 良い値が出るまで測り直せる経路は、測定値の選別を許す形であり絶対規律 2 の攻撃面である。
- 自己申告 field の追加や手順側の義務は、同じ主体が書ける限り保証にならない。
- 批准の執行 (D905) と同じ性質の要件であり、実行主体の設計を共有できる。

**却下した選択肢:**
- 現状維持 — 選別が構造的に可能なまま正式系列へ入る。
- 手順書へ禁止と書く — 機械強制のない禁止は同じ主体が破れる。

## {{D:truncated-row-repair-needs-injection-measurement}}. 追記記録の修復可能形式は、壊れ方を注入して測ってから決める

**決定 (ユーザー裁定):** 追記記録の最終行が途中で切れると以後すべて拒否され cell が
永久に失われる件は、修復可能形式への移行を**測定の後に決める**。電断・部分 write・
末尾改変を注入し、**未完の最終 record だけを安全に破棄でき、拒否すべき壊れ方は
拒否したままであること**を実測してから形式を確定する。

**理由:**
- 修復可能形式は、壊れた行を無視して緩い側へ倒れる fail-open を作りうる。
  拒否すべき破損まで通す形は絶対規律 2 に触れる。
- 現状は fail-closed に倒れており、実害は「枠が失われる」であって誤った値の受理ではない。
  急いで緩める理由がない。

**却下した選択肢:**
- 測らずに修復可能形式へ移す — fail-open の危険を確かめないまま受理集合を広げる。

## {{D:retry-semantics-registry-is-canonical}}. 再試行の意味論は registry を正とし、版境界を置いて旧経路を段階廃止する

**決定 (ユーザー裁定):** 旧 `valid=False` 由来の retry と registry の
`retryable_failure_reasons` が食い違う件は、**registry を canonical な意味論とし、
旧経路を fail-closed に段階廃止する**。旧成果物を暗黙に新しい意味へ昇格させない版境界を
同時に置く。retry 枠を使い切った cell の cut 復帰規則も同じ変更で決める。

**理由:**
- 同じ「再試行」という語が 2 つの意味を持ち続けると、受理集合が読み手によって変わる。
- 旧成果物の暗黙昇格は、旧い基準で取った値を新しい基準の値として数える形になる。

**却下した選択肢:**
- 旧経路を残す — 意味の二重性が恒久化する。
- 版境界なしで一括切替 — 旧成果物が新しい意味へ黙って昇格する。

## {{D:non-ancestor-landed-branch-deletable-with-cas}}. 内容着地済みの非祖先 branch は expected-tip の CAS つきで削除対象へ入れる

**決定 (ユーザー裁定):** 内容としては着地済みだが main の祖先でない branch を、
掃除の削除対象へ**入れる**。削除は `-D` ではなく **expected-tip の CAS**
(`git update-ref -d` の期待値指定) と削除直前の再検査を必須とし、
**判定不能な branch は残す**。

**理由:**
- 現行 §2 の `ahead=0 のみ削除` では、判定器が `landed` と言っても運用が何も変わらない。
- `-D` は期待と異なる先端でも消すため、判定と削除の間に進んだ branch を落としうる。

**却下した選択肢:**
- `-D` で削除する — 判定と削除の間の変化を検出できない。
- 現状維持 — 着地済み branch が永久に溜まる。

## {{D:observer-role-needs-lifetime-cap}}. official 専用の観測役割には役割横断の生涯観測上限を置く

**決定 (ユーザー裁定):** official 専用の観測役割を足すにあたり、
**役割横断の campaign 生涯観測上限**を別途要求する。承認 nonce による 1 回ごとの承認だけでは
将来の役割追加を止められず、役割ごとに観測を増やせる形が残る。

**理由:**
- 上限が無ければ、役割を増やすたびに観測回数を増やせる。これは
  「良い値が出るまで見る」経路であり、絶対規律 2 の面が開いたままになる。
- nonce 単位の承認は個々の起動を縛るが、総量を縛らない。

**却下した選択肢:**
- nonce 単位の承認だけで運用する — 実質的な上限にならない。

## {{D:unnumbered-archive-carry-is-checked}}. 非採番 archive の carry も検査母集団へ入れる

**決定 (ユーザー裁定):** 非採番 archive の carry が構造的に検査対象外である件は、
**検査を拡張して母集団へ入れる**。名前で対象外を固定している既存テストの期待値を更新し、
同じ parser 契約で扱う。該当は全コーパスで 1 件である。

**理由:**
- 実在する記録を母集団から構造的に落とす理由がない。
  名前で外した対象は、検査の完全性の主張を静かに弱める。

**却下した選択肢:**
- 現状維持 — 母集団が「たまたま名前で外れたもの」を含んだままになる。

## {{D:known-violation-ledger-needs-protected-review-boundary}}. 既知違反台帳と exact テストの協調改変は保護レビュー境界で塞ぐ

**決定 (ユーザー裁定):** 既知違反の台帳・固定総数・exact テストを同一 patch で書き換えれば
無裁定で緑にできる件は、**保護レビュー境界**を置いて塞ぐ。
**その境界自体を同じ patch から変更できないこと**を条件とする。

**理由:**
- 台帳と検査を同じ提案者が同時に動かせるなら、検査の権威は提案者の自己申告と同じ強さになる。
- 境界が同じ patch から動かせるなら、境界は保護になっていない。

**却下した選択肢:**
- 承認 receipt の要求だけ — receipt の発行者が同じ主体なら同じ穴が残る。
- 現状維持 — 既知違反台帳が権威を持てない。

## {{D:critic-pair-receipt-enforced}}. 有効な pair receipt を持たない critic 応答は protocol violation として拒否する

**決定 (ユーザー裁定):** 段 4 driver は、有効な pair receipt を持たない critic 応答を
**protocol violation として fail-closed に拒否する**。legacy の generic role 起動経路も
同じ関門を通す。受理集合を変える変更として実施する。

**理由:**
- 拒否しない限り、閉じた module の存在は謳うだけで発火しない保証である。
- 前提条件 3 が「機構あり・強制なし」のままでは論文の主張に使えない。

**却下した選択肢:**
- 現状維持 — 閉じた module があることを保証と数えることになる。

## {{D:contract-modules-move-to-shared-layer}}. 契約 module と authority data は production / shared 層へ置く

**決定 (ユーザー裁定):** production 側が tests 配下を runtime import している逆向き依存は、
**契約 module と authority data を production / shared 層へ移して**解消する。
移動時に正本が 1 つであることを固定する。

**理由:**
- tests 配下を消すと production が動かなくなる構造を正式化すべきでない。
- 同配下に先例が無く、逆向き依存を認めると以後の判断基準が失われる。

**却下した選択肢:**

## {{D:post-oracle-material-regeneration-banned}}. oracle 判定後の材料再生成を禁止する

**決定 (ユーザー裁定):** oracle が判定した後に、build 処理が source tree 内で材料を
作り直す経路を**禁止する**。手段は private snapshot からの build か、
判定後の source tree の書込み不能化とする。

**理由:**
- 判定した材料と build 入力が一致しない可能性を残すと、判定そのものが形骸になる。
- 宣言した述語の実行到達を証明する裁定と同じ面であり、同じ束で閉じるべきである。

**却下した選択肢:**
- 現状維持 — 判定と実物の不一致が残り、測定の意味が壊れる。

## {{D:dangling-audit-root-retirement}}. 到達不能 commit 監査の残る律速は探索根の退避で下げ、所要上限は現状のまま置く

**決定 (ユーザー裁定):** 到達不能 commit 監査の残る律速 (repo 外探索根の走査が最終走の 73%、
探索根は実測 1,299,504 inode) は、**古い wave 成果物の退避で探索根を縮める**運用側の変更で
対処し、**所要上限は現状のまま**とする。退避物については
**復元可能性と保持期限を同じ変更で固定する**。索引化は行わない。

**理由:**
- 現状の 4 分 43 秒は既に掃除ゲートの所要上限に収まっており、索引化の設計費用
  (無効化条件の設計) が利得に見合わない。
- 並列化は実測で否定済みである (16 thread で改善 20%)。
- 探索根の規模は tool の性質でなく置き場の性質であり、運用で下げるのが筋である。
- 退避が復元不能なら、監査が守っている救出可能性そのものを削ることになる。

**却下した選択肢:**
- 索引化 — 無効化条件の設計に別 wave を要し、現状の所要が上限内である以上先行しない。
- 現状維持のみ — 探索根は今後も伸びるため、退避の規則を今置くほうが安い。

## {{D:trace0-checker-holes-must-fail-closed}}. TRACE=0 前処理同一性検査の既知の穴は塞ぐか、未対応構文で fail-closed にする

**決定 (ユーザー裁定):** TRACE=0 前処理同一性検査に残る 3 件の穴は**すべて塞ぐ**。
全件修理が過大なら、少なくとも
**未対応の構文を検出した時点で fail-closed にする**形を必須とする。
対象は (1) `set(VAR MACRO)` + `${VAR}` の間接供給と行継続 `#define` を追わない、
(2) include を展開前に除去するため定義変更を伴う差分を false-green にしうる、
(3) report が hash 不一致と `identical: true` を同時に立てうる、の 3 件である。

**理由:**
- (1)(2) は false-green を生む。限界の明記だけで残すと、入力の書き方で
  観測者効果の検査を迂回できる。絶対規律 1 と 2 に直接触れる。
- (3) は報告の自己矛盾であり、証拠として使えない出力を出す。

**却下した選択肢:**
- (3) だけ修理し (1)(2) は限界の明記に留める — 迂回可能な検査を権威として使い続けることになる。

## {{D:landing-tip-runner-change-forces-reacceptance}}. 実行器を変える main 取り込みだけ受領証の再利用を拒否する

**決定 (ユーザー裁定):** 受入後に clean な forward-main merge を足した landing tip について、
**取り込んだ main 側が実行器を変えている場合だけ**受領証の再利用を拒否して再受入させる。
実行器を変えない取り込みは現行どおり再走させない。

**理由:**
- 保証対象が変わったときにだけ再検査するのが、保証の意味に正確に対応する。
- 無関係な forward merge まで再走させると、受入全走の回数が理由なく増える。

**却下した選択肢:**
- 保証を original tested tip に限定して明記する — 着地物と主張の対象がずれたままになる。
- すべての main 取り込みで再受入 — 費用が保証の増分に見合わない。

## {{D:digest-neutral-renderer-rejected}}. digest の間接識別子を中立化する renderer は採らない

**決定 (ユーザー裁定):** critic digest 中の間接識別子 (variant label、src token、genome label、
WAL 由来の自由文) を中立 label へ射影する型付き renderer は**採らない**。
必要になった場合は、切替点を再登録した別実験として扱う。

**理由:**
- digest 生成の下流に第 2 の描画経路ができ、両アームの digest 内容が変わる。
  事前登録 §3.1 の切替点固定と衝突する。
- 走行中の系列へ後付けで描画を変えるのは、事前登録の意味を壊す。

**却下した選択肢:**
- 採用して切替点を再裁定する — 既存の実験系列を作り直すことになる。

## {{D:figure-caption-and-overlap-fixed-others-deferred}}. 図は誤キャプションの是正と重なり検査の拒否化だけ行う

**決定 (ユーザー裁定):** 作図の残件 5 件のうち、
**(1) 凍結スナップショット 2 本の誤キャプションの是正**と
**(3) `_overlap_check` の警告から拒否への昇格 (結果を provenance へ残す)** を実施する。
(2) 図の byte 決定的な再生成、(4) パネル間 y 軸の共有または正規化、
(5) read-heavy の CI 帯の視認性は**見送る**。
(1) は凍結物の説明文に触れるため、運用ルールの改訂を同じ変更単位で行う。

**理由:**
- (1) は図が表す内容の正しさに直結し、誤ったまま論文へ入る。
- (3) は誤った図を通さない関門であり、警告のままでは発火しても止まらない。
- (2) は再現性の強化、(4)(5) は視認性で、現段階では正しさより優先度が下がる。

**却下した選択肢:**
- 5 件すべて実施 — 作図まわりに 1 wave を丸ごと使うことになる。

## {{D:legacy-resume-manifest-stays-accepted}}. resume 経路は旧 manifest を legacy として受理し続ける

**決定 (ユーザー裁定):** resume 経路が禁止措置以前の durable manifest を受理し続けることを

**却下した選択肢:**
- 閉じる — 既存の床値記録が一括失効し、得られる保証は資格印が既に与えている。

## {{D:ruling-record-must-refresh-every-covered-item}}. 裁定を記録する wave は、覆われた全 ID の項を同じ fold で更新する

**決定 (ユーザー裁定):** 裁定を canonical へ記録する wave は、その裁定が覆う
**すべての次の一手 item を同じ fold で更新する**。裁定が decisions へ着地しても
worklog の carry stub が裁定前の本文のまま残ると、次の収集がその item を
「裁定待ち」として再提示する。

あわせて、**repo 外の inbox 控えだけを裁定の canonical な証拠にしない**。
控えは収集の補助であり、担い手 branch が未着地のまま裁定が台帳に届かない場合は、
追認の decisions entry を起こして台帳側に置く。

**理由:**
- 2026-08-26 の全件収集で、decisions へ着地済みの裁定 7 件が worklog 側では
  裁定前の本文のまま carry されており、そのまま裁定待ちに見えることを実測した。
- 同じ収集で、inbox 控えにしか裁定が無い案件が 2 件あり、
  台帳を読む者が裁定の存在を知れない状態だった。

**却下した選択肢:**
- 収集側で毎回 decisions と突き合わせる — 収集の費用が item 数に比例して増え、
  突き合わせの取りこぼしが裁定済みの再提示として現れる。
- 控えを canonical と認める — repo 外の file が台帳と同じ権威を持つことになる。
