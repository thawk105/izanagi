## {{D:a2-inert-compare-diff-classification}}. inert 比較は畳んでから比べるのでなく、差を取ってから置き場所由来かを判定する

**決定 (ユーザー裁定):** A-2 の inert (stock) 比較が `preprocess-root-dependent-builtin` で
構造的に必ず赤になる件は、**前処理後 bytes の差を取り、その差が source root / control root 由来の
ものだけかを判定する形**で直す。比較の前に root path を同一の logical token へ畳む案は採らない。
置き場所以外の差が残れば必ず赤になることを、正例 (patch 済み inert = stock で緑) と
負例 (実際に意味が違えば赤) の両方で登録してから入れる。

**理由:**
- 現行の guard は常時発火する。`capture_define_inputs` が stock root と source root を別 path に
  置くことを要求し、code-owned header が `__FILE__` を展開する限り差が必ず出る。
  常に赤の検査は情報を 1 bit も持たず、検査ではなく定数である。
- 畳んでから比べる形は、比較の前に情報を捨てる。畳み方を誤れば本物の差まで隠れ、
  D1198 が守ろうとした「供給は緑だが実行側の意味が違う」型を素通しする。
  差を取ってから分類する形は、元の bytes を検査に見せたまま差の性質だけを判定するので、
  隠す方向の事故が構造的に起きない。
- 負例の登録を条件に付けるのは、置き場所以外の差を通す実装になっていないことを
  挙動で確かめるためである。同一性検査では「効いたか」を言えない。

**却下した選択肢:**
- 比較前に root path を正規化する (起草時の推奨) — 情報を捨ててから比べる形であり、
  畳み方の誤りが差を隠す。別系統モデルも同案について、活性 token の差が残ることを
  負例で確かめる必要があると指摘した。
- `__FILE__` を使う header を owner TU の閉包から外す — CCBench 側の改変であり、
  測定対象そのものを触る。
- inert 比較を A-2 で使わない — 関門が見る命題を変える。受理集合の変更にあたる。

## {{D:certification-build-offline-wiring}}. 認証経路の build は共有経路へ引数を通してオフライン依存へ配線する

**決定 (ユーザー裁定):** A-2 / A-6 の certification 経路の build を、永続 cache と取得 helper を
使うオフライン依存へ配線し直す。配線は共有 measurement pipeline (`run_campaign` →
`pipeline.evaluate` → `buildcache`) へ FetchContent の source dir 引数を通す形で行い、
認証経路だけの別経路は作らない。既存の測定値は取り直さない。

**理由:**
- 計算ノードは offline であり、これが read-heavy の実測が 1 件も取れていない直接の原因である
  (F808)。保管庫と helper は既に在り、他の 2 driver が使っている。足りないのは引数の引き回しだけである。
- 認証経路だけ別の道を作ると測定経路が二重化し、どちらで測ったかが後から混ざる。
- 横断変更で全 driver の configure argv が動くが、既存の測定は当時の事実として残る (規律 7)。
  同一性の差だけを理由に過去の測定を無効にしない。

**却下した選択肢:**
- 認証経路だけ別経路を作る — 測定経路の二重化。
- 配線しない — read-heavy の実測を諦めることと同義である。

## {{D:a5-second-boot-not-satisfied}}. A-5 は未充足のまま残し、Pegasus の結果を別 boot の再現と読み替えない

**決定 (ユーザー裁定):** D1100 が求める「同一機体の別起動」を、Pegasus で取った結果で
充足したとは読み替えない。cygnus を 1 回だけ例外として使うこともしない。
**A-5 は未充足のまま残し、その旨を成果物へ明記する。**

**理由:**
- 元の値は cygnus で取られている。Pegasus で回すと「別の起動」と「別の環境」が同時に変わり、
  起動単独の効果を分離できない。交絡した値を「別起動の再現」と名乗るのは測定の意味を偽る側である。
- 2026-08-05 のユーザー裁定が cygnus 依存の研究をしないと定めており、1 件のために曲げる理由が
  台帳に無い。
- 未充足を正直に残せば主張が 1 つ弱くなるだけで、嘘にはならない。

**却下した選択肢:**
- Pegasus の結果を充足として受け入れる — 交絡した値を再現と名乗る。
- この 1 回だけ cygnus を例外にする — 既存方針を 1 件のために曲げる。

## {{D:oracle-report-judge-selection-enforcement}}. 報告・評決・判定へも選択強制を入れる

**決定 (ユーザー裁定):** oracle の report / verdict / judge へも選択 identity の強制を入れる。
これらは凍結成果物の生成元一覧に含まれるため bytes が動くが、凍結物の所定手続きで払う。

**理由:**
- historical reverify が選択 identity を実行しないという事実 (D1503) は、
  「その経路を被覆済みと数えるな」という決定であって、「強制が不要」を導かない。
  被覆と数えられないなら穴は開いたままである。起草時の推奨はこの決定を誤って援用していた。
- 強制は既に床値の verifier / publish と oracle manifest まで入っている。
  残る 3 経路だけ自己申告で結論と順位へ到達できる形は、防壁の非対称を残す。

**却下した選択肢:**
- 実装しない (起草時の推奨) — 上記のとおり D1503 の誤引用に基づいていた。
- 凍結 bytes を動かさないために据え置く — 凍結物の変更手続きは存在する。

## {{D:lease-generation-granularity-per-acquisition}}. 排他権の世代の粒度は取得ごととし、非保持走行の値を同時に定める

**決定 (ユーザー裁定):** 排他権の世代の粒度は **取得ごと**とする。
併せて、**排他権を取得しなかった走行を表す値を同時に定める** — 取得ごとの粒度では
「取得が無い走行の世代」が定義できず、これを空けたままにすると意味論が完成しないためである。

**理由:**
- 再送防止の射程は既に「別 wave・別 main・別 tip・**別の排他権取得**への再利用を拒否する」
  ところまでと定められている (D1450)。取得より粗い粒度を選ぶと、この射程が構造的に成り立たない。
- 実測では、payload を 1 byte も変えない導出値 (現行 payload の hash、保持者と main の hash、
  wave 単位、main 単位、lease directory の inode) はいずれも再取得で同値であり、
  取得ごとの粒度では恒真になる。粒度を先に固定すると候補の分類が決まる (D1498)。
- 保持しなかった走行の受領証は、保持した走行の受領証と lease の証拠において区別できないことが
  本番経路の観測で確かめられている。粒度だけ決めて非保持側を空けると、
  署名だけ足して鍵の置き場を決めない形と同じ恒真が再生産される。

**却下した選択肢:**
- wave 単位 / main 単位 / lease directory 単位 — いずれも再取得で同値になり、
  D1450 の射程を表せない。
- 取得ごとを採り、非保持走行の扱いを後回しにする — 意味論が未完成のまま実装へ進むことになる。
- 非保持走行を着地不可にする — D1449 が明示的に不採用としており、投入規律を壊す。

## {{D:lease-generation-adoption-deferred}}. 排他権の候補は絞り込みまでで止め、最終採用は鍵儀式の後に再提示する

**決定 (ユーザー裁定):** 排他権の世代の候補について、棄却と shortlist の確定までで止める。
最終採用は行わず、鍵と発行権限の配置が済んだ後に改めて提示する。

**理由:**
- 現行の着地ツールが署名版の検証器を呼ばないため、世代を強制する production consumer が実在しない。
  読み手がいない機構を先に採ると、発火しない保証が 1 つ増える。
- 鍵と発行権限の配置は人間の手番であり (D906、D1400)、AI は代行しない。
- 使い捨て directory は本番 directory と同値でない。拡張属性・inode・保護された別 file・
  外部台帳の積極採用には、本番と同じ filesystem・権限・並行条件での証拠が要る。

**却下した選択肢:**
- shortlist から今すぐ採用する — 上記 3 点がいずれも埋まっていない。

## {{D:missing-population-caveat-by-claim}}. 欠測母集団由来の数値主張には但し書きを付け、単位は文書でなく主張で切る

**決定 (ユーザー裁定):** 欠測 attempt を含む母集団から出た派生記述に但し書きを付ける。
**但し書きの単位は「文書」でなく「数値主張とその母集団」とする。**

**理由:**
- 正典が数えた 4 件では閉じない。同じ規則を当てると「約 7 倍」「balanced 約 6 時間半」
  「read-heavy 約 23 時間」「84.4 マイクロ秒/commit と相関 0.9991 / 0.4044 と係数 -0.309」が入り、
  逆に「15 認証単位」は構造数なので外れる。数値ごとに母集団が違う以上、
  文書単位では必ず取りこぼす。
- 但し書きは値を無効にするものではなく、読み手が根拠の強さを区別できるようにするものである。

**却下した選択肢:**
- 文書単位で切る — 正典の 4 件が全数でないことが実測で示されている。
- 但し書きを付けない — 欠測を含む母集団から出た値が、含まない値と同じ顔で成果物へ入る。

## {{D:s8c-judge-authority-binding-with-producer}}. 段 8c の受理判定の権威束縛は、本番の呼び手を繋ぐ変更と同じ単位で行う

**決定 (ユーザー裁定):** 段 8c の受理 consumer で正しさ判定と attestation を権威へ束縛する作業は、
**tictoc / cicada を接続する変更と同じ変更単位**で行う。今すぐ単独では実装しない。

**理由:**
- 現状は caller の自己申告で公式結論と順位まで到達できるが、production caller が存在せず、
  未接続の interface である。実害はまだ発生し得ない。
- 接続時に必ず通る場所であり、先に防壁だけ建てると使われないまま実装が古びる。
  実 producer の接続と同一変更単位で閉じる形には先例がある。

**却下した選択肢:**
- 今すぐ単独で束縛する — 使われない防壁を先に建てる。
- 束縛しない — 接続時に自己申告の経路がそのまま公式へ通じる。

## {{D:measurement-spec-freeze-by-content-rederivation}}. 測定手順 spec の凍結束縛は、hash 記録でなく内容の再導出で行う

**決定 (ユーザー裁定):** 測定手順 spec の凍結を、spec の path と期待 hash を同じ呼び手が渡す
現行の形から、**承認済み spec から内容を再導出して完全一致で比較する形**へ改める。

**理由:**
- 渡す側が path と期待値の両方を選べるなら、照合は自分で決めた値と自分で決めた値を比べている
  だけで、受理集合を 1 bit も狭めない。同じ形について D302 が既に「hash の記録では束縛にならず、
  承認済み spec から再導出せよ」と決めている。本件はその適用である。
- 粗い provenance の既定方針 (D320) は正しさゲートと測定の公正を対象外としており、
  本件は見送りの対象外である。起草時の「現状維持 + 限界の明記」はこの点を取り違えていた。

**却下した選択肢:**
- 現状維持 + 限界の明記 (起草時の推奨) — D302 の既裁定と逆向きである。
- 新しい凍結受領証を建てる — 再導出で足り、新機構は要らない。

## {{D:measurement-authorization-conditional}}. 測定認可の機械的要求は、成果が公式へ到達しうるかを確かめてから決める

**決定 (ユーザー裁定):** 測定認可の受領証を機械で要求するかは、
**認可なしに回した成果が official / certified の consumer へ到達できるかを dataflow で確かめてから**
決める。到達しないなら要求しない。到達するなら要求する形を設計する。

**理由:**
- 新しい受領証の仕組みは、粗い provenance の既定方針では見送り側に入る。
  しかし到達するなら見送りの対象外 (正しさゲートと測定の公正) へ移る。
  到達性を確かめずにどちらへ倒しても、根拠のない判断になる。
- 実験用に閉じているなら、認可の受領証は発火しない保証を 1 つ増やすだけである。

**却下した選択肢:**
- 到達性を確かめずに要求しないと決める (起草時の推奨) — 別系統モデルが根拠不足と判定した。
- 無条件に要求する — 発行主体・束縛項目・一回限りの消費をすべて凍結が定める必要があり、
  到達しない場合には過大である。

## {{D:artifact-immutability-scope-unchanged}}. 成果物の不変性は同一 path の再作成防止までとし、範囲を明記する

**決定 (ユーザー裁定):** 測定成果物の不変性は現行のまま「同じ path が残っている間の再作成」を
防ぐところまでとする。削除・改名・別 path での選別再走は防がない。**防いでいない範囲を
成果物へ明記する。**

**理由:**
- これらを防ぐには成果物とは別の権威へ attempt を予約する仕組みが要る。
  改竄が正式な受理まで届く実経路が示されていない段階では、bytes 級 provenance の見送り側に入る。
- 防いでいない範囲を明記すれば、恒真な保証にはならない。

**却下した選択肢:**
- 予約の仕組みを新設する — 実経路が示されていない。

## {{D:sample-independence-one-per-window}}. 標本の独立性は 1 時間窓 1 標本とする

**決定 (ユーザー裁定):** 測定標本の独立性の規則を **1 時間窓 1 標本**とする。
同一 window 内の連続標本を独立な機会として数えない。

**理由:**
- 連続した測定は機械の状態を共有するので、独立と数えると機会の数を過大に計上する。
- 保守側に倒しておけば、後から主張を弱める必要がない。

**却下した選択肢:**
- 同一 window 内の連続標本を独立と数える — 独立性の過大計上。
- 最小間隔を置く — 間隔の値を選ぶ根拠が今は無い。

## {{D:upper-bound-statistics-frozen-as-two}}. 上限統計は現行の 2 件のまま凍結する

**決定 (ユーザー裁定):** 上限統計の登録簿は、保守側 = 最大の機械化 2 件のまま凍結する。
分位・信頼水準・許容限界の規則は今は採らない。

**理由:**
- 最大値は上限として保守側であり、標本が少ない段階で分位を持ち込むと、
  根拠のない精度を主張する形になる。
- 段階導入の方針に合う。必要が生じたときに ID と入力単位を凍結が定めればよい。

**却下した選択肢:**
- 分位・信頼水準を今のうちに足す — 使う根拠がない。

## {{D:perfconfig-producer-conditional}}. 校正済み設定の producer は、代替の用意の可否を確かめてから決める

**決定 (ユーザー裁定):** 完全な `PerfConfig` 成果物の producer を作るかは、
**既存機構または認可された人間手番で校正済み設定を用意できるかを先に確かめてから**決める。
用意できるなら作らない。用意できないなら作る。

**理由:**
- 現物の calibration は `extime` / `reps` / `ycsb_max_ope` を持たず、driver は spec の明示で埋めている。
  代替の producer が無いまま「作らない」と決めると、事前登録 §5 の充足を永久に塞ぐ。
  別系統モデルがこの点を指摘した。
- 用意できるなら、校正の権威を artifact 側へ移す作業は不要である。

**却下した選択肢:**
- 無条件に作らない (起草時の推奨) — §5 の充足を塞ぐ可能性を検討していなかった。
- 無条件に作る — 代替があるなら重複した権威を作る。

## {{D:layer3-self-inconsistent-calibration-hold}}. 自己整合しない較正は、健全な世代が発効するまで層 3 の床値に使わない

**決定 (ユーザー裁定):** 有効な環境契約が pin する較正が自分の effective-clock 述語を
48 本中 1 本で通らない件について、**健全な世代が発効するまで、当該環境系列の within-run は
一致なしのまま保つ。** このまま使う現行実装は改める。

**理由:**
- 自分の検査に落ちる値を新しい系列の床値として黙って採ると、恒真な保証が 1 つ増える。
  「既知の例外として登録済み」であることは、床値として使ってよい根拠ではない。
- 既存成果物の値は 1 件も変わらない。現存する層 3 レポートはすべて別環境の lock であり、
  影響は今後生産される分だけである。したがって一致なしに保っても過去の測定は動かない。
- 健全な世代の発効は人間手番であり、発効後に値は自然に埋まる。

**却下した選択肢:**
- このまま使う (現行実装) — 自己整合しない値を床値として採る。
- 自己整合性を層 3 で再検査する関門を新設する — 新しい防壁の新設であり、既定では見送り側。
  発効を待てば不要になる。

## {{D:genome-absent-record-allowlist}}. genome 不在 record の silo 仮定は既存分の内容 hash に閉じる

**決定 (ユーザー裁定):** 層 3 が genome 不在の within-run record を silo と仮定する扱いを、
**既存 record の内容 hash の許可リストに固定する。** 今後作られる genome 不在 record は
層 3 で拒否する。

**理由:**
- この仮定は「歴史的 record」の扱いとして認められたものである (D1374)。
  限定が実装で効いておらず、非 certify 経路が今後も同じ形の record を書ける。
  過去の記録に仮定を置くことと、これから作れる記録に仮定を置くことは意味が違う。
- 内容 hash の固定は、既に決まっている限定をコードで表すだけの最小変更である。
  既存の値は 1 つも動かない。

**却下した選択肢:**
- 非 certify 経路にも由来を導ける仕組みを作る — producer の作り直しであり、
  公式の値を出している経路を触る。
- 現状のまま silo 仮定を続ける — 仮定が静かに将来へ広がる。

## {{D:dynamic-input-unreachability-unresolved}}. 動的入力に依存する設定式では、不在を到達不能の証明に使わない

**決定 (ユーザー裁定):** 設定式が動的入力に依存するとき、部分 inventory に載っていないことを
`proven-unreachable` の根拠にしない。**`unresolved` へ倒す。**

**理由:**
- 動的な入力がある以上、部分的な inventory を閉じた集合として扱う到達不能の証明は成立しない。
  現状はこの扱いで 18 セルが落ちている。
- 受理集合を**狭める**方向であり規律 2 の側である。誤った到達不能の証明を直した先例が
  既にある (D1501)。閉包の被覆は到達可能 domain に対する割合で報告する形とも整合する (D1502)。

**却下した選択肢:**

## {{D:mutation-application-not-drift-check}}. 変異が広域に赤を出す件は当て方を直し、drift 検査は弱めない

## {{D:grammar-version-sort-local-binding}}. 文法版の cache 束縛は sort 軸へ局所適用し、族へ一般化しない

**決定 (ユーザー裁定):** 文法の版を identity・WAL・build cache の三脚へ束縛する規則について、
**任意の軸への一般化は行わないが、sort 軸には局所的に同じ形の束縛を入れる。**
束縛は D1411 と同じ campaign 由来の明示引数で渡す形とする。

**理由:**
- sort 軸は contract ID 経由で identity と WAL には届くが、build cache の鍵には届かない。
  この分断は stale build の再利用を生む実在の欠陥であり、放置は測定の意味に触れる。
- 一般化ではなく個別対処なので、族一般化の条件 (独立 2 例) を満たす必要はない。
  起草時の推奨 (backoff 限定のまま維持) は、族一般化の条件を満たさないことを
  「何もしない」の根拠として使っており、実在する分断を見落としていた。
  別系統モデルが独立にこれを指摘した。
- path 判定でなく campaign 由来の引数で渡すのは、版を持たない campaign の variant id と
  cache key まで動かさないためである。

**却下した選択肢:**
- backoff 限定のまま維持する (起草時の推奨) — sort 軸の実在する分断を残す。
- 任意の軸へ一般化する — 独立 2 例の条件を満たさない。

## {{D:t2097-deferred-items-declined}}. probe 同等性の立証設計と旧 checkout の再現は行わない

**決定 (ユーザー裁定):** 先行 wave が範囲外として裁定へ返した 2 件 —
(1) probe 効果の同等性を複数 job と無作為化で立証する設計、
(2) 旧 checkout での所要値そのものの再現 — は、**いずれも行わない。**
ただし次の一手へ番号を付けて記録し、insights にだけ残る状態を解消する。

**理由:**

- (2) は既存の測定が当時の事実として残る以上、再現できないことと事実でないことは別である

**却下した選択肢:**

## {{D:d1511-premise-remeasure}}. 旧 grammar 裁定の前提は、実測で確かめてから再提示する

**決定 (ユーザー裁定):** 旧 grammar の互換読取器を作らないとした裁定 (D1511) の前提と、
稼働 wave の実測が食い違う件は、**まず旧 grammar が受入全走の失敗原因であることを実測で
確かめる。** 原因と確定したら、D1511 の再訪条件が成立したものとして 3 案
(版付き decoder を作る / 該当 lock を新閉包で発行し直す / 図の生成経路を別の束縛へ移す) を
改めて提示する。いずれの案も現行 certified 経路を緩めないことを必須条件とする。

**理由:**
- D1511 は「repo 側 consumer は file bytes の SHA-256 で束縛して読んでおり、受入は赤にならず
  図の再生成も壊れない」を理由の柱にしている。しかし稼働 wave は受入全走で図の生成経路が
  旧 grammar lock を decode できずに落ちると実測し、そのために着地できていない。
  前提と実測が逆を向いている以上、どちらかが誤っているか、両者が別の経路を指している。
- D1511 の再訪条件は「当該 artifact を admission API 経由で読み直す必要が実際に生じたとき」である。
  受入が実際に落ちているなら、この条件は既に成立している可能性が高い。
- 前提の確認を飛ばして案を選ぶと、実在しない原因に対して受理側へ分岐を足すことになる。

**却下した選択肢:**
- D1511 をそのまま維持して閉塞を放置する — 完成済みの実装が着地できないままになる。
- 実測せずに版付き decoder を作る — 実在しない原因に対して受理範囲を広げうる。

## {{D:untracked-residue-cleanup-authorized}}. 作業ツリーの 0 byte 残骸は、変異走行の不在を確かめたうえで削除してよい

**決定 (ユーザー裁定):** 主 checkout に残る 0 byte の想定外 untracked file 群
(日本語の文の断片が file 名になっているもの、および同時に作られた同種の空 file) は、
**稼働中の変異走行が 0 本であることを確かめたうえで削除してよい。**
`.git/info/exclude` は触らない。

**理由:**
- 引用を誤った shell 実行の残骸であり、内容を持たない。
- 共有の untracked 集合は変異 harness の観測対象であり、走行中に変えると
  source 木の status bytes 不変の事後検査を破って全損させうる。したがって不在の確認を条件に付ける。
- `.git/info/exclude` で隠すと、変異 harness が観測している `?? .codex/worktrees/` の
  扱いまで変わりうる。除外設定ではなく削除で解く。

**却下した選択肢:**
- 確認せずに削除する — 稼働中の変異走行を全損させうる。
- `.git/info/exclude` へ足して隠す — 観測対象の集合を変える。
- 残す — `git status` が読めない状態が続く。
