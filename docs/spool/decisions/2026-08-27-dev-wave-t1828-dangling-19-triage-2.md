## {{D:rescue-pin-before-triage}}. 到達不能 commit の救出は、分類の前に ref で固定してから行う

**決定:** 到達不能 commit を分類・救出する作業では、**着手直後に対象全件へ
`refs/rescue/<task>/<sha>` を張って自動 prune を止め、その状態で分類する**。
救出物を作り終えたら、同じ wave の終端で ref を全部外す。外した時点で破棄と判定したものは
到達不能へ戻り、救出したものは bundle が唯一の復元経路になる。

適用条件は「対象に `gc.pruneExpire` の既定 2 週間を越えたものが 1 件でもある」場合とする。
手動 gc・`git prune`・`git repack`・branch 削除は依然として行わない。

**理由:**
- 分類には対象の全 path の内容照合が要る。本 wave の実測では repo 外 1,482,382 file の
  走査に index 作成だけで 6 分以上かかった。分類の所要時間は数十分の桁になる。
- 一方 D970 の対象は最古が 2026-08-11 で、着手時点で既に猶予を越えていた。並行 wave が
  commit するたびに `gc --auto` が走りうるため、**分類が終わる前に対象が消える経路が実在する**。
- ref は分類の前提そのものを守る。ref を張らずに分類すると、判定した瞬間に対象が
  無くなっている可能性を排除できず、判定の根拠が事後に検証できない。
- 前段の救出 wave は source repo の ref DB へ書かない方針を採ったが、それは対象が
  猶予内にあったから成立した設計であって、猶予切れの集合には転用できない。

**却下した選択肢:**
- ref を張らずに分類する — 対象が消える窓を開けたまま長時間の走査を行うことになる。
  消えたかどうかは走査後にしか分からず、消えていれば作業が丸ごと無駄になる。
- 全件を無条件に bundle 化してから分類する — 分類の結果に関わらず全件が恒久保管物へ入る。
  救出対象を絞る裁定の趣旨に反する。
- ref を張ったまま wave を終える — 破棄と判定したものまで永久に生き残る。破棄は
  「放置して自動 gc に委ねる」ことなので、ref を残すと破棄が実行されない。
