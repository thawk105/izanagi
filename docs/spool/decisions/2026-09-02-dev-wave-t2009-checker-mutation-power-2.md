## {{D:identity-layer-attribution}}. 検出力を数えるとき、同一性層の赤は挙動検出として数えない。冗長 gate の集合は等価変異 1 件を走らせて実測する

**決定:** 変異による検出力の測定では、次の 2 つを分けて数える。

1. **挙動 node** — 受理集合または fail-closed 挙動の変化を捕まえた赤。
2. **同一性層** — source の bytes が記録 blob と違うことだけを見た赤。

同一性層の集合は**推測で決めず、受理集合を一切変えない等価変異を 1 件走らせて実測する**。
その等価変異が赤にした node が、その走行における冗長 gate の集合である。本走ではこれを
`--deselect` し、挙動 node の完全集合を期待として登録する (`DW-M03`、`DW-M08`)。

**理由:**

- 2026-09-02 の実測。`orchestrator/verifier/dsg.py` の `if u != v:` を `if not (u == v):` に
  書き換えるだけの等価変異が **53 node** を赤にした。理由はすべて
  `IdentityMismatch: contract-loader-drift: disk bytes が記録 commit blob と不一致` であり、
  `CONTRACT_LOADER_RELATIVE_PATHS` の HEAD blob pin である。
- 同じ 53 node は、rw 反依存辺を落として検査器を実際に壊す変異でも赤になる。
  **同一性層は「壊した変異」と「何も変えない変異」を区別しない。** 壊した側の赤 72 件のうち
  53 件 (74%) がこの層であり、これを検出力として数えると 3.8 倍に水増しされる。
- これは絶対規律 7 の「同一性は『変わったか』しか言えず『効いたか』を言えない」という主張の、
  repo の現物による実測である。**同一性検査を禁じるものではない** — 規律 7 自身が束縛・
  完全性・意味互換性の検査としての同一性検査を明示的に許している。禁じるのは、
  その赤を弱体化の検出と読み替えることだけである。
- 集合を静的に推定してはならない。同 wave の段 2 プランと段 3 の独立検査者が**そろって**
  「呼び出し関係を辿ると、この分母では同一性 pin は発火しない」と結論し、実測が覆した。
  追跡自体は正しかったが、分母に入れた 2 file がその経路を通っていた。

**却下した選択肢:**

- **同一性層を分母ごと外す** (pin に載る file を含む test file を丸ごと落とす) — 同じ file に
  実在の挙動検出 node が同居する。実測では正例対照を捕まえた node が、まさに同一性層と
  同じ file にあった。file 単位で落とすと真の検出を捨てる。
- **同一性層の赤も検出として数え、注記だけ付ける** — 等価変異でも同じ赤が出る以上、
  数字が意味を持たない。注記は数字の誤りを直さない。
- **冗長 gate を静的解析で列挙する** — 上記のとおり 2 者が独立に外した。

**射程:** 本決定は「変異で検出力を数えるとき」の手続きであり、同一性検査の是非には触れない。
族全体への制度化 (等価変異の常設対照化) は独立 2 例が揃っていないので行わない (`DW-G03`)。

## {{D:mutation-denominator-is-verdict-consumers}}. 変異の分母は「実 checker を呼ぶ test」ではなく「その判定を使う test」で決める

**決定:** 検査器の変異に対する検出力を測るとき、走らせる test の集合は、対象 module を
import するか、あるいは対象を呼ぶかではなく、**対象が返した判定を後段で使うか**で決める。
静的な呼び出し列挙だけで node を選ばず、file 単位で走らせて観測 node から絞る。

**理由:**

- 2026-09-02 の実測。`orchestrator/tests/test_campaign.py` には実 verifier を呼ぶ経路が
  2 つあり、検出力が正反対だった。一方は実 verifier を呼んだ**直後に結果を固定の赤
  オブジェクトへ差し替える**ので、verifier をどう壊しても緑のまま通る。もう一方は
  差し替えないので、rw 反依存辺を落とす変異を実際に捕まえた。
- 「対象を呼んでいる」ことは検出力の必要条件ですらない (呼んで捨てる consumer がある) し、
  十分条件でもない。**判定を使っているか**だけが条件である。
- 静的に「実 checker を呼ぶ node」を列挙する方法は、同 wave で実在の検出 node を
  1 件取りこぼした。file 単位で走らせて観測 node から絞る方が安く、取りこぼさない。
  対象の 5 file 全体で 709 件 / 28 秒だった。

**却下した選択肢:**

- **exact node selector を静的に組む** — 上記のとおり取りこぼした。費用の節約にもならない。
- **transitive import 閉包を全部走らせる** — 100 file を超え、その大半は保存済み JSON を
  consumer として検査するだけで source 変異に反応しない。分母を膨らませると
  同一性層の赤で全件 KILLED に見える。
