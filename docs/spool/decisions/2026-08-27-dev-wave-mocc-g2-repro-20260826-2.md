## {{D:preregistered-repro-rate-study}}. 再現率 study は分母を job の値だけで決め、投入集合を正本の全列挙で閉じる

**決定:** 正しさの再現率を測る study では、次を実走前に凍結し、結果を見た後に緩めない。

1. **分母・分子は、job が書いた値だけで機械的に決める。** 事後の裁量が入る欄を作らない。
   本 study では `failure.json` の `stage`、verifier の rc、verifier JSON の中身の組で決めた。
2. **「失敗した run を除外する」と素朴に書かない。** 正しさの anomaly は job を
   fail-closed させるので、素朴な除外規則は分子を構造的に消す。
   除外は失敗の**段階**で決め、判定器が verdict を出した run は結果にかかわらず分母へ入れる。
3. **投入集合は正本の全列挙で閉じる。** 解析対象へ写した後の集合を数えるのは恒真である。
   投入口が作る create-only な submission directory を全列挙し、
   receipt の `source_commit` で分割して凍結 commit のものだけを受理する。
   除外したものは件数だけでなく識別子と理由を残す。
4. **反復数は「何を排除したいか」から決める。** 費用が安いことは根拠にならない。
   k=0 のときの上側信頼限界が、排除したい率を下回るように N を選ぶ。
5. **estimand の環境条件は、固定したつもりの量と実際に観測された量を分けて報告する。**
   投入時の扇出と実行時の同時実行数は別物である。

**理由:**
- 正しさの run を緑が出るまで回して緑だけを報告するのは selection bias であり、規律 2・3 の
  趣旨に反する。事前登録はその誘惑を機械的に断つ唯一の手段である。
- 除外規則の素朴な書き方が分子を消す件は、実際に前 wave の観測で起きうる形だった。
- 閉包を解析対象側で取ると、「解析対象へ写さない」という 1 手で受理集合を選べる。
  正本側で取ればその手が使えない。

**却下した選択肢:**
- 投入口へ ordinal と study ID を持たせる — 実走前に検証済みの投入口を変えることになり、
  study 本体が未検証コードに依存する。正本の全列挙で同じ閉包が取れる。
- 結果を見てから反復を追加する — 停止規則が結果依存になり区間の意味が失われる。
- 同時実行数を制御するため 1 本ずつ直列に走らせる — queue 待ちが反復数だけ増え、
  時間帯の交絡がかえって大きくなる。

## {{D:anchor-externality-tiers}}. 外部 anchor は自己導出できない証拠がある場合だけ名乗る

**決定:** 成果物の同一性を「外部 trust anchor で検証した」と主張してよいのは、
**repository と receipt の両方の外**に由来する証拠を検証できた場合だけとする。
段階を名前で分ける。

- `consistency_checked_but_unanchored` — 内部整合性だけを確認した。
  過去に独立した pin が保持されていない成果物 (歴史的 receipt) は常にこれ。
- `caller_supplied_consistency_checked` — 呼び手が pin を与えたが、
  その pin は repository と receipt から自己導出できる。
- `externally_anchored` — repository の外で保持された署名済み manifest を検証できた。

**あわせて、attestation していない範囲を成果物本文へ明記する** —
同じ Git repository を source store として信頼していること、host・runtime・
検証器自身は attestation していないこと。

**理由:**
- receipt が指す commit は receipt 自身の自己申告である。その commit の blob と
  receipt 内の hash を照合しても内部整合性しか示さない。これを外部 anchor と呼ぶのは
  恒真な保証であり、下流が実際より強い保証を受け取ったと誤解する。
- 段階を名前で分けないと、弱い検証しかできない場合に強い名前へ倒れる圧力がかかる。

**却下した選択肢:**
- 検証器が自分で Git blob を読んで一致を出力する — 検証器が改変されている脅威に対して循環する。
  防げるのは偶発的な live drift までである。
- 歴史的成果物にも遡って anchor を発行する — 当時独立した pin が保持されていない以上、
  発行できるのは自己整合性の確認だけである。
