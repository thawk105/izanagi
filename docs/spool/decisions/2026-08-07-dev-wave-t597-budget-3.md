## {{D:budget-reduction-by-duplication}}. dev-wave 予算の捻出根拠は「同一読点で読まれる上位互換節との重複」に限り、「機械が強制するから」を根拠にしない

**決定:** `docs/dev-wave/**` の byte 予算を捻出する縮約は、次の 3 条件をすべて満たす重複だけを
対象にする。

1. **同一読点** — 削る記述の義務が効く瞬間に、担い手とされる節が入口の段 dispatch または
   条件 dispatch で**必ず読まれる**こと。「別の場所にも書いてある」では足りない。
2. **上位互換** — 担い手の逐語が、削る記述の全要素を含むこと。要素の欠落は義務の消失である。
   削除前後を逐語で並べて照合し、片方にしかない要素を列挙して確認する。
3. **単一正本化** — 縮約後に同じ集合・同じ値を 2 箇所で管理しないこと。
   逐語の再掲でなく参照へ倒す。

**「テストや機械検査が担うから prose を削る」を捻出の根拠にしない。** T-127 裁定の
「恒久対応は prose でなくテスト・機械検査を優先」は**新しい義務の置き場所**の指針であって、
**既存 prose の削除根拠**ではない。この区別を置く理由は次の実測である。

- 削除候補の義務を実装が**満たしていない**ことがある。F95 は `DW-M08` が定める正規化を
  harness 自身が持たないと明記しており、その修正は未了のままだった。prose を削れば、
  実装が満たさない義務の唯一の住所が消える。
- 機械強制の**射程が prose より狭い**ことがある。canonical stdout の義務は runner mode により
  経路が分かれ、独自 harness を条件付きで許す節がある以上、tool への pointer は全読者を覆わない。
- 機械強制に**対応する pin がない**ことがある。分岐は存在するが test がなく、分岐を消しても緑のまま
  という状態は珍しくない。pin のない機械強制は、prose を削る根拠として自己申告に等しい。
- pin を足そうとしても**恒真にしかならない**ことがある。同値再代入の分岐は、単独削除で
  赤くならないため検出力ゼロの test しか書けない。

したがって機械化は「新しい義務を prose でなく test へ置く」ためには使えるが、
「既存 prose を削ってよい」証明にはならない。後者には上の 3 条件を要求する。

**理由:**
- `docs/skill-self-improvement.md` は「予算のために安全義務を削除・弱化してはならない」と定め、
  かつ「義務本文の文言と意味の保存は lint に固定せず、敵対監査と人間レビューで担保する」と
  明記している。機械化を削除根拠にすると、この担保が形骸化する。
- 3 条件は敵対レビューで**反証可能**である。同一読点は dispatch 表で、上位互換は逐語照合で、
  単一正本化は grep で、それぞれ実測して真偽を判定できる。「機械が担う」は実装の全経路を
  読まなければ反証できず、レビューの負荷が非対称に大きい。

**却下した選択肢:**
- **可読性用の空白削り** — inline code 前後の半角空白を全廃すれば約 107 bytes になるが、
  予算のために可読性を削るのは手段目的の逆転で、`docs/skill-self-improvement.md` の禁止に触れる。
- **節 (H2) の削除** — D94 決定 2 によりユーザー裁定必須。かつ削除候補として残る節は
  「完全機械化できた場合だけ再裁定」の条件付きであり、その完全機械化が上記のとおり成立しにくい。
- **個別 cap の再割付** — T-127 裁定の独立審査対象であり、実効 gate は aggregate なので
  再割付では 1 byte も増えない。
- **他文書への外出し** — D94 却下案 (a) が既出。契約は leaf 節読了であってファイル全読ではないため
  読了 payload の削減が 0 になる。
