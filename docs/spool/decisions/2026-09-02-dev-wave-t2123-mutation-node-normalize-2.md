## {{D:mutation-node-match-key-seam}}. 変異 harness の node 同形化は比較の座だけで行い、記録は観測の姿を保つ

**決定:** `DW-M08` の要求する「同形式へ正規化した記録 node との完全一致」は、
比較 key を作る関数 (`_match_key`) だけで実現する。台帳へ書かれる `failed_nodes` /
`collected_nodes` / registration の `expected_nodes` は、観測した表記のまま保存する。
xdist group 接尾辞の除去は、node を最初の `::` で分割した**test 名部分にだけ**当て、
`rfind("@") > rfind("]")` が成り立つときに一段だけ落とす。

**理由:**
- `DW-M08` の前段は「harness は rc と失敗 test node を毎回記録する」と定める。記録側で
  正規化すると、実行時に接尾辞が実際に付いていたという観測事実が台帳から消える。
  正規化は突き合わせの都合であって、観測の書き換えではない。
- 除去を node 全体へ当てると path 内の `@` を group 名と誤認する。
  `tests@left/x.py::test_case` と `tests@right/x.py::test_case` がどちらも `tests` へ潰れ、
  別テストしか落ちていないのに完全一致が成立して偽 KILLED を作る。
  現行 repo に該当 path は無いが、比較器の受理集合を広げない形を選ぶ (絶対規律 2)。
- 条件節 `rfind("@") > rfind("]")` は parametrize ID 内の `@` を守るために要る。
  repo の実在 nodeid 19519 件のうち `@` を含む 26 件へ当てた実測で、実 group 接尾辞 1 件だけを
  落とし、parametrize ID 内の 25 件を保った。守られた側には
  `[@]`、`[試験::場合@直列]`、`[試験::場合[値@例]]` という敵対的な入力が既に含まれる。

**却下した選択肢:**
- 記録側 (`_normalize_node`) で除去する — 台帳の忠実性を失う。変異走行で実際にこの向きを
  当てたところ、`failed_nodes` が base 表記へ変わって専用の assert が赤になった。
- 単純な `split("@")` / `rpartition("@")` — parametrize ID 内の `@` を壊す。実在例がある。
- 複数段の `@` 除去へ一般化する — pytest-xdist は複数 group 名を `_` で連結するため
  nodeid の `@` は必ず 1 個であり、repo の group 名にも `@` は無い。到達不能な形へ備えない。

## {{D:duplicated-rule-needs-per-layer-controls}}. 同じ規則を 2 実装へ複製したら、敵対入力は層ごとに用意する

**決定:** 同一の判定規則が独立した 2 つの実装として存在する場合、その規則を守る
正例・負例は**各実装を直接呼ぶ形で層ごとに置く**。片方の層だけを攻撃するテストで
両方が守られていると数えない。変異の事前登録も層ごとに分ける。

**理由:**
- 本 wave では node の同形化規則が変異 harness と fan-out の終端検証器の 2 箇所に複製された。
  実装は同形だが、共有された関数ではない。
- 段 6 のレビューが「敵対 literal が harness 側しか通っていない」ことを検出した。
  この状態では、fan-out 側で同型の欠陥が再発しても追加したテストは緑のままである。
- 層ごとに変異を登録して実測したところ、両層の対応する変異がそれぞれ別のテストを
  赤にした。層をまとめて 1 件として数えていたら、片側の検出力ゼロを見逃していた。

**却下した選択肢:**
- 実装を 1 つへ寄せて共有 module にする — fan-out の終端検証器は harness と独立に
  台帳を再検証することが存在意義であり、共有すると同じ誤りが両方で同時に起きる。
  独立実装のままにして、代わりに層ごとの検査を課す。
- 片方の層のテストで代表させる — 独立実装である以上、代表にならない。
