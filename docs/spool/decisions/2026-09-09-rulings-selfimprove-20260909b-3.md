## {{D:r17-minimal-form}}. 第 17 回の裁定の実装は最小形に限り、名指し外の gate・検査・台帳を足さない

**決定 (ユーザー裁定、2026-09-09 /rulings 全件 第 17 回、推奨どおり):** 本回の各裁定を実装する wave は、
決定本文が名指しした変更だけを行う。付随して気づいた防壁・検査・台帳項目を同じ変更単位へ足さない。
起草推奨のうち 8 件は別系統モデルの相談が覆した形を採っており、覆った側の理由も各 D に残す。

**理由:**

- D1736 / D1769 / D1811 が第 13〜15 回について同じ枠を定めており、本回もそれを継ぐ。
- 本回の索引 52 件のうち過半は「見送る・明記する」であり、実装面へ落ちるのは少数である。
  最小形を先に固定しないと、見送りの明記に付随して新しい検査が増える。
- 相談が覆した 8 件には、既裁定と正面から矛盾する起草推奨が 2 件あった (source closure の収載範囲、
  受入時間の測定面)。矛盾の再発を防ぐため、各 D に既裁定との関係を明記する。

**却下した選択肢:**

- 覆った推奨だけを記録し、起草推奨を残さない — なぜ覆ったかが後から辿れない。

## {{D:r17-a6-perf-byproduct}}. 実行基盤の測定に付随して得た A-6 の性能値は attempt に数えない

**決定:** 遠隔検査の実行基盤を測る過程で得た A-6 の性能値 (効果 −4.876%) を、A-6 の 2 本目の
attempt として扱わない。実行基盤の副産物のまま残し、A-6 の主張には使わない。

**理由:**

- attempt として数えるには、attempt 数と停止基準の事前登録および `tracked_destination` の新 leaf が要る。
  事前登録は結果を見る前に立てる規範であり (規律 3)、値を見た後の昇格はこれを崩す。
- D1841 が「結果を見た後の虚偽分類をコードで検出できない」として、運用者の申告で解錠する設計を
  既に退けている。昇格の判断も同じ性質を持つ。

**却下した選択肢:**

- 2 本目として数える — 標本は 1 本増えるが、事前登録の後付けになり cohort の主判定の信頼性を落とす。

## {{D:r17-b4-prereg-start-time}}. B-4 事前登録の開始時刻欄は発効条件から外す

**決定:** `docs/phase3-b4-reflux-ablation-preregistration.md` の「実行責任者・開始時刻」欄について、
**開始時刻を発効条件から外す**。`p3_b4_admission_record.py` の行 label 集合は変えず、本欄に限り
`未記入` を受理する。§0 の原子性・sentinel 規則は他の欄についてはそのまま維持する。
事前登録本文の改訂は同文書の改訂契約 (追補) に従って別 wave が行う。

**理由:**

- D1649 決定 2 が既に「timezone 付きの予定開始時刻を記入し、この時刻より前に実走を開始しない」という
  拘束を撤廃し、「欄は `未記入` のままでよく、実際の開始時刻は実走成果物側の記録だけを正本とする」と
  定めている。受理側がまだ `未記入` を拒否しているのは、その裁定の未実施である。
- 起草推奨は「本欄に非 sentinel の値を定義する」だったが、これは D1649 の「未記入のままでよい」と
  食い違う。別系統モデルの相談が誤引用として指摘し、現物で確認した。
- §0 の規則そのものを改訂する案は、他の欄の発効条件まで緩めるので採らない。

**却下した選択肢:**

- 本欄へ登録時刻などの値を書く (起草推奨) — D1649 が不要と決めた記入を復活させる。
- §0 の原子性・sentinel 規則を改訂する — 対象外の欄の保証まで弱める。

## {{D:r17-gate-core-fallback}}. 起動検証済み凍結の gate は exact 必須へ縮める

**決定:** `_gate_check_core` の v2 fallback を廃し、exact な `LaunchValidatedFreeze` を必須にする。
D65 決定 (5) の不変条件を全分岐で成立させる。実装面なので Codex `role=author` と変異事前登録を要する。

**理由:**

- 到達に「初回 read 失敗 → 直後の再 read 成功」という外部要因が要ることと、受理されうる freeze が
  active 世代に限られることは偶然の性質であって、gate の意味ではない。gate が 2 通りの意味を持つ
  状態は正しさゲートの穴である (規律 2)。
- 受理集合を狭める局所修正であり、新しい機構を作らない。

**却下した選択肢:**

- 現状維持で台帳へ記録する — 穴を記述するだけで穴は残る。

## {{D:r17-frozen-spec-fixpoint}}. 凍結 spec の不動点は狭い形を採らず現行の広い形を維持する

**決定:** 凍結 spec の同一性判定に「唯一の親 + spec 1 path 差分」という狭い形を採らない。
D1774 が定めた祖先関係と tracked blob 一致の形を維持する。

**理由:**

- 狭い形は freeze commit の後続 commit で load 不能になる。正常な前進で既存の凍結成果物が
  読めなくなるのは、凍結が守るべきもの (測定の意味) を守らず bytes の同一視に寄せた形である (規律 7)。

**却下した選択肢:**

- 狭い形を採る — 同一性の主張は強くなるが、freeze 後 1 commit で運用が止まる。

## {{D:r17-stock-inline-authorization}}. 在庫比較の正式測定を認可し、事前登録前の生値は主張へ転用しない

**決定:** balanced の stock-inline 対比較について、事前登録の実値 (期待 commit・gitlink・環境契約 digest・
job body script digest・arm 別 source digest) を固定したうえで**正式測定を認可する**。
2026-09-07 に取れた balanced の生値は、本項の主張へ**転用しない**。文脈としてだけ残す。

**理由:**

- D1244 が求めた最小 3 部品は着地済みで、D1267 が認可の前提とした条件に到達している。
  保留を続けると在庫比較の主張が測れないまま止まる。
- 事前登録の前に取れた値を後から主張へ入れるのは prospective 事前登録の意味を壊す (規律 3)。

**却下した選択肢:**

- 既存の生値を転用する — 1 本分の計算は節約できるが、prospective の看板を下ろすことになる。
