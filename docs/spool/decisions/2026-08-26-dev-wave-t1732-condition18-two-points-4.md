## {{D:archive-name-entry-form-decided-first}}. archive 名は entry 形を先に確定し、残りを日付形とする (D445 の判別鍵を改訂)

**決定:** `docs/archive/worklog-*.md` の位置文法で、**`<MMDD>-<entry>` の形を日付範囲より先に確定する**。
D445 が定めた「日付 token と entry 番号 token の判別鍵は先頭ゼロの有無」を、
**「位置文法で entry 形を先に確定し、残りを日付形とする」**へ改める。
三値分類 (非採番 / 採番 / malformed) と、正規文法に合わない名前を malformed にする方針は D445 のまま残す。

**理由:**

- **D445 の根拠が実測で反証された。** D445 は理由に「先頭ゼロを鍵にすると、4 桁の entry 番号
  (1000 以上) を MMDD と取り違えない」と書いているが、**10〜12 月の MMDD に先頭ゼロは無い**。
  `ARCHIVE_MMDD_TOKEN_RE` と `ARCHIVE_ENTRY_TOKEN_RE` の交差は
  entry 1001-1031 / 1101-1131 / 1201-1231 の計 93 件ある
  (日部が月と独立に 31 を通すため、暦上存在しない 11/31 も含む)。
- **生成側は既に entry 形を宣言している。** `tools/spool_fold.py` の `_rotation_name` は
  日付範囲名を生成せず、`ROTATION_PATH_RE` は 2 番目の token を entry 番号として pin している。
  検査側だけが同じ位置を日付として先に読んでいた。**生成側と検査側の契約の食い違いを、
  誰の生成物も変えずに解消する。**
- **既存 790 件の分類が 1 件も変わらない。** 現行は採番 781 / 非採番 9 / malformed 0 で、
  両義 token を含む名前は 0 件。凍結済みの 7 月の日付範囲名と `worklog-phase1-2.md` は
  全 token が先頭ゼロを持つため entry 形に一致せず、順序を変えても非採番のままである。
- **残余は fail-closed の側に倒れる。** 真の日付範囲名で終端が 10〜12 月のもの
  (`worklog-phase3-0930-1001.md` 等) は entry 範囲と誤読されるが、
  採番側は範囲照合などの検査**対象になる**ので、検査が減る方向ではない。現行 fold はこの形を生成しない。
- 桁数規則の却下 (D445) は今も成立する。`0724` は先頭ゼロにより entry 形に一致しないため、
  本改訂は桁数規則の復活ではない。

**却下した選択肢:**

- **採番名に明示 marker を入れる** — marker 必須の厳格版は既存 781 件の rename を要する。
  旧文法を互換受理する版は二重契約が恒久化し、marker 省略による偽装が残る。
- **両義 token を持つ名前を malformed にする** — 安全だが、**その時点で着地させようとしている
  生成物そのものが malformed になり、修理が自分自身の着地を塞ぐ**。生成側の同時変更が要る。
- **内容の H2 見出しから entry 番号を採る** — 凍結済みの 7 月 archive の H2 は
  `2026-07-05 (2)` のように**日ごとに 1 へ戻るローカル ordinal** であり、全域 entry 番号ではない。
  全域番号として取り込むと実在 entry と衝突する。回避には日付 cutoff の例外が要り、
  D445 が「fail-open の方向に既定値がある」として却下した allowlist に戻る。
  共有テスト fixture も日付範囲名の archive に numeric H2 を持つため、clean baseline を汚染する。
- **生成側に両義でない名前を出させて検査側は据え置く** — 着地はできるが、
  両義名が非採番へ落ちる関門は残る。症状を回避して原因を残す形である。

**閉じていないもの (別裁定へ送る):** 先頭ゼロ付き 2 token の日付範囲形に entry の H2 を入れると、
その archive の entry は全域 universe に入らない。本改訂では閉じない。
これは本改訂が作るものではなく、既存の免除路である。
**閉じるときの依存関係:** universe の正本を内容側へ移す案を採るなら、
上記のローカル ordinal と全域番号を H2 の書式で区別できるようにする改訂が**先に**要る。
この依存を踏まえずに内容側へ移すと、同じ衝突を再発見することになる。
