## {{D:axis1-cond4-cond5-unchanged}}. 軸 1 の条件 4 と条件 5 は改訂しない — 1 走の返却集合を完全とみなせないため

**決定:** D1331 が要求した 3 確認を軸 1 について完了させた結果、**条件 4 と条件 5 の
どちらも改訂しない。** 条件 4 の文言・条件 5 の文言・判定器のいずれも変更しない。
したがって意味的 amendment は発生せず、新 epoch も全枝の再実行も生じない。

**この決定はユーザー裁定ではない。** 再改訂契約 §8 の U11 は未決として登録され、
同契約 §13 が人間の裁定へ返している。本決定が済ませたのは**事実の測定と、その事実から
導かれる維持案の提示**までであり、**維持の追認と U11 の解決はユーザー裁定に残る。**

**本決定は、既に条件 5 で `未完走` になっている leaf へ免除を与えない。**
3 確認が済んだことも条件を改訂しないことも、既知の不成立を処理済みにする決定ではない。

**理由:**

- **判断が依存する事実は 1 つだけである。** 同じ登録 request を同じ日に cursor 先頭から
  2 回走らせたところ、**返却された work ID の集合が異なった。** 差は各 1 件で、
  いずれも名指しできる実在の work である (`W7168152262` と `W7161158986`)。
  2 走が先頭からの首尾一貫した独立走であることは page evidence の束縛
  (identity 一致・頁 0 が cursor 先頭・親応答 digest の鎖・位置の鎖・status・body digest) で
  14 run 全件を検査して確かめた。
- したがって **1 回の走の返却集合を完全とみなしてはならない。** 許容幅・頁境界重複の吸収・
  distinct 化のいずれを採っても、**互いに食い違う 2 走の少なくとも一方を `完走` として受理する。**
  取得完全性のゲートを緩めることになる (絶対規律 2)。
- **条件 4 の重複保存は診断能力そのものである。** 全 occurrence を重複除去せず multiplicity として
  保存しているからこそ、頁境界の重複 32 occurrence の位置と
  `(relevance_score, publication_date, id)` の三つ組を測れた。その測定が
  「cursor 位置の record が内容を変えずにそのまま再送される」という代替説明を否定した —
  **32 件すべてが前頁と異なる三つ組を持っていた** (同一のまま再出現した例は 0 件)。
  ただし 32 件中 23 件は前頁の cursor 鍵が指す record 自身であり、
  **cursor の境界規則そのものは否定できない。**
  D1331 が「distinct 化は同時に条件 4 の頁間重複も落とす」と指摘したとおりであり、
  条件 5 を変えない以上、条件 4 を変える理由も無い。
- **測定は新規取得を要しなかった。** 凍結 bundle の 14 run / 93 頁で足りており、
  無償枠の窓を 1 つも使っていない。D1564 の「取得の副産物として測れる」という前提は成立した。

**この決定が依存していないもの** (いずれも未確定のまま先へ進める):

- **単一機序の確定。** 関連度順 cursor 走査中の再採点は有力な説明だが、欠落時点の索引側スコアも
  全頁共通の snapshot 識別子も証拠に無く、新規取得でも過去時点は復元できない。
- **登録された独立第 2 走の digest 不一致。** catalog の `independent_pass_required` は
  OpenAlex 80 論理 query 中 76 件が真で、偽はちょうど 4 件 (`Q1`/`Q2`/`Q4`/`Q5`) である。
  現在 条件 5 が不成立なのは 3 leaf (`Q1`/`Q4`/`Q5`。判定器は最後の attempt を採るため
  `Q2` は通っている) で、これは上の 4 件の部分集合である。
  **すなわち条件 5 で落ちている leaf は、いずれも第 2 走を要求されていない。**
  登録上の第 2 走は 1 本も走っていない。
- **申告総数に幻の件数が無いこと。** 走が 1 本しかない 2 leaf では排除できていない。
- **`申告総数 − distinct` を非返却件数と読む解釈。** この等式は失敗した走の申告母集合が
  固定されていることを要し、頁内重複 0・非隣接重複 0 ではそこまで言えない。主張しない。

**却下した選択肢:**

- **条件 5 に許容幅を持たせる** — D1564 が既に却下しており、実測もこれを支持する。
  食い違う 2 走の一方を `完走` として受理し、実在する取得のずれを隠す。
- **頁境界の重複を除いたうえで厳密一致を保つ** — D1331 が却下した distinct 化と実質同じで、
  同じ理由で 2 走のずれを隠す。条件 4 の重複保存も失われ、機序の診断ができなくなる。
- **別の索引について重複排除を採った D1454 を軸 1 へ持ち込む** — D1564 が射程超過として
  明示的に禁じている。本決定でも採らない。
- **条件 4 の occurrence 保存をやめる** — 代替説明を否定できたのはこの保存のおかげである。

**ユーザー裁定へ返す項目:**

- **本決定 (条件 4 と条件 5 を改訂しない) の追認**、および U11 の解決。
- **取得 program の択一** — 現 epoch のまま失敗 leaf を再取得する / 登録 request へ安定した
  並び順の鍵を足す / 非 shard の 4 leaf も固定 shard 化する / 現状のまま `未完走` で止める。
  後ろ 2 つと 2 番目は新 epoch・新 ID・全枝の再実行を伴う。既存の shard 方針は
  `adaptive_split: forbidden` / `observed_count_is_input: false` であり、観測件数に応じた
  後付けの境界を禁じている。年 grid では 1 頁に収まらない実測がある (951 件 = 5 頁)。
  **加えて、取得を全部終えても現実装では軸 1 は `完走` にならない** —
  `axis_complete` は `retrieval_complete` に加えて 5 つの component と
  `unimplemented_schema_layers == 0` を要求し、production 経路にその設定箇所が無い。
