## 新規

### {{F:asserted-artifact-before-creating-it}}. 成果物を作る前に「作った」と着地対象の本文へ書いた [捏造/幻覚] [手順漏れ]

- 事象: 事前登録へ足す追補の本文に「読んだ file と出力の逐語は
  `output/insights/2026-09-14_t2547-b4-descriptive-erratum/` に保存した」と書いたが、
  その時点でディレクトリは存在しなかった。同じ wave の段 4 裁定表にも「親資料を訂正した」と
  書いたが、指している job dir の資料には過大な断言が 4 件残ったままだった。
  **どちらも「これから行う処置」を完了形で書いており、段 6 の敵対レビュー 2 本が
  独立に同じ must-fix として指摘するまで残った。**着地していれば、事前登録の読者が
  解決しない参照を追うことになっていた。
- 根本原因: 処置の計画と実施を同じ文で書いた。着地対象の本文 (事前登録・裁定表) に
  「保存した」「訂正した」と書いた時点では、その実体を作る操作をまだ 1 度も走らせていない。
  **`DW-S07` は「受入・検査は実測前に欄を作らず未実施はそう書く。値なし前方参照と
  placeholder を禁じる」と定めているが、この規律を検査欄の外 (散文の事実主張) へ
  適用しなかった。**
- 恒久対応: `DW-S06-A` が要求する異なるレンズの敵対レビュー 2 本。本件は 2 本とも独立に
  同じ must-fix を出して着地前に止めた。加えて `DW-S07` の「未実施はそう書く」を
  検査欄だけでなく着地対象の散文の事実主張へも適用する。
- 再発検知: `tools/check_docs.py` の `PATH_REF` は living docs の実在しないパス参照を検出するが、
  **正規表現が拡張子つきの file path しか拾わない** (`[\w.\-/]+\.[A-Za-z0-9]+`) ため、
  本件のような末尾 `/` のディレクトリ参照には掛からない。機械化の候補はこの拡張だが、
  `tools/` 配下の変更は Codex author を要するため本 wave では実施していない。
