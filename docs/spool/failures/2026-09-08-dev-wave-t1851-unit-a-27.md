## 新規

### {{F:main-tip-committed-nested-worktrees-as-gitlinks}}. local main の先端が入れ子 worktree 110 個を gitlink として commit し、取り込んだ側が黙って汚染される [手順漏れ] [ドリフト]

- 事象: local main の先端 `c12e25078` が `.codex/worktrees/` 配下の Codex 子 worktree
  **110 個を mode 160000 の gitlink として commit している。** `.gitmodules` に対応する
  mapping は 0 件。この commit を checkout した木では submodule 操作が必ず失敗し、
  `dev_wave_submodule_init.py` が `runtime-io-failure: {'label': 'submodule',
  'kind': 'update-no-fetch'}` で落ちる (同じ引数で 2 回とも)。素の `git submodule status` は
  `fatal: no submodule mapping found in .gitmodules for path '.codex/worktrees/<名前>'`。
- **取り込みは警告も競合も出さずに成功する。** 本 wave が試験 merge を 1 回だけ回して実測した
  ところ、rc=0 で「Automatic merge went well」と表示され、**110 件の gitlink が staged された**。
  直後に abort して汚染 0 件へ戻した。**静かに伝播する型である。**
- 混入は先端 1 commit だけで、その 1 つ前 `6172ea26b` は gitlink 0 件で健全。
  本 wave の branch も 0 件だった。健全側では submodule 初期化が成功することを実測し、
  診断の裏を取っている。
- 根本原因: primary checkout で `.codex/worktrees/` が未追跡のまま `git add -A` 相当が走った。
  同 directory は Codex 子の worktree 置き場であり、**worktree は `.git` file を持つため
  git からは埋め込み repository に見え、`add -A` が gitlink として拾う。**
- 影響: **main を取り込むすべての wave に波及する。** 受入待ち手は投入前に main 先端を
  merge するため、受入全走を回すと汚染が branch へ入る。本 wave は受入全走を実行せず、
  健全な `6172ea26b` を固定 SHA で取り込む形で迂回した。**汚染を飲んで gate を満たすことは
  規律 6 と停止条件の迂回にあたるため行っていない。**
- 恒久対応: **`.codex/worktrees/` と `.claude/worktrees/` を追跡対象から構造的に外す**
  (`.gitignore` への登録)。加えて、取り込み前に gitlink 件数を数える検査を land / 受入の
  前段へ置く — `git ls-tree -r <main> -- .codex/worktrees/ | grep -c '^160000'` が 0 でなければ
  取り込まない。**main の是正そのものは共有状態への操作なのでユーザー裁定へ返す。**
- 再発検知: 新規 worktree での `dev_wave_submodule_init.py` の
  `runtime-io-failure`。**ただしこれは取り込んだ後にしか出ないので、取り込み前の
  gitlink 件数検査が本命である。**
