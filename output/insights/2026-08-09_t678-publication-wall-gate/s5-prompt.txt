## 実装上の要点 (親裁定より)
- `_stage_receipt_write` は fsync 済み temp の `Path` を返し、削除しない。
- `_atomic_create_json_reserved` は「呼出側が用意した fsync 済み temp を公開する」形へ変える。
  **temp の所有権は helper へ渡した時点で helper へ移る** (成功時も例外時も helper が後始末する)。
  helper へ渡す前の例外だけ caller が `finally` で unlink する。この所有契約を docstring に固定してください。
- launcher 局所の `_monotonic_ns()` 間接層を新設し、module 内の `time.monotonic_ns()` 呼出しを
  これ経由へ揃える。テストは共有 `time` module ではなくこの seam を差し替える。
- `_run_supervised` の accepted 経路は
  output 公開 → hash 照合 → audit(published) → stage(exact bytes の write+fsync) →
  **`_latch_final_job_limit`** → まだ accepted なら staged temp を公開して rc=0。
- flip したら: staged temp 破棄 → published output unlink → **output の親を `_fsync_parent`** →
  `output_published_by_run=False` → `_receipt` 再構築 → audit(False) → 再 staging → 公開 → rc=1。
- flip 判定は `receipt["outcome"]` ではなく `attempts[-1]["accepted"]` を見る
  (`_receipt` は attempts を深いコピーしないため)。
- 再評価は 1 回だけ。`outcome != "accepted"` の candidate は再評価しない。
- `_publish_launcher_error_receipt` の output unlink の後にも `_fsync_parent` を入れ、
  その後で flag を false にする。
- `actuals.wall_clock_s` が receipt object 構築時点の値であり late gate の観測時刻とは別である、
  という事実を該当 docstring に 1〜2 行で書いてください (docs ファイルではなく production の docstring)。
