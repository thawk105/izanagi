## 直すもの (親が採用した 2 件だけ)

### F1 (must-fix、R2 の MF-1) — N3 の検出力が意味的に無効
`test_accepted_publication_reuses_the_staged_receipt_temp` は、変更前 production では
`_stage_receipt_write` が `None` を返すため `temporary.stat()` の `AttributeError` で落ちます。
これは「二度目の temp write が復活した」ことの検出ではありません。変異 MT2 でも同じ
観測器依存の例外になり、kill を過大評価します。

**直し方 (R2 の提案を採用):** helper の signature に依存しない、production-visible な観測へ変える。

- `LAUNCHER._write_json_temp` を wrapper 化し、**receipt path に対する呼出しだけ**を記録する
  (manifest 等への呼出しは除外する)。
- 正常 accepted 経路で、receipt path に対する temp 作成が **ちょうど 1 回**であること。
- 公開後の receipt final path の inode が、**その 1 回目の temp の inode と同一**であること。
- 上記により、変更前 production (stage の temp を捨てて公開時に別 temp を書く) では
  「2 回」および「inode 不一致」で赤になる。`AttributeError` に依存しない。

### F2 (nit、R1 の nit 1) — 例外時の temp 所有契約が未検証
`test_receipt_publication_failure_removes_output_and_writes_error_receipt` は
`_atomic_create_json_reserved` 自体を差し替えて即座に送出するため、
「helper は例外時も temp を消す」という本 wave が新設した所有契約を検証していません。

**直し方 (R1 の提案を採用):** helper 自体を置換せず、その内部の `os.link` を
**receipt path に限って**失敗させる形にする。併せて `.receipt.json.tmp.*` の残骸が無いことを
assert する。既存の期待値 (`launcher_error` / rc=2 / output 不在) は**変更しない**。
