## provisional 裁定 (攻撃対象)

- **(P1) 順番票の置き場と形:** `<common git-dir>/dev-wave-land-turn/` (flock と同じ common dir)。連番は同 dir の小さい registry file を短い flock で守って払い出す。1 ticket = 1 regular file `<seq:08d>-<holder12>.json` で、待ち手 process が `LOCK_EX` を保持し続ける (FD lock = 生存)。payload は seq / acceptance_wave / tested_main / tested_tip / landing_tip / receipt sha256 / pid / phase。同じ request (同 wave・同 tested_tip・同 receipt digest) の再試行は既存 ticket を引き継いで seq を保つ。
- **(P2) 先頭選出と引き継ぎ:** 先頭 = 生存 (FD lock 保持) ticket の最小 seq。死亡 (lock が取れる) ticket は `phase` を読み、`mutating` なら recovery を先に (既存 fold state 経路)、それ以外は次候補が回収。先頭は initial→監査→fold gate→ff/fold を通して先頭のまま、新規到着は追い越せない。先頭は各 mutation 直前 (ff-only 前、fold apply 前) に自分が先頭かつ生存 owner であることを再確認する。
- **(P3) 待ち予算:** 順番待ちは新 module 定数 `_LAND_TURN_WAIT_SECONDS = 3600.0` (1 invocation の絶対期限、land は detached で外側 timeout 無し、成功 land の窓は実測 186 秒なので 13 本で約 43 分)。flock 取得の 180 秒累積予算 (D432/D1996) は先頭が「順番票を知らない holder」と競合する場面の予算として残す。証拠保持 = 監査後・fold gate 後の再取得が lock-busy でも receipt を捨てず、順番期限まで driver 内で待って再開し、main/tip (fingerprint) が変わったときだけ失効 (既存 `RC_PROVENANCE` / `_FoldGateFailure` の retryable 経路)。期限到達時だけ `lock-busy` (rc=11) を返す。
- **(P4) 登録前提:** 順番票の登録は `_verify_repository` 後、受入 receipt の lock 非依存部分 (schema / holder / tested_main・tip / verdict 緑 / fingerprint) を通した後。lock 内の `_verify_acceptance_receipt` 完全検証は不変。
- **(P5) 非接触の範囲:** `_worktree_snapshot` は wave 自身と `protected_paths` に重なる child だけを open して `_validate_admin_binding` する。無関係 child は名前も identity も読まない (`observed_worktree_identities` から外れ、無関係 child の同名差し替え検出は捨てる = D109 の方向)。`_open_container` の後の `.git` 消失 race は対象外 child を開かないことで消す。handoff の名前集合比較は維持。
- **(P6) cleanup の対象限定:** `git worktree prune --expire=now` (全体) をやめ、`_administrative_gitdirs_for_wave` で解決した自 wave の admin gitdir だけを撤去し、`_verify_record_state(absent=True)` で確認する。他 wave の stale 残骸は触らない (`/cleanup-branches` へ引き渡す)。
- **(P7) 旧構造の負例:** 旧挙動を選べる knob は作らない。負例は (i) 変更前 tree で同じ決定的 schedule test を走らせた記録 (probe、insight に残す) と (ii) 変異 M1「順番票の先頭 gate を外す」が正例 test で KILLED されることで恒久化する。
- **(P8) test の形:** 既存 fake clock + 実 flock fixture (`_exercise_cumulative_waits`、3414 付近) を拡張し、複数 request を 1 process 内で決定的に交互実行する scheduler (patched `_land_lock_sleep` / `_land_turn_sleep` で切替) で: 新構造で 8 本が有限 step に全完了・順位維持・先頭赤 (provenance rc≠0) / 死亡 (FD lock 解放) で次候補・fold 途中死亡で recovery 優先かつ二重採番なし・cleanup 交錯 (無関係 child の `.git` 消失は通す、自 wave 差替えは拒否)。
- **DW-G05:** 放置時は研究記録の着地が manager の手動 GO に依存し続け、無人ループ (ユーザーの柱) で台帳 3 本の追記が止まる。受理集合は「拒否は狭まらず、進行だけが変わる」方向で、certified 選択・proof chain・campaign 値は不変。
