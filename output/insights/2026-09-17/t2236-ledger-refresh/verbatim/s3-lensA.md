## plan への must-fix と nit

**must-fix**

1. **今回の land 競合手順を明文化する。** main base に古い JUnit を当てるだけでは他 wave の追加を失う。競合時はまず新 main と入力集合の差を確認し、現在の固定入力・出所契約で処理できなければ、その条件では採用を停止する。入力を取り直す場合も、F902 の「両親の旧値をすべて保存」と refresh の「既存値を置換」は別契約であることを明記する。JSON の手修正や main 値の無条件持越しを逃げ道にしない。

3. **親 brief の被覆分子と原因断定を修正する。** plan 内だけの訂正では、親の完了基準・insight へ誤記が残る。

**nit**

- 兄弟 file を非凍結として更新する正例を追加すると、`.py::` 境界の維持を固定できる。
- `plan:218` の failed testcase の重複拒否は「canonical nodeid を復元できたもの」に限定する。join できない failed/error は `nodeid=None` となり重複検査を通らない（`生成器:214–220,247`）。
