## 総括

- 必読資料、6条件の evidence 全96行、6組の会計・trace・receipt・resultを読み、実走せず照合した。
- 主要時刻36値（6条件×E/J/t0/δ/E−J/E−t0）を再計算。掲載値との不一致は表示丸めの範囲を超えて **0件**。
- heartbeatの件数・列挙には **3箇所の不整合**。結論・手順・表現を含め **must-fix 6件**（A-1〜A-6）。
- 事前登録の遵守判定：**事後変更**。S0/S30は分類前の必須適格性条件を満たさない。
- 規律3で最も保守的な結論：**打切りを含むため完全ベクトルの同値類割当ては保留**。部分比較を許しても `(不明,70,不明,70)` は **Bのみ不適合、A/C/Dは未分離**。

以下、`README` は指定insight草稿、`s4` / `s5` は指定job dirの裁定・実測文書、`evidence` は指定ディレクトリを指す。

### A-1 — 打切り走を窓分類へ戻す「親の読み」は事後変更

**判定：must-fix**

**根拠：** s4 §4.2「数値を分類する前に全部満たす」、§4.3、§5。README L103–120、L14–16、L36–38、L157–164。S0/S30の最終record。

`child-exit` が t0+75±1にあることは分類前の必須条件であり、「E後のheartbeatで代替可」という例外はない。§4.3の生存確認は即時killとの非両立を述べるだけで、§4.2の条件を解除しない。§5も記録不足を機序表へ割り当てないとしている。

したがって、数値としての `E−J` と窓の位置は報告できるが、それを**事前登録に適合した完全ベクトル**としてA類へ割り当てることはできない。「除外条項の目的」を結果後に補って適格とするREADME L117–119は事後変更である。

A類との一致を残すなら、適格性条件を緩めた**探索的な参考比較**と明示し、正式結論・D2048追補・T-2676への確定入力から分離する必要がある。

### A-2 — 後退案の「B/C類は不適合」は誤り

**判定：must-fix**

**根拠：** README L119–124、s4 §4.4。

完全ベクトルを仮に採用した場合、README §4.2の要素別比較は正しい。

| 類 | S0予測／観測0 | G0予測／観測70 | S30予測／観測25 | G30予測／観測70 |
|---|---:|---:|---:|---:|
| A | 0 ○ | 70 ○ | 25 ○ | 70 ○ |
| B | 0 ○ | 0 × | 25 ○ | 25 × |
| C | 70 × | 70 ○ | 70 × | 70 ○ |
| D | 0 ○ | 70 ○ | 70 × | 70 ○ |

しかしS0/S30を除外すると、Cを排除した根拠も失われる。`(不明,70,不明,70)` のG0/G30は **A/C/Dすべての予測と一致**する。

第三の、最も保守的な読みは、§5に従って実験全体の類への割当てを保留し、適格な個別走の結果だけを残すことである。部分ベクトルの比較を付記する場合も「Bのみ不適合、A/C/D未分離」とする。

### A-3 — S0の終端記録不足後も追加投入している

**判定：must-fix**

**根拠：** s4 §3.3項目4〜6、§2異常時手順。s5 L39–56、L67–79。

事前登録は「終端記録不足」で追加投入停止を要求する。S0はt0+125まで回収しても `child-exit` がなく、その後G0・S30・G30を投入している。S30の終端不足後にもG30が続いている。

これは解釈上の問題とは別の**実験進行規則違反**である。READMEに逸脱と発生時点を記録し、後続走を計画どおりに完遂した検証として扱わないこと。正常receiptやhold不在は、この停止条件の代替にならない。

### A-4 — heartbeat欠落から「消えた」「消される」を断定できない

**判定：must-fix**

**根拠：** README L37、L128–140、L163、s5 L49–50・L76、s4 §1 P3・§4.3。S0 child seq11、S30 child seq16。

確認できるのは次だけである。

| 条件 | 最終生存記録 | 次の予定record | 記録状況 |
|---|---:|---:|---|
| S0 | t0+40.001008 | t0+45 | なし |
| S30 | t0+65.001014 | t0+70 | なし |

`E+35.4〜40.4` / `E+35.3〜40.3` は、表示Eを基準にした「最後の記録から次の予定記録まで」の区間として計算は合う。しかし死亡時刻、停止時刻、書込み失敗の発生時刻をこの区間へ拘束する証拠ではない。スケジューリング遅延も区別できない。

見出し・結論・引継ぎを「その時点まで生存を確認し、その後の予定記録なし」に統一する必要がある。後段の留保だけでは、前段の死亡断定を打ち消せない。

### A-5 — A類の参考一致から機序と対策粒度を断定している

**判定：must-fix**

**根拠：** README L30–31、L146、L163–164、s4 §1 P1・§4.4・§5。

「生きたprocessが1本でもあればRUN」「判定は現在の所属」「session単位の回収がNQSVと同じ粒度」「追加介入は不要」は本データから強すぎる。

正式結論はA-1/A-2の保留とし、対策は検証候補として記述する必要がある。

### A-6 — heartbeatの件数と列挙を修正する

**判定：must-fix**

**根拠：** README L116、s5 L52・L74、`probe-setsid-now.jsonl` 全14行、`probe-setsid-30.jsonl` 全19行。

不整合は以下の3箇所。

1. **S0「8回（t0+10…40）」**：10〜40は7回。表示Eより後のrecordは **5〜40の8回**。秒丸めの曖昧さを避けて明確に後のものだけを数えるなら10〜40の7回。
2. **S30「t0+30未満のheartbeat 6回」**：実際は **5・10・15・20・25の5回**。`child-start` はheartbeatではない。
3. **S30「E後7回（35…65）」**：35〜65の7回は列挙として正しいが、表示Eとの単純比較なら **30〜65の8回**。30秒recordを除くなら「秒丸めを考慮して明確にE後と判断できる7回」と区別する。

件数を訂正しても、E後の生存が確認できること、およびA-1の適格性不成立は変わらない。

### A-7 — 時刻36値の独立再計算

**判定：nit（主要掲載値は照合済み。t0の定義表記は訂正推奨）**
