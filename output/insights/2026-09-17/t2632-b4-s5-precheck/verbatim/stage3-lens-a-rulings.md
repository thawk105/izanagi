## 所見

### A1. この2欄の順序制約は残るが、「D1483 以後改訂なし」は広すぎる

- 判定候補: real
- 根拠: `docs/decisions.md` D1483 は床値の「12 行裁定、測定、成果物の採用裁定」の後とし、PerfConfig 等への解禁波及を否定する。一方、D1812 (a) は primary outcome 欄の既存記入を明示的に維持する。D1871 は開始時刻だけの例外。D1641、D1812 (c)、D1936 項7、D1986、D2088／D2089 に、この2欄を先行記入する許可は見当たらない。
- 親 brief への影響: **P1 の結論は維持**。「D1483 の順序には後続の個別裁定があるが、今回の PerfConfig・env_tag 欄について解除する裁定は確認できない。今日は両欄とも記入しない」と限定する。

### A2. §11.1 の導出・校正を、§5 記入の先行許可と読む反論は成立しない

- 判定候補: refuted
- 根拠: `prereg-s11.1.md` 手順4・5は env_tag の導出と校正成果物の作成。手順8は「確認結果だけでは §5 を変更しない」、手順9は採用裁定後の floor 行記入を別に置く。D1812 (c) の追記も「§5 の記入」を許可しないと明記する。
- 親 brief への影響: **P1 を維持**。「値の導出・校正・証拠準備は先行できるが、それだけでは値セルを記入できない」。なお手順一覧は「案」であり、各部分の効力は後続の採用裁定と組み合わせて示す。

### A3. 床値用 reps の承認は、本走への包括委任ではない

- 判定候補: refuted
- 根拠: D1641 決定3は床値の凍結項目。D2088 の承認根拠は **D1641 の委任と T-2288 の名指し依頼の両方**であり、対象は `floor-pair-spec/v3`。同決定と T-2288 README は、reps が「calibrator の出力を採り」の外にある AI 選択だと明記する。D1812 (c) は既裁定の反映で、用途を拡張しない。
- 親 brief への影響: **P2・P5 の別途裁定は妥当**。「B-4 用 reps=5 は候補であり、床値用承認の自動転用はできない。承認対象には値だけでなく、その出所を §5.1 の要件にどう位置付けるかを含める」。§11.1 の AI 候補禁止は無承認での凍結を禁じるもので、明示された委任内の承認まで否定しない。

### A4. extime は復元可能だが、「calibrator が決めた出力値」とは呼べない

- 判定候補: real
- 根拠: D2088、`parent-resolver-and-calibration-probe.txt`、T-2288 README「A-3」。`extime=3` は取得 argv と現在の CLI 既定からの復元。D2088 は「取得当時の source bytes まで検証したものではない」と限定する。`ycsb_max_ope=10` も取得構成からの復元である。
- 親 brief への影響: **P2・P5 を補足**。「records／threads／workload 3 key は較正出力、extime／max_ope は取得構成からの復元、reps は設計上の選択」と分ける。B-4 採用時には、復元した構成を採用する読みも明記する。**reps だけ承認すれば §5.1 の全要件が自動的に閉じるとはしない**。

### A5. 床値と同じ環境であるべきことは、本走 site の指名そのものではない

- 判定候補: refuted
- 根拠: D1641 決定3の site は床値用。`prereg-s5-s5.1.md` は floor を「対象動作点で再実測」、env_tag を「選択した driver と実行 site が確定」してから記入とする。D924 は対象と器具の pin・環境契約の一致を要求するが、B-4 本走 site を指名する裁定ではない。
- 親 brief への影響: **P3(a) を維持・精密化**。「既存の床値計画・較正を使うなら Pegasus が整合する候補である。しかし一致要件から本走 site の指名済みまでは導けない」。P5 の裁定パッケージには、この用途の確定を落とさない。

### A6. 確認者の不足は「identity 未定」ではなく「担当範囲の未確定」

- 判定候補: real
- 根拠: D1266 は §5.1(i) の記入者・レビュー者を指名する。D1641 決定1は床値担当3者を指名する。D1483 は、それらの役割が床値手続きに効き、他欄を解禁しないと説明する。ただし「解禁しない」こと自体は、同じ identity の利用を禁じる規定ではない。
- 親 brief への影響: **P3(c)・P5 を修正**。「既存 identity は thawk105。未確定なのは、今回2欄の確認・記入まで AI 委任を及ぼすか」である。新規人物の再指名や床値担当の再裁定ではなく、必要なら **担当範囲の追加**として返す。D1641 だけで env_tag 欄の確認者を確定済みとも扱わない。

### A7. 世代の選択と artifact の同定を分ける必要がある

- 判定候補: real
- 根拠: D1484 は g2 発効を鎖の末尾に置く。D1537 は健全な世代の発効まで当該環境系列の within-run を一致なしに保つ。親 probe では resolver の active は g1、g2 は登録済み未発効。また `contract_sha256=e576e9cd…` と `env_contract.py` の file SHA `292bbed3…`、activation file SHA `6a44b5b1…` は別物である。
- 親 brief への影響: **P3(b) を修正**。「今の導出証拠は g1。発効版には、その時点で実際に有効な契約と整合する証拠を併記する。g2 登録を activation 済みと読まない」。加えて、**どの実在 path の bytes をどの hash が束縛するか**を提示する。code path に semantic contract hash を添えて file hash と見せない。

  世代・契約 bytes・activation が変われば記入前／発効前に再導出・再確認する、という運用案は妥当。ただし model snapshot 欄の陳腐化検査が env_tag 欄にも実装済みとは書かない。D1812 (a) の source-file 解釈も、明示的に primary outcome 欄限定なので自動転用できない。

### A8. 複合セルの書式自体を新裁定待ちにする必要はない

- 親 brief への影響: **P2・P3(d) の「形が未裁定」を独立した停止理由から外す**。「確定した値を `key=value; ` で列挙する形式案は AI が作れる。説明・解除条件はセル外に置き、必要な値が揃うまで未記入を保つ」。ただし書式の自由は、較正 artifact に欠ける reps や契約証拠の不足を補わない。

## 裁定パッケージ候補

- **B-4 用 PerfConfig の採用範囲**：3較正の値、取得構成から復元した extime=3／max_ope=10、AI 候補 reps=5を区別して提示する。特に後二者を §5.1 の要件にどう位置付けて承認するかを返す。単に「reps=5でよいか」だけに縮めない。
- **B-4 本走の site と担当範囲**：Pegasus 計算ノードを本走用にも固定すること、および thawk105 名義の AI 委任を今回2欄の確認・記入へ及ぼすことを候補とする。実走認可は含めない。
- **環境契約の artifact 解釈**：既存 code・activation の path／file hash と契約の semantic hashを区別した具体案を先に作る。その束を §5.1 の「環境契約の artifact」とする読みが未確定なら、その限定した解釈を返す。新 producer は前提にしない。
- **既裁定 D1641／D1812(c)／D2088〜D2090 で閉じる**：床値の担当者、床値用 PerfConfig 承認、床値用3 cell・較正選択。これらを再裁定へ返さない。
- **既裁定 D1483／D1484 で閉じる**：今回2欄の記入順序と g2 発効順序。今回の precheck を理由に前倒しを求めない。
- **既裁定 D1854 と §0・§5.1 で閉じる**：複数較正を1セルに置けること、確定値の複合表記、部分記入禁止。単なる区切り文字や pin 転記作業をユーザーへ返さない。

## 総括

- **今日は2欄とも記入できない。** 第一の理由は、この2欄について D1483 の順序を解除する後続裁定がないことである。
- 較正3件は records／threads 等の供給源になるが、完全な B-4 用 PerfConfig の承認済み artifact と同一視できない。
- 親の実測と読んだ裁定資料に直接の矛盾はない。ただし本相談は実測の再実行ではなく静的検査である。
- 修正点は「以後改訂なし」の限定、担当 identity と委任範囲の区別、extime／max_ope の採用解釈、契約 hash と file hash の区別。
- 複合セルの書式は新裁定待ちから外し、B-4 用の採用範囲・site・担当範囲・契約証拠の解釈に裁定項目を絞る。
