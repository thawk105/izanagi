## 総括

caption 訂正と旧 fig5 の bytes 保持は両立できる。親の「両立しない」は、legacy caption を一律変更する場合に限って正しい。  
目盛の訂正は依頼の本題に含まれる。`fixed 10 us / fixed 5 us` を残す段 2 案では、図そのものを改訂稿の命題へ合わせたとは言えない。  
新 prefix は既存 pin で生成経路に入れるが、caption だけを変えても描画内容は旧図と同じになる。  
改訂稿の `tracked_inputs` 追加は成立する。この稿は明示的な凍結物なので、変更時に closure が赤になる結合も妥当である。  
以下は静的検査の結論であり、生成・pytest・編集は実施していない。

## 所見

**1. caption の両立不能という断定は広すぎる。**

- **主張:** 新 prefix に限定した固定文言の訂正なら、旧 caption と検証を維持できる。
- **根拠:** `tools/plotting/plot_a2_certification.py:609` は出力 PNG から prefix を復元し、`:859` がその prefix で `_caption` を再評価する。`:839` は生成器 hash を現行 source に照合しないと明記する。
- **影響:** legacy 本文の条件記述だけを一律変更した場合と、新 prefix 限定の場合は、次のように異なる。「緑」は変更による失敗がないという静的判定である。

| 検証対象 | legacy 一律訂正 | 新 prefix 限定訂正 |
|---|---|---|
| `validate_repo_closure` に旧 fig5 provenance を渡す | **赤**。保存 caption と再生成文字列が不一致 | **緑を維持** |
| `_assert_named_landed_bundle` に旧 fig5 を渡す | **赤**。`:1243` の closure で失敗 | **緑を維持**。旧 caption の README 収録も保持する |
| `test_landed_fig5_repo_closure_and_caption_when_present` | **赤**。`:1521` で失敗 | **緑を維持** |
| `test_caption_uses_figure_number_from_output_prefix` | **緑を維持**。`:1407` は `Figure 6.` の先頭だけを検査 | **緑を維持** |

`_assert_named_landed_bundle` 自体はテストとして収集されない。current-full の bundle に適用するなら、legacy 一律訂正でも先行 return により影響しない。

抜け道も区別できる。

- **既存 profile 分岐:** `:622` は current-full 専用。新旧とも legacy 入力のままでは区別できない。
- **prefix 分岐:** 新旧を区別できる。段 2 案はこの正当な経路を使う。
- **provenance field 追加:** 新図だけに固定の訂正版識別情報を記録し、欠落時は旧文言とする実装も可能。ただし現行コードでは未知 field を追加するだけでは何も変わらない。`build_provenance:797` は戻り値ではなく入力 `data` で caption を作るため、生成時と closure 時の双方へ情報を渡す必要がある。
- **skip:** `test_landed_fig5…:1517` は全成果物不在かつ README に名称不在の場合だけ。README `:20` に名称がある現状では成立しない。外部入力テストの skip は別経路である。

- **判定:** 親の一般的な両立不能説は **refuted**。一律変更による旧 fig5 検証失敗は **real**。

**2. 目盛を残す案は本題を未達にする。**

- **主張:** 新図の目盛も実効条件へ訂正する必要がある。
- **根拠:** 生成器 `:725`–`:726` は上下両段へ `"no backoff"` と `"fixed … us"` を設定する。改訂稿 `docs/paper-story/results/2026-09-07-a2-certification-reject.md:83`–`:88` は、実効差を内蔵 backoff の無効／有効と断定する。段 2 `s2-plan.md:54` は誤った表示を保持している。
- **影響:** 新図では、例えば `no backoff` / `built-in adaptive` と表示し、caption で実効条件を展開する。これは条件記述の訂正そのものであり、scope 外の追加実装ではない。

訂正による影響は限定できる。

| 対象 | 目盛だけを訂正した影響 |
|---|---|
| `cells` / `genome` | 変更不要 |
| `_artist_series` | `:681`–`:691` は内部 identity・値を組み立て、目盛文字列を含まないため変更不要 |
| `validate_repo_closure` | 描画し直さず、目盛も検査しない。旧出力 bytes を保持すれば旧 closure は壊れない |
| 既存テスト | 目盛の文字列一致 assertion はない。`:1366` の layout 検査は文字幅変更で失敗し得るため、成功は実走で確認する |

新図だけへ適用するには作図経路にも対象情報が必要である。現行 `make_figure(data)`（`:694`）は prefix を受け取らず、`main:881` の作図が publish より先に走る。caption 分岐だけの変更では目盛へ届かない。新 prefix の判定を作図にも渡す最小変更が必要となる。

- **判定:** 目盛訂正の必要性は **real**。「訂正すると cell identity／artist 整合が必ず壊れる」は **refuted**。

**3. 新 prefix は通るが、現プランの画像は視覚的な複製になる。**

- **主張:** pin 追加は不要だが、番号変更と caption 訂正だけでは絵は変わらない。
- **根拠:** 生成器 `:121` は certification path で pin を引き、`:157` は legacy schema を選ぶ。`:603` の番号抽出は caption 用である。`make_figure:694` は prefix を参照せず、`:802` の `fig._a2_caption` 代入も表示用 `Text` を追加していない。
- **影響:** 同じ値・同じ目盛・同じ図中文字になる。PDF の生成時情報などがあるため、ファイル bytes まで同一とは断定しない。訂正 caption を付した bundle には意味があるが、誤記を残した画像を別番号で増やすだけでは今回の完了条件に不足する。目盛を訂正すれば、同じ測定を正しく説明する訂正版として意味がある。
- **判定:** pin 追加不要は **real**。caption 訂正だけで画像も訂正されるという期待は **refuted**。外部入力の完全性を含む生成成功は未実測。

**4. 改訂稿の hash 結合は成立し、この文書には適切である。**

- **主張:** `.md` の一 byte 変更でも赤になるが、それ自体は今回の欠陥ではない。
- **根拠:** 生成器 `:840`–`:844` は kind に関係なく全 tracked input を現物照合する。一方、改訂稿 `:7` は「凍結物」「書いた後は更新しない」と明記する。
- **影響:** `authority_scope` を条件説明に限定しても hash 検査は免除されない。将来の訂正は別稿として追記し、生成時の出所は保持する。この運用なら段 2 の `kind: "caption_source"` 追加は妥当である。

可変の文書を単なる参照先として記録する別要件なら、新図限定の top-level `caption_source` に path・生成時 hash・説明範囲を記録する方法がある。ただし現行 closure はそれを照合しない。全図へ無条件追加すると、テスト `:1452` の top-level key 完全集合 assertion が赤になる。今回、その変更は不要である。

- **判定:** 変更時の失敗は **real**。「したがって tracked_inputs へ入れるべきでない」は、この凍結稿については **refuted**。

**5. プランの主要な行番号は一致するが、二箇所にずれがある。**

- **主張:** 実装判断の主要参照先は実在する。
- **根拠:** `_caption:618`、legacy 本文 `:653`、目盛 `:726`、`build_provenance:775`、caption 照合 `:859`、テスト `:1238`・`:1400`・`:1511` は現物と一致する。

- **判定:** 二箇所の参照ずれは **real**。主要経路が架空という懸念は **refuted**。

## 親 brief の誤り

- `s1-brief.md:31`–`:35` の「両立しない」は一律変更に限る。新 prefix 限定訂正を排除する根拠にはならない。
- `s1-brief.md:57` の P4 を「caption 以外の表示訂正は禁止」と解釈すると、冒頭の完了条件と衝突する。**新図の目盛訂正は必要**である。旧 bytes・数値・status・内部 identity の保持とは両立する。
- 「図中 label はすべて cell_id」という説明は現物に反する。ただし、その文言自体は今回の射影 brief にはなく、`s2-plan.md:119` が親の説明として引用している。
- その他の不変条件に、実装を不可能にするものは見つからない。改訂稿の hash 記録も凍結運用と整合する。

## より安い解

**誤った図を論文で使わないという目的だけなら、図を生成しない解はある。** 旧 fig5 を歴史資料として保持し、論文の掲載・参照対象から外し、旧 attempt は改訂稿の条件説明と表で扱う。正しい静的 backoff の attempt は既存 fig6 と区別して扱う。README `:437`–`:443` は既に旧図の用途制限を記している。

ただし、これは誤記画像そのものを訂正せず、今回明示された「訂正した図 1 枚と caption、provenance」を満たさない。**現在の成果物要求を維持するなら、目盛と caption を訂正した新図を作る必要がある。**
