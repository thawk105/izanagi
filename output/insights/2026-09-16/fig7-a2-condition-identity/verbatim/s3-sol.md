## 所見

**2. in-place 訂正を支持する最強の反論と、その限界**

- **主張:** 「作り直す」「差し替える」は通常、既存成果物の置換を意味する。値と判定を保持して説明だけ直すなら、絶対規律7の「過去判定の変更」には当たらないとも論じられる。README の AI 起草文だけで直接依頼を退けるのは不適切である。
- **根拠:** この反論は規律7単独に対しては有効。しかし保存根拠は README だけではない。D1645（`docs/decisions.md:50495`）は「当時の測定と判定は事実として残し、訂正は追記でのみ行う」。D1753（`:53229`）は凍結図 caption の byte 保持を確認し、`:53237` で新図の `fig5` 系 filename を却下している。README（`docs/paper-story/figures/README.md:443`）も三成果物を明示して保持する。

- **判定:** in-place を現授権で実施できるという主張は **refuted**。

**3. 新図の価値と用途制限**

- **主張:** fig6 の存在は旧測定の説明価値を消さないが、新図は採用静的 backoff の証拠にはならない。

- **影響:** この命題を説明する新図は許容される。番号だけ変えて採用静的 backoff の結果として論文へ戻すなら、D1936 項21／D1993 決定5の実質的な迂回となる。段2の「歴史説明」という限定は維持すべきである。
- **判定:** 「価値が全くない」「新図は必ず迂回になる」は **refuted**。採用静的 backoff の証拠へ転用できない制約は **real**。

**4. caption と凍結 bytes は両立できる**

**5. `tracked_inputs` の追加は妥当だが、唯一の機構的選択肢ではない**

- **主張:** P3 は測定出所を保存する実装として妥当。ただし「差し替えは機構上できないから追加する」という正当化は成立しない。
