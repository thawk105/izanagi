## 見落としの疑い

**hold と実装面。** `growth_test_holds.py:300` の対象は `correctness_gate=True`、解除条件は `explicit-user-command-only`。`collateral_note` は、48 件の固定件数、成功・失敗集合の非交差、JSON pair の完全分割の検査まで停止すると明記している。実際には当該 node 全体の物理コピー照合・replay も実行されない。

`conftest.py` は焦点走／全走とも同じ opt-in 判定で skip を付ける。全走には hold 対象 node の収集漏れを拒否する追加検査があるが、**成果物集合の不一致を代わりに検査するものではない**。hold 契約テストも、台帳の件数・digest・解除条件などを固定しており、旧コーパスの内容を保証しない。

したがって親は、**この wave では修正しない**とは裁定できるが、**対応不要・整合性確認済み**とは書けない。既存不一致 6 件と今回の増分、検査されなかった範囲を既存 insight に残すべきである。ユーザーの解除指示なしに hold を解除する必要はない。

段 2 の「必ず実装子が必要」も強すぎる。予定一覧の生成物・docs は実装変更を必然にしない。コーパステストを変更しなければ、新 nodeid も生じず duration ledger 更新は不要である。テスト分類を修正する場合は Python の実装面となり、その時点で変異 matrix 免除は成立しない。

`docs/dev-wave/core.md` は実装面差分ゼロの場合の変異 matrix 免除を明記している。**今回の免除は最終差分を確認する条件付きで可。受入全走は免除されない。**

**D2026 の射程限界。** 旧 JSON の実測値は以下のとおり。

早期停止は 3 点以上で判定し、警告を停止条件に含めない。旧系列では停止時点ですでに適合点が観測されているため問題は顕在化していない。しかし新系列で警告付きの選択が返れば、そのまま打ち切られ、未観測の適合点があっても却下され得る。**投入前に知るべき帰結は「今回も却下で終わり得る」であり、この wave 内で停止条件を変更する根拠にはならない。**
