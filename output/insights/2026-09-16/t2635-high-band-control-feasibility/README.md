## 0. 結論と利用資格

ユーザー裁定 D2044 項 13 は「候補の設定について、高域 (`Backoff_` > 50 µs) への到達と既存 J1 が要求する共通の辺の成立を先に確かめる。
既存の事前登録を変えずに対照が作れると分かれば新しい走行を取る。分からなければ改めて諮る」である。

**答え: 現制約と記録済み証拠では、既存の事前登録を変えずに高域の対照が作れるとは確認できない。したがって新走行は取らず、§6 の裁定パッケージを返す。**
「将来も成立しない」とは言わない。

用語 (本文書で使う意味): **狭窓 / 広窓** = 適応 backoff の更新間隔 10 µs / 2560 µs。**共通の辺** = 直前 event の `{backoff_before, backoff_after}` を
順序を無視して完全一致させた辺のうち、両条件に非ゼロ符号の観測があるもの。**主帯域** = 辺の両端が 50 µs より大きい。**K_high** = 主帯域の共通辺の種類数で、
既存 J1 は共通辺 10 種類以上を要求する (閾値 10)。つまり「高域へ届く」だけでは足りず、**同じ辺が両条件で 10 種類以上**要る。

根拠 (記録済み事実と現物の制約だけ。§4 の代理計算は根拠に含めない — F29):

1. **既存の事前登録 (T-2188 `s4-ruling.md` §4 格子・§6 J1) は対照の 2 cell を名指しし、刻み・上限・トリガ型・workload・thread・extime・patch stack を
   全部固定している。** 初期 `Backoff_` は stock で 0 固定 (`external/ccbench/include/backoff.hh` の `Backoff::Backoff_(0)`、patch 3 本は定義行を触らない)
   で knob が無い。**設定を変える候補はすべて旧登録外である。** 設定を変えない候補は登録集合の再走だけである。
2. **登録集合の記録済み走行では、広窓側 `nm-step1-u2560` は 1,170 event すべてで `backoff_before` / `backoff_after` が 0.0〜12.0 µs にあり
   高域へ 1 度も入らない** (`no_high_band_observation`、D2020 の再現)。無改変の `_j1_sign_instability` は 2026-09-10 の記録
   (共通辺 12・重み 1,168・0.4984 / 0.4583・差 +0.0402・`not_supported`・`direction_unstable`) を完全に再現した。
3. **main の現物 driver は、trace mode で登録済みの cell 集合しか受理しない。** 実測 (driver を無改変で import): 広窓 cell の刻みを
   0.5 / 2 / 25 / 100 に変えた 6 cell 集合は文法上 parse できるが `BACKOFF_TRACE_CONTRACTS` に無く (`contract_absent`)、投入不能。
   登録集合は contract があるが `rep_index = 1` は `_validate_backoff_trace_contract` が拒否する (再走は rep 0 の別 job としてのみ可)。
   `.pbs` 側も 219〜247 行で同じ 4 集合に固定している。**候補 cell を走らせるには driver (`.pbs` / `.py`) と解析器 (`_NEW_TRACE_CELL_AXES`)
   の登録変更と新しい事前登録が要る。**
4. **記録済み広窓 walk の水準別の移動** (§3.4)。この記録では、5 µs 以下で上昇が多く (上昇 273 / 下降 146 / 据置 1)、7 µs 以上で下降が多かった
   (上昇 196 / 下降 314)。水準別に見ると 2 µs で 19/1、5 µs で 122/81、6 µs で 119/121、8 µs で 61/90、10 µs で 10/33、12 µs で 0/2。
   全水準の合計は上昇 588 / 下降 581 / 据置 1。`parity_branch` は 1,170 中 1,168 が `none` — 1,168 回は非ゼロ勾配の分岐で方向が決まり、
   parity 分岐は 2 回 (勾配ゼロ 2 件)。**この集計から、再走が 50 µs を超える到達可能性や確率は判断できない。** これは当該記録の記述であり、
   機序・到達確率の同定ではない。
5. **K_high >= 10 の必要条件** (理想格子 + stock 更新則の仮定内): 刻み S の広窓側が 10 本の異なる主帯域辺に非ゼロ符号を付けるには
   少なくとも `(floor(50/S) + 1 + 10) × S` まで登る必要がある — S=0.5: 55.5、1: 61、2: 72、**25: 325**、100: 上限超過 (`null`)。
   主帯域の非自己遷移辺の総数は S=0.5 / 1 / 2 / 25 / 100 の順に 1899 / 949 / 474 / 37 / 9 本。

## 1. 問いと、裁定の読み

- **(P1) 「既存の事前登録を変えずに」の読み。** 段 3 相談 A の裁定: J1 は cell を名指しし、格子は「6 セル、増やさない」「更新間隔だけが違う」と固定する。
  J1 の**方法** (順序なし完全一致辺・K >= 10・差 0.10・3 区間) を保った新 cell 対は「解析方法の継承」であって「登録された対照の継承」ではなく、
  旧登録を保存した別登録 J1' の候補である。その採否は D2044 の「改めて諮る」側に属する。
- **段 1 brief の断定を 3 件訂正した** (段 3 の指摘)。「高域へ届く広窓側は必ず別 cell」→ 「設定を変える候補は旧登録外」 (再走は旧登録内の唯一の候補で、
  1 rep の不到達から再走の不到達を確定しない)。「S=100 は 9 本だから構造的に不可能」→ 理想格子と stock 更新則の仮定内の結論 (F718 の表現上端の留保)。
  「再走は D2020 の不到達を繰り返す見込みなので取らない」→ 取らない理由は D2044 の条件付き投入許可 (先に確かめ、分かれば新走行) を満たす根拠が
  記録済み走行に無いからである。
- **本 wave は盲検ではない。** 設計時点で T-2583 の全数値、D2020 / D2021、旧 J1 判定を知っていた。事前登録 (段 4 裁定、
  `verbatim/s4-adjudication.md`、sha256 `5bd2d661829fb1d6d0bb05fd24a4f31d7e91a9571a2f5b1c6b7f39e46d3dd5ff`) が抑えるのは
  「本 wave の新しい集計を見た後に語彙・境界・候補集合を動かす余地」だけである。

## 5. 外挿の限界

- 1 rep。隣接 event 対は独立でない。`nm-step0.5` は走行の 69.90% を、`nm-step1` は 0.54% を取りこぼしており開始区間が無い。
- 平均回帰の機序、計数ノイズの寄与、未観測の広窓走行の到達確率、双子間の再現性は同定しない。
- §3.4 の水準別傾向は記録された 1 走行の記述であり、別の刻み・別の walk へ転移する保証は無い。
- 理想格子の本数は保存表現 (F718 の上端 1000 の留保) を含めた無条件の上限ではない。
- 出力 JSON の `limitations` には「将来も成立しないとは主張しない」「`predictor_range` を将来値の上下限としない」の 2 項が写っていない
  (段 6 レビュー A の nit)。凍結仕様 (`verbatim/s4-adjudication.md` §3.8) と本 README の限定が正であり、JSON の計数・判定値には影響しない。

## 6. 裁定への答え — 裁定パッケージ

**結論文:** 記録済みの登録対照では広窓側の最大値は 12.0 µs であり高域比較の共通台は成立していない。設定を変える候補はすべて旧登録外で、
