## 所見 (観点 1〜6、各 real / 不成立 を明記)

1. **刻み単位の外挿 — real。ただし「大刻みなら必ず平均回帰する」は不成立。**

   `gradient = Δtput / Δbackoff` では、分母を正の倍率で拡大するだけなら符号は変わらない。破れるのは、設定変更後も分子の符号、ゼロ発生、歩行履歴を保存できるという仮定である。backoff の変更は commit 数・競合・窓時間を変え、その結果が次の移動へ戻る。傾きが負の領域で信号が雑音より強くなれば下向きに戻され得るが、「刻みが大きいほど決定的」は更新則だけからは導けない。

   ゼロ勾配時も独立な公平コインではない。分岐は**累積 commit 数の parity**に依存し、上端では parity によらず減少、下端では偶数なら減少を clamp して据置になる。端点・符号だけを転写しても、変更後の parity と整合する保証はない。S=0.5 には整数型 `last_backoff_` による追加の非相似性がある。1,170 update 自体も設定不変の予算ではない。

   u10 の S=25/100 が 1000 へ到達したことは「大刻みでは高域へ絶対に届かない」を反証する。しかし約 3.3万／3.8万 update の到達は、広窓の約1,170 update の到達を保証しない。上端自己辺に帰属する符号が全てゼロという事実も、負勾配による平均回帰の証拠ではない。stock では直前変位ゼロなら throughput 差によらず勾配ゼロになるうえ、T-2583 は表現上端の留保も残している。

2. **u10 の先頭 1,170 update — real。先頭欠落の見落としという攻撃は不成立。**

   同 update 数でも、狭窓では起動直後の短い時間、広窓では走行のほぼ全期間を見る。cache、競合、thread の進行状態、窓内 commit 数が違い、同じ backoff 水準でも勾配を生成する状態が一致しない。11.7 ms は名目値にすぎず、`sum(window_us)` を出すプランの修正は妥当である。ただし実時間を併記しても、この移植可能性は検証できない。

   より強い問題は、開始 prefix の非ゼロ辺集合を \(E_b\)、同じ保持列全体を \(E_L\) とすると、全期間集計では
   \[
   E_b\subseteq E_L,\qquad |E_b\cap E_L|=|E_b|
   \]
   となる点である。**共通性は別走行で再現されたのではなく、構成上保証されている。** プランは「楽観的に見せうる」と認識しているが、これは単なる偏り以上に、双子間の共通性を検証する能力がない。

   `nm-step0.5` の152,205件欠落だけでなく、`nm-step1` の355件欠落もプランは明示し、保持先頭で代用しない。ここは対処済みである。

3. **格子の構造上限 — brief の無条件な不可能判定は real。プランの境界誤算・到達との混同は不成立。**

   `(50,75)` は主帯域に入らず、境界横断辺である。固定刻み・初期値0・上限1000の隣接非自己辺なら、プランの **1899/949/474/37/9 本**は正しい。上端自己辺を含めると、それぞれ1本増えるが、全符号辺種と非ゼロ共通辺数は別物である。307/196/38/10 を K と読まない設計も正しい。

   brief の「S=100 は9本なので構造的に不可能」は条件の省略がある。忠実な整数格子と stock 更新が成立するモデルでは、自己辺直後の勾配ゼロから9本の上限を説明できる。しかし保存表現を含めた無条件の主張にはできない。プランがこの優先判定を止めたのは妥当である。

   **さらに、S=25 の転写最大300には見落とせない制約がある。** 通常の隣接格子で主帯域に入るのは `(75,100)` から `(275,300)` までの9本だけである。非自己辺10本には少なくとも325への到達が要る。したがって高域の非ゼロ自己辺・格子外辺がなければ、(a) は到達を示しても **\(K_{a,\mathrm{high}}\le9\)**。これは候補全体の構造上限37とは別の、転写された歩行の制約である。

   S≤2 の (a) は高域に届かず、S=100 は適用不能なので、この通常格子モデルでは、現在の候補集合から二予測子一致による `K_predicted_ge_10` は出ない。将来走行の不可能性ではなく、**この転写法の限界**である。

4. **もっと強い記述証拠 — 一部 real。「それで広窓到達を同定できる」は不成立。**

   プランは既に水準別移動数・平均変位、広窓符号の自己相関、窓分布を含む。これらを丸ごと見落としているという攻撃は成立しない。ただし次は改善の価値がある。

   - 水準別の `P(up)` 単独では足りない。据置が多ければ0.5未満になるため、既定の up/down/stay と平均変位を中心に読む。上端の負変位は境界規則でも生じるので、内点の傾向と分ける。
   - **`parity_branch` の集計が出力仕様にない。** loader が落とすことは把握しているため、生 JSON の補助読取で件数を残せる。勾配ゼロ件数と併記すれば、符号保存だけでは移動を保存できない箇所を具体化できる。
   - セル全体の窓分布では「水準差」を見られない。既定の水準別表へ commit 数・窓時間の件数／平均／分散を添える方が、この問いに直接答える。

   それでも、平均回帰の因果、計数雑音の寄与、未観測広窓の到達確率は同定できない。窓分散には水準・時間変化も混ざる。広窓 lag 1〜10 の相関が小さくても独立性や長時間の到達則は保証されない。これらは外挿への反証材料であり、外挿を認証する材料ではない。

5. **probe の実効性 — 基本設計への攻撃は不成立。150行と検出範囲には real な限界。**

   プランは `spec_from_file_location`、解析器無改変、グローバル差替え禁止、旧 J1 の直接呼出し、`python3 -B` を明記している。解析器は標準ライブラリだけを使い、CLI は `__main__` guard 内なので、静的には import を妨げる要因は見当たらない。

   `--selftest` も最大12.0、辺種307/196/38/10、旧 J1 の12辺・重み1168・丸め値・判定に加え、帰属の1 eventずれ、50境界、ゼロ符号、欠落伝播を対象にする。**計算結果を固定期待値と比較し、合成例の期待値を手で固定すれば恒真ではない。** ただし同じ helper で期待値も生成したら検出力を失う。旧 J1 再現だけでは新しい転写・帯域分類の正しさも予測妥当性も保証しない。

   (b) の交差一致は恒等関係だが、これは selftest の恒真性とは別問題である。

   150行の配分表は実現の証拠になっていない。生計数、複数集計、三値判定、欠測、合成自己検査、出力まで含めると余裕は乏しい。ただし「収まらない」とも静的には断定できず、目安超過を理由に検証を削らない方針は適切である。

   140 MB入力、先例RSS約385 MiBから1 GiB未満を目標にするのは妥当な概算。loader は全セルを保持し、正規化中は生 JSON と正規化列が共存するので、「候補を逐次処理する」だけでは低メモリを保証しない。補助読取の文書を解放する設計は有効である。現在の空きは未確認であり、先例の385 MiB・2.87秒を今回の実績としては使えない。

6. **結論の限定 — brief は real。プランは概ね修正済みだが F29 の説明は不足。**

   brief 冒頭の「新走行の候補設定が…作るかを…読取だけで判定」、再走を「不到達を繰り返す見込みなので取らない」とする箇所は、1走行の転用から得られる強さを超える。

   プランは「条件付き模擬」「独立でない」「predictedだけでは作れる枝に入れない」と修正している。一方、「模擬予測を材料として」裁定へ返すという表現だけでは、F29の「模擬を裁定根拠にしない」との境界が曖昧である。**模擬と明記するだけで裁定根拠として適格になるわけではない。**

   裁定パッケージで根拠にできるのは、記録済み広窓の不到達、保持範囲、既存登録との適合関係、明記した仮定内の格子制約、未観測部分が残るという事実である。(a)(b)の一致・不一致、`predictor_range`、代理列内のKは、候補成立、新走行選択、再走却下、機序採否の根拠には使えない。

## 総括

P2の最大の破れは、符号・parity・更新予算の設定間移植と、prefix包含による見かけの共通性である。  
S=25は転写で高域へ届いても、通常格子では主帯域の非自己辺が最大9本にとどまる。  
先頭欠落、50境界、自己辺、無改変importへの攻撃は、プランで概ね対処済みである。  
probeは記述と実装上の自己検査には有効だが、予測能力の検証にはならない。
