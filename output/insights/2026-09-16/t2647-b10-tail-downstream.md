## 6. 親 brief の誤りと、段 4 の裁定

段 2 の plan と段 3 の 2 レンズが、親 brief の次を訂正させた。すべて本文へ反映済みである。

1. **「既測は 1000 マイクロ秒まで」は誤り。** 事前登録 §2.1 が記録するとおり、探索走
   ([T-2418]) で 2000 / 4000 / 9999 マイクロ秒は既に測られていた。09-15 は**正式格子の本走**で
   あって「1000 マイクロ秒より右を初めて測った結果」ではない。探索点の取得・正式系列の取得範囲・
   本格 cohort の判定は分けて書く。
2. **P1 の根拠 1 (「両系列の最新版が図の新規作成・昇格をしない」) は成立しない。** その文言が
   あるのは backoff 09-10 版だけで、本体 09-14 版には無い。しかも版自身についての記述であり
   後続 wave を制限しない。**図を作らないという結論は維持し、根拠を §4 の 3 点へ差し替えた。**
3. **事前登録 §3 の throughput 併記要件が完了条件から落ちていた。** 判定だけを渡すと、
   過抑制の費用が下流へ継承されない。§3 を足した。
4. **stale とする対象が §8 の 2 文に縮まっていた。** 実際は本体版の 5 箇所である (§5.1)。
   概要・ストーリー・実証状態表から材料を拾う読者に古い分類が残る。
5. **「図表への接続」を入口注記へ縮めていた。** cohort を明示した表を持たないまま「既存図とは
   別」とだけ書いても、受け渡しの完了を示せない。§1・§3・§4 の表を置き、両入口からここを指す形にした。

### 段 3 の所見のうち、親が採らなかったもの

**worklog fragment の `title:` を引用符で囲む案は採らない (refuted)。** 提案の根拠は
「`[` で始まる値が YAML の flow sequence として解釈され構文エラーになる」であり、レンズは
`yaml.safe_load` で確認したと述べた。**しかし実際の consumer は YAML パーサではない。**
`tools/spool_fold.py` の `_parse_frontmatter` は正規表現 `([a-z]+): ([^\n]+)` で frontmatter を
読む。`[T-2647] …` はそのまま文字列として取れる。逆に引用符を付けると、fold が生成する
worklog 見出しへ `"` が混入する — 既存の見出しは `— [T-541][T-507] …` の形である。

**2 レンズは割れなかった。** 一方は過大主張の側、もう一方は接続漏れの側を攻め、所見は
補完的だった。両者と plan が独立に同じ指摘へ収束した点が 2 つある (上の 1 と 2)。
