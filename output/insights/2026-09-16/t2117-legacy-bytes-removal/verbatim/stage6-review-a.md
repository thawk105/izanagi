## 判定の前提

すべて**静的読解による予測**です。pytest・変異実行・ファイル変更・git 状態変更は行っていません。

以下、`T` は `orchestrator/tests/test_codex_reasoning_ab.py`、`P` は `tools/codex_reasoning_ab.py` を指します。

## M1〜M5 の検出力

正例＝`test_m2_production_golden_requires_both_routes`、負例＝`test_m2_production_golden_rejects_route_mismatch`。

| 変異 | 静的読解による予測 | 失敗する根拠 |
|---|---|---|
| M1：比較を `return dict(route_a)` に置換 | **負例のみ失敗、正例は成功** | 負例は例外が発生せず `pytest.raises` が失敗する（T:3703）。正例は比較 wrapper を通り、返却値も期待どおりなので全 assert を満たす（T:3677）。 |
| M2：導出末尾を `return route_a` に置換 | **両方失敗** | 正例は `comparisons == []` となる（T:3677）。負例は例外が発生しない（T:3703）。 |
| M3：逆適用を `False` に変更 | **両方失敗** | `integrated` に対して `golden` を除去しようとして context エラーになる（P:744、960）。負例も要求する理由文字列と一致しない（T:3710）。 |
| M4：fix1→author に順序反転 | **両方失敗** | `base` に fix1 の `-authored` が見つからず、独立 parser の context エラーになる（P:831、969）。負例の理由完全一致も失敗する（T:3710）。 |
| M5：route B を通常 parser に置換 | **両方失敗** | 正例は通常 parser の呼出しが増え、独立 parser が呼ばれない（T:3669）。負例は mismatch 例外自体は出るが、`route_b_calls == []` なので失敗する（T:3713）。 |

期待 node が失敗しない変異は見つかりませんでした。既存 wiring node は第三の rollout 探索で停止するため、これらの変異まで到達しません（T:9033、9086）。確認した呼出し範囲では期待外の失敗も見つかりません。ただし、完全集合と変更前 HEAD の「0 件」は実測していません。旧 m2 の skip は歴史 rollout の不在に依存します。

## 所見 1：負例末尾の assert は production を何も守っていない

- **主張:** `assert expected_a != expected_b` は、直前に作った literal 同士を比較する恒真 assert です。
- **根拠:** T:3706、3707、3708、3718。
- **壊れる具体例:** production が誤った辞書を返すよう壊れても、この式自体は `golden` と `golden-mismatch` の差だけで真になります。ただし M1 は、この式より前の `pytest.raises` が検出します。
- **重大度:** nit。
- **成果物影響:** 認証済み選択・材料レポート・試行台帳の値、受理集合、参照は変わりません。この assert を独立した検出証拠として数えることだけが不適切です。

その他の assert は実観測に結び付いています。

| assert | 検査しているもの |
|---|---|
| 正例の `route_a_calls` | 入力 blob、fix2、逆適用、呼出し回数 |
| 正例・負例の `route_b_calls` | base、author→fix1、独立関数への到達 |
| 正例の `comparisons` | 比較への到達と両経路の実出力 |
| 正例の `golden` | production の返却 bytes |
| 負例の `rc`・`reasons` | 拒否の種類。比較前の別エラーを排除 |
| 負例の `comparisons` | 実際に異なる bytes が比較されたこと |

これらが個々の変異に対して真のままでも、それだけで恒真とはいえません。

## 期待値と wrapper の検証

期待 bytes は T:3668、3706〜3708 の literal から作られ、production の結果から導出されていません。

観測 wrapper は保存した実関数へ委譲しています（T:3651、3656、3660、3695、3699）。generator は list 化した **`recorded` を渡しており**、消費済み generator を渡す問題もありません。patch の期待値は fixture 入力との照合であり、production 出力の再利用ではありません。

stub 化や期待 bytes の自作自演は見つかりませんでした。

## 所見 2：歴史材料との統合保証は引き継がれていないが、裁定済みの代償である

- **主張:** 新 2 node は一般的な二経路導出を守りますが、実 commit・歴史 rollout・既定 manifest の組合せが導出に成功する保証は引き継ぎません。
- **根拠:** T:3593 の commit 定数差替え、T:3628 の合成 provenance、T:3665 の明示 manifest。旧保証は `impl.diff:149`、151 の削除箇所。
- **壊れる具体例:** production の歴史 commit 定数が誤った object を指す → 新 node は定数を上書きして成功し得る一方、実材料の導出は失敗します。
- **重大度:** scope 外（段 4 の A-4 で受容済み）。
- **成果物影響:** 本変更による成果物の値・受理集合の変更はありません。将来の歴史参照破損について、この 2 node から得られる検出保証が失われます。

旧 m2 に明示的な拒否入力の検査はありません。歴史材料が利用可能なら「例外なく導出できること」を要求する正例でした。新 2 node が撤去した既存の負例は見つかりません。

復元不能な歴史 bytes の要求は、T:9291 の実 rollout SHA 照合と T:9299 の source line 完全一致に残っています。ただし、これは D1615 により維持するよう指定された別 node であり、今回の撤去漏れとは判定しません。

## 所見 3：source SHA 拒否は新 2 node だけでは証明できない

- **主張:** rollout と期待 SHA を同時に生成するため、SHA 検証の無効化を新 2 node は検出できません。
- **根拠:** T:3630、P:944〜950。
- **壊れる具体例:** SHA 検証を無効化した production に、期待 SHA と異なるが同じ patch を含む rollout を与える → 本来の拒否が消えても、新 2 node は正常な SHA しか使わず検出できません。
- **重大度:** scope 外（段 4 の A-3 と同じ既存限界）。
- **成果物影響:** 現差分による受理集合の変更はありません。将来 SHA 検証が壊れた場合、出典不一致の材料受理をこの 2 node では検出できません。

production 差分がないため、変更前に `ValidationError` だった入力が本変更だけで受理される経路は見つかりません。

## 所見 4：一時 repo の commit はシステム git 設定に依存する

- **主張:** ユーザー環境は除去されていますが、システム git 設定により新 2 node が比較到達前に失敗し得ます。
- **根拠:** T:3574、3585、P:519、3829。`GIT_CONFIG_NOSYSTEM` は設定されず、外側から指定しても除去されます。
- **壊れる具体例:** システム設定で `commit.gpgsign=true`、利用可能な署名鍵なし → 合成 commit が失敗し、正常な production でも両 node が失敗します。失敗するシステム `core.hooksPath` でも同様です。
- **重大度:** nit。
- **成果物影響:** 認証済み成果物の値・受理集合・参照は変わりません。検査結果が環境依存の失敗になります。

その他の指定条件は次のとおりです。

- **既定 branch 名:** `HEAD` のみ参照するため、`main`／`master` の違いには依存しません（T:3594）。
- **`GIT_*`・user.name 未設定:** 前者は除去され、後者は commit 引数で指定済みです（P:3829、T:3587）。
- **ファイル順序:** 固定 tuple を反復し、辞書比較を使うため、ディレクトリ列挙順には依存しません。
- **`PATCH_PATHS` 要素数:** 空では成立しません。commit 対象がなく、負例には `[0]` 参照もあります（T:3584、3708）。現定義は 2 要素であり、現状の flaky 要因ではありません（P:233）。
- **xdist:** function scope の一時ディレクトリと process ごとの monkeypatch なので、固定 session ID による衝突は見つかりません（T:3572、3614、3617）。

## 総括

blocker／must-fix は見つかりませんでした。  
最も実行上の影響がある所見は、システム git 設定による合成 commit の失敗です。  
静的読解では M1〜M5 の期待どおりの検出が成立し、恒真 assert は負例全体を無効化しません。  
段 4 で受容済みの被覆限界を前提に、**実装は受け入れてよい**と判断します。変異実測の証明は別途必要です。
