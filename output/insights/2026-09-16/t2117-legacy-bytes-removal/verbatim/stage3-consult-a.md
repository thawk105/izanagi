## 1. 負例が比較前の失敗を成功扱いする穴は、計画上は閉じている

- **主張:** 静的読解では、指定された fix1 改変は比較まで到達でき、途中の別エラーを mismatch 検出と誤認する構造ではない。
- **根拠:** `plan.md:106` は追加行だけを変更する。production の `tools/codex_reasoning_ab.py:818–835` は除去側 `authored` を検索するため、追加側の `golden-mismatch` は適用を妨げない。path は `:233–236` の allowlist 内、envelope は `:848–849` に適合する。manifest 検証 `:2755–2763` は必要な auxiliary pin を受け付け、更新後 SHA は `:944–950` の検証と一致する。fix2 は独立した入力で、`:951–960` の逆適用も影響を受けない。
- **壊れる具体例:** JSONL 追記前の SHA を誤って使う → 比較前に `fix1 rollout sha mismatch`。しかし `plan.md:55–60` の理由タプル完全一致と比較記録の assert が不成立になるため、負例成功には化けない。正常に構成すれば、最初の path だけが異なり、`:915–921` が指定の一理由を返す。
- **重大度:** **nit**。この攻撃では設計欠陥を確認できなかった。実行結果の判定ではない。

## 2. 正例は比較関数の恒真化を検出しない

- **主張:** 正例が守るのは呼出しと正常入力の結果であり、比較関数内部の拒否能力は負例だけが守る。
- **根拠:** `plan.md:31–38` の wrapper は実関数へ委譲する。両入力が期待 golden と一致する場合、production `tools/codex_reasoning_ab.py:912–922` を `return dict(route_a)` にしても、呼出し回数・比較入力・返却 bytes は変わらない。
- **壊れる具体例:** 比較関数本体を恒真化 → **静的予測では正例は成功したまま**、負例は例外が出ず失敗する。一方、`:978` で比較呼出し自体を省略 → 正例の比較到達 assert と負例の例外期待がともに不成立になる。この二変異を同じ検出実績として扱ってはいけない。
- **重大度:** **nit**。`plan.md:166–167` は既に区別しており、正負二本の案はこの攻撃に耐える。

## 3. SHA 拒否の統合被覆まで回復したとは言えない

- **主張:** production 無変更なので今回の撤去による実入力の受理集合拡大は見当たらないが、新二本は `verify_source_sha` の拒否能力を証明しない。
- **根拠:** 新入力はすべて正しい SHA を持つ（`plan.md:125`）。`_find_rollout` は SHA 不一致を捕捉して探索へ戻り、所有 session が一件ならその path を返す（`tools/codex_reasoning_ab.py:618–637`）。最終拒否は `:944–950` に依存する。既存 `test_codex_reasoning_ab.py:985–995` は検証関数の直接呼出しであり、`:8887–8919` と `:8922–8973` は最終 SHA 検証より前で打ち切る。
- **壊れる具体例:** auxiliary SHA だけが誤り、session 所有者は一件、patch は正常 → 現実装は最終 SHA 検証で拒否する。仮に `:944–950` を迂回させる変異なら受理され得るが、正しい SHA を使う新二本はその変異を検出できない。manifest pin の解決先を観測する既存テストも、この拒否の代替にはならない。
- **重大度:** **scope 外**。既存の被覆限界として裁定パッケージ候補にできるが、本 wave への検査追加は勧めない。今回の変更で新たに生じる穴とは認定しない。

## 4. commit 定数の差替えは実在する手法だが、歴史入力との統合保証は失う

- **主張:** plan の既存例は実在するが、差替え後の検査が保証するのは合成 commit に対する結線である。
- **根拠:** `test_codex_reasoning_ab.py:2417–2454` は一時 repo と二 commit を作り、`:2461–2462` は実際に両定数を monkeypatch する。ただしその既存例は `_build_snapshot_base` 用で、`:2463–2464` では `BRANCH` と `TRACKED_PATHS` も差し替える。golden 導出そのものの前例ではない。新案では production `tools/codex_reasoning_ab.py:169–170` の値を上書きしてから `:957`、`:963` を通る。
- **壊れる具体例:** production の歴史 commit 定数が誤った値へ変更される → 新二本は正しい合成 commit に上書きするため、その誤りを観測しない。また一行置換だけなので、歴史 patch の複雑な hunk 処理との統合保証も引き継がない。
- **重大度:** **nit**。歴史 bytes 要求の撤去として説明可能な代償であり、比較恒真化を検出する目的の blocker ではない。

## 5. 親 brief は静的観察を全体保証へ一般化している

- **主張:** P1-a と P1-c は提示された観察だけからは導けず、とくに「登録判断を誤れば exact 検査が落とす」という補強も成立しない。
- **根拠:** `brief.md:47–50` は全項目を実測とする一方、`:65`、`:81–82` は読解と明記する。項目2／P1-a（`:54–57`、`:94`）が直接示すのは当該 guard の利用箇所だけである。項目4は fixture 本文の読解、項目6の定数と引数の関係もコード上の性質である。項目7／P1-c（`:74–84`、`:99–100`）の grep 不在は、新 node の資源利用を証明しない。

## 6. 五変異について、既存の別テストへの検出帰属は確認できない

- **主張:** 指定された五つの局所変異を「既存の別 test が先に検出する」とする根拠は、調査した呼出し経路にはない。

- **重大度:** **nit**。既存別テストによる帰属不成立は確認できなかった。ただし五変異はいずれも未実走であり、検出順序や検出の一意性は断定できない。
