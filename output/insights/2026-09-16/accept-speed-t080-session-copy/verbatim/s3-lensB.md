## critical path の費用モデル

**所見**：proto 化が勝つには、実 repo 読込みの競合削減が、proto 待ちと追加コピーの費用を上回る必要がある。
**分類**：plausible
**根拠**：同時開始・後段不変なら勝利条件は `max(R_k) > R_proto + D`。brief の値を仮置きすると、`R_proto=38/52.9、D=3` では旧 critical-path の R が **41/55.9 秒超**で初めて勝つ。38 秒は直列平均であり予測値ではない。
**影響**：延べ読込みを 5→1 にしても、非競合で各 R が等しければ最初の key は D だけ遅くなる。
**推奨**：plan v2 はこの不等式を採用し、R・D・後段の並行時所要を未測定として明記する。

**所見**：5 key の同時開始を仮定したモデルだけでは、48 worker の受入を説明できない。
**分類**：real

**所見**：200〜222 秒と118.2 秒の差を、そのまま proto 化で減る競合時間にはできない。

**推奨**：差を「測定範囲の差、lock 待ち、準備競合、発行・本体競合」に分け、scheduler 待ちは span 側で評価する。

**所見**：発行53.3秒が不変なら、直列 base 全体の理想改善率でも54.9%を超えず、今回の分割点の上限はさらに低い。
**分類**：real
