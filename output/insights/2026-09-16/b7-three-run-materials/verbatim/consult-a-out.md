## 新稿を足すことの当否

**3 走行併記稿は条件付きで許容できる。ただし、brief の純増説明と plan の対抗案排除は、そのままでは採れない。**

**所見 1 —「results 系列に [T-1998] の材料が無い」は広すぎる。重大度: must-fix**

`2026-09-14-b7-all-workload-regression.md` §0.1 は [T-1998] の存在・受理判定と版 §8 への参照を持ち、§4.4 も 3 走行の要約へ接続している。一方、同稿の表・生標本・出所一覧は明示的に A-2 / A-6 のみを対象とする。

したがって純増は「[T-1998] への言及や導線」ではなく、**[T-1998] の生標本・条件・限定・出所を備えた詳細な結果節材料と、既存 2 attempt との併記**である。§4.4 の「その材料の詳細版」を、[T-1998] まで詳細化済みという意味には読めない。

影響: 放置すると、入口と下流の執筆が既存稿の対象外指定を欠陥と誤認し、新稿を訂正版として参照する。

**所見 2 — 対抗案 (b) は部分的に成立し、(a) は排除できていない。重大度: should-fix**

「B-7 の材料化と 3 走行への導線は既にある」という意味なら (b) は成立する。「3 走行すべての詳細材料が results にある」という意味では成立しない。

不足が [T-1998] の詳細材料なら、(a) 単独稿も直接の解決になる。plan の「一緒に読める依頼には不足」は、検査対象である親の「1 稿にする」という完了条件を根拠に親案を選んでおり、配置の独立した正当化にはならない。**併記の利便性を選ぶ編集判断**として説明すべきである。

影響: 放置すると、詳細材料の不足という問題から、3 走行を必ず 1 file に収めるという不要な配置要件が導かれる。

## 系列規則への適合

**所見 3 — 新稿の追加自体に違反はないが、全体再導出の対象を明確にする必要がある。重大度: must-fix**

抵触し得る逐語は、README「results 系列」の以下である。

- 「**その結果の一次資料全体**」
- 「**一項目だけを直した差分改訂を新しい日付として置かない**」

A-2 / A-6 を旧稿から引き継ぎ、[T-1998] だけ一次資料から起こすなら、この禁止に当たる。plan はその危険を認識しているが、総括の「既存稿の全体再導出」という表現では対象が狭い。必要なのは、**新稿が定義する 3 走行の報告単位全体についての再導出**である。

反対に、それを実施した新稿は、追加内容が主に [T-1998] であるという理由だけでは差分改訂禁止に当たらない。「純増の項目数」と「導出作業の範囲」は別である。

影響: 放置すると、再照合していない旧稿の条件・限定・出所が、新しい日付で確認済みの事実として再発行される。

append-only、新規ファイルへの配置、results 表への登録については、plan に具体的な違反は認めない。

## 単位の妥当性

**所見 4 — 既存の個別登録は、任意の追加を認める一般則ではない。重大度: should-fix**

README の既存行が認めているのは、**名指しされた 2 attempt・6 cell の報告単位**である。balanced の別対比較を加えても workload の集合自体は増えない。したがって、brief P2 の「全 workload の集合の拡張」は厳密ではない。

ただし D1631 は「完走した 1 つの protocol **または campaign 群**」を認め、共同の単一 protocol を必須とはしていない。3 走行を名指しし、それぞれの登録・判定を保持する plan の構成を、規則違反と断定する根拠もない。

適切なのは、**今回限定の campaign 群の結果材料として選ぶ**という説明である。「B-7 に関連する結果なら随時追加できる」という一般則にはしない。(a) 単独稿は単位の説明がより直接的だが、併記稿を禁止する理由にはならない。

影響: 放置すると、「全 workload」を名目に異なる結果を際限なく束ねることが、results 系列で受理される前例になる。

## 凍結境界への影響

**所見 5 — bytes の保持に加え、旧稿との用途関係を入口でも固定する。重大度: should-fix**

plan は旧稿を誤りの訂正と呼ばず、旧 fig5 の用途制限も残すため、現時点で制限を緩める具体的な案は認めない。ただし README の提案行には「旧稿を改めるものではない」がない。既存表は、訂正版・別 attempt・英語稿の関係を明記しており、新行にも同程度の区別が必要である。

新稿本文と入口に、**既存稿は 2 attempt の材料として残り、新稿は別事前登録の対比較を含めて併記する**と明記する。

影響: 放置すると、bytes が不変でも下流の引用先が自動的に新稿へ置換され、旧稿の対象範囲や用途が変わる。

旧 fig5 については、`figures/README.md` の「追補 — 旧 fig5 の用途制限に期限を設けない」が優先する。D1993 項1の解除を fig5 に及ぼさず、fig6 を fig5 の後継図とも呼ばないという plan の扱いは妥当である。D1874 の禁止対象と A-2 balanced を区別する方針にも問題はない。

## 入口の表と裁定の射程

**所見 6 — 提案行の列構成は適合するが、完了の意味を限定する。重大度: should-fix**

既存 4 列への追加位置・形式は整合する。`protocol status` 列に consumer の `accepted` を置くことも、出力主体を明記し、producer の `complete` と分離しているため、直ちに列の意味を壊さない。

一方、brief の「3 走行そろった」という完了条件は、**指定した掲載対象がそろったという文書作業の完了**に限る必要がある。B-7 の材料が網羅的・十分になった、あるいは [T-2610] が解消したという意味にはしない。plan は充足判定を禁じているが、この区別も本文へ出すとよい。

影響: 放置すると、稿の完成が B-7 の受理条件を満たす証拠として流用され、未裁定の [T-2610] を事実上閉じる。

**所見 7 — D1986 項5の帰属は、認可と再諮問条件まで正確に書く。重大度: should-fix**

据え置いたのは **A-1 本番測定の認可**である。「今は認可を出さない」「試験運転専用の分岐を外す実装が閉じた時点で改めて諮る」「認可はユーザー手番」が内容であり、本走未投入や `formal=false` の直接の実行証拠ではない。実装完了が自動認可になるわけでもない。

D1993 は項1・2の素材利用、項3の限定付き解除、項4の非遡及、項5の旧判定・fig5 制限、項6の集計禁止として引ける。**3 workload の但し書き解除を、[T-1998] の独立な certification に読み替えてはならない。** この点の plan の分離は妥当である。

影響: 放置すると、裁定参照が未確認の実行状態や追加走行の認証、将来の自動投入認可まで保証するものに広がる。

## 総括

**配置案を禁止する所見はないが、plan の無条件な採用理由には不同意。** 起草前に次を直す必要がある。

- 純増を「[T-1998] の詳細材料と併記」に限定する。
- 新稿の 3 走行全体を再導出の対象にする。
- 3 走行の束ね方を今回の編集判断として説明し、旧稿の置換や B-7 の充足条件にしない。

[T-1998] 単独稿は依然として有効な対抗案である。3 走行併記稿を選ぶなら、規則がそれを要求しているからではなく、異質な結果を限定付きで一緒に読めるようにするため、と説明するのが正確である。
