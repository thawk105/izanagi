## 受理集合の向き

静的なコード追跡による結論であり、v3 の実行実測ではない。現行 R:55–56 はまだ v2 である。

**生 JSON では逆向きの実例がある。** 他のフィールドが正常な6 trial に、各 trial の `n=2` と schema `/v3` を与える。

| 入力 | 現行 v2 | 計画どおりの v3 |
|---|---|---|
| `/v3`、全 trial に整数 `n=2` | R:812–813／887–888 で拒否 | 新設型・下限・一致検査を通る |
| `/v2`、`n` なしの正常な旧形式 | 受理対象 | 版検査で拒否 |

版だけを `/v2` に戻しても、前者は R:769／662 の `unknown=['n']` で拒否される。したがって、これは単なる版文字列の比較だけに由来する差ではない。

**版を旧版へ戻し、`n` を削除する射影では、旧条件を破る入力が新たに通る例は見つからない。** R:761–793 の既存検査はすべて維持される。ただし全旧正例を `n=2` で拡張できるので、この層では「旧契約を保持し、追加フィールドを制約する」が正確である。

## 恒真化の危険

manifest は root／版／commit 検査後に `_parse_trials` へ入る（R:811–817）。registration はそれに先立ち改行・canonical JSON・登録メタデータも検査する（R:875–906）。**経路全体の検査順序は同じではないが、trial 内の検査は共通**。registration の trial 順序検査は新設予定の検査より後になる（R:800–801）。

| 負例・変異 | 静的判定 |
|---|---|
| `n` 欠落 | 既存 exact-key で落ちる。必須キー集合の検証として有効だが、新設型・下限検査の到達証拠ではない。 |
| `n="2"` | 正常な他フィールドを保持すれば新設型検査に到達する。 |
| `n=True/False` | 厳密型検査を `isinstance` に弱めても、下限違反で落ちる。P:88 の**型エラーメッセージ照合**が必要。拒否の有無だけでは変異を殺せない。 |
| `n=2.0` | 型検査を外すと `2.0 < 2` は偽、集合でも整数 `2` と同値なので、通常の `n=2` fixture では通り得る。型検査を孤立して攻撃する有効な負例。 |
| `n=1/0/-1` を1 cellだけに設定 | 下限検査を外しても holdout 内不一致で落ちる。下限エラーの照合なら変異を検出するが、拒否だけでは二重防壁に隠れる。 |
| arm 間不一致 | 各 `n` が整数かつ2以上なら、新設一致検査まで到達する。 |
| canonical tuple の `n` 変異 | T:6780–6783 は parser を通さず比較 helper を直接呼ぶ。型・holdout 一致検査に隠れない。 |
| `n` 付き v2 の拒否 | 新設版判定の維持には使えるが、**`n` なしの真正 v2 を受理する互換変異は検出できない**。 |
| 取得だけを欠落補完へ変更 | exact-key が先に拒否するため、その変異は生存し得る。欠落を実際に受理させる変異とは区別が必要。 |

P:111 の「型エラーの期待を外す」は曖昧である。**テスト側の期待照合を削除する意味なら、bool は下限で拒否されて緑になり、変異検出が失われる。** P:88 の期待を保持し、変異実装がその期待に合わなくなる、という意味に限定すべきである。

## scope 外だが real

**観測反復の consumer は不足したままである。** [8b:469–471](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t1957-manifest-replicates/docs/phase3-8b-descriptor-design.md:469) と [8c:248–256](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t1957-manifest-replicates/docs/phase3-8c-preregistration.md:248) は登録値と観測集合の exact 一致を要求する。R:3607–3612 は、複数反復の初回 slot を拒否する一方、各 trial の反復0だけならこの局所検査を通す。**`n≥2` の宣言自体が genesis を必ず拒否させるわけではない。** B:35／P:134 の記述は、この区別を欠く。

本 wave の `n` は parser・serialization・manifest/registration identity には効くので、全面的な休眠 field ではない。しかし、**観測数を拘束する層では休眠している**。

- **進めてよい理由：** 保存・読込・identity の契約を準備し、正式発効や反復観測の受理成功を成果に含めない範囲なら、既存 gate の撤去を伴わない。
- **進めてはいけない理由：** これを「反復束縛が完成」「D959 の(d)を解除」「§5 記入可能」と扱うなら、実消費を要求する8c:196–199に反する。既存 gate を後から緩める根拠にしてもならない。

凍結2文書の編集を必須にする新たな schema 版指定の衝突は、確認範囲では見つからない。**文書を触らず実装準備を進めることと、仕様への完全適合は別である。** exact 反復束縛の欠落、および H1=2／H2=3 と8b:450–451の完全 block 文言との関係は未解決のまま残る。ここでは実装修正を提案しない。

規律2について、計画に既存検証を緩めるコード変更は見つからない。ただし、旧版互換負例の穴と「縮小」という不正確な説明は、将来の受理拡大を見逃す具体的な弱点になる。
