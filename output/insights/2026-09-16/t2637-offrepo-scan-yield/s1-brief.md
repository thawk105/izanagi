**割れうる前提 (親の provisional 裁定・攻撃対象)**:
- **(P1) 抑止の収量は構造的にほぼ 0 である。** D247 条件 5 の祖先 dir 条項は、D248 が `/` を境界に
  含めないため、docs が dir を長い path の接頭辞として書く限り発火しない。実測で 2 走連続 0 対。
- **(P2) 走査が実際に買っているのは `unreferenced_copies` の注記であり、その consumer は
  掃除ではなく D970 の救出 triage である。** よって「掃除を速くする」と「注記を保つ」は別問題。
- **(P3) 候補先行方式は `suppressions` を厳密に保つが `unreferenced_copies` を壊す。**
  被覆部分木の外にある控えは見つからなくなる。つまり価値のある方を削る。
- **(P4) cold が実運用の regime である。** 掃除は日をまたいで散発的に走る。warm 455 秒 / cold 2429 秒。
- **(P5) 定数削減だけでは足りない。** C + 並列でも cold 1583.99 秒 (CPU は wall の 4.6%)、
  Python 比 1.53 倍で、必要な 8.1 倍を埋めない。
- **(P6) 本 wave は実装しない。** ユーザーの指定成果物が「収量の実測と、採る案の設計」であり、
  採る案が D985 と衝突するため。
