# 段 1 brief — 合成監査の必要性判定と高速化

## ユーザー裁定 (確定)
「合成監査の必要性を確認する。必要ならば維持し高速化する。不要ならば撤廃する。」

## 親が実測した必要性の判定 (撤廃は選ばない)

`docs/archive/` の worklog 22 file から抽出した合成監査 (main 取り込み時の Codex
`role=author` 監査) の走行は 13〜15 回。うち **8 回が本物の欠陥を検出**した。

検出したもののうち次の 4 件は「textual conflict ゼロ・テスト緑」で通過していた。

- F324 (T-817): 呼出し規約を厳しくした側の契約を、相手側の新規呼出し 3 件が満たさない
- F481 (0823-852-853): 相手の認証済み `--ignore` を絞り込みと誤認し、受入全走のたびに
  stale 検査を無効化していた (**受入全走でも緑になる型**)
- 0823-863: `failure_class` 必須化により旧 schema V1〜V3 receipt が拒否される受理集合の退行
- 0818-656: 凍結の不変検査が祖先 commit で永久拒否になる状態

検出ゼロだった走行は 5 件以上ある。工数は receipt 台帳の実測で 106〜468 秒 / model call
6〜28 (n=5、launcher error 2 件を除く)。

**判定: 必要。** 検出率が 5 割を超え、検出物には受入全走でも緑になる型が含まれる。
これは絶対規律 2 (正しさゲートを緩める変異を許さない) が守る面そのものであり、
費用 (数分) は防いでいる損失 (main へ入る受理集合の退行) より小さい。

## scope

高速化だけを実装する。撤廃・発火条件の緩和・監査観点の削減はしない。

親が実測した高速化の余地は 1 点に絞れる。**監査子の所要は、親が事前にどれだけ
アンカーを渡したかで決まる。** 現物比較 (job artifact):

- `t1726-s9-merge-audit`: 親が重複実装面 path 1 本を名指しし疑い所を 3 点書いた
  → 320 秒 / 7 call
- `stage6-merge-audit-2`: 事前射影が薄い → 468 秒 / 28 call

この事前射影は今すべて手作業であり、`docs/failures.md` F504 (経路が塞がっていた)、
D554 が引く 52 分の損失、`stage=merge-message-provenance` rc=70 の空転の原因でもある。

**成果物:** 取り込み予定の 2 commit から監査子への射影を決定的に生成する 1 tool。
出力は (a) 両親が触った実装面 path の重複集合、(b) path ごとの両親の diff の所在、
(c) 変更された top-level 識別子と、その全呼出し箇所の AST 数え上げ (F324 が処方した監査形)。

## 不変条件

- 監査の観点を減らさない。tool は子が読む材料を増やすだけで、子の判断を代替しない
- (a) の path 集合は `tools/check_ai_provenance.py` の
  `_is_implementation_path` / `_combined_diff_paths` を**再実装せず再利用**する。
  checker と食い違う集合を第 2 の権威にしない
- 出力に「重複はこれで全部」と書かせるなら、母集合と除外規則を同じ出力に書く。
  数え上げゼロを恒真にしない (F324 の再発検知欄)
- 既存の受理集合・land 経路・provenance の判定を 1 bit も変えない

## 攻撃対象の provisional 裁定 (親の暫定であり段 3 で攻撃せよ)

- (P1) 事前射影を厚くすると監査は速くなる。**逆に、tool が過小報告すると子が
  それを信じて探索を止め、監査が恒真化する**のではないか。t1726 の prompt は実際に
  「他に実装面の重複は無い」と断言している
- (P2) 高速化の対象は監査子の実行時間である。親の手作業と rc=70 の空転の方が
  大きいなら、tool の出力先は prompt でなく親の手順そのものではないか
- (P3) AST 数え上げは Python に限られる。実装面には C++・shell・JSON もある。
  部分被覆の数え上げを「全呼出し」と名乗ると F324 の再発検知欄を偽装する

## 成果物の形

`tools/` 配下の 1 script + そのテスト。docs は既存 D への追記でなく新規 D と、
`docs/dev-wave/` への配線 1 行 (byte 予算に入らなければ裁定へ返す)。

## 並列分割方針

段 3 は 2 レンズ (恒真化・被覆の嘘 / 手順と実行の食い違い)。段 5 は実装子 1 本
(tool + テストは同じ編集面)。段 6 はレビュー 2 本。
