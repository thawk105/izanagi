# 段 6 裁定追補 3 — fix 子のテスト編集範囲 (親起因の空振りへの是正)

fix-2 は実装せず停止した。**判断は正しい。**親の prompt が「既存テストの期待値を変更しない」と
無条件に書いたため、裁定 C-6 / C-3(B-9) が要求する挙動変更と、同 wave の段 5 で自分たちが書いた
テストの期待値が正面から衝突した。

## 衝突の実体 (子が特定、親が確認)

1. `orchestrator/tests/test_t810_pbs_wrapper.py:297` — 第 2 process 走査が失敗するケースでも
   `start_ack` が書かれることを期待している。C-6 は「post-release 再検査が**すべて成功した後にだけ**
   ack を書く」を要求するので、両立しない。
2. `orchestrator/tests/test_t810_pbs_wrapper.py:355` — 外部 tree について `repo_absence` の全 boolean が
   true であることを期待している。C-3/B-9 は「node からは証明できないので false 固定」を要求するので、
   両立しない。

## 裁定 (例外の明示)

**「変更しない」対象は wave 開始前から存在した tracked テストである。**
本 wave の段 5 で本 wave の子が新規作成したテスト
(`orchestrator/tests/test_t810_{harness_schema,coordinator,pbs_wrapper,runner_policy,guard,budget}.py`)
は、**段 6 の裁定が契約を変えた箇所に限り**期待値を更新してよい。

ただし方向を固定する。

- **強化方向のみ。**受理を広げる変更 (fail-open 化、拒否の削除、skip/xfail 化、assert の削除) は
  引き続き禁止する。今回の 2 件はいずれも**受理を狭める**方向であり、これに該当する。
- 期待値を変えた箇所は、変更前後を報告の対応表に 1 行ずつ書く (どの裁定条項が要求したかを併記)。
- 契約が要求していない期待値には触れない。
