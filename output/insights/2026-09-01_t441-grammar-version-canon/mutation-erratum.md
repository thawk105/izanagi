# 変異事前登録の erratum (2026-09-01、親)

段 4 で M1〜M12 を凍結した。実装が確定した後に注入点を実コードで確かめた結果、
**2 件が注入不能**と判明したため、登録から外して 2 件を追加する。凍結は自分が書いたものでも
拘束するので、差し替えを黙って行わず本 erratum に残す。

## 外した 2 件

- **M7 (正準化を WAL 記録だけに留め raw source を残す)** — 注入点が存在しない。
  確定した設計は WAL へ**版**を記録するのであって正準形の数値 token を記録しない
  (`wal.py:646-662`)。したがって「WAL だけ正準化する」状態を作る既存コードが無く、
  変異は新規機能の追加になってしまう。M6 (canonicalizer を quarantine へ配線しない) が
  同じ防壁 — 材料化 bytes の検査 — を単一理由で突く。
- **M12 (版なし旧 cache key への fallback を残す)** — 注入点が存在しない。
  段 6 の 2 レンズが独立に確認したとおり production に fallback は無く
  (`buildcache.py:2495`、`:3086`)、変異は既存文字列の置換ではなく新規 lookup の挿入になる。
  代わりに fix の D-4 が、poison した unbound entry を実配置して bound-v1 が
  それを開かないことを実 lookup で固定している。これは変異ではなく正例・負例の対で
  同じ穴を塞ぐ。

## 足した 2 件

段 6 の fix で新設した 2 つの防壁は、段 4 の凍結時点には存在しなかったため登録できなかった。
実装が確定した今、単一理由性を確認して追加する。

- **M13 (reject identity の版不一致検査を無効化)** — fix D-3 が入れた
  `record_diff_reject()` の exact 比較 (`p3_s4_loop.py:411-421`) を殺す。
  段 3 のレンズ A が F-04 で指摘した穴に対応する防壁であり、これが効かないと
  variant identity と WAL が別版に帰属する。
- **M14 (共有 reject helper の既定を v1 へ戻す)** — fix D-2 が直した最重要の回帰を再現する。
  既定が `None` でないと、版を渡さない sort / trigger / probe の 7 呼び出しの
  reject identity が backoff の版に束縛される。

## 変更しない点

登録件数は 12 件のまま。期待は `DW-M07` に従い probe (全件 SURVIVED 期待) で観測 node を
集めてから KILLED 期待へ確定する。
