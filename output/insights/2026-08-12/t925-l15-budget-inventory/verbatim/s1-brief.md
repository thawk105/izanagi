## 不変条件 (実測で確定、攻撃対象ではない)

1. **`DW-O01` の `` `<model>`: `` 行、`DW-S06-A` の `reasoning=high` 行、`DW-S06-C` の
   `reasoning=high` 行は機械権威**である。`tools/dev_waves/launch_authority.py` が
   `_MODEL_LINE_RE` / `_REVIEW_EFFORT_LINE_RE` / `_FOCUS_EFFORT_LINE_RE` で逐語解析し、
   節全体の sha256 を `AuthoritySection` として起動 receipt / manifest に束縛する。
   **これらの行および節見出しは削除も語順変更も不可。**
2. `snapshot_authority` は `commit=None` (live) のとき
   `docs/dev-wave/operations.md` と `docs/dev-wave/workers.md` の working tree と
   authority commit を **byte 比較**し、差があれば `AuthorityError` で fail-closed する。
   → **この 2 ファイルを編集した時点で codex 子は一切起動できなくなる。**
   段 2・3 の子は編集前に投入し、編集後に子を要するなら先に commit する。
3. 正しさゲート・観測者効果・信頼境界の絶対規律は不変。予算のために規律文言を落とさない。

## 成果物の形

1. 全 L1.5 / L1 節の**義務単位**の棚卸し表 (節 → 義務 → 機械代替の有無 → 発火実績 → 判定)。
2. 削除候補一覧 (実測根拠付き) = ユーザーへ返す 1 回の裁定パッケージ。
3. 測定が明白に支持する範囲での実施 (テスト化を含む) と、そこで空いた bytes への候補反映。
4. worklog fragment (docs-only なら受入免除判定の証拠 1 行を含む)。

## 判断が割れうる前提 (親の provisional 裁定であり攻撃対象)

- **(P1)** 「発火実績なし × 機械検査で義務代替済み」の両方が真の節だけが無条件削除可で、
  片方だけの節は裁定パッケージへ回す。
- **(P2)** テスト化 (義務を機械検査へ移して散文を削る) は「意味を変える縮約」に当たらず、
  個別承認なしに実施してよい。ただし新設 gate は `DW-O13` に従い入力の実在を先に確認する。
- **(P3)** L0 入口の余白 0 は、L1/L1.5 と独立した第 4 の閉塞であり、[T-934] (a) は
  入口の陳腐化行を削らない限り実施不能である。
- **(P4)** 機械権威 3 行に隣接する散文も、regex が節境界の sha256 を取る以上、
  編集すると authority digest が変わる。digest 変化は wave を跨いで pin されていない
  (manifest は wave 単位) ため、編集自体は許される。
