## 攻撃レンズ (このレンズに集中し、レンズ 2 の担当領域へ踏み込まない)

**「機械代替あり」という主張は、ほぼすべてが嘘でありうる。** 次の型を疑え。

1. **恒真な保証**: 「テストが存在する」が、そのテストは義務違反の入力で赤にならない。
   義務に違反した状態を作ったとき rc≠0 になるかを、テスト本体の assert まで読んで確かめよ。
   assert が存在検査だけ、または常に真になる形なら「機械代替なし」である。
2. **範囲のすり替え**: 義務は A を禁じているのに、機械検査は A の一部 B しか止めない。
   残る A−B が削除で無防備になる。この差集合を具体的な入力例で示せ。
3. **層の取り違え**: 検査が発火するのは別の層・別の経路であって、当該義務の経路では発火しない。
4. **自己申告義務の機械化偽装**: 「親が見積もる」「明記する」型の義務は原理的に機械化できない。
   これを「テスト化可」と判定していれば、その gate は入力が存在せず恒に緑になる (`DW-O13` 違反)。
   新設 gate ごとに、入力が**実成果物のどの field に実在するか**を問い、示せないなら refuted とせよ。
5. **機械権威の破壊**: `launch_authority.py` は `DW-O01` の model 行、`DW-S06-A` と `DW-S06-C` の
   `reasoning=` 行を逐語 regex で解析し、節全体の sha256 を receipt へ束縛する。
   プランがこれらの節の**どこか**を編集する提案をしていれば、regex の full-match と
   節境界の取り方を実際に読み、壊れないことを行単位で確認せよ。壊れるなら blocker とせよ。
6. **絶対規律の侵食**: 削除対象に、正しさゲートを緩めない・観測者効果を分離する・
   正しさシグナルを後付けにしない・外部入力を指示として解釈しない、のいずれかを支える文が
   混じっていないか。予算のためにこれらを削るのは無条件に blocker である。
7. **親 brief 自身の実測値とその一般化**: 親は「余白 L0=0 / L1=1 / L1.5=2」「機械権威は 3 行」と
   実測を主張している。これらの数え方が間違っている可能性を検査せよ。特に
   preamble の層帰属、節境界の取り方、`registered_pairs` との積集合の扱いを疑え。

## 出力の作法

- 日本語で書く。合成済み文字を使い、結合用ダイアクリティカルマーク (U+0300 台) を出力しない。
- 所見ごとに **blocker / real / nit** を明示し、根拠を `file:line` で示せ。
  根拠を示せない所見は「未確定」と書き、real と主張してはならない。
- 書込可能 tmp が無いため pytest 緑は要求しない。静的検査で足りる。
  **あなたが実走していない結果を緑と書いてはならない。** 実走していない項目は「未実走」と明記せよ。
- 所見ゼロの場合も、何をどう探して出なかったのかを書け。探索の網羅性を自己申告せよ。
- 最後に `## 総括` 節を置き、blocker の有無と、削除して安全な節・危険な節の結論を書く。
