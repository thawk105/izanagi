## 直す対象 (親が実測した事実)

`orchestrator/tests/test_codex_worker_launch.py::test_sigterm_ignoring_child_is_killed` が
**repo 全走 (pytest-xdist 並列・高負荷) でのみ**落ちた。

```
FileNotFoundError: [Errno 2] No such file or directory:
  '/dev/shm/pytest-of-tanab/pytest-689/popen-gw5/test_sigterm_ignoring_child_is0/pids/child.pid'
```

親の再現実測:

- 単独実行 3 回: いずれも 1 passed
- 同ファイルを `-n 8` で 2 回: いずれも 58 passed
- repo 全走 (約 3,800 test の並列): 1 failed

原因: このテストは `max_wall="0.25"` (wall-clock 上限 0.25 秒) で走らせるため、
高負荷時には **fake の子が `child.pid` を書き終える前に** launcher が上限へ到達して
process group を停止する。その後テストは `(paths["pid_dir"] / "child.pid").read_text()` を
**無条件に**読むため FileNotFoundError になる。

同じファイル内の別テスト (`child_pid_path.exists()` を deadline 付きで待つ箇所、
現行 255-260 行付近) は既に正しい待ち方をしている。**その型に合わせよ**。

## 要件

- テストの**検出力を落とさないこと**。この test は「SIGTERM を無視する子が KILL されること」を
  検査しており、その assert (`_assert_pid_gone`) を削除・緩和してはならない。
- pid ファイルの出現を bounded deadline で待つ、あるいは子の pid 登録が上限到達前に
  必ず完了するようにする。どちらでもよいが、**上限到達で停止したこと自体の検査
  (`stop_reason == "max_wall_clock_s"`、`limit_trigger`、`process_group_residual == 0`) は保持**する。
- pid ファイルが deadline 内に現れない場合は、黙って skip せず**明確に失敗**させること
  (fail-open にしない)。
- `time.sleep` の固定待ちを増やして誤魔化さない。負荷に強い待ち方にする。
