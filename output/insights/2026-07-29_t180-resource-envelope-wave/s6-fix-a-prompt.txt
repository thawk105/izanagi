## 直すもの (裁定表で単位 A のもの)

1. **A-1**: 累積 usage の巻き戻しで上限を迂回できる。観測した `cli_reported` / `model_calls` の
   **running max を latch** し、後から小さい累積が来ても超過の事実を消さない。
   累積が非単調なら `metering_status="inconsistent"` として非採用にする。
2. **A-2**: `token_count` の `info=null` を「観測した event」として数える。
   1 件でもあれば metering は不完全として**非採用**にする
   (`observed_token_count_events` という名乗りと整合させる)。
3. **A-3**: `check-receipt` が sealed artifact から actuals を**再計算**し、receipt の自己申告と
   突き合わせる。`--expect-prompt-sha256` / `--expect-max-*` 等の外部期待値 option を足し、
   外部期待値なしのときは「limits は self-asserted である」ことを出力と receipt に明示する。
   **外部期待値なしで limits 改竄を検出できるとは主張しない**。
4. **A-4 (限定)**: seal 時の `rollout_sha256` と `rollout_bytes` を receipt に記録し、
   `check-receipt` は rollout が seal 後に伸びていれば `rollout_grew_since_seal: true` を明示する。
   ledger を receipt に合わせて EOF 未満で止める変更は**しない**。
5. **A-5 / B-7**: `/proc` の scan 失敗・個別読取失敗・`read_pid_identity()` 失敗を
   「residual=0」に落とさない。**unknown は fail-closed** とし `termination_verified=false`、
   その attempt は accepted にしない。
6. **A-7 / B-2**: wall-clock の計測を launcher process の開始時点から始め、
   output 公開・receipt 書込み・self-check も含める。receipt に
   `wall_clock_scope: "launcher_process"` を記録し、`setsid()` 脱出子まで覆う保証はないことを
   docstring と receipt の既存 `escaped_process_containment` で正直に表す。
   「job 全体の hard cap」という表現をコード・help・docstring から外す。
7. **A-8**: 完全 receipt の create-only を TOCTOU なしにする。temp を書いてから
   `os.link(temp, final)` のような**原子的 create-only** で公開し、既存があれば失敗させる。
8. **A-9 (bounded)**: `--cwd` が `--repo-root` 配下であること、`--base-commit` が当該 repo に
   実在すること (`git cat-file -e` 相当) を検査する。`check-receipt` は manifest header の
