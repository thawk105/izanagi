## 2. b = 1000 µs が測定不能である理由 (F718 の符号化を現物で確認)

`patches/silo-backoff-fixed.patch` の合成枝は、供給された値を単一の量として扱わない。
`q = BACKOFF_FIXED / 1000`、`r = BACKOFF_FIXED % 1000` として次の 4 分岐になる。

| 条件 | `now_backoff` | 意味 |
| --- | --- | --- |
| `q == 0` | `BACKOFF_FIXED` | 固定値 (真の静的) |
| `q == 1` | `(r + (coin ? 2r - X : X)) / 2.0`、`X = hash % (2r+1)` | symmetric-modulo 乱択 |
| `q == 2` | `(r + coin * 2r) / 2.0` | binary 乱択 |
| それ以外 | `r` | 剰余のみ |

- **b = 1000 は `q=1, r=0`。** `X = hash % 1 = 0` なので分岐のどちらを取っても 0 になり、
  `now_backoff = (0 + 0) / 2.0 = 0`。**厳密に 0 µs を測る。**
- **b = 999 は `q=0`。** 静的 999 µs として正しく表現できる。
- **b = 750 も `q=0`。** 静的 750 µs として正しく表現できる。
- **この符号化では静的値の上限が 999 µs である。** 1000 以上は必ず乱択モードへ落ちるので、
  「静的 1000 µs」は原理的に表現できない。最近傍の表現可能点は 999 µs (差 0.1%)。
- 既存格子の 150〜900 はすべて `q=0` なので、**真の静的 `T(b)` として正しく測られている。**
- 3 分岐は B-10 の待ち方 campaign が使う `constant` / `symmetric-modulo` / `binary` の
  wire そのものである (`docs/b10-backoff-shape-preregistration.md`)。
  **符号化を変えるとその campaign が壊れる。** F718 が修正を別 wave へ送ったのはこのためと読める。

### 2.1 既存の binary 同一性検査はこの型を捕まえない

`orchestrator/campaign/backoff_extended_sweep.py` の
`_require_distinct_static_binary_hashes` は「異なる `BACKOFF_FIXED` が同じ binary を作ったら失敗」
を要求する。b = 1000 と b = 0 は `-D` の値が違うので**別の binary になり、この検査を通過する。**
通過したうえで意味だけが 0 µs と同じになる。F718 の
「供給され、適用され、検査も通る。違うのは値の意味だけ」がここで裏づけられた。

## 3. 依頼の目的はどこまで閉じ、どこが閉じないか

段 3 の 2 レーンが別レンズで検算し、次のように割れた。

- **閉じる (real):** 「谷に届く静的 tail が存在する」は外挿なしで閉じる。
  write-heavy の 560 µs = 1,252,136 tps と 600 µs = 1,218,351 tps が、
  適応側の谷 1,241,671 tps を**両側から挟んでいる。**
  750 の欠測はこの存在証明を崩さない。700・800・900 まで滑らかに低下している。
- **閉じない (refuted):** 依頼が挙げた 6 点の完全取得と、機序の閉鎖。
- **判定できない:** 歩行 model を実測 tail で再計算しきること。
  **有効な 901〜1000 µs の点と rep 単位の abort 率が無い。**
  歩行 model の格子は 1000 µs まで到達しうるのに、その領域に有効点が 1 つも無い。

### 3.1 旧 model の指数外挿と実測の乖離

| b (µs) | 旧指数外挿 `T` | B-10 実測 `T` | 比 |
| --- | --- | --- | --- |
| 150 | 1.902 M | 2.048 M | 1.08 倍 |
| 200 | 1.538 M | 1.849 M | 1.20 倍 |
| 500 | 0.429 M | 1.305 M | 3.04 倍 |
| 900 | 0.078 M | 1.035 M | 13.21 倍 |

**旧 model は tail を大きく過小評価していた。** 刻み 25 µs の旧 model は
`P(Backoff_ > 100 µs) = 3.8%` なので、滞在重みを固定した単純混合なら
tail 差し替えの寄与は最大でも `0.038 x 0.964 M = 0.037 M tps` である。
旧予測 2.860 M を観測 1.242 M へ近づけるどころか**わずかに上げる方向**であり、
**「素直な滞在説では足りない」という T-2216 の否定的結論はむしろ強まる。**

ただし完全な予測方向は判定できない。`T` と abort 率は leader 周期と遷移確率にも入るため、
差し替えると滞在分布そのものが変わる (`tools/t2216_backoff_walk_model.py`)。

## 4. 本 wave が実装したもの

依頼は「同一ビルド・同一 job 割付けで測る」という**測定行為**を要求している。
既測 4 点は別 job・別時刻の値なので、そのまま 750 と繋ぐと継ぎ合わせになる。
したがって既測 4 点も含めて 1 job 内へ並べ直す opt-in mode を、既存 B-10 経路へ足した。

- 格子は `none` + `adaptive` + 固定 {150, 200, 300, 500, 750, 999} の **exact 8 点**。
  固定 0 は no-backoff ではないので baseline に使わない。
  **`adaptive` を同じ job に入れる**ことで、これまで別 job (`0:966801.nqsv`) 由来だった
  谷との比較の継ぎ合わせも消える。
- **要求集合と実現集合を別項目にした。** 999 を 1000 の測定値として扱わない。
  1000 は F718 の理由つきで未実現として保持する。**「6 点完了」とは書かない。**
- **rep 単位の throughput と abort 率を全 rep 分保存する。** 既存成果物は
  throughput が中央値、abort 率が代表 1 rep だけで、§3 が「判定できない」とした
  rep 単位 abort が失われていた。**これが本測定の主目的の一つである。**
- 既存 `EXTENDED_SWEEP_US` と `SWEEP_US` は 1 bit も変えていない。前者は着地済み図 2c の
  campaign identity を、後者は S1 freeze の source hash を決めるためである。
- 新しい Pegasus path を作らないので `tools/pegasus/admission_registry.json` は無変更。
  既存 B-10 grid の job body と submitter に run kind を足し、既定は現行のまま挙動を変えない。

## 5. 確定していないこと

- **測定はまだ走っていない** (本 wave 時点)。§1〜§4 の数値はすべて既存測定の再解析である。
  **2026-09-07 に [T-2320] wave が投入し完走した。結果は §8 にある** — 750 と 999 は初測定、
  既測 4 点は 0.5% 以内で一致、rep 単位値も取得済み。以下の §5 の残りは §8 の後も有効である。
- **機序は確定していない。** §3 は既存 28 点で「谷に届く tail の存在」を閉じるが、
  滞在分布・遷移損失・スレッド同調・履歴依存・leader 固有 abort・窓内 commit 分布は
  いずれも未観測である。これらは診断ビルドによる直接観測 ([T-2265]) が要る。
- **混合仮定そのものは検証していない。** 静的 tail は「動的に `Backoff_` = b にいるときの性能が
  固定 b の静的性能に等しい」という仮定を検証しない。
- **真の固定 1000 µs は現符号化では取得できない。** 999 で代替しても
  「6 点を測った」ことにはならない。
- すべて単一環境 (Pegasus 48 物理コア) である。

### 8.3 読み取れること・読み取れないこと

- **静的 tail は 999 µs まで単調に下がり続け、谷は無い。** 3 workload とも 150 → 999 で throughput は
  単調減少 (write-heavy 2.06 倍、balanced 2.20 倍、read-heavy 2.23 倍の低下)、abort 率も単調減少である。
  §3 が既存 28 点で閉じた「谷に届く tail の存在」は、750 と 999 の初測定でも覆らない。
- 静的 6 点の rep 間ばらつきは小さい (cv 0.12〜0.62%)。**非静的 2 点は大きい** (write-heavy の none は
  cv 3.9%、balanced の adaptive は 3.3%)。1 本の rep で代表させると誤差が乗る。
- **abort 率の代表値は中央値 rep 1 本である** (§1.2)。本節の rep 列があるので、必要なら平均へ再集約できる。
  静的 6 点では平均と代表値の差は 0.1% 未満だが、write-heavy の adaptive では代表 0.1230 に対し
  平均 0.1233、範囲 0.1173〜0.1285 と幅がある。
- **機序は本測定でも観測していない。** 滞在分布・遷移損失・スレッド同調は未観測のままで、
  診断ビルドによる直接観測 ([T-2265]) が要る。
- **1000 µs は測定していない。** 999 での代替は F718 の符号化制約によるもので、依頼の 6 点目ではない。
- 本測定に至るまでに driver 側の欠陥を 1 つ直した (凍結 view の型変換と rep 突合の不一致)。経緯は
  `output/insights/2026-09-07_t2320-backoff-sweep-gate-layer2/README.md` §6。
