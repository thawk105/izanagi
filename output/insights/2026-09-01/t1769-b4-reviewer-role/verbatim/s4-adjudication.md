## 追加実測 (相談の未確認点を親が閉じた)

1. **whole-file binding は現時点で存在しない。** production module
   `orchestrator/campaign/p3_b4_admission_record.py` は record の repository path を driver 種別ごとの
   exact 3 path に固定し、一致しなければ拒否する
   (`_REQUIRED_ADMISSION_RECORD_REPOSITORY_PATH_BY_DRIVER`、消費側で照合)。
   その 3 path (`docs/phase3-b4-reflux-ablation-admission-record-{base,sort,trigger}.json`) は
   `git ls-tree -r HEAD` にも作業木にも 1 件も無い。よって文書全文を束縛する active な record は無い。
2. **文書の全文 hash はどこにも作られない。** `p3_b4_analysis_path.py` の
   `_generate_analysis_source_closure_receipt` は受け取った全文 bytes を
   `preregistration_section_5_1_1_bytes()` へ通し、切り出した §5.1.1 の sha256 だけを receipt へ載せる。
   `_SOURCE_CLOSURE_PATHS` の member は Python source 5 本だけで、文書は member でない。
3. **D1266 を上書きする後続裁定は無い。** `docs/decisions.md` を「記入者」「レビュー者」「独立検査者」
   「兼任」「D1266」で検索した。D1266 以降に本主題を扱う決定は無く、他の「独立検査者」hit は
   認定・variant hidden case という別主題である。

## 不変条件 (差分適用時に守る)

- `## 5.` 行と `### 5.1` 行は各 1 個のまま。新見出し・fence・HTML コメントを足さない。

## ユーザーへ返す裁定パッケージ (本 wave では実装しない)

1. **§10 の残件記述の更新。** §10 は「残るのは (i) の先行 freeze — 候補集合…記入者とレビュー者 —
   であり、人間の指名を含むため AI が確定できない」と書く。本 wave で記入者・レビュー者が
   D1266 に基づき確定したので、この**理由の説明**は不完全になる。残件の存在自体は真のまま。
   §5.1 に scope を切ったため本 wave では触らない。別変更単位で更新するかを諮る。
2. **レビュー者の履行を観測可能にするか。** 相談 A は「確認時点・項目別確認・確認事実の記録」を
   足すべきだと主張した。D1266 は役割定義文の中身を裁定済みで、追加は非同値な義務の新設になる。
   足すか否かはユーザーの裁定事項とする。足さない場合、レビュー者の履行は外形上観測できない
   状態が残る (D1266 が受容した制約の範囲内かどうかが論点)。
