# 逐語の可逆最小正規化 (2026-09-01)

`DW-S07` は「逐語末尾空白の `git diff --check` 抵触時も、原文 hash・byte 数・復元法を
記録した可逆最小正規化だけを許す (可視文字不変)」と定める。本 wave で 1 file に適用した。

## 対象

`s6-review-b-call-closure.md` (段 6 敵対レビュー B の逐語)。

| 項目 | 値 |
|---|---|
| 原文 SHA-256 | `1fff1ad14bdaeda567b049bbca5c6afd4ba8702dec0d62ac20590972900913de` |
| 原文 byte 数 | 8792 |
| 正規化後 SHA-256 | `acc52e5e7c469f0188604ec52396d2a6ad72ad2440028d2160a80b4deba73bd2` |
| 正規化後 byte 数 | 8764 |
| 差 | 28 byte |
| 影響行数 | 14 行 |

## 何をしたか

各行の末尾の空白文字 (space / tab) を除去した。子の出力は markdown の
「行末 2 空白 = 改行」記法を使っており、その 2 空白が 14 行に付いていた。
**可視文字は 1 文字も変えていない。** 28 byte = 14 行 x 2 空白 で一致する。

## 復元法

正規化後の file の該当 14 行 (箇条書きの項目行と、その継続行のうち末尾で改行を
意図している行) の行末へ、それぞれ半角空白 2 個を戻すと原文の SHA-256 に一致する。
機械的には、`s6-review-b.md` の原本が repo 外の
`/work/1/SFC/tanab/dev-wave-jobs/2026-09-01_t2027-root-class2/artifacts/dev-wave-t2027-root-class2/`
に残っている間はそこから取れる。

## なぜ正規化したか

`git diff --check` が trailing whitespace で非 0 を返し、受入形の検査を通らない。
逐語を捨てる、または内容を要約する選択は取らず、可視文字を変えない最小の正規化に留めた。
