## 3. 入庫できなかった 6 件 — 審査結果と引き上げ可否

**総括: 予算値の引き上げは推奨しない。**理由は次の 3 つである。

1. 本 wave は L1 で 49、L1.5 で 213、2 command で 326 bytes を意味等価な縮約だけで空けた。
   その全量を使い切ってなお 6 件が入らないのは事実だが、**縮約の余地が尽きた証拠にはならない**。
   段 2 のプラン、段 3 の 2 レンズ、親の実測のいずれも、
   「発火実績なし × 機械検査で義務代替済み」を両方満たす削除候補をゼロ件しか出せていない。
   これは棚卸しが不十分だったのではなく、**現行の L1/L1.5 が実際に生きた義務で埋まっている**ことを示す。
2. 入らなかった 6 件はいずれも**実害の頻度が低いか、代替の記録が既にある**。
   引き上げの費用 (全 wave の毎回の読み込み量が恒久的に増える) に見合わない。
3. [T-789] の起票文自身が「予算値の引き上げは自己改善に含めない規律であり、
   dev-wave 系への外出しは D94 で却下済みなので、**陳腐化した既存節の特定と等価縮約が審査の対象**」
   と定めている。本 wave はその審査を実施し、等価縮約を出し切った。

## 4. 裁定へ返す新規事項

### R-1 — [T-773] の結線は docs 層までで、runtime 層は未閉包 (段 3 両レンズが独立に指摘)

新設した機械検査は「命令上の参照が実在する」ことを保証するが、
**manager が実行時に本当にその script を呼んだこと**は保証しない。
`tools/dev_wave_wait.py acceptance` は `--` 以降に任意の child command を受け取り、
invocation receipt を発行しない。したがって文書に canonical literal を置いたまま、
実行時には旧来の手書き待ち手を呼ぶ wave を機械的に検出できない。

- 選択肢 = (a) 待ち手に invocation receipt (stage・wave・argv・script digest の束縛) を発行させ、
  段 7 の記録検査で照合する / (b) docs 層の束縛で留め、実害の再発を待つ。
- 成果物影響 = (b) のままなら F32 族 (自己マッチ死、独立 2 例、実測 20 時間 23 分 + 7 時間 36 分) の
  再発経路が runtime 側に残る。
- 親の推奨 = **(a) を別 wave で起票**。本 wave の scope (docs 予算棚卸し) を超え、
  `DW-G04` の発火 gate も本 brief には書けなかったため実装しなかった。

### R-2 — [T-765] は予算ではなく安全の問題として差し戻す

`DW-S04` の変異免除を「実装しないと裁定した wave」から「実装差分ゼロの全 wave」へ広げる案は、
byte 上は入る (置換自体が -30) が、**変異検査の免除範囲を実際に広げる**。
段 3 レンズ A が blocker 判定し、段 2 のプラン自身も非等価と認めた。

- 選択肢 = (a) 免除を「実装差分ゼロの wave」へ一般化する / (b) 現行のまま曖昧さを残す /
  (c) 曖昧さだけを解く別表現を探す。
- 成果物影響 = (a) なら、docs-only の予算 wave が否定変異や consumer 検査なしで完了できるようになる。
  本 wave 自身がその第一号になりえた。
- 親の推奨 = **(c)**。曖昧さの解消は必要だが、免除拡大とは分離すべきである。

### R-3 — [T-788] は docs でなく機械検査で閉じるべき (上表の再掲)

制御 byte の混入は「artifact を作る側で機械的に除去する」のが本筋で、
入口の義務として書くと L1.5 を 110 bytes 恒久的に消費する。
- 親の推奨 = **新規タスクとして tool 側の検査を起票**し、`DW-O02` への追記は取り下げる。

## 5. 予算引き上げの可否 (求められた審査結果)

**推奨 = 引き上げない。**上記 §3 のとおり、入らなかった 6 件のうち
2 件は別解 (機械検査化・運用) で閉じられ、2 件は実害が `DW-G03` の独立 2 例に届かず、
1 件は本 wave の結線で不要化し、1 件は再訪条件が未成立である。
**引き上げを正当化する「実害が大きく、かつ縮約でも別解でも閉じない候補」は 1 件も残らなかった。**

再訪条件を明示する: 次のいずれかが成立したら L1.5 の引き上げを独立審査へ戻す。

- [T-789](2) と同型の「必読 path 不在によるレビュー空費」が 2 例目に達したとき
- 機械検査化で閉じられない義務が、実害の独立 2 例つきで 2 件以上滞留したとき
