## このレンズの担当

**テストの検出力、変異の帰属、回帰面。**

必ず検討する攻撃面:

1. **生き残る弱実装**: このテスト集合をすべて通しながら、段 4 裁定の不変条件を破る実装を
   具体的に構成せよ。少なくとも次を試せ — CR だけ検査して LF を落とす、`in` を `endswith` に
   狭める、最初の 1 件で止める / 最後で上書きする、走査を既知 schema 位置に限る、
   root や深い入れ子を落とす、`is_path` を dict の子へ誤伝播する、
   detail に node を載せる、検査を canonical 化の前へ動かす。
   殺せない変異があれば、どのテストが不足かを file:line で言え。
2. **変異の帰属**: 段 4 裁定 F 節の変異 M1〜M12 それぞれについて、期待 kill node が実際に
   その変異でだけ落ちるか。別の原因で落ちる、前段 gate に先取りされて後段の診断が
   置き換わる、といった帰属不成立の系列を探せ。
   期待 node の**過不足**は harness が MISMATCH にするので、集合の抜けも指摘せよ。
3. **回帰面**: この差分で赤くなりうる既存テストを repo 全体から列挙せよ
   (`orchestrator/tests/` 以外も見る)。共有 fixture・helper の一般化で
   NUL 側の既存テストが壊れていないかを特に見よ。
4. **恒真・自己整合**: 期待値を production の派生関数から取っているテスト、
   実装と同じロジックを書き直して比較しているテスト、揮発値を焼き込んだ期待値が無いか。
5. **裁定との突き合わせ**: 段 4 裁定 B 節の F1〜F7 のうち、テストとして実在しないもの、
   あるいは名前だけで中身が要件を満たさないものを名指しで挙げよ。
6. **T-739 資産の非破壊**: `output/insights/2026-08-11_t739-freeze-nul/` が 1 byte も
   変わっていないことを確かめよ。

## 制約

- sandbox は read-only。pytest の実走は不要で、静的検査でよい。実走は親が行う。
- テストを弱める提案、期待値を実装に合わせる提案はしない。
- 各所見に「これを直さないと成果物 (凍結台帳・proof chain・certified 選択) のどの値・受理集合・
  参照がどう変わるか」を 1 行で付ける。書けない所見は nit と自己申告せよ。
- 結論は GO / NO-GO のいずれかを明示する。
- 出力の最後に `## 総括` 見出しで要点を 10 行以内にまとめる。
