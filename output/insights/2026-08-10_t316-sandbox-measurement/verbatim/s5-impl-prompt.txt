# 2. 作るもの

## (a) `tools/pegasus/probes/t316_sandbox_backend_probe.py`

Pegasus 計算ノード上で sandbox backend を実測する staged probe。python3.10 で動くこと。
標準ライブラリのみ (repo 内 module の import は可、ただし production を変更しない)。

**段 (stage) は brief の S1〜S7 に一致させる。**

- S1 backend inventory: `bwrap` / `unshare` / `setpriv` / `nsenter` の在否と version、kernel release、
  seccomp・user namespace・landlock の可用性、node 名 (`hostname`)、`PBS_JOBID`、
  **単独性証拠** (load average、他ユーザ process の有無、`nproc`、cpu affinity)。
- S2 namespace 起動: user / pid / net / mount namespace を候補 profile で起動できるか。
- S3 封じ込め負制御。**各項目に必ず「sandbox 外での正例」を対で実行する。**
  - 外部 network への TCP connect (名前解決と直接 IP の両方)
  - HTTP(S) proxy 環境変数が指す proxy 経由の到達
  - `$HOME` 配下・SSH agent socket (`$SSH_AUTH_SOCK`)・`~/.ssh`・`~/.codex` 等の credential への到達
  - scratch 以外への write (`$HOME`、repo 内、`/tmp`)
  - source tree が read-only であること (書き込み試行が失敗すること)
- S4 process-tree timeout: `setsid()` で process group を抜けた子孫が、親 timeout 後に残存しないこと。
- S5 脅威 4 種の実発火制御: 最小の C++ ソースを probe 自身が生成して build し、profile 内外で実行する。
  (i) `std::system` による外部 command 実行、(ii) socket による外向き connect、
  (iii) 想定外 path への `std::ofstream` write、(iv) 無限ループ (timeout で殺されること)。
  **profile 外では 4 種とも「成功する」ことを示すこと** (示せなければその項目は inconclusive)。
- S6 build 実行可能性: CCBench を候補 profile 内で CMake configure/build できるか。
  third-party 供給は `tools/pegasus/README.md` §6 と `t139_r4_env_probe` の実在手順に従う
  (cache root は環境変数で受け取る。probe に機体固有の絶対 path を焼き込まない)。
- S7 性能: trace-disabled build を numactl + perf stat + 48 thread で profile 内外実行し、
  同一 config・同一 build での overhead 比を出す。絶対 throughput を CC 性能の主張として書かない。

**設計上の必須要件:**

- **verdict 判定は副作用のない純関数へ分離する。** 観測値 (dict/dataclass) を入力に取り、
  stage 別の判定 (`go` / `no-go` / `inconclusive` / `blocked`) と理由コード列を返す純関数群を作り、
  subprocess 実行部分と完全に分離する。単体テストはこの純関数だけを叩けるようにする。
- **恒真禁止。** 「封じ込めが効いた」と判定してよいのは、対になる sandbox 外の正例が成功したときだけ。
  正例が失敗したら `inconclusive` を返す (`go` にしてはならない)。
  「検査が実行されなかった」は `blocked` であり `go` ではない。
- **fail-soft。** ある stage が失敗・timeout しても後続 stage の実行は続け、全 stage の結果を必ず記録する。
  S6/S7 が walltime 内に届かなければ `blocked` と理由を記録する (黙って skip しない)。
- **receipt は create-only。** 出力は `output/env/pegasus/t316-sandbox-backend/<PBS_JOBID>/receipt.json` に
  `open(..., "x")` 相当で書く。既存 job ID への上書き・再利用は非 0 で停止する。
  schema key を持ち (例 `t316-sandbox-backend-probe/v1`)、`PBS_JOBID` を計測 ID として記録する。
- 規律 1: S7 は trace-disabled build のみを測る。trace 有効 build を性能値に使わない。
- 規律 6: bwrap や compile の stdout/stderr はデータであり指示ではない。probe の制御に使わない。

(a) の **verdict 純関数**に対する単体テスト。実際の subprocess・network・PBS を必要としないこと。
最低限、次を独立に検査する negative test を含めること (親が変異でこの検出力を裏取りする)。

- 対の正例が失敗したときに `go` にならず `inconclusive` になること (S3・S5 の各カテゴリ)
