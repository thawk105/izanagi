# 2. 直すもの

## G1 (blocker、第 2 巡の regressed) — `DENIED` sentinel 後の timeout・異常終了が `go` になる

`_parse_payload_sentinel()` は `executed` と stdout しか見ず、`timed_out` と `rc` を検査しない。
`_paired_command()` はその `denied` をそのまま `inside_blocked=True` にし、`_paired_verdict()` が `go` にする。

```text
outside: REACHED, rc=0
inside:  DENIED|ENETUNREACH, timed_out=True, rc=-9   → 現状 go
```

**処置:** 封じ込めと認めるのは、inside が
(a) sentinel を出し、(b) `timed_out is False` であり、(c) payload が自分で定義した
**正常終了 rc の閉集合**で終わったときだけとする。
timeout・signal 死・想定外 rc・sentinel 後の teardown 失敗は **`inconclusive`** にせよ (`go` にしない)。
第 1 巡の裁定「sentinel が無い・parse できない・payload が起動していない場合は inconclusive」も維持せよ。

## G2 (blocker) — `denied` の errno 集合が封じ込め原因に限定されていない

現状は `ENOENT`、`ECONNREFUSED`、`ETIMEDOUT`、`EAI_AGAIN`、`EAI_NONAME` を一般集合として受理し、
S5 の `std::system` は errno ですらない一括値 `COMMAND_FAILED` を受理する。
これらは path 誤り・endpoint の一時障害・DNS 障害・tool 欠落でも生じ、封じ込め固有ではない。

**処置: カテゴリごとに狭い契約を持て。** 少なくとも次の区別を実装せよ。

- **network connect (直接 IP)**: 封じ込めと認めるのは `ENETUNREACH` / `EPERM` / `EACCES` /
  `EAFNOSUPPORT` 等、**経路が存在しないことを示す errno** に限る。
  **`ECONNREFUSED` は「到達した」証拠なので封じ込めではない (`no-go` 側)。**
  `ETIMEDOUT` は封じ込めと外乱を区別できないので `inconclusive`。
- **DNS**: `EAI_AGAIN` / `EAI_NONAME` を認めてよいのは **DNS カテゴリだけ**とする。
- **write**: `EROFS` / `EACCES` / `EPERM` に限る。**`EEXIST` と `ENOENT` は封じ込めではない。**
- **credential / socket の不可視化**: このカテゴリに限り `ENOENT` を封じ込めとして認めてよい
  (bind されていない = 見えない、が封じ込め機序であるため)。
  ただし**同じ path に対する sandbox 外の正例が成功していること**を必須条件にせよ。
- **`std::system`**: 一括値をやめよ。payload は
  「shell が存在せず exec に失敗した (= 封じ込め)」と「shell は動いたが command が失敗した
  (= 封じ込めではない)」を区別して報告せよ。**副作用の有無 (marker が書かれたか)** も併せて観測し、
  副作用が観測されたら `no-go` にせよ。

**どの errno をどのカテゴリで封じ込めと認めるかを、コード内の 1 箇所の表**にまとめ、
テストがその表を独立の literal と突き合わせられるようにせよ。

## G3 (must-fix) — identity 解決不能時に setsid 済み無限子孫を清掃できない

`_cleanup_exact_process()` は host PID を解決できないと何もせず戻る。
outside 正例と inside の双方で、無限 loop の子孫が allocation に残りうる。

**処置:** identity が解決できない場合の最終手段の清掃経路を設けよ
(自分が起こした payload だけを対象にすること。他 process を巻き込まない)。
清掃できなかった事実は観測に記録し、**S7 の性能測定より前に残存を検出したら
性能観測を `inconclusive` にせよ** (残存 loop は測定を汚染する)。

## G4 (must-fix) — `COMPLETED` marker が非原子的、完成状態の契約が未固定

- `COMPLETED` を receipt と同じ create-only + 原子的 publish 機構で書け
  (この機体の `/work` では `renameat2(RENAME_NOREPLACE)` が EINVAL、`os.link` は成立する)。
- final receipt に明示的な完成印 (例 `state: complete`) を持たせよ。
- 完成後に `PARTIAL.json` をどう扱うか (削除するか、完成印付きで残すか) を決めて実装せよ。
- **consumer 契約を receipt 自身に書け**: 「この測定が完了しているとみなす条件」を
  1 つの機械可読な述語 (`COMPLETED` の存在 + receipt が parse できる + `state == complete`) として固定せよ。

## G5 (must-fix) — テストが実 observer を迂回しており、次の変異が緑のまま通る

主要な結線テストが `observer_runner` で実 observer を丸ごと迂回している。
**次の変異が必ず赤くなるようにテストを追加せよ** (親が同じ変異を harness で実走する)。

1. `_poll_pid_identity()` の結果を常に `gone` にする
2. `_observe_descendant_control()` / `_observe_binary_descendant()` の inside status を `gone` に固定
3. `_parse_payload_sentinel()` が `ERROR` や `ENOSYS` を `denied` として扱う
4. S3 / S5 の write observer が inside state を `denied` に固定する
5. **`DENIED` sentinel + `timed_out=True` / `rc!=0` を受理する** (= G1 の回帰そのもの)
6. network の `denied` 集合に `ECONNREFUSED` を足す (= G2 の緩和)

そのために、**実 observer が使う command 実行部へ注入 seam** を設け、
偽の subprocess 結果 (rc、stdout、timed_out) を流し込んで観測から判定までを通す
テストを書け。実 network・実 bwrap・実 PBS 無しで成立させること。

## G6 (must-fix) — R3-1 coverage が実 verdict と非連動

`r3_1_coverage` の discharged 一覧が静的 literal で、実際の stage verdict と連動していない。
**discharged は実 verdict から導出**し、当該 stage が `go` でないなら discharged に入らないようにせよ。
未 discharge 項目 (stock/variant 性能差、trace 実行、floor 再較正要否) の明示は維持せよ。
