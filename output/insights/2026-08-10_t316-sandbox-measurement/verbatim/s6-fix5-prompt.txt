# 直すもの

## H1 — write カテゴリの「不可視化による封じ込め」を計上できない (非対称の是正)

実測値:

```
S3.write_home:            outside=REACHED (正例成立) / inside=DENIED|ENOENT → invalid → inconclusive
S5.runtime.file_write:    outside=REACHED (正例成立) / inside=DENIED|ENOENT → invalid → inconclusive
S5.build.file_write:      同上
S3.write_repo, write_tmp, source_read_only: contained (EACCES/EROFS 経路)
```

内側の `ENOENT` は「その path が sandbox 内に存在しない」= **不可視化による封じ込め**である。
資格情報カテゴリでは既に `_INVISIBLE_CONTAINMENT_ERRNOS = {ENOENT}` として封じ込めと認めており、
write カテゴリだけ排除しているのは非対称である。

**処置:**

- write カテゴリで `ENOENT` を封じ込めと認めてよい条件を、**資格情報カテゴリと同じ厳しさ**で置く:
  (a) 同一 path に対する **sandbox 外の正例が `REACHED` で成功**していること、かつ
  (b) `inside_side_effect_observed` が false であること。
- **理由コードを分けよ。** errno による能動的拒否は従来どおり `*_CONTAINED`、
  不在による封じ込めは `*_CONTAINED_BY_ABSENCE` のように**別コード**にし、receipt から
  両者を区別できるようにせよ。混同させないこと。
- **`EEXIST` は引き続き封じ込めではない。** ここは絶対に変えない。
- カテゴリ別 errno 表の単一正本という構造と、テスト側の独立 literal 比較は維持せよ。

## H2 — 単独性検査がシステム常駐 process を co-tenant と数える

実測値:

```
S1.exclusivity_evidence:
  other_non_root_user_processes: count=18, uids=[100,101,102,103,104,114,115,117,122,126,997]
  load_average = [0.0048828125, 0.25244140625, 0.6318359375]
  nproc = 48, cpu_affinity = 0..47 (全数)
S7.exclusivity_valid = false → S7 は inconclusive
```

uid 100〜997 は**システムサービス用アカウントの常駐 daemon** であり、他ユーザのジョブではない。
load average と 48 CPU 全数の affinity は実質専有を示す。

**処置:**

- co-tenant の判定を「**自分以外の非システムユーザ (uid >= 1000) が所有する process**」に限定せよ。
  システムアカウント (uid < 1000) と自分自身の process 群は co-tenant と数えない。
- 併せて **load average による閾値検査**も残し、いずれかが破れたら `inconclusive` にせよ
  (`tools/pegasus/policy.json` の `silo_ladder_rung1.solo_load1_threshold` が既存の先例)。
- **観測は落とさない。** 除外した process 群 (uid と件数) を receipt に残し、
  何を根拠に専有と判定したかを後から検証できるようにせよ。
- **専有でないときに `go` にしてはならない。** 判定を緩めるのではなく、
  判定対象を「他ユーザのジョブ」へ正しく絞るだけである。

## H3 — DNS が帰属不能であることを理由コードで区別する

実測値:

```
S3.network_dns: outside=DENIED|EAI_AGAIN (正例が成立しない) / inside=DENIED|EAI_AGAIN
```

計算ノードは **sandbox の外でも DNS を引けない**。したがって内側の拒否を sandbox へ帰属できない。
これは probe の欠陥ではなく node の性質であり、判定は `inconclusive` のままが正しい。

**処置:** 理由コードを、単なる「正例の sentinel が不正」ではなく
「**node 自体に当該 egress が無いため帰属不能**」と読める専用コードへ分けよ。
判定 (`inconclusive`) は変えない。同型の状況 (外側正例が対象機能そのものを持たない) を
一般に表現できる形にすること。
