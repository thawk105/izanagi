skip (二重実行しない)。実行順序列は §3.2 で事前凍結済みのため、再開しても順序・抽出は不変。

### 4.1 axis-proposer.md への契約追記 2 点 (D42 条件 4 = ユーザー明示承認が必要)

1. **空 diagnostics 構成:** 「`diagnostics` は空オブジェクト `{}` の場合がある — 帰属情報が
   提供されない運用構成も契約上有効な入力であり、射影漏れではない。その場合
   mechanism_hypothesis は stock 抜粋と編集面の地図の構造観察から書く (attribution 実在項目の
   名指し要求は diagnostics が非空の場合に限る)。恒真提案の禁止は不変 — 対象コードの実在
   構造に繋がり反証可能な観測を指定できない提案を出さない」
2. **位置指定構成:** 「入力に `hole_region_directive` (編集面の地図の領域名 1 つ) が存在する
   場合がある — その場合 hole_location.region はその領域に固定し、領域内の position/skeleton/
   mechanism_hypothesis の構成は通常どおり行う。directive は領域の指定であって骨格・機序の
   指定ではない」

**正確な位置づけ (v1 の「対称に作用する」の修正):** 追記される定義テキストは 3 アーム共通
だが、**空 diagnostics 分岐が発火するのは C5 のみ、directive 分岐が発火するのは C4 のみ**。
特に追記 1 は純粋な「帰属除去」ではなく、除去時の代替生成指示 (構造観察フォールバック) の
付与を含む — これなしでは C5 の挙動が未定義になり S-3 が「契約違反入力への混乱」と交絡する
ため必要だが、S-3 の検定内容を変える (§4.2)。

### 4.2 S-3 主張文の限定 (報告義務)

S-3 の報告は「帰属遮断で適格率が退化するか」でなく **「帰属遮断 (+ 構造観察フォールバック
指示下) で適格率が退化するか」** と限定して書く。フォールバック指示は C5 を有利にする方向
(= S-3 の退化仮説に不利 = 保守的) であることを併記する。

### 4.3 C5 の「除去」の操作的定義

`diagnostics` キーは残し値を `{}` にする (スキーマ存在検査を全アーム共通に保つ)。alive 軸の
attribution も dead 軸の生死二値も丸ごと除去 (部分保持は単一差分を破る)。

## 5. 由来盲検採点の運用

### 5.1 採点単位

**1 採点 = 1 ラウンドの提案束** (proposer 1 呼び出しの出力 JSON 全体)。根拠: (i) 凍結上限
「総採点 120 件 = 60 + 補充上限 60」の単位はラウンドと読むのが唯一整合 (提案単位だと最大 180 で
構造的に不足)。(ii) ラウンド二値の判定材料が 1 採点に閉じる。(iii) 縮約規則 (副指標のみ) は
ラウンド内提案の同時参照を要する。「1 件ごと fresh 採点」の「件」= この採点単位と操作化する。

### 5.2 採点プロンプトの事前凍結 (must 2 の反映)

- **採点者に投入する定型部全文 (システムプロンプト + ユーザープロンプト雛形。可変部は匿名化
  提案束のプレースホルダ 1 箇所のみ) を、いかなるアームの提案も生成される前に sha256 凍結し
  git コミットする** (freeze-before-observation — proposer 側と対称)。
- provenance に凍結コミット hash・時刻と、第一 proposer 呼び出しの時刻を記録し、先行性を
  照合可能にする。全採点呼び出しで定型部が凍結版と同一であることを機械 diff で検証。
- 匿名化スクリプト・除去規則 (§5.3) も同時に凍結コミット (事後記録でなく事前凍結)。

### 5.3 匿名化・混合順と盲検保証の正確な記述 (must 3 の反映)

- **ラベル除去 (機械的):** アーム名・実行順・session_id・タイムスタンプ・コスト等の実行メタを
  落とし、proposer 出力 JSON 本体のみを渡す。スクリプトは §5.2 で事前凍結。
- **混合ランダム順:** 採点順は master seed 由来 (§3.2)。fresh 独立採点の下で混合順の実効は
  「採点時間帯・API 状態の系統差をアームに相関させない」補助であり、盲検の実体はラベル除去 +
  1 件ごと fresh である (v1 の表現を格下げ)。
- **盲検保証の downgrade (正直な記述):**
  - C4/C5 は提案内容から**準決定的に識別可能** — C4 は 1 ラウンドの全提案が同一 (機序と乖離
    しうる) 領域に固まる署名、C5 は mechanism が attribution を一切参照しない署名を持つ。
  - ゆえに**本盲検は S-2/S-3 比較について「採点者がアームを知って基準を持ち替えること」を
    機構的には保証しない** (ラベル除去が防ぐのは確実な知得のみ)。
  - **一次防壁は採点基準の構造**: 3 項のいずれも判別署名を適格性に直結させない — (1) は射影
    既出性、(2') は attribution 接続を要求せず (「接続は本アームのみの追加観測、適格性に
    使わない」を採点プロンプトに明記)、(3) は mutation_type のみを見る。region の多様性・
    attribution 参照の有無は適格性の判定材料でない。
  - **残余 = 採点者の無意識バイアスと曖昧境界 (「曖昧は no」) の非対称解決に限定される。
    その向きは対照を低く見る = 主張有利であり、fails-closed が保証されない残余である** —
    報告に明記する。**C4 の適格率低下のうち処置効果 (無作為領域による機序希薄化 — S-2 が
    検定したいものそのもの) と識別バイアスは分離不能** — 限界として併記する。

### 5.4 採点 3 項の操作化 (全アーム共通、D47 決定 4 + D52 (2'))

1. **既存性 (完全射影基準):** 提案の軸名・hole 骨格が**凍結射影 (診断込みの完全版) に既出**
   (diagnostics 中の軸・骨格の再掲、既存軸の探索範囲内の変異) なら no。**照合対象は全アーム
   共通で「凍結射影の完全版」に固定する** — C5 のラウンド入力 (diagnostics 除去版) 基準に
   すると照合基準がアーム非共通になるため。事後の軸台帳 (trigger-gating 等) とは照合しない
   (D47 決定 4 (1) の原文操作化 — n=1 採点との基準同一性を保つ)。trigger-gating 同型提案が
   適格になりうるのは仕様であり「S-2 は入力射影からの提案能力の検定、新規性の裁定は人間承認
   gate の仕事」と報告に明記。
2. **(2') 機序仮説の実質性:** mechanism_hypothesis が対象コードの実在構造 (stock 抜粋に実在
   する処理・構造) に繋がり、反証可能な観測を指定していれば yes。恒真は no。**attribution
   への言及の有無自体は判定材料でない (非参照を減点しない) — この一文を採点プロンプトに含めて
   凍結する** (C5 への系統的不利の誘因を塞ぐ)。attribution 接続の観測は本アームのみの追加
   観測とし適格性に使わない。
3. **軸適格性 (D44 決定 1(i)):** mutation_type = scalar 単体は no (既存グリッドで代替可能)。
   構造変異 (code_fragment) または構造 + スカラー複合は yes。

判定規則: 各項二値、曖昧は no (scored-but-undecidable = 不適格、凍結済み)。提案適格 = 3 項
すべて yes。ラウンド適格 = 適格提案 ≥ 1。

### 5.5 採点者側の失敗処理と 120 カウンタの機械化 (must 5 の反映)

- **120 の操作化: 「二値が得られた成功採点」の件数** (ラウンド初回 60 + 補充スロットの採点)。
  機械カウンタで管理し、カウンタが 120 に達した時点で未採点ラウンドが残っていれば当該検定は
  判定不能 (凍結の停止規則の執行手続き)。
- **採点者出力の三分 (proposer §3.3 と対称):**
  - パース可能・二値フィールド present だが値が判定不能/所見が曖昧 → **不適格 (=0) に確定、
    再採点しない** (内容依存の翻し経路を塞ぐ。scored-but-undecidable の凍結規則と同型)。
    成功採点として 120 に数える。
  - JSON パース不能・必須フィールド物理欠落・API エラー → **機械故障。別カウンタで retry ≤ 2/
    採点スロット** (120 には数えない — 数えると正味 0 件の採点が予算を食い全ラウンド成功でも
    判定不能に至る)。**retry 超過 = 当該ラウンドの二値が得られない = 当該検定判定不能**
    (0 計上への置換はしない — 「補充は判定不能原則を置換しない」の凍結原則の採点側への延長)。
- 採点は全ラウンド完了後に一括 (逐次採点しない — 混合順が組めないため)。

## 6. アーム間単一差分の機械 diff (手続き定義 — 恒真ゲート化の防止)

- 対象: 全 60 呼び出しの完全ペイロード (システムプロンプト文字列 + ユーザープロンプト JSON)。
- 手続き: (i) システムプロンプトの sha256 が全呼び出しで凍結値と一致。(ii) ユーザープロンプト
  JSON を正規化 (キーソート・空白正規化) し、キー集合の差が {diagnostics の値, 
  hole_region_directive の有無} のみであることを検査。(iii) それ以外の共通部 (stock_excerpts /
  edit_surface_map / スキーマ上の他要素) が 3 アームで byte 同一であることを検査。
- 発火条件: (i)〜(iii) のいずれか不成立 = 実走停止 (fails-closed)。検証は driver が各呼び出し
  直前に実行し、結果を provenance 記録。
