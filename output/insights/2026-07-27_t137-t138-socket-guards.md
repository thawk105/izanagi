## 何を塞いだか

1. **[T-137] serve thread の偽緑**: `test_socket_roundtrip_works_beyond_108_byte_repository_path` は
   serve thread を起動して `thread.join(2)` するだけで、`shutdown()` が serve ループを止めなくなっても
   緑だった。join の結果を検査していなかったため。
2. **[T-138] 恒真ゲート**: 同 node の capability probe が検査対象の `bind_repo_socket()` 自身を呼び、
   108 byte 回避 (`protocol.socket_path_alias` の `/proc/self/fd/<dirfd>` alias) が壊れても
   `pytest.skip` + rc=0 になっていた。

## 構造的な知見 (他の gate にも転用できる形)

- **恒真ゲートは「赤が出ない」ではなく「赤の代わりに skip が出る」形で現れる。** M-B (108 byte 回避を
  壊す変異) の SURVIVED は `1 skipped, rc=0` だった。rc だけを見る harness はこの型を検出できない。
  変異検査では **rc に加えて skip 数の変化**も期待値に含める必要がある。
- **capability probe は、本番と同じ syscall 列と同じ名前を踏まなければ本番を代表しない。** 最初の実装は
  basename を長さ等価な別名 (`.p`) にし、`bind` だけを試していた。敵対レビューは (a) `socket()` 自体を
  拒否する sandbox では probe が例外を漏らして過剰拒否になり、(b) `listen`/`chmod` を拒否する sandbox では
  probe が通って本番だけ落ちて偽赤になり、(c) pathname policy を持つ LSM 下では `.p` が `.s` を代表しない
  ことを指摘した。**probe は socket → bind → chmod → stat → listen を本番と同じ basename で踏む**形に直した。
- **検出力を上げる変更が可用性を下げることがある。「赤にする」と「終わる」は別の性質である。**
  worklog の当初指示は「serve thread を非 daemon 化」だった。段 1 では A2 退行 (shutdown の
  `set()` 落とし) で 3.4 秒で赤になることを実測し、hang しないと結論した。**この実測は退行 1 種しか
  見ておらず、結論が一般化できていなかった (F29 型)。** 敵対レビューの指摘を受けて M-D
  (serve ループの `select` を timeout なしにする = lease 検査へ戻らない退行) を測ると、
  **daemon=True は 31 秒で rc=1 の赤、非 daemon 版は外部 timeout 90 秒でも終了しなかった**
  (内部では `1 failed` まで到達している)。**偽緑の原因は daemon 属性ではなく生存 assertion の欠如**
  であり、`assert not thread.is_alive()` だけで検出力は得られる。非 daemon 化は受入全走を
  「赤」ではなく「終わらない」に変える純損失だった。
- **probe を持つテストは両方向 (True/False) を固定しないと、恒真化が形を変えて戻る。** 最初の正例
  テストは「capability 不足 → False」だけを固定し、冒頭で probe が False なら skip していた。
  焦点再レビューは「probe が常時 False へ退行すると、正例も長 path node もそろって SKIP + rc=0 に
  なり、T-138 の恒真ゲートが形を変えて戻る」と指摘した。**mock で capability 十分な socket を
  与えて True 側も固定**し (`_PermissiveAliasSocket`)、M-E1/M-E2 で両方向の退行が kill されることを
  実測した。
- **AST の語彙で直列化対象を導出する meta-test は、docstring の文字列でも taint する。** 新しい helper の
  docstring に `bind_repo_socket` の言及があるだけで taint が伝播し、marker 欠落で受入全走が赤になった。
  helper は実際に raw AF_UNIX socket を bind するので直列化は意味的に正しく、**根拠を docstring の
  偶然マッチから実体へ移すため語彙へ `socket.socket` を足した** (契約が要求する「なぜ同時実行で壊れるか」
  = 同じ runtime dir の socket path の奪い合いと、socket module を差し替える mock の同 worker 内漏洩)。

## 残った既知の弱点 (次の一手へ計上)

- join(30) の二律背反 (確定退行でも 30 秒待つ / 30 秒超の starvation は偽赤)。runner に全走 timeout が
  ないため現状は nit。外部 ceiling が 30 秒増分を吸収できない構成が現れたら must-fix へ昇格する。
- probe cleanup の fault injection 経路 (unlink 例外が `False` を上書きして偽赤、bind が実体を作ってから
  例外化すると `created=False` で `.s` 残留 → 偽緑)。実 socket の正常経路では再現しない。
- 逐語 3 本の中の `/tmp/...` パスは生成時の作業領域であり、参照先は本 insights と台帳へ凍結済み。
