# [T-1875] 対計画用 pilot の事前登録 — 実装せず裁定へ返す

対象は D1268 が定めた「対計画用 pilot は `n` と `sd_max` の導出だけに使い、`delta_min` は pilot と
独立に先に固定する」の実装である。**本 wave は事前登録を発行しない。** 理由は下記 3 件で、
どの 1 件だけでも発行を止めるに足りる。実装面の差分はゼロである。

段 2 (codex plan, read-only, xhigh) と段 3 の敵対相談 2 本 (同 xhigh、レンズ = 前向き性と恒真化 /
実効性と整合) はいずれも NO-GO を返した。親は下記のとおり real / refuted を裁定し、
決め手になる事実は自分で現物にあたって確かめた。

## 1. 事前登録が固定すべき対象が、正式実験の対象と一致しない

計画は「凍結した候補集合の全順序対を測る pilot」を設計した。しかし 8c の正式実験で 1 アームの
結果とされるのは**その場で生成された最終世代の variant** である。

- `docs/phase3-8c-preregistration.md` の「arm の outcome 単位」節が、outcome を
  `G=2` の最終世代の canonical variant と定めている (2026-08-27 の裁定 D1066)。
- 固定候補を測った pilot のばらつきは、生成 variant のばらつきの推定になっていない。
  pilot の後に「どの候補が正式 cell に対応するか」を選べば結果依存になり、選ばないなら
  登録していない対象への外挿になる。

**成果物への影響:** 対応づけ次第で導出される反復数と上限が動き、公式性能表の受理集合を
後から動かせる。凍結物として発行してはならない形である。

## 2. `delta_min` に使える独立な根拠が repo に無い

判定器が要求するのは**毎秒トランザクション数の絶対値**であり、向きと単位を同時に固定する。
`orchestrator/campaign/s8c_result_judge.py` が `delta_min` を有限かつ正の実数として検査し、
対差の平均がそれを厳密に上回る場合だけ成立候補にする。

一方、候補として挙がる既存資料はすべて**相対値**だった。

- 床値の候補は 0.22% / 0.67% / 1.07% といった変動係数である
  (`docs/b10-backoff-shape-preregistration.md`)。
- A-3 の既知利得は +38.3288% / +11.2682% / -6.6430% で、対比の相手も別である (同上)。
- A-1 の pilot 方針が持つ 3% 床値と ±6% 条件も割合であり、かつ `formal=false` の
  反復数決定専用である (`orchestrator/campaign/paper_story_a1_paired.v3-pilot.json`)。

相対値を絶対値へ直す基準スループットを今ここで選ぶ行為そのものが、結果を見てから基準を作る形に
当たる。**絶対値を持つ既存実測は、すでにどれも閲覧可能な結果である**ため、独立な根拠にならない。

**成果物への影響:** `delta_min` は反復数と公式判定の閾値の両方へ直接入る。値の選び方で
certified な受理集合が変わる。値を作って埋めることはしない。

## 3. 判定パラメータの表現が、読み取り側と判定側で分断されている

事前登録 §5 の値を読む parser と、実際に判定する judge が、別の形を要求している。

- parser (`orchestrator/campaign/s8c_preregistration.py` の
  `_validate_iteration_contrast_parameters`) は、ちょうど `H1` と `H2` の 2 つを根 key とし、
  それぞれに `n` / `delta_min` / `sd_max` / `unit` / `direction` を要求する。
- judge (`orchestrator/campaign/s8c_result_judge.py` の `judge`) は、**単一の**
  `_ContrastParams` を受け取り、それを 6 cell 全体へ適用する。manifest は
  「2 holdout × 3 arm = ちょうど 6 cell」で正規化される。

したがって H1 と H2 に別々の値を登録しても、現行 judge へ一意に渡す経路が無い。
どちらの閾値が公式判定を支配するかが決まらない。

なお計画が置いた「`H1/H2` × 2 holdout = 4 contrast」という層の数え方も誤りだった。
**`H1` と `H2` がその 2 つの holdout そのもの**である。層の数が変われば、多重比較の分母、
ばらつきの上界、導出される反復数がすべて変わる。

**成果物への影響:** 今この形で値を登録すると、judge が消費できない値を凍結物として発行する。
この分断は T-1874 (§5 値 gate の結線) の完了条件に属する欠陥であり、T-1875 の担当ではない。

計画は台帳に T-1142 の n-pilot だけを載せる案だった。敵対相談が欠落を挙げ、親が現物で
少なくとも 1 件を確かめた。

- **A-1 探索走の対差実測**が `output/insights/2026-08-24_paper-story-a1-paired/result.json` に
  絶対値で存在する。`mean_signed_positional_difference_tps` = -5698.0、
  `sample_sd_positional_difference_tps` = 43649.05535060295。
  **計画はこの結果から作られた A-1 の方針を導出式の手本にしている。**
- 他に挙がった欠落は、T-1431 の床値 pilot (12 cell、rr20 35.55k / rr80 45.51k の床値案)、
  2026-09-01 の同一 12 cell 再測定 2 本、A-1 の既知反復数 72/205/28 と 218/564/28、
  A-3 と A-2 の相対利得である。

**成果物への影響:** これらを見た状態で式・候補・`delta_min` を選んでおきながら
「T-1142 だけを除外した前向き pilot」と報告すると、HARKing 境界の宣言が偽になる。

## 5. 順序前提について — 親の当初根拠を撤回する

親は当初、着手順序の根拠に D229 決定 (6) の `producer → pilot → validator/consumer → 本走` を
挙げた。**この援用は撤回する。** D229 は別系列 (T-139 の統計設計) の個別裁定であり、
8b §10.2 の再凍結より古い。本件を支配するのは後発かつ主題固有の §10.2 である。

そのうえで、着手そのものは止まらないと裁定する。§10.2 の 5 条件は「**値を記入してよいのは**
次がすべて成立したときに限る」という連言であり、条件 2 は pilot の完全 block 成立、条件 4 は
3 値を結果を見る前に決めていることである。**pilot の事前登録は pilot に先立つほかなく、
条件 2 と 4 はその順序を前提にしている。** したがって T-1874 の保留は T-1875 の着手を禁じない。

**ただし本 wave が止まる理由はこれではない。** 上記 1〜4 で止まる。

なお D229 決定 (5)「目標効果量を固定し pilot の結果で引き下げない。下回る場合は計画不成立として
終える」は、`delta_min` の書き方の**文面の手本**としては引き続き使える。順序の権威としては使わない。

## 6. 論文側の対応づけについて — A-1 と B-4 には資さない

依頼は論文 §8 の A-1 と B-4 を要求として挙げていた。実体を読んだ結果、この pilot は
その 2 つの反復数根拠にはならない。

- **B-4 は pilot を持たないと自ら凍結している。** 反復数は `A_min = 0.60` と符号検定から
  `n = 201`、検定単位は block と確定済みである
  (`docs/phase3-b4-reflux-ablation-preregistration.md`)。
- **A-1 は別方針・別対比である。** `formal=false`、昇格禁止、3 workload、
  `variant-minus-baseline`、1 workload あたり 60 対の別 study である
  (`orchestrator/campaign/paper_story_a1_paired.v3-pilot.json`)。
- `n` / `delta_min` / `sd_max` という語彙は 8b §10.2 と 8c §5 のものであり、対象は
  8b/8c の反復単位対比だけである。

**したがって、この pilot が完走しても論文 §8 の A-1 と B-4 の未取得状態は動かない。**
これは依頼の枠組みと食い違うので、ユーザーの確認を要する。

## 7. T-1777 との所有境界

T-1777 の残工程 (3)(4) は A-1 の反復数認証と A-1 study の事前登録凍結である。
本 wave の起動時および段 3 時点で、T-1777 の作業ツリーに本 wave と重なる編集面は無かった

## ユーザーに決めていただきたいこと

1. **`delta_min` の絶対値。** H1 と H2 それぞれについて、毎秒トランザクション数の
   正の実質効果境界と向き。独立な根拠が repo に無いため、研究上の判断として決める必要がある。
   決まらない限り事前登録は発行できない。
2. **pilot が測る対象。** 生成 variant を対象にするのか、固定候補で代理するのか。
   代理にするなら、代理であることと外挿の限界を事前登録に明記する形になる。
3. **H1/H2 別値と単一判定パラメータの分断をどちらに寄せるか。** parser を単一値へ寄せるか、
   judge を holdout 別へ広げるか。これは T-1874 の完了条件へ含める形が自然である。
4. **論文側の対応づけ。** この pilot を A-1 と B-4 の根拠として数えない、という上記の裁定でよいか。
