## 2. 反対

### 2-1. T-2558 — 宣言だけで閉じるのは D1915 の理由と衝突する

D1915 は同じ T-1998 について「文書を置くだけでは、呼び手が結果を見た後に成果物から identity を
写して手組みでき、canonical 文書を 1 度も読まずに受理へ到達できる。段 3 の 2 レンズが独立に
この経路を突いた」を理由に機構を選び、「文書だけを置き、loader を任意呼び出しにする」を却下した。

→ 「全 CLI へ不可避化」は過剰だが、数値を公表する production 入口の本数を先に実測し、
1 本なら既存 loader をそこへ束縛する局所修正を推す。多数または不在なら宣言で閉じ、限界を明記。

### 2-2. T-2584 と T-2562 の同時見送りは、平坦外挿を明記しないままにする

T-2584 本文は混合検算の 3.1% / 9.6% の時間が b>900 に落ち、そこを 900 µs の値で平坦に
置いたと書く。T-2562 を見送ると 1000 µs の既測 (schema v2) は歩行 model が受け取れないので、
「1000us 既測との重複を除く」は記録上だけの重複になる。

→ 見送り自体は費用対効果で妥当。ただし条件を足す — 平坦外挿を D1724 / D1857 の
「記述的な会計」の限界として成果物へ明記する。しないなら T-2562 の移行が要る。

## 6. Git

現物:

- `origin/main` = `HEAD` = `e618883c2`、`git rev-list --count origin/main..HEAD` = 0
- `origin/main` の reflog 直近は `2026-09-10 10:21:15 +0900 update by push`、HEAD の commit 日時は 09:01:24

ただし遠隔の実体はここから確認できない — SSH は `Permission denied (publickey)`、
HTTPS は `could not read Username`。「未 push 0」は手元の remote-tracking ref に基づく主張で
あって遠隔の実測ではなく、recommendations.md はこの区別を書いていない。
ユーザーの「未 push 20 commit 以上」との食い違いは、10:21 の push より前の観測か
別ツリーの話である可能性がある。AI は push しないので、いずれにせよ AI 手番の git 操作は無い。
