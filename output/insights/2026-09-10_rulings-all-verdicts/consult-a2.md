### 2. t1259 fixture の module scope 化 — D1877 の却下枝そのもの
- D1877 の本文は「fixture の共有範囲は**変えない**」と書き、「走査を session 単位へ寄せる —
  設計変更で交絡が増える」を**却下枝**として明記している。未 land fragment
  (`{{D:t1259-repo-snapshot-once-per-module}}`) は共有範囲を module へ変え、timeout は据え置く。
  D1877 と**逆向き**であり、「実測に基づく重複除去」として D1877 と併存はしない。
- 索引には「D1877 を supersede する裁定」として出す。実測 (51 node × 全走査、単発 3.6 秒、
  8.33 倍膨張) は supersede の根拠になるので、その数字を添える。
- **追補 (必須):** module scope の fixture は `conftest._declare_default_test_site` の
  function scope autouse より先に走るので site 中立化が効かない。2026-09-09 [T-2316] で
  `test_p3_b4_material_report.py` ほかが踏み、35 件が setup error になった実例がある。
  採用するなら fixture 自身で `site_policy.socket` と `_has_nqsv` の**両方**を中立化する条件を付ける。
- **追補:** fragment が併せて要求する「real-repo inventory / parent-only 集合 / 独立 golden への登録」は
  既存機構かを実測で確かめてから。新 golden の新設なら過剰側なので分離して諮る。

### 1. T2534 define 除去 — 「最小修正」の看板が立たない
- 親の反論 (過去の別 build の hash 不一致は、同条件での define 有無の binary 一致を反証しない) は妥当。
  fragment の「binary identity で担保していない」は、define 除去を否定する根拠にはならない。
- ただし fragment はもう 1 本、**独立した**却下理由を挙げている。(i) 案 2 が成立するのは
  define・configure argv・claim・関門を**同時に**落とす場合だけで、関門だけ消す形は偽の緑 (規律 2)。
  (ii) D1863 の独立軸表 (`SPACES["silo"]` と exact 表検査) の同時変更が要る。
  したがって**軸表の削除は必要**であり、変更面は fragment 側の案より小さいと言えない。
  「最小修正だから define 除去」という理由付けは落とし、択一として出す。
- **未 land fragment を裁定済みとして扱わない。** 採番前の spool fragment で、
  ユーザー授権の記載なし、同 branch insight README §9 も裁定待ち、本文自身が
  「この決定は本 wave では実行しない」と書いている。索引では「main の推奨 vs 未 land の設計案」
  という択一で出す。両者が一致している点 (**関門は 1 文字も緩めない**) は明記する。

### 11-2. C3b 裁定 2 — 統合しても hold は恒真のまま
- 実測は「`HELD=True` でも `_assert_freeze_allowlist()` が同じ 2 値を無条件に比較するので、
  hold は結果を 1 bit も変えていない」。裁定 1 の (a) を採ると**両検査とも通る**ので二重化は消えるが、
  hold が結果を変えないという性質は残る。「統合で解消」とだけ書くと、効かない機構を有効と誤読させる。
- 索引では「hold は現状 恒真。効力の是非は別途」を 1 行残す。拡張 (b) と全解除 (c) を採らない点は支持。

### 8. T2563 certify walltime — 「整合させる」で数字を隠さない

  凍結文書に触れるなら erratum 経路 (本文の直接改訂をしない)。

### 3. 認証 smoke / wait の rc — 判断基準を consumer で書く
- 定期 smoke の新設見送りは支持 (次実走への同梱確認で足りる)。
