`docs/skill-self-improvement.md` の発火 gate・routing・command 別終端を一度だけ適用した。

## 候補 1 — fix prompt が段 4 の規模上限を継承しない → **reference へ統合 (実施済み)**

- 実測: 段 6 の fix 子が must-fix 8 件を閉じる過程で、使い捨て probe を 100 → 486 コード行へ
  膨張させた。段 4 は 100 行の上限を課していたが、fix prompt へ継承されていなかった。
- routing 3 (dev-wave 固有の手順 → 発火段に対応する既存 leaf 節) に従い、
  `docs/dev-wave/workers.md` の `DW-S06-B` の継承列挙へ「段 4 の規模上限」を足し、
  「超過は所見が閉じても差し戻す」を付けた。新しい節もファイルも作っていない。
- **予算の扱い:** dev-wave docs の合計は上限に張り付いていた (25199 / 25200)。
  契約どおり**予算値は上げず**、同ファイル内の冗長表現 3 箇所 (焦点再レビューの重複括弧、
  揮発 payload の 3 文 → 2 文、「単一化の」の冗語) を詰めて捻出した。正味 +5 bytes。
- **手続き上の逸脱 (正直な記録):** 本改善は段 8 ではなく段 7 の記録 commit (`cf181f7a`) に
  含まれている。失敗台帳の「恒久対応は実体へのポインタ必須」を満たすには、F エントリと
  同じ commit で実体が存在している必要があったためである。「専用 commit にする」という
  終端規定とは食い違うが、`検査と commit 境界` の「変更理由になった failures と整合を
  同じ commit で保つ」は満たしている。history は書き換えない。

## 候補 3 — 変異 harness の runner が pytest に束縛されている → **decisions のみ**

- 実測: `tools/mutation_harness.py` は runner を pytest に限るため、pytest node でない
  使い捨て probe をそのままでは駆動できない。
- `DW-M05` は既に「独自 harness は同等の検査を備えると段 4 で事前登録する」と規定しており、
  規則の欠落ではない。具体的な回避方法 (probe を叩く最小 pytest node を作って runner にする) は
  decisions へ送った (本 wave の decisions fragment `disposable-probe-mutation-wrapper`)。
  `docs/dev-wave/mutation.md` は残余 76 bytes しかなく、意味等価に収まらない。

## 候補 4 — `DW-O16` の「3 巡上限」の数え方 → **裁定パッケージへ (実装しない)**

- 実測: 本 wave の fix は 4 巡した。内訳は (1) レビュー所見 8 件の fix、(2) 親が規模膨張を
  差し戻した巡、(3) 親が receipt 回帰を検出して復元させた巡、(4) 焦点再レビューの残存 2 件の fix。
- `DW-O16` は「**NO-GO が続く場合**は fix を重ねず 3 巡を上限とし」と書いており、
  (2)(3) のように**親自身の裁定ミスや回帰検出で差し戻した巡**を上限に数えるのかが読み取れない。
  厳格に数えれば本 wave は上限超過、NO-GO 継続だけを数えれば 2 巡である。
- これは**裁定境界**に触れるため、`docs/skill-self-improvement.md` の dev-wave 終端に従い
  実装せずユーザー裁定へ返す。

  **択一:** (a) 3 巡は「レビューが NO-GO を返し続けた回数」とし、親が自分の裁定ミス・回帰で
  差し戻した巡は数えない (代わりに worklog へ内訳を必ず書く) / (b) 差し戻し理由を問わず
  fix 子の投入回数で数える / (c) 現状の曖昧さを残し、超過時は毎回 worklog で理由を述べる。

  **推奨 = (a)。** 上限の目的は「レビューと fix の無限ループを止める」ことであり、親が
  自分の誤りを直す巡はその失敗モードではない。ただし (a) は親が「自分のミスだった」と
  名乗れば無制限に巡を増やせる抜け道を作るため、内訳の worklog 記載を義務にして塞ぐ。

  **成果物影響 (決めない場合):** 上限が実効しないまま「3 巡で打ち切った」と記録される wave と
  「4 巡したが 2 巡と数える」wave が混在し、fix 巡数を根拠にした品質判断ができなくなる。
