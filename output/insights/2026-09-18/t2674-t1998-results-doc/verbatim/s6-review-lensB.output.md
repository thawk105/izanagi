### 1. must-fix — §3 限定5：温度ドリフトの影響を排除したように読める

**問題の文：**
> 走行間ばらつき・cold boot・温度ドリフトを含まない。

1 job・1 boot・1 node であることから、温度ドリフトが測定に含まれないとは言えない。baseline と target は異なる時刻に順次測られており、時間変化の影響を分離した記録も提示されていない。「評価していない」と「影響がない」が混ざっている。

**代案：**
> 独立した走行間・boot 間・node 間のばらつきは評価していない。また、baseline と target は順次測定されており、温度ドリフトなど時間変化の影響を分離・評価していない。

**根拠：** 親導出 WAL 表の時刻、稿 §2.5、事前登録 §9 の A-5 限定。
**対応観点：** 1・3。

### 2. should-fix — §1.4・§4(a)：source digest の一致と patch 適用履歴の対応を混同している

**問題の文：**
> patch `patches/silo-backoff-fixed.patch` が当たった木で両 arm とも build されたことを記録している

> この対応の代わりに立つ束縛である。

§4(a) は patch file と tracked diff の対応を再現していないと明記する。一方、§1.4 は変更対象パスと diff hash から特定 patch の適用を断定している。特に baseline の source digest は patch の有無で変わらないので、source digest の一致だけではこの不足を埋めない。

**代案：**
> 両 arm の記録は、同じ2ファイルの変更と同じ tracked diff digest を持つ。arm 別 source digest は事前登録値と一致する。ただし、この tracked diff と指定 patch file の対応は本稿では再現していない。

§4(a) の末尾は次に置き換える。

> source digest の一致は、事前登録が要求する arm 別 source identity の照合であり、patch file と tracked diff の対応確認とは別である。

**根拠：** 事前登録 §4.2、とくに「baseline の値は patch 適用の有無で変わらない」、稿 §4(a)、親 brief の欠落候補(a)。
**対応観点：** 1・7。

### 3. should-fix — §2.3・親P2：既定値の列挙だけでは実行条件の導出にならない

**問題の文：**
> これは束縛された code から導いた値であって、成果物の記録ではない。

「成果物の記録ではない」という区別は適切。ただし、示されている根拠は `CorrectnessWorkload` の**既定値**までである。その値が当該呼出しで上書きされず使われたという経路の説明がないため、「検査条件を導いた」とするには一段足りない。

**代案：**
> 以下は lock が束縛する `pipeline.py` の `CorrectnessWorkload` の既定値である。実行時 argv の記録ではなく、この列挙だけでは当該走行が各既定値を使用したことまでは確認できない。

実際の条件として残す場合は、既存の束縛 code の呼出し・引数まで根拠を示す。追加の gate や実走は不要。WAL が直接示す「legacy の `verify_done` が各 arm 1件」という記述は維持できる。

**根拠：** 親P2、稿 §2.3・§4(c)。D1993 項3も、条件の束縛を lock **と pipeline constructor** に区別している。
**対応観点：** 6。

## 親の brief への異議

- **P1：掲載必須とする理由に不同意。** 一次資料全体を調べることと全点の数値を掲載することは別。全点表は編集判断であり、ユーザー要件として扱わない。所見4の削減を推奨する。
- **P2：条件付きで同意。** 既定値をcode由来と表示することは妥当だが、それだけでは実際の検査条件の導出にならない。成果物のargv記録の代用にもならない。所見3の書き分けが必要。
- **不変条件：方針自体への異議なし。** ただし「未照合」を「証拠不存在・復元不能」へ拡張しないこと。また「patch適用の記録」という親の要約は所見2と同じ強すぎる表現。
- **研究前進：異議なし。** 既存の認証済み結果を単独稿として供給する範囲なら一次資料が支持する。`check_docs.py` の成功は内容の正しさを代替しないため、本レビューの修正確認も着地判断に含める。
