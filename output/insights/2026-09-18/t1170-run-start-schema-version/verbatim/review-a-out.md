## 変異帰属の判定 (M0〜M4)

以下は静的予測。変異実走の結果・kill node の完全集合を確認したという意味ではない。

| 変異 | 判定 | 帰属 |
|---|---|---|
| M0：コメントの句点変更 | SURVIVED 相当 | 実行意味・定数・診断が変わらない。 |
| M1：run-start 版検査 block 削除 | KILLED | v99・現行形は版以外の gate を通るため、未知版テストが「例外なし」で検出する。既存の v3・現行形や版欠落も同様。一方、新規 v3・旧形は後段の `run-start generation_driver differs` で拒否され、全文期待の不一致で kill される。**旧形 node は受理拡大の検出ではなく、拒否理由の移動の検出。** |
| M2：対応定数を v3 に変更 | KILLED | v4 正例が版 gate で拒否される。さらに `consumer_supported` の期待不一致や、v3 が版 gate を通過することによる失敗も発生する。**複数の診断期待が同時に壊れるため、単一理由に集約できない。** |
| M3：legacy／unknown 交換 | KILLED | v3 と v99 の全文期待が世代分類の相違を検出する。受理集合は変わらず、診断契約の変異に帰属する。 |
| M4：比較右辺を producer 定数へ戻す | KILLED | 独立性テストで producer 定数が `v5-fixture` になる一方、fixture は独立リテラルの v4 を保持する。最初の `_verify` が版 gate で例外となり、確実に失敗する。後半の負例に到達する必要はない。 |

前段には journal hash・event 種別・順序・transport・report 版の検査がある。新規負例は `_persist` が hash を再計算し、その他の正常条件も保持するため、これらによる拒否の横取りはない。旧形については、上述の後段の重複拒否がある。
