## should

- **何が不足か:** plan は「lock保持時間や他threadのスケジュールへの影響まで無いとは言えない」と訂正していますが、観測被覆への帰結がまだ抽象的です。write lock は validation で取得され（`M:989–1000`）、L 出力はその保持中です（`M:1141–1147`）。他 transaction の validation が旧版を読み、その後も `W_LOCKED` を観測する場合、`M:1024–1033` は commit を拒否します。L の I/O がこの状態の継続時間を延ばすことは静的な説明候補です。
- **放置時の影響:** 「witness onで0/40」を、S が `[publish, unlock]` を伸ばす経路だけで説明したように読めます。S だけ軽くした追試が陰性でも、観測者効果全体の否定にはなりません。
- **修正案:** L による拒否機会の変化を、S の窓延長と並ぶ**未実測の候補**として追記してください。L を今回移動する必要はありません。「固定する」は介入範囲の選択であり、無影響の証明ではありません。

同様に E が058側にも存在することは、E の時間寄与や他の計装との相互作用を排除しません。058 source は射影されておらず、同位置という事実の独立照合は未実施です。plan のこの留保は適切です。後続 write の stamp が先行 write の publish 後に入るという訂正も、`M:1160–1207` に整合します。

**S2 — 診断 arm の低下・非低下を、原因三分岐の識別と分けて書く**

- **どこ:** brief 冒頭、plan §5・§7、`Dpatch:8–14,22–34`。
- **何が不足か:** plan の「根因・必要性は確定しない」は正しいものの、結果別の主張範囲を明記すると過剰解釈を防げます。診断変更は cold 側の追加 abort と validation の版再読を一緒に施します。前者は read-set 登録前の退出であり（`M:347–370`）、後続の RLL・温度適応への入力も変わり得ます（`M:1059–1084`、`R §1`）。
- **放置時の影響:** 率低下を「(ii)が根因」「hook／verifierは無関係」と解釈したり、非低下を「静的候補が誤り」と解釈したりできます。
- **修正案:** insight の解釈を次の範囲に固定してください。

| 結果 | 言える範囲 | 識別できないもの |
|---|---|---|
| diag の検出率が低い | 固定条件で、二変更を束ねた介入と検出率低下が整合する | cold検査とvalidation再読の寄与、(i)/(ii)の寄与、実装／hook／verifier仮定の三分岐 |
| 差を検出しない | この標本・条件では低下を検出できない | 効果ゼロ、候補経路の不在、診断の無効性 |
| diag でも正例がある | 当該 producer／計器条件で signal が残る | 元と同じ実行経路による signal かどうか |

「受理集合を縮小」は**既存の観測を固定した attempt に追加拒否を加える**意味に限定すべきです。実行全体の履歴集合、commit 数、G2 検出確率の単調減少は導けません。この点は plan §5 が既に適切に限定しています。

また verifier は同一 key の `(epoch,tid)` を整列し、その直後版へ rw 辺を張ります（`orchestrator/verifier/dsg.py:16–18,146–157,247–248`）。今回の witness-off 三 arm はこの版順序仮定を独立に検証しません。G の `supported` も writer version・store順・commit順の証明ではありません（`G:648–653`）。

- **放置時の影響:** 「bo1で0 → backoffがG2を消す」「bo1でも同率 → witnessが主因」のどちらも成立したように読めます。後者には witness-on の同時対照も、効果の同等性を示す設計もありません。

**S4 — thread-local 保持先の生存期間を一文で閉じる**
