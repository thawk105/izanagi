## 削除候補 (番号、対象、根拠、失うもの)

1. **待ち手の後詰め全体は条件付き削除候補。** brief の T-968・未着地 probe は残差保存の根拠だが、「起動器が死亡し、待ち手だけ生存した」実例ではない。提示された DW-C00 の停止契約も後詰めの根拠にならない。ただし依頼の「起動器 / 待ち手」を**両 tool**と読むなら、待ち手実装は明示要求内であり、仮想リスクという理由だけでは削れない。「子の走行終了時点」を指すと解釈する場合に限り、起動器への一本化が整合する。
   **削ると:** 起動器だけが異常終了した場合の救済と両 tool 解釈への適合を失う。**残すと:** CLI・配線・入力契約・テストが増える。

2. **待ち手の「done 非空でも発火」と check-only への書込み追加は削る。** 現行 `wait_for_producer` は PID 死亡後にファイル待ちへ進む。非空 done を別の発火条件にする必要はなく、brief の「死亡確定後」からも逸脱する。check-only に commit させる必要性も示されていない。
   **削ると:** PID 生存中・check-only 経由の保存を失う。**残すと:** 新しい終端判定と観測経路の副作用が増える。

3. **待ち手による done の非0 rc の再解釈は削る。** 現行の指定範囲は done 内容を読まず、死亡とファイル存在を扱う。残差 commit の追加に、既存成功 outcome を producer rc で変更する契約は不要。commit 自体の失敗表示とは分けるべき。
   **削ると:** waiter による producer rc の伝播を失う。**残すと:** 保存以外の終了コード契約と解析処理が増える。

4. **index.lock の事前検査・失敗後再検査・skip 再分類は削る。** Git の add/commit エラーを通常の failed とすれば、lock を尊重し残差を保持できる。独立した skip 理由は必要ない。
   **削ると:** lock 専用の診断を失う。**残すと:** 同じ書込み不能に複数経路・競合タイミング・専用テストが増え、rc=0 の skip に未保存を隠す場合も生じる。

5. **rebase・cherry-pick・sequencer への横展開は削除候補。** 指定資料が示す実経路は DW-C01 に由来する merge であり、それ以外の操作中保存は示されていない。安全側 skip を gate として非難するのではなく、未完了操作の種類ごとの分岐・試験負担を削る判断である。
   **削ると:** それらの操作中に明示的に不発火とする保証を失う。**残すと:** 本体の根拠がない操作別契約と実 conflict テストが増える。

6. **同じ観測を繰り返すテスト・変異を統合する。** clean 初回と二回目、local identity、trailer、base patch は一つの実 Git 正例へ併記できる。削った waiter 拡張・skip 専用の変異も削る。
   **削ると:** ケース別の独立した故障位置特定を一部失う。**残すと:** 同じ保存結果を検査する fixture と保守箇所が増える。

detached は DW-S05-A の `-b`／midflight で既に排除される。main・root 不一致・index.lock も、適正な投入手順で発生する実例は指定資料にない。ただし **detached/main は brief の明示負例、root 一致は渡された保存対象を限定する局所条件**なので、そのまま削除確定とはしない。特に root は現行 `_absolute` が絶対パス化するだけで、repo サブディレクトリを拒否しない。

**削ると:** 保存先・branch の限定を弱める。**残すと:** 少数の局所検査が増える。ここは lock 専用処理より残す理由が強い。

## 不足 (依頼の本体に足りないもの)

- **待ち手 opt-in を実運用で渡す箇所がない。** plan は parser と関数配線を挙げるが、どの投入手順が flag を渡すかを示していない。両 tool 解釈なら、未使用の機能追加では完了しない。
  **削ると:** 待ち手の実用上の保存を失う。**残すと:** 既存呼出し箇所への最小の配線が必要になる。

- **receipt 欠落時の read-only 不発火は保証されていない。** plan 自身が flag を実装子の指定とみなすため、read-only 子への誤指定を排除できないと認めている。新しい証明 framework は不要だが、保証範囲を「呼出し側が対象を正しく指定する」に限定し、brief の絶対保証と整合させる必要がある。
  **削ると:** receipt 欠落時の救済を失う。**残すと:** 呼出し側契約と、その実配線を検証する必要が増える。

- **本体の正例は概ね具体的だが、起動器成功時の配線も一緒に固定する。** 実 Git＋fake launcher は、検査対象が起動器の終端処理なら適切である。launcher rc=0/7 を同じ正例で確認し、helper を代役にせず、tracked 編集・削除・untracked と commit tree を比較する。read-only 負例は dirty な同条件で HEAD・index・作業ファイル不変を確認する。
  **削ると:** 正常終了側の配線漏れを見逃す。**残すと:** 同じ正例のパラメータが一つ増えるだけで済む。

## brief への攻撃

- **scope 2／P3 は、未確認の故障形態を解決策に変えている。** 「signal で死んだ場合の後詰め」は必要性の実測ではない。ただし両 tool が明示要求なら、その要求を根拠として最小実装に留めるべき。
  **削ると:** 後詰めという説明を失う。**残すと:** 根拠の薄い救済拡張を正当化しやすくなる。

- **P2 への plan の異論は妥当。** 現行 parser は stage と sandbox を独立に受理する。author/fix と workspace-write の積で発火させる局所条件は、実装子という対象限定であり、新しい CLI gate ではない。
  **削ると:** 非実装 stage の workspace-write でも commit する。**残すと:** 発火条件と負例が一つ増える。

- **provenance の指示が brief 内で矛盾する。** 「実測値が確定できなければ unknown」と scope 4 の「requested に fallback」は同じ契約ではない。plan は後者を採用している。指定資料だけなら、確定済み事項として書かれた recorded→unknown に揃えるべき。
  **削ると:** requested 値による補完を失う。**残すと:** 要求値を実測値として扱う曖昧さと fallback テストが増える。

- **scope 3 の「小さな新 module」は落とせる。** plan の既存 `git_state.py` に一関数という選択で足りる。6 引数は具体的な commit metadata 用で、現案に将来拡張 option や汎用 framework はない。allowlist の4追加も説明上は各 Git 操作に対応している。ただし `git_state.py` 本文は今回の射影外なので、再利用可能性の独立確認はしていない。
  **削ると:** 配置の自由度を失う。**残すと:** 不要な module 境界を選ぶ余地が増える。

- **stdout 案に新しい保存 schema・台帳はない。** 一行の結果表示で足りる。`commit -F` 用一時ファイルは永続 sidecar ではない。固定書式を機械可読の別契約へ育てる必要もない。
  **削ると:** 結果の可視性を失う。**残すと:** 現案の一行表示程度で済む。

- **P5 は現状、scope を守っている。** 相互作用の worklog 記録に留まり、cleanup の rc=20 回避や祖先保持への変更は提案実装に入っていない。解決策追加は不要。
  **削ると:** 保存後に撤去拒否される相互作用の共有を失う。**残すと:** 既存 worklog の短い記録だけ増える。

## 推奨する plan v2 の最小形

1. 起動器の launcher 復帰後、author/fix＋workspace-write の残差を既存 module の一関数で commit。launcher 非0 rc を保持し、launcher 成功時の commit 失敗だけ失敗として返す。
2. **依頼の両 tool 解釈を保持するなら**、待ち手は明示 opt-in と既存 PID 死亡分岐だけに接続する。done 非空の別判定、check-only 書込み、done rc の再解釈を足さない。実際の opt-in 呼出し箇所を名指す。
3. 保存先 root、detached/main、mid-merge の局所 skip は残す。lock は Git の通常失敗へ集約し、rebase 等の拡張を外す。
4. 実 Git の正例に残差・二回目 no-op・identity・trailer・base patch 同値を集約する。別の負例は read-only、保存対象の限定、merge、commit 失敗を中心とする。
5. DW-S05-A は `<base>` 化と終端契約の一文だけを追加し、既存義務を保つ縮約で相殺する。

文書案は静的計数で **584→583 bytes、差分−1 byte** を確認した。brief の総量が正しければ **9,695 / 9,696 bytes**。所有 path 限定、隔離 session の `git -C` 禁止、`-b`、直前 midflight、非0停止、NOTE による anchor 再読、pin 行は維持されている。ただし終端文は実装に合わせて author/fix の限定を反映する必要があり、現案が最小 bytes とまでは言えない。

**削ると:** 過剰な故障対応と診断の細分化を失う。**残すと:** 明示された保存契約・不発火条件・patch 抽出の維持に必要な変更だけになる。

## 総括

最大の削減対象は、待ち手に付随した **done 判定・check-only 書込み・rc 再解釈**と、**lock 専用処理・未根拠の操作別 skip・重複テスト**である。

待ち手全体の削除は「終端＝子の走行終了時点」という解釈なら成立するが、両 tool の明示要求を保持するなら最小配線を残す。P5 と一行 stdout は過剰ではない。文書案の−1 byte は確認済み。実装・pytest は行っていない。
