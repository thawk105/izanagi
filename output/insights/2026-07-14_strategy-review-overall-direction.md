## 1. 結論 (3 分割の問いへの答え)

「CC の自動合成がうまくいきそうか」は 3 つに割ると答えが分かれる:

1. **「LLM が機械探索を性能で上回る CC を合成する」— 現在の土俵 (silo/YCSB) では構造的に不成立。**
   努力不足ではなく設計と土俵の帰結 (§2)。Phase 3 で LLM 合成が stock を between-run floor 超で
   上回った実証は 3 軸すべてで 0 件。floor 超の実測 (+61〜99%) はすべて機械列挙 sweep の成果。
2. **「AI の系 (LLM + 機械探索 + 検証防壁) がワークロード特化 CC を自動合成する」— 見込みあり。
   既に半分示されているのに主張として拾われていない。** D50 の「勝ち gate が workload 間で
   入れ替わる」は特化の実在証拠だが、看板の中核 8b (workload のループ入力化) が未配線のため
   主張に昇格できていない。
3. **「論文になるか」— なる。ただし当初野心より弱い形。** 方法論 + negative results + 空間外合成
   1 事例 (P2-4) + 信頼できる評価器という骨格は既に手中 (roadmap §8 の系譜 3 本目)。最大の空白は
   roadmap 自身が「差別化の決定打」と呼ぶ層 3 (説明生成) が driver 0 本のまま論文期に入ること。

「ドツボ」感は主観でなく客観的実体を持つ (§3 の工数実態)。ただし沈没ではなく、**投資先の
向け替えで抜けられる種類の停滞** (§5)。

## 2. 停滞の構造 — 3 つの噛み合った歯車

**歯車 1: 土俵の枯渇 (根因)。** silo/YCSB に「フラグ空間の外にあり、かつ LLM でしか見つからない
大きな山」が乏しい。3 軸の結末が同一方向を指す — backoff = スカラー軸適格性違反 (D44 追記 1)、
sort = floor 超地形なし = 死に軸 (D46)、trigger-gating = 偵察空間 = coder 変異空間で失敗条件 (c)
構造発火 (D48 決定 2 → D52 背景)。headline → 主張 S → 縮小 S' の後退は毎回この土俵側の信号に
押し出された**強制退却**であり、方針の迷走ではない (停滞構造レンズの最有力診断: 主張ドリフトは
土俵枯渇の症状)。

**歯車 2: 安全と価値の正面衝突 (設計のジレンマ)。** 偵察の完全性・リーク制御・reward hack 遮断の
要請を全部満たすよう変異空間を絞る (D48 決定 2: 構文契約 = 要因 enum + 定数のみ) と、空間が機械
列挙可能になり **LLM の探索価値が設計時点で構造的に消える** — 失敗条件 (c) の構造発火は事故で
なく必然。逆に空間を広げる (メンバ読取拡張・非列挙軸) と偵察の生死先取りが効かず、監査面と
正しさ攻撃面が開く。現設計では「安全に探索できる空間」⊂「機械で探索できる空間」となり、軸内
探索に LLM の出番が原理的に残らない。P2-5 (フラグ空間で誘導は貪欲に勝てない) のコード粒度での
再演。

**歯車 3: 手続きのラチェット (増幅器)。** 定量 (機構複雑性レンズ / 工数配分レンズの実測):
- 機構質量: orchestrator 非テスト ~15,000 行 + テスト 7,535 行 (413 本) + hooks 576 行 +
  docs 1.78MB (decisions 212KB / worklog 204KB)。防壁系だけで 4,000 行超。
- 探索の表現力: coder 編集面は 3 軸とも単一式 (スカラー 1 個 / comparator 本体 / bool 述語 1 行)。
  Phase 3 の合成総量 = **全軸合計で十数個の一行変異**。機構:探索 ≈ 1 万:1。
- 軸 1 本の固定費: 実測 ~5 セッション + 3 レンズ敵対レビュー (1 回 37〜38 万トークン) × 複数巡。
  段 8a は約 18 エントリを消費。
- iteration 律速: 機械 66〜175 秒に対し実間隔はその 10〜20 倍 (セッション運営)。
- worklog 78 エントリ中、実験の実体前進 (a) = 7 件 = **9%**。直近 5 日 (07-09〜13) は全エントリの
  67% (52 件) を占めながら心臓部 (合成 + 計測) 接触は **12%**、その実測もすべて null / floor 内 /
  探索枯れ / 非有意。実 CC 合成の最終実走は 07-12 (6)、以降 8 セッションは全てメタ作業。
- ラチェットの帰結: 最強の実結果 D50 (+61〜99% cross-run) は偵察 firewall と「非 LLM ベースライン
  で到達可能」条件により headline から構造的に締め出され、S-2 を救いえた探索的信号 (CC 本体換算
  p=0.115 → 0.0006) は HARKing 境界で封鎖 — **見つけた山を昇格できない構造**が完成している。
  (注意: この封鎖自体は事前登録規律の正しい作動であり、緩めてはいけない。問題は次の主張設計で
  同じ構造を再生産すること。)

補助病理 2 つ: (i) **計測順序の逆転** — 判定重心が性能次元 (S-1) と自認しながら弱い代理指標
(S-2/S-3 適格率) を先に実走して瓦解、S-1 は driver 未実装のまま。(ii) **「計測窓待ち」が実装
未了の隠れ蓑** (07-13 (11) 棚卸しで露呈)。

**07-12 の処方 (系レベル再構成) が防げなかった理由:** あの処方は土俵を広げず成功の定義を作り
替える手だったため、根因 (歯車 1) を温存したまま、対照アーム・canary・n 確定・事前登録改訂の
固定費 (歯車 3) を増やした。主張を 4 分解した 2 本 (S-2/S-3) は翌日に失効。**同型の手 (もう一段の
主張再構成) を次に選ばないこと**が最大の教訓。

## 3. 主要 findings (事実、一次資料ポインタ付き)

1. **Phase 3 で LLM 合成が stock を floor 超で上回った実証 = 0 件** (3 軸すべて)。sort の coder
   到達点は valid 12 点中 10-11 位、trigger-gating の LLM ループは +0.27% (floor 3.0% 内) で
   「帰属不能・探索停止推奨」。[2026-07-10_s6-sort-sweep-preliminary.md §5 / worklog 07-12 (6) /
   2026-07-11_s8a-trigger-gating-recon.md]
2. **D50 の +84.5%/+61.2%/+98.9% は vs ident_all の機械 sweep 成果** (ident_all ≈ 真 stock、骨格
   常駐コスト ±1.24% 以内 = floor 内)。10 点機械列挙・偵察カテゴリ・事前登録外。[同 recon insight]
3. **LLM ループは軸が生きる動作点で一度も走っていない** — 機械 sweep は 1M records/48thread
   (abort 41〜82%)、LLM ループは 100k/4thread (abort ~2.3%、gate が bite しない)。「LLM が負けた」
   のではなく「土俵に立っていない」(工程欠落)。[worklog 07-12 (6) / recon insight]
4. **balanced の最速点は g_none (backoff 全撤廃)** = 地形の主成分は gating の質でなく backoff
   総量の削減。best g_rl はその中で gate の質の信号。[recon insight 地形解釈]
5. **S-2 天井の主因は指標の弁別力不足** (main 20/20 vs C4 17/20)。CC 本体作用の要求項欠落で
   ハーネス提案 (WAL フラグ・thread affinity 等) 10 件が適格素通り。探索的換算 (C4=11/20) で
   p=0.0006 — 凍結判定に不使用 (HARKing 境界、正しい作動)。[2026-07-13_s6-rounds-content-analysis.md /
   s6-report-language.md §2]
6. **S-1 は「結果既知の登録追試」** (D50 を見た後の事前登録、confirmatory と呼ばない限定表現義務)・
   対象軸 n=1・既知軸集合は合成未探索の下界。成立しても headline は限定表現の束を伴う。
   [phase3-main-experiment.md 2026-07-12 追記 既知結果台帳・既知限界]
7. **三層アーキテクチャの実装被覆 = 層 2 のみ、silo 単一プロトコル** (CCBench 7 YCSB プロトコル中
   1)。層 1 (ベース選定)・層 3 (説明生成 = 差別化の決定打)・8b (workload 入力) は driver 0 本。
   coder は対象 workload を知らされずに合成している。[roadmap §1/§2 vs orchestrator/campaign/
   driver 一覧 / D44 ギャップ (ii)]
8. **工数実態**: worklog 78 エントリ中、実体前進 9% / 防壁実装 28% / 監査・レビュー・裁定 23% /
   協議・設計判断 24% / 文書・プロセス 15%。実 LLM 合成日 5 日・性能計測日 5 日 (15 日中 1/3)。
   複数 iteration が回った実走は 07-09 (3) の 1 回のみ。docs 整合監査の反復 ≥8 回。

## 4. 見落とされている光 (悲観の較正)

1. **山は本物** — trigger-gating の floor 超は 3 workload・cross-run 再現・勝ち gate の workload 間
   入れ替わり = **ワークロード特化の実在証拠**が既にある (D50)。
2. **LLM ループは敗北ではなく未戦** (finding 3)。
3. **S-2 の探索的信号** は「指標を直せば分離しうる」ことを示唆 (finding 5)。
4. **P2-4 は certified な正の実証 1 件** (真 stock 最良比 +39.0%/+12.9%。同一 boot・rounds=1 の
   留保付き)。
5. **評価器・防壁・監査文化は一級の資産** — 主張の縮小が正直に機能していること自体が方法論の
   健全性の証明であり、論文素材 (Jitskit/IDS 系譜の 3 本目)。

## 5. 提言 (拘束力なし、採否はユーザー裁定)

1. **S-1 は「安く完走」** — 手続きの増設なし (新レビュー層・新対照アームを足さない) で整地 →
   実走し、族判定表を閉じて段 6 を畳む。driver は既存 4 器から流用可、整地は計測ゼロで開始可能。
2. **段 6 完了後、「LLM vs 機械の統計的分離」という戦場から撤退する。** 列挙可能空間では原理的に
   勝てず (歯車 2)、非列挙空間では偵察不能で投資が博打。答えは既に持っている — 「軸内探索に LLM は
   不要、価値は軸発見と機序帰属にある。ただし適格率という代理指標ではその優越を示せなかった」=
   境界画定の貢献として報告する。
3. **浮いた投資を看板直結の 2 つへ向け替える:**
   - **8b (workload のループ入力化)** — D50 の gate 入れ替わりが有望性の既存証拠。主張形が有利:
     「系が workload ごとに異なる特化構成を自動発見する」は LLM vs 機械の分離を要求しない
     (機械 sweep も系の一部)。最小の一歩 = rr5/rr50/rr95 並走は既存の器で可能。
   - **層 3 (説明生成)** — 差別化の決定打が driver 0 本のまま論文期に入るのが現状最大の空白。
     素材 (WAL proof chain・機序帰属・insight 群) は成熟、**計測ゼロで進む** = 計測窓と競合しない。
     完了ラインは「主実験 WAL からの材料レポート自動射影 1 本」と定義済み (07-12 戦略レビュー)。
   - クロスプロトコル (S1 移植)・移植 b2 はこの 2 つの後。
4. **物語の再構成** — 「LLM が機械に勝つ」でなく「AI の系がワークロード特化 CC を合成し、なぜ
   速いかを説明する。その過程で LLM の要否の境界を誠実に画定した」。この形なら P2-5・S-2/S-3 の
   negative results は方法論の柱、D50 の山は「系の成果」として正面から使える。roadmap 改訂に
   相当するためセレモニー (roadmap-history/README.md) 経由。
5. **手続き固定費の運用上限** (絶対規律は不変) — 3 レンズ敵対レビューの適用を「新しい統計的主張・
   不可逆な決定」に限定し、可逆な作業 (報告文言等) は 1 レンズか事後監査へ。docs 整合の反復監査は
   check_docs の拡充で機械側へ移す。正しさゲートの話ではなく、レビューという有限資源の配分の話。

**総括:** このプロジェクトは「失敗しつつある」のではなく、**厳密さの機構が完成した結果、その機構が
要求する水準を満たせる主張が現在の土俵に残っていない**局面にいる。抜け道は主張をもう一段削る
ことでも規律を緩めることでもなく、機構をそのまま持って、主張が自然に立つ土俵 (ワークロード特化と
説明生成) へ移ること。
