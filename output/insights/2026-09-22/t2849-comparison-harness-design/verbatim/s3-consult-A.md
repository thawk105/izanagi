## 所見

参照略号: `brief.md`・`skeleton.md`・`facts.md` は指定された job directory 内。`B5` は `docs/b5-generator-contrast-preregistration.md`、`IR` は `output/insights/2026-09-21/silo-function-synthesis-space/README.md`、`gap` は `output/insights/2026-09-21/vldb-direction/gap-analysis.md`。以下は静的点検のみで、実装・テスト・計算は行っていない。

**A1・must-fix・対象 P3／骨子 §1・§3：支持集合の差を許すなら、純粋な探索法比較とは呼べない。**

- **確認済み:** sweep／BO は固定 template の像、他の三手法は IR 全体を探索する。共通 admission は成立しても、到達可能な最良値は揃わない。B-5 もこの条件では「異なる選択方策を持つ、凍結した生成器」の比較と限定している。
- **根拠:** `skeleton.md:8,27-30`、`B5:89-91`、`IR:405-406`。
- **放置時の影響:** template 外の解による勝利を探索アルゴリズムの優越として報告し、比較 A に表現制限の効果が混入する。
- **修正案:** 主比較を全 arm 共通 template 内にするか、現案を「支持集合の制限を含む構成比較」と明記する。後者でも比較 B の自由 C++ 拡張とは別物だが、純粋な探索法の効果は分離できない。template の選定時点・根拠も固定する。

**A2・must-fix・対象 P5／骨子 §5：「同じ観測情報」と「同じ記録を保存する」が未分離。**

- **確認済み:** 非 LLM は fitness／有効性のみを使い、LLM は構造化 anomaly・leading indicators・critic 診断を利用できる。さらに S1 の表には K2 または知識なし版が残り、主比較 K0 と一意に繋がっていない。
- **根拠:** `brief.md:29`、`skeleton.md:25,41-43`、`B5:49-50,173-188`。
- **放置時の影響:** 情報の利用方針・critic・生成器の効果を、LLM 単体の効果へ誤帰属する。
- **修正案:** 「全 arm が利用可能な共通入力」と「各アルゴリズムが実際に消費する field」を分けて列挙する。非 LLM の非利用は方式の定義として許せるが、結果はその定義を含む構成比較とする。critic 診断の生成元を自系列の許可情報に限定し、主比較の LLM は K0 に一意化する。K0 は「外部の実験知識射影なし」であり、モデルの事前学習知識なしとは意味しない。

**A3・must-fix・対象 P6／骨子 §5：共通初期候補の費用・観測共有・endpoint 資格が未確定。**

- **確認済み:** 初期 k 件を B 外に置く一方、BO の追加初期 design／進化の残りの個体群は B 内。初期候補を endpoint に選べるか、全系列で独立測定するか、共通測定値を配るかは明示されていない。「初期 3＋探索 8」は一次資料では試走の費用換算で、一般的な予算契約ではない。
- **根拠:** `brief.md:30`、`skeleton.md:45-46`、`IR:411-415,448-449`、`B5:297-300`。
- **推測:** 初期測定を共有すれば系列間に依存が生じる。別々に測れば同じ候補でも観測値は異なる。既知の良い初期候補を endpoint に許すと、探索前から達成済みの利得が曲線を支配しうる。
- **放置時の影響:** 「B 回の探索成果」が、無料の初期成果や手法ごとの初期化支援量によって変わる。
- **修正案:** 共通候補列を各系列で fresh に測り、全観測を初回 ask 前に渡す案を推奨する。B は「追加探索評価数」、総評価数は k＋B と明記し、初期費用を時間軸から除かない。初期候補の endpoint 資格・失敗時の扱い・手法固有初期化の費用を固定する。BO／進化への初期観測の利用を認め、LLM にも同じ初期履歴を渡す。
- **参照点の補足:** 空間外の `p2_2_flag_opt` は報告用対照と初期参照観測として区別し、BO の訓練点・探索 endpoint に入れない。BACK_OFF=0 を log v=0 等へ写像してはならない。目標水準による停止も禁止する。参照を渡す／渡さないの二案は `brief.md:30` と `skeleton.md:45` で揺れており、主構成を一つ選ぶ必要がある。

**A4・must-fix・対象 P7／骨子 §2・§6：無料の内部選び直しの境界が広すぎる。**

- **確認済み:** 骨子は「測定を使わない決定的計算」を無料とするが、B-5 は提出前の候補選び直しも A 消費とする。B-5 の乱数偏り除去だけは明示的な例外である。brief の「候補を返した回数」と骨子の「ask 回数」も一致していない。
- **根拠:** `brief.md:31`、`skeleton.md:14,52-53`、`B5:109-119,204-209`。
- **推測:** 決定的な compile・静的正しさ検査まで「測定なし」に含めれば、機械手法だけが失敗候補を無料で捨てられる。LLM の planner／coder／critic を各一 ask と読む余地もある。
- **放置時の影響:** A と有効候補率が手法ごとに別の量になり、正しさ失敗を予算外へ押し出せる。
- **修正案:** 無料範囲を獲得関数最適化・事前定義した型を保つ構成・乱数偏り除去などへ限定する。具体候補への compile／smoke／verify、結果を見た修復・再生成は共通の費用境界内に置く。A は空出力・不正出力を含む一候補提出機会とし、LLM の役割呼出数は別計上する。A 上限を全 arm に必須とし、B 未達系列を残す。Tier0 の compile 失敗が A のみなのは、この有限 A と実費計上があって初めて整合する。

**A5・must-fix・対象 P1・P5／骨子 §2：自系列限定という契約だけでは、親の射影と設計時の漏れを閉じない。**

- **確認済み:** ask の入力制限はあるが、LLM の親が参照する資料・初期 context・critic の入力範囲が列挙されていない。B-5 は fresh context、親の追加助言禁止、各役割の実入出力保存まで明記している。
- **根拠:** `skeleton.md:14,17,42`、`B5:164-171`、`orchestrator/critic/online_digest.py:7-18,35-41`。
- **推測:** 共通 WAL／sidecar producer が他系列を読める場合や、親が偵察結果を知った context で自由文を合成する場合に漏れる。producer と同じ記録を照合するだけでは独立な漏れ検出にはならない。
- **放置時の影響:** 「自系列のみ」が保存形式の性質に留まり、入力漏れを否定したという［恒真ゲート］が再発する。
- **修正案:** 新 gate を足さず、既存入力契約に読取範囲と射影元を明記する。初期 stock／seed／許可した reference を例外入力として列挙し、他系列・floor・endpoint 再計測・偵察・既知結果文書を実行時入力から外す。親は機械的射影だけを行い、役割 context と実入出力を分離保存する。「保存した」ことを「他の情報を見ていない証明」とは呼ばない。

**A6・must-fix・対象 P8／骨子 §7：全系列への anomaly 波及と、自系列限定の情報契約が接続されていない。**

- **確認済み:** 再利用対象の B-5 endpoint 規則は、他 arm／他系列で見つかった anomaly でも同候補を全系列から失格にする。一方、確認した `run_series` の失格集合は自系列の evaluations から作られている。
- **根拠:** `skeleton.md:14,60`、`B5:302-306,316-320`、`orchestrator/campaign/b5_generator_contrast.py:815-816`。
- **放置時の影響:** 全体失格を生成器へ返せば他系列情報が漏れ、系列内処理だけを再利用すれば既知 anomaly 候補の score が残る［consumer 取り残し］になる。
- **修正案:** 生成履歴への tell と、最終採用資格の判定を分離する。後者は他系列由来の anomaly も同じ identity／workload へ波及させ、履歴は保存するが生成器へ他系列の診断を還流しない。既知失格候補の再提案に対する共通の拒否・費用・返却分類を明文化する。集約担当は本基盤側で決め、系列単位コードが全体規則を実装済みとは扱わない。

**A7・must-fix・対象 P7・P8／骨子 §6・§7：時刻を残すだけでは、費用曲線と統計単位を再現できない。**

- **確認済み:** 骨子は node 秒と LLM wall を別軸にするが、一次依頼の P3 は経過時間比較も求める。slot の Elapse だけでは非 LLM の生成計算、初期化、共有対照、並列占有、待機の算入規則が決まらない。
- **根拠:** `skeleton.md:50-56,60`、`gap:109-115`、`IR:453`、`B5:308-320`。
- **放置時の影響:** 後から都合のよい時間原点・費用範囲・打切り処理・評価 checkpoint を選べ、［測定の交絡］が生じる。
- **修正案 — 本 wave で固定:** 独立探索系列を統計単位とする。rep・session・endpoint 再測定を独立探索数に数えない。共通 block stock／共有初期値があれば依存を明記する。生成を含む費用範囲、時間原点、候補の開始／完了／結果利用可能時刻、締切を跨ぐ候補、欠測・A 枯渇・fallback、endpoint 選択・tie-break・再計測分離の意味を定義する。node 秒と経過時間は別の量として残す。
- **修正案 — T-2850 に残す:** B・A・k・系列数・費用上限・checkpoint の実値、主 endpoint／曲線要約、対比較の族、多重性、同等幅、割当順・block 設計。これらは新 cohort の結果を見る前に登録する。B=10 や N_eval=5 を継承するなら、その選択も明示する。

**A8・must-fix・対象 P1・P8／骨子 §2・§9：S1 の proposal 契約を S3 の共通入口として一般化している。**

- **確認済み:** 骨子は planner／coder／prior_critic_reverse の閉じた schema と単一 loop を示す。しかし S3 一次設計は planner を外し、LLM×IR を IR JSON として共通 renderer に通す。auditor は LLM 由来だけに課される。
- **根拠:** `skeleton.md:15-16,73-78`、`IR:367-382`、`orchestrator/campaign/b5_generator_contrast.py:139-151`。
- **放置時の影響:** IR の identity・受理・auditor 費用が adapter に隠れ、「同じ口」が見かけだけになる［consumer 取り残し］。
- **修正案:** 共通化するのは候補 identity・評価要求・結果・費用の契約とし、S1 scalar／S3 IR の入力 adapter を区別する。S3 の追加 auditor は正しさ契約上の差として保持し、その拒否を A／B のどちらに置くかと費用を定義する。全候補が文字通り同一の役割経路を通るとは書かない。

**A9・should・対象 P3・P4・P6／骨子 §3〜§5：設計時の既知結果利用が random 以外で開示されていない。**

- **確認済み:** log v、GP の定数、変異方式、template、初期 5／10 µs を採用するが、選択時に見た結果との対応がない。B-5 は random 分布と sweep 格子についてこの対応を明記している。

- **推測:** BO の length scale／noise、進化の変異幅、template、seed を既知の地形へ合わせれば、実行時 K0 でも実験設計は結果既知である。
- **放置時の影響:** K0／open-loop を「結果を知らずに設計した中立な対照」と誤読させる。
- **修正案:** 新台帳を増やさず、設計文書に各選択の根拠・閲覧済み結果・採用時点を短く記す。試走で調整する範囲と本比較からの分離も定義し、結果を見て最良の設定だけを主比較に選ばない。

**A10・should・対象 骨子 §1：「主張しない」の限定が不足。**

- **確認済み:** 必要性・非 LLM 一般・コード合成一般への拡張は否定しているが、構成要素の因果分離、他 workload／protocol／環境、費用軸の違い、certified の有限性は列挙していない。

- **修正案:** 以上の限定を追加する。特に「共通初期情報・登録した支持集合・固定予算・指定 workload 下の構成比較」であり、LLM／critic／知識それぞれの因果効果や、未知条件への転移をこの比較だけでは示さないと明記する。

**A11・should・対象 facts.md／骨子 §4：確認範囲の限定が設計の断定へ引き継がれていない。**

- **確認済み:** facts の実装不在は orchestrator／tools の識別子検索、package 不在は login の特定 interpreter、計算ノードは未測定である。骨子では「repo に実装 0 件」と断定し、標準ライブラリ再実装へ繋げている。これらは facts 上も［親］の確認ではなく［子］報告である。
- **根拠:** `facts.md:3,26-27`、`skeleton.md:34-36`、`brief.md:28`。対して［親］の機械 proposal 制限は `facts.md:7` と実コード `orchestrator/campaign/b5_generator_contrast.py:139-151` が一致する。
- **放置時の影響:** 限定的検索を実装不存在の証明にし、弱い再実装を BO／進化一般の代表として扱う［設計調査漏れ］になる。

## 反証済み

- 同一候補の fresh 再評価に A・B を課す方針自体は B-5 と整合する。重複を無料の新規評価にする案ではない（`skeleton.md:51`、`B5:93-95`）。
- stock と BACK_OFF=0 の `p2_2_flag_opt` を区別している点は正しい。ただし入力用途と採用資格の固定は A3 のとおり必要（`facts.md:18-19`、`B5:262-264`）。
- B-5 の cohort と新比較の標本を混ぜず、旧三 arm の検定規則を流用しない方針は明示されている（`skeleton.md:62`）。
- anomaly による reject と trace-disabled 性能測定を維持する方針は明示されている。問題はその予算・集約上の具体化である（`brief.md:15`、`skeleton.md:16,53`）。
- MOCC を pin 前進前に実在する比較空間として扱わず、既存の小規模 certified 実績を本比較の保証にしない留保は存在する（`skeleton.md:66-68`、`facts.md:39`）。

## 総括

must-fix は **8 件**。正しさゲートの緩和ではなく、入力・費用・採用資格の契約を具体化する修正が必要。
親の択一は、①全 arm 共通 template の探索法比較／支持集合差込みの構成比較、②共通初期 k 件を総予算内／追加探索 B 外として実費込み、③既知 reference を全 arm の入力にも渡す／報告用対照に限定、の三つ。
B・系列数・時間上限・検定族の実値は T-2850 へ残せるが、それらの意味と打切り・endpoint・共有観測の扱いは本 wave で固定する。
