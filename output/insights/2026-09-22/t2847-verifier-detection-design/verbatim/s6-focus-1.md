## 新しい所見

1. **[must-fix] §1 結論2・§3 B06／集計・§5.2「未被覆の3案だけ」 — B06 型の巡回は既に trace 入力で使われている —** `test_verifier.py:2484-2503` の `_ordinal_witness_trace()` は、T1 が T8 の書いた cc を読み、T8 が T1 の書いた aa を読む履歴を組み立てる。両 key に後続版はなく、`1→8` と `8→1` は wr だけである。さらに T1 と T16 にも wr の往復がある。`:2506-2530` の test は実際にこの trace を verifier に渡し、巡回 `[1,8]` を期待している。したがって「G1c 型の巡回を trace 入力で与えることが未被覆」は誤り。一方、この test は分類を独立に `"G1c"` と固定していない — **B06 を「既存 trace 入力あり・分類の独立期待値の追加候補」と直す。** 現行の意味被覆基準で inline 被覆済みに移すなら集計は **13／10／2／2**。分類 assert の不足を別に記載し、§1・§5.2・§8も揃える。
