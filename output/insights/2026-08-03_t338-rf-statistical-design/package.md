## 0. まず伝えるべきこと — 裁定 (121) の前提が 1 つ足りなかった

裁定 (121) は **「RF 統計設計のうち paired session 差による floor の取り方を正例より先に裁定する。
残る統計設計 4 点も同じパッケージで提示する」**だった。本 wave はそのパッケージを起草したが、
**独立に走らせた敵対レンズ 2 本が、そろって「5 点だけでは閉じない」と判定した。**

理由は 1 行で言える。**floor が何を守る線なのかは、RF をどの母数として定義するかが決まらないと
定まらない。** 具体的には:

- `RF = E[N]/E[D]` (session ごとの差の平均の比) と `RF = E[N/D]` (session ごとの比の平均) は
  別の量である。前者は劣化幅の大きい session を重く数える。
- 分母の識別を「0 より大」で見るのか「実用上の最小幅 `δ_D` より大」で見るのかで、
  floor が超えるべき対象そのものが変わる。

したがって **floor 単独の先行裁定は実行できない。** これは裁定 (121) の否定ではなく、
**それを実行するために必要な前提が 2 つ手前にあった**ということである。親の見落としであり、
本パッケージは 5 点を **11 件の裁定項目**へ組み替えて提示する。

**変わらないこと:** 本 wave は docs のみで、コード・gate・凍結 bytes・certified 選択・
材料レポート・proof chain を 1 byte も動かしていない。Phase 2 の `compare()` Gate1 の
√2 保留も**動かしていない** (両レンズが「別件に保つ判断は正しい」と一致した)。

## 2. 前提の 2 件 (5 点の外だが、5 点を支配する)

### Q1. RF の推定量をどちらにするか

`N_j = m_X,j − m_D,j`、`D_j = m_S,j − m_D,j` (j = 独立単位、m = arm の代表値) としたとき:

- **(a) 総回復率** `RF = E[N_j] / E[D_j]`
  「対象環境全体で、失われた throughput のうち何割を取り戻したか」。
  `E[N]/E[D] = E[r_j D_j]/E[D_j]` なので、**劣化幅 `D_j` が大きい session ほど重く数える**。
- **(b) 典型 session の回復率** `RF = E[N_j / D_j]`
  「1 つの session を取ったとき、平均してどれだけ回復しているか」。session を等重みにする。

両者は `r_j` と `D_j` が相関すると一致しない。

**推奨は (a)。** RF は「劣化を埋め戻した割合」を系全体の量として述べる指標であり、
劣化が大きい局面での回復の方が物理的意味が大きい。ただし **session 間の異質性を等しく扱いたい
なら (b) が正しい**ので、これは目的から決まる裁定である。
どちらを採るにせよ、「事前登録した session 母集団」が node・時刻・allocation のどの分布を
指すかも同時に固定する必要がある。

**成果物影響:** session ごとの劣化幅が変動すると、**同じ raw 値から RF 点値・境界分類・
材料レポート記載値が変わる**。

### Q2. 最小識別幅 `δ_D` と primary endpoint

分母の識別を `E[D] > 0` で判定するか、`E[D] > δ_D` (実用上の最小幅) で判定するか。
`δ_D` を置くなら、単位 (絶対 tps か stock 比か)、workload 共通か別か、変更手続きを決める。

**推奨:** `δ_D` を置き、**stock 比の相対量として workload 別に事前登録**する。
理由は、絶対 tps は workload 間で 2 桁違う (実測で W1 は 10 万台、W2 は 100 万台) ため
共通の絶対値が意味を持たないこと。primary endpoint は **trace-disabled の
`throughput_tps` 1 本**に固定し、abort 率等は説明用の副次指標として RF の family へ入れない。

**成果物影響:** `δ_D` の選び方だけで**正例の成立/不成立が反転する**。ノイズ量と混ぜて
1 つの数にすると、後から「どちらの理由で落ちたか」が言えなくなる。

## 3. 点 ③ — floor (裁定 (121) が名指しした中心)

### Q3. floor の種類

- **(a) 第 3 の scalar floor を新設する** — 既存の within-run / between-run に並べて
  「paired floor」を足す。`docs/roadmap.md` §3.6(3') の改訂と、D19 の適用前提の明示的な限定が
  **原子的に**必要になる (下記「手続き上の注意」)。
- **(b) 既存 unpaired between-run floor (`BETWEEN_RUN_CV = 0.030`) をそのまま使う** —
  paired の利得を捨てる。手続きは最も軽い。
- **(c) scalar floor をやめ、同時信頼領域で判定する** — paired contrast の cluster-level 標準誤差と
  多重性調整済みの信頼限界を RF 専用の名前空間で定義し、判定は
  「gap > floor」ではなく「信頼下限 > `δ_D`」で行う。

**推奨は (c)。** 理由は 3 つある。

1. **(a) は「floor」という 1 つの数に、性質の違う 2 つの役目 (物理的な散布と判定の余白) を
   混ぜてしまう。** 段 2 とレンズ A が独立に、この 2 つを別 field に分けるべきだと指摘した。
2. **(b) は使えない。** 既存の 3.0% は「variant と baseline を別 session で測る」設計を前提にした
   周辺 CV であり、同一 block で 3 arm を測る RF の誤差構造とは別物である。
3. **(a) を採っても、値をどう決めるかで詰まる。** 後述の erratum のとおり、親が当初推した
   「fresh 下限と別時間窓の値の最大を取る」という既存手続きは、統計的な上側限界ではない。

**注意 (レンズが refuted としたので、心配しなくてよいこと):**
floor による丸めと検定を AND で直列に置くこと自体は、型 I 誤りを増やさない (受理集合が
検定側の部分集合になるだけで、通常は保守側へ寄る)。問題になるのは、floor を通過した後だけ
報告対象や family を変える**選択推論**である。

**手続き上の注意 (重要):** どの案でも、**RF の paired 化は D19 と roadmap §3.6(3') が置いた
前提 (「variant と baseline は決して同一セッションで測らない」) の例外を作る。**
`docs/decisions.md` D104 は先例として引けるが、**supersede の根拠にはならない** (射程が
受入全走施策の一次証拠に限られる)。したがって採用するなら、**roadmap §3.6 の改訂と D19 の
適用前提の限定を、この裁定と同じ変更単位で行う**必要がある。roadmap は戦略層なので、
ユーザーと合意した協議改訂の手続き (`docs/roadmap-history/README.md`) に従う。

**成果物影響:** 同じ raw 値を既存 3% と新しい判定余白のどちらで見るかで、**正例の成立と
certified 選択の受理集合が反転する**。

### Q4. 独立単位をどう取るか — G12 との衝突

段 2 は「各 session を別 allocation にする」案を出したが、Pegasus の campaign 契約は
`single_process=True / allow_resume=False` (G12 = campaign を単一 allocation/node/process で
完遂する) である。**素直に複数 allocation を跨ぐと、この契約を破る。**

- **(a) G12 を supersede する** — 1 trial が複数 allocation を跨ぐことを認める。
- **(b) 1 allocation = 1 immutable subcampaign とし、新しい trial aggregator が束ねる** —
  G12 は各 subcampaign に対して保たれ、cluster 間成分の標本化は trial 層で行う。
- **(c) 単一 allocation の fresh 下限 + 事前固定した cross-campaign 系列** —
  本数・時点・集約規則を実走前に固定する。いずれにせよ新規データ取得が要る。

**推奨は (b)。** G12 の目的は「途中で kill された数値を採らない」ことであり、これは
subcampaign 単位で保てる。(a) は防壁そのものを弱める。(c) は集約規則が経験則へ戻りやすい。

**あわせて 1 つ縮約する。** 親は当初「別 allocation でなければ D19 の再演になる」と書いたが、
これは強すぎた。**allocation ID は独立性の必要十分条件ではない** — 同一 allocation 内でも
十分離れた無作為 block なら独立近似は成り立ちうるし、別 allocation でも同じ node の連続時間窓なら
相関しうる。**独立単位は対象母集団と相関構造から定義し、node / 時間窓を cluster として数える。**

**事実 (変わらない):** 現存する唯一の 3 arm データ
(`output/env/pegasus/t139-positive-control-probe/0_877859.nqsv/`) は **1 job = J=1** であり、
**cluster 間の paired 分散はここから 1 点も推定できない。** どの案でも新規取得が要る。

**成果物影響:** これが決まらない限り、**正例 artifact は生成経路そのものを持たない。**

### Q5. 標本数 J と検出力 — これは費用の裁定である

段 2 は「16 独立 session」を最小と置いたが、これは標準偏差の推定精度から選ばれた値で、
**検出したい効果量と目標検出力から導かれていない。** レンズ A の概算:

| 前提 | 必要な cluster 数 (概算) |
|---|---:|
| 片側 IUT、各成分 α=.05、極端に整った符号 | 5 |
| 片側 sign-flip + Holm 6、同上 | 7 |
| 片側 α=.05/6、検出力 80%、標準化効果 d=1.0 | 約 11 |
| 同 d=0.8 | 約 17 |
| **同 d=0.5** | **約 42** |
| 6 成分の同時検出力 80% を union bound で確保、d=0.5 | 約 49 |

**J=16 は d≳0.81 の大きい効果しか 80% で拾えない。** 中程度の回復 (d=0.5) を拾いたいなら
40〜50 cluster が要る。上表は正規近似による楽観的下限で、小標本補正・carry-over・欠測は
まだ入っていない。

- **(a) pilot を先に取り、covariance と効果量から J を設計する (二段階)**
- **(b) J を固定値で決め打つ**

**推奨は (a)。** ただし **「どの効果量まで拾いたいか」はユーザーの裁定である** — ここが
そのまま計算資源の費用になる。d=1.0 で足りる (= 大きい回復しか主張しない) と決めるなら
11 cluster 規模で済む。

**成果物影響:** J が足りなければ正例は恒常的に判定不能になり、結果を見てから J を足せば
受理集合の事後変更になる (D126 決定 (4) が禁じた型)。

## 4. 残る統計 4 点

### Q6. 点 ① — 帰無分布

**論点:** 「差がない」をどの確率モデルで表すか。段 2 は「session 内で arm を測定位置へ無作為
割付し、同じ割付制約で帰無分布を作る」restricted randomization test を推した。方向は妥当だが、
**有限標本で厳密なのは Fisher の sharp null (誰の値も一切変わらない) に対してだけ**であり、
実際に検定したい weak null (平均効果が 0 以下) には漸近的な妥当性しかない。studentize しても
これは変わらない。

**さらに実データで 1 つ判明した。** 現存 probe の W1 では、`shuf` を使ったにもかかわらず
**stock が position 3 に 3 回・position 1 に 2 回・position 2 に 0 回**と偏っている
(`order.tsv`)。無作為化は「実現した balance」を保証しない。

**推奨:** (i) 割付可能な schedule の集合、(ii) 位置と一次 carry-over の balance 条件、
(iii) washout 規則、(iv) sharp null と weak null のどちらを primary にするか、を事前登録で固定する。
weak null を primary にするなら、**cluster 数での型 I 誤りを事前 simulation で較正する**。

**成果物影響:** raw 値が同じでも帰無分布が変われば調整済み p が変わり、正例の pass が反転する。

### Q7. 点 ② — 多重比較 family

**論点:** 何を 1 つの family と数えるか。段 2 は「全 workload × 全 contrast」の 6 仮説に Holm を
推したが、レンズ A が構造的な指摘をした — **主張が「全 workload で全条件が同時に成立」という
1 つの連言なら、各成分を α で検定するだけで偽の全体受理は α 以下に収まる** (intersection-union)。
Holm は有効だが目的に対して過剰に保守的である。加えて `D = N + G` なので、3 つを独立な family
member のように扱うのは論理構造を無視している。

逆に、**結果を見ながら候補を差し替えて最後の成功だけを certified にする経路には、Holm では
足りない。** 新しい trial ID を発行するだけでは多重性はリセットされない。

**推奨: 主張の型ごとに 3 つに分ける。**
1. **全体の `all_pass` 1 本だけを主張する**なら intersection-union (補正不要)。
2. **workload 別・cell 別の主張も公表する**なら Holm または closed testing。
3. **候補系列**には、最初の実走前に固定した親系列 ID・累積 alpha 台帳・spending 関数・
   候補数の上限を置く。

**BH (FDR) は採らない** — FDR は発見集合中の偽陽性の割合を管理する手続きであり、
「1 つでも偽の certified artifact が入る確率」を制御しない。この点は段 2・レンズとも一致した。

**成果物影響:** family を狭めると偽の正例が増え、広げすぎると正例が不必要に減る。

### Q8. 点 ⑤ — 選択的欠測

**論点:** 欠測をどの単位で落とし、どこまで置換を許すか。**ここは規律 2 に直結する。**
親の当初案 (「部分欠測なら session ごと落とす」) は、**arm 固有の timeout や verifier anomaly まで
session 削除で消せてしまう**。これは「正しさゲートを緩める」経路そのものである。

さらにレンズ A の指摘 — 完全 session だけを残して予備 session で置換しても、
**欠測が結果に依存している (遅い arm ほど落ちる) 限り、残った分布は選ばれたままである。**

**推奨: 3 つを閉じた表にする。**
1. **correctness anomaly は「欠測」ではなく候補の終端 reject。** 削除も置換もしない
   (規律 2 の「anomaly を検出したら即 reject」をそのまま適用する)。
2. **結果を見る前に外部証拠で確定する infra failure だけ**、事前に順序を固定した予備から置換可。
3. **走り始めた後の性能側の欠測は、既定で reject または判定不能。** 救済したいなら
   worst-case bound と、欠測が結果依存だった場合の感度分析を併記する。

全 attempt と全欠落を registry に残し、材料レポートへ出す (proof chain の全件性)。

**成果物影響:** correctness 不合格の arm が解析集合から静かに消えると、
**失敗した候補が再試行経由で正例・certified 選択へ入る。**

### Q9. 点 ④ — 区間推定と `RF<0` / `RF>1` の帰属

**論点 3 つ。**

1. **区間の作り方。** 比の区間なので、**Fieller を primary** に置く (分母が弱いときに
   非有界や不連結の集合を返せることが、むしろ正しい診断になる)。bootstrap を primary にすると、
   分母 0 の近傍でも見かけ上有限の区間を返してしまい被覆が壊れる。
   親は当初 bootstrap を primary に推したが、段 2 とレンズ A の論証に従い **Fieller primary へ改める**。
   検定反転や block bootstrap は事前登録した感度分析に回す。
2. **分母 screening をやめる。** 既存の暫定規則は「分母が識別可能になるまで RF は未定義」だが、
   母数 `μ_N/μ_D` は真の `μ_D ≠ 0` なら定義されている。標本から 0 と区別できないことは
   「未定義」ではない。しかも**同じデータで分母を screen してから RF を報告すると、
   報告される集合は分母が偶然大きい標本へ偏る** (選択後推論)。
   **推奨:** `N̄`・`D̄` と条件付けない信頼集合は常に出し、状態名を
   **`weak_denominator_not_certifiable`** (弱い分母のため認証不能) とする。
   認証は `D > δ_D` かつ `N > 0` かつ `G > 0` の同時信頼領域で行う。
3. **境界の帰属。** clamp はしない。**`RF > 1` を「回復」とも「新規改善」とも帰属させない** —
   「stock 超過」とだけ述べ、機序の帰属は別証拠 (機序 + ablation) を要求する。
   分類は点推定ではなく**多重性調整済みの信頼集合全体**で行い、
   **有界 / 非有界 / 不連結 × 0 と 1 の境界の全組合せ**を閉じた表で覆う
   (段 2 の分類規則は非有界・不連結の一部を覆っていなかった)。

**成果物影響:** 見かけ上有界な区間で `partial_recovery` が過剰に付与されると、
複数 workload の proof chain が名目の被覆率を名乗れなくなる。

## 5. 横断の 2 件

### Q10. 事前登録の方式

段 2 は D116 方式 (git に commit した 1 枚の文書 + ancestry で先後を証明) をそのまま使い
「追加の凍結機構は不要」と書いたが、**D116 の射程は 8c 正式系列であり、RF への拡張自体が未裁定**である。
加えてレンズ A の指摘 — **ancestry が示すのは「事前登録 commit が結果 commit より先」までで、
外部の raw 値が事前登録より前に生成・閲覧されていないことは示さない。**

- **(a) D116 方式を RF へ拡張する** — ただし measurement-start receipt (実走開始を事前登録
  commit へ束縛する受領証)、全 attempt の双射、親系列 ID を一体で要求する。
- **(b) RF 専用の凍結機構を新設する。**

**推奨は (a)。** ただし「拡張する」ことを明示的に裁定する。なお **既存 8c ですら成果物への
事前登録 commit の束縛は未実装**であり、これは実装 scope に入る。

### Q11. gate の実体化 — 誰が何を実装するのか

**現状では、上記のどれを裁定しても成果物は 1 byte も変わらない。** RF を消費する経路が無いからである。

- 適格性を宣言する権威は [T-337] で未裁定のまま。凍結 ledger は今も
  recovery/pipeline 不適格を厳密に要求している。
- 層 3 レポートは既存 campaign の既知 stage を射影するだけで、RF session・欠測 registry・
  p 値・信頼集合・受理状態のいずれも読まない。
- **`pairing_valid` や `rf_acceptance_status` を producer の自己申告 field にすると、
  D127 が既に裁定した「自己申告は検出器でも意味 gate でもない」型の恒真 gate になる。**

**推奨:**
1. **状態は独立 validator が raw receipt から再計算する。** allocation 受領証・raw run・schedule・
   測定 checkout・理由コードから導出し、validator の identity と再計算結果を成果物へ束縛して、
   宣言値との不一致を拒否する。
2. **層 3 の calibration floor 閉表を広げる形は採らない。** 層 3 の floor 検索は
   `(records, threads, workload)` だけで照合するので、候補や contrast ごとの trial 固有統計を
   同じ表へ入れると識別できない。RF 統計は
   `trial × candidate × workload × contrast` を key とする別区画へ置く。
3. **後続 scope を [T-339] の中身として起票する:** 計測 producer / attempt registry /
   schedule validator / RF calculator / [T-337] の適格性権威 / 層 3 の次版 /
   selector・材料レポートの consumer / 双射・変異検査。

**成果物影響:** これが無ければ裁定しても成果物は変わらず、逆に自己申告をそのまま繋げば
権威境界を迂回する経路ができる。

## 6. 親の誤りの訂正 (この wave で反証されたもの)

裁定の材料として、親がこの wave 中に書いて**実データで反証された**ものを明示する。

1. **「paired にすれば floor は小さくできる」は撤回する。**
   `Var(A−B) = Var(A) + Var(B) − 2Cov(A,B)` であり、既存の calibration JSON は
   **covariance を 1 つも持たない**。正なら縮むが負なら増える。方向は未知である。
2. **「abort 率が高いほど run 間ドリフトが大きい」は撤回する。** 実測は逆を含む —
   abort 81.95% の write-heavy が CV 0.666%、abort 70.47% の balanced が CV 1.067%。
   3 workload 各 1 系列では単調性も因果も識別できない。
3. **「fresh 下限と別時間窓の値の最大を取る」(既存 floor の手続き) を RF へ移す案は撤回する。**
   独立な分散成分なら合計は `√(σ₁²+σ₂²)` で max より大きく、同じ量の推定 2 つの max にも
   所定の被覆はない。**既存の 3.0% がこの経験則の産物であるという事実認定は維持する。**
4. **「paired 前提が崩れたら unpaired へ戻す」は撤回する。** 負 covariance では unpaired の
   式が真の差分散を**過小評価する**。正しくは `pairing 不成立 ⇒ 判定不能` である。
5. **「D104 が paired を承認済みの型として挙げている」は縮約する。** D104 の射程は
   受入全走施策の一次証拠であり、RF floor の既裁定変更ではない。
6. **「別 allocation でなければ D19 の再演」は縮約する** (Q4 に記載)。事実認定は維持する。
