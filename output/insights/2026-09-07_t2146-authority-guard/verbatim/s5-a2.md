## 実装した内容

[hooks/guard_write.py](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t2146-guard-author/hooks/guard_write.py) に以下を実装した。

- A1 と同名の固定定数 `_AUTHORITY_ROOT`、境界付き `_AUTHORITY_LITERAL_RE`
- A1 と同名の `_authority_path_violation`
- lexical・canonical・path 要素境界による発行主体 root/子孫判定
- `_HooksInodeIndex` と同型の regular-file inode 索引
- `decide()` ごとに authority index を一度だけ生成
- `classify_path()` の `_protected_hooks()` と同列に authority deny を追加
- Write / Edit / MultiEdit / NotebookEdit の root・子孫拒否
- apply_patch の Add / Update / Delete / Move to 両方向の拒否
- Delete / Move 元は authority 判定だけ `resolve_final=False` とし、外部 symlink entry 自身を許可
- `main()` 例外 fallback に境界付き authority literal 判定を追加

## 反実仮想 (判定を外したときの挙動)

| 外した判定 | 基準時 | 反実仮想 |
|---|---:|---:|
| `classify_path()` の authority union | Write deny | allow |
| 同 union | apply_patch Add deny | allow |
| lexical 側 | deny | allow |
| canonical 側 | symlink 経由 deny | allow |
| inode 側 | hardlink deny | allow |
| `main()` authority fallback | `rc=2` | `rc=0` |

過剰拒否側の対照も確認した。

- `_inside` を部分文字列 prefix に弱めると sibling が `allow → deny`
- Move/Delete 元を `resolve_final=True` にすると、外部 symlink entry の unlink が `allow → deny`
- fallback を単純な部分文字列 regex にすると `dev-wave-authority2` が `rc=0 → rc=2`

各 detector を外すと対応する拒否が消え、別層に隠れて無効になっている追加判定はなかった。
