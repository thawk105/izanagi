## 実装した内容

[hooks/guard_bash.py](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t2146-guard-author/hooks/guard_bash.py) に以下を追加した。

- 固定絶対 path `_AUTHORITY_ROOT`
- 境界付き専用 trigger。既存 `_MENTION_RE` / `_TREE_LITERAL_RE` は未変更
- lexical・canonical・path 要素境界による判定
- root の祖先を含む削除・移動・展開拒否
- glob の literal prefix 重複判定
- regular file の inode index。`decide()` ごとに一インスタンス
- 削除・移動元で final symlink を解決しない処理
- `_tree_violation`、`_argument_hits_protected`、`_redirect_hits_protected` への authority 判定
- authority 専用の絶対 cwd 追跡
- fast path、`perf`、builder 例外分離、`main()` 例外 fallback
- 読取りと sibling/job/worktree path の従来許可を維持

scope 前は authority 配下への書込み、root・祖先の削除が許可されていた。既存防護対象の条件は削除・緩和していない。

## 実測 (decide 直呼び)

構文検査は `PYTHONPYCACHEPREFIX=/tmp/dev-wave-t2146-pycache-final python3 -m py_compile hooks/guard_bash.py` で `rc=0`。最初の `python3 -c` 形は既存 guard が protected path と inline program の同居として拒否したため、安全な同等形へ切り替えた。

指定された全ケースが期待どおりだった。

- deny: redirect、root の `rm -rf`、親の `rm -rf`、末尾一文字を `?` にした glob、authority への `cp`、authority からの `mv`
- allow: authority 配下の `cat` / `grep`
- allow: `dev-wave-authority-copy`、`dev-wave-authority2` の書込み・削除
- allow: 同じ親の無関係 directory への書込み
- allow: job directory、現在の worktree への書込み判定

追加確認も通過した。

- canonical symlink 経由の書込み: deny
- symlink entry 自身の unlink/move: allow
- `cd authority && ... > relative`: deny
- authority の親への archive 展開: deny
- authority 配下の builder: deny
- authority への `perf -o`: deny
- hardlink alias への書込み: deny
- hardlink alias 自身の unlink: allow
- `main()` 内部例外: exact authority は `rc=2`、sibling は `rc=0`

現行版と変更版へ同一の23コマンドを入力した比較では、既存の allow/deny はすべて維持され、`deny → allow` は0件だった。変化したのは authority 書込み・祖先破壊の `allow → deny` のみ。

pytest は指示どおり実行していない。

## 反実仮想 (判定を外したときの挙動)

変異は実行中の module またはメモリ内 source にだけ適用し、作業ファイルは変異していない。

| 外した判定 | 基準時 | 反実仮想 |
|---|---:|---:|
| fast-path authority 条件 | deny | allow |
| tree 呼出しの authority OR | deny | allow |
| argument 呼出しの authority OR | deny | allow |
| redirect 呼出しの authority OR | deny | allow |
| ancestor overlap | deny | allow |
| partial-glob prefix | deny | allow |
| inode index | deny | allow |
| canonical 側 | deny | allow |
| lexical 側 | deny | allow |
| authority cwd 更新 | deny | allow |
| `perf` 専用出力判定 | deny | allow |
| builder 例外分離 | deny | allow |
| `main()` fallback | `rc=2` | `rc=0` |

過剰拒否側の対照も確認した。

- path 要素境界を外すと sibling が `allow → deny`
- final symlink を解決しない規則を外すと、外部 symlink entry の unlink が `allow → deny`

各 deny detector を外すと対応する拒否が消えたため、別層に隠れて歯が立たない追加判定はなかった。
