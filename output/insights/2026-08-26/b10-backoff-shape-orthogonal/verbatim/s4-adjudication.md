# 段 4 裁定 — B-10 待ち方 / 待ち量の直交切り分け

親が段 2 plan と段 3 の 2 レンズを real/refuted・採用/不採用・scope 内/外で裁定し、plan v2 を確定する。
所見はすべて **real** と判定した。refuted は 0 件である。

---

## 0. 裁定の要点 (先に結論)

**親 brief の実験設計は、そのままでは B-10 を閉じられない。** レンズ A の指摘が正しい。
主要な作り直しは 2 点で、どちらも追加コストは小さい。

1. **待ち方の族を「0 を含む形」から「0 を含まない半幅の形」へ変える。**
   一様を 0〜2μ から μ/2〜3μ/2 へ、二値を {0, 2μ} から {μ/2, 3μ/2} へ変える。
   平均は変わらず μ のままで、**どの形も待ち量 0 を指示しなくなる**。
   これによりレンズ A の must-fix「物理的な spin 下限が形ごとに違う」と
   レンズ B の should-fix「物理待機平均を揃えたとは言えない」が、
   解析的に上界を書ける残差まで縮む (§2.2)。
2. **各セル 1 セッションをやめ、独立 3 ブロック (セッション) を取る。**
   解析を「閾値超えの数え上げ」から「ブロック内 paired 比較 + 符号反転 permutation 検定 +
   Holm 補正」へ置き換える。これでレンズ A の must-fix「偽陽性率が未制御」
   「独立検定単位が無い」「floor が比較対象の分散を表していない」の 3 件が同時に閉じる。
   **しかも外部 between-run floor への依存が消えるので、Pegasus の rr5 / rr50 floor 欠落は
   阻害要因でなくなる** (参考線としてだけ報告する)。

## 1. レンズ A (実験設計) の裁定

### A-1 母集団平均と実走平均の一般化 — real / 採用 (形を変えて解消)

64 bit 全域の母平均が μ でも、有限の実走で観測される `rdtscp` 列が均衡する保証はない、
という指摘は正しい。加えて**一様と二値で別の乗数を使うと、差が分布形でなく撹拌器の違いでも生じる**
という指摘は決定的である。

- **採用 1**: 両方の乱数形で**同一の撹拌器**を使う。これは無条件に正しく、費用ゼロである。
- **採用 2**: 一様の変動係数を定数 0.577 と書かない。μ ごとに違う値を事前登録の表に書く。
- **不採用 (scope 外へ)**: 実走での要求待ち量の分位点・自己相関・スレッド間同時値率を測る
  診断ビルドの新設。これは実装面を hole 1 行の外へ広げる。§4 の裁定パッケージへ送る。
  代わりに、**abort 回数から求まる呼び出し回数を全セルで報告**し (追加計装不要、§A-6)、
  主張を「指示した待ち量の平均を揃えた」に限定する。

### A-2 物理的な spin 下限 — real / 採用 (形を変えて解消)

「待ち量 0 を指示しても最低 1 回は `_mm_pause()` と `rdtscp()` を通る」は正しい。
二値の μ=2 では半数が 0 指示になるため、名目平均と物理平均がずれる。

- **採用**: §0 の半幅族へ変える。指示される最小値は μ/2 で、μ=2 でも 1 µs = 2100 cycle である。
  一方 1 回の pause + rdtscp と式評価の合計は数十 cycle 程度なので、
  **最小セルでも 1% 未満**の残差に収まる。事前登録にこの上界を書く。
- 上界の算出根拠 (式評価の cycle 数) は段 5 の実装子が実測して事前登録へ入れる。

### A-3 「6 点中同符号 2 点」は偽陽性率を制御していない — real / 採用 (規則を差し替え)

レンズ A の見積り (閾値を floor そのものに置くと 1 セルあたり約 48%、
1 判定で約 74%) は、各セルが 1 セッション中央値であるという前提の下で正しい。
**この規則は使えない。**

- **採用**: 判定規則を次へ差し替える。
  - 単位は**独立ブロック**とし、同一ブロック内で同じ μ の形と一定を対にする。
  - 各 (workload, 形) について、18 個の対 (6 μ × 3 ブロック) の差に対し
    **符号反転 permutation 検定**を行う。
  - 族は 6 個 (3 workload × 2 非一定形) とし、**Holm 補正**を掛ける。族全体で α = 0.05。
  - 効果量と信頼区間を**全セル**について報告する。有意でないセルも退行も全部載せる。
  - 有意でない場合は信頼区間を示し、事前登録した等価範囲を外れないかを述べる。
- **統計的有意性と呼んでよいのはこの検定の結果だけ**であり、記述的な数え上げは補助に留める。

### A-4 独立セッションが各セル 1 個しかない — real / 採用

- **採用**: 各 workload について**独立 3 ブロック**を取る。1 ブロック = 全 20 genome の 1 巡。
  ブロック間は時間的に分離する (別ジョブまたは同一ジョブ内の別フェーズ)。
  ベンチ実時間は 3 workload × 3 ブロック × 20 genome × 5 反復 × 3 秒 = 2700 秒であり、
  ビルドと検証を除けば 45 分程度。**規律 4 の「大きすぎる罠」には当たらない。**
- 検出限界を事前登録に書く。3 ブロックで検出できる最小効果量を、
  既存 floor (rr5 0.67% / rr50 1.07% / rr95 0.11%、いずれも linux-baremetal の between-run) から
  見積もって明記する。**Pegasus の値ではないので、見積りであることを明記する。**

### A-5 floor が比較対象の分散を表していない — real / 採用 (依存を解消)

- **採用**: ブロック設計により、**比較する両側の run 間変動を実験自身が測る**。
  外部 floor への依存を解消する。既存 floor は参考線としてだけ報告する。
- **これにより Pegasus の rr5 / rr50 floor 欠落は本 wave の阻害要因ではなくなった。**
  取得は有用だが本 wave の必要条件から外す (§4 へ送る)。

### A-6 総 spin 量・実効並列度との交絡 — real / 採用 (追加計装なし)

「1 回あたりの待ち量が同じでも、abort 回数が変われば総 spin 時間は同じでない」は正しい。

- **採用**: CCBench は abort 回数を bench の標準出力に出しており、既存の計測成果物にも
  `aborts` / `abort_rate` として記録されている。silo は abort ごとに backoff を 1 回呼ぶので、
  **呼び出し回数 = abort 回数**である。よって**追加計装なしで**次を全セル報告できる。
  - 呼び出し回数と毎秒呼び出し回数
  - 名目の総待ち量 = abort 回数 × μ
- 主張は「指示 schedule の効果」に限定し、脱同期という機序名は
  総待ち量が動いていない場合にだけ副次的主張として書く。

### A-7 二値の半分ゼロを識別する対照 — real / 不要になった

半幅族へ変えたので二値に 0 の腕が無くなり、この所見は消滅する。
ただし `BACK_OFF=1, BACKOFF_FIXED=0` (待ち量 0 だが loop は通る) を**参照点として追加**し、
`BACK_OFF=0` (loop 自体を飛ばす) と loop 下限を分離する。**採用**。

### A-8 read-heavy は反証点でなく経路曝露の確認が先 — real / 採用

- **採用**: 各セルで呼び出し回数を報告し、**事前登録した最小曝露**を満たさないセルは
  「経路未観測・判定不能」とする。無差の成功数へ入れない。
  最小曝露の値は段 5 で pilot から決めず、既存 rr95 の abort 率 (Pegasus 15.48%) を根拠に
  事前登録へ数値で書く。

### A-9 1M は飽和点ではない — real / 採用 (表現の修正)

- **採用**: 事前登録には「D15 の下限基準で選択、1,000,000 件、作業集合が L3 の 4.93 倍、
  miss 率は飽和していない」と正確に書く。「飽和確認済み」とは書かない。

### A-10 既知結果を見た後の登録である開示 — real / 採用

- **採用**: 事前登録に、着手前に見ていた既存成果 (magnitude sweep 5 件の path と既知の傾向、
  floor 成果物、calibration 成果物) を列挙し、
  **「既知の μ grid 上での前向きな形の拡張であり、登録追試である」**と明記する。

### A-11 完走だけでは B-10 を閉じない — real / 採用 (主張を限定)

- **採用**: 事前登録に「本実験で書ける文」と「書けない文」を分けて書く。
  本実験が閉じるのは **「指示待ち量の平均を揃えたとき、待ち方 (ばらつき) が throughput を
  動かすか」** であり、これは B-10 の「待ち方と待ち量の直交切り分け」そのものである。
  閉じないのは過抑制域の機序、ピーク位置の再現、balanced の profile であり、
  これらは B-10 の別項目として未取得のまま残ることを明記する。

## 2. レンズ B (機構安全) の裁定

### B-1 「hole 1 行だけ」が実行時 gate になっていない — real / 採用

`source_digest` はファイル集合しか制限せず、hook も内容を見ない、
`build_admission` の raw marker 検査は trigger 軸だけ、という指摘は正しい。
本 driver は `quarantine()` を通らないので、**独自の実行時 preflight が要る**。

- **採用**: driver の preflight で次を全部確かめ、1 つでも外れたら campaign へ入る前に停止する。
  - patch の変更先が正確に `{cmake/Options.cmake, include/backoff.hh}` であること
  - 事前登録した patch SHA と適用後ツリーが一致すること
  - BEGIN / END マーカーが各 1 個であること (重複 marker を数える)
  - hole が単一行で `EXPECTED_HOLE_LINE` と byte 一致すること
  - stock 枝・待機ループ・骨格が byte 一致すること
- **grammar と ALLOWLIST は広げない。** 受理集合を広げる変更は本 wave に無い。

### B-2 inert 検査が受入で発火せず driver にも gate が無い — real / 採用

既存 inert テストは patch 未適用なら `return` する。受入 suite の通常状態は未適用なので、
**この検査は受入では一度も発火していない。** これは「謳うだけで発火しない保証」である。

- **採用**: 隔離 checkout に実 patch を適用し、`BACKOFF_FIXED=-1` の全参照 genome で
  `compute == baseline` かつ `src_token == "stock"` を要求する検査を、
  (a) 単体テストと (b) campaign の最初の書き込み前の実行時 preflight の**両方**に置く。
  未適用は成功扱いにせず失敗させる。

### B-3 旧 consumer の variant identity 互換 — real / scope 外 (裁定へ送る)

旧 6 値の数値挙動は不変だが、preprocess 後ソースが変わるので `src_token` と `variant_id` は変わる。
旧 consumer を再走すると同じ campaign に新 ID が増え、旧 WAL の SHA pin と resume を壊しうる。

- **既存の凍結成果物・台帳・pin は本 wave では 1 byte も壊れない** (レンズ B の全数確認どおり)。
  危険は「将来だれかが旧 consumer を再走したとき」に顕在化する潜在的なものである。
- **scope 外と裁定する。** 全 consumer の identity 移行または v1 patch の別名凍結は、
  本 wave の変更面 (hole 1 行) を大きく超える。§4 の裁定パッケージへ送る。
- **ただし本 wave で無料でできる警告は入れる**: `patches/README.md` に
  「hole の式が v1 と v2 で異なり、同じ `BACKOFF_FIXED` でも variant 識別子が変わる」ことと、
  旧 campaign への resume を避けるべきことを明記する (docs のみ)。

### B-4 事前登録 commit の束縛が部分的 — real / 採用

- **採用**: `prereg_commit`、事前登録文書の blob SHA、patch SHA、式 SHA を
  `search_config` と campaign lock と各 `BUILD_START` に**必須束縛**として入れ、
  この束縛が無い既存 WAL への resume を拒否する。
  検査は layout 作成・性能 probe・`run_campaign()` より前に走らせる。
  否定テスト (dirty / blob 不一致 / commit が非祖先 / legacy WAL / 束縛不一致) を置く。

### B-5 実 C++ 式を評価する検査が無い — real / 採用

- **採用**: `EXPECTED_HOLE_LINE` をそのまま使う最小 C++ harness を
  `-Wall -Wextra -Werror` でコンパイルし、各 (形, μ) の代表入力で
  Python の厳密モデルと一致することを確かめるテストを置く。親が実走して緑を確認する。

### B-6 coder 仕様との矛盾 — real / 採用 (docs)

- **採用**: `src/coder-spec.md` を更新し、**coder の受理集合は数値リテラル 1 個のまま不変**で、
  新しい式は **B-10 driver が byte 固定する人間所有のテンプレート baseline** である、という
  二層構造を明記する。grammar の fixture と archive は一括置換しない。

### B-7 「平均を揃えた」は指示値までである — real / 採用 (表現の限定 + 形の変更で縮小)

- **採用**: 一様を `symmetric-modulo` と呼び、表見出しと事前登録の主張を
  「構成上の指示 `now_backoff` の平均が μ」に限定する。
  §A-2 の半幅族により物理平均との差は最小セルでも 1% 未満に収まるので、その上界を併記する。

## 3. plan v2 (確定)

### 3.1 待ち方の族 (半幅、平均はすべて厳密に μ)

| 名前 | 指示値の範囲 | 平均 | 変動係数 |
|---|---|---|---|
| `constant` | μ のみ | μ | 0 |
| `symmetric-modulo` | μ/2 〜 3μ/2 | μ | μ ごとに算出して事前登録 (連続極限で 0.289) |
| `binary` | μ/2 または 3μ/2 を確率 1/2 ずつ | μ | 0.5 |

- 両乱数形は**同一の撹拌器**を使う。撹拌器は `backoff()` 入口で既に計算済みの `start` だけを入力とする。
- 符号化は `BACKOFF_FIXED = 形コード × 1000 + μ`。0〜999 は従来と数値的に同一。
- 実装面の編集は `patches/silo-backoff-fixed.patch` の hole 1 行のみ。

### 3.2 grid

- μ ∈ {2, 5, 10, 25, 50, 100} (既存 sweep と同じ座標系)
- 形 3 種 × μ 6 点 = 18 点
- workload 3 種 (write-heavy rr5 / balanced rr50 / read-heavy rr95)
- 参照点 3 種: `BACK_OFF=0` (loop を飛ばす) / `BACK_OFF=1, BACKOFF_FIXED=-1` (stock 適応) /
  `BACK_OFF=1, BACKOFF_FIXED=0` (loop は通るが待ち量 0)
- 合計 genome = 21。workload あたり 21 セル、3 workload で 63 セル。
- **独立ブロック 3 巡。** 各ブロックで全 21 genome を測る。

### 3.3 動作点

- レコード数 1,000,000 (D15 の下限基準で選択。作業集合が L3 の 4.93 倍。miss 率は未飽和)
- 48 スレッド / extime 3 秒 / reps 5
- 正しさ検証は `legacy+performance`。**(genome, workload) につき 1 回**行い、
  ブロック 2・3 は性能のみ再測定する (規律 1 の別ビルド・別 run は既存 pipeline が担保)。
- verifier が anomaly を返したセルは即 reject。bench へ到達させない (既存 pipeline)。

### 3.4 判定規則 (事前登録。実走後に変えない)

- 単位は独立ブロック。同一ブロック内で同じ μ の形と `constant` を対にする。
- 各 (workload, 非一定形) について 18 対の差に符号反転 permutation 検定。
- 族 6 個に Holm 補正。族全体で α = 0.05。
- 全セルの効果量と信頼区間を報告する。退行も全部報告する。
- 呼び出し回数が事前登録した最小曝露を下回るセルは「判定不能」とし、成功数にも失敗数にも入れない。
- 有意でない場合は信頼区間を示し、事前登録した等価範囲との関係を述べる。

### 3.5 成果物

2. `orchestrator/campaign/b10_backoff_shape_sweep.py` (実行時 preflight を内蔵)

7. 実走結果とレポート

## 4. 裁定パッケージ (scope 外の real 所見。ユーザーへ返す)

1. **実走での要求待ち量そのものを測る診断ビルドの新設。** 実装面を hole 1 行の外へ広げる。
   本 wave は主張を指示値の平均に限定し、物理平均との差は解析的上界で押さえる。
2. **旧 backoff consumer の campaign identity 移行、または v1 patch の別名凍結。**
   既存成果物は壊れないが、旧 consumer の再走時に新 ID が混入する潜在的危険がある。
3. **Pegasus の rr5 / rr50 between-run floor の取得。** 本 wave の必要条件からは外れたが、
   他の campaign の採否参照線として有用である (既存 driver あり、2 workload で 20〜30 分)。
4. **「commit 前に一度も性能を見ていない」ことの機械証明。** repo 内 preflight より強い
   外部権威が要る。本 wave は formal driver 経路に限って保証する。
