# Izanagi 本体論文：貢献節草稿

本稿は 2026-09-20 の新規執筆依頼に基づく日本語草稿である。[序論草稿](intro.md) と
[限界節草稿](limitations.md) と同時に起草し、主張の強さを揃えてある。貢献は強い順に並べる。各項の
見出しの角括弧はその項の主張の範囲を示し、項の中の個々の結果には claim-evidence 稿の実証状態 7 値
(実証済み / 測って届かなかった / 登録追試として成立 / 限定付きで取れた観測 / 固定条件で certified な
正しさ / 運用上の証拠 / 未取得) を角括弧で付す。資料の採用時点は local main `482f19b88` (2026-09-20
17:56 JST の commit)。既存の凍結稿・図は書き換えていない。本文中の資料番号は末尾の出所を指す。

貢献の順序は「主張の強さ」であって「実証の進み」ではない。第 1 項は新規性の候補であって未確定で
あり、実証済みの科学的主張は第 2 項の一事例と第 4 項の否定的結果である。この非対称を隠さないために、
実証状態を本文と同じ行に置く。

本稿で「certified」と書くときは、指定した検証構成の下で実際に観測された YCSB の point read / write の
trace について、判定器が直列化可能と判定したことを指す。観測されなかった実行、述語や phantom、
公平性、および性能の優越は保証しない。certified は実際に build された bytes についての判定であり、
検証条件と source identity の束縛に残る限界は限界節の第 2 節に示す。

## 1. 対象の空白 ［新規性候補。文献の guardrail としては未取得 — 関連研究の調査は限定付きで止まっている］

評価器をループ内に置いた対象特化合成の系譜を、単一ノードのトランザクション処理系の直列化可能性と
many-core 性能へ適用した。本論文が言えるのは次の 1 文までである。

> 本調査では、LLM が、トランザクションの並行性制御を対象として、アクション空間自体をコードで
> 拡張する (固定した原始操作の語彙の中で生成するのではなく) 既存例を発見していない。

この記述は 3 条件 (LLM が / トランザクションの並行性制御を対象として / アクション空間自体をコードで
拡張する) のすべてに限定され、どれ 1 つ落とした短縮形では成り立たない。「先行なし」「世界初」「系譜の
中で何本目」は書かない。関連研究の調査は 2 軸とも費用対効果を理由に限定付きで止めており (完了では
なく、制限が恒久化したのでもない)、この項の主張は調査が進めば動きうる。個々の先行との比較は関連
研究の節に委ねる。[1]

## 2. 対象実装の action vocabulary を拡張する合成 ［一事例は実証済み (科学的主張)。一般性と LLM の因果的必要性は未取得］

評価指標の帰属 (適応 backoff は abort を抑えているが IPC が崩れている) を起点に、既存フラグ空間の外の
新しい軸「abort 後の待機量の静的固定」を Silo に合成し、旧 `linux-baremetal` 環境の記述的な sweep で、
同一 sweep 内の無 backoff 対照に対して write-heavy +38.3%、balanced +11.3%、read-heavy −6.6% を得た
［実証済み (科学的主張)。旧測定契約下の記述的な一事例］。3 workload のうち 2 つで勝ち、1 つで負けた。
分母は無 backoff 対照であって stock の適応 backoff ではなく、適応を分母にした値 (+147.4%) は過抑制の
大きさを示す診断値であり論文値ではない。[2]

この一事例が示すのは実行可能性までである。合成の一般性、および「LLM でなければこの軸に到達
できなかった」という因果的必要性は実証していない［未取得］。後者は対照を取っても言えない形の主張であると
裁定されており、主張は固定予算・固定編集面の下での条件付き優越へ狭まっている — その対照の事前登録は
作られ、部品の段階実装と上限付きの試走が認可されたが、本走は未認可で対照は未取得である。合成した軸が
既知軸最良を超えるかは事前登録して測り、不成立だった (第 4 項)。さらに「空間の外」の「外」を厳密な
意味的無限として定義することは、現行の編集面では原理的に支持できない — C++ の観測はすべて有限幅で
あり、述語空間を広げようとすると禁止された代理指標 (大域の進捗時計、run 自身の fitness 信号など) に
行き当たる。この「非列挙」条件をどう置き直すかは未裁定である。[3]

現行 Pegasus 環境で採用静的 backoff を測った正式な走行 (write-heavy と balanced の連言で
`observed-positive`、read-heavy で `reject`、balanced の別の事前登録で `accepted`)、非認証 lane の
descriptive な走行、同一候補を 3 workload で同時期に測った descriptive な走行、および合成ループの 3 巡は、
いずれもこの項の主張を強めない。一事例の性能効果が現行環境でも観測されたことは一般性の証拠でも
LLM の必要性の証拠でもなく、ループが評価したのは固定 backoff の初期値であって新しい CC 構造では
ない。[4]

## 3. 説明可能性 ［核 3 点と事実層は運用上の証拠 (対象とした campaign 群について)。機序仮説層は実装・適用済みだが、機序の証拠は未取得］

「なぜそれが速いか」の説明について、本論文の核は次の 3 点で書く。**(i) 対象がトランザクションの
並行性制御であること、(ii) 対象実装の action vocabulary そのものを拡張すること、(iii) 正しさゲート
(直列化可能性の検証) を毎反復回すこと。** (i) と (ii) は backoff / sort / trigger-gating の 3 軸の合成
そのものであり、(iii) は safe variant loop が毎反復実行する trace 有効 build と判定器である。3 点はいずれも
実装と計測が動いている面である。「説明可能性が差別化の核である」という短縮形は使わない。[5]

成立しているのは事実層である［運用上の証拠］。材料レポートは、WAL と whiteboard の入力と、レポートが
挙げる参照とを 1 対 1 で突き合わせる双射検査を持ち、対象とした campaign 群についてその検査を通っている。
任意の campaign について完全とは書かない。機序を言語化する仮説層は実装され、合成ループの 2 巡目と
3 巡目で適用されたが、生まれた材料は検証されていない二次的な view であり、機序の証拠ではない［未取得］。「なぜ速いか」を
機序まで言語化した実証は、今も第 2 項の手作業のケーススタディに依存している。「因果」と呼べるのは
アブレーションで分離できた効果に限り、それ以外は仮説と表示する。説明の忠実性・証明の連鎖・試行の来歴は
補助であり、核として書かない。[6]

## 4. 否定的結果の定量化 ［種別の異なる 4 つの結果。実証状態は結果ごとに付す］

**探索についての否定的結果 ［実証済み (科学的主張)］。** Silo の既存フラグ空間 (実質 1 ビットで決まる自明な空間) で、LLM 誘導
探索は LLM を使わない貪欲探索の到達コストを超えず (balanced: 確率優越 A = 0.5813、p ≈ 0.16)、
欺瞞的な構造を持つ write-heavy では貪欲より有意に有害だった (A = 0.2304、全 50,268 構成を列挙した厳密
permutation で p = 2.52 × 10⁻⁴、6 検定の Holm 補正後も維持、12 試行中 8 が誤収束)。これは事前に立てた
仮説「LLM 誘導探索は全探索より速く収束する」を独立に反証した結果であり、評価器の側の過信が欺瞞的な
信号の下で負債になることの定量実証である。read-heavy は最良群が 8 構成中 4 構成を占め、識別力のある
比較として扱わない。[7]

**縮小主張 S' の不成立 ［測って届かなかった］ — 新しい否定的発見ではなく、登録した複合主張の失敗
報告。** 合成した軸 (trigger-gating) と既知軸最良 3 種の直接比較 9 対で、既知軸最良を超えるという主張
(S-1a) は不成立 (family p = 1.0)、発見再現性の適格率 (S-2) は不成立 (名目 p = 0.115)、帰属の寄与 (S-3) は
「退化を示せる」側を棄却した (名目 p = 1.0)。合成軸は書込ロック順の並べ替えには 3 workload とも勝ち
(+55.5% から +98.4%)、コンパイル時フラグ最適化 (−9.3% から −55.1%) と静的 backoff 最良値 (−36.0% から
−51.9%) には負けた。合成軸の on/off 効果 (S-1b) は登録した追試として成立した ［登録追試として成立］
(+60.6% から +99.9%、family p = 0.000204) が、機械 sweep で既知だった効果であり新発見ではない。S-1 は
既知結果を見た後に登録された追試であるため、S' の不成立は「事前に立てた仮説が独立に棄却された」型では
なく、「結果既知の追試として登録した複合主張が、測ってみたら成立しなかった」という失敗報告として
書く。[8]

**現行環境の負の判定 ［限定付きで取れた観測 — 正式 protocol の status］。** read-heavy において、正しい
identity で build した採用静的 backoff (fixed 2 µs) は無 backoff より 5.7841% 遅かった (正式 protocol の
`reject`)。旧環境の −6.6% と符号は同じだが再現判定ではなく、「合成した軸が負けた」でもない — 比べたのは
採用静的 backoff と無 backoff である。同一候補 fixed 5 µs を 3 workload で同時期に測った descriptive な
走行 ［限定付きで取れた観測 — descriptive］ でも read-heavy だけが走行間ばらつきの下限を超えて退行した
(−11.3787%、下限 0.2228%) が、これは全 workload の退行込み報告の材料であり、この項には正式判定として
数えない。[9]

**右 tail の記述的な結末 ［限定付きで取れた観測 — 事前登録した格子の記述的判定、性能は未認証］。**
静的 backoff の右 tail (1000 から 9999 µs) を事前登録した格子で測り、
「この事前登録の述語では、表現可能域である 9999 マイクロ秒までに飽和を観測しなかった」という結末を
得た。同じ格子で throughput は 3 workload とも半分以下へ下がる (過抑制の費用)。独立再現の第 2 cohort も
同じ集団判定を出したが、主結果と併記するだけで合成せず、「再現されたので飽和しない」とは書かない。
機序は同定していない。[10]

## 5. AI 主導研究の運用方法論 ［運用上の証拠。運用が結果を良くしたという対照実験ではない］

全主張への多エージェント敵対的反証、統計の再校正と訂正の履歴を機械可読で残すこと、判定器の
fails-closed 化、外部から来た入力を指示ではなくデータとして扱う信頼境界、Phase 完了時の監査、文書の
一貫性を保つ機構、を実運用の記録として持つ。本論文で報告できる素材の例を挙げる。[11]

- 統計指標の系統バイアス (tie を勝ちに数えない主指標) を再校正し、その後の p 値の過大表示も訂正し、
  「訂正の訂正」まで成果物に残した。
- 正式 protocol が要求した build 定義を黙って無視したまま完走した事例 (旧 A-2 attempt) を、判定を
  取り消さずに「支持する命題が違う」と追記で訂正し、identity を source に束縛した driver で取り直した。
  測定条件の関門族が守ろうとした型の実例が、負の側と正の側の両方でそろった。
- 正しさの一次防壁の穴 (source identity が前処理指令の効果を捉えない範囲) を、既存の identity を
  1 byte も動かさない形で狭め、残る限界を明記した。
- 認可済みの再測定を、正しさ由来の防壁が投入前に拒否した事例で、防壁の受理集合を AI の裁量で広げず
  裁定へ返した。
- 第 2 cohort の地位 (独立再現、主結果と合成しない) と退行の判定規則 (対差が床値を下回れば退行) を、
  結果を見る前に固定した。
- 道具の整備が研究の測定を締め出す引力に対し、実在の欠陥が観測されていない追加を足さず、保証していない
  範囲を文面へ出す向きの是正を繰り返した。過剰実装の抑制は防御的な堅牢化にだけ適用し、正しさゲートには
  適用しない。

## 副産物 ［実証済みの副産物 2 件と、限定付きの観測。合成能力や新規性の証拠には数えない］

素材コーパス CCBench の潜在バグ 2 件 (write-ahead log の ftruncate XOR、ODR 違反による heap-overflow) を
上流へ還元した ［実証済み、上流でマージ済み］。SS2PL には YCSB のバイナリが存在せず「SS2PL を ycsb-a で
測る」ことが一度も行われていなかったこと、および測定値を静かに壊す 3 つの穴 (`DLR0` が timeout 解決では
なく素の待ちであること、abort の二重計上など) を見つけた ［実証済み、還元は人間手番］。「realizable trace
の全 cycle は必ず G2」という定理、oze の skew 病理、静的 backoff の符号化衝突 (要求値 1000 µs が 0 µs と
して実現していた) も同種の副産物である。stock mocc の G2 signal が trace の witness を切った producer で
だけ再現し witness を入れると 0 件だった (非有意) という観測は、根因が未同定のまま上流への報告案までで
ある ［限定付きで取れた観測、非 certifying］。これらを見つけた SS2PL のロック規律スタディ自体は手設計で
証明の連鎖の外にあり、新規性の主張には置かない。[12]

## 貢献として書かないもの

次は本論文の貢献ではない。理由は限界節に書く。「新しい CC を作った」(出力契約は certified な選択結果で
あり、証拠が支持しなければ stock または差なしを返す)。「合成した軸が既知軸最良を超えた」(測って不成立)。
「ワークロード特化の合成ができた」(descriptor を条件にした生成の因果証拠がない)。「LLM でなければ
できない」(対照を取っても言えない形であり、条件付き優越の対照も未取得)。「無人で研究ループが回る」
(bounded MVP であり正式系列は未発効)。「クロスプロトコルへ広げた」「mocc は第 2 の成功例」(Silo 固定の
方針は解除され、素材コーパスの版も mocc の trace hook を含む候補へ進んだが、その前進に較正の再取得・
mocc の certified 系列・性能比較は含まれず、非 Silo の性能比較は 0 件)。「先行研究を調べ終えた」(限定付きの
停止)。
