# 段 1 brief — [T-2620] 残存数計数のゾンビ除外: D2044 項 21 の確認手番

- **研究前進 (土台):** T-2620 はユーザー裁定待ち (D2044 項 21)。裁定が確定しないと T-2622 (計算ノード job が pytest 完了後に終わらない事象、F973 で subreaper 案が撤去) の再設計が「残存の契約」を仮定できず止まる。本 wave は裁定に必要な実測 (負例 3 種 × consumer の観測値、現行 vs Z 除外) を作って裁定パッケージへ返す。production の差分はゼロ、受理集合は変えない (裁定文どおり)。
- **scope:** `tools/codex_worker_launch.py` の `_group_member_count` (l.1692〜、PGID 一致で全 state 加算) と、その値を消費する経路。(1) `_normal_reap` l.1854 / `_terminate` l.1809 → attempt record `process_group_residual` (int|None) + `termination_verified`、(2) `accepted` 述語 l.1984、(3) `check-receipt` の `_validate_attempt` l.3904/3949、(4) `_writer_truth` → outcome / `launcher_rc` (dev_wave_codex.py l.349 が rc をそのまま返す)、(5) 診断 sidecar `residual_observation` l.700、(6) test helper `_assert_launcher_returncode` の failed_predicates。**同型走査 `tools/dev_waves/worker.py:_group_members` (l.146、bool、別 producer) は scope 外・列挙のみ** (一般化は裁定文で禁止)。
- **確定済み裁定:** D2044 項 21「今は除外を決めない。ゾンビを除外した後も実行中の子・読取不能・回収不全を区別できることを receipt の consumer と負例で確かめてから決める」。F973 恒久対応「計数側を直す案は受理集合を変えるため採らず裁定へ返した」。D95 (実装面は Codex author)。先例: D464 (claim 排他は `Z` を DEAD として通す)、D705 (占有検査は zombie を非占有)。これらは別 consumer であり本件の根拠にしない (DW-G03: 族一般化は独立 2 例でも裁定事項)。
- **DW-G01 生死実験 (済、login node、07:20 JST、`probe_zombie_group.py`):** (a) subreaper 無し: 孫ゾンビは leader 終了後に init が即回収 → 残存 0、`_normal_reap`=(0, True)。(b) subreaper 有り (prctl 36、回収せず): 孫が state `Z` で PGID に残り `_group_member_count`=1、`_normal_reap`=(1, False)、`worker._verified_group_exists`=True。(c) 実行中の孤児 (TERM 無視): state `S` で 1、(1, False)。→ 回収不全は subreaper 祖先の下でだけ決定的に作れる (F973 と同じ機序)。
- **模擬/実の差:** 「読取不能」は本 host で実 process から作れない (`/proc` に hidepid 無し、`grep hidepid /proc/mounts` 0 件)。既存 unit test 5 本 (l.4482〜) が monkeypatch で `None` + source を検査済み。本 wave は consumer 側 (`check-receipt` が `residual: null` + `accepted: true` を拒否するか) を実 receipt で足す。(P1)
- **(P1) 提案する負例集合 (親の provisional、攻撃対象):** N1 実行中の子 = fake codex が TERM 無視の子を残して正常終了 → 現行 residual 1 / accepted False / termination_verified False / launcher_rc 1 / sidecar final_count 1。N2 回収不全 = subreaper harness の下で fake codex が孫を `Z` にしてから正常終了 (孫を wait しない) → 現行 residual 1 (Z) / accepted False (= F973 の現象の positive control)。N3 読取不能 = 上記 consumer 負例。各負例は e2e (launcher を subprocess で起動、receipt と sidecar を読む) とし、既存 `_run_case` / `_write_fake_codex` の FAKE_MODE を 2 つ足す。harness は test file 内の helper script (`_write_subreaper_harness`)。
- **(P2) Z 除外の実測 = 変異 matrix の 1 項目:** DW-O19 で `_group_member_count` に `if fields[0] == "Z": continue` を一時変異し N1/N2/N3 + 既存 `test_sigterm_ignoring_child_is_killed` + unit 5 本を走らせ、flip する test を記録して復元。予想: N2 だけ residual 0 / accepted True へ flip し、receipt・sidecar のどの field でも clean と区別できない (`residual_observation` にゾンビ数 field が無い)。予想が外れたらそれが主結果。
- **不変条件:** 規律 2 (受理集合を緩めない — production は 1 byte も変えず、変異は復元)。新 gate・台帳・一般化を足さない。`worker.py` に触らない。負例は「性質」でなく実 process で作る (memory: mechanism-positive-control-must-name-the-real-callee)。
- **成果物:** (i) `orchestrator/tests/test_codex_worker_launch.py` への負例 test (Codex author)、(ii) `output/insights/2026-09-20/t2620-zombie-residual/README.md` (負例 × consumer 観測値の表、現行 vs Z 除外、裁定パッケージ: 除外する / しない / 別 field を足す の 3 択と推奨)、(iii) worklog fragment (spool)。decisions fragment は裁定待ちなので書かない。
