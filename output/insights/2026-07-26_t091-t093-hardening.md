## 2. 実装 (何が変わったか)

- **[T-091]** `orchestrator/tests/test_t080_freeze_migration.py`

## 3. 検証プロセスと親裁定

段 2 codex プラン v1 → 段 3 敵対相談 2 (max、**両 NO-GO**、所見 14) → 段 4 親裁定
(real 12 / **部分 refuted 1** / scope 外 1) → 段 5 実装 2 並列 (所有素集合・worktree 分離) →
段 6 敵対レビュー 2 (A=GO / B=NO-GO、所見 4) → fix → 焦点再レビュー (closed 3 / partial 1)。
逐語は `2026-07-26_t091-t093-hardening-verbatim.md` に凍結した。

**親が覆した主要な判断**:

- **(P1) 15 件へ拡張**: D78 (6)(f) 本文は 13 件だが、metadata 2 件も receipt 由来で独立性が
  同じく無いため 15 に広げた。両レンズとも妥当と判定。
- **(P2) pre-R 分岐削除**: A-6 は「既存検査を弱める」と指摘したが、**部分 refuted** と裁定した。
  post-R の現 repo では当該分岐は**到達不能** (R が履歴に存在することを親が実測) であり、
  失われる実効検出力は 0 である。A-6 の対案 (never-issued 固定の別 node を実物 freeze に対して撃つ)
  は検出力の**追加**であって保持ではないため scope 外とし、次の一手へ送った。
- **(P5) 改竄 field の実装子裁量を却下**: 裁量にすると別 gate の拒否を T-091 の KILL として
  誤帰属する経路が開くため、`reconstruction/holdout/projected_document_sha256` に固定した。
- **A-4 は部分採用**: 完全 stub-free 化は fixture コストが過剰。receipt を引数に取る先行 check は
  実関数へ戻し、**stub のまま残した 4 gate をテスト内コメントと報告に明記**させた。
  「全 gate を検証した」とは主張しない。

**A-3 が本 wave の最大の収穫**: 「15 cell を literal 化しただけでは、production が
*receipt を無視して常に実 repo の値を返す*退化を検出できない (単一 real-repo vector なので恒真化できる)」。
この指摘に対し親は、real-repo だけでなく hermetic fixture 側に**basis を分岐させた第 2 vector**を
置く形へ設計を変更した。これが §4 の M6 として実測で成立した。
