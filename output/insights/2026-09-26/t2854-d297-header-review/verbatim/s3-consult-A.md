# レンズ A 所見

**静的審査の結論:** 規則案は D780 の別防壁を単独で設計したとは言えず、C2' の合格も先取りしていない。一方、consumer 選定と文脈対応に、保証名より狭い集合を比較して緑にする経路が残る。以下の must-fix は設計文を直してから規則案 v2 にするべきである。

1. **must-fix｜成立 — `-MG` が依存の途中で探索を止め得る。** `-MG` は未生成 header を依存として報告しても、その先の include を辿れない。plan は変更 header の実在と、*選ばれた consumer* の前処理成功を要求するが、未生成の中間 header の先にだけ変更 header がある entry は選定されない。別 entry が同じ変更 header を読むなら「header ごと consumer 0 件」の拒否も働かない。根拠: [plan:18–24](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/out/s2-plan.md:18)、[plan:42](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/out/s2-plan.md:42)、[ThirdParty.cmake:66](/work/1/SFC/tanab/izanagi/.claude/worktrees/t2854-d297-header-review/external/ccbench/cmake/ThirdParty.cmake:66)。**放置時:** pin の受理集合に、TRACE=0 で変更 header を使う未比較 TU が入る。**代替案:** 生成物を用意した後、全 entry の依存列挙を欠落 header を許さない `-M` で成功させる。`-MG` を残すなら、全依存が実在して探索が完了したことを entry ごとに確定し、できなければ拒否する。

2. **must-fix｜成立 — 「protocol の target entry だけ」という文脈対応は、実 configure の効果を捨てる。** 親の追加実測では `CCBENCH_KEY_SORT` など一つの option が他 protocol の entry の define も変えた。plan の「各 genome configure に当該 protocol の target entry を対応」という選別では、その configure で実際に変わった他 target の文脈を保証から外す。C→C2' の変更 header でこれが差分を隠すことまでは実測されていないが、一般的な header 受理規則の閉包にはならない。根拠: [plan:28–32](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/out/s2-plan.md:28)、[genome-configure-measure.md:9–16](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/evidence/genome-configure-measure.md:9)、[Options.cmake:25](/work/1/SFC/tanab/izanagi/.claude/worktrees/t2854-d297-header-review/external/ccbench/cmake/Options.cmake:25)。**放置時:** 別 protocol の性能 build 文脈で TRACE=0 の展開が変わる header 候補にも、選定範囲を曖昧にした D297 pass が付く。**代替案:** 「選定した production configure のうち、変更 header を読む全 entry」を比較対象にするか、protocol 絞りを維持するなら *他 target の実効 argv が変わっても保証外* と保証名・裁定案に明記する。「production 文脈を覆う」とは書かない。

3. **should｜成立 — compile database の母集合は build の母集合ではない。** plan 自身が database 外の TU・未 configure target を保証外とするのは正しい。現行 CMake では通常の protocol target が無条件に登録され、親の三つの configure で source root 内の `(file, target)` 集合は一致した。ただし option で target の有無が変わらないという一般則ではなく、`CCBENCH_BUILD_MICROBENCH` のような opt-in target もある。forced include、`#include_next`、計算 include は、対象 entry に対して依存探索が完了する限り compiler の依存出力で拾えるため、それ自体への攻撃は不成立。根拠: [plan:24](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/out/s2-plan.md:24)、[genome-configure-measure.md:11](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/evidence/genome-configure-measure.md:11)、[CMakeLists.txt:78](/work/1/SFC/tanab/izanagi/.claude/worktrees/t2854-d297-header-review/external/ccbench/CMakeLists.txt:78)、[CMakeLists.txt:89](/work/1/SFC/tanab/izanagi/.claude/worktrees/t2854-d297-header-review/external/ccbench/CMakeLists.txt:89)。**代替案:** 受理規則の主語を一貫して「選定 configure の compile database に載る entry」とし、production の全 TU という表現を避ける。

4. **should｜成立 — TRACE 値は追加した引数だけでは確定しない。** 親の一時 script は実 argv の末尾へ `-DTRACE=0/1` を足している。現行 database にも `-DTRACE=0` があり、これは探索の実測としては使えても、TRACE=1 照会の最終値や `-Wp,`・response file・forced include 内の再定義まで一般化できない。plan は不透明 argv を拒否し、最終 TRACE 値を記録すると述べているので、方向は妥当である。根拠: [consumers.py:16–44](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/evidence/consumers.py:16)、[plan:20](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/out/s2-plan.md:20)、[Options.cmake:60–68](/work/1/SFC/tanab/izanagi/.claude/worktrees/t2854-d297-header-review/external/ccbench/cmake/Options.cmake:60)。**代替案:** 規則本文で、照会時の実効 TRACE=0/1 を前処理の macro 状態として確認できない entry は拒否、と明記する。`CCBENCH_TRACE=0` の configure 指定だけを証拠にしない。

5. **should｜一部成立 — 正規化が消すものを保証名で限定する必要がある。** `-E -P -dD` の完全展開は有効枝の `#define/#undef` を残す。したがって header 内 `#if !TRACE` の値変更や有効な定義変更を消してしまうという攻撃は、比較対象 TU では不成立。`#line` も `__LINE__`・`__FILE__` の展開結果を変えれば検出できる。一方、使われない診断位置だけの差と、意図して同一論理 root に畳む実 path 差は比較外である。根拠: [plan:36](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/out/s2-plan.md:36)、[plan:59–62](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/out/s2-plan.md:59)、[source_digest.py:1666–1673](/work/1/SFC/tanab/izanagi/.claude/worktrees/t2854-d297-header-review/orchestrator/campaign/source_digest.py:1666)。**代替案:** 「完全展開と include 活性の同一性」に限定し、line marker 全体や診断位置の同一性は名乗らない。root 置換は対応が確認できた prefix に限る。

6. **should｜不成立 — D780 項 2 の別防壁を単独設計した、という攻撃。** 実 compile database を source 比較の入力に使うこと自体は、admission の全 TU・link object・trace symbol/data・build receipt を結合する別防壁の設計ではない。plan はその未結合を明示している。D774 の「実 build の全 define の不在を証明しない」という限界とも整合する。根拠: [D780.md:5–9](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/verbatim/D780.md:5)、[D774.md:3–7](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/verbatim/D774.md:3)、[plan:44–48](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/out/s2-plan.md:44)。**代替案:** 裁定文に「compile database は選定 source 比較の文脈入力であり、admission build receipt との対応を証明しない」の一文を置く。D780 の別防壁や trace 完全除去の証明という名は使わない。

7. **nit｜不成立 — `.cc` 既存拒否、mocc 例外、承認順序を密かに緩めるという攻撃。** plan は header と `.cc` が同居すれば両検査を要求し、mocc の一行例外を拡張しない。これは D2207 の当該 mocc 候補に対する裁定を遡って読み替えず、D2225 決定 6・D2244 項 4 の過去の「D297 合格を名乗らない」事実も維持できる。pin 承認を実装結果の後に別裁定とする案は D2249 項 2 に合う。根拠: [plan:11–14](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/out/s2-plan.md:11)、[plan:66](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/out/s2-plan.md:66)、[plan:87–93](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/out/s2-plan.md:87)、[D2249.md:46–52](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/verbatim/D2249.md:46)。**代替案:** 承認事項案の「pass」は、改訂後 checker の新しい結果にだけ用い、単位 11 の既存証拠を遡及して D297 pass と呼ばない、と明記する。

8. **nit｜不成立 — 親 brief の数値を一般則として使ったという攻撃。** 135 entry・78 file は third-party を含む stock configure の総数、21 entry・12 file はその中の変更 header 消費者であり、直接検索との一致もこの構成に限る。追加実測の source root 内 117 entry と矛盾しない。login の `-E` 失敗は masstree `config.h` 未生成によるもので、完全展開の不一致を示すものではない。plan は GCC 12.3 と genome 文脈の正例を未実測として残している。根拠: [brief:21–27](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/s1-brief.md:21)、[genome-configure-measure.md:9–16](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/evidence/genome-configure-measure.md:9)、[plan:52](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2854-d297-header-review/out/s2-plan.md:52)。**代替案:** これらの数値には引き続き「stock・GCC 11.4・当該 configure」の条件を添える。

## 総括

- **成立した攻撃:** `-MG` による依存探索の途中停止、genome configure が他 protocol の argv も変えるのに target を protocol で絞る点。
- **不成立の攻撃:** 完了した依存探索での forced include 等の見落とし、有効枝の `#define` や `#if !TRACE` の差が完全展開から消えるという主張、D780 の別防壁の単独設計、既存 `.cc` 拒否や承認順序の逸脱。
- **規則案 v2 への修正案:** 全 entry の依存探索が完了したことを受理条件にし、選定 configure 内で実際に変更 header を読む entry の扱いを保証名と一致させる。database 外と admission build との未結合は残る穴として明記する。
- **承認事項案への修正案:** 規則承認・実装委任・実装後の C2' pin 承認を別々に維持する。改訂 checker の pass が得られるまで pin は C、C2' の D297 合格・TPC-C certified は名乗らない。

以上は指定資料の静的検査であり、build・前処理・検査器の実走は行っていない。
