## 1. 問題

トランザクション処理系の並行性制御 (concurrency control、CC) は、競合をいつ検出し、abort の後に
どれだけ待ち、書き込み対象のロックをどの順で取るか、といった判断の集まりである。その最良の形は
ワークロード — 読み書きの比率、アクセスの偏り、スレッド数 — によって変わる。一つの実装を全ての負荷に
使うと、ある負荷では競合を過剰に抑えて CPU を空回りさせ、別の負荷では競合を放置して abort を
繰り返す。ワークロードに合わせて CC を作り分ける動機はここにある。

ワークロード特化を機械に任せる取り組みは、設定パラメータ (knob) の調整、あらかじめ定義した操作の
集合の中での方策探索、CC を学習可能な関数として近似する方法など、いくつかの形で存在する。これらに
共通するのは、対象実装が「取りうる動作の集合」(action vocabulary) を固定したまま、その中から選ぶ
点である。本論文が扱う問いはその一段外にある。**対象実装の動作の集合そのものを、コードとして
拡張できるか。** すなわち、大規模言語モデル (LLM) に CC 実装の中の新しい動作 — abort 後の待機量と
その発火条件、write set の施錠順序、abort 要因別の gate — を生成させ、生成のたびに直列化可能性を
検査しながら、ワークロードごとに検証済み (certified) の選択を出せるか、である。

この問いには安全性の問題が付随する。生成された実装変異は正しさを壊しうるし、性能を最適化する
圧力は正しさの検査を緩める方向に働く (評価器の穴を突いた variant が「速い」と判定される、いわゆる
reward hacking)。したがって正しさの検査は、探索の最後にまとめて回す関門ではなく、毎反復で回して
次の生成の入力にする必要がある。本論文の設計はこの前提から出発している。

## 2. 取り組み: Izanagi

Izanagi は、CCBench の既存実装を素材コーパスとし、ワークロード特化の CC を AI が合成・選択する
システムである。出力は次の 3 点であり、証拠が支持すれば新しい variant を、支持しなければ stock または
「差なし」を正直に返す。**新しい CC が必ず出てくる契約ではない。** [1]

1. **certified な選択結果** — 指定した検証構成と判定器の下で直列化可能性の検査を通り、性能測定を
   経て選ばれた構成。
2. **なぜそれが速いかの説明** — 数値・判定・参照からなる事実層は自動生成できる。機序を言語化する
   仮説層は実装され適用されているが、それが出す仮説は検証対象であって証拠ではない。
3. **試行錯誤の記録** — どれをやるとどうだったかを再現可能な台帳として残す。記録が存在することと、
   その真正性の強さは別である。

先行する取り組みとの差は、次の 3 点で書く。**(i) 対象がトランザクションの並行性制御であること** —
説明と合成の対象は abort・待機・競合検出の判断構造を持つ CC 実装であって、性能 knob の設定ではない。
**(ii) 対象実装の action vocabulary そのものを拡張すること** — LLM が生成するのは既存 knob 上の
条件付き方策ではなく、CC 実装の中の新しい動作であり、固定した原始操作の語彙の中での配合探索ではない。
**(iii) 正しさゲートを毎反復回すこと** — trace を有効にした build と直列化可能性の判定器を毎反復
実行し、正しさ検査を後付けの関門にしない。3 点はいずれも実装と計測が動いている面である。ただし、
すべての説明測定が certified な選択へ束縛されたこと、および 3 点が一続きの科学的証拠鎖を成すことは、
本論文では実証していない。説明の忠実性・証明の連鎖 (proof chain)・試行の来歴 (provenance) は、
核ではなく補助として扱う。[2]

位置づけについて、本論文が言えるのは次の 1 文までである。「本調査では、LLM が、トランザクションの
並行性制御を対象として、アクション空間自体をコードで拡張する既存例を発見していない。」この記述は
3 条件 (LLM が / トランザクションの並行性制御を対象として / アクション空間自体をコードで拡張する)
のすべてに限定され、どれ 1 つ落とした短縮形では成り立たない。LLM の進化探索で取引の scheduling 方策を
コードとして進化させた研究 (ADRS) については、関連研究の正典でこの 1 文の 3 条件ごとに判定し、「LLM が」は
満たすが、「並行性制御を対象として」と「アクション空間自体をコードで拡張」は一部だけ満たす近傍と記録した。
反例ではないが、その判断は 1 文の条件の狭い読みに依存する。したがって 1 文を「取引に関わる」「コードを書く」の
ように緩めた短縮形では成り立たない。近傍という判定は非該当の断定ではなく、先行研究の間に順位をつけるものでもない。
先行研究の調査は費用対効果を理由に限定付きで止めており、完了でも優先権の主張でもない。個々の先行との
比較は関連研究の節に委ねる。[3]

## 3. 本論文の主張の流れ

本論文は 3 幕で構成される。第 1 幕は評価器、第 2 幕は当初仮説の反証と価値の所在、第 3 幕はコード
粒度の合成であり、**論文の主軸は第 2 幕にある。**

**第 1 幕 — 信頼できる評価器を先に建てる。** 合成の前に、正しさの判定器と性能の測定契約を整えた。
判定器は実行 trace から読み書きの依存グラフを作り、反依存を含む循環 (G2) まで検出する。その検出力は
双方向に確かめた — 意図的に壊した Silo で 1,310 件の G2 を赤と判定し、無改変の snapshot isolation の trace でも
3,576 件の G2 を赤と判定した (後者は snapshot isolation の旧形式 trace を受理していた当時の判定器の記録で、
現行の判定器はその形式を parse error で拒否する)。素の Silo と 8 genome の既知構成は緑だった。判定器自身への
敵対的検証は「不正な trace で赤を隠せる」穴を見つけ、判定を 3 値化 (indeterminate の追加) して安全側に倒した。
その後、壊し変異の検出期待表を実走で埋めた — 既存の Silo 壊し patch では 13 run 中 12 run が期待どおりだったが、
新規の Silo 変異と診断変異の 15 行では期待した層での検出は 3 行にとどまり、変異が挙動を変えその取引が commit した
履歴を直列化可能と判定した「盲点」が 6 行あった。mocc の 34 cell では期待した層での検出が 20 cell、盲点が 1 cell で、
sort の変異 1 件も判定器は捕まえない。盲点は判定器の欠陥の主張ではなく (値や lock 順のように直列化可能性の条件の
外にある変更を含む)、これは検出力の網羅的な証明ではない。ここで「certified」が意味するのは、YCSB の point read / write に
限った、実際に観測できた trace 上の直列化可能性までである。述語や phantom、公平性、観測されなかった
実行は保証しない。TPC-C の段 1 (NewOrder / Payment、点読み・点書き・insert) について判定器は存在履歴を
含む trace の形式を読めるようになり、実 trace 1 本を直列化可能と判定したが、本稿はこれを上の定義の
certified とは呼ばず、合成した候補を TPC-C で評価したこともない。性能測定は trace を無効にした別
build・別走行で行い、正しさの検査と分離する。[4]

**第 2 幕 — 当初仮説の反証と、価値の所在の発見。** 対になる 2 つの結果が本論文の心臓部である。
否定的結果では、Silo の既存フラグ空間 (実質 1 ビットで決まる自明な空間) を対象に、LLM 誘導探索と
LLM を使わない貪欲探索の到達コストを比べた。balanced では有意差がなく (確率優越 A = 0.5813、
p ≈ 0.16)、欺瞞的な構造を持つ write-heavy では誘導が貪欲より有意に有害だった (A = 0.2304、厳密
permutation p = 2.52 × 10⁻⁴、12 試行中 8 が誤収束)。評価器の側の自信ある早期停止が、欺瞞的な信号の下で
負債になることの定量実証である。肯定的結果では、評価指標の帰属 (適応 backoff は abort を抑えているが
IPC が崩れている) がフラグ空間の外の新しい軸「backoff 量の静的固定」の合成を駆動した。旧
`linux-baremetal` 環境の記述的な sweep では、同一 sweep 内の無 backoff 対照に対して write-heavy
+38.3%、balanced +11.3%、read-heavy −6.6% — 3 workload のうち 2 つで勝ち、1 つで負けた。この一事例が
言うのは「対象実装 (CCBench の Silo) のフラグ空間の外へ合成が到達した」ことまでであり、backoff という
機構の新しさではない — backoff の学習は Polyjuice (OSDI'21 §4.5) が既に扱っている。この対比が
第 2 幕の結論を決める。**フラグ空間の探索は自明で LLM の出る幕がなく、価値は空間の外への合成に
ある。** 否定的結果は薄い結果ではなく、コード粒度の合成が要る理由を定量的に動機づける要石である。[5]

**第 3 幕 — コード粒度の合成。** Silo 1 protocol と backoff / sort / trigger-gating の 3 軸に限定して、
設定した正しさゲートを一度も緩めずにコード粒度の合成を certified まで回せる safe variant loop が
成立した。これは運用上の証拠であり、ワークロード条件付き合成の因果証拠ではない。性能の側では、
事前登録した縮小主張 S' が不成立で確定した — 合成した軸 (trigger-gating) は既知軸の一部 (書込ロック順の
並べ替え) には 3 workload とも明確に勝ったが (+55.5% から +98.4%)、コンパイル時フラグ最適化と静的
backoff 最良値には負け、「既知軸最良を超える」という家族連言は満たさなかった。合成した軸の on/off 効果
そのものは登録した追試として成立したが、事前に既知だった効果であり新発見ではない。一方で、正しさの
側と測定契約の側は前に進んだ。採用した静的 backoff は、性能を測った workload そのもので certified で
あり (保証範囲は第 1 幕のとおり観測できた point-key trace に限り、残る限定は限界節に示す)、現行
Pegasus 環境の正式な対測定は 3 つの独立した走行で判定を出した (write-heavy と balanced の
連言で `observed-positive`、read-heavy で `reject`、balanced の別の事前登録で `accepted`)。これらは
事前登録した判定式の出力であって研究の成否宣告ではなく、旧環境の値と符号が一致したことは記述的な
照合であって再現判定ではない。機構 (軸提案のループ内化、セッションを跨がない駆動、材料レポート、
機序仮説層) は深まったが、一続きの鎖として実走した事実はなく、「非列挙のコード片軸」を現行の編集面で
実体化しようとした試みは、有限幅と代理指標の二重の壁に当たって止まっている。[6]

第 3 幕には、本稿の時点で結論を変えない 3 種類の前進がある。第 1 に、合成ループを同じ job の中で stock
対照と並べて走らせる経路が成立し、候補と stock がともに certified の記述値 (同 job の比 2.366 と 2.493) を
得た — これは配線 1 点の記述値であり、改善・候補間の優劣・診断の効果を示すものではない。第 2 に、合成の
単位を関数単位の方策 (型付きの有限な中間表現) へ広げる軸を開き、その固定 16 点を機械で偵察した。
既知最良 (静的 10 µs) を同じ job に置いた小比較では 16 点のうち 3 点が 6〜7% 上回ったが、1 回・再測なし・
16 点から最大を選ぶ多重選択の補正なしの探索的な観測であり、既知最良を超えたとは書かない (論文でそう書く
前に再測すると裁定されている)。16 点は LLM が生成したものではなく、LLM が方策を生成する段階は本稿の時点で
実装されていない。第 3 に、LLM による生成器を乱択・機械 sweep と同じ評価数で比べる事前登録した対照は、
本走の最初の段で LLM の週上限に当たって系列が欠測し、現行の標本の比較はすべて判定不能になった
(続け方は裁定待ち)。性能の側の結論 — 既知軸最良を超えるという主張には届かなかった — はどれによっても
変わらない。[7]

## 4. 本論文で言うこと、言わないこと

本論文が言うのは、(a) 判定器の検出力と certified の保証範囲、(b) 自明な空間での LLM 誘導探索の
無益さと有害さ、(c) 空間の外への合成の一事例とその性能効果 (勝ちと負けの両方)、(d) 正しさゲートを
毎反復回す合成ループが限定スコープで成立したこと、(e) 既知軸最良を超えるという主張が測って
不成立だったこと、(f) AI 主導の研究を運用した記録、である。

本論文が言わないのは、優先権や世界初、「新しい CC ができた」、「LLM でなければ到達できない」、
「ワークロード特化の合成ができた」、「無人で研究ループが回る」、「一般に直列化可能性を保証した」、
「mocc は第 2 の成功例」、「関数単位の合成が既知最良を超えた」、「TPC-C で CC を評価した」、
「生成器の対照で LLM が勝った・負けた」である。これらは限界節で理由とともに扱う。証拠の種別 — 科学的主張、
登録追試、限定付きの観測、固定条件で certified な正しさ、運用上の証拠、未取得 — は貢献節で
主張ごとに分けて示す。
