## 1. 問いに対する答え

本論文が問うたのは、対象実装が取りうる動作の集合 (action vocabulary) そのものを LLM にコードとして拡張させ、生成のたびに直列化
可能性を検査しながら、ワークロードごとに certified な選択を出せるか、である。答えは次の 2 つに分かれる。

第 1 に、**そのような loop は限定スコープで成立した。** Silo 1 protocol と backoff / sort / trigger-gating の 3 軸に限り、設定した正しさ
ゲートを一度も緩めずにコード粒度の合成を certified まで回せる safe variant loop が動き、pin 前進前の CCBench の下で 4 度 certified の
終端判定へ到達した。ただしこれは運用上の証拠であって、ワークロード条件付き合成の因果証拠ではなく、loop が評価したのは固定 backoff の
初期値であって新しい CC 構造ではない。[1, 6]

第 2 に、**拡張した動作が性能を変えることは一事例として実証された。** 評価指標の帰属を起点に、Silo の既存フラグ空間の外へ合成した軸
「abort 後の待機量の静的固定」は、旧 `linux-baremetal` 環境の記述的な sweep で、同一 sweep 内の無 backoff 対照に対して write-heavy
+38.3%、balanced +11.3%、read-heavy −6.6% を示した — 3 workload のうち 2 つで勝ち、1 つで負けた。この一事例が示すのは実行可能性まで
であり、合成の一般性と「LLM でなければこの軸に到達できなかった」という因果的必要性は実証していない。backoff という機構は既存の学習型 CC
(Polyjuice) も学習の対象に含めていたので、この一事例は機構の新しさではなく、対象実装 (CCBench の Silo) のフラグ空間の外へ合成が到達したことを
示す。[2, 3, 10]

## 2. 否定的結果が決めた価値の所在

本論文の心臓部は、対になる 2 つの結果である。Silo の有限フラグ空間 (実質 1 ビットで決まる自明な空間) では、LLM 誘導探索は LLM を
使わない貪欲探索の到達コストを超えず (balanced: 確率優越 A = 0.5813、p ≈ 0.16)、欺瞞的な構造を持つ write-heavy では貪欲より有意に
有害だった (A = 0.2304、厳密 permutation p = 0.0002521、12 試行中 8 が誤収束)。これは事前に立てた仮説「LLM 誘導探索は全探索より速く
収束する」を独立に反証した結果であり、評価器の側の過信が欺瞞的な信号の下で負債になることの定量実証である。この否定的結果と、
空間の外への合成の一事例とを対にすることで、**価値はフラグ空間の探索ではなく空間の外への合成にある**と言える。否定的結果は薄い
結果ではなく、コード粒度の合成が要る理由を定量的に動機づける要石である。[3]

一方で、合成した軸が既知軸最良を超えるという事前登録した縮小主張 S' は、測って不成立だった。合成した軸 (abort 要因別の gate) は
既知軸の一部 (書込ロック順の並べ替え) には 3 workload とも +55.5〜+98.4% で勝ったが、コンパイル時フラグ最適化と静的 backoff 最良値には
負け、9 対の家族連言を満たさなかった (family p = 1.0)。合成軸の on/off 効果は登録した追試として成立したが、機械 sweep で既知だった効果で
あり新発見ではない。適格率次元の発見再現性は未実証のままであり、この成立はその限界を解消しない。S' は結果既知の追試として登録されたので、この不成立は「事前に立てた仮説が独立に棄却された」型ではなく、「登録した
複合主張が測ってみたら成立しなかった」という失敗報告として書く。本論文の主張は、この不成立を経て、一事例の実行可能性へ狭まっている。[4]

## 3. 正しさの側で到達したこと

合成の前に建てた評価器は、その検出力を双方向に確かめてある — 判定器は意図的に壊した Silo で 1,310 件、無改変の snapshot isolation で
3,576 件の G2 を赤と判定し (後者は判定器が snapshot isolation の旧形式 trace を受理していた当時の記録で、現行の判定器はその形式を parse error で拒否する)、
素の Silo と既知の 8 genome は緑だった。判定器自身への敵対的検証は「不正な trace で赤を隠せる」穴を見つけ、
判定を 3 値化して安全側に倒した。ここで certified が意味するのは、YCSB の point read / write に限った、実際に観測できた trace 上の直列化
可能性までである。述語や phantom、公平性、観測されなかった実行は保証せず、certified は実際に build された bytes についての判定であって、
要求した構成が build されたことを含意しない。[5]

検出力はその後、事前に期待を登録した変異の実走で、Silo と mocc の行が表として埋められた (第 3 の実装 si の行は未実走)。Silo の新規変異と既存の trigger 誤帰属の 15 行では、期待した層で検出 3・
別の層で検出 1・変異が挙動を変えてその取引が commit したのに判定が certified だった行 (盲点) 6・変異が起きなかった行 2・正しさを保つ対照の誤検出 0 で、
第 2 の実装 (mocc) の 34 cell では期待した層で検出 20・盲点 1・停止 3 などだった。盲点の行は、値・取引内の読み・lock の順序のように直列化可能性の
判定の外にある変更を含み、判定器の欠陥の主張ではない。これらは各 cell 1 回の有限の走の観測で、検出力の網羅的な証明ではない。[5, 11]

その保証範囲の中で、正しさの側は前に進んだ。採用した静的 backoff は、性能を測った workload そのもので certified である (現行環境の
A-2 の 4 cell と A-6 の 2 cell、いずれも trace 有効の別走行)。これは性能の認証ではなく、限定が 5 つ残る — 保証範囲は上のとおり point-key
trace に限る、正しさ側の実行引数は独立に記録されていない、artifact hash 単独では compile-out の証明にならない、測定条件の関門について残るのは
admission の記録と ID まで、source identity の一致は実翻訳単位全体の意味の一致を保証しない。この certification は旧環境の 3 値へは遡らず、
旧 3 値の正しさは今も「backoff は正しさに影響しない」という機序論証による外挿である。採用候補 2 genome (fixed 5 / fixed 10 µs) の検証相は、候補ごとに
判定集合 30 verify で anomaly 0 という操作的事実を残した (確率主張ではなく、性能値を含まず、別の要件である「種を変えた長時間実行による
最終候補の検証」の充足でもない)。その別の要件については、合成した軸 (abort 要因別の gate) の最終候補 (案 A = 系側 gate 構成) を対象に、
S' とは別に登録した事前登録 (B-8 の事前登録) を発効させ、対象・種・長時間の 3 要件が揃った検証を行った — 本走 (独立 8 反復 × 3 workload、
extime 10 s の trace 有効 build) 24 枠と校正の完走 6 枠を合わせた判定集合 30 枠すべて anomaly 0、規則を機械適用した 3 値判定は `pass` だった。
これは研究の成功宣告でも S' の事前登録の (iv) 付属 (検証相の規則) の充足でもなく、上の保証範囲を超えない操作的事実である。「種を変えた」は独立 process の
自己シード、「長時間」は extime 10 s という操作的定義で、性能値を含まず、この候補が既知軸最良を超えなかったこと (§2) も変えない。
検証相とは対象が違うので、両者を比較もプールもしない。
正式 protocol が要求した build 定義を黙って無視したまま完走した旧 attempt は、判定を取り消さずに
「支持する命題が違う」と追記で訂正し、source を identity に束縛した driver で取り直した — 正しさの緑だけでは要求した構成が build された
ことを言えない、という穴の実例と、その塞ぎ方の両方がそろった。残る限界 (前処理指令と include の相対位置、`push_macro` / `pop_macro`) は
限界稿に明記してある。[5, 6, 9]

YCSB の外では、TPC-C の NewOrder / Payment だけからなる段 1 について、判定器が表と key の組で履歴を読み、段 1 の存在の契約 (初期ロードと insert の
規則) を検査するよう広げられ、Silo の実 TPC-C trace 1 本 (36,156 取引) を判定器が直列化可能と判定し、存在違反を注入した写しと末尾を欠いた写しは
拒否した。この判定は本論文の certified の定義 (YCSB の point read / write) の外にあり、範囲読み・削除・再挿入を含む段 2 の保証を意味しない。合成した
候補を TPC-C で評価・判定した記録と、TPC-C の性能測定は無い。[12]

## 4. 測定契約の側で到達したこと

性能の比較は、比べる構成を同じ campaign の中で対にして測り、判定規則を結果を見る前に事前登録する契約へ移った。現行 Pegasus 環境で
採用静的 backoff を測った正式な 3 走行は、write-heavy と balanced の連言で `observed-positive` (median 比 +63.5485% / +14.4213%)、
read-heavy で `reject` (−5.7841%)、balanced の別の事前登録による対で `accepted` (+11.2254%) という判定を出した。これらは事前登録した
判定式の出力であって研究の成功宣告でも失敗宣告でもなく、信頼区間も有意差判定も持たず、3 つは独立した protocol であって 1 つの横断
実験ではない。符号が旧環境の 3 値と 3 workload とも一致したことは記述的な照合であって再現判定ではなく、旧値と新値はプールしない。[2, 6]

現行契約が定める配置と推定対象 (均衡ブロック交互配置、対差平均、n = 30、登録済みの区間推定) による測定では、非認証 lane の attempt が
2 本完走し、いずれも登録済み解析の分類は 3 workload とも `resolved-above-floor`、対差平均の符号は + / + / − だった (attempt-0002 では
write-heavy と read-heavy で標本標準偏差が計画値を超えたが分類は変わらない)。2 本は同じ policy・同じ seed・同じ物理順の独立した観測で
あり、本論文はそれらをプールせず、再現性の判定も行わず、この測定契約の正式な結果や要件充足とも扱わない — その lane は昇格を禁じられ、
充足の判定はユーザー手番に残っている。同一候補 fixed 5 µs を 3 workload で同時期に測った走行では read-heavy だけが走行間ばらつきの
下限を超えて退行し (−11.3787%、下限 0.2228%)、「全 workload の退行込み報告」という報告要件は単一 attempt・descriptive・非認証・
反復間安定性は未判定という限定付きで満たしたと裁定された。利得側だけを引用することはせず、read-heavy の負の向きは旧環境・正式
protocol・同一候補の測定・非認証 lane の 2 attempt のいずれでも落とさない。[6]

## 5. 未実証のまま残る主張

本論文は次を実証していない。既知軸最良の超越 (測って不成立)、ワークロード記述を条件とする生成の因果効果 (on / off の対照が無い)、
無人系列の完走 (駆動は bounded MVP で、止めている最上流は権限の不在である)、構造化された正しさシグナルの還流による改善 (適格な赤
precursor が 0 件で ablation は実施不可)、生成器の条件付き優越 (対照の事前登録に基づく本走は認可されて投入されたが、LLM の利用上限で
生成側の系列が止まり、登録した 6 比較すべてが判定不能 (欠測) となって、続行形は裁定待ちである)、backoff の機序の
同定 (閉じているのは 0〜10 µs の帯だけで、右 tail は「登録した述語では表現可能域までに飽和を観測しなかった」という記述的な結末に
とどまる)、クロスプロトコルの選定 (Silo 固定の方針は解除され、素材コーパスの版は第 2 の実装 (mocc) の計装を含む版へ進み、比較基盤へ mocc を
差し込む疎通も確かめたが、非 Silo の性能比較は 0 件)、体系的な先行研究調査 (2 軸とも限定付きで止まっている)、TPC-C での合成と評価
(段 1 の trace の判定まで、§3)。現行契約下の対測定は記述的な観測までで正式な充足は未判定、論文採用値の別 boot での取り直しは
未取得である。実装・準備・裁定・認可の進展は、これらの証拠の取得を意味しない。種を変えた長時間実行による最終候補の検証はこの一覧に
含めない — 3 要件が揃った検証で 3 値判定が `pass` だったが (§3)、それは最終候補の正しさ側の検証であり、上に挙げた主張のどれも
埋めない。[6, 7, 9, 13]

関数単位のコード空間についても、主張は届いていない。Silo の lock 競合への応答と abort 後の待ち方の方策を型付きの小さな中間表現で書ける空間を開き、
その 4 因子 × 2 水準の固定 16 点を機械で偵察したところ、同じ job に置いた既知最良 (pin `e9e477ca` の branch で測り直した静的 10 µs。Silo の該当 source は現行の pin C と差分がない) を 3 点が 6〜7% 上回った。ただしこれは報告カテゴリが偵察の
1 回の走行で、再測も、16 点から最大を選んだことの多重選択の補正もしておらず、比べた静的値は 10 µs の 1 点、workload は write-heavy だけである。
論文でこの 3 点を既知最良を超えた点として書くには、その前に別 job で測り直すと定めてあり、本稿の時点で測り直しは無い。16 点は結果を見る前に定数を固定した
格子の点で (未調整)、LLM がこの空間で方策を生成した結果も無い。したがって「合成が既知軸最良を超える」という主張 (上の一覧の最初) は不成立のままである。[14]

したがって本論文は、「新しい CC ができた」「ワークロード特化の合成ができた」「LLM でなければできない」「無人で研究ループが回る」
「一般に直列化可能性を保証した」「mocc は第 2 の成功例」「関数単位の合成が既知最良を超えた」「TPC-C で CC を評価した」とは書かない。
位置づけについて言えるのは「本調査では、LLM が、トランザクション
の並行性制御を対象として、アクション空間自体をコードで拡張する (固定した原始操作語彙の中で生成するのではなく) 既存例を発見していない。」
の 1 文 (関連研究稿 §2.1 の逐語) までであり、優先権や系譜の中の順序は主張しない。近傍の研究 (ADRS) はこの 1 文の 3 条件を一部だけ満たすと判定しており、
それを「最も近い」と順位づけることもしない。[7, 8]

## 6. 方法論としての含意

本研究は AI が主導する研究の運用そのものを記録として持つ — 全主張への多エージェント敵対的反証、統計指標の再校正と訂正の履歴を
機械可読で残すこと、判定器の fails-closed 化、外部から来た入力を指示ではなくデータとして扱う信頼境界、結果を見る前に規則を固定する
事前登録、認可済みの再測定を正しさ由来の防壁が拒否したときに受理集合を AI の裁量で広げず裁定へ返すこと。これらは運用上の証拠であり、
運用が結果を良くしたという対照実験ではない。本論文の書き方 — protocol の status を成否のラベルとして読まず、性能の判定と別走行の
正しさの証拠を別の段で書き、別 protocol の走行をプールせず、旧い判定を取り消さずに追記で訂正し、証拠の種別を主張ごとに分ける — は
この運用の帰結であり、結果の非対称 (機構は深まったが、測りたい量の多くは未取得) を隠さないための規律である。
費用の見積りが実測の後で大きく外れたとき (評価 1 回の所要の大半が正しさの検証だった)、検査の本数や判定を減らして費用を削る案は採らず、
同じ検査を同じ node で同時に走らせる形や、生成の待ちを計算資源の外へ出す形を比べて裁定へ返したことも、同じ規律の例である。[8, 13]

## 7. 次に必要な証拠

本論文の主張を一段強くするために要る証拠は、いずれも新しい測定であり、その多くは投入の認可と計算の事前確認を要する。生成器の条件付き優越は、
事前登録した対照 (合成 loop・ランダム変異・機械 sweep を同一評価数で比べる) の本走で問う — 上限付きの試走は完走したが、主標本の外で
優劣は言えず、認可された本走の最初の段は判定不能で止まったので、系列を登録し直すか見送るかの裁定が先にある。探索の独立反復の費用と成果の曲線も、
write-heavy だけに縮めた試走が最初の段で欠測を出して止まっており、結果は無い。反例還流の効果は、適格な赤 precursor が
必要数そろったときにだけ ablation で問える。正しさシグナルを毎反復回す loop の同 job stock 対照は、再投入で候補と stock がともに certified の pair が
成立し 4 巡目でも同型だったが、その比は配線 1 点の記述値で、改善や診断の効果を示すものではない。現行契約下の対測定は attempt 2 本の記述的な観測までで、
formal な lane での充足はユーザー手番の判定に属する。ワークロード記述を条件にした合成の因果証拠は、descriptor を入力にした選択と材料レポートの経路で問うが、
その前提の旧系列 (凍結した oracle 実走の起動と正式系列) の再開は、論文の必須経路から外すと裁定されている。関数単位の空間で既知最良を超えるかは、
偵察で上回った点の別 job の測り直しと、LLM が方策を生成する段で問う (後者は裁定済みで未実装)。TPC-C は、合成候補を段 1 で評価・判定する経路の
配線と、範囲読みを含む段 2 が要る。素材コーパスの第 2 の実装 (mocc) は比較基盤で動くことを確かめた段階で、比較はまだ無い。未知条件への転移は
事前登録と実行器があり、測定は発効していない。これらのいずれも、本論文の時点で得られた条件付きの観測と、未実証の生成・還流効果とを分けて報告する形は
変えない。[6, 7, 13, 14, 15]
