## 1. 要旨 — 短縮版 (約 600 字)

トランザクション処理系の並行性制御 (CC) の最良の形はワークロードによって変わる。本論文は、対象実装が取りうる動作の集合
そのものを大規模言語モデル (LLM) にコードとして拡張させ、生成のたびに直列化可能性を検査しながら、ワークロードごとに検証済み
(certified — 指定した検証構成で観測した YCSB point read / write の trace 上の直列化可能性の判定であり、性能の認証ではない) の選択を
返すシステム Izanagi を報告する。Silo の有限フラグ空間では LLM 誘導探索は貪欲探索を上回らず、欺瞞的な負荷では有意に有害だった。一方、フラグ空間の外へ
合成した「abort 後の待機量の静的固定」は、旧環境の記述的な sweep で無 backoff 対照に対し write-heavy +38.3%、balanced +11.3%、
read-heavy −6.6% を示した (機構の新しさではなく、対象実装の空間の外への到達の一事例である)。別の合成軸である abort 要因別の gate が既知軸最良を超えるという登録追試の主張は、測って不成立だった。
限定スコープで正しさゲートを一度も緩めずに合成を certified まで回す loop は成立したが、ワークロード条件付き合成の因果証拠と
LLM の必要性は未取得である。価値がフラグ空間の探索ではなく空間の外への合成にあることを、否定的結果と一事例の対で示す。[1, 2, 3, 4, 5]

## 2. 要旨 — 標準版 (約 1,910 字)

トランザクション処理系の並行性制御 (CC) は、競合の検出時点、abort 後の待機、ロックの取得順といった判断の集まりであり、その最良の
形はワークロードによって変わる。設定パラメータの調整や固定した操作集合の中での方策探索は、対象実装が取りうる動作の集合 (action
vocabulary) を固定したまま選ぶ。本論文は、その集合そのものを大規模言語モデル (LLM) にコードとして拡張させ、生成のたびに直列化
可能性を検査しながら、ワークロードごとに検証済み (certified) の選択を返すシステム Izanagi を報告する。CCBench の既存実装を素材とし、
正しさの判定器 (実行 trace の依存グラフから反依存を含む循環 G2 までを検出する。意図的に壊した Silo で 1,310 件、無改変の snapshot
isolation で 3,576 件の G2 を赤と判定した — 後者は判定器が snapshot isolation の旧形式 trace を受理していた当時の記録) と、trace を無効にした別 build・別走行で性能を測る契約を先に整えた。本論文で certified と
書くのは、指定した検証構成で観測した YCSB の point read / write の trace に対する判定器の直列化可能性の判定であり、観測されなかった
実行や述語・phantom・公平性は対象外で、性能の認証でもない。Silo の有限フラグ空間
(8 構成) では、LLM 誘導探索は LLM を使わない貪欲探索の到達コストを超えず (balanced: 確率優越 A = 0.5813、p ≈ 0.16)、欺瞞的な構造を
持つ write-heavy では有意に有害だった (A = 0.2304、厳密 permutation p = 0.0002521、12 試行中 8 が誤収束)。一方、評価指標の帰属を起点に
フラグ空間の外へ合成した軸「abort 後の待機量の静的固定」は、旧環境の記述的な sweep で、同一 sweep 内の無 backoff 対照に対し
write-heavy +38.3%、balanced +11.3%、read-heavy −6.6% を示した (2 負荷で勝ち、1 負荷で負ける)。backoff という機構は既存の学習型 CC
(Polyjuice) も学習の対象に含めており、この一事例が示すのは機構の新しさではなく、対象実装 (CCBench の Silo) のフラグ空間の外へ合成が
到達したことである。正しい identity で測った現行環境の
正式な 3 走行 (write-heavy と balanced の連言で `observed-positive`、read-heavy で `reject`、balanced の別の事前登録で `accepted`) は、
旧環境と同じ向きの符号を示したが、これは記述的な照合であって再現判定ではない。別に、昇格を禁じられた非認証 lane の 2 attempt が完走し、
各 attempt の登録済み解析は 3 workload とも `resolved-above-floor`、対差平均の符号は write-heavy / balanced / read-heavy の順に + / + / −
だった — これは記述的な観測であり、A-1 の正式充足や再現判定ではない。合成した別の軸 (abort 要因別の gate) が既知軸最良を超えるという
事前登録した主張は測って不成立で
(family p = 1.0)、既知軸の一部 (書込ロック順の並べ替え) には 3 workload とも +55.5〜+98.4% で勝った。この軸の最終候補 (案 A = 系側
gate 構成) は、この主張とは別に事前登録した正しさ検証で、本走 (独立 process の自己シードによる 8 反復 × 3 workload、extime 10 s の trace 検証)
24 枠と校正の完走 6 枠を合わせた判定集合 30 枠すべて anomaly 0 となり、規則を機械適用した 3 値判定は `pass` だった — これは性能値を含まない
正しさ側の結果であり、研究の成功宣告でも、上の主張の事前登録の充足でもなく、その不成立を変えない。限定スコープ (Silo 1 protocol・
3 軸) で正しさゲートを一度も緩めずにコード粒度の合成を certified まで回す loop は成立したが、それは運用上の証拠であり、ワークロード
条件付き合成の因果証拠、LLM の必要性、正しさシグナルの還流による改善はいずれも未取得である。本論文は、価値がフラグ空間の探索では
なく空間の外への合成にあることを否定的結果と一事例の対で示し、主張ごとに証拠の種別 (科学的主張、登録追試、限定付きの観測、固定条件で
certified な正しさ、運用上の証拠、未取得) を分けて報告する。[1, 2, 3, 4, 5, 6, 8, 9]

## 3. 要旨 — 構造化版

**背景。** トランザクション処理系の CC の最良の形はワークロード (読み書きの比率、アクセスの偏り、スレッド数) によって変わる。
設定パラメータの調整や、あらかじめ定義した操作集合内の方策探索では、対象実装が取りうる動作の集合を固定して選択する。[1]

**目的。** 対象実装の動作の集合そのものを LLM にコードとして拡張させ、生成のたびに直列化可能性を検査しながら、ワークロードごとに
certified な選択を出せるかを問う。位置づけについて言えるのは次の 1 文までである —「本調査では、LLM が、トランザクションの並行性
制御を対象として、アクション空間自体をコードで拡張する (固定した原始操作語彙の中で生成するのではなく) 既存例を発見していない。」
(関連研究稿 §2.1 の逐語)。3 条件のどれ 1 つを落とした短縮形では成り立たず、括弧内の限定も落とさない。先行研究の調査は限定付きで止まっている。
近傍の研究 (LLM が取引の scheduling 方策をコードで進化させた ADRS) は 3 条件のうち「LLM が」だけを満たし他の 2 条件は一部だけ満たすと判定しており、
反例ではないことは 1 文の条件の狭い読みに依存する。[1, 7]

**方法。** CCBench の既存実装を素材とし、(i) 正しさの判定器 (実行 trace の依存グラフから G2 までを検出。検出力は意図的に壊した Silo
1,310 件、無改変の snapshot isolation 3,576 件 (旧形式 trace を受理していた当時の記録) で確認し、判定を 3 値化して安全側に倒した) と、(ii) trace 無効の別 build・別走行の性能測定
契約を先に整えた。certified は、指定した検証構成で観測した YCSB point read / write の trace に対する判定を指し、性能の認証ではない。合成は、指定した編集領域に LLM がコード片を挿入する操作と、列挙できる軸内の機械探索を組み合わせ、毎反復で trace
有効 build と判定器を実行する。性能の比較は、比べる構成を同じ campaign の中で対にして測り、判定規則を結果を見る前に事前登録する。[2, 3]

**結果。** (a) Silo の有限フラグ空間では LLM 誘導探索は貪欲探索を超えず (balanced A = 0.5813、p ≈ 0.16)、write-heavy では有意に有害
(A = 0.2304、p = 0.0002521、12 試行中 8 が誤収束)。(b) フラグ空間の外へ合成した静的 backoff は、旧環境の記述的な sweep で無 backoff
対照に対し write-heavy +38.3% / balanced +11.3% / read-heavy −6.6%。backoff という機構は既存の学習型 CC も扱っており、示すのは対象実装の
空間の外への到達の一事例である。現行環境の正式 3 走行 (`observed-positive` / `reject` / `accepted`)
は同じ向きの符号を示した (記述的な照合であって再現判定ではない)。別に、昇格を禁じられた非認証 lane の 2 attempt が完走し、各 attempt の
登録済み解析は 3 workload とも `resolved-above-floor`、符号は + / + / − だった (記述的な観測であり、A-1 の正式充足や再現判定ではない)。
(c) 合成した軸 (abort 要因別の gate) が既知軸最良を超える主張は不成立 (family p = 1.0)。書込ロック順の並べ替えには +55.5〜+98.4% で
勝ち、コンパイル時フラグ最適化と静的 backoff 最良値には負けた。この軸の最終候補 (案 A = 系側 gate 構成) は、この主張とは別に事前登録した
長時間の正しさ検証で、本走 (独立 8 反復 × 3 workload、extime 10 s の trace 有効 build) 24 枠と校正 (extime 6 s / 10 s) の完走 6 枠を合わせた
判定集合 30 枠すべて anomaly 0、規則の 3 値判定は `pass` だった。これは規則の機械適用の出力であって研究の成功宣告ではなく、性能値を含まず、
上の不成立を変えず、その主張の事前登録の (iv) 付属 (検証相の規則) を充足するものでもない。「種を変えた」は独立 process の自己シード、「長時間」は extime 10 s
という操作的定義である。(d) 現行環境の A-2 / A-6 で採用した静的 backoff には、性能を測った
workload に対応する別走行 (trace 有効) の correctness 記録がある。この認証は旧環境の 3 値へ遡らず、性能の認証でもなく、実行引数の独立記録・
compile-out・条件関門の保存証拠・source identity の束縛範囲に限定が残る (限界稿 §2)。(e) 限定スコープで正しさゲートを一度も緩めずに
コード粒度の合成を certified まで回す loop が成立した (運用上の証拠)。[3, 4, 5, 8]

**結論。** 価値はフラグ空間の探索ではなく空間の外への合成にあり、否定的結果はその理由を定量的に動機づける。本論文が言うのは
一事例の実行可能性までであり、合成の一般性、ワークロード条件付き合成の因果証拠、LLM の必要性、還流による改善、合成軸が既知軸最良を超えることは未取得である。
出力契約は certified な選択結果であり、証拠が支持しなければ stock または「差なし」を返す。[5, 6]

## 4. 要旨に書かないこと (理由は限界稿)

要旨は論文全体で最も強く読まれる場所なので、次の短縮形・過大表現を使わない。禁止の理由と代替の書き方は
[限界節草稿](../paper-intro-ja/limitations.md) が持つ。前稿からの継承 11 項に、前稿の採用時点より後の着地に対応する 7 項 (末尾の「(本稿で追加)」) を足した。

- 「先行なし」「世界初」「唯一」「最も近い」「系譜の N 本目」、および位置づけの 1 文から 3 条件のどれかを落とした短縮形。
- 「新しい CC ができた」— 出力契約は certified な選択結果であり、証拠が支持しなければ stock または「差なし」を返す。
- 「ワークロード特化の合成ができた」— descriptor を条件にした生成の因果証拠が無い。
- 「LLM でなければできない」— 対照を取っても言えない形であり、条件付き優越の対照も未取得。
- 「合成した軸が既知軸最良を超えた」— 測って不成立。
- 「現行環境で再現した」「A-1 の値がある」— 符号の一致は記述的な照合、非認証 lane の 2 attempt はプールも再現判定もしない。
- 「無人で研究ループが回る」— 駆動は bounded MVP で正式系列は未発効。
- 「一般に直列化可能性を保証した」— 保証は観測できた YCSB point read / write の trace 上に限る。
- 「最終候補の正しさを証明した」「異なる乱数列で検証した」— B-8 の `pass` は規則の機械適用の出力であり、種 (独立 process の自己
  シード) と長時間 (extime 10 s) は操作的定義で、性能値を含まない。
- 「mocc は第 2 の成功例」「クロスプロトコルへ広げた」— 非 Silo の性能比較は 0 件 (MOCC を比較基盤へ差し込んだのは疎通の確認までで、比較ではない)。
- 「説明可能性が差別化の核」— 核は 3 点 (対象が CC / action vocabulary の拡張 / 正しさゲートを毎反復) で書く。
- (本稿で追加) 「静的 backoff という機構が新しい」— backoff は既存の学習型 CC (Polyjuice) も学習の対象に含めていた (D2212 の理由欄)。
- (本稿で追加) 「関数単位の合成が既知最良を超えた」— 固定 16 点の偵察で 3 点が同 job の静的 10 µs を 6〜7% 上回ったのは探索的な 1 回の観測
  (再測なし・多重選択の補正なし) で、論文で既知最良超えと書く前に再測すると裁定されている (D2243 項 1)。LLM が方策を生成した結果は無い。
- (本稿で追加) 「LLM の必要性を測った」「B-5 の結果が出た」— 生成器対照の本走は投入後に中断し、現行 cohort の 6 比較すべてが判定不能
  (欠測) で、続行形は裁定待ち。判定不能は性能の結果ではない。
- (本稿で追加) 「TPC-C で CC を評価した」「TPC-C で certified」— TPC-C で得たのは段 1 の silo の trace 1 本を判定器が直列化可能と判定したことまでで、
  本稿の certified の定義 (YCSB point read / write) の外にある。合成候補を TPC-C で評価・認定した記録と性能測定は無い。
- (本稿で追加) 「K2 で改善した」「正しさシグナルの還流が効いた」— 同 job の候補と stock の比は配線 1 点の記述値で、改善・優劣・診断の効果ではない。
- (本稿で追加) 「判定器の検出力を網羅的に確かめた」— 検出期待表の実走には、変異が挙動を変えて commit した履歴が certified になった行 (盲点) も含まれる。
- (本稿で追加) 「ADRS が最も近い先行研究」— 近傍の判定は非該当の断定でも順位でもない (F1047)。
