## 総括

現状の草稿は、そのまま凍結すべきではない。主要な問題は次の 4 点である。

- patch 上、policy 2 の LCG は各更新で確実に 1 回進む。ここに `#if` による抜け道は見つからなかった。ただし、固定された決定的 LCG 列であることから「物理過程と厳密に独立」は導けず、主推定量を厳密な無作為化 ITT と呼ぶには追加仮定が要る。
- `Z_i` と `Y_i = ln(T_{i+1}/T_i)` の添字対応は正しい。反面、最後の更新の除外と `T_{i+1}=0` の除外は現在の割当に影響されうるため、割当独立という草稿の主張は誤りである。
- n=12 は cluster SD=0.032、真値 0、正規性、90% CI TOST という計画仮定の下でだけ約 80% の検出力を持つ。既存 1 run の naive SE は cluster SD の推定ではない。
- prereg 草稿と s2-plan で、効果の符号、seed、等価域、CI、欠測規則が異なる。結果を見た後に規則を選べる状態なので、単一 protocol に統合するまで事前登録として発効できない。

厳密な「何が起きても同じ結論になる」判定式は見つからなかった。ただし、局所 ITT の等価を機構全体や長期性能の等価へ読み替えると、過渡応答が小さい限り等価になりやすい、実質的に恒真へ近い解釈経路がある。

## 所見 1 — LCG の毎更新発火は確認できたが、厳密な独立性は確認できない

**主張**

policy 2 の記録対象更新について、LCG が進まない `#if` 経路は見つからなかった。勾配 0、推奨差分 0、clamp のいずれでも割当 bit は生成される。

一方、「毎更新で進む」ことは、「割当が物理過程と確率的に独立」の十分条件ではない。各列は seed と更新 index だけで完全に決まり、すべて同じ full-period LCG 周期上の異なる開始点である。先行割当が pre-state を作り、LCG の現在 bit が先行 bit と厳密に独立とは限らないため、carryover と系列依存がある場合は現在の Z と pre-state の関係を数学的にゼロとはできない。

**根拠 (file:line)**

- LCG state は policy 2 でだけ生成される: `patches/cicada-adaptive-counterfactual.patch:265-282`
- step-adapt の両枝が合流した後に割当があり、LCG 更新から clamp まで早期分岐はない: `patches/cicada-adaptive-counterfactual.patch:478-486`, `:498-514`, `:548-573`
- 草稿の独立性主張: `output/insights/2026-09-07_t2265-backoff-itt/verbatim/prereg-draft.md:59-63`
- 草稿自身も列が seed と index の決定関数だと認める: 同 `:171-176`
- s2-plan は形式的に独立な stream とは主張しない: `output/insights/2026-09-07_t2265-backoff-itt/verbatim/s2-plan.md:121`, `:169`

列挙された草稿 seed を主層の実測長 583 更新まで式どおり再計算すると、Z=1 比率は約 0.461〜0.569 である。先頭 1000 更新だけの 0.474〜0.534 より広い。入力となる式、seed、583 件という長さは `prereg-draft.md:139-166` と `stage1-liveness.md:42` にある。

**正しさ境界か整合か**

正しさ境界。実装上の割当欠落は否定できたが、「厳密な因果対比」という識別主張は未証明である。

**提案**

次のどちらかを凍結前に裁定する。

1. 現機構を維持し、「事前固定された疑似無作為列について、物理過程との同期がないという as-if randomization 仮定下の近接対比」と書く。「厳密に独立」「独立 seed」は使わない。
2. 厳密な無作為化主張が必要なら、seed の外生的な無作為抽出と job 順の無作為化を事前登録し、その割当設計に対応した推定を使う。

**反証されたら何が変わるか**

現在 bit が過去の割当履歴および潜在次窓 outcome と独立になる正式な無作為化設計が提示されれば、主推定量を逐次無作為化 ITT と呼べる。LCG の発火位置に関する結論は変わらない。

## 所見 2 — outcome の 1 窓対応は正しいが、最後の更新の除外は処置依存になりうる

**主張**

trace event i に載る `window_commits/window_us` は割当 Z_i より前に終了した窓の統計であり、Z_i が変更した `new_backoff` はその後に store される。したがって event i+1 の窓を使う `Y_i` は 1 個ずれておらず、添字対応は正しい。

ただし、event i が「最後」になるかは Z_i に影響されうる。Z_i が throughput を変えれば、count 条件に達する時刻と次の更新が 3 秒の終了前に発生するかが変わる。最後の event を除外することは常に必要だが、「割当と独立」は成立しない。

**根拠 (file:line)**

- 現在窓の commit/time を計算してから状態を更新する: `patches/cicada-adaptive-counterfactual.patch:407-417`
- trace の現在窓統計を割当前に保存する: 同 `:435-448`
- 割当、clamp、store の順: 同 `:548-586`
- event に現在窓と現在割当を一緒に記録する: 同 `:612-623`
- parser は stdout 順を維持し、seq 連続性を要求する: `tools/pegasus/probes/t2187_adaptive_const_probe.py:993-1018`, `:1071-1088`
- driver の既存一段先計算も current と following を組にする: 同 `:948-961`
- 草稿の最後の更新に関する割当独立主張: `prereg-draft.md:131-132`

**正しさ境界か整合か**

outcome alignment は正しい。終端 censoring は正しさ境界である。影響は通常 1 event/run だが、厳密な ITT という表現には触る。

**提案**

裁定パッケージ候補は二つある。

- 現実装を維持するなら、estimand を「後続 event が観測された complete pair 上の近接対比」と書き、厳密な ITT とは呼ばない。
- 厳密な ITT を保つなら、事前に決めた解析 cutoff より前の割当だけを対象にし、cutoff 後も最大窓長以上 trace を続けて、対象となる全割当に次窓を確保する。これは実行体変更を伴いうるため scope 拡張の裁定候補である。

**反証されたら何が変わるか**

次 event の有無が Z_i の全潜在値で同一になることが示されれば、最後の更新は純粋な行政 censoring と扱える。ただし現在の count 発火契約からは示されていない。

## 所見 3 — `T_{i+1}=0` と complete-job 選択は割当独立ではない

**主張**

`T_i=0` は現在の Z_i より前の状態だが、`T_{i+1}=0` はまさに Z_i が影響しうる outcome である。両者を一括して「割当と独立」とし、該当 event を落とす規則は誤りである。また「完走した job だけを使う」としつつ、全滅時以外の最小 cluster 数を定めていない。1 run しか残らなければ t 分散は定義できない。

**根拠 (file:line)**

- 草稿は zero throughput event を落とす: `prereg-draft.md:80-84`, `:129-135`
- 同時に outcome 値による除外を禁止しており、内部矛盾する: 同 `:133-134`
- driver は `window_us>0` だけを要求し、`window_commits=0` を拒否しない: `tools/pegasus/probes/t2187_adaptive_const_probe.py:1058-1060`
- 完走 job のみ使用し、12 本すべて失敗した場合だけ判定なしとする: `prereg-draft.md:142-144`
- s2-plan は zero が 1 件でもあれば主判定全体を inconclusive、12 run 不足なら確認的判定なしとしている: `s2-plan.md:123-137`

**正しさ境界か整合か**

正しさ境界。処置後 outcome による event 選択と、未定義の小標本判定経路である。

**提案**

s2-plan の規則を採用する。

- `window_commits=0` を個別除外せず、主判定全体を inconclusive。
- 主判定には 12 cluster 完備を要求する。
- `recommended_delta_sign=0`、`both_actions_feasible=0`、trigger、gradient、step、ceiling、時間 block による主解析除外も明示的に禁止する。
- retry は outcome を開く前に確認できる infra-only 理由に限定する。

**反証されたら何が変わるか**

実行契約が全 trace event の `window_commits>0` を保証し、job 完走が全割当列の潜在 outcome と独立だと証明されれば、この選択バイアスは消える。現 parser と事前登録にはその保証がない。

## 所見 4 — ±3% の表現が数理的に不一致で、静的曲線は過渡効果の根拠にならない

**主張**

throughput 比 `[0.97, 1.03]` の log 域は `[-0.03046, +0.02956]` であり、`±0.02956` ではない。腕の向きを入れ替えても同じ実用域にしたいなら、s2-plan の `[1/1.03, 1.03]`、すなわち `±ln(1.03)` が整合する。

また固定 backoff の定常曲線から、約 2.5 ms の直後 1 窓に数%の効果が現れるとは導けない。次窓には更新前に開始した transaction、制御状態の carryover、窓長の変化が混在しうる。過渡応答が薄まれば、長期的に重要な機構でも局所 ITT は ±3% 内に入る。

**根拠 (file:line)**

- 草稿の不一致な比率域と log 域: `prereg-draft.md:95-101`
- 静的曲線と内挿による約10%予測: `stage1-measurements.md:42-62`
- 親実測自身が定常応答と過渡応答の違いを認める: 同 `:63-64`
- brief は 1 更新 ITT と常時反転 run 効果の近似を置く: `brief.md:37-38`
- s2-plan はこの近似を棄却し、対称 log 域を採る: `s2-plan.md:7-8`, `:62-80`, `:164-166`

**正しさ境界か整合か**

等価域の数値不一致は整合問題。等価結果を機構全体または長期性能へ一般化する経路は正しさ境界。

**提案**

- 等価域は `[-ln(1.03), +ln(1.03)]` と一意に記す。
- 等価判定は標準 TOST の 90% CI、推定には95% CIを別掲する。
- ±3% は「局所一窓効果についての実用上の許容幅」として外生的に定義する。
- 「機構が効いているなら外に出る」「静的曲線から検出可能」とは書かない。
- 長期 policy 0/1 性能との対応は別 estimand とする。

**反証されたら何が変わるか**

1 回の backoff 変更に対するインパルス応答が 1 窓内で完結し、静的曲線と同じ応答量になる直接測定があれば、静的曲線を効果量予測へ使える。それでも比率域と log 域の算術不一致は残る。

## 所見 5 — n=12 の検出力は未観測の cluster SD 仮定に全面依存する

**主張**

既存の `SE(差)` は単一 legacy run の `sd(Y)*sqrt(4/n)` であり、自己相関を無視した計算値である。これは 12 個の `d_j` の run 間 SD ではない。

観測された負の lag-1 は、隣接する `Y_i` が `log T_{i+1}` を逆符号で共有することから構造的にも生じる。通常の平均なら負の自己相関は SE を小さくするが、Z で符号付けした差では、割当列の隣接積との組合せにより共分散項の向きが変わる。したがって naive SE が保守的か反保守的かは、この表だけでは決まらない。

**根拠 (file:line)**

- 親実測は自己相関を無視した式だと明記する: `stage1-measurements.md:35-36`
- 主層候補の値は sd=0.1197、naive SE=0.0082、lag1=-0.451: 同 `:21`
- 他層には lag1=-0.650 もある: 同 `:26`
- 草稿は 0.0282 を run 間 SD の代理にする: `prereg-draft.md:102-108`
- s2-plan も cluster SD=0.032 を計画仮定と認め、実測推定ではないとする: `s2-plan.md:94-99`

**正しさ境界か整合か**

検出力の説明は整合・実効性問題。ただし、低検出力の試験から「等価」を主張すれば正しさ境界に入る。

**提案**

n=12 は「十分」と断定せず、cluster SD に対する感度表を事前登録する。標準的な 90% CI TOST、真値 0、正規 cluster という同じ計画モデルでは、おおよその80%到達本数は次の通りである。

| 仮定 cluster SD | 必要 run 数の目安 |
| ---: | ---: |
| 0.032 | 12 |
| 0.040 | 18 |
| 0.050 | 27 |
| 0.064 | 44 |

したがって、12 本を維持するなら「SD≤0.032 の条件付き計画」と明記する。より広い SD まで80%を要求するなら、結果を見る前に本数を固定して増やす。

**反証されたら何が変わるか**

独立した policy 2 pilot から cluster SD≤0.032 が outcome 非盲検による選択なしで確立されれば、n=12 の約80%という主張は支持される。現在の stage 1 はその pilot ではない。

## 所見 6 — write-heavy 48 を選ぶ説明が表の実測を過度に一般化している

**主張**

「他 regime は gradient 0 が39〜51%」は実測表と一致しない。balanced 48 は 2.1%、7.4%、8.1%であり、backoff 中央値も 2 µs、最大10 µsに達する。write-heavy 48 が最も強く床を離れることは支持されるが、「唯一腕が届く層」は支持されない。

さらに、実際の policy 2 生死確認では全6 regime の `both_actions_feasible` が 0.967〜0.982、反転実現も割当のほぼ全量である。policy 2 では他 regime にも腕が届いている。

**根拠 (file:line)**

- brief の「他 regime は39〜51%」: `brief.md:34-36`
- prereg 草稿にも同じ一般化がある: `prereg-draft.md:91-93`

## 所見 7 — これは純粋な未観測事前登録ではなく、protocol 自体も二重化している

**主張**

草稿は「反実仮想の腕の出力を観測していない」と書く一方、同じ腕の event 数、割当、反転実現、両方向可否を見て主層と検出力を更新している。これらは指定 Y ではないが、policy の処置後帰結であり、event 数は throughput の代理にもなる。したがって「指定 outcome は未閲覧」は言えるが、「腕の出力を未観測」は言えない。

加えて、s2-plan と草稿は単一 protocol になっていない。

- 効果の符号: s2 は forward−invert、草稿は invert−forward。
- 等価判定: s2 は90% CI TOST、草稿は95% CI。
- seed: s2 は SHA-256 由来、草稿は既定 seed と splitmix64。
- zero/missing: s2 は主判定全体を inconclusive、草稿は event を落とし、欠けた run 数でも判定可能な記述。

**根拠 (file:line)**

- 草稿が観測済み構造データを列挙する: `prereg-draft.md:22-32`
- liveness の観測内容と、それを主層・検出力へ使用した記録: `stage1-liveness.md:33-79`
- 符号差: `prereg-draft.md:84-86` 対 `s2-plan.md:35-44`
- CI 差: `prereg-draft.md:110-114` 対 `s2-plan.md:73-80`
- seed 差: `prereg-draft.md:139-166` 対 `s2-plan.md:101-121`
- 欠測差: `prereg-draft.md:129-144` 対 `s2-plan.md:123-139`
- 現 driver はまだ `"pending"` を生成する: `tools/pegasus/probes/t2187_adaptive_const_probe.py:2727-2737`, `:3387-3388`

**正しさ境界か整合か**

protocol 二重化は正しさ境界。結果後に都合のよい符号、CI、seed 集合、欠測規則を選べるためである。事前観測の表現は透明性・整合問題だが、未観測性を過大に主張すれば事前登録の意味に触る。

**提案**

凍結前に単一文書へ次を統合する。

- forward−invert の符号。
- `±ln(1.03)` と90% CI TOST、95%推定 CIの併記。
- seed 一覧を一つだけ採用する。s2 の新 seed 集合なら liveness で使った既定 seed とも分離できる。
- zero、欠測、retry、必要 cluster 数を s2 規則へ統一する。
- 発効節は「指定 outcome Y と median_tps は未閲覧だが、policy 2 の処置後構造指標を用いて設計を更新した、data-informed prospective protocol」と書く。

**反証されたら何が変わるか**

s2-plan が明示的に廃案であり、草稿だけが唯一の凍結対象だと結果閲覧前の記録で確定しているなら、二重 protocol の問題は解消する。符号、zero、独立性、検出力の個別問題は残る。

## 親 brief と親の実測への異議

- P1-1 は半分だけ支持される。LCG の毎更新発火は確認できたが、「先行状態と厳密に独立」は固定決定列からは導けない。
- P1-2 は「最も強く床を離れた data-informed 主層」なら支持できる。「他 regime は39〜51% gradient zero」「腕が届かない」は balanced 48 と policy 2 生死確認に反する。
- P1-3 の「1更新 ITT ≈ 常時反転 run 効果」は棄却すべきであり、s2-plan の修正が正しい。
- P1-4 の n=12 は cluster SD=0.032 という未検証仮定に条件付けられる。既存 run 内 SE は根拠にならない。
- P1-5 の pre-state 層別を記述的二次に留める判断は妥当。ただし相対時間 block は最終 event 数に依存するため、やはり記述専用である。
- P1-6 はこの統計レンズの範囲では評価対象外。
- 「outcome を見ていない」は指定 Y の未閲覧としては受け入れられるが、event 数、可否、反転実現率は処置後の構造的 surrogate である。「反実仮想腕の出力を一切見ていない」は不正確である。
- stage1 の `SE(差)` は文書自身が自己相関無視と明記しており、cluster SD や独立 run の分散として一般化できない。

## 見つからなかったもの (探したが無かった)

- policy 2 の記録対象更新で LCG が進まない `#if` 経路は見つからなかった。
- `Z_i` と次窓 `T_{i+1}` の 1 event ずれは見つからなかった。patch と parser の添字対応は正しい。
