## R-A. 待ち札の先着順位が、赤・argv エラーのたびに失われる

### 事実

- 待ち札の到着順は payload の `queued_at_ns`、生存は file mtime の heartbeat
  (D253 が意図的に分離)。heartbeat を出すのは待ち手 process の `claim` 呼び出しだけ。
- `_WAITER_TTL_SECONDS = 300` (`tools/wave_land_window.py:28`) を超えて heartbeat が途切れた札は
  stale として unlink され、次の `claim` で**新しい到着時刻**の札になる。
- 受入が赤・argv エラーで終わると、親は解析・修正・新しい `--receipt-file` / `--log-file` の用意を
  経て再投入する。**300 秒を超えるのが普通**。
- **実測 (2026-08-16)**: t1180-pilot-approval は 20:20 の赤 → 記録 commit → 20:50 再投入で
  順位を失い (`queued_at_ns` 20:50:17 → 21:42:28)、後着 3 本に追い越されて通算 79 分待ち。

### 効き

行列長 4〜6 本のとき、**フレーク 1 件の実コストが「受入 1 走 2.5 分の再走」から
「40〜70 分の待ち直し」へ 1 桁以上増幅される**。F57 フレークの実害の大半はここに乗っている。

### 択一

- **(a) 同一 process 内で再試行させる** — 待ち手を切らさず、attempt の切り替えを process 内で行う。
  `--receipt-file` / `--log-file` の attempt ごと別 path 必須と噛み合わせる設計が要る。
  [T-694] の裁定済み方針「`tools/` に正本 wrapper (`acquired` 検査・`trap` による確実な release・
  周期固定) を置く」(2026-08-12 /rulings) と同じ的。**親推奨**。
- **(b) 札の heartbeat を `claim` 以外の経路でも出す** — 順序キー (payload) と生存 (mtime) の
  分離を維持したまま、生存だけ別 process が延ばす。**親は非推奨** — D253 が
  「到着順と生存を同じ mtime に持たせられない」として作った分離に、別の書き手を足すことになる。
  書き手が増えるほど「よく呼ぶ側が新しく見える」型の退行が入りやすい。
- **(c) 待ち札 TTL 300 秒を延ばす** — 最も簡単だが、D253 が
  「最も重い失敗様式は不公平ではなく停止である」として選んだ値である。延ばすと
  放棄された札が行列の先頭を塞ぐ時間がそのまま延びる。**親は非推奨**。
- **(d) 何もしない** — 現状維持。フレークが出るたびに 40〜70 分を失い続ける。

### 親の推奨

**(a)**。理由は 3 つ。(i) [T-694] で既に「正本 wrapper を置く」方針が裁定済みで、新しい設計判断を
足さずに済む。(ii) D253 の待ち札意味論に一切触れないので、受理集合も停止性も変わらない。
(iii) 根 3 (lease 取得後に落ちる) の対策と同じ場所 (`tools/dev_wave_wait.py` 周辺) に入るので、
t1142 が今やっている preflight と 1 つの wave にまとめられる。

## R-C. ff-only land の連鎖やり直し (構造)

### 事実

`tools/dev_wave_land.py:1559` `_main_is_allowed` は `locked_main == tested_main`、
または自分の監査済み閉包内の commit であることを要求する。他 wave が land すると
自分の受入結果は構造的に無効になり、main 再取り込み → 受入再走が要る。

### 判断

**これは ff-only land の当然の帰結であり、緩めるとゲートを弱める。** 「main が動いても
受入結果を有効とみなす」方向の変更は、テストしていない木を main にする経路を作るので、
規律 2 とユーザーの「リワードハック禁止」に真正面から抵触する。**本 wave では触らない。**

健全な軽減は **merge train / batch land** (複数 wave の tip をまとめて 1 回の受入で certify し、
まとめて land する) だが、これは新しい直列化機構であり規模が別。
現状の直列度 (受入 lease で 1 本ずつ) では、そもそも他 wave が land できる窓が
lease 保持中には無いので、根 1・2・3・4 を閉じた後に**実測してから**必要性を判断すべき。

### 親の推奨

**根 1〜4 を閉じてから再測定する。今は起票のみ。**
