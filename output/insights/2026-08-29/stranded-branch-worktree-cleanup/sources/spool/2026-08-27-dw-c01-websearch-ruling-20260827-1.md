## 本文

ユーザーの問い「子の Web 検索禁止をどう思うか、外部知識に届かないのは痛いのではないか」に対し、
クラス 1 で台帳を突き合わせた。実装・機構の変更はしていない。

- `DW-C01` の「子はWeb検索禁止。成果物が全損する。」の因果は F259 に実測済みで、Codex CLI の
  `web_search` event が同一 object 内に `id` を 2 個持ち、`orchestrator/codex_roles/events.py` の
  重複 key 拒否が `evidence_status=invalid` を立てるため成果物が捨てられる。**知識の否定ではなく
  道具側の制約**である。全損の実費は 848 秒/43 call、1242 秒/38 call、2668 秒/入力 920 万 token 相当。
- 既裁定 [T-981] (2026-08-17 /rulings 全件 第 5 回) は「記録する + Web 検索は既定 off」であり、
  **必要な段だけ明示的に有効化する**と定める。`DW-C01` の無条件禁止はこれより広い。
- 実測 (本セッション): codex-cli は 0.147.0 から 0.149.1 へ更新済み。`codex exec --help` に
  検索の on/off flag は依然として無い。一方 `.codex/hooks.json` は PreToolUse matcher で
  `apply_patch` と `Bash` を既に機械拒否している。
- 外部知識への懸念の現況: 制約は codex 子だけで、親は Web 検索を持ち証拠鎖の脆さも無い。
  外部知識は親が出典付きの**データ**として brief へ渡せる (規律 6 と整合)。この経路は
  既定の作法として docs に書かれていない。
