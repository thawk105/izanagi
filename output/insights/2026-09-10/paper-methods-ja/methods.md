# Izanagi 本体論文：方法節草稿

本稿は、2026-09-10 の新規執筆依頼に基づく日本語草稿である。既存の論文スナップショットを
置き換えず、現行コードで記述できる方法と、未完の評価契約を区別する。
主要記述の根拠と適用限界は [実装対応メモ](implementation.md) に示す。

## 1. 対象と方法の構成

Izanagi は、ワークロードに応じたトランザクションの並行性制御（CC）の実装変異を生成し、
正しさを検査したうえで性能を評価するシステムである。CCBench の既存実装を素材とし、
既存フラグの組合せを探索する操作と、指定されたソース領域へコードを挿入して実装の振る舞いを
変える操作を組み合わせる。列挙できる軸内の探索は機械探索へ渡し、LLM は変更の方向やコード片を
提案する。対象実装が選べる操作の集合（action vocabulary）を拡張し、各反復に正しさの検査を
組み込む点を方法の中心とする。

合成範囲は、導入済みの編集領域とその軸に認められた文法に限る。たとえば段4の backoff 軸では、
abort 後の待機量を定める一つの文を生成する。コードを出力する形式であっても、この軸で探索する
自由度は数値一つである。sort や trigger-gating は別の軸として、それぞれの制約下で扱う。
これらの実装から、任意の CC アルゴリズムを自動合成できるとは結論しない。

基本の評価順序は、提案、差分検疫、検証用・性能用の二つのビルド、実行トレースによる検証、
独立した性能測定、記録と次の提案へのフィードバックである。以下の certified は、指定された
検証構成と判定器の意味論に照らした受理を指す。プログラムの全入力・全実行順序に対する形式証明や、
論文での性能優越の成立を意味しない。

## 2. 変異の生成と編集範囲の限定

提案生成は planner と coder に分ける。planner は現在の性能指標と反復履歴から変更方向を提案し、
coder はその方向と与えられた基準情報から具体値とコード片を返す。critic は評価後の指標や拒否理由を
読み、次の方向を提案する。段4ドライバ自身は LLM を呼び出さず、これらの構造化出力を引数として
受け取る。したがって、この経路の反復運営はメインセッションが受け渡す人間監督のループである。

編集領域は `EVOLVE-BLOCK` の開始・終了マーカーで指定する。テンプレートは合成側の分岐と
既存実装を保持する分岐を用意し、coder の変更対象は合成側の内部だけに限る。検疫はテンプレートを
適用した後のソースを基準に、マーカー、分岐骨格、既存実装側の保存と編集範囲を確認する。
続いてホストへの作用を検査する有限の字句規則と軸固有の文法を適用する。backoff 軸では、
提案した値とコード中の数値リテラルが一致することも確認し、記録する候補と実際にビルドする
実装の対応を保つ。字句検査だけで任意コードの意味的安全性が証明されるとは扱わない。

検疫に通らない提案はビルドへ進めず、拒否の種類、理由、対象領域を記録する。通過した提案は、
固定した CCBench の版に対して隔離・排他された適用区間で評価し、終了時に変更を戻す。
ビルドの識別にはフラグを表す genome に加え、実際のソースに由来する識別情報を用いる。
同じ genome を持つ既評価候補の重複提案では、保存済み証拠を確認して評価を再利用する場合がある。
検疫通過だけの試行やビルドを省いた配線確認を、検証済み候補へ昇格させない。

## 3. 正しさ検証と反例のフィードバック

正しさはトレースを有効にしたビルドを別に実行して検査する。各検証構成について、正常終了、
空でないコミット履歴、実行体が報告するコミット数等の証拠を確認し、トレースを判定器へ渡す。
判定器は履歴の整合性を確認し、トランザクション間の読み書きに基づく直列化グラフを構築する。
書込み間・書込みから読込み・読込みから後続書込みへの依存を扱い、反依存を含む循環（G2）まで
検出する。診断には循環を構成するトランザクション、依存辺とその理由を含める。anomaly が検出された候補は
その時点で失格とし、性能が高くても採用しない。空トレース、解析不能、実行失敗等も、
正しさを確かめられた成功例には数えない。

既定の検証構成に追加構成を指定した場合は、その全構成・全反復を通過させる。小規模検証と
性能動作点の検証は同義ではない。実装には legacy に S2 を追加する経路と、性能設定から
検証構成を作る経路があり、どれが実際に使われたかは試行記録の構成タグで区別する。
ある設定での検証成功を、まだ試していない負荷や別プロトコルの正しさへ一般化しない。

拒否は単なる二値の失敗にせず、判定器が返した構造化診断を試行記録へ残す。依存関係上の
反例を含む検証失敗、コミットが得られない等の生存性の失敗、差分検疫の拒否を区別し、
どの構成で失敗したかを次の提案へ渡せる形にする。通常の還流では、critic に成功候補の
性能指標と失敗候補の診断を併せて提示し、その判断を次の方向提案へつなぐ。
反復状態はチェックポイントに保存し、提案履歴と停止条件の判定をプロセス間で継続する。

還流の効果を調べるため、critic 用の要約へ拒否診断を含めるかどうかを切り替える実装を持つ。
この切替は診断の提示に作用し、実際の正しさ検証を省くものではない。反例を次の生成に利用できる
配線の存在と、反例還流が性能や探索効率を改善したという因果的結論は分ける。

## 4. 正しさ検証から独立した性能測定

性能はトレースを無効にした別ビルド・別実行から取得する。トレース処理と検証専用メタデータは
コンパイル時に除去し、実行時フラグで処理を飛ばすだけの構成にはしない。候補と比較対象は
ともにトレース無効でそろえる。この分離により、検証のための観測処理を測定対象の CC に
混ぜない。「独立」はビルドと実行の分離を指し、探索中の逐次試行が統計的に独立だという意味ではない。

測定条件は、レコード数、スレッド数、ワークロード、実行時間、反復数、環境契約で指定する。
探索規模には、較正によって必要な競合やキャッシュ挙動を再現する最小規模を用いる。
測定層は実行の競合を確認し、スループットの反復標本、中央値、変動係数、abort 率等を記録する。
規定範囲の再測定でも安定しない場合は `unstable` として残す。測定が完了したこと、
正しさを通過したこと、安定した比較材料になったことを別々に判定する。

一回の測定内のばらつきと、別 run 間の比較に使う noise floor は区別する。性能差の解釈には、
比較対象と競合条件に対応する between-run floor を用い、別の対象で得た定数を無条件に流用しない。
試行数や検証相を満たさない中間走行は記述的に報告し、有意差や LLM 固有の優越を主張しない。

## 5. raw screening と certified 経路

本稿では、未検証の性能観測を使う候補の絞込みを raw screening と呼ぶ。性能値が存在しても、
それだけでは certified な fitness にならない。性能だけの探索・診断成果物と、評価 pipeline の
明示的な bench-first screening は区別する。後者は検証の前に性能を測って明白に遅い候補を
落とす最適化であり、すべての合成反復で使う既定経路ではない。

bench-first screening では、基準値と floor から定めた保守的閾値を下回り、かつ測定が安定し
abort 率による曖昧さがない候補を、未認証のまま棄却する。基準点が古ければ通常の検証先行へ戻す。
スクリーニングに残った候補も、指定された全検証を通過して初めて COMMIT に進める。
したがって、検証前の `BENCH_DONE` は測定記録であり、正しさの合格証ではない。
棄却候補には採用用の fitness を付けない。

certified 経路でも、生成直後の評価結果だけを信じて後段へ転記しない。保存済み記録の対応関係と
受領証を読み手が検査し、用途に応じて受理した証拠を消費する。探索用の名前空間にある段4の
成功記録を、正式な比較や選択の証拠へそのまま流用することはできない。
履歴を読む用途と、現行の certified な判定に使う用途も区別する。

## 6. 選択と評価の射程

最終的な選択契約は、証拠が支持する新しい候補、既存実装（stock）、差を支持できない場合の
同率（tie）を区別して返すことである。stock や tie は有効な「改善を示さなかった」結果であり、
新しい CC の実証達成には数えない。候補に性能値がない場合や比較の前提が成立しない場合を、
有効な tie と取り違えない。段4ドライバは反復と停止を実行する部品であり、一般的な
統計比較による最終勝者を自動決定する実装とは位置づけない。

ワークロード記述に基づく段8bの選択部品は、検証した descriptor と固定候補一覧を入力にし、
一覧内の候補一つと理由を出力させる。不正な出力は既定候補に置き換えず拒否する。
ここでの候補の指名は予測であり、性能測定・正しさ検証に基づく最終評価とは別である。
正式評価では、事前登録で定めた比較対象、検証構成、floor、標本設計、報告規則を満たす必要がある。

評価設計は、同一編集面・同一予算の非 LLM 対照、軸内機械探索、還流の有無などを分けて比較する。
逐次探索の個々の試行を独立標本とせず、採用した登録に従って系列を検定単位とする。
多重比較、有意性を主張しない場合、全ワークロードの退行を含む報告を結果を見る前に定める。
旧主実験の登録・改訂履歴を、新しい全比較が実走済みである証拠としては使わない。
特に B-4 は記述統計に限定する裁定が採用されており、その採用だけで既存 consumer の変更や
正式選択への接続まで完了したとは扱わない。

試行記録と材料レポートは、提案、拒否、検証、測定の出所を追うための補助成果物とする。
LLM が述べた機序は仮説であり、説明の生成や記録の整合性から説明の忠実性・因果機序の同定を
推論しない。本草稿は未完の性能結果を補わず、研究全体の無人化や任意 CC 合成の達成も主張しない。
