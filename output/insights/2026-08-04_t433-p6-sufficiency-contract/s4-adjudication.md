## 3. 実装しない裁定 (`DW-S04`)

**本 wave は実装しない。** 根拠は 3 つあり、いずれも独立している。

1. **ユーザー裁定。** (175) の裁定文言が「設計 wave が案を起草して裁定パッケージで返す」である。
2. **`DW-G04` (条件付き機能の発火 gate)。** 認定手続の発火条件を満たす既存 artifact
   (P6 実装・calibration fixture・認定 request) は 1 件も存在しない — P6 実装要素は
   識別子 4 種の grep で 0 件 (R8 の限定付き)、D150 決定 (4-b) も `NOT_IMPLEMENTED` を記録済み。
3. **裁定の既成事実化の回避。** 契約の採否・V1 は裁定パッケージの事項であり、実装すれば
   未裁定設計を既成事実にする (D138 決定 (7)(c) と同型)。

したがって段 5・6 を飛ばして `4→7→8→9` とする。

- **変異事前登録 (`DW-M01`) は対象外。** 実装差分が無いため変異させる位置が存在しない。
- **変異 matrix と受入全走も対象外** (`DW-S04` の明文どおり)。docs 検査 (`tools/check_docs.py`) と
  docs 変更が影響しうるテストは走らせる。
- `MAX_APPROVED_GENERATIONS = 1` (D114) は変えない。cap-lift の結線もしない。
  凍結ファイルには触れない。

## 5. 本 wave が主張しないこと

- 契約が**採用された**とは主張しない。採否・V1 とも裁定パッケージの事項である。
- P6 の実装状態を変えたとは主張しない。現在も `NOT_IMPLEMENTED` である。
- 認定手続が発火可能だとは主張しない。発火に要る artifact (実装・fixture・認定 request) は
  すべて将来所有である (R9)。
- 成果物 (certified 選択、材料レポート、proof chain、試行台帳) の値・機械受理集合・参照は
  **不変**である。実装差分がゼロだからである。契約採用時に変わるのは cap-lift の**規範上の**
  受理集合だけである (R14)。
