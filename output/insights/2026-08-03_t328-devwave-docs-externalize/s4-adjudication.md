## ユーザーへ返す裁定パッケージ

`docs/dev-wave/**` の逼迫をどう解くか。**3 条件 (縮約しない / 上限を上げない / 候補を載せる) は
同時に成立しない**ので、どれを緩めるかを決める必要がある。

- **択 1 — 上限据え置き + 陳腐化節の削除で空ける。** D94 決定 2 の routing に従い、L2 のうち
  「発火実績なし × テスト/機械検査で義務代替済み」を満たす節を削除候補として提示し、
  ユーザーが削除を裁定する。総量は増えず D94 とも衝突しない。費用 = 削除候補の抽出と立証
- **択 2 — 上限引き上げを正面から裁定する。** 「+2,000 bytes の予算引き上げ」であることを明示し、
  新 D で D94 却下案 (a) を supersede したうえで外出しを実装する。
  A-3 / A-5 / A-6 / A-7 / B-4 の必須作業がすべて scope に入る
- **択 3 (親の推奨) — [T-313] を先に実装する。** [T-313]「byte 予算を常時読量 gate へ置換」は
  **(109) で既にユーザー裁定済み・実装待ち**である (F79 で一度失われ (114) で復元、再裁定不要)。
  これなら (i) 上限を上げず、(ii) ファイル分割をしないので D94 と衝突せず、(iii) レンズ A が
  指摘した「読量が増える」を正面から測る gate になる。[T-341] も「どちらも [T-313] の後なら入る」
  と記録し (a) を推奨している。[T-328] / [T-341] / [T-345] / [T-346] / [T-264] / [T-279] / [T-317] は
  すべてこの後に入る

**推奨は択 3。** 択 2 を採る場合でも、D94 の supersede と上記 5 件の必須作業を含めた別 wave が要る。
