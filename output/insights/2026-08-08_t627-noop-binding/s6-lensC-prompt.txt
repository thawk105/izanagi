## レンズ C — 実装の正しさ・fail-open・境界・契約

**実装を守る側に回ってはいけない。**次を疑え。

1. **fail-open 経路**: `_validate_activation_transition` の中で、拒否すべき入力が拒否されずに
   関数を抜ける経路が無いか。とくに `first_failure` の集約 (最初の失敗だけを記憶して
   残りを継続する構造) が、後続の失敗を握り潰して受理へ倒れる経路を作らないか。
   例外・非 bool・False が混在した場合の最終挙動を追え。
2. **評価順序と到達可能性**: `_validate_activation_transition` 内の env 集合一致検査は、
   呼出し前の catalog 照合で既に保証されており到達不能ではないか。到達不能なら
   「恒真な保証 (謳うだけで発火しない assert)」に該当しないかを判定せよ。
   同様に `callable(...)` 検査の位置が、serial 1 のみの chain でも発火するかを確認せよ。
3. **受理集合の未承認変更**: 段 4 裁定が禁止した 4 種以外に、拒否が増えていないか
   (過剰拒否)。逆に、裁定が拒否を求めるケースで受理へ倒れていないか。
   `predecessor.generation + 1` の算術、`generation` の型、negative index、
   `GENERATIONS[env][gen-1]` の境界を具体的に検査せよ。
4. **adapter の穴**: `_resolve_activation_entry` が `None` を返す条件は網羅的か。
   `GENERATIONS` が monkeypatch されている状況、`row.generation` が登録数を超える状況、
   `env_tag` 不一致の状況を追え。`_is_valid_activation_successor` が
   `is_valid_successor` の返り値を確実に返しているか。
5. **例外契約**: `ActivationRecordError` 以外の例外 (KeyError、TypeError、AttributeError) が
   loader から漏れる経路が無いか。漏れると issuer (`tools/issue_env_contract_activation.py`) の
   捕捉が外れる。`predecessor_by_env[successor.env_tag]` の KeyError 可能性を追え。
6. **不変条件**: 本番 record 1 件の load 結果、`_ACTIVATION_HEAD_*`、
   `env_contract_activations/00000001.json`、凍結成果物の bytes が変わっていないか。
   activation leaf の stdlib-only 性 (`campaign` / `orchestrator` / `calibrator` の import 禁止) と
   env 中立性 (env 固有 literal 禁止) が保たれているか。`TYPE_CHECKING` 下の import が
   実行時 import を持ち込んでいないか。
7. **既存テストの弱体化**: 差分の中に、期待値の緩和・反転・skip・削除・
   assert の削除が紛れていないか。既存 node が消えていないかを
   `git diff` で 1 件ずつ確認せよ。**とくに、変更前に存在した assert が
   変更後に消えている箇所**を列挙せよ。
8. **所有外への波及**: `orchestrator/tests/conftest.py`、`orchestrator/campaign/execution_guard.py`、
   `orchestrator/tests/test_campaign.py` (pytest 不在でも素の Python で走る二重 runner 契約を持つ)
   への波及が無いかを静的に確認せよ。
