## 実装する内容

model の権威を dispatcher (`.claude/commands/dev-wave.md`) の 1 行だけにした。
その単一権威が黙って壊れないよう、`tools/check_docs.py` に次の 3 つの pin を追加せよ。

### pin 1 — dispatcher の段別 model 行を exact literal で固定する

`.claude/commands/dev-wave.md` に次の文字列がそのまま存在することを要求する。
存在しなければ finding を 1 件出す。

```
codex の `-m` は段 3 が `gpt-5.6-sol` と `gpt-5.6-luna` を 1 本ずつ、他の全段が `gpt-5.6-sol`。
```

`CODEX_DEV_WAVE_STAGE9_LAND_LITERAL` と同じ「literal 定数 + `in text` 判定」方式でよい。

### pin 2 — `DW-S02` / `DW-S03` に model slug が現れないことを要求する

`docs/dev-wave/workers.md` の `DW-S02` と `DW-S03` の**可視本文**
(`_visible_markdown_text` を通したもの) に `gpt-5.6-` で始まる model slug が
**1 つも現れない**ことを要求する。現れたら節ごとに finding を 1 件出す。

**期待値との一致ではなく「不在」を要求する点が重要である。**
期待 slug との一致方式は、期待 slug を 1 つ残したまま別の slug を decoy として
足せば通ってしまう (段 3 レンズ A の BLOCKER)。不在方式ならその攻撃が成立しない。

検出する正規表現は、backtick の有無にかかわらず slug を拾うこと。
`` `gpt-5.6-sol` ``、`-m gpt-5.6-sol`、`--model=gpt-5.6-luna`、行頭の bare slug を
すべて拾わなければならない。

### pin 3 — `DW-O01` に model slug が現れないことを要求する

`docs/dev-wave/operations.md` の `DW-O01` の可視本文についても pin 2 と同じ不在検査を行う。
起動雛形は `-m <model>` という placeholder でなければならない。
