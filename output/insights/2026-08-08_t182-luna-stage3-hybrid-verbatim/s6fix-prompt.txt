## 直す欠陥 (段 6 レビューの real 所見)

### F1 — dispatcher literal pin が `in` 判定で、件数も可視性も見ていない (R1 BLOCKER, R2 BLOCKER)

現状は `CODEX_DEV_WAVE_STAGE_MODEL_LITERAL not in dev_wave_text` である。
これでは正規の契約行を消し、同じ literal を HTML comment / fenced code block /
「以下は廃止」の後ろへ置いても通る。さらに矛盾する第二の model 規則を足しても通る。

**直し方:** 既存の段 9 land literal と同じく、`_visible_markdown_text` を通した可視テキスト上で
**出現回数がちょうど 1 回**であることを要求せよ。0 回でも 2 回以上でも finding を出す。

pin する literal は、親が入れた次の行のものへ更新すること
(`.claude/commands/dev-wave.md` の「凍結境界」節を読んで正確に写せ)。
レンズ割当ての文も pin 対象に含めること。**2 つの literal 定数に分けてよい。**

### F2 — `DW-O01` に `-m <model>` が在ることを pin していない (R1 BLOCKER)

slug の不在しか見ていないため、`-m <model>` を丸ごと削除すると
codex の既定 model で起動できるのに全 pin が通る。

**直し方:** `DW-O01` の可視本文に literal `-m <model>` が**ちょうど 1 回**現れることを要求せよ。

### F3 — slug 不在検査が 3 節に閉じており、第二の権威を置ける (R1 BLOCKER)

現状は `DW-S02` / `DW-S03` / `DW-O01` の本文しか見ない。
`DW-S05-A` や `DW-S06-A` に model slug を書けば第二の権威になるが検査されない。
`_reference_id_sections` は heading を除いた body しか返さないため、
`## DW-S03 — gpt-5.6-sol で起動` のような見出しへの記載も通る。

**直し方:** 節単位をやめ、`docs/dev-wave/workers.md` と `docs/dev-wave/operations.md` の
**ファイル全体の可視テキスト**に `gpt-5.6-` 系 slug が 1 つも現れないことを要求せよ
(見出しも含まれる形にすること)。file ごとに finding を 1 件出す。
`.claude/commands/dev-wave.md` は model の権威なので、この不在検査の対象にしない。

### F4 — 節 cardinality と slug 混入が同じ finding に畳まれている (R1 SHOULD)

「節が一意でない」と「slug がある」が同じ文字列を出すため、修正理由を判別できない。

**直し方:** F3 でファイル全体検査に移すため、`DW-S02` / `DW-S03` の節 cardinality 判定は
この pin から外してよい (既存の H2 一意性検査が別に存在する)。
`DW-O01` については F2 のために節を取る必要があるので、
「節が一意でない」と「`-m <model>` が 1 回でない」を**別々の finding** にせよ。

### F5 — 別 model family が素通りする (R1, R2)

`gpt-5.4-mini` や `gpt-6-*` は現行 regex の対象外である。

**直し方:** 検出対象を `gpt-` で始まる model slug 一般へ広げよ
(`gpt-<digit>` で始まり、識別子文字が続く形)。
ただし `gpt-5.6-*` のような**説明のための表記**を巻き込みすぎないよう、
