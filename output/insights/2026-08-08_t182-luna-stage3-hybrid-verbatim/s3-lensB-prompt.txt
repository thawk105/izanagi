## 攻撃せよ

1. **規律 2 との関係。** 段 3 敵対相談は dev-wave における「正しさゲート」か、
   それとも単なる process か。親は後者寄りに扱っている。
   前者だとすると本変更は規律 2 違反になるか。両側の論証を書き、どちらが正しいか結論せよ。
   結論が「違反」なら、それは絶対規律なのでユーザー裁定でも緩められない — その帰結まで書け。
2. **D207 との関係。** D207 は reasoning effort を pin し、model は pin していない。
   親は「機械 pin には抵触しないが理由は同型」と判断した。
   D207 の理由が model にも及ぶなら、本変更は D207 を実質的に無効化する先例になるか。
   D207 を明示改訂せずに model を変えることの制度的帰結を述べよ。
   逆に、D207 が意図的に model を対象外にしていた読み筋があれば、それも書け。
3. **「91%」の読み方への攻撃。** 91% は 11 件中 1 件の見落としである。
   段 3 は並列レンズを複数本走らせる。全レンズを luna にする場合と、
   sol と luna を混成にする場合とで、見落とし確率はどう違うか。
   親の (P2) 「全部 luna」は、ユーザー裁定の文言から本当に導かれるか。
   混成のほうがユーザーの意図 (能力を保ちつつトークンを減らす) に適合する論証があれば書け。
4. **記録の正直さ。** 段 2 プラン §5 の記録方針 (根拠をユーザー裁定に限定、
   T-182 の数値を採用根拠に使わない) で十分か。
   後から読んだ人が「証拠に基づいて採用された」と誤読する経路が残っていないか。
   worklog / decisions に**書かねばならないのに段 2 が挙げていない**項目を名指しせよ。
   rollback 手順が実際に元へ戻せるかも検査せよ。
5. **F56 の未閉塞。** served model の identity は attest できず、receipt は要求 slug のままである。
   段 3 を luna に切り替えた後、「実際に luna で敵対相談した」ことを
   どうやって示すのか。示せないなら、worklog にその限界を書く義務があるか。
   `DW-S03` を変えることで F56 の危険度が上がるか下がるか。
6. **成果物影響 (DW-G05)。** 段 3 の model 変更が izanagi の成果物
   (certified な選択結果、proof chain 付き材料レポート、試行台帳) の
   どの値・受理集合・参照を変えうるか。「変えない」と主張するならその論証を検査し、
   反例を構成せよ。
7. **未裁定の論点。** 本 wave が親の一存で決めてしまっているが、
   本来ユーザー裁定へ返すべき論点があれば名指しせよ (`DW-S04`)。
