## plan の変異候補への判定

[変異候補表](/work/1/SFC/tanab/dev-wave-jobs/dev-wave-t2867-silo-contrast-impl/codex/s2-plan/out.md:149) のうち、**U1 の auditor 拒否復活、U2 の mode/argv 変更、U4 の attempt 据置き、U5 の coder 入力への key 追加、U6 の固定12系列・初期点混入・Holm 族結合**は、対応する単一境界を直接検査すれば帰属できる。

**mask に注意が必要**なのは、U1 の fixed10 define（先に build 自体が失敗しうる）、U3 の `c += 1`（固定乱数で最初の木が有効なら到達しない）、U4 の B 計上（job 不成立が先行しうる）、U5 の 429 判定（出力 JSON の parse 失敗が先行しうる）である。各試験はそれぞれの変異行まで到達する固定入力を使い、期待する拒否・event・判定理由を一つに絞る。特に U1 には **LLM×IR を機械 proposal に偽装した入力**と、**登録 seed と違う IR を seed slot に置く入力**を加えるべきである。
