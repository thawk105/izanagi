## 等価性の論証

- [s8b_holdout_freeze.py:417](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t2273-issue-subprocess/orchestrator/campaign/s8b_holdout_freeze.py:417) の helper が非 `None` を返す式では、各 alternative の key は literal、値側で許される regex メタ文字は `.` だけである。したがって全 match は導出した軸 literal \(L\) を含み、anchor・lookaround・`\b` による窓外文脈への依存がない。この条件のときだけ `search(text, pos, endpos)` を使う。
- [s8b_holdout_freeze.py:516](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t2273-issue-subprocess/orchestrator/campaign/s8b_holdout_freeze.py:516) 付近で Python 3.10 の `sre_parse.parse(expression).getwidth()[1]` を使う。3.10 では上限が `sre_parse.MAXREPEAT` に飽和するため、`W >= int(sre_parse.MAXREPEAT)` は有限とみなさず全文 search に戻す。解析失敗も同じ扱いにする。`L is None`、非 exact `str`、または幅が使えない場合も全文 search に戻す。3.10 の `sre_parse.MAXWIDTH` は存在しない。
- [s8b_holdout_freeze.py:564](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t2273-issue-subprocess/orchestrator/campaign/s8b_holdout_freeze.py:564) で、出現位置 \(p\) ごとに `lo=max(0,p+len(L)-W)`、`hi=min(len(text),p+W)` とする。長さ \(m≤W\) の match が \(L\) のその出現を含めば、match 開始は `p+len(L)-m ≥ lo`、終了は `p+m ≤ hi`。よって全文に match があれば少なくとも一つの窓で見つかる。逆向きは窓が同じ text の `pos/endpos` であり、上記の文法では文脈依存 assertion がないため成立する。`endpos` は終了位置がちょうど `hi` の match も許す。
- [s8b_holdout_freeze.py:562](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t2273-issue-subprocess/orchestrator/campaign/s8b_holdout_freeze.py:562) の次位置を `p+len(L)` にすると重なる出現を失う。`p+1` が必要。Unicode でも `find` と regex の幅はともに Python `str` の文字位置で扱われる。
