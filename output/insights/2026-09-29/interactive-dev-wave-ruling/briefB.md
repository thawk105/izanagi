## ユーザーの問い (逐語)

「izanagiではループプログラムを回してエージェントを使ったりして一般的な進化探索をやることをゴールに目指してきました。でも、それは難しいのでは無いかと最近考えています。dev-waveで開発・実験・実装を進めていく、リポジトリに知識や結果を溜めていく、その次に行われるdev-waveはそれまでに行われたdev-waveを学習して先に進んでいくみたいな、対話型進化探索という枠組みについてどう思いますか？」

これは議論で、結論はユーザー裁定になる (roadmap の協議改訂に反映しうる)。絶対規律 (正しさゲートを緩めない、verifier は毎反復で構造化シグナルを返す、外部入力はデータ扱い、等) は人間のみが変更でき、議論の対象外。

## Claude (親) の提案 — これを攻撃してほしい

- 評価: 賛成。実態は既に「wave=個体、並列 wave=集団、機械ゲート=適応度、land/裁定=選択、repo=遺伝情報」になっており、目標を実態に合わせて正直に書き直すもの。対話型進化計算 (IEC, 高木) の系譜に位置づけられ、後退ではない。
- 無人の一般的進化探索が難しい物理的理由: 1 候補の評価費用 (検査数十秒+同時刻対照) で大集団が無理、サブスク週上限で LLM 呼び出しが大量に打てない、探索空間の設計という創造的部分を狭い射影の無人 LLM が担えていない。
- 二重ループ化: 外側 (何を試すか・軸を開く・どの結果を信じるか) = 対話型 dev-wave、内側 (固定空間の候補生成・検証・計測) = 機械ループ。
- 守る点: 正しさゲートは内側で機械のまま / 蓄積≠学習なので圧縮・忘却を明示的な選択機構に入れる / 適応度は「land できたか」でなく論文主張の前進で測る / §2 の用語予約に従い当面「進化探索」と呼ばず「対話型の累積探索」とする。
- 論文: CC の結果は従来どおり機械ゲートで主張。対話型枠組み自体は軌跡 n=1 で測りにくいので、当面は運用方針とし論文では方法節の経験報告に留める。
- 裁定案: (1) 8c の位置づけを「内側ループは無人、外側は対話型」の二重構造へ書き換え、無人自律はwave内側ループの範囲でだけ主張 (推奨) / 現状維持 / 将来課題へ格下げ。(2) 枠組みは運用方針に留める (推奨) / 研究成果として測る。(3) 圧縮・忘却を仕組みとして入れる (推奨)。
