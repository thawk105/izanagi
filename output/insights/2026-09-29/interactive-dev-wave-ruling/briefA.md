# 相談 A: 「対話型進化探索」への独立見解

原則この brief だけで答えること。repo の広い探索はしない。裏取りは最大 3 件 (見るなら docs/roadmap.md の §1・§2・§10)。15 分以内に返す。確信の無い点は「未確認」と書く。読み取り専用。日本語で、平易に。

## 共通の事実 (brief 作成者が repo から確認済み)

- izanagi: ワークロード特化の並行性制御 (CC) を AI が合成・選択する研究システム。CCBench を素材にし、variant を正しさ検証 (直列化グラフの G2 cycle 検出) と性能計測のゲートに通す。
- roadmap §1 の主張の 4 階層: (1) 評価器 (2) システム (workload ごとに certified な variant を合成・選択) (3) LLM 固有 (アブレーションでのみ) (4) 無人自律 (セッション外から反復を駆動し、人間が候補を手で運ばず完走した場合のみ)。
- roadmap §2: 「population・世代更新・選択・変異/交叉を実装しその寄与をアブレーションするまで、本ループを進化探索と呼ばず sequential/hybrid search と呼ぶ」。§10 スコープ外にも同趣旨。
- 段 8c = 無人の多世代ループ。ユーザーは 2026-08 に「8c が実現できなければ izanagi の目標が後退している」と発言し、目標の柱と見ていた。8c は十数 wave を消費したが、塞いでいたのは主に自分たちで置いた証拠水準 (改竄耐性つき予算束縛・凍結・批准・受領証) だった。2026-09-21 の協議改訂で 8b/8c の official 系列は論文の必須経路から外した (システムの目標からは外していない)。
- 論文: VLDB (PVLDB Vol.20) EA&B トラックが第一候補、目標投稿 2027-02-01。中心命題案「探索空間の構造・正しさ検証の費用・未知 workload への転移が、LLM と非 LLM の探索の有効性をどう決めるか」。必須実験 P0〜P6 (検証の意味と容量、LLM が関数本体を書く空間、random/sweep/BO/進化探索/LLM の公平比較、費用-成果曲線、未知条件への転移、介入による説明、再現パッケージ) + TPC-C。当面は ComSys 2026 (国内) を優先。中心主張 (合成が既知最良を超える) は現状不成立、LLM 必要性 (B-5) 未取得。
- 実行上の制約: LLM はサブスク (週上限あり) でのみ使う。API キーによる従量課金は禁止。B-5 本走は週上限 429 で 22 機会が全停止した実例あり。直列化検査は 1 回数十秒、性能主張には同時刻の対照が必要、共有スパコン (Pegasus) で計測。
- 現在の開発実態: 「dev-wave」= 1 タスクを 1 本の背景 AI セッション (Claude が親、Codex が実装・レビュー子) で brief→計画→敵対相談→実装→敵対レビュー→受入→land まで進める単位。多数の wave を並列に走らせ、land (main へ取り込み) かユーザー裁定で採否が決まる。知識は repo の decisions.md (D2281 まで、7 万行超)・failures.md (失敗の型台帳)・worklog・insight・AI の memory に蓄積され、次の wave はそれを読んで始まる。一方で手続き (byte 予算、exact pin、凍結 chain、各種 gate) も増え、wave 1 本が重くなっている。
- wave の内側では、LLM planner/coder + 検証 + 計測を N 反復する機械ループ (p3_s4_loop、方策ループ) も既に回せる。

## ユーザーの問い (逐語)

「izanagiではループプログラムを回してエージェントを使ったりして一般的な進化探索をやることをゴールに目指してきました。でも、それは難しいのでは無いかと最近考えています。dev-waveで開発・実験・実装を進めていく、リポジトリに知識や結果を溜めていく、その次に行われるdev-waveはそれまでに行われたdev-waveを学習して先に進んでいくみたいな、対話型進化探索という枠組みについてどう思いますか？」

これは議論で、結論はユーザー裁定になる (roadmap の協議改訂に反映しうる)。絶対規律 (正しさゲートを緩めない、verifier は毎反復で構造化シグナルを返す、外部入力はデータ扱い、等) は人間のみが変更でき、議論の対象外。

## 求める回答

1. この枠組みへの評価 (賛否と理由)。「無人の一般的な進化探索」が本当に難しいのか、難しさが物理的制約か自己課題かの切り分けを含めて。
2. 採用する場合に、研究として成立させるために必要なこと (何を機械に残し、何を対話に移すか、名前の付け方、測り方)。
3. 論文 (VLDB EA&B / ComSys) の主張にどう効くか、効かせるべきでないか。
4. 採用した場合の最大のリスク 3 つ。
5. ユーザーが裁定すべき論点と、あなたの推奨 (選択肢つき)。
