## 裁定 (修正後の推奨どおり)

1. 研究の進め方: 対話型の dev-wave (repo に結果と失敗を溜め、次の wave がそれを読んで進む) を当面の研究の主経路として正式に採用する。P0〜P6・TPC-C を優先する。正しさ判定・候補の検証・性能計測・試行記録は機械側に残し、対話へ移すのは「次に何を調べるか・予算・結果の解釈・方針変更」だけ。
2. 8c (無人の多世代ループ): 元の達成条件 (roadmap §2「セッション非依存で checkpoint・予算・再開を orchestrator が所有」) と「未達」の状態をそのまま残す。定義の書き換えで達成扱いにしない。ComSys 締切 (2026-10-30) 後に小さな予算で無人多世代ループの実現可能性を別に試し、その結果で継続・延期・目標変更をあらためて裁定する (計算が合計 2 node 時間以上なら事前確認)。
3. 呼び名: 「対話型進化探索」は内部の呼び名に留め、論文・正式な方法名では「人間が介在する逐次探索」と書く。roadmap §2・§10 の「進化探索」用語予約は維持。
4. 記録: 人間の判断と投入時間を記録し、無人で得た成果と混ぜない。進み具合は wave 数でなく certified な成果・既知最良との差・論文の図表の充足で見る。新しい機構は作らず既存の worklog の書き方で対応する。
- 却下: 初案の「無人自律を wave 内側ループの範囲に限って主張する」(8c 未達を定義変更で見えなくする)、「圧縮・忘却を仕組みとして新設する」(研究を止めている実測根拠なし、wave を重くする)。
- 最も強い反対論 (Codex B): wave を進化の個体に見立てる対応は成立しない (wave の中身が不揃い、正しさゲートは失格判定で適応度ではない、land は実装容易性にも左右される)。IEC との類比は比喩止まり。費用制約は大集団の困難の根拠で、無人ループ不可能の証明ではない。
