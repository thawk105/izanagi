## 新しい所見

- **N1｜must-fix｜read API 照合の対象定義が循環している。** `README.md:64` は `read_internal` を迂回する成功 read の検出を目的とするが、`:69` は「外部 read」を `read_internal` を通った呼び出しと定義する。このままでは迂回した呼び出しが照合の母集団に入らない。公開 `read()` の成功を read set 登録とは独立に記録し、再読・read-own-write の除外を分岐として照合するよう定義する。

- **N2｜should｜費用の台帳値が古い。** `worklog fragment:26` の 0.3〜0.4 node 時間を、`README.md:131` と同じ **0.22〜0.36 node 時間**に直す。

- **N3｜should｜陰性の読解結果から代替案の安全を断定している。** `README.md:100,206` は検索範囲で反例が見つからなかったという限界を認める一方、`:60,100` と `decisions fragment:15` は代替案が「解放済み memory を読まない」と断定する。実装 wave で解放経路を確認することを採用条件とし、現段階では指定範囲の読解上の見込みとして表現する。

## 総括

**NO-GO。** R2 の目的である `read_internal` 迂回の検出が、現在の定義では成立しない。N1 を直し、台帳の旧見積りと代替案の断定も整える必要がある。
