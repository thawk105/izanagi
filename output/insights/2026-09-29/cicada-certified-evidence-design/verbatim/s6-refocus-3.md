## 新しい所見

- **G1｜must-fix｜M の性能値を格上げする条件から read 側照合が落ちている。** M の必須条件と完了条件は B・U・read 側の違反 0 である（`README.md:66,177`、`decisions:12,16`）。一方、案ごとの性能値の地位は「巡回 0 と束縛・公開の照合 0」（`README.md:161`）、ユーザーへの判断点は「巡回 0 + 束縛・公開の照合 0」（`README.md:186`）だけを条件とする。このままだと read 登録漏れがある variant も格上げ対象に読める。両箇所を **巡回 0 + B・U・read 側 API 照合の違反 0** に揃える。
- **G2｜nit｜案 A の壊し patch の費用表に I が任意と読める表現が残る。** A は write 側 I を必須とする一方（`README.md:67,147`）、費用表は「+ I を入れるなら 1 本」と書く（`README.md:130`）。実装時に変異試験の本数を決める粒度なので、I 自体の必須性と変異試験の選択を区別して記すとよい。

## 総括

**NO-GO。** R2・N3・F1・F2 を含む既往の所見は閉じ、回帰も見つからなかった。ただし G1 はユーザーが判断する性能値の格上げ条件を、M の必須証拠より弱くしているため、一次資料内で揃える必要がある。
