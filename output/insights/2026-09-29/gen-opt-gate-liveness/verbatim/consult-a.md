## brief で正しいと確認した点

- D1 の「最初の操作」は、同じ key について**実行される `pro_set_` の順序**で決める。READ→READ は `R` 1 行、WRITE→READ は通常 `R` なし、READ→WRITE→READ は `R` と `W` 各 1 行、RMW→RMW は `R` と `W` 各 1 行、WRITE→WRITE は `W` 1 行になりうる。[ycsb.hh](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-gen-opt-gate-liveness/external/ccbench/include/ycsb.hh:117)、[transaction.cc](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-gen-opt-gate-liveness/external/ccbench/cc/silo/transaction.cc:195)。`KEY_SORT` の既定は 0。1 にする場合は sort 後の順序が基準になり、同 key の WRITE 比較は厳密順序になっていないため別途扱いが要る。[procedure.hh](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-gen-opt-gate-liveness/external/ccbench/include/procedure.hh:25)

- abort 時は集合が消去され、手順列は再生成されず `goto RETRY` で同じ列を再実行する。`Q` を成功した `commit()` の後だけに出し、読み刻印を試行ごとに初期化すれば、失敗試行の値は混ざらない。Silo の `commit()` は read-only でも `writePhase()` を通る。[ycsb.hh](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-gen-opt-gate-liveness/external/ccbench/include/ycsb.hh:108)、[transaction.cc](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-gen-opt-gate-liveness/external/ccbench/cc/silo/transaction.cc:706)。`is_ronly_` による Silo commit の近道は見つからない。

- `YCSB::id_` は payload 内にあり、YCSB の key は `pro.key_` から作られる。初期 load の `id_` は key id で、200 key・4 thread の設定では提案の上位 16 bit を使う書き手刻印と衝突しない。RMW の `val_` コピーとも、コピー後に刻印すれば整合する。[ycsb.hh](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-gen-opt-gate-liveness/external/ccbench/include/ycsb.hh:40)

- 修正案の `read` で書き込み集合を先に探すこと自体は、既に登録した読みを validation から消さない。先に読んだ key の `R` は残り、blind write 後の自分の値の読みは `W` の lock 対象になる。2 度目の `update` は既存 `WriteElement` の**値だけ**を置換し、key・tuple pointer・op を保てば `lockWriteSet` と `max_wset_` の前提を保てる。[transaction.cc](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-gen-opt-gate-liveness/external/ccbench/cc/silo/transaction.cc:145)、[transaction.cc](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-gen-opt-gate-liveness/external/ccbench/cc/silo/transaction.cc:449)。YCSB 外の `scan` は別に読み集合優先なので、この修正だけで全 API の意味が揃ったとは主張できない。[transaction.cc](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-gen-opt-gate-liveness/external/ccbench/cc/silo/transaction.cc:305)

- stock・B1・修正の 3 build に各 workload を走らせ、stock から (a)(c) を同時に読む構成は依頼の「(b) と (c) は同じ job で取れるなら合わせる」より少ない job で 4 読みを満たす。B1 を使い捨ての専用 build に無条件適用することも、判定述語や production の条件 gate を変更しない限り、検査を甘くしない。[md_5.txt](/work/1/SFC/tanab/tmp/gen-opt-2026-09-29/md_5.txt:13)
