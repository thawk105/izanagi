# 共通記法 (md_9 の書き分け用、親が 2026-09-29 に固定)

対象の方式ごとに、次の 7 項目を同じ語で埋める。原典にない項目は「記述なし (読んだ節: …)」と書き、推測で埋めない。

- **位置 π(T)**: その方式が動かす「tx の直列化位置」の表現。点 timestamp / 区間 [L, U) / epoch / commit 時に導出される commit_ts など。
  いつ決まり、いつ確定 (1 点に潰れる) するか。
- **契機**: π(T) が変わるきっかけになる事象 (例: lock 衝突の検出、read 時、commit/validation 時、先行 tx の commit、abort 後の再試行)。
- **向き**: π(T) が動く向き。「後へ (later)」「前へ (earlier)」「両端が内側へ縮む」「動かない」。何に対して後/前かも書く。
- **読む版の選択**: π(T) から、あるキーのどの版を読むかの規則 (最新版だけ / π(T) で可視の版 / 下限未満で最大の版 など)。
  旧版 (最新でない版) を**新たに**読めるか (single-version なら不可)。
- **既読維持の判定**: π(T) が動いたとき (または commit 時)、既に読んだ版がその位置でも同じ値であることを、いつ・何で保証するか
  (lock と区間の不変条件 / commit 時の validation / lease (rts) の延長 / epoch 規則 など)。保証できないときの帰結 (abort / 待つ / 読み直す)。
- **GC への反映**: 版データの回収境界 (GC が「まだ要る」と見なす下限) が、この tx の何 (開始 timestamp / π(T) / epoch …) で決まるか。
  π(T) の変化がその境界を動かすか。版データ以外の回収 (lock 表の項目など) に結んでいるなら、それは別に書く。
- **長い tx / 読み取り後に止まっている tx への効き方**: 記述があれば。

引用は原典テキストに実在する英語の逐語だけ (節番号つき)。要約と逐語を混ぜない。
