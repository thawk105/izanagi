## レンズ A の攻撃面

1. **恒真化が残る経路**。プランを全部実装したとして、なお「検査が常に通る」入力を作れるか。
   設計案 §5 の各層について、その層を無効化しても現行テストと提案テストが緑のままにならないか
   コード上で確認せよ。緑のままなら、その検査は変異を殺せていない。
2. **層の相互 mask**。ある層の負例が別の層に手前で落とされていて、対象の層を消しても赤にならない
   ものはどれか。とくに schema 上限 `<100.0` を入れたあとで loader の完全一致検査の負例が
   `100.0` のままなら、その負例は schema が食うので loader の変異を殺せない。
3. **恒真な assert**。提案されている新テストのうち、production 定数から期待値を生成しているもの、
   空 loop で成功するもの、壊れた JSON を負例にしていて well-formed な攻撃 artifact を試して
   いないものを名指しせよ。
4. **受理集合の非承認な変更**。プランが scope 外で受理集合を広げる/狭める箇所。とくに
   schema 上限を狭めたことで **正当な履歴 artifact が parse 不能になる** 経路 (U-5 が
   明示的に禁じている) が生まれていないか。
5. **N2 の扱いが正しさの後退でないか**。既存の観測 artifact が canonical 述語で落ちる事実を、
   既知例外・legacy 分類・skip・条件分岐のどれで表現しても、それが「将来の非適合 artifact も
   一緒に通す」抜け道になっていないか。既知例外は **artifact を name/SHA で名指しして閉じている**か、
   それとも述語の形で開いているか。
6. **変異の帰属不成立**。プランが「この変異はこの検査が殺す」と主張する対応のうち、実際には
   別の理由で赤くなるもの (赤理由が一つに絞れないもの)。
