## 費用構成の組み替え (D1779 / T-2414 の中身)

`orchestrator/campaign/floor_pair_driver.py` が pair-sample ごとに exact 要求するのは、
2 side session・各 session 2 測定・合計 4 測定・うち reference ちょうど 2 件である
(`REFERENCE_MEASUREMENTS_PER_PAIR_SAMPLE = 2`)。したがって 1 pair・1 セルあたり
**248 side session・496 測定 (候補 248・参照 248)**。

**加算ではなく組み替えである。** 候補側の名目 3,720 秒は変わらず、参照側が 1,860 秒から
3,720 秒になり、かつ別セッションではなく候補と同じ 248 セッションの中へ入る。
名目合計は 5,580 秒から 7,440 秒になる。

単位の根拠は driver 自身にある — 測定ごとに `reps` を渡し、成果物 header へ
`measurements_per_session` と `reps_per_measurement` を別々に書く。**反復数は session ではなく
測定ごとに掛かる。** 段 3 レンズ A はここを「単位を無断で移した未証明の派生値」と攻撃し、
親が現物で裏を取って本文へ根拠を明記した。

数値の系列は erratum に 3 世代とも残してある — 起草時 (n=59) 236 / 3,540 / 1,770 / 計 5,310、
D1695 後の旧構成 248 / 3,720 / 1,860 / 計 5,580、現構成 496 測定 / 7,440 秒。

## ユーザー裁定へ返す項目

1. **「開始時刻」欄の発効版での書き方。** D1649 決定 2 は「欄は `未記入` のままでよい」とするが、
   §0 は「placeholder 語が 1 つでも残る限り実走前検査は閉じたままである」と定め、
   `p3_b4_admission_record.py` は sentinel を含む値セルを拒否する。**この 2 つが両立する限り、
   他の 9 欄が全部埋まっても本書は発効できない。** 解き方は少なくとも 3 つある —
   (a) §0 の原子性・sentinel 規則を改訂する、(b) 本欄に非 sentinel の値を定義する
   (本 wave は未授権として採らなかった)、(c) 行 label 集合を変えずに本欄を発効条件から外す。
   いずれも受理集合を変えるので AI が既成事実にしない。
2. **§11.3 と D1641 の食い違い。** §11.3 は担当者の指名・対象集合・統計関数・採用証拠の受理を
   ユーザー手番として列挙したままだが、D1641 決定 1・2 は担当 3 者を `thawk105` 名義で AI 委任とし、
   採用裁定も委任下の AI が行うと決めている。**D1812 (c) が名指ししたのは §11.1 と §11.2 なので、
   本 wave は §11.3 を編集していない。** 訂正には追加の授権が要る。
   段 6 レンズ A の must-fix はこの 1 件である。
