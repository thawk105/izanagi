### 2. 「凍結しない」は「先に床値を測ってよい」ではない

- **主張:** 差分ゼロ自体は緩和ではない。ただし、それを事前凍結が済んだ扱いにすると規律の向きが逆になる。
- **現物:** 事前登録 `:1084` の手順6は結果を見る前の別 commit、続く手順7は凍結どおりの測定を要求する。`:287` は期待 spec 列も結果を見る前に閉じる。`floor_pair_driver.py:1237` の HEAD blob 一致と `:1285` の真の祖先確認は、結果を見た時刻を検証しない。issuer `:62`、`:1230` はその非保証を明記する。
- **成果物への影響:** 結果を見て spec／期待列を選び直せば、最大値を取る母集合と参照 pin を変えられる。閉包一致だけでは、その選び直しを排除できない。一方、現状の §5 floor は `未記入`（事前登録 `:162`）で、材料レポートは floor 不在を渡す（`p3_b4_material_report.py:268`）。
- **scope:** 「今回は未凍結であり、既存の事前凍結手順が残る」という結論の限定は内。時刻検査等の追加は外。
- **判定:** brief `:10` は凍結を前段としており、先行測定の許可は読み取れない。ただし「差分ゼロだから順序も機械保証される」とは報告できない。

### 3. 1 cell の spec は構文上可能。閉包一致は対象集合の正しさではない

- **主張:** 「1 cell なら loader が拒否する」は成立しない。plan はこの区別を保ち、縮小集合による凍結を提案していない。
- **現物:** `floor_pair_driver.py:798` は cells を非空とするだけ。`:1079` の比較対象は spec 自身が宣言した planned strata。issuer `:1031` は期待 spec 列を非空とするが「3件」は要求せず、`:1058` は各 spec の窓ちょうど2を要求する。`:1090` 付近のセル閉包も spec 内の cells が基準。事前登録 `:297` と D1696／D1974 は意味的な対象集合一致を人手責任としている。
- **成果物への影響:** 必要なセルを落とした spec と、それに整合する summary を採れば、保守側最大の対象が狭まり、床値と出所一覧が変わり得る。コードの閉包検査だけでは正規の3 workload×対象セルを証明しない。
- **scope:** 採用根拠の確認は内。件数 gate やセル検査の追加は外。
- **失敗型:** `[恒真ゲート]` の攻撃面。ただし現在の閉包検査は独立した期待列との不一致を拒否するため、それ自体が恒真なのではない。期待列を観測入力から作れば循環する点は D1974 が明示している。

### 4. 「strict」の内訳には、発火しない外部照合と冗長照合がある

- **主張:** brief `:58` と plan の「strict 検証」を、現行 policy・外部 source pin までの完全照合と拡張して読んではならない。

- **失敗型:** F962（`docs/failures.md:25203`）の `[恒真ゲート][説明と実装の食い違い]` に照らした確認。**brief／plan が独立保証と明言した再発は確認していない。**
