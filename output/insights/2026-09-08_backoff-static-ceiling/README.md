# 静的 backoff の表現可能上限を 999 から 9999 マイクロ秒へ広げた

2026-09-08。branch `worktree-dev-wave-backoff-static-ceiling`。base `cf4273f56`。実装 commit `91a5bfca3`。

## 0. この wave が主張すること・しないこと

**主張する:** 静的 (定数) backoff の表現可能な上限が 999 マイクロ秒に固定されていた原因を符号化の側で
閉じ、静的値 1000〜9999 マイクロ秒を測れる状態にした。既に測り終えた生値 0〜2999 の意味は
1 つも変えていない。

**主張しない:** **測定は一切していない。** 1000 マイクロ秒より上を実際に測ってはいない。
右側の打ち切りが 999 から 1000 へ 1 点動いただけであり、**abort の抑制が飽和する領域には
到達していない。** どの点を、いくつ、どの停止基準で測るかは本 wave の外の裁定である。

## 1. 何が問題だったか

`patches/silo-backoff-fixed.patch` の合成枝は、供給された値 V を単一の量として扱っていない。
商 `V / 1000` がモードを選び、剰余 `V % 1000` が振幅になる。

| 生値 | 意味 (変更前) |
|---|---|
| `-1` | stock の適応 backoff (inert) |
| `0`〜`999` | 一定待ち。物理値 = 生値 |
| `1000+μ` | μ/2 から 3μ/2 の対称 modulo |
| `2000+μ` | μ/2 か 3μ/2 を確率半々 |
| `3000` 以上 | 一定待ち。物理値 = `V % 1000` (すなわち 0〜999 へ戻る) |

したがって静的な 1000 マイクロ秒はどの生値でも表現できなかった。生値 1000 は「形 1・振幅 0」を
選んで実質 0 マイクロ秒を測る。これが F718 で記録された計測汚染の正体である。

受領済みの実測 (worklog entry 1314) では、格子の上端 999 マイクロ秒でも abort の抑制が
飽和していない。したがってこの上限は待ち方 campaign を実際に制約していた。

## 2. 何をしたか

**未使用だった `V >= 3000` の復号だけを `V % 1000` から `V - 2000` に変えた。**
静的値 μ の符号化は次になる。

- `0 <= μ <= 999`: 生値 `V = μ` (変更なし)
- `1000 <= μ <= 9999`: 生値 `V = μ + 2000` (生値 3000〜11999)

C++ の hole line で変えたのは最終項の 1 箇所だけで、`#if` / `#else` / `#endif`・マーカー・
stock 枝・待機ループは 1 byte も変えていない。生値 0〜2999 の 3 領域の復号結果は数値的に不変である。

**上限 9999 は設計判断である。** 段 3 の敵対相談が、上限のない符号化では
(a) `μ = 2^53+1` 付近で C++ が倍精度へ丸め Python の有理数が丸めないため両者が別の関数になり、
(b) 待ち時間 `clocks_per_us * now_backoff` の符号なし 64 bit 変換が
`clocks_per_us=2100` で `μ ≈ 8.8e15` から桁あふれすることを現物で示した。
9999 は現行上限の 10 倍で、適応 backoff の上限 1000 マイクロ秒を十分に越えつつ、
丸めからも桁あふれからも遠い。定義域の強制は Python 側の codec と `exact_model` が行う。

## 3. 事前登録を動かす必要があった理由 (親が現物で見つけた新事実)

`orchestrator/campaign/b10_backoff_shape_sweep.py` の `load_preregistration` は、
**作業ツリーの patch の中身が事前登録 commit の blob と一致すること**と、
**登録した式の SHA が現行の hole line から導く SHA と一致すること**を preflight で要求する。

したがって符号化を変えた時点で、新しい登録 commit を持たない限り B-10 の正式走行は必ず止まる。
**事前登録の版立ては符号化の変更と不可分であり、後回しにできない。**

B-10 事前登録は v5 とした。動かしたのは次の 3 つだけである。

| field | v4 | v5 |
|---|---|---|
| `schema_version` | `.../v4` | `.../v5` |
| `artifacts.patch_sha256` | `36cd974c…0832` | `a5e0710c…8580a` |
| `artifacts.formula_sha256` | `5b3d8dee…c662` | `1205b1ff…e8df` |

R1〜R5、μ 格子、workload、block 数と実行順、threads、extime、反復数、cell の切り方、
α、Holm、permutation、信頼区間、等価域、欠測規則、曝露規則、判定手続き、
`physical_residual` の値と provenance は 1 文字も変えていない。

**v4 の下で完了した 135 cell は v4 の束縛のまま残す。** 新版へ resume・追記・再ラベルしない。

## 4. 段 6 のレビューが見つけた最大の欠陥

**旧 v4 の 135 cell が、現行 v5 の束縛で検証されるようになっていた。**
`_legacy_write_heavy_binding` と `_legacy_balanced_binding` は、`prereg_commit` /
`prereg_blob_sha` / `spec_sha256` / `patch_sha256` / `formula_sha256` の 5 つを
**現行の** `prereg.binding` から取っていた。事前登録が v4 のうちは正しかったが、
v5 になった瞬間に旧記録行を拒否する。上記「v4 のまま残す」と両立しない。

**2 本の敵対レビューが独立に同じ所見を挙げた。** 直し方は、旧束縛の 5 値を成果物に記録された
v4 の値へ固定し、現行事前登録から独立させることである。これは受理集合を**狭める**修正である。

あわせて、この欠陥を隠していた恒真な fixture (期待束縛を同じ関数から作っていた) も直し、
「現行事前登録が v5 で記録行が v4」という負例を足した。

## 5. 段 6 のレビューが見つけたその他の must-fix

- **codec の全域検査が自己参照だった。** 符号化器と復号器を往復させるだけで、両方を同じように
  誤らせれば通る。独立した閉じた式をテスト側に literal で書いて全域を突き合わせる形へ直した。
- **旧診断モジュールの呼び手が凍結 helper を通ることが固定されていなかった。** 呼び手を現行の
  genome 一覧へ戻しても helper を残せば緑のままだった。実体を名指しして接続を固定した。
- **事前登録の現物と patch の現物を突き合わせる検査が無かった。** 古いハッシュのまま単体テストは
  緑で、正式走行だけが `patch-sha` で止まる状態だった。canonical な文書を実際に読んで
  現物のハッシュと比較する node を足した。schema の負例も直前版 (v4) を拒否する形にした。

## 6. 焦点走で出た赤 1 件と、その裁定

`test_t2266_requested_realized_and_unrealized_are_separate_identity_fields` が
`assert M.T2266_REQUESTED_US is not M.T2266_REALIZED_US` で落ちた。
両者の中身が等しくなった (1000 が測れるようになった) ため、処理系が同じ定数を共有したからである。

**親は「誤っているのは実装ではなく期待値」と裁定した。** この検査が守ろうとしていた性質は
「成果物が要求した点と実際に測れた点を別の欄として持ち、未実現点を隠さない」ことであって、
Python のオブジェクト同一性ではない。成果物側では別々の list として生成され欄も分かれている。

**tuple をわざと別オブジェクトに作り分けて `is not` を通す直し方は禁止した。**
処理系の実装詳細を固定するだけで、守るべき性質を守らないからである。
両方の欄が存在すること、生成される 2 つの並びが独立であることを検査する形へ変えた。

## 9. この wave が閉じないもの

1. **1000 マイクロ秒超の測定格子。** どの点を、いくつ、どの停止基準で測るか。追加点数と walltime。
   科学的設計と計算資源を変えるので本 wave では数値を決めていない。
   **飽和を本当に閉じるならこれが次の必須手番である。**
2. **非負 `BACKOFF_FIXED` の production 意味宣言。** 意味判定器は実在し、生値 3000 が
   実測 1000.0 になる正例も生値 1000 が 0 になる負例も張れる。しかし production の driver は
   非負値に宣言を渡しておらず、`unestablished` のまま admission される。
   全 driver への一般化は依頼が scope 外と明示した一般化に当たるので実装していない。
3. **実測後の walk model の更新。** 現行テストは realized 1000 を拒否する形で凍結されている。
   反転は実測が出た後の別変更単位である。
4. **完了済み B-10 135 cell の再測定・再ラベル。** 行わない。旧束縛のまま残す。
5. **cache admission の preimage 変更による旧 cache key の温存。** 行わない。
   stock の preprocess digest・`src_token`・variant 識別子は不変だが、
   admission receipt 経由の cache key は変わり、安全側に miss する。
