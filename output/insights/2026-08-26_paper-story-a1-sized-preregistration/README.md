## 1. 何を測るか

同一 campaign の中で 2 つの構成を測り、その差を出す。

| arm | genome |
|---|---|
| `adaptive` | `silo` + `BACK_OFF=1`, `BACKOFF_FIXED=-1` (適応 backoff) |
| `static10` | `silo` + `BACK_OFF=1`, `BACKOFF_FIXED=10` (固定 10 マイクロ秒) |

対比は `static10 - adaptive`。workload は write-heavy (`ycsb_rratio=5`) / balanced (`50`) /
read-heavy (`95`) の 3 つで、それぞれ独立した campaign を 1 本ずつ立てる。
規模は records=1,000,000 / threads=48 / zipf skew=0.9 / rmw=0 / max_ope=10 / extime=3 秒。
**規模は 2026-08-24 の探索走から 1 つも変えていない。** 変えたのは反復数だけである。

## 2. 反復数

`n` は次の 2 条件を同時に満たす最小の整数とする。評価は正規独立同分布・真の SD = 計画 sigma を
仮定した Monte Carlo (seed 20260826、20,000 試行) による。

1. 真の差が 0 のとき `bounded-below-floor` と判定される確率が 0.80 以上
2. 真の差が floor の 2 倍のとき `resolved-above-floor` と判定される確率が 0.80 以上

さらに `n >= n_min = 28` を課す。`n_min` は「**標本 SD 自身**の片側 95% 上側信頼限界への膨張係数が
1.30 以下になる最小の n」である。n=5 では 2.3724、n=8 で 1.7972、n=28 で 1.2938。
5 点の SD が使い物にならなかったことがこの再実施の出発点なので、SD の推定品質にも下限を置く。

| workload | 計画 sigma (tps) | 規則が出す n | **採用 n** | k = t(0.975, n-1) |
|---|---|---|---|---|
| write-heavy | 103551.0849 | 72 | **72** | 1.993943 |
| balanced | 156906.1857 | 205 | **205** | 1.971661 |
| read-heavy | 60384.6868 | 11 | **28** (n_min が効く) | 2.051831 |

計画 sigma = 2026-08-24 探索走の位置対応差の標本 SD x 2.372356
(自由度 4 の片側 95% 上側信頼限界)。合計 610 反復、bench 約 34.2 分 (実測 3.36 秒/反復)。

**探索走から引くのは、この分散の値だけである。** 探索走の結論 (差の符号・大きさ・
「判別できない」という記述) は 1 つも引かない。判定にも一切使わない。

### 到達する動作特性 (上と同じ Monte Carlo)

| workload | 真値 0 → below | 真値 = floor → unresolved | 真値 = 2 x floor → above |
|---|---|---|---|
| write-heavy (n=72) | 0.828 | 約 0.95 | 0.918 |
| balanced (n=205) | 0.814 | 約 0.95 | 0.910 |
| read-heavy (n=28) | 1.000 | 0.950 | 1.000 |

真の差がちょうど floor のときは 95% で `unresolved` になる。**これは設計どおりである** —
floor は「差と言えるかどうかの境目」であり、境目の上下を断定しないのが正しい。

## 3. 判定規則

判定が消費するのは、対差の平均・標本 SD・反復数 n・凍結した k・その走行の adaptive 平均だけ。
実行時に分布の分位点を計算しない。

- `B = 0.030 * (その workload の adaptive arm の平均 tps)` — **この走行で測った値**を使う。
  0.030 は D19 の between-run noise floor で、D496 決定 4 が用途を維持している。
  D19 の floor はもともと変動係数 (相対量) なので、絶対 tps ではなく相対で置く。
  過去の走行から取った絶対値を境界にすることは D496 決定 1 が禁じている。
- `h = k * SD / sqrt(n)`。`k` は 2 節の表の凍結値。

優先順位つきで次のとおり分類する。

| 順位 | 条件 | 分類 |
|---|---|---|
| 1 | `abs(mean) - h > B` | `resolved-above-floor` |
| 2 | `abs(mean) + h <= B` | `bounded-below-floor` |
| 3 | 上のどちらでもない | `unresolved` |

3 分類は全実数値を尽くし、互いに重ならない。`h > B` のときは順位 2 が成立しえないだけで、
値域に穴は開かない。

`variance_plan_breach = (実現標本 SD > 計画 sigma)` を**独立の報告項目**として出す。
**この flag は分類を上書きしない。** 実現 SD は既に `h` に入っており、SD が大きければ
自然に `unresolved` へ寄る。その上でさらに分類を潰すと、誤判定率の定義されていない閾値で
結果を抑制することになる。

## 4. 走行と成果物の規則

- **横断結論を作らない。** workload ごとの終端結果だけを出す。1 つの workload が invalid でも
  他の 2 つの値は消さない。
- **publish は 3 workload すべてが終端結果 (valid + 分類、または invalid + 理由) を持つときだけ**
  行う。公開先は一度しか作れないため、途中で壊れた束が公開先を永久に占有するのを防ぐ。
- **再走してよい理由は次の閉じた列挙だけ** — build 失敗、verify 失敗、競合テナントの検知、
  scheduler / infra 失敗。いずれも bench が始まる**前**の失敗である。
  **`rep_notes` が空でない・`rounds != 1`・`unstable` は再走しない。** その workload を
  invalid として確定させる。理由は 5 節に書く。
- 走行は `formal=false` / `promotion_prohibited=true` のままとする。
- 公開先 `output/insights/2026-08-26_paper-story-a1-sized/`、durable base も本 study 専用にする。

## 5. この設計で言えないこと (n を上げても解けない)

- **2 つの arm を別々の時間帯で測る交絡は、反復数では消えない。** campaign は arm ごとに
  build して全反復を通すため、balanced では 1 つの arm の区間が約 615 秒になり、探索走の
  約 15 秒から 40 倍以上に伸びる。同じ番号どうしを引く「対」の時間隔も同じだけ開く。
  交互配置に改めるには campaign の実行順序を変える必要があり、その実装は批准 closure に
  含まれるため本 study の範囲外である。
- **位置対応差の標本 SD が表すのは、この 1 走で便宜的に同番号を引いた差の散らばりだけ**であって、
  母平均の不確かさではない。探索走では 3 workload とも、この SD が
  独立を仮定した推定値 (`sqrt(var_a + var_b)`) を上回っていた。
- したがって出す区間は**事前登録した記述的な区間**であり、公式の信頼区間ではない。
  因果・母集団・再現性・公式の有意差は主張しない。
- 計画 sigma は 5 点から作った上側限界であり、正規性・定常性・本走との同分布性は検査できない。
  3 workload を同時に 95% とも扱えない (Bonferroni 補正なら 85% に落ちる)。
- 観測窓が 40 倍に伸びるため、within-run CV が 5% を越えて `rounds != 1` になる確率は
  探索走から予測できない。
- **`rep_notes` が空であることの要求は、反復数に対して急速に壊れる。** 1 反復あたりの
  note 発生確率を p とすると、1 workload が壊れる確率は `1-(1-p)^(2n)`。balanced (n=205) なら
  p=0.1% でも約 33.5% になる。これは感度分析であって p の推定ではない。
  それでも再走しないのは、note に残る典型が部分的な rep timeout であり、**遅い反復ほど
  起きやすい性能依存の欠測**だからである。これを理由に測り直せば、速く完走した試行を
  選ぶことになる。D510 決定 4 は失敗の分類を「性能出力の外側の証拠から、出力を読む前に」
  確定せよと要求しており、rep timeout はその条件を満たさない。
- **この走行は `formal=false` のままなので、論文 §8 の A-1 (「同一 campaign 内の対測定による
  性能比較データはまだ 1 件も無い」) を正式には動かさない。** 正式にするには D510 決定 7 の
  後続 (判定器・証拠契約・registry・judge) が先に要る。
