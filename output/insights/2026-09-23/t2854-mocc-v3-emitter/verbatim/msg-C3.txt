feat(mocc/trace): emit trace v3 frames under the TPC-C context

In MOCC's writePhase, read the TPC-C transaction-type context (set by
tpcc.hh after begin, from the previous commit) once per committed
transaction. When it is set, emit the C/R/W lines and the four
lock-coverage X lines (not-locked-at-entry, lock-lost-before-write for
UPDATE and DELETE, lock-lost-before-publish) in the v3 form (table id
from get_storage(), nS = nQ = 0 for TPC-C stage 1, the transaction
type on C). When it is not set (YCSB and the other workloads), the
existing v2 expressions and the existing
izanagi_trace::emit_lock_violation calls are used unchanged, so v2
output is byte-for-byte the same. Each committed transaction emits
exactly one C line. The context is cleared right after the E line.

All changes are inside the existing #if TRACE blocks; the existing
#line directives are kept and one more restores the base source's
logical line numbers for TRACE=0 after the E block. The permutation
P line, validation, locking, the G2 watermark hooks (environment
gated) and the INSERT exclusion of the entry X check are unchanged.
