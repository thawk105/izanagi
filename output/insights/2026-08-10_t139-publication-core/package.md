## 3. 裁定を求める問い

### C-1. `d = 1.0` では適格な `J` が 1 つも無い — 上流の設計問題

**事実。**追補 A `a10` は本走の `J` を「`L_J^cert ≥ 0.80` を満たす最小の候補」として選ぶ。
一次資料の式は**成分ごとの失敗確率の和**である。

```text
p_k(J) = F_nct( q(J, α₁) ; df = J−1 , ncp = δ⁻_k )      δ⁻_k = √J · μ⁻_k / sqrt(Σ⁺_kk)
L_J    = max( 0 , 1 − Σ_{k=1..6} p_k(J) )
```

`L_J ≥ 0.80` は `Σ_k p_k ≤ 0.20` を要し、`p_k ≥ 0` なので**各成分が個別に `p_k ≤ 0.20`**
でなければならない。失敗確率は `δ⁻_k` について非増加なので、**最小の成分**
(その `δ⁻_k/√J` がまさに gate 値 `d⁻` である) が必ず最大の `p_k` を与える。

`a11` の臨界値は `q(13, 0.025) = 3.449997` であり、`d⁻ = 1.0` のときの成分検出力は
`0.57628`、すなわち `p = 0.42372 > 0.20` である。したがって他の 5 成分がどれほど強くても
`Σ_k p_k ≥ 0.42372 > 0.20` であり、

```text
L_J ≤ 1 − 0.42372 = 0.57628 < 0.80        (候補 J = 4, …, 13 のすべてで)
```

となる。**`d⁻ = 1.0` では、どの候補 `J` も適格にならない** (親が独立に計算して確認した)。
なお 6 成分がすべて `d = 1.0` の場合は `Σ_k p_k = 2.54 > 1` となり `L_J = 0` だが、
**`L_J = 0` は一般には成り立たない** — 他の 5 成分が強ければ `L_J` は 0 より大きくなりうる。
いずれにせよ `0.80` には届かない。

**必要条件と十分条件を分ける (初版はここを取り違えていた)。**

| 種別 | 内容 | 値 (`J = 13` が最も緩い) |
|---|---|---|
| **必要**条件 | 最小成分の検出力 ≥ 0.80 (`p_k ≤ 0.20`) | `d⁻ ≥ 1.2210` |
| **十分**条件 (6 成分がすべて `d⁻` のとき) | 検出力 ≥ `1 − 0.20/6 = 0.96667` | `d ≥ 1.5623` |

すなわち `d⁻ < 1.2210` なら**確実に** `design_not_feasible` である。`d⁻ ≥ 1.2210` でも
十分ではなく、他の 5 成分の `δ⁻_k` 次第で `L_J` は 0.80 に届かないことがある。
6 成分がすべて同じ水準なら `1.5623` が要る。

source core §6 は「正規近似の目安は成分ごと 80% で `J≈11`、全体 80% で `J≈13`」と書き、
**「これは sanity 値であって本走値ではない」と明記している。**したがって文書としての矛盾ではない。
しかし実務上の帰結は重い — **裁定 U4 が「引き下げない下限」と定めた `d = 1.0` は、
本走が成立する水準ではない。**pilot がそれを大きく上回る効果を示さない限り、
source study は `design_not_feasible` で終端する。

- **(a) 事実として記録し、凍結文書は変えない (推奨)。**`d⁻ < 1.2210` なら確実に、
  それ以上でも成分次第で `design_not_feasible` で終端する、という設計をそのまま受け入れる。
  **追補 A も core も 1 byte も変えない。**pilot 前に「この水準でないと本走に行けない」ことを
  worklog へ記録する。
- (b) `a10` の `J` 選択規則 (union bound の下界) を、相関を使うより緩い下界へ差し替える erratum を
  当てる。→ **追補 A の推論内容の変更**であり、core §14 の閉集合の外。別 study が要る。
- (c) 26 割当ての上限 (裁定 U10) を上げて `J` を増やす。→ 費用の再裁定。`J = 13` でも
  `d = 1.0` では届かないので、必要な `J` はかなり大きくなる。

**成果物影響:** (a) を採ると、pilot の結果次第で本走・材料レポート・公表表がいずれも
生成されないまま終端しうる。それは正直な帰結である。(b)(c) は費用または凍結境界を動かす。

### C-2. 現 追補 B の扱いと `main_admission` — 新 core は本走を解禁しない

**事実。**source core は本走に「追補 A **と** 追補 B」を要求する
(`main_admission: requires_addendum_a_and_b`)。追補は従属先 core の三つ組と一致しなければならない。
**新 core に従属する追補 P は、source core が要求する追補 B にはなれない。**
したがって**新 core を承認しても本走は投入できない。**

追補 B 草案は B8 (a) により段階 1 で保留されている。その保留理由は「`alpha_pub_1` に
適用先が無い」ことだった。**本 wave が公表手続きの正本を起こしたので、適用先は生まれる**
(ただし新 core 側の `p02` としてであり、現 B の中身としてではない)。

- **(a) 現 B を source core 用として承認・発効させ、新 core + 追補 P を別に凍結する (推奨)。**
  現 B は現 core にだけ従属し、`b01`〜`b03` の値を持つ。追補 P は新 core にだけ従属し、
  同じ値を**独立に再記述**する (B4 (a) の「引き継げるのは値であって文書ではない」)。
  文書は互いに参照しない。→ 本走の admission が閉じる。
- (b) 現 B を破棄し、source core 用の追補 B を起草し直す。→ 起草 wave 1 本分の作業が増えるが、
  現 B のレビュー履歴を捨てることになる。
- (c) 本走を断念する。

**成果物影響:** 決まらない限り本走は投入できず、試行台帳・材料レポート・公表表のいずれも
生成されない。
