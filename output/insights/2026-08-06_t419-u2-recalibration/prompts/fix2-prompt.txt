### G-1 (最重要・NR-02 / C-03 regressed) — 1 巡目の fix が新しい回帰を入れた

`_write_exclusive` の cleanup が、`O_EXCL` で**既存ファイルを検出して失敗した場合にも**
無条件に `unlink` するようになっている。これは**自分が作っていないファイル・symlink を消す**。
`registered/` は content-addressed な公開領域なので、他者の成果物を破壊しうる。**直せ。**

- 掃除してよいのは「自分が `O_EXCL` で作成に成功した後に、書込み・fsync・close で失敗したとき」だけ。
- 作成そのものが失敗した場合 (既存ファイル衝突を含む) は、**何も削除するな**。
- caller 側は、`_write_exclusive` が正常 return した後だけ temp の所有者だとみなすこと。
- 「既存ファイルと衝突したときに既存ファイルが残る」ことを固定する negative test を書け。

### G-2 (NR-01 / PC-01 残件) — profile hash の preimage が成果物に無い

`rejection.json` に保存している SHA-256 は、保存した `effective_clock_input` の hash ではなく
**in-memory profile 全体の canonical JSON bytes** の hash である。その preimage は
成果物のどこにも残らないので、第三者が同じ hash を再計算できない。**直せ。**

次のどちらかを選び、選んだ理由を報告に書け。

- (a) hash 対象を**実際に保存した `effective_clock_input`** に変え、field 名も
  「何の hash か」が一意に分かる名前へ是正する。
- (b) `attestation_profile` 全体を成果物へ保存し、canonicalization 規則
  (`json.dumps(..., sort_keys=True, separators=(",", ":"), ensure_ascii=True)` 相当) を
  成果物内の識別子として明記する。

いずれの場合も、**成果物だけから hash を再計算できる**ことを固定するテストを書け
(テスト外の fixture から profile を再構成して hash を作り直す形にしてはならない)。

### G-3 (NR-03 / C-02 残件) — 例外経路がまだ `try` の外にある

evaluator が `set(expected)` や `expected.get()` を `try` の**外**で二度目に評価するため、
stateful / custom な `Mapping` では例外が構造化拒否にならず外へ漏れる。**直せ。**

- shape 検査と値取得は 1 回だけ行い、例外になりうる評価を全て構造化拒否の対象に含める。
- public 述語の**制御フローと戻り値**は現状 (旧版と同じ短絡順) を保つこと。
- `__contains__` / `keys` / `get` が例外を送出する custom Mapping を negative vector に加え、
  public 述語が例外を送出せず `False` を返すことを固定せよ。
