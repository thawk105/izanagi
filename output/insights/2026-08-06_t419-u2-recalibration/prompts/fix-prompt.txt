## 直す所見 (親が real / must-fix と裁定したもの)

### F-1 (最重要・レビュー A の C-02 / レビュー B の REG-01) — public 述語の例外同値が壊れている

`effective_clock_comparison_passes` が evaluator を常に完全評価するようになったため、
**旧版が `False` を返していた入力で例外を送出する**。静的反例:

- `expected={"samples_mhz":[10**400],"tolerance_pct":0.0}` — 旧: policy 不一致で band math 前に
  `False`。新: `float(10**400)` で `OverflowError`。
- `expected={"samples_mhz":[100.0],"tolerance_pct":2.0}`,
  `observed={"samples_mhz":[200.0, 10**400]}` — 旧: `all()` が先頭帯外で短絡して `False`。
  新: 2 番目まで走査して `OverflowError`。

これは所有外 consumer (`receipt_matches_contract` 経由の campaign / floor / oracle / ratified freeze)
の fail-closed 性を壊す。**直せ。**

- public 述語は shape 検査と policy 検査を evaluator の**前**に短絡させ、旧版と同じ順序・
  同じ早期 return を保つこと。
- band 走査も旧版の `all()` と同じ短絡性を持たせること (診断 projection だけが全件評価してよい)。
- 診断 projection 側でも `OverflowError` を捕捉し、構造化した拒否として返すこと。
- **上記 2 つの反例を含む negative vector を `test_execution_guard.py` へ追加せよ。**
  併せて「public 述語は旧版と同じく例外を送出しない」ことを固定せよ。

### F-2 (レビュー B の PC-01) — early 拒否が「実際に判定した profile」を残していない

`rejection.json` に median・上下限・違反 sample しか残らず、評価に使った
**全 `samples_mhz`・`tolerance_pct`・`method`・`governor`** と profile の SHA-256 が残らない。
第三者が失敗した α profile を再計算できないので proof にならない。**直せ。**

- `rejection.json` の診断へ、評価に使った effective_clock の入力を exact に保存する
  (`samples_mhz` 全件、`tolerance_pct`、`method`、`governor`)。
- 判定対象 profile の canonical JSON bytes の SHA-256 も保存する。
- 保存した入力から canonical 述語を再計算すると同じ結論になることを固定するテストを書け。

### F-3 (レビュー A の C-01) — clock-only 拒否の reason が 2 件に増えている

現状は `effective-clock-self-comparison-failed` を直接足したうえで
`acquisition-invalid: effective-clock-self-comparison-failed` を再度足すため、reason が重複する。
既存の metamorphic test は exact 1 件を固定している。**reason 集合を exact 1 件へ直せ。**
どの reason 名を残すかは、既存テストの期待値 (触ってはならない側) に合わせて決めること。

### F-4 (レビュー A の C-03) — publish 一時ファイルの orphan

`_write_exclusive(temporary, artifact)` が cleanup の `try` の外にあり、
write / fsync 失敗時に `.publish-*.tmp` が `registered/` へ残る。
unlink 失敗も無記録で捨てている。**temp 書込みを cleanup 範囲へ入れ、
削除不能なら構造化 reason に残せ。**

### F-5 (レビュー A の C-05) — 新規テストが自己参照 oracle になっている

`assert rejection["not_evaluated"] == list(cli._EARLY_CLOCK_REJECTION_NOT_EVALUATED)` は
実装定数を期待値へ差し込んでいるため、定数から項目を削っても緑になる。**直せ。**

- `not_evaluated` は**テスト側の literal list** と比較する。
- reason は membership でなく exact 比較にする。
- early 拒否テストで `quality.status == "rejected"`、`tolerance_pct` の literal 値、
  `candidate.json` / `publish.json` / `registered` の不在も exact に固定する。
