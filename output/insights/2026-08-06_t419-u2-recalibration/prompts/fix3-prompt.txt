- `stat(path)` と `unlink(path)` が分離した **TOCTOU** であり、
- その危険な cleanup を**共有 helper の全 caller へ新規に拡大**している。

これは C-03 が指していた orphan 問題より重い risk である。**縮退させよ。**

### 具体的に行うこと

1. `_write_exclusive` を**本 wave 以前の挙動へ戻す**。
   - helper 自身は `stat` も `unlink` も行わない。他 caller の挙動を 1 つも変えない。
   - 失敗時にファイルを消す責務を helper に持たせない。
2. 一時ファイルの掃除は **publish 経路 (`registered/` の `.publish-*.tmp`) だけ**に閉じる。
   その経路が消してよいのは、本 wave 以前と同じく
   「`_write_exclusive` が正常 return した (= 自分が `O_EXCL` で作成し書き切った) temp を、
   その後の rename が失敗したとき」だけである。**この条件は本 wave 以前と同一にすること。**
3. `_write_exclusive` の**書込み・fsync が失敗した場合**は、消さずに
   **構造化した理由として残す** (orphan の path 名を含む reason または診断)。
   消しに行って TOCTOU を作るより、残して申告する方を選ぶ。
4. 上記に対応するテストを直す/足す。
   - 作成前に既存 file / symlink があるとき、それが**保存される**こと (2 巡目で追加済みなら維持)。
   - 書込み失敗時に orphan が**残り**、かつその事実が構造化して報告されること。
   - rename 失敗時に temp が掃除されること (本 wave 以前と同じ)。
   - **`_write_exclusive` の他 caller の挙動が変わっていないこと**を固定する検査を 1 本入れよ。
