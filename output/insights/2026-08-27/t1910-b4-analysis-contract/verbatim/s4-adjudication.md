# 段 4 裁定 — [T-1910] 分析契約の一括凍結 + [T-1913] 実行責任者

親が段 2 plan と段 3 の 2 レンズを real / refuted、採用 / 不採用、scope 内 / 外で裁定する。

## A. 中心の争点 — 「着地させない」を採らない

段 2 plan の総括「D1082 の差分はまだ着地させない」は **refuted (不採用)**。

- レンズ A (E1) が独立に同じ結論に達した。「対象 driver と軸が埋まらない」ことは D1060 が
  逐語で記録済みの既知事実であり、**その後に**ユーザーが D1082 で一括凍結を裁定している。
  裁定時の未見事実ではないので `DW-S04` の停止事由に当たらない。
- レンズ A (E2) の切り分けを採用する。**「裁量の凍結」と「凍結済み規則の機械適用による具体化」は
  別物**である。D1082 自身が「pilot から n を後で導出する」形を許しているので、この区別を
  認めないと D1082 は内部的に実現不能になる。

## B. 採用する所見 (real、scope 内)

1. **(レンズ A C6 / P6) pilot を使わない。** block score が `{0, 1/2, 1}` に限られるため分散は
   分布によらず `1/4` 以下である。この最悪値を事前固定すれば **pilot なしで n が今決まる**。
   pilot を残すと「n を小さくできる」自由度が残り、それは D1082 が閉じようとしたものである。
   → **分散上限 = 1/4 を凍結し、pilot を設計から外す。** D1082 は pilot を許すが要求していない。
   将来 pilot を入れる場合も供給できるのは分散上限だけ、と本文へ書く。
2. **(レンズ B 3) 部分着地を「凍結」と書かない。** 4 項目を同じ変更単位で実在させる。
   B-1 により n は数値化できるので、母集合以外の 3 項目は本 commit で実体を持つ。
   母集合は**規則を凍結**し、その規則が一意に出力する manifest の記入だけを後へ残す。
   この区別を §5.1.1 と §9 に明記する。
3. **(レンズ B 4) primary の判定は §7.1 の 4 分類を優先する。** `A` と p 値だけで成立にできる
   草案は不可。treatment 未発火・off 汚染・protocol violation を入力契約に入れ、
   1 件でもあれば成立にしない (判定不能へ倒す) 規則を凍結する。
4. **(レンズ A C1 / E2) 母集合は全域規則として凍結する。** manifest の生成・完全性・
   canonical 順序・全 attempt 保持・追加削除並べ替えの禁止までを含める。
   hash を記録するだけでは不足、という指摘を採る。
5. **(両レンズ) §0 に複合セルの狭い例外を置く。** `実行責任者 = thawk105、開始時刻 = 未記入` は
   機械的には fail-closed だが、§0 の「未記入の欄には placeholder 語だけを置く」と文字どおりには
   衝突する。行単位の例外を明記する。
6. **(レンズ B 6) §9 の追記は既知結果表の直後に置く。** 並行 wave (`dev-wave-t1769-b4-wiring-probe`)
   が §10 冒頭を編集する可能性があり、diff の context を離す。
7. **(レンズ B 7 / レンズ A C6) `2^n` 全列挙と書かない。** 本統計量の帰無分布は閉じた形を持つ
   (tie でない block だけが label 交換で値を変えるため、非 tie 数 `m` の二項分布に一致する)。
   **非 tie block 上の厳密符号検定**として書く。列挙不能の問題は消える。
8. **(レンズ A C6 / B 7) n の導出は正規近似であることを明記する。** 厳密検定の検出力保証その
   ものではない、と限定を本文へ書く。
9. **(レンズ B 5) 既存 §5.1 の n bullet を更新する。** 分散上限を事前固定し pilot を使わないことを
   同じ bullet へ書き、「B-4 データを含まない」との整合を明示する。

## C. 裁定した設計択一

- **最小重要効果 = 確率優越 `A_min = 0.60`** (レンズ A C5 の推奨を採る)。
  本書の estimand は狭い機序主張であり (§2.1)、「大効果」を主張する実験ではない。
  `0.71` は net win 42 percentage point に相当し、慣用的な大効果分類をこの estimand の
  重要性へ流用することになる。`0.60` は net win 20 percentage point。
  **この値は §9 の既知結果・pilot・算出した n・予算のいずれからも導いていない。**
  実行可能性で選んでいないことは、`0.60` の方が `0.71` より要求 block 数が**多い** (155 対 36)
  ことで示される。実行可能性を理由に `A_min` を上げることはしない (レンズ A C5 の禁止に従う)。
- **n = 155** (`A_min = 0.60`、分散上限 `1/4`、片側 `alpha = 0.05`、検出力 `0.80`)。
  この規模は総計測予算を超える見込みが高い。その場合は §5.1 の既定どおり
  **記述統計に留め有意性を主張しない**。この分岐は結果を見る前に宣言する。
- **primary outcome の順位規則**は段 2 草案を採る (certified > rejected/aborted > missing、
  非 certified 同士は tie、certified 同士は共通 parent 基準の利得差を floor で tie 判定)。
  §4 の「reject に fitness を付けない」に反しない。
- **参照点**は共通 parent snapshot 基準の利得差とする (arm 内前後の別基準を使わない)。

## D. 不採用 / scope 外へ送る所見

1. **(レンズ A E4) 実装を同じ変更単位に入れる案 — 不採用 (scope 外)。**
   raw→status adapter、manifest 完全性 consumer、primary 関数の実装、conformance fixture は
   `DW-G04` の発火 gate を満たさない — B-4 の outcome が 1 件も存在せず、発火する artifact path も
   計測 ID も書けない。規律 5 (段階導入) に反する。
   **代わりに**、この契約が閉じないこと (実装と conformance consumer の不在) を §5.1.1 の中へ
   明記し、§5 の primary セル解除の条件を §5.1 へ書く。
   実装は別 wave の候補として worklog の次の一手へ新規登録する。
2. **(レンズ A E3 / B 2) 参照セルが後から空洞化される懸念 — 部分採用。**
   実走経路では `verify_b4_admission_record` が**文書全体の content_sha256 を HEAD blob と
   byte 一致で照合する**ため、参照先 §5.1.1 の bytes は同じ record に束縛される。
   参照セルが指す先だけを黙って差し替える経路は、admission record を伴う実走では成立しない。
   この根拠を §5.1 の解除条件へ書き、hash を値セルへ二重に書く案は採らない
   (bytes 級の一致自体を関門にしない方針、および §0 の「値セルに説明文を書かない」に従う)。
3. **(レンズ A E5) 値・順位を裁定へ返す案 — 部分採用。**
   D1082 は凍結の時期と依存方向を裁定したもので、値そのものは裁定していない。
   しかしユーザーは「裁定待ちを理由に止まらないこと」と明示している。
   **本 wave で固定し、選定根拠を同じ変更単位へ残し、最終報告で見直し余地を明示する。**
   文書は発効前 draft であり、§1 に従い発効前の変更は履歴を残して可能である。
4. **母集合セルを参照文字列で埋める案 — 不採用。** manifest が未生成の段階で埋めると、
   将来他の欄が揃ったとき中身の実在なしに admission を通す経路になる (レンズ B 2)。
   **母集合セルは `未記入` のまま残し、§5.1 の解除条件を manifest path + sha256 + 行数に締める。**
