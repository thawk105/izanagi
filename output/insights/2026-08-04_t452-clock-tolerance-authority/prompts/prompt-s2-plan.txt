## 課題

`attestation_profile.effective_clock.tolerance_pct` には現在**権威の出所が無い**。較正取得 CLI の
引数として人が手で渡し、境界検査は (0, 100] だけである。100 を渡せば取得時の自己整合 gate も実行時の
attestation 述語も実質的に通ってしまう。ユーザー裁定により、権威は **policy 固定値の方向**で設計する。

**この許容幅を policy として一元的に権威づける設計案**を、実装可能な file:line 粒度で起草せよ。
あなたは実装しない。設計案はユーザー裁定パッケージの素材になる。

## 設計案に必ず含める節

1. **権威の所在** — policy 値をどの module のどの識別子に置くか。単一定数か env_tag ごとの表か。
   既存 `env_contract.REGISTRY` に載せる案と独立 policy module 案の比較を、それぞれの
   「誰が書き換えられてしまうか」で評価する。
2. **固定値と根拠** — 具体的な数値を 1 つ推奨し、その根拠を述語の**意図**から導く
   (実測 smoke 分布からの逆算は裁定で採らない方向とされている)。値を変えるときの手続きも書く。
3. **observed sentinel との衝突** — expected と observed が同じ schema 型を共有しており、observed は
   `tolerance_pct=100.0` を「自前の policy を持たない」印として書いている。schema の上限を狭める案と
   この sentinel は両立しない。どう解くか (型の分離 / optional 化 / sentinel の意味の明示化など) を
   複数案で比較し、既存 artifact の bytes と consumer への影響を各案について書く。
4. **恒真化を塞ぐ機械** — 値域を狭めるだけでは publish 経路の手入力権限が残ることを踏まえ、
   どの層 (CLI 検証 / schema / 取得時 gate / registry 不変条件 / 実行時 guard) に何を置くか。
   **各機械について「これを壊す変異を 1 つ書き、それを殺すテストは何か」を必ず対にして示す。**
   恒真な検査 (謳うだけで発火しない assert) を作らないことを自分で検証せよ。
5. **移行** — 既存の登録済み較正は自分の述語を通らない (median から +46.641 % の標本が 1 個)。
   pin 閉包 (env_contract の path+sha256、silo ladder evidence の binding、テスト 3 site、
   既知例外 1 件) を踏まえ、[T-419] U-1 (probe 実験) → U-2 (較正再取得) との**順序**を明示する。
   本設計を先に入れると再取得が塞がる／塞がらないのどちらかを、コードの実際の経路で判定して書く。
6. **反証テストの設計** — positive control (参照が自分の判定を通る) と negative control
   (権威を迂回した値が拒否される) を、file 名とテスト名の粒度で列挙する。
7. **却下した案** — 述語を緩める案・attestation を外す案・issuer の独立実装を canonical へ統合する案は
   裁定で却下済みであり、再提案してはならない。それ以外に検討して落とした案を理由付きで書く。
8. **未決の設計択一** — ユーザー裁定に返すべき論点を `U-1`, `U-2`, … の形で列挙し、各々に
   選択肢・有利材料・不利材料・あなたの推奨を書く。
9. **成果物影響** — 1〜8 の各主要項目について、「実装しなかった場合に certified な選択結果・
   材料レポート・試行台帳のどの値／受理集合／参照がどう変わるか」を 1 行で書く。

## 制約

- コード・テスト・docs を編集しない。git を変更しない。
- pytest の緑は要求しない (書込可能 tmp が無い環境である)。**静的検査でよい。**
  テストの実測は親が行う。走らせていない検査を「通った」と書いてはならない。
- 参照は必ず `path:line` の形で書く。行番号を憶測で書かない。読んだものだけを引く。
- 述語を緩める方向・attestation を外す方向・受理集合を広げる方向の提案をしない。
- 出力の最後に必ず `## 総括` 節を置き、推奨設計を 5 行以内で述べる。
