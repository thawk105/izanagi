## 2. いま本当に塞いでいるもの — ここが裁定点

(ii)(iii) を成立させる唯一の計測が **pilot** である (D229 決定 (6) がそう設計した)。
その pilot は今、次の連鎖で止まっている。

```
validator を作れない
  ← 発火条件 (ii)(iii) 不成立
    ← pilot が 1 本も走っていない
      ← pilot_submission = forbidden (canonical decision の運用状態)
        ← 追補 P の凍結が済んでいない
          ← 「公表台帳の実体の確定」待ち = 公表層実装 wave の裁定事項
            ← 公表層の残り実装 (R1/R2) は [T-793] で D320 により保留終端
              (理由: 「公表層の残り実装は論文粒度の主張に不要」)
```

**最下段に注意していただきたい。** D320 はユーザーが 2026-08-12 に「論文に要るのは
生成物 + 概ねの時期であり、bytes 級 provenance の機構は既定で見送り」と決めたものである。
その見送りの対象が、いま [T-338] の実装を止めている連鎖の根に座っている。

**ただし親が確定できなかった点を明示する。** 「公表台帳の実体の同定」が [T-793] の R1/R2
そのものなのか、保留終端になっていない別項目なのかは、台帳を読んだ範囲では確定できなかった。
連鎖が本当に閉じているか (= 誰も動かせない状態か) は、この 1 点で変わる。

## 3. 択一

### A. 現行境界を維持し、[T-339] の前段だけ先に起票する

D162 / D229 / D264 / D282 / D291 / D292 と [T-339] 境界をそのまま守る。次の wave では
権威を持たない producer と attempt registry の前段だけを作る (D229 決定 (6)(7) はこれを禁じていない —
レンズ B が親の「実装可能 slice 0 件」を部分的に倒した)。validator / consumer は
pilot が (ii) を満たしてから起票する。

- 得るもの: 裁定を 1 つも変えずに前へ進む。
- 失うもの: 第 2 節の連鎖は解けないので、**validator にはこの経路では到達しない**。

### B. [T-339] を [T-338] へ戻し、`producer → pilot → validator/consumer` を 1 つの scope にする

D229 は順序を守る限り supersede を要求していない。依頼が「[T-339] は実装するな」と切った境界を
外し、全順序を 1 本の系列として回す。

- 得るもの: validator まで届く道筋が引ける。
- 失うもの/条件: **pilot 投入の解禁は別途 canonical decision が要る** (第 2 節の連鎖)。
  これが解けない限り B も同じ場所で止まる。

### C. validator を pilot より先に置く (依頼の文字通りの実装)

D162 決定 (10) と D229 決定 (6) を明示的に supersede する。

- 得るもの: 依頼どおりのコードが今 land される。
- 失うもの: validator が読む raw receipt の schema を producer が 1 つも出していないため、
  合成 fixture だけで緑になる未結線 leaf になる (D147 決定 (3) / D163 決定 (1) が却下した型)。
  pilot 後に記録項目が確定した時点で作り直しになる — これは D229 決定 (6) が
  「残る risk」として名指しした事象そのものである。**親は推奨しない。**

### D. 発火条件そのものを D320 の線まで下げる

いま塞いでいるのは自作の証拠水準であり、その一部は既にユーザーが「論文に不要」と裁定した
領域と重なっている。具体的には次の 3 つを個別に下げられる。

- **D1.** 発火条件 (ii) の 4 項のうち **attestation** を落とす。D320 は「attestation 証跡 schema の
  見送り」を先例として自ら挙げている。**環境タグは落とさない** — D320 が
  「測定の公正 (環境契約タグ)」を対象外 (不変) と明記しているため。
- **D2.** pilot 投入の解禁条件から「公表層実装の完了」を切り離す。公表層は D320 で保留終端であり、
  そこに待たせ続けると RF 系列全体が無期限に止まる。
- **D3.** D229 決定 (6) の 4 段階を、プロトタイプ基準の 2 段階 (`producer+pilot` → `validator+consumer`)
  へ縮める。

- 得るもの: 連鎖の根が外れ、A でも B でも validator まで到達できる。
- 失うもの: 正例 artifact の証拠水準が下がる。**ただし規律 2 は下げない** —
  D320 自身が verifier / admission / 変異検査を対象外 (不変) としており、本裁定もそれに従う。

## 4. 親の推奨

**D1 + D2 を先に裁定し、その上で B を回す。**

理由は 3 つ。

1. **A も B も C も、第 2 節の連鎖を外さない限り同じ場所で止まる。** 択一の形を守って
   A や B を選んでも、pilot が投入できなければ (ii) は永久に不成立のままである。
   したがって最初に裁定すべきは順序でも scope でもなく、**解禁条件**である。
2. **C は依頼どおりに見えて、依頼の目的を果たさない。** 依頼が求めたのは
   「報告値ではなく raw receipt から再計算する」経路である。raw receipt を出す producer が
   存在しない状態で validator だけを置くと、検証対象が合成 fixture しかない —
   それは「報告値を採らない」ことの証明にならない。
3. **D は証拠水準の引き下げであって、正しさゲートの緩和ではない。** 落とすのは attestation 証跡と
   公表層の束縛であり、verifier / admission / 変異検査・環境契約タグ・測定の公正は一切触らない。
   規律 2 はこの裁定の対象外である。

なお **D3 は推奨しない。** 4 段階を 2 段階へ縮めると、pilot の記録項目が validator の要求を
取りこぼしたときに pilot ごとやり直しになる。D229 決定 (6) が記録項目の確定を単独 gate に
したのはこの risk を切るためで、そこは費用に見合っている。

## 5. 裁定が済んだ後、最初に投げられる形

- **D1 + D2 を採る場合:** 次の wave は「pilot 投入の解禁 canonical decision を起草し、
  発火条件 (ii) から attestation を外す decision を同じ変更単位で land する」。docs のみ。
- **その次:** 「RF producer + attempt registry の前段を実装する」(コード)。
- **その次:** pilot 実走 (計算ノード)。ここで初めて (i)(ii) を同一計測で満たす artifact が出る。
- **その次:** 「独立 validator + consumer」= 依頼が求めた実装。発火条件 3 点が揃った状態で起票する。

## 6. 本 wave が確定させたこと (裁定を待たずに使える)

1. 発火条件の項目別現況 — (i) 成立 (`892042.nqsv`)、(ii) は 4 項中 `env_tag` と `attestation` の
   2 項が 0 file hit で不成立、(iii) は RF consumer 0 件で不成立 (`trigger-audit.md`)。
2. 実装候補 6 件の却下理由 (`s4-adjudication.md`)。
3. **J は「規則」と「選択済み値」を分けねばならない。** 規則 (`J_max=13`、候補集合、選択式、
   結果後の変更禁止、pilot slot `[1..8]`、main の slot 数と J の一致、予備の非算入) は D282 が
   digest 凍結済み。未存在なのは pilot から導かれた選択済み J と、それを本走最初の qsub より前へ
   束縛する実 validator / admission だけである。
4. **J の事後追加を塞ぐ 4 つの必須 kill 変異**を事前登録した (`s4-adjudication.md`)。
   D229 決定 (8) の 3 件に追加する形で、将来の validator wave が発火時に kill すること。
