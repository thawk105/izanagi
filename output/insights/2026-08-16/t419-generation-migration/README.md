## 何が分かったか (要点だけ)

1. **裁定の 2/3 は既に land 済みだった。** D143 (b) の「較正を取り直す」と
   「取得時受入検査」は実装済みで、未実施は「登録し直す」= 活性化だけである。
2. **活性化は実行時の受理挙動を変えない。** canonical clock 述語は期待列の中央値だけを使い、
   帯検査は観測列にのみ適用する。第 1 / 第 2 世代とも中央値 2101.0・tolerance 2.0 で
   受理帯 [2058.98, 2143.02] が完全に一致する。
3. **`effective_clock.method` の比較は恒真ゲートである。** 期待側 (素朴法) と
   観測側 (巡回方式) の実体不一致が pass として receipt に残っていた。
4. **活性化は既裁定に反する。** D272 と較正・凍結権限束の設計は、環境世代と凍結世代の
   lockstep と、承認 / 発効がともに人間であることを確定している。
   同設計は段 0 が未完了で、ユーザー裁定待ちを 1 件抱えている。
5. **pin 前進が凍結証拠の完全検証を赤にする型は、既に 1 度実現していた。**
   環境世代の前進で起きる同型と合わせ、独立 2 例が揃った。
