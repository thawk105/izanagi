## ファイル名の位置文法 (P1 の置換、A3 + B6 を閉じる)

判別鍵は**先頭ゼロ**である。日付 token は `0722` のように先頭ゼロを持ち、entry 番号は
`[1-9][0-9]*` で先頭ゼロを持たない。これにより 4 桁の entry 番号 (1000 以上) も日付と区別できる。

`worklog-` を剥いだ残りを `-` で分割し、次の順に分類する。

1. 先頭 token が `phase<数字>` でない → **entry 範囲を名乗らない** (除外)。
   合成 fixture (`worklog-synthetic.md`、`worklog-new.md`、`worklog-a.md` 等) はここ。
2. 2 番目の token が MMDD (`(0[1-9]|1[0-2])(0[1-9]|[12][0-9]|3[01])`) でない → **名乗らない** (除外)。
   `worklog-phase1-2.md` (Phase 1〜2 の意味) はここ。**この条件が無いと entry 2 と誤読する。**
3. 2 番目以降の token がすべて MMDD → **日付だけの旧 archive** (除外)。8 件。
4. 2 番目以降が MMDD と entry token (`[1-9][0-9]*`) だけで構成され、entry token を 1 個以上含む
   → **採番 archive** (検査対象)。entry token は出現順に `lo`、`hi` とする (1 個なら `lo`=`hi`)。
5. 上記のいずれでもない (MMDD で始まるのに壊れた token を含む。例 `...-106-110-copy`)
   → **malformed filename として赤**。

phase 番号は `phase<数字>` で一般化するので `worklog-phase4-0901-600-605.md` は 4 で検査対象になる。

## README「現在の収容物」行の文法 (B1)

物理行でなく**論理項目**で読む。`- ` で始まる行から、次の `- ` かこの節の終わりまでを 1 項目として
畳む (継続行は行頭空白で始まる)。項目内で次を探す。

```
— worklog の <日付1> (<lo>) [〜 [<日付2> ]( <hi> )] 分
```

- `<日付1>` は `YYYY-MM-DD`。`<日付2>` は省略可、`YYYY-MM-DD` と `MM-DD` の両方を受理する。
- `〜` の前後空白は任意。`分` の後ろの注記は自由。
- `<hi>` 省略時は `hi = lo`。
- **採番 archive の行がこの文法に合わなければ免除せず赤**にする (P2 の修正)。
- 採番でない archive・`audit-*`・墓標行は対象外。
- **postcondition (A4)**: 実在する採番 archive の集合と、この節で正規行を持つ採番 archive の集合が
  一致し、各 1 回だけ現れること。

## 検査の内容

### (i) carry 参照先の実在

- 対象書式は full-match の 2 つだけ。`- [T-NNN] (N)` と `- [T-NNN] 変わらず ((N) 参照)`。
- 全域番号 universe = 現行 worklog の全 entry 番号 + **採番 archive**の全実体 entry 番号。
  名乗らない archive の内部番号は universe に入れず、その内部の carry も検査しない。
- 保持は**参照先番号ごとに 1 件**の `(path, line, task_id)` だけ (B2)。
- 同じ番号が 2 か所以上に実在したら、carry とは別種の赤にする。重複番号を指す carry に
  宙吊り診断を重ねない。
- 採番 archive の読取・構造抽出が 1 件でも失敗したら、宙吊り判定を行わず停止理由を 1 度だけ出す。

### (ii) archive の主張と実体

- 実体 entry 集合は既存の entry title 抽出から作る。
- filename 主張と README 主張を**それぞれ独立に**実体集合と突き合わせる。
- 一致条件: `lo <= hi`、範囲外の実体番号が無い、欠番が無い。min/max だけの一致では通さない。
- 採番 archive 内に番号なし H2 / `(続き)` があれば別の赤 (A5 前半)。

### コスト不変条件

新しい `glob` / `iterdir` / `read_text` / `open` / `stat` を 1 つも増やさない。既存の archive 走査
loop と既存の README 読取の中で完結させ、2 pass 間はメモリ値で繋ぐ。保持量は履歴に比例させない
(carry は distinct target 数、universe は entry 数)。

## ユーザーへ返す裁定パッケージ

### R-1 — carry の「実体保存」まで検査を広げるか

現行の裁定 (115) は「参照先エントリが**実在するか**」までである。実測すると、参照先エントリは
実在するのに**そこに同じ ID が無い** carry が 4 件ある。

- `docs/archive/worklog-phase3-0731-77.md` のエントリ (77) が
  `[T-208]` `[T-209]` `[T-210]` `[T-211]` を `変わらず ((73) 参照)` と書いている。
- これらの実体はエントリ **(74)** で起票され、エントリ (76) は正しく `((74))` を指している。
  (73) は実在するが、この 4 ID を 1 つも含まない。**参照番号の書き誤りである。**

択:

- **(a)** 保存則を「参照先エントリの次の一手に同じ ID がある」まで広げる。受理集合はさらに狭まり、
  上記 4 件が赤になる。archive は凍結なので、訂正注記を足すか erratum で例外登録するかの
  運用手当てが同時に要る。
- **(b)** 今回は実在検査に留め、4 件は内容側の欠陥として記録だけ残す (親の既定)。
- **(c)** 広げるが、既存 4 件は「凍結済みの既知違反」として台帳へ登録し、新規発生だけを赤にする。

### R-2 — `spool_fold.py` 直接 CLI の postcondition

`check_docs.py` を呼ばない。

択:

- **(a)** T-329 は公式 land の postcondition gate と明記し、直接 CLI の postcondition は別タスクへ送る
