## 裁定

1. **投稿区分:** VLDB (PVLDB Vol.20 = VLDB 2027) は EA&B トラックを第一候補にする。LLM が勝たない結果も主要成果として扱う (推奨どおり)。
2. **主張の射程と TPC-C:** 推奨していた「当面は point read/write に限定し TPC-C は後回し」には、ユーザーが疑義を示した (「後回しにする理由はわからない」)。
   → 親が推奨を改訂し、**TPC-C を必須に入れる**。
   - 段 1: NewOrder / Payment の混合 (既定比で 88%、点読み・点書き・insert のみ) を正しさ認定の対象にする。
   - 段 2: Delivery / OrderStatus / StockLevel の範囲読み (`tx.scan`) を含む全 5 取引へ広げる。
   反対が無ければこれで進める (改訂推奨。ユーザーの明示確認はまだ取れていない)。
3. **探索空間:** LLM が関数単位でコードを書ける合成空間を開く。現行の編集面の制限 (合成枝の中身だけ・#include / 関数 / 型の追加禁止・3 file) を広げてよい。**正しさゲートは不変** — anomaly は即 reject、trace は compile 時に除去、毎回検証して構造化フィードバックを返す (推奨どおり)。
4. **計算費用: 実験の計算投入は、都度 node 時間の見積りを示してユーザーの確認を取る。** ユーザー発話「計算費用は私に確認を取って欲しい。重大な話ですそれは。」
   試走・本比較の一括承認はしない。
   **確認ライン (2026-09-21 21:3x ユーザー追補、逐語):** 「計算予算を2ノード時間以上使うものは確認が欲しいな。つまりこれは2ノードで一時間ずつか、1ノードで2時間か。4ノードで30分ずつか。」
   → 1 つのタスク (1 本の実験、または 1 本の wave) で投げる job の合計が **2 node 時間以上**なら、投入前に見積りを示して確認を取る。2 node 時間未満は確認不要。
   開発の検査 (受入・焦点走・変異) も同じ線で数える (親の解釈)。
