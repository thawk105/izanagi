## 項 1 — 既裁定誤引用

(i) の維持は支持するが、R2 との不可分な採用は支持できない。D325 の逐語は「その走行のうち 1 本を単独走にせよ」「追加 dispatch は原則 0 本」であり、新 runner が唯一とは書いていない。
却下対象は「段 6 受入へ焦点走を 1 本足す」と「受入と同一 job へ畳んで」で、別 job 全般の禁止へ広げるのは誤引用。
延べ22中2・単独走4本は資料どおり。ただし緑は3本、残り20 file の他経路は未確定で、最大+20 job は既存走を組み替えない条件付き試算である。
(ii) の費用説明は妥当。DW-O26 全文 literal、独立 fixture、単独走文の削除を拒否する M8 があり、Codex author と pin・テスト追随が必要。「包含なら検出経路が無くなる」は過大で、失うのは単独 process の検出力である。

## 項 2 — 根拠不足

焦点走どうしの同 job 化は D325 の却下対象ではないが、同 D は「往復の除去は本件とは別に評価する」と留保しており、採用済みでもない。
現行の焦点走経路は一つの argv を一つの pytest command に渡す。複数 invocation と個別 env の表現・実行・結果記録への対応は実在する改修で、単なる flag 追加ではない。
K1 の27秒＋条件付き22秒、K3 の735秒は過去の比較値であり、§8 が未測定とする将来待ち・完了時間短縮を保証しない。
既存走の置換で満たせない残件数と、最小改修の範囲・同条件での効果を示してから採否を決めるべき。「足さなければ+20 job」は撤回する。

## 項 3 — 同意

(a) の局所修正を支持する。README の SKIP 規約に対し、`test_check_docs.py::_run` は `Skip(Exception)` を ERROR に数える。pytest 側の SKIPPED と食い違い、完全一致を要求する final は MISMATCH となるため、偽 KILLED という認定ではない。
ただし「1 file」は当該 harness に修正を限定する場合だけ成立する。静的走査では、`_run` が汎用 Exception を捕捉し Skip を区別しない file が47本あり、`test_login_headroom.py` 等にも同じ構造がある。
これら全部で Skip が実際に到達するとは未確認。今回は当該 file の修正と明記し、全体の乖離解消やメタゲート追加まで約束しない。

## 項 4 — 反対

(b) 別途調査を採る。D325 の独立2例は「全走の緑では単独の健全性が分からない」問題で、今回は受入が検出するため、同じ件数だけで同じ契約新設を要求することはできない。
一方、資料は改訂費用と局所的な探索改善の効果を測っておらず、「改訂費用が実害を上回る」「全 wave に21〜735秒が乗る」は立証されていない。
2例の目録 test を既存探索で拾える局所策と追加実行時間だけを調べる。無条件の集合拡張は採らず、根拠のない「3例目」待ちも置かない。

## 項 5 — 同意

(a) を支持する。走行中の HEAD 変更、投入前の untracked、集合への契約 module 混入は、既存手順と親の確認補助で扱う範囲にある。
58＋100秒と47＋477秒は異なる反実仮想なので合算しない。投入前の拒否条件を新設しても走行中 commit は防げず、追加 gate を推す根拠にならない。
既存の実走・受入・完全一致条件を維持する限り、規律2・3・5を弱めない。

## 項 7 — 同意

## 項 8 — 既裁定誤引用

現状維持という結論は支持するが、起草の理由づけは直すべき。D2045 の逐語は「環境 fingerprint…」を束縛し、「環境 fingerprint で区画する」であり、理由欄に列挙した環境差の説明はない。
「区画の差が…git の挙動を変えうるため」という文は今回の診断 README §8 の説明で、D2045 自身の理由として引用してはいけない。
また、起動 env を実際に統一し全13 bindings の照合を維持する案は、束縛を外す案とは異なる。「統一は意味を弱める」と断定せず、救済件数と等価性が未確認だから見送ると書き換える。

## 項 9 — 同意

ユーザーへの push 承認提示を支持する。`origin/main..9a24372c3` は22 commit で、索引時点の検算は一致した。
確認時の `origin/main` は `21641fee7`。前回承認 `5efd69367` はその祖先で、そこから4 commit 進んでいる。
ただし現物の HEAD は `925af17f5` へ進み、未 push は26 commit。提示時点で件数と承認上限 SHA を更新し、以後の commit は含めない。AI は push しない。
