## 所見

1. **real / must-fix — unsigned宣言だけでは符号付き演算とshift UBを除けない。**
   **箇所：R §2.7、F決定4・理由。**

   32-bit `int`の対象では、次は許可された型・演算子だけで書けます。

   ```cpp
   uint32_t f(bool b) noexcept {
     return (b << 30u) * (b << 30u);
   }
   ```

   `b`は`int`へ昇格します。`b=true`なら積は`2^60`となり、**uint32_tへのreturn変換より前にsigned overflow**です。また、`(b - true) << 1u`は`b=false`で負の左辺となり、C++17ではUBです。右辺の`u`は左辺をunsignedにしません。[C++17整数昇格](https://timsong-cpp.github.io/cppwp/n4659/conv.prom)、[shift規則](https://timsong-cpp.github.io/cppwp/n4659/expr.shift)。

   さらに「複合代入」を許しながら、右辺制約は`/ % << >>`にしか書いていません。`s.x /= c.attempt;`や`s.x <<= c.rand;`にも同じ制約を適用するのか未確定です。

   修正は、算術・bit演算の**各部分式の型**をU32/U64へ閉じ、Boolの算術使用には事前変換を要求し、複合代入にも右辺制約を適用することです。結果全体へのcastでは遅すぎます。

   **放置時の影響：UBを持つ候補が受理対象に残り、certified候補の性能値と「構造的に安全な空間」という報告が食い違う。**

2. **real / must-fix — 初期化子必須は、初期化前読出しの排除ではない。**
   **箇所：R §2.7、F理由。**

   例えば、先に定義した値渡しhelperを使う`uint32_t x = helper(x);`は、初期化子を持ちながら初期化前の`x`を読みます。局所宣言の自己参照禁止は記載されていません。

   単純な自己初期化は警告され得ますが、警告は完全な初期化証明ではありません。GCC自身も未初期化警告の最適化依存と見逃しを説明しています。[GCC警告仕様](https://gcc.gnu.org/onlinedocs/gcc/Warning-Options.html)。この環境で個々の例が単独TU検査を通るかは未実測です。

   構文検査側で「初期化子の検査中は宣言対象を参照可能にしない」と固定すれば、予定済みの検査の中で閉じられます。

   **放置時の影響：初期化安全性が文法ではなくcompilerの警告能力に依存し、受理集合とUB排除の説明が変わる。**

- **C下側0.36 h：** 生死確認6 sessionだけの値です。負例と受入を含む合計ではありません。同じ換算方法と受入1.15 hを仮定するなら、`(6+8)×217/3600+1.15=1.993889 h`です。これは新しい下限ではなく、現表の両端が同じ費用項を足していないことの確認です。
- **確認境界：** ユーザー裁定は「2 node時間**以上**」。R §9・Fは正しいですが、R §0/6の「超える」は厳密には一致しません。

量化の照合では、「段3の3本ともadopt_with_conditions」は支持されます。一方、「3レンズが状態拡張の害について一致」「CCヘッダ追加で列挙した負例が通る」「初期化子があれば未初期化を構造排除」は支持されません。

## 判定

**NO-GO — 現稿を、再設計なしに次waveへ渡せる受理契約として固定するには不足があります。**

修正対象は、既に予定した文法・接続・probe・見積りの具体化です。新しいsanitizer基盤、公平性gate、台帳の追加を求めるものではありません。
