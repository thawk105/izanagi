## 所見

1. **real / must-fix — `/ %` の結果型が誤っている。R §2.7 の型表、F 決定4。**

   C++17 の `/ %` は通常の算術変換後の型を結果型にします。「左辺の型」は一般には成立しません。`/=`・`%=` は演算後に左辺型へ変換して格納するため、通常演算と同じ一行にまとめられません。[C++17 乗除算規則](https://timsong-cpp.github.io/cppwp/n4659/expr.mul)、[複合代入規則](https://timsong-cpp.github.io/cppwp/n4659/expr.ass)。

   例えば対象の通常の32/64 bit構成では、

   ```cpp
   uint64_t f(uint32_t x) noexcept {
     return (x / 1ull) << 32u;
   }
   ```

   実 C++ の左辺は64 bit unsignedなので合法です。しかし表どおりなら除算結果を U32 とし、shift を拒否します。逆に `std::min(x / 1ull, x)` は表では同型と判断しても、実 C++ ではテンプレート引数推論が一致しません。

   `/ %` と `/= %=` の型規則を分け、literal の型を C++17 の接尾辞・値から決める必要があります。また、同じ64 bit幅でも `unsigned long` と `unsigned long long` は別型です。min/max の「同じ型」が幅だけを意味しないことも固定してください。[整数 literal](https://timsong-cpp.github.io/cppwp/n4659/lex.icon)、[min/max の署名](https://timsong-cpp.github.io/cppwp/n4659/alg.min.max)。

   **放置時の影響：合法な候補の構文拒否と TU 段への誤通過が実装解釈で変わり、受理集合・構文通過率・reject 内訳が変わる。**

2. **real / must-fix — 保存域の規則が衝突し、文法にも未確定箇所がある。R §2.5・2.7・8、F 決定5。**

   R §2.7 は上位宣言として `constexpr T name = 定数式;` を許しています。しかし namespace scope の constexpr 変数も静的記憶域を持ちます。R §2.5 の禁止には括弧書きの許可が併存し、F 決定5には例外がありません。「追加の持続する**可変**状態は禁止、namespace constexpr は許可」などに統一すれば済みます。[C++17 静的記憶域](https://timsong-cpp.github.io/cppwp/n4659/basic.stc#basic.stc.static)。

   次 author が選択を迫られる箇所も残ります。

   - 宣言の `T`・「許可型」の集合が明示されていない。scalar 型、列挙型、局所 `LockResponse` の可否を列挙する必要がある。
   - void 補助関数の定義は許す一方、文の一覧に `helper(s);` の呼出し文がない。許可リストを厳密に読むなら拒否になる。
   - 補助関数の引数名は自由に見えるが、メンバ読出しは `s.`・`c.` のみ。固定名なのか、名前解決された引数を意味する記法なのか未指定。

   **放置時の影響：同じ定数・補助関数を持つ候補が parser 実装者によって受理／拒否に分かれ、有効候補率と探索可能集合が変わる。**

3. **real / nit — 字句規則を外す自己試験の期待が強すぎる。R §3.3。**

   「代替綴りの字句規則を外した構文検査器では `bitand`・`<:` の負例が通る」は保証できません。`<:` を `[` として認識しても、後段の配列・添字禁止が残ります。単項 `bitand` もアドレス取得禁止で拒否されます。

   字句段だけを試すのか、合法な二項 `bitand` を使うのかを、既存の自己試験仕様で区別すれば足ります。

   **放置時の影響：自己試験の期待結果が不一致になるが、これだけで certified 値や受理集合が変わる具体例は確認できない。**

4. **real / nit — 状態射程の主要な帰属は正しいが、別の一括支持表現が残る。R §2.5。**

   指定された逐語との対応は成立しています。

5. **refuted / nit — 指定された旧 UB 経路は、訂正後の規則では閉じている。R §2.7。**

   | 検算対象 | 結果 |
   |---|---|
   | bool・比較結果から signed 算術 | 算術の各被演算子を U32/U64 に限定するため拒否。外側だけの cast では救済されない |
   | 列挙型・`?:`・min/max・cast | 列挙型の直接算術は禁止。同型分岐、unsigned 限定 min/max、指定先だけの cast から signed 算術への経路は確認できない |
   | shift と `<<=` | shift は右辺型で左辺を64 bit化しない。左辺幅未満という規則は正しい。ただし所見1の誤った型付けは修正が必要 |
   | 除算・複合代入 | 非零 unsigned literal 制約が `/= %=` にも明記され、変数除数・零除算を排除 |
   | 初期化 | `helper(x)` に渡す `x` も自己参照禁止の対象。メンバ既定初期化子は literal なので補助関数・`s.` を経由できない。通常の `s.` 読出しは既に初期化された骨格状態を読む |
   | return | 関数本体の最後の文を直接 `return` とする読みなら、入れ子の if/switch が抜けてもそこへ到達する。全枝 return の if を末尾に置く形は、この狭い契約では拒否 |
   | 代替綴り・digraph | 全拒否と単項アドレス取得・添字禁止を合わせれば指定の迂回は閉じる |
   | 構文検査と TU | UB 排除規則を構文側、型不一致・署名・未宣言名を TU 側とする分担は妥当。switch の初期化を飛び越す不正な case 移動も TU が拒否する |
