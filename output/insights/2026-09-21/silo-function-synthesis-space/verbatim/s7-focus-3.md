## 所見

1. **real / must-fix — 代入式の出現位置が閉じておらず、unsigned だけでも UB を作れる。R §2.7。**

   「文」では代入・複合代入を許し、「式と型の規則」ではそれらに結果型を与えています。部分式への埋込みを禁止する記述がないため、次の補助関数を受理する読みになります。

   ```cpp
   uint32_t helper(PolicyState& a, PolicyState& b) noexcept {
     return (a.m = 1u) + (b.m = 2u);
   }
   ```

   `m` を U32 メンバとし、hook から `helper(s, s)` と呼べます。代入先、被演算子型、実引数、呼出し DAG、末尾 return はすべて記載された条件を満たします。

   しかし `+` の左右の評価は順序付けられず、同じメモリへの二つの書込みになるため UB です。C++17 の代入内部の順序規則は、別々の代入式を足す場合の左右までは順序付けません。[C++17 評価順序](https://timsong-cpp.github.io/cppwp/n4659/intro.execution#17)、[代入規則](https://timsong-cpp.github.io/cppwp/n4659/expr.ass)。

   単独 TU の型・署名検査だけでは、この別名参照による UB の排除を保証できません。最小の訂正は、**代入・複合代入を独立した文だけに許し、部分式としては禁止する**ことです。汎用の別名解析や追加 gate は不要です。

   **放置時の影響：この候補を受理する parser と拒否する parser に分かれ、受理集合に UB を含む方策が入り得ます。**

2. **real / nit — literal の説明には64 bit上限の前提を補うべき。R §2.7、F 決定4。**

   C++17 の候補型リストには、`u` にも `ul` にも `unsigned long long` が含まれます。「`ull` を禁止したから現れない」という説明だけでは不十分です。[整数 literal の型規則](https://timsong-cpp.github.io/cppwp/n4659/lex.icon)。

   ただし、指定対象では `unsigned long` と `unsigned long long` がともに64 bitなので、標準整数型で表現できる範囲では次が成立します。

   | literal | 型 |
   |---|---|
   | `u`、値 ≤ `UINT32_MAX` | U32 |
   | `u`、`UINT32_MAX` < 値 ≤ `UINT64_MAX` | U64 |
   | `ul`、値 ≤ `UINT64_MAX` | U64 |

   U64 に収まらず ULL にだけ収まる値はありません。`UINT64_MAX` 超を拒否する旨を添えれば説明が閉じます。

   **放置時の影響：説明の根拠は不正確ですが、指定対象で ULL が混入して certified 選択を変える有効な反例は確認できません。**

3. **refuted / nit — 数値の結果型・narrowing に、前回の不一致は残っていない。R §2.7。**

   | 型表の行 | 検算 |
   |---|---|
   | `+ - * & \| ^`、`/ %` | U64 が一方にあれば U64、双方 U32 なら U32。通常算術変換と一致 |
   | 単項 `~ -` | unsigned の型を維持。一致 |
   | `<< >>` | 左辺型を維持。右辺が U64 でも左辺は拡幅しない |
   | 全複合代入 | 演算後に代入先型へ変換。U64→U32 は剰余。除数・shift 幅制限も一致 |
   | `=` | unsigned 間の変換は定義済み。bool・列挙型・Response の同型限定は C++ より狭い契約 |
   | 比較・論理 | 記載された被演算子から結果は bool |
   | `?:` | 同型枝という制限なら結果型は一致 |
   | `static_cast` | 指定された変換先から signed 型は生じない |
   | `std::min/max` | U32 同士・U64 同士なら型推論は一致 |
   | 自前関数の実引数 | unsigned 間の値渡し変換は定義済み。参照引数は実 C++ の const・参照束縛条件も必要 |
   | メンバ・列挙子 | 宣言型と一致 |
   | `LockResponse{action, wait}` | 第2要素を U32 に限定するので narrowing は生じない |

   `LockResponse{action, 1ul}` は実 C++ では定数値が収まるため許されますが、本契約では U64 なので拒否します。これは意図した部分言語の制限であり、型誤認ではありません。[list-initialization](https://timsong-cpp.github.io/cppwp/n4659/dcl.init.list)。

   なお、代入の結果は lvalue、2引数の `std::min/max` は `const T&` を返します。表を「式の型」として読む限り矛盾しませんが、値カテゴリまで表した表ではありません。局所参照と参照戻り値は禁止されており、これだけから dangling reference の経路は確認できません。[min/max の署名](https://timsong-cpp.github.io/cppwp/n4659/alg.min.max)。

   **放置時の影響：所見1を除き、これらの行から signed 算術・narrowing UB に抜ける具体例は確認できません。**

4. **refuted / nit — 前回要求した宣言・文の具体化と `constexpr` の整合は成立する。R §2.5・2.7・8、F 決定5。**

   - 宣言ごとの型集合、代入先3種類、void の自前関数だけを呼ぶ文は明示されています。
   - メンバ読出しは引数名に依存しない `名前.メンバ` に訂正されています。
   - switch は条件型・label・各 case/default の終端・局所宣言のブロック化を指定しています。重複 label、型不適合、const への書込みは TU 検査で拒否できます。
   - 非 void 関数は最後の**直接の文**を return とし、末尾が全枝 return の if である形を明示的に拒否しています。
   - namespace `constexpr` の許可と、可変の静的・thread 記憶域の禁止は各文書で一致しています。

   初期化と return の変換には、代入表の同型制約を自動的には適用できません。例えば C++17 の `return true;` は U32 戻り値を初期化できます。通常の C++ 初期化規則を採るなら成立しますが、独自に狭める意図なら一文で明示するとよいでしょう。[return の初期化規則](https://timsong-cpp.github.io/cppwp/n4659/stmt.return)。

   **放置時の影響：前回の保存域・型集合・呼出し文の衝突は解消しています。具体的な UB を伴う文法残件は所見1です。**

5. **refuted / nit — 帰属と fragment の訂正に不整合はない。R §2.5・6、F 決定4・5。**

   A 所見6は txn 内状態を推奨し、共有状態・時計を局所適応の必須条件としません。A 所見5の表は set サイズ・競合位置を型15の代理として評価しています。B 所見9は限定した worker 内履歴と成功通知を推奨し、共有 atomic・時刻を最小拡張から外しています。訂正後の帰属はこの範囲に収まっています。

   F 決定4・5は README の型制限・状態寿命・`constexpr` 例外と一致します。front matter、H2 の `## {{D:slug}}. 題`、題末尾の日付なし、既存 D の実番号参照、決定／理由／却下案の構成も指定書式に適合しています。

   **放置時の影響：今回の帰属・書式訂正による受理集合や報告値の不整合は確認できません。**
