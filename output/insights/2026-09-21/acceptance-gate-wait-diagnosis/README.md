## 2. 定義 (段 4 裁定 `verbatim/s4-ruling.md` §2〜3)

親の初案 (P1)〜(P5) は段 3 相談を受けて全部修正・却下した。以下はその後の版である。

- **起動回と区間:** 起動回 = 門番 log file 1 本。区間 = 起動回の中を、tick 間隔 > 600 秒 (周期上限 140 + 乱数 45 + 再試行準備 60 + 余裕) または rc 行で区切ったもの。
- **区間の種類:**
  - `observed-wait`: 最初の tick → 同区間内の投入行 (GO / `attempt N:`)
  - `censored`: 投入行の無い区間 (打切り)。分布には混ぜない
  - `retry-prep`: rc → 次 tick
  - `submit-prep`: 投入行 → started.txt
  - `run`: started → finished
  
  **wave の待ち = observed-wait 区間の和。** post-claim merge と待ち手の走行は待ちに含めない。
- **日付:** log は `HH:MM:SS` しか持たない。まず mtime を最終行の日付として時刻の逆行で日を戻し (推定)、次に started.txt (ISO) を錨に投入行と突き合わせる。日付が食い違う file、逆行が複数ある file は `unresolved` として分布から外す (最終走では 0 file、mtime からの推定で日付を付けた file が 7)。そのあと `--until` より後の行を捨てる。
- **閉門理由:** 各 tick を条件値で `open` / `leaders-only` / `load-only` / `both` / `pigz` / `unknown` に分類する。条件値は、chain 型なら tick 自身の `(cond …)`、loop 型なら script から読む。分数配分は「直前 tick の状態が次 tick まで続いた」と置いた推定であり、因果寄与ではない。
- **再カウント拒否:** 連続成立後の recount で leaders > maxl になったもの (chain 型では `gate closed at recount`)。
- **長時間待ちと飢餓候補:** 長時間混雑待ち = 区間 ≥ 1800 秒。飢餓候補 = 長時間混雑待ち ∧ 同一区間の再カウント拒否 ≥ 2。これは事例探索のための条件であり、一般定義ではない。probe の self-check に次の 4 件を固定した。
  - 正例: T-2610 の初回区間が候補 1 件・拒否 2 回になる
  - 負例: T-2814 が候補 0 になる
  - 投入行の変種 2 件: paper-story-20260921、t2243
- **同時待ち数:** 母集合に入った門番 log (mtime が `--since` 以降) の observed-wait / censored 区間を集め、各 tick 時刻に他 wave が待ち区間を持っていた数を数えた (wave 単位で重複排除)。段 4 裁定 A-5 は「全残存 log」と書いたが、実装は since で絞った集合を使う (mtime が 9/19 より古い log の待ちは入らない)。log の leaders 値 (走行側の観測) では補正しない。log の無い待ち手は欠測になる。
- **走行数:** 走査対象の全 dir で 9/19 以降に始まった started → finished 区間のうち、tick 時刻を含むもの (started ≤ t < end) の他 wave 数。
  - finished が欠けていれば、同 attempt の rc 行、それも無ければ until で打ち切る (推定)。
  - `leaders − 走行` は偽 leader 疑いの上限であって、断定ではない。
- **同時 GO 帯:** 投入時刻 ±120 秒に投入を持つ他 wave の数。
- **感度分析 (仮定付き参考模型、効果見積りではない):**
  - observed-wait 区間の記録 tick 列に maxl ∈ {1, 2, 3} × maxload ∈ {60, 80} を再適用し、「連続 2 tick 成立 → 直後の記録 recount 値 (無ければ直前 tick) ≤ maxl」を満たす最初の tick (開門候補) を求める。
  - その起動回の実条件を同じ模型に当てた基準 (b0) との差 (代替 − b0) を出す。
  - 別行の `実 GO − b0` は、模型と実の差 (乱数待ち + recount の実費など) である。
  - 模型は pigz 条件と、再カウント時の load 再評価 (chain 型の門番は recount でも load を見る) を含まない。b0 も実門番の全条件の再現ではない。

**親の推奨:** A を先に採る (写し元の置き場はユーザーが決める)。A の後、同じ probe で leaders 起因閉門の走行数内訳を取り直し、なお長い待ちが残る場合に限って B を期間限定で試す。C・D・別枠は採らない。

理由: 直近 20 の帯では待ちの中央値が門番の構造下限に近く、30 分以上の観測待ちは 1 区間だった。9/19 以降では、全対象区間の leaders 起因閉門の推定分 2049.3 分のうち 1003.0 分 (約 48.9%) が、記録上の走行 ≤ 1 の時刻に当たる (記録どうしの不一致であって、偽 leader と確定したわけではない)。択 A は、意図した leader 上限 (他 1 本) を保ったまま既知の偽陽性を消す修正であり、閾値を上げる択 B と違って受理する同時走行の設計値を動かさない。実際の同時走行数と待ち時間がどう動くかは、採用後に同じ probe で確かめる必要がある (この資料は保証しない)。

## 8. 限界・言わないこと

- **条件値:** script の条件は現存版から読んだ値で、過去の走行時の実効条件 (gate.conf の後付け変更を含む) は保証しない。chain 型は tick 行に条件が出るので、その値を優先した。
- **日付:** `HH:MM:SS` だけの log では 24 時間を超える空白を識別できない。mtime から復元した 7 file は「推定」である。
- **欠測:** log の無い待ち手 (門番なし直接投入、消えた `~/.claude/jobs/`) は同時待ち数に入らない。同時待ち数の母集合は mtime が 9/19 以降の門番 log に限る。走行数は started.txt のある走行だけを数え、finished が欠けていれば rc 行か `--until` で終点を推定する。9/19 より前に始まった走行は入らない (門番 log の無い dir の走行は 1 本だけ見つかった)。
- **leaders:** leaders は走行側の観測で、偽陽性を含みうる。`leaders − 走行数` は偽 leader 疑いの上限であって、断定ではない。
- **推定値:** 閉門理由の分数配分は、tick 間の状態が一定という仮定に立つ。感度分析は仮定付き参考模型で、上下限にも回転率にも換算しない。
- **飢餓候補:** 条件 (≥ 1800 秒 ∧ 拒否 ≥ 2) は事例探索用で、実在 leader との正当な競合を除外しない。後着 wave の先行投入や偽 leader の一次資料 (当時の process 一覧) は無いので、原因は分類していない。
- **母集合の再現:** 直近 20 は `--until` で締めたので、同じ入力なら同じ集合になる。ただし log は job dir の削除で消えるので、後日の再走で完全には再現しない。数値は `verbatim/run-final.md` と対応する。
- **帯の偏り:** 直近 20 の観測区間は 9/20 19:45 〜 9/21 04:57 で、夜間に偏る。この帯の待ちの短さを混雑帯全般へ一般化しない。
- **自 wave の除外:** 本 wave (`dev-wave-lease-gate-wait-diagnosis`) は母集合からも走行数の照合からも除いた。本 wave 自身の受入はこの数値に入らない。
