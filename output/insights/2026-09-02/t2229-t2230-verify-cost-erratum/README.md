## 2. 誤り 1 と 2 — 23 分の帰属と積み方

一次資料は `output/insights/2026-09-02_b10-trace-truncation/README.md` の
「所要の内訳と、並列化への入力」節である。同節は次の 2 つを明記している。

- 1 反復の所要は WAL の時刻差であり**混合区間**である。内訳はベンチマーク本体 (extime 3 秒)・
  トレースの書き出しとスレッド終了時の flush・C 行の数え直し・標準出力の解析・
  直列化可能性検査・一時ディレクトリの作成と削除・WAL への書き込み。
  同節は「**『検査器そのものの費用』ではない**」と書いている。
- read-heavy で走った 4 変種のうち高 commit の 3 変種は 1 反復あたり commit 16.83M-17.19M、
  所要 **1346.9-1465.6 秒**。

ここから積み直す。

| 量 | 既存記述 | 帯の上端 1465.6 秒で積み直した値 |
|---|---:|---:|
| 1 反復 | 23 分 (`max` と表記) | 約 24.43 分 |
| full-scale 10 回 | 3.83 時間 | **約 4.07 時間** |
| `12:00:00` の倍率 | 約 3.1 倍 | **約 2.95 倍** |

検算: `1465.6 / 60 = 24.4267`、`1465.6 * 10 / 3600 = 4.0711`、`12 / 4.0711 = 2.9476`。
帯の下端は `1346.9 / 60 = 22.4483` 分なので、**23 分は上端ではなく帯の中ほど**である。

> **但し書き (D1529、2026-09-04)。** 上の帯 1346.9-1465.6 秒 (高 commit 3 変種) と、そこから
> 積み直した約 24.43 分・約 4.07 時間・約 2.95 倍の母集団は、read-heavy で commit 数が飽和した
> 3 変種の本規模 (performance) 反復 (反復数 5・5・3) である。3 反復だけの 1 変種は、campaign
> 記録上 commit (変種の認証確定) に到達しないまま打ち切られた実行 (以下「欠測 attempt」) の
> `constant-mu2` 変種 `292d58f1dad8` である。旧値 (23 分・3.83 時間・約 3.1 倍) も同じ母集団から
> 出ているが、本 wave の訂正は変えない (旧値は誤りのまま)。値を無効にするものではなく、
> 欠測 attempt を除いた再計算は行っていない。

**誤りは 2 つとも見積りを小さい側へ倒す向きに働く。** `max` と書いた値が実際には中ほどであり、
検査器単体の費用と読むと、並列化で消せる分を過大に見積もる。walltime の結論は動かないが、
同じ数字を別の判断へ流用するときにはこの向きが効く。

## 3. 誤り 3 — cell と変種の単位混同

`docs/archive/worklog-phase3-0902-1187.md` は「`965996` は 5 時間 5 分で 15 cell 中 3 cell しか
終えず、`fitness_tps` は全件 null」と書いている。**cell と変種が混ざっている。**

一次資料 `output/insights/2026-09-02_b10-missing-iterations-scope/README.md` によれば、

- read-heavy campaign `ed8a676b` は `build_start` 4 / `build_done` 4 / `commit` **3** /
  `verify_done` 22 で、「15 点中 4 点だけ開始、3 点で撤去」である。
  つまり完了したのは **3 変種の認証 attempt** であって 3 cell ではない。
- 同資料の格子表は `| cell | 3 block x 15 点の性能 record | 45 |` と定義する。
  **1 workload の性能 cell は 3 block x 15 点 = 45** であり、「15 cell」という母数は存在しない。
- 性能 `fitness_tps` は 1187 自身が書くとおり全件 null で、性能 record は 1 件も無い。

**3/15 を性能 cell の進捗と読むと、存在しない性能 record を受理済みと数えうる。** これが
この単位混同の成果物影響である。分子 3 は認証 attempt の数、分母 15 は認証単位 (点) の数で、
どちらも性能 cell の数ではない。

> **但し書き (D1529)。** 「5 時間 5 分」は撤去された request `965996` の走行時間を指すが、その
> 計測区間は現記録から確定できない (request 全体の Elapse は 20950 秒 = 約 5 時間 49 分)。いずれの
> 区間でも、完了 3 変種のほかに欠測 attempt (`constant-mu2`) の初期確認 (legacy) 1 反復と本規模
> 3 反復の時間を少なくとも含む。
> 終了直前に次の反復が始まっていたかは記録が無く不明である。値を無効にするものではなく、
> 欠測 attempt の時間を除いた再計算は行っていない。

> **追記 (T-2321、2026-09-18): 記録境界と旧所要の区別。** 上の「5 時間 5 分」の計測区間は引き続き未同定である。
> request `965996` の Started (2026-09-02 01:07:49 JST) からの秒表示差として、3 変種目の認証確定までは
> 16,387 秒、WAL 末尾 (4 変種目の本規模 3 反復目) までは 20,682 秒、Ended までは 20,946 秒 (scheduler の
> Elapse 記載は 20950S)。欠測 attempt の本規模 3 反復を含むことは WAL 末尾まで等の区間では確認できるが、旧所要
> への帰属は確定しない。根拠と精度は `docs/b10-multinode-formal-run-design.md` §1 の同名追記を参照。既存行と
> 当時の判定を保持し、値を無効にせず、欠測 attempt の時間を除いた再計算は行わない。

## 4. 本書が主張しないこと

- **検査器並列化タスクの射程を再裁定していない。** 「検査器側の並列化で詰める」という方針が
  混合区間の事実によってどう変わるかは、本 wave では決めていない。混合区間のどこが律速かを
  分離する材料も無い (一次資料自身が「この時刻差からは分離できない」と書いている)。
- **`docs/archive/worklog-phase3-0902-1189.md` へ in-file の訂正注記を書いていない。**
  起動時の重複検査で、同 file の H2 直後 (訂正注記を置く slot) を並行 wave
  `dev-wave-t2200-k2-role` が未 commit で所有していることが分かったため回避した。
  同 file の当該項は帯が既に「1 回 22-24 分」へ直っており、費用の単位も
  「45 cell ではなく 15 認証単位」へ訂正済みで、**残っている誤りは帰属だけ**である。
- **新しい測定はしていない。** 保存されている帯と campaign 別内訳を読み、積み直しを検算した
  だけである。生 WAL は読んでいない。
- **当時の判定を昇格も降格もさせていない。** 撤去の裁定、1187 が報告する thread-scaling の結果、
  45 cell の `correctness_certified=true` は、いずれも本 wave の対象外である。
- **`docs/b10-multinode-formal-run-design.md` は編集していない。** 別 wave が所有する予定の
  file であり、かつ本 wave の訂正対象語 (「23 分」「3.83」「12:00:00」) を 1 件も含まない。
