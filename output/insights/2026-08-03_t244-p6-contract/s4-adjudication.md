## 1. 本 wave の中心結論 — 択一 7 への答え

### 1.1 定理 (両レンズが独立に到達し、親が形式化した)

P6 に「**実測した候補だけを禁止する**」という健全性要求を課すと、導出集合 `B` は必ず
「validation で qualifying red を実測した mask の集合」に含まれる。ところが赤を実測した各 mask は
**それ自体が exact-mask cut の 3 条件を満たす**ので、`B` の各元は exact cut として独立に追加される。
したがって

```
C ∪ {p} ∪ B  =  C ∪ {p} ∪ (⋃_{m∈B} {m})
```

であり、**`B` は受理集合に何も足さない**。座標 cut (`S_e(U,R) = H(i,b)`) の場合も、
`H(i,b)` の 16 点すべてを実走し終えた後の主張なので結論は同じである。

**系:** P6 が受理集合を実際に狭めるには、**少なくとも 1 つの「実測していない候補」を禁止する**
必要がある。それは測定からは導けない **帰納段** である。

### 1.2 択一 7 の問いの形が変わる

択一 7 は「exact-mask (安全だが封じ込め相当) と座標 cut (軸 (i) を満たすが根拠が要る) の
**中間**をどう設計するか」と問うていた。上の定理により、

> **連続的な中間は存在しない。** 帰納段を踏むか踏まないかの二者択一である。
> 「根拠が要る」の正体は**帰納の正当化**であって、測定の量ではない。
> 測定を増やしても (32R まで増やしても) 帰納段を踏まない限り効果はゼロのままである。

これが T-244 本体が D106 残余 1 から 9 wave にわたって解けなかった**構造的な理由**である。
D121 決定 (4-b) が「安全側に振った結果、候補 A (現状維持 = 封じ込め) に近い強度しか持たない」と
書いたのは正しかったが、**「近い」ではなく「受理集合に関しては同一」**であった。

### 1.3 したがって P6 契約の正しい形

P6 を「健全な再導出」として書くことはできない。**明示的帰納契約**として書く。
設計本文 (`README.md`) はこの形で書く。骨子:

1. 仮説クラス `H` を **source failure より前に**事前登録する。
2. **`B \ (実測赤集合) ≠ ∅` を契約の成立条件にする** — 効果がゼロなら P6 は成立していないと定義する。
   これが A-BLOCKER2 / B-B1 を構造的に閉じる唯一の方法である。
3. 仮説を反証する paired test を事前登録し、**反証されたら origin を seal する**。
4. 主張を「`H` のもとで、この origin・この environment に限り」へ有界化し、「証明した」と名乗らない。
5. 規律 2 の verifier 必須条項は不変。禁止集合に無いことは安全の保証ではない。

## 4. 実装しない裁定 (`DW-S04`)

**本 wave は実装しない。** 根拠は 3 つあり、いずれも独立している。

1. **ユーザー裁定。** command 引数が「設計だけ (実装なし)」である。
2. **`DW-G04` (条件付き機能の発火 gate)。** 発火条件を満たす既存 artifact path も計測 ID も
   **1 件も書けない**。実 campaign 30 本の WAL census で、構造化 non-serializable witness は
   fixture 由来の 1 件 (帰属が偽) だけである。よって設計メモに留める。
3. **§1 の定理。** 帰納段の設計がユーザー裁定を要する以上、実装すれば未裁定設計を既成事実にする。

したがって段 5・6 を飛ばして `4→7→8→9` とする。

- **変異事前登録 (`DW-M01`) は対象外。** 実装差分が無いため変異させる位置が存在しない。
- **変異 matrix と受入全走も対象外** (`DW-S04` の明文どおり)。docs 検査
  (`tools/check_docs.py`) と、docs 変更が影響しうるテストは走らせる。
- `MAX_APPROVED_GENERATIONS = 1` (D114) は変えない。cap-lift の結線もしない。
