## 閉じる must-fix (レビュー B の 1〜3。4 は親が変異 spec 側で処理するので触らない)

### R1. 凍結発行 API と複数世代履歴の CR/LF テストが無い

NUL には `prepare_revision` のテストが 2 本 (発行前・既存 freeze 後) あるが、CR/LF には無い。
「`evidence_contract_sha256` と履歴検証だけ新検査を使い、`prepare_revision` は旧経路を使う」
弱実装が現状の全テストを通る。

- **`prepare_revision` × CR/LF × (初回発行 / 既存 freeze 後)** のテストを追加する。
  既存の NUL 版 (`test_prepare_revision_rejects_nul_path_contract_before_create` /
  `..._with_existing_freeze`) と同型にし、reason は `evidence-contract-path-crlf` を要求する。
- **複数世代の履歴テスト**を追加する。CR/LF-bound g1 (pre-wave hash literal に正しく束縛したもの、
  既存 `_install_legacy_crlf_bound_g1` を再利用または一般化) の上に **clean な g2** を積んだ履歴で、
  `validate_condition_freeze_at` が **祖先の CR/LF** を理由に
  `evidence-contract-path-crlf` で倒れることを固定する。「tip だけ新検査、祖先は旧経路」という
  弱実装を殺すためである。これは段 4 裁定 A の「履歴では祖先順で最初に禁止制御文字を含む契約が
  理由語を決める」を機械で固定するテストでもある。

### R2. 「その他の制御文字は受理」の正例が VT だけで不足

「CR/LF/NUL に加えて TAB・BS・FF・U+0001 も拒否するが VT だけ許す」実装が現状の全テストを通る。
exact `path` の中に **TAB (U+0009)、BS (U+0008)、FF (U+000C)、U+0001** を置いた入力を、
既存の受理正例と同じ形式で **exact hash 固定の受理側**へ追加する。
U+000B (VT)・U+0085・U+2028・U+2029・文字どおりの `\r` `\n` の既存正例は残す。

### R3. 文書順と形状の固定が不足

- **混在 CR/LF の文書順**: 現在の複数 CR/LF fixture は両 node に同じ制御文字を入れているため、
  「文書順ではなく常に CR を LF より優先する」実装が通る。**先行 LF・後続 CR** と
  **先行 CR・後続 LF** の両方を追加し、いずれも**文書順で最初**の pointer を要求する。
- **root が list の入力**: root が list のとき走査しない実装が通る。
  `[{"path":"x\ralias"}]` 形の入力を拒否側で固定する (LF 版も)。
- **十分深い dict/list 交互入れ子**: 現在の最深 fixture は浅く、深さ上限で打ち切る実装が通る。
  深さ 10 以上の dict/list 交互入れ子の末端に CR/LF path を置いた入力を拒否側で固定し、
  pointer も exact に要求する。
