## 0. 何が分かったか

**適応 backoff の刻みに対する応答が非単調になる機序は、`Backoff_` の滞在分布である。**
更新窓が狭いと歩行は高い `Backoff_` へ暴走し、**その滞在先の静的な性能がそのまま throughput になる。**
刻みは、歩行がどこまで暴走するかを決める従属変数である。

**決定的な対照 (更新間隔だけが違う 2 条件、他の軸はすべて同一):**

| 条件 | throughput | `Backoff_` 中央値 | 時間加重 `P(>100 µs)` |
|---|---:|---:|---:|
| 刻み 1 µs / 更新間隔 **10 µs** | 2,201,348 | **88 µs** | 0.648 |
| 刻み 1 µs / 更新間隔 **2560 µs** | **4,030,122** | **6 µs** | 0.000 |

**窓を広げるだけで中央値が 88 → 6 µs へ下がり、throughput が 1.83 倍になる。**

**混合の検算。** 実測した滞在分布を、既に測ってある静的 `T(b)` 曲線へ時間加重で混ぜると、
6 セルすべてで実測 throughput を **−9.1% 〜 +4.7%** で再現する。

**`output/insights/2026-09-02_t2216-adaptive-backoff-nonmonotonicity-mechanism.md` §4-bis の
歩行 model は、同じ谷 (刻み 25 µs) で相対誤差 130% だった** (実測 1,241,671 に対し予測 2,827,148)。

**したがって T-2216 の否定的結論「素直な滞在説では足りない」は、混合の仮定が誤っていたのではなく、

静的性能に等しい」という仮定は、本測定の範囲では棄却されない。**

## 1. 測る前に分かったこと — 既存記録の読み方の訂正 2 件

新しい測定に入る前に、既存成果物だけで 2 件の訂正が出た。**どちらも本 wave 以前の記録が
持っていた読み方であり、機序の議論の土台になっていた。**

### 1.1 記録済みの `Backoff_` trace 26 file に、stock と同じ時間トリガの条件は 1 つも無い

`/work/1/SFC/tanab/izanagi-job-evidence/dynamic-backoff/trace/` の 26 file はすべて
「commit 数で窓を切る」セル (`count_window = 10000`) であり、刻みは全部 1.0 µs、
更新間隔は全部 2560 µs である。解析器の `trace_inventory.time_triggered_cell_count = 0`。
**非単調性は更新間隔 10 µs の下でだけ現れるので、既存 trace だけでは本題は決まらない。**

### 1.2 保存済み `directional_success` は独立な正解に対する的中率ではない

この指標は、実際に適用された action の符号と次窓 throughput 差の符号が一致した回数を数える。
次 event の勾配は**同じ throughput 差を直前の action で割った量**なので、
両者は同じ観測量から作られている。

event 対 359,969 件の分割表 (468 走行):

| | 次勾配が正 | 次勾配が正でない |
|---|---:|---:|
| 再計算 success = true | 101,697 | 160 |
| 再計算 success = false | 100 | 258,012 |

**一致は 99.93%。食い違いは 260 対 (0.072%)。**
一方、走行ごとの合計は 101,857 = 101,857 で**完全に一致する** — つまり
**合計だけを比べると相殺で一致してしまい、同一性を示したことにならない。**
出力には `ground_truth_independent: false` を literal で持たせた。

### 1.3 窓内 commit 数が Poisson かどうかは、既存記録では判定できない

記録済みセルは commit 1 万件で止まる停止規則の標本であり、かつ窓長と `Backoff_` が
走行内で動くので、生の分散/平均が大きくても Poisson の棄却にならない。
解析器の `poisson_verdict` は入力によらず `"not_adjudicated"` に固定してある。

**本 wave はこの判定を、時間トリガの窓を実測することで別に閉じた (§3 の J3)。**

### J1 — 符号の不安定度: **不支持 (`not_supported`)**

刻み 1 µs の 2 条件について、各 event の勾配符号を直前 event の順序なし辺へ割り当て、
辺ごとの不一致率を `2p(1-p)` とし、共通台の重みを固定して加重平均した。

- **走行を 3 等分した各区間で向きが揃わない** (`direction_unstable`)

**限界が 2 つある。** (1) 共通辺は 12 本しかない (`Backoff_` <= 12 µs)。狭窓側は時間の大半を
88〜358 µs で過ごし、広窓側はそこへ行かないので、**両者が重なる範囲は低域だけ**である。
(2) 推定量 `2p(1-p)` の形は結果を見た後に親が定めた。**事前登録された盲検の判定ではない**
(出力に `estimator_specified_after_data: true` を持たせた)。

**読み方:** 低域に限れば、狭窓の符号は広窓よりわずかに不安定なだけである。
**「計数ノイズが符号を支配する」という説明は、少なくとも低域では主要因ではない。**

## 4. 機序の全体像

1. 刻みが大きいほど、狭い窓の下で歩行は高い `Backoff_` へ行きやすい (J2)。
2. 高い `Backoff_` では更新の機会そのものが減る (J4)。窓の長さが大きく歪み、
   窓内 commit 数が激しく過分散になる (J3)。
3. throughput は、歩行が居着いた場所の静的な性能でほぼ決まる (§0 の混合、−9.1%〜+4.7%)。
4. 窓を広げると歩行は最適帯に留まり、throughput は最良になる (対照、1.83 倍)。

**刻みに対する非単調性は、「歩行がどこに居着くか」の非単調性である。**
刻み 25 µs で中央値 550 µs まで行き、刻み 100 µs では 300 µs に戻る
(上限 1000 µs への張り付きが増える一方、中央値は下がる)。この非単調な居着き方が、
静的曲線を通してそのまま throughput の非単調性になる。

## 5. 確定していないこと

- **b > 900 µs の静的 `T(b)` は測定不能である** (F718、現符号化では b=1000 が固定 0 へ復号される)。
  `nm-step25` は時間の 15.1%、`nm-step100` は 9.6% をこの領域で過ごす。
  混合の検算ではそこを 900 µs の値で平坦に置いた (外挿していない)。
  `T` は減少関数なのでこの置き方は予測を過大にする側であり、実際その 2 セルの予測は実測よりわずかに高い。
- **単一 workload (write-heavy)・単一スレッド数 (48)・1 rep・単一環境 (Pegasus)。**
  balanced / read-heavy へは一般化しない。
- **計数ノイズの寄与を否定していない。** J1 が見たのは両条件が重なる低域だけである。
  高域で符号がどう振る舞うかは、比較対象が無いので測っていない。
- **`nm-step0.5` の統計は末尾 slice である。保持区間の被覆率は 0.293** (68.9% 取りこぼし)。
  `nm-step1` の被覆率は 0.988、残る 4 セルは 1.00 で全走行である。
- **性能値は非認証である。** 本 wave は直列性の検査を 1 度も走らせていない。
