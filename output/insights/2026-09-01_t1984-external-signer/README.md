# [T-1984] D906 の外部署名主体 — 部品を実装し、必須化は送る

wave: `dev-wave-t1984-external-signer` / base = local main `08a17b3b3` (着手時)

## 何をしたか

D906 (ユーザー裁定) が求める外部署名主体について、**署名検証 library と repository 内の
reference issuer を実装した。production の着地関門は 1 bit も変えていない。**

**【機構追加・未強制】** 追加した部品は現在の着地関門では効いておらず、無署名受領証による
既存の受理を 1 件も置換していない。**D906 の enforcement 完了とは数えない。**
着地受領証を根拠にした正しさ主張は、D1197 に従い**未閉鎖**である。

## なぜ必須化しなかったか

段 2 のプラン、段 3 の敵対相談 2 レンズ、親の独立実測が、独立に同じ 4 つの障害を示した。

1. **鍵を AI が生成すると D906 を満たさない。** D906 は鍵と発行権限を AI が書ける領域の外に
   置くことを求め、却下選択肢に「署名だけを足し鍵の置き場を決めない = 恒真になる」を挙げている。
   生成時点で AI が秘密を支配した事実は、後から書込みを拒否しても消えない。
2. **書込み防護そのものも AI には足せない。** 書込みを止める機構は自分の subtree への
   書き込みを自ら拒否し、Claude と Codex の双方へ配線済みである。防護対象の追加も人の手番。
3. **必須化は鍵が配置されるまで着地を全面的に止める。** 過去の受領証だけでなく、世代を持たない
   既存の排他権、非保持走行、旧い待ち手で稼働中の wave、鍵未配置期間のすべてに及ぶ。
4. **必須化しても関門は不可避にならない。** 着地ツールは自身の実行 copy を `__file__` から
   解決し、cwd しか検査しない。署名検証を含まない旧い着地ツールを wave 側から起動すれば、
   新しい検証を通らずに main を進められる。

## 親の独立実測 (レンズが出さなかったもの)

**排他権の payload は field 集合を厳密一致で検査し、解釈できない payload を
「誰も保持していない」へ縮退させる。** したがって D906 が要求する「排他権の世代」を
payload へ足すと、旧い実装で稼働中の wave が保持中の排他権を空きと読み、受入の排他が壊れる。
共有の排他権 directory を 6 本以上の wave が使っている。
**よって世代は schema の slot として定義するに留め、production の値の生成源は決めていない。**

## 段 6 で閉じた恒真化

敵対レビューが、**固定鍵の loader と高水準検証 API を一度も通らない control** を検出した。
低水準 API へ呼び手が作った鍵を直接渡す形では、loader が環境由来の鍵を採用しても、
高水準 API が署名検証を迂回しても緑のままだった。**この初回結果は消さない。**
fix が、固定 path の loader と高水準 API を実際に通る正例と、鍵違い・環境差し替え・
鍵欠落・不正形式の 4 負例を追加して閉じた。
