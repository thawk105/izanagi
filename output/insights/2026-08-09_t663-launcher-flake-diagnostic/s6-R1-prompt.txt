## レンズ C = 検出力の保全 (何が静かに失われたか)

1. **削除された assert の 1 件ずつの照合。** 実装子は「launcher 実行の rc equality だけを削除し、
   同じ期待値で helper へ移した」と報告している (s5-impl.md の「削除した assert」節)。
   差分を読み、**期待 rc の値が 1 件でも変わっていないか**、rc 以外の assert が巻き添えで
   消えていないかを照合せよ。変わっているものがあれば file:line と旧新の値を示せ。
2. **恒真化の検査。** 新設 meta-test 7 本それぞれについて、
   「診断が実際には出ていないのに通る」実装ミスが残っていないかを読め。
   とくに (a) `pytest.raises` の対象例外が広すぎる、(b) 検査対象が
   `str(exc)` でなく別物、(c) 部分文字列検査が空文字列や自明な token に当たる、
   (d) sentinel 差し替えが実際の assert 経路を通っていない、を疑え。
3. **一次失敗を覆う経路が残っていないか。** 診断生成中の例外・非 UTF-8・巨大 stream・
   receipt 破損・stream ファイル不在で、`actual rc != expected rc` の情報が失われる経路を
   差分から探せ。`_hash_file` 相当の読み込み、`json.load`、`read_text` の各所を見よ。
4. **時間予算が本当に据え置きか。** 段 4 は wall 3 / evidence 1.0 / termination 0.05 /
   poll 0.01 / 外側 timeout 10 の据え置きを命じた。差分の全 call site を走査し、
   1 箇所でも変わっていれば file:line を示せ。新設 meta-test が独自の予算を使う場合、
   それが既存テストの予算に影響しないことも確認せよ。
5. **新設 fake mode の非干渉。** 実装子は `child_error` mode を追加したと報告している。
   既存 mode (`normal`, `no_token`, `delayed_thread`, `no_rollout`, `inconsistent`,
   `final_drain`, `term_success`, `sigterm_ignore`, `manifest_while_running` 等) の
   挙動が 1 つも変わっていないことを、埋め込み fake の差分で確認せよ。
6. **受理集合の不変。** production は無編集のはずである。差分に
   `tools/codex_worker_launch.py` が含まれていないことを確認し、
   テスト側で production の挙動を monkeypatch で置き換えて緑にしている箇所が無いか探せ。
