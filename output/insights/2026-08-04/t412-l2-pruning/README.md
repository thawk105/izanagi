- **現行の routing 3** は「ID 件数でなく repo 全体 (insights・memo 含む) の意味検索で
  反証されないことを確認する」までしか書いていない。**文書の意味検索は「記録されたか」しか見ない**
- **改善案**: 条件の**外延を直接検査する**手続きを足す — 削除条件なら git 履歴の削除 commit、
  commit message 条件なら実 message の全文、テスト条件なら実行記録。
  「その条件を満たす事象が実際に起きたか」を、**それを記録した文書の有無とは独立に**測る
- **行き先**: 削除 gate の判定手続き = 裁定境界に触れるため裁定パッケージ。
  **これは gate を厳しくする方向の変更であり、緩める提案ではない**

### 候補 3 — `DW-O03` は prompt だけを対象に書くが、guard は全 Bash command に発火する

- **実測**: 親が防護パス文字列と `$()` を含む probe command を組み立てたところ、

- **価値は小さい** (guard の拒否メッセージが正しい代替手段を案内するので実害に至らない)
- **行き先**: 本来は `DW-O03` へ数語足せば済む意味を変えない明確化だが、
