## 設計判断 (段 4 裁定、敵対相談 2 + レビュー 2 反映)
- **機構 (P1)**: 明示 frozenset を採用。key-set digest との比較で、集合等価は衝突耐性に依存せず、
  canonicalization 不要、失敗 message に missing/unexpected を直接表示でき、査読で期待 path が読める。
- **新 node を作らない理由**: D76 (freeze-permanent-design-s2.md:2678) が既存 42-node baseline の
  base に frozen_artifacts の 2 node を「HEAD 関数定義の実測値・生成器由来でない」として列挙。
  新 node は将来設計 baseline を陳腐化させる。既存関数強化なら _run harness と pytest の双方に載る。
- **主張の限定**: 本 assert が閉じるのは「狭義 R2 = manifest membership」。広義 lineage
  (commit ancestry・実走真正性 = C02/R3/R4 + 外部 attestation) は本 assert の対象外で、seal ancestry は
  別 E2E test (test_s8b_floor_campaign.py) が担う (相談 lens2-4)。
- **命名と限界**: 定数は seal 固有名 `..._82803D6D`。同一ファイル内 pin は manifest と定数を
  協調編集すれば通る = 独立改竄境界ではなく「manifest-only 編集に対する運用 sentinel」。恒久形 (D76) は
  別ファイル golden で分離する。コメントに独立改竄境界・恒久 membership の双方を明示否定 (相談 lens2-3)。
- **群件数 assert 不要 (P3)**: exact 23 path 一致が保たれれば群件数は論理的帰結。件数だけでは同一群内
  差し替えを検出できない (floor-protocol-package → ruling-package はともに裁定資料で件数不変)。
