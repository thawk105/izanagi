> ほとんどないテスト・記録というものが膨れ上がっているはずだ。慎重に調査し、慎重に掃除してください。

## 研究前進 (土台)

止めている研究は実測でゼロである。本 wave が扱うのは**開発ループの固定費**であり、次が実測値。

- 2026-08-24 (D747 の測定日) から 2026-09-14 まで 4,147 commit。
  `orchestrator/tests` は **+286,904 行 / -21,385 行**、正味 +265,519 行 (約 2 倍)。repo 全体で
  14,375 file 変更・+4,492,679 行。
- 受入所要台帳の直列総和は **5,364.9 秒 → 15,306.6 秒 (2.85 倍)**、nodeid 14,467 → 23,105。
- tracked file 24,684 / 約 690 MB。1 wave ごとに 774 MB の checkout と submodule 初期化を払う。

最小差分は「**証拠価値ゼロが機械的に示せる記録・テストだけを削り、それ以外は削らずに裁定へ返す**」。

## 既存被覆 (純増だけを本 wave の scope にする)

- **D747** — 受入高速化のためのテスト削除は採らない (削除 0 件)。本 wave の実測でも
  `<0.01 秒` 12,223 件の合計は 25.8 秒しかなく、この裁定は母数 2.85 倍でも成立する。
- **D1894 / D1918** — 受入 wall 短縮の対象は「最遅 shard (shard-2) の最大 worker 占有」で、
  別系列が担当中。**本 wave は受入 wall 短縮を目的にしない。**
- **D1941** — 既存 insight は bytes を変えず日付配下へ移し、旧名索引を残す (削除ではない)。
- **D958** — 掃除の削除可否は所要上限に拘束されない。
- **D204 / D703** — branch 削除はユーザー指示時のみ。自 wave の branch だけ自動削除可。

純増は「持ち続ける費用」の側であり、wall 短縮でも evidence 削除でもない。

## scope

1. 膨張の内訳を実測で確定し、ユーザーの仮説のうち**成立する部分と成立しない部分**を分ける。
2. 次の 3 条件をすべて満たす tracked file / test だけを削除候補にする。
   (a) 現行コード・docs・台帳・凍結 manifest のどこからも参照されない、
   (b) proof chain・事前登録・certified 選択の入力でない、
   (c) 削除しても受理集合・成果物の値・参照が変わらない (DW-G05)。
3. 上記を満たさないが費用が大きいものは、削除せず**裁定パッケージ**にして返す。

## scope 外 (やらない)

- 受入 wall の短縮 (D1894/D1918 の別系列)。
- 生の測定値・trace・封印済み bundle の削除 (絶対規律 7、D1941)。
- git 履歴の書き換え、force、rebase、push。`.git` 1.8 GB は本 wave では縮まない。
- 他 session 所有の worktree・branch の撤去 (D204。実測して裁定へ返すだけ)。
- テストの高速化リファクタ (共有化) — 削除ではなく実装であり、別変更単位。

## 不変条件

- 絶対規律 2 を緩めない。**anomaly を検出する test・gate は 1 件も削除しない。**
- 絶対規律 7 を守る。測定時点の事実を「現行コードと違う」だけの理由で消さない。
- 絶対規律 6。削除候補の判定に、削除対象自身が書いた文言を根拠として採らない。
- 削除は `DW-O11` に従い、`git ls-files` の空確認を先に行う。`git status` を不在証明にしない。
- `DW-O09` の pin 閉包を候補ごとに取る。path 検索だけで「pin なし」と結論しない。

## (P1) 親の provisional 裁定 — 攻撃対象

- **(P1-a)** ユーザーの仮説「研究に影響しない記録が膨れている」は、`output/` については**概ね偽**。
  最大の `job-staging` 1,206 件 / 124 MB は他所に同一 blob ゼロで、コード 4 か所から参照されている。
  committed build artifact も 121 KB しかない。
- **(P1-b)** 仮説はテストについては**概ね真**。3 週間で +265,519 行。ただし「遅いテストを消す」は
  D747 で閉じており、価値があるのは**重複・恒真・死んだ pin** の側である。
- **(P1-c)** 実ディスク量は制約でない (85T 中 4%)。膨張の実害は checkout・検索・読み込みの固定費。
- **(P1-d)** 機械的に inert と示せる削除候補は**少数**であり、本 wave の主産物は削除量ではなく
  「どこが削れてどこが削れないかの確定」になる。

## 成果物の形

- 削除候補表 (path・bytes・inert の根拠・pin 閉包の結果) と、実際に削除した集合。
- 削れないと確定した集合と、その理由 (証拠・pin・consumer)。
- 裁定パッケージ: ユーザー権限が要る掃除 (worktree 42 本、insight 18,205 file の配置、
  台帳 4.88 MB の読み込み費用)。
- worklog / decisions / failures の fragment、insight。
