## (2) 親の新規主張の検証

1. 「core §16 があるため、本走だけ先に進める選択肢は存在しない」

   **一部正しいが、結論は過大。** core §16 が「6 セルすべての調整済み p 値と同時区間」の公表を義務づけること自体は正しい (`preregistration.md:438-442`)。しかし §16 は公表手続きの本走前固定を要求しておらず、literal な `submit_main` 条件は追補 B の解決までである (`preregistration.md:246-253,414-416`)。

   したがって、「手続きが最後まで決まらなければ §16 の成果物を生成できない」は正しいが、「core §16 自体が本走先行を禁止する」は導けない。正確には「本走先行は literal gate では可能だが、結果後に手続きを選べるため事前登録の proof chain が閉じない」である。package 自身も primary の式は影響を受けないと認めている (`package.md:143-145`)。

2. 「core への erratum 機構を既に 2 回使っている」

   **誤り。** §15 exact-key erratum は canonical worklog 上で一括承認・段階 2 発効済みなので、1 回目の使用実績はある (`docs/worklog.md:615-616`)。一方、§7 erratum は R2(a) で経路が裁定されたにすぎず、文書は未発行である (`package.md:174-179`; `addendum-b.md:215-216`)。正確には「1 回使用済み、2 回目は選択済みだが未発行」。

3. 「今回は手続きを新設するので先例より一歩踏み込む」

   **実質は正しいが、先例の数え方が不正確。** §15 erratum は既存の誤記 2 箇所だけを exact replacement する (`erratum-core-s15.md:50-80,91-99`)。§7 案は既存義務の置換、B4(a) は core が定義していない検定手続きを追加する案であり、変更の強さは確かに増す。ただし発行済みの先例は §15 の 1 本だけで、§7 は未発行案として区別すべきである。

4. 「B4(b) なら現 study は終端し、現追補 B は新 core で使えない」

   **正しい。** 閉集合外の変更は別 study・新 core とする契約である (`preregistration.md:311-316`)。追補 B は現 core の path・commit・digest 三つ組へ静的に従属しているため (`addendum-b.md:20-27`)、別 core の有効な追補として再利用できない。`b01`〜`b03` を設計入力として参照することはできても、追補 blob 自体は使えない。
