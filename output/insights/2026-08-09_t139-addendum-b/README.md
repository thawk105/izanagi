    `検証 1 + pilot 8 + pilot 予備 2 + 本走 13 + 本走 予備 2` でちょうど候補 1 本分であるため。
    **導出ではなく governance の提案値**と明記した。上限の変更は本追補を書き換えず、
    同じ根・同じ配分表を継承する新 study の新追補で行う。
  - `b02` 個別公表系列の spending = **`0.05 / (k(k+1))`**、本 study は `k = 1` で **`0.025`**。
    総和がちょうど `0.05` なので**候補数上限に依存せず**、後から上限を上げても配分の総和は
    `0.05` を超えない。未使用 tail は回収も再配分もしない。
  - `b03` 正規の根 = `(fold_commit = 88d68f91…, ledger_kind = individual_publication)`。
    primary とは別台帳で、根は呼び手が選べず、予約は作成のみ・失敗しても番号を解放しない。

  値を与えず、`alpha_pub_k` を primary の入力にしない。本文は両者を**参照はする**が固定し直さない。
- **3 field はいずれも測定値を入力に取らない。**候補の通し番号と固定定数だけの関数である。
  **ただし「実際に pilot の生データを見る前に凍結された」という時点の独立性は、文面からは
  検証できない。**草案はこれを主張しないと明記した。

  初稿の `b02` は公表用の `p` 値の式・Holm の閾値列・同時区間の使い方まで書いており、
  これは「配分の数値」を越えて新しい推論規則を足す閉集合違反だった。
  `b03` の「primary 予約 entry への必須参照」も、裁定 U8 の別台帳の範囲を越えうる新しい拘束であり、
  かつ**その参照が無くてもリセット経路は閉じる**ことを示された。
  **両方とも受け入れて草案を縮めた。**現在の `b02` は配分の数値だけを持ち、公表手続きを
  定めないと明記する。`b03` から親参照を外した。
