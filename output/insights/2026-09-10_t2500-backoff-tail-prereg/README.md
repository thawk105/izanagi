## 0. 依頼と、実際に起きたこと

依頼は「格子・反復数・停止基準・失敗条件を結果を見る前に固定した事前登録を書いて凍結する。

## 1. 前向きに固定したもの、していないもの (本書の正直さの境界)

第 1 段の探索は本書より前に完走しており、飽和の不在は既知の状態で本書を書いた。したがって

- **前向きなのは、まだ 1 度も観測していない本格 cohort に対する測定規則と判定規則だけ**である。
- **前向きでないもの** = 格子の位置と刻み幅、5% という等価幅、変動係数の gate 0.02、
  「域内で飽和しない」を正当な結末に含めるという選択。いずれも探索結果を見た後に選んだ。
- 本書は「静的 tail 研究全体の事前登録」ではなく「**探索開示済み・本格 cohort 前の事前登録**」である。

先例 `docs/b10-backoff-shape-preregistration.md` が同じ型の限定を持っている。

## 2. 格子 — 段 3 の指摘で設計から変えた

段 2 プランは 1000 マイクロ秒から上向きに半オクターブで刻み、上限手前の余りを埋めるために
8000 と 9999 の幾何中点 8944 を足す案だった。段 3 のレンズ B がこれを数値で壊した。

- 終端の短い区間は対数比が 0.11 しかない。**真に平坦でも到達できる上限は 9.1% で、5% 基準に届かない。**
- つまり **飽和が最も起こりうる右端でだけ、述語が構造的に発火しない**。8944 を足した目的を
  達成しないどころか、そこだけ判定不能になる。

親は格子を**表現上限 9999 を起点に下向きへ半オクターブ**へ変えた。

```
b_k = round(9999 / 2^(k/2))   k = 6..0、b_k > 1000 のものだけ
→ 1250, 1768, 2500, 3535, 5000, 7070, 9999
```

境界参照 1000 を足して 1 workload 8 genome。**tail の隣接区間の対数比は 0.34642〜0.34673 で均一**、
境界参照区間だけ 0.22314 なので述語には入れない。1 workload 8 genome は先例 `t2266-tail` と同数で、
実走 11 分の実績がある規模である。

**親は最初この格子の値を間違えた。** 下端から上向きに掛けて `3536` / `7071` と書いたが、
規則の解は `3535` / `7070` である (9999/2^1.5 = 3535.180、9999/2^0.5 = 7070.361)。
段 4 裁定文に誤った literal が残っており、段 6 の 2 レンズと焦点 1 巡目が独立に再計算して指摘した。
**事前登録の本文は正しい値を持っている**が、裁定文には erratum を追記し、
「後続 wave は裁定文の literal を数値の権威にしてはならない」と明記した。

## 3. 量子化 — 「測れていないこと」が「飽和」になる経路を塞いだ

段 3 の 2 レンズが独立に同じ穴へ収束した。親は根本原因を実装まで辿った。

- **`external/ccbench/common/result.cc` の `Result::displayAbortRate` は abort 率を小数第 4 位までしか
  印字しない。** tail の右端では abort 率が 0.007〜0.015 まで下がるので、1e-4 の量子は平均の
  0.7〜1.4% に当たる。
- 実測: write-heavy 9999 マイクロ秒の 5 rep は `[0.0114, 0.0114, 0.0114, 0.0115, 0.0114]` で、
  **標本標準偏差 (相対 0.39%) が量子の半分 (0.44%) より小さい。**
- この丸め値から標本分散を作ると区間が不当に狭まり、**分解能の不足が飽和の証拠に化ける。**
  規律 2 と規律 3 に直接触れる。

**塞ぎ方:** 本走は rep ごとの `abort_counts_` / `commit_counts_` を整数のまま保存し、
abort 率を `aborts / (aborts + commits)` で全精度に再計算する。丸め値への fallback は禁止。

**この要求が満たせるかを WAL の現物で確かめた。**

- CCBench は `Result::displayAbortCounts` / `displayCommitCounts` で両カウンタを整数のまま印字し、
  abort 率と同じ表示経路から呼ばれている。parser も両 key を知っている。
- 正しさ検査の記録 (`verify_done`) は `commits` / `aborts` を**整数のまま持っている**。
  つまり整数を WAL へ載せること自体はこの family で既に行われている。
  ただしそれは trace 有効側の値であり、性能測定の代わりにはならない。
- **性能測定の記録 (`bench_done`) は rep ごとの throughput 配列と、cell 全体で 1 つの丸めた
  abort 率しか持たない。rep ごとの abort 率は WAL に無く、実行中の in-process 捕捉から
  report へ直接入っている。**
- したがって「WAL から再構成する」を満たすには本走側の新しい保存が要る。**投入前条件**にした。

## 4. 判定の全域性と一意性 — 3 巡かけて閉じた

親の初稿と 2 回の fix が、いずれも「どの入力にも唯一の結論を返す」を満たしていなかった。

| 巡 | 指摘 | 何が壊れていたか |
|---|---|---|
| 段 6 | `indeterminate` が明白な低下継続まで吸収する | 検出力の事前条件を観測傾きより先に見ていた |
| 段 6 | 集約 verdict が排他でない | 同じ観測から複数の結論を合法的に出せた |
| 段 6 | 局所的な平坦 2 区間を tail の飽和と呼べる | 右側が低下に戻っても位置を出していた |
| 段 6 | ゼロから正値への遷移が失敗条件に無い | `qL` 自体が計算できない入力を `qL > 0` で判定していた |
| 焦点 1 | ゼロ abort 規則と分散なし規則が別表で優先順位なし | 同じ全ゼロ区間が 2 通りに分類できた |
| 焦点 1 | 分散なしの区間で「必ず併記」の診断値が計算できない | 診断値自身が未定義の自由度を要求していた |
| 焦点 1 | `j = 1` の位置と bracket が 3 通りに割れた | 一般式・打切り記述・spec が食い違った |
| 焦点 2 | **正常な cohort が必ず無効になる** | 3 job の workload 座標を一致させる条項を書いた (設計上一致しない) |
| 焦点 2 | 正値から全ゼロの区間で診断値が未定義 | 分類だけ決めて値を決めていなかった |

**焦点 2 の 1 件目は親の fix が持ち込んだ致命的欠陥である。** 3 job は設計上それぞれ別の workload を
測るのに、cohort の同一性条件へ `workload_coordinates` を入れてしまい、
**正常な走行がすべて `invalid` になる = 非 `invalid` の結末が到達不能**になっていた。

最終形は次のとおり。

- 区間は 6 規則の単一表で `saturated` / `declining` / `indeterminate` に分類する。
  ゼロ abort の 2 規則を表の先頭に置き、対数を取る前に決める。
- `saturated` = 倍増あたり低下の同時上限が 5% 以下。`declining` = 同時**下限**が 5% 超。
  どちらとも言えなければ `indeterminate`。**分解能不足を非飽和と読む経路も、明白な低下を
  保留へ落とす経路も、どちらも閉じている。**
- 飽和位置は**上限 9999 まで続くこと**を要求する。`j = 1` は「1250 以下・左側打切り・下端なし」。
  両側から挟める最左は 1768。
- workload 状態の 3 つは「`indeterminate` が 0 件」を条件に含むので**評価順に依存せず排他**。
  集約 verdict は上から順に評価する 5 行の表で、一意性を与えているのは評価順であると明記した。
- 失敗条件は 12 項 → 19 項 (spec 側は 24 項)。

## 5. 数値は 3 者が独立に再現した

- 段 3 レンズ B、段 6 レビュー B、親がそれぞれ独立に t 分位点と検出力を計算し、一致した。
  親は `betacf` による正則不完全ベータ関数から t 分布の分位点を自前実装した
  (`verbatim/17-tquant.py.txt`)。
- 多重度 18 (片側) では t = 3.758586、半オクターブの `U_flat` = 2.881〜2.884%、
  対数比 0.11 の短区間では 8.692%。**この差が上限アンカー格子を選んだ根拠である。**
- 最終形は両側 36 の片側限界なので t = 4.255642、`U_flat` = 3.256〜3.259% / 9.783%。
  いずれも半オクターブは 5% 基準に届き、短区間は届かない。
- 探索の低下率は**倍増あたりの点推定**で 29.8〜37.1% (`verbatim/18-explore-slopes.py.txt`)。
  多重度に依存しないので、開示にはこちらを使った。
- 格子・raw 値・3 つの測定順・区間の対数比は、段 6 レビュー B と焦点 2 巡が独立に再生成して一致した。
