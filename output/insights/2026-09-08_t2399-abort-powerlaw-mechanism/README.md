## 0. 結論

依頼は「abort 率が指数 -0.44 から -0.52 の冪則に従う理由」を問うた。答えは 3 つある。

1. **そもそも単一指数の冪則に従っていない。** 3 workload とも log-log は下に曲がる。
   -0.44 から -0.52 は 6 点への直線回帰の傾きであって、局所の傾きではない。
   局所の傾き (隣り合う 2 点を結んだ平均の傾き。以下「区間傾き」) は 150 から 999 マイクロ秒で
   -0.40 から -0.54 まで動く。**この曲がりは測定の精度に対して実在する** (3 節)。
2. **-0.5 に近い値が出る理由には、条件を限れば説明がある。** backoff は abort 経路からのみ
   1 abort につき 1 回だけ入るので、1 commit あたりの 48 worker 集約時間には
   「1 commit あたりの abort 回数 x b」がそのまま乗る。ここに
   **「abort 率は、待ちに使われていない残余時間の割合 f が 0 に近づくところで f の theta 乗のように
   振る舞う」という形の関係 (以下「閉じの式」。未知の関係を仮定して式を閉じるためのモデル)** を置くと、
   大きい b で `alpha ∝ b^(-theta/(1+theta))` になる。**theta が 1 なら指数は -0.5 で、
   指数そのものは当てはめていない** (4 節)。
   **これはこの形の族に限った代数的な帰結である。単調でありさえすればよい、ではない。**
3. **ただしこの閉じの式は、当てはめでは選ばれない。** 自由度をそろえた 3 定数の対抗形
   (2 次 log-log、shifted power、power x exponential) と同じ 1 点除外 score で比べると、
   **balanced では対抗形の方が良く、write-heavy と read-heavy では記録丸めを伝播すると区別できない。**
   閉じの式そのものの適合も、balanced と read-heavy では測定精度の帯を超える (5 節)。
   **よって「この閉じの式が正しい」とは言えない。** 言えるのは、-0.5 近傍の値を生む形が
   1 つに絞れないところまでである。

**答えていないこと。** 因果 (走行中スレッドが減るから abort が減るのか) は観測していない。
theta が workload ごとに違う理由も未確定である。**workload 差については、記述的な再現までしか
答えていない** (6 節)。999 マイクロ秒より上の挙動、他のスレッド数・他の CC への一般化、
adaptive backoff の谷の機序も、本稿の外である。

## 1. 会計 — 恒等な部分と、仮説の部分

観測数を A abort、C commit、経過を tau、worker を 48 とすると、次は定義または代数である。

- `alpha = A/(A+C)`、したがって 1 commit あたりの abort 回数は `a = alpha/(1-alpha) = A/C`
- `T = C/tau`、1 commit あたりの 48 worker 集約時間は `s = 48e6/T` マイクロ秒
- 静的モードでは `Backoff::backoff()` の呼び出しは `TxExecutor::abort()` の中の 1 箇所だけで、
  待ち量は定数 `b` マイクロ秒である。したがって**名目**の待ち総量は `a x b`

**ここから先は恒等式ではない。** 次はいずれも反証可能な仮説である。

- 実際の spin 所要を名目 `b` と同一視できること
- 残余 `y = s - a x b` が、b に依らない定数で `u + a x r` と書けること
- abort 率が f の関数として書けること
- f の低下が abort の低下を**引き起こす**こと

先行解析は `s = u + a(r+b)` を「会計恒等式」と呼んだが、**恒等なのは `a x b` の分離までで、
定数 `u`、`r` は仮説である。** 本稿はこれを分けて扱う。

残余の当てはめ (rep 生値、6 点、等重み):

| workload | `u` (マイクロ秒/commit) | `r` (マイクロ秒/abort) | `r` の rep 対応 bootstrap 95% 区間 | `r` の記録丸め端点範囲 | `y` の最大残差 (%) |

## 4. -0.5 近傍が出る筋道 (条件付きの代数的帰結)

`s = u + a(r+b)`、`a = alpha/(1-alpha)`、`f = (u + a r)/s` の下で、
**f が 0 に近づくところで `alpha` が `f` の theta 乗に比例して振る舞う閉じの式**
(いちばん単純な代表が `alpha = k f^theta`) を連立する。大きい b では `s -> a b`、
`u + a r -> u` なので

    alpha ≈ k (u/(alpha b))^theta   すなわち   alpha^(1+theta) ≈ k u^theta b^(-theta)

となり、**`alpha ∝ b^(-theta/(1+theta))`。** theta = 1 なら指数はちょうど -0.5 である。
**指数は当てはめていない。** 当てはめるのは `u`、`r`、`k`、`theta` であり、指数はそこから出る。

この式の中身は「**待ちが待ちを減らす**」という釣り合いである。b を伸ばすと 1 abort あたりの待ちが増え、
集約時間に占める待ちの割合 phi が上がり、残余 f が下がる。f が下がれば abort 率が下がり、
abort が減れば待ちの総量 `a x b` の伸びが鈍る。この釣り合いの解が代数的な減衰になる。

**適用範囲を限る。** 上の導出が要るのは「f の theta 乗のように振る舞う」という形であって、
**単調でありさえすればよい、ではない。** 実際、5 節で残る対抗形のうち
`C b^g exp(q b)` は q が 0 でなければ固定指数の冪則を漸近形に持たず、2 次 log-log も
一定の漸近指数を持たない。**本測定はこれらを排除していないので、
「指数関数的な減衰にならない」とは書けない。**

区間傾きの閉じた式も書ける。`N = u + a r`、`D = s` として

    g(b) = -theta x phi / (1 + theta x u x (1/N - 1/D)/(1 - alpha))

この点値を Gauss-Legendre 64 点で `d log b` について積分した区間平均は、モデルの端点区間傾きと
1e-10 以内で一致する (実測差は 8.33e-16、1.94e-15、1.33e-15)。
**観測の区間傾きと比べるべきは点値ではなく区間平均である。**

当てはめ結果 (推定量は `observed_alpha_estimating_equation_fit` に統一した。
`theta`、`k`、`g_inf` はすべてこの 1 つから作っている):

| workload | `theta` (95% 区間) | `theta` の記録丸め端点範囲 | `k` | `g_inf = -theta/(1+theta)` | 観測の端点区間傾き |
| --- | --- | --- | ---: | ---: | ---: |
| write-heavy | 1.236827 (1.230621 から 1.242949) | 1.2091 から 1.2656 | 0.900363 | -0.552938 | -0.515601 |
| balanced | 1.058285 (1.052770 から 1.063733) | 1.0371 から 1.0802 | 1.048786 | -0.514159 | -0.479233 |
| read-heavy | 1.006281 (0.997665 から 1.015820) | 0.9815 から 1.0320 | 0.177133 | -0.501565 | -0.439754 |

**`g_inf` はモデルが含意する条件付きの漸近値であって、実測ではない。** 成立条件は
`u`、`r`、`k`、`theta` が一定、alpha が小さい、`a x b` が `u` より十分大きい、`N` が有限の正へ収束すること。
999 マイクロ秒でも phi は 0.9154、0.9340、0.8637 で、f は 0.0846、0.0660、0.1363 である。
**漸近域には達していない。**

`theta` は **alpha 自身を含む量に対する事後の当てはめ値** (記述用の連鎖推定量) である。
**物理的な衝突の弾力性ではない。** `log f` の `log alpha` に対する感度の絶対値は
150 から 999 で write-heavy 4.9322 から 11.2992、balanced 6.3221 から 15.0361、
read-heavy 2.3338 から 6.4895 に達する。**`theta > 1` に物理的な意味を与えない。**
とくに no-wait 検証施錠の衝突次数と結び付けてはならない。

同じ目的関数で theta = 1 と比べた判定は、**閉じの式そのものが適合しない workload では下せない。**

| read-heavy | power x exp | 3 | 0.176 | 0.672 | -0.433 から 0.350 | -1.163 から 0.817 | 記録丸めの下で区別できない |

**read-heavy では、bootstrap だけを見ると 2 次形と shifted power が有意に良いが、
記録丸めを対応差へ伝播すると区間が 0 を含む。** 判定は記録丸めを伝播した側を採る。
balanced は丸めを伝播しても対抗形が良いままである。

**したがって「閉じの式が正しいから -0.5 が出る」とは書けない。** 書けるのは次までである。

- `a x b` が集約時間に入るという会計は、定義と呼び出し位置から従う。
- その上に「f の theta 乗のように振る舞う」形の閉じの式を置けば、大きい b で代数的な減衰になり、
  theta が 1 に近ければ指数は -0.5 に近くなる。
- 本測定はどの形かを選べない。shifted power の `b0` は 13.14、37.68、41.77 マイクロ秒、
  その指数は -0.535、-0.530、-0.492 で、alpha を再利用しない変数だけで同じ帯に着く。
  **これは閉じの式の反証でも、その正しさの証拠でもない。** 区別できないという事実である。

read-heavy では 200,000 回の対応 bootstrap のうち 10 回で閉じの式の解が非物理になった。
両方の扱い (その 10 回を除外する / 閉じの式の失敗として扱う) を標準出力に出してある。

## 6. 窓の指数が -0.5 に届かない分の内訳 (モデル内の条件付き感度)

閉じの式の中で `theta` を 1 に置き換えたときの、対数 b について平均した傾き:

| workload | 自由 theta | theta = 1 | 差 (95% 区間) |
| --- | ---: | ---: | --- |
| write-heavy | -0.515134 | -0.462478 | -0.052656 (-0.053744 から -0.051564) |
| balanced | -0.478744 | -0.465007 | -0.013737 (-0.014919 から -0.012523) |
| read-heavy | -0.439550 | -0.438009 | -0.001541 (-0.003829 から **0.000579**) |

theta を 1 に置き換えても -0.4625、-0.4650、-0.4380 が出る。**observed の帯 -0.44 から -0.52 の
大部分は、phi が 1 に届かないという有限の b の事情から出る。** write-heavy がそれより急な分は
theta の違いに対応する。read-heavy では差の区間が 0 を含むので、置き換えの効果自体が
測定精度で分離できない。

**これはモデルの中でパラメータを置き換えた計算であって、原因の分解ではない。**
phi も theta も `alpha`、`T`、`b` から導かれる量であり、独立に固定できない。
「主因」「寄与」「反実仮想」という因果の言葉をこの分解に使ってはならない。
**しかも 5 節のとおり、このモデル自体が balanced と read-heavy では適合しない。**
**theta が workload ごとに違う理由は未確定である。** したがって
「なぜ workload で指数が違うのか」という問いに対しては、**記述的な再現までしか答えていない。**

## 7. 対抗仮説

**加法的な abort 下限 `alpha = alpha0 + c b^g`。** 無制約の最良当てはめは 3 workload とも
`alpha0` が負 (-0.005341、-0.023047、-0.011487) で、記録丸め端点範囲も負である。
`alpha0 >= 0` を課すと最大誤差は 0.731%、1.655%、1.552% となり、rep 精度の帯
(0.226%、0.385%、0.183%) を超えて適合しない。
**片側 95% 上限は与えない。** 無制約 bootstrap の分位を 0 で切っても、それは境界制約を
扱った検定の反転ではないので、校正された上限ではない。判定は
「制約付きの族は支持されず、無制約の点推定と記録丸め端点範囲は負」までである。
**「正の下限を反証した」とは書かない。** 正の下限があれば区間傾きは漸近的に平坦化するので、
観測された下向きの曲がりとは向きが逆である、という定性的な整合は付く。

**f と commit 到着率という 2 つの代理。** `N = u + a r` の最大と最小の比から 1 を引いた値は
0.0667、0.0692、0.0248 である。同じ score 契約で 2 つの代理を比べると、3 workload とも
区別できない。**どちらの代理が正しいかは本測定では決まらない。**
ただし 4 節の漸近形はどちらでも同じなので、4 節の結論はこの未決着に依存しない。

## 8. 先行知見との関係

先行解析 `2026-09-07_backoff-tail-mechanism` は候補 H として `alpha = k f` を記録し、
正確な比例則としては破れていると結論した。**本稿はその上書きではなく、tail 6 点に限った事後的な追補である。**

- 本稿の閉じの式 `alpha = k f^theta` は、H に定数を 1 つ足した入れ子の一般化である。
  **theta = 1 が H に当たる。**
- **定数を足して範囲を狭めれば適合が良くなるのは当然であり、機序の証拠の強化ではない。**
  実際、閉じの式の適合は balanced と read-heavy で rep 精度の帯を超えており、支持されない。
- 先行解析が「待ち時間そのものが集約時間の 7 割から 9 割」と述べた点は、本稿の phi = 0.688 から 0.934 と
  同じ量である。**本稿が足したのは、その残りがどう abort 率へ返るかという形と、
  その形が 1 つに絞れないという判定である。**
- **静的 tail の機序を adaptive backoff の非単調性の機序として読んではならない** (D1637)。
  本稿は固定 b の応答だけを扱い、滞在分布・遷移損失・谷を説明しない。

## 9. 言えること・言えないこと

- **因果は未確定である。** 「走行中スレッドが減るから abort が減る」は観測していない。
  backoff は spin であってコアを占有するので、**f を走行中スレッド数の代理と呼んではならない。**
  f は「48 worker の集約時間に占める、名目 backoff 以外の残余時間の割合」でしかない。
  同じ f でも、全スレッドが薄く動く場合、一部が集中して動く場合、同期した burst がある場合とで、
  瞬間の競合数は異なる。平均から同時性の分布は復元できない。
  反証に要る観測は次で、いずれも診断ビルドが要る (規律 1 により性能計測とは別ビルド・別 run)。
  - 各スレッドの spin、trx 実行、検証の時系列から得た瞬間 active-count の分布
  - abort 原因別の、直前 active-count と phase 重なりで条件づけた hazard
  - 同じ平均 f のまま同時性や burst 構造だけを変えたときに alpha が同じか
- **定数費用 `u`、`r` は仮説であり、恒等式ではない。** tail 6 点では残差 0.351%、0.700%、0.200% に
  収まるが、これは「追加の正の費用を要求しない」という記述であって、convoy、cache 汚染、
  leader の飢餓の不存在を示さない。
- **999 マイクロ秒は測定格子の右端であって、abort の抑制が飽和した点ではない。**
  静的値の符号化上限は 2026-09-08 に 999 から 9999 マイクロ秒へ広がった
  (`output/insights/2026-09-08_backoff-static-ceiling/README.md`) が、
  **1000 マイクロ秒以上の実測は 1 点も無い。** 1000 マイクロ秒超の測定は [T-2418] の裁定待ちである。
- **記録分解能 0.0001 が推定の精度を制限する。** とくに read-heavy の `r` は丸めだけで 0.83 から 4.86 まで動く。
- **単一環境・単一 job である** (Pegasus 48 物理コア、gen_S)。
  5 rep はいずれも同じ job 内なので、job 間・ノード間のばらつきは評価できない。
- **report の `correctness_verified` は report に記録された field であって、certification ではない。**
  材料は trace-disabled で直列性を検査していない。
- 6 点に 4 定数を当てているので、有効な残差の自由度は小さい。**予測・holdout・認証と呼んではならない。**

## 12. 判定表

**主張の種類ごとに分けて読む。** 「判定が変わる条件」は反証条件と同じではない — 定義や代数の行は
経験的な判定の対象ではなく、条件付きの代数的帰結の行はモデルの経験的妥当性とは別である。
