## gate の禁止 (署名) と通る正例

- **禁止**: `audit_dangling_commits` は、到達不能 commit `C` について
  `unreachable(C) ∧ (∃f ∈ changed(C): f ∉ tree(main) ∧ ∀b ∈ branch_tips: f ∉ tree(b))` を満たすとき
  だけ報告する。3 条件の連言のいずれかを落として報告してはならない。
- **通る正例**: 現行 repo の実走で報告 0 件。`95fd6d0c` (中身が main にある insight) と
  `e4fcf748` (上位版 rotation が main にある fold commit) は報告されない。

## 変異事前登録 (B-057、実装前)

実装はこれから Codex が書くため、位置は**意味論**で先に固定する。段 5 完了後、matrix を走らせる
前に各変異を file:line へ束縛し、「同じ入力を拒否する層が前後に無い」「無効化時の赤理由が一つ」を
コードで確認する。確認できない変異は登録を取り下げ、実効 gate へ再照準する (F28)。

| # | 変異 (無効化する判定) | 期待する唯一の赤理由 |
|---|---|---|
| M1 | 判定 1「到達不能性」を外し全 commit を候補にする | negative control「main に到達可能な commit は報告しない」が赤 |
| M2 | 判定 2「変更ファイルが main に不在」を常に真にする | negative control「中身が main にある到達不能 commit は報告しない」が赤 |
| M3 | 判定 3「他のどのブランチ先端にも無い」を常に真にする | negative control「生きたブランチの tip は報告しない」が赤 |
| M4 | 既定除外 (`docs/spool/`, `docs/archive/`) を外す | negative control「fold が消費する経路は報告しない」が赤 |
| M5 | 報告経路を no-op にする (常に「0 件」を返す) | positive control「ブランチごと消した未 land 作業は必ず鳴る」が赤 |

- M5 は I2 の恒真性検査である。M5 で positive control が緑のままなら、その control は何も検査して
  いない (`DW-M02`/`DW-M08` へ回す)。

## 追加登録 (段 6 の親実測 P-1 を受けて、fix 実装の前に登録する)

親が現行 repo で実走して **3 件の誤検出**を実測した (不変条件 I1 違反)。機序は
「main の**現在の tree**にしか照会せず、main の履歴に実在して改名・削除された path を
失われた作業と誤認する」ことである (`orchestrator/campaign/reflux_origin_authority_v1.json`、
`e6349be8` 作成 → `61fc5202` 削除、どちらも main 上、`..._v2.json` へ置換)。

**裁定: 判定に第 4 条件を足す。** 既存 3 条件を通過した path について
`git rev-list --all --max-count=1 -- <path>` が空であること (= 到達可能な ref の履歴のどこにも
その path が現れないこと) を要求する。既存 3 条件は安価な prefilter として残す
(第 4 条件は 1 path あたり実測 0.08〜0.10 秒であり、prefilter 前の全 path へ回すと高くつく)。

| # | 変異 | 期待する唯一の赤理由 |
|---|---|---|
| M6 | 第 4 条件 (到達可能履歴への出現) を常に真にする | 新設 negative control「main の履歴に在って現在の tree から消えた path は報告しない」が赤 |

- 追加する negative control 1 本を必須とする。内容 = 合成 repo で main 上に path を作り、
  main 上で削除 (または改名) し、その path を変更した到達不能 commit を残す。報告 0 件を要求する。
- 第 4 条件は既存条件 2・3 を意味論的に包含するが、M2・M3 の単一理由性は保たれる —
  各 negative control は prefilter 段で落ちるため、条件 2・3 を無効化すると
  第 4 条件が拾う前にその control が赤になる…とは限らない。**fix 後に M2・M3 が
  SURVIVED になったら、それは第 4 条件による mask であり `DW-M02` に従って
  両層同時変異まで裏取りする。**
- **受理集合を縮小する wave ではない** (新規検出器の追加であり、既存の受理を狭めない) が、
  I1 のため「通る正例 = 現行 repo で 0 件」を M1〜M4 の各走で併せて観測する。
