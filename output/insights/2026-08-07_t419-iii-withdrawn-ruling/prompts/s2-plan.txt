## 依頼

段 1 brief の scope に対する **file:line 粒度の実装プラン**を書け。目的は
「publish 済み較正 artifact を、それを作った process の外から、bytes だけを入力に判定し、
判定を第三者が再計算できる artifact として残す」ことである。

プランには最低限これを含めること。

1. 新規 module / entry の正確な path と、既存 module のどの関数の直後に何行入るか (file:line)。
2. 判定 artifact の JSON schema (key を全部列挙。値の型と、何を preimage として残すか)。
   第三者が **artifact だけから** 判定を再計算できることを要件とする。
3. 既存テストのどれが影響を受けるか。特に:
   - `output/env/pegasus` を rglob する exact 集合 test に新ファイルが引っかからないか
   - `attempts/*/calibration.md` の exact 集合、48 件の count pin
   - `check_docs.py` / `run_tests.py` の untracked・削除検査
4. 新規テストの nodeid 案と、それぞれが**何を壊したら赤くなるか** (恒真なテストを書かない)。
   実 artifact 2 件 (94a4=accept / 753f=reject) を固定 vector にする形を具体的に書け。
5. `certify_calibration.sh` へ結線する場合の正確な挿入位置と、失敗時の rc の扱い。
   publish 済み artifact を削除しないこと (D191 決定 4) を守る形にすること。
6. 変異事前登録の候補: 「この 1 行を壊したらこの nodeid が赤くなる」を最低 6 件、
   期待赤 node を**具体的な nodeid で**書け。冗長 (複数層が同時に赤くなる) なものはそう明記せよ。
