## 直し方 (方針は親が裁定済み)

**production 側を直す。**新設検査は、対象節が**構造的に健全なときだけ**走らせる
(可視 H2 が一意で、byte slice と 1:1 であるとき)。節の構造が既に壊れている入力は、
既存の H2 一意性検査・slice 1:1 検査・`DW-O01` cardinality 検査が既に赤にしているので、
新設検査が重ねて報告する必要はない。`tools/check_docs.py` には同型の先例がある —
`_check_dev_wave_layer_budget` は `_dev_wave_visible_inventory_is_exact()` が真のときだけ走る。
同じ規律に揃えること。

## 禁止事項 (守らないと差し戻す)

- **上記 2 つの既存テストの期待値を変更しない。**反転・緩和・skip・削除・件数の書き換えを禁じる。
  これらは tracked な既存テストであり、赤なのは新設検査側が誤っているためである。
- **新設検査を fail-open にして辻褄を合わせない。**「構造健全なときだけ走る」であって
  「エラー時は黙って通す」ではない。段 5 が追加した negative 9 件は**全て赤のままでなければならない**
  (これらは構造が健全なまま義務だけを壊す入力なので、guard を入れても発火し続けるはずである)。
- 予算定数 (`DEV_WAVE_L1_BYTES_MAX` / `DEV_WAVE_L1_5_BYTES_MAX` /
  `DEV_WAVE_L2_SECTION_BYTES_MAX` / `COMMAND_LIMITS`) を変更しない。
- `REQUIRED_REFERENCE_SECTIONS` / `STAGE_UNCONDITIONAL_DISPATCH_CONTRACT` /
  `CONDITION_DISPATCH_CONTRACT` を変更しない。
- docs (`docs/**`、`.claude/commands/**`) を編集しない。commit しない。

段 5 が追加した**未 commit のテスト**は編集対象に含めてよい。ただし編集してよいのは
