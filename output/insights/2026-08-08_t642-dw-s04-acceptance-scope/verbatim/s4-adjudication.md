## ユーザーへ返す裁定パッケージ (scope 外の real 所見)

1. **受入全走の免除判定を自己申告のままにするか (A1/A5/B4)。** 改訂後も「実 repo を読むテストが
   あるか」の判定主体は wave 親であり、判定証拠 (nodeid・検索手順) の記録義務も、旧文への回帰を
   拒む機械 pin もない。選択肢は (a) 現状受容 (意味レビューのみ)、(b) 判定証拠の worklog 記録を
   契約に足す、(c) `tools/check_docs.py` 側に本文 literal pin を置く (dev-wave の byte 予算とは別枠)。
   **成果物影響:** (a) のままだと、docs のみの wave が全走を省いて台帳・成果物索引の赤を
   land 前に検出できない経路が残る。
   **親の推奨 = (b)。** 判定証拠 (該当 nodeid か「不存在」の判定手順) を worklog へ書く義務は
   契約 1 文で足り、byte も既に 5 空いた。(c) の本文 literal pin は `check_docs.py` 側の予算で
   実装できるが、契約文の言い回しを固定すると将来の改訂ごとに pin 更新が要るため次善とする

   前向き supersession の記録だけを行い、遡及改変しない。これで足りるかは裁定対象。
   **親の推奨 = 現状 (前向き supersession のみ)。** 過去の decisions は wave-local な当時の決定で
