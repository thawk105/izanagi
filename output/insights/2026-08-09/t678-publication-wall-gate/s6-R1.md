### backlog 1 — `replace_invalid=True` の所有・inode 経路が回帰テストで固定されていない

- **主張:** N3 は通常の `os.link` 経路だけを固定しており、invalid partial を置換する `os.replace` 経路では exact staged inode と cleanup が未固定。
- **根拠:** N3 は事前に partial receipt を作らない（[orchestrator/tests/test_codex_worker_launch.py:2154](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t678-publication-wall-gate/orchestrator/tests/test_codex_worker_launch.py:2154)）。partial 置換テストは outcome だけを見る（[orchestrator/tests/test_codex_worker_launch.py:3114](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t678-publication-wall-gate/orchestrator/tests/test_codex_worker_launch.py:3114)）。
- **影響:** 現実装の `os.replace` は staged inode を final path へ移し、temp 名も消すため、現時点の receipt/output/rc に静的な不整合はない。ただし将来この分岐だけ再書込みへ戻っても N3 が検出しない。
- **提案:** N3 を「final 不在／invalid partial あり」で parameterize し、Path・inode・temp 不在を両方で確認する。異常系も `os.link`／`os.replace` の syscall failure を各1件固定する。

## temp 所有と atomic publication

静的な所有移転は一貫している。

- `replace_invalid=False`: `os.link` 後も temp 名が残るため、成功時は helper の `finally` が temp 名だけを消す（[tools/codex_worker_launch.py:464](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t678-publication-wall-gate/tools/codex_worker_launch.py:464)）。
- `replace_invalid=True`: `os.replace` が temp 名を消費し、`finally` の再 unlink は `OSError` として無害に吸収される（[tools/codex_worker_launch.py:461](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t678-publication-wall-gate/tools/codex_worker_launch.py:461)）。
- syscall 後の `_fsync_parent` 例外では、公開済み final を unlink・再 fsyncしてから temp cleanup へ進む（[tools/codex_worker_launch.py:465](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t678-publication-wall-gate/tools/codex_worker_launch.py:465)）。
- `_atomic_create_json`、`_run_supervised`、launcher-error fallback は、helper 呼出し直前に caller 側変数を `None` にし、helper へ移す前だけ caller `finally` が所有する（[tools/codex_worker_launch.py:488](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t678-publication-wall-gate/tools/codex_worker_launch.py:488)、[tools/codex_worker_launch.py:1813](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t678-publication-wall-gate/tools/codex_worker_launch.py:1813)、[tools/codex_worker_launch.py:1861](/work/1/SFC/tanab/izanagi/.claude/worktrees/dev-wave-t678-publication-wall-gate/tools/codex_worker_launch.py:1861)）。

通常の同期例外では二重所有、二重 unlink による成果物破壊、所有の宙吊りは認めなかった。atomic create 後の不可逆例外は親裁定の S-C／S-F であり、再分類していない。
