## Must-fix

### MF-1：N3 は変更前赤と MT2 kill が意味的に無効

- **主張**：N3 は「旧 production が別 temp を作る」ことを検出する node として登録されているが、変更前はその assert まで到達しない。
- **根拠**：変更前 `_stage_receipt_write` は `None` を返す（`s5-integrated.patch:281-284`）。N3 は直後に `temporary.stat()` を呼ぶ（`orchestrator/tests/test_codex_worker_launch.py:2164-2166`）。
- **影響**：変更前は意味のある assert ではなく `AttributeError` で落ちる。MT2 も同じ観測器依存の例外になり得る。これを mutation harness が kill と数えると、実際には `receipt.outcome=accepted`、`launcher_rc=0`、output 存在の回帰を誤って検出済みと扱う。
- **成果物影響**：未修正なら、二重 temp write に戻った変異が `accepted / rc=0 / output 実在`のままでも、N3 の検出力を過大評価して land する可能性がある。
- **提案**：`_atomic_create_json_reserved` の signature に依存せず、`_write_json_temp`（`tools/codex_worker_launch.py:372`）を記録する。正常経路は temp 作成 1 回、最終 receipt の inode がその最初の temp と同一、という production-visible な assert にする。
