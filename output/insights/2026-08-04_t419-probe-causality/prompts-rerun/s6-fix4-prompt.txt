## 直すこと (erratum-5)

abort (INVALID + 後続 arm 停止) を **signal CPU の率超えだけ**に限定する。

- **signal CPU** = その subwindow の
  `{reader の CPU} ∪ {pin target があればそれ} ∪ {A2 の target があればそれ}`。
- signal CPU で `unexplained >= 3 tick` かつ `> 25.0 tick/s` → 従来どおり `COMPETITOR`
  (arm を INVALID にし後続を止める)。
- **非 signal CPU での率超えは `ATTRIBUTION_UNRESOLVED` とし、abort しない。**
  次を必ず記録する: 対象 CPU の集合、各 CPU の率と duration、
  **その CPU が control (= pin target でも reader でもない) として帯外に現れた読みの件数との交差**。
  field 名は README から参照するので安定した名前にすること。
- 既存の `nonpinned_out_of_band_rate <= 0.05` 条件は**そのまま**残す (統計的な歯止め)。

## 単一理由 fixture を足す

1. **signal CPU** (reader または target) で率超え → `COMPETITOR` + INVALID + 後続停止。
2. **非 signal CPU** で率超え → `ATTRIBUTION_UNRESOLVED` + **arm は VALID** + 後続は止まらない。
   交差の記録が出ていること。
3. 1 と 2 の**両方**が同一 subwindow で起きたら `COMPETITOR` が勝つこと。
