## 親の裁定

### M-1 (b1) 窓内 migration を検出したら self 帰属を撤回する

現状は両端 affinity から per-CPU 帰属を決め、窓内 migration を検出しても**その帰属を撤回していない**。
検出した時点でその自 process の **per-CPU 帰属を取り消し、全量を
`self_unattributable_total` へ移す**こと。endpoint 由来の帰属を残さない。
単一理由 fixture を足す: **両端の affinity が同一 singleton なのに窓内で移動した self**
(equal-singleton return migration) → per-CPU 帰属されず、`ATTRIBUTION_UNRESOLVED` になる。

### M-2 (b2) `migration_detected` の意味を正す

現状は「affinity が singleton でない」ことを migration と記録しており、非 pin の reader が
常に migration 扱いになる。次の 2 つを**別 field** に分ける。

- `affinity_not_singleton`: 単一 CPU に固定されていない (= per-CPU 帰属できない)。
- `migration_observed`: 実際に走行 CPU が変わったことを観測した。

どちらも per-CPU 帰属は行わない (全量 unattributable) が、**記録上は区別する**。
A4 (migration 記述 arm) と因果レポートがこの 2 つを混同しないこと。

### M-3 (erratum-4) 閾値を実測に基づき再較正する

`COMPETITOR_MAX_TICKS_PER_SECOND` を **6.7 → 25.0** にする。docstring の根拠を次へ差し替える:

「走行 889279 の実測 65 subwindow で、非自活動の率は中央値 0.00 / 最大 11.86 tick/s。
その活動は読み値を汚していない — A1 の control 観測 11,280 件のうち帯外は 1 件 (0.0089%) で、
率 7.9 tick/s の subwindow が 4 つあっても control 帯外は増えなかった。
一方 A2 が置く busy child は 1 コア占有で約 100 tick/s。
25.0 は観測された背景最大 11.86 の約 2 倍、1 コア占有の約 1/4 であり、
背景ノイズと実負荷を分離する。絶対下限 3 tick は据え置き。」

**因果判定の 3 条件 (0.95 / 0.05 / 46) は 1 bit も変えない。**
テストで 25.0 の値そのものと、絶対下限 3 tick の境界 (2 tick は通る / 3 tick かつ率超えは落ちる) を固定する。
