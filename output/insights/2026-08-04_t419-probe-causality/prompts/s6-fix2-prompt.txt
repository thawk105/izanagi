## 親の裁定 (これが最優先。レビューの是正案と食い違う場合は本裁定が勝つ)

### G-1 (R1-6 / R2-3 の regressed、最重要) 単独性 attribution を三値にする

**親が意味論を確定した。次のとおり実装せよ。**

- **process 帰属可能 tick** = `/proc/stat` の `user + nice + system + guest`。
  **`irq` / `softirq` / `steal` / `idle` / `iowait` は帰属計算に入れない** (別 field として診断へ記録)。
- **CPU 横断の相殺を禁止**する。residual は CPU ごとに `max(0, proc_delta_cpu −
  self_attributed_cpu)` を計算し、その総和を `residual_total` とする。
- 自 tree の帰属は **PID + starttime** で束縛する。pin されている自 process (A1 の reader、
  A2 の child) の tick は pin 先 CPU へ厳密に帰属させる。pin されていない自 process
  (A0/A3/A4 の reader) の tick は特定 CPU へ確定できないので `self_unattributable_total` に入れる。
- **三値** (`isolation_attribution`):
  - `CLEAN`: `residual_total == 0` かつ非自 PID の正の delta が snapshot に無い。
  - `COMPETITOR`: 非自 PID が正の CPU-time delta を持って snapshot に現れる、
    **または** `residual_total > self_unattributable_total` (自分の消費では説明できない量)。
  - `ATTRIBUTION_UNRESOLVED`: 上記以外 (`0 < residual_total <= self_unattributable_total`)。
- **validity への効き方 (ここを間違えないこと)**:
  - `COMPETITOR` → その arm は `INVALID`、かつ**後続 arm を走らせない**。
  - `ATTRIBUTION_UNRESOLVED` → **arm は VALID のまま**。`residual_total` と
    `self_unattributable_total` を必ず結果へ記録する (曖昧さの上界を残すため)。
  - `CLEAN` → VALID。
  - 理由: 曖昧量が自分の消費以下に収まる限り、偽 `CONFIRMED` を作るには「試験対象 CPU 上で
    自分より少ない CPU を使う競合」が必要であり、それは A1 の非 pin 側帯外率 (≤ 0.05 条件) に
    現れる。**この判断根拠をコードの docstring に 1 行で書け。**
- **単一理由 fixture を 4 本**追加する: (a) irq/softirq だけの tick → `CLEAN` (通ること)、
  (b) 非 pin reader の migration → `ATTRIBUTION_UNRESOLVED` かつ VALID、
  (c) 短命非自 process で `residual_total > self_unattributable_total` → `COMPETITOR` かつ
  INVALID かつ後続停止、(d) snapshot に非自 PID が正 delta → `COMPETITOR`。

### G-2 (R1-2) band の不変性を外部 oracle で固定する

`lower=98.0` / `upper=102.0` (median 100.0、tolerance 2.0) を**テスト側の literal** で固定し、
`97.999` と `102.001` が拒否されることを assert する。`valid_band()` は
`lower == median − median*tolerance/100` と `upper == median + median*tolerance/100` の
**数式的一致**を検査する (band を勝手に広げる変異が赤になること)。

### G-3 (R1-3) pin 順の再現性を検査する

seed から期待 permutation を再計算し、`pin_order` および flat reads の 5 件群の順序が
それと一致することを validity で検査する。`rng.shuffle` を消して sorted 順にする変異が
赤になる正例・反例を追加する。

### G-4 (R1-4) child 証拠の算術整合と sham 上限を検査する

- `cpu_ticks_delta == end_ticks − start_ticks` の算術一致、PID と starttime の同一性を検査する。
- **親の裁定した閾値**: busy child は当該 condition で **5 tick 以上**、sham child は
  **1 tick 以下**。逸脱した pair は `INCONCLUSIVE`。
  **`INCONCLUSIVE` の pair が 8 対中 3 対以上なら A2 arm を INVALID** とする。
- 定数として外出しし、テスト側 literal で固定する。

### G-5 (R1-5) validity を total にする

`execution_validity_reasons()` は**あらゆる入力で例外を投げない** (total 関数)。
`mode` の型不正、MHz 値の非有限・非正、想定外の型はすべて validity reason にする。
`sorted(["busy", None])` 型の TypeError 経路を塞ぐ。単一理由 fixture を追加する。

### G-7 (R2-5) rc の命名と wrapper の最終 rc

- `result.json` の `"wrapper.rc"` を `probe_rc` へ改名する (probe の rc であって wrapper の rc ではない)。

  driver の docstring と PBS のコメントに明記する。
- `.o/.e` と qstat 会計の receipt 化は**親の作業**なので実装しない。

### G-8 (R2-6) 実行中 race と queue/project の照合

- **finalization 時に** driver / PBS / 較正 / `env_attestation.py` の現在 hash を
  **submission expected と再照合**する (開始時だけでなく終了時も)。不一致は INVALID。
- queue/project は非空検査でやめ、`PBS_QUEUE` または `PBS_O_QUEUE` 等の scheduler 由来 env と
  `T419_QUEUE` / `T419_PROJECT` の一致を検査する。取得できない env は `unavailable` として
  記録し、**それ自体は INVALID にしない** (記録のみ)。
- `repo_dirty` は **probe 自身が作る出力 dir を除外**して計算する
  (自分の出力で常に dirty になるのは証拠にならない)。所有 3 ファイルの hash 一致は別途厳密に検査する。

### G-9 (R2-1 の backlog) `late` を意味のある量にする

`late` は恒真になっている。`lateness_ns` (scheduled deadline と実 `started` の差) を記録し、
`late` は `lateness_ns > read_interval_ms * 1e6 / 2` のときだけ真にする。
