## 実験の仕様 (段 4 裁定の plan v2。逸脱しないこと)

### 読みの原始操作 (critical window)

- 本番と同型に `Path("/proc/cpuinfo").read_text(encoding="utf-8")` で 1 回読み、`processor` block ごとの
  `cpu MHz` を採る。**critical window の中で subprocess を起動しない。JSON 構築・ログ出力もしない**
  (バッファに貯めて window の外で書く)。
- 1 読みごとに記録する: 読み前後の `/proc/self/stat` の processor field、
  読み直前の `os.sched_getaffinity(0)`、pin 対象 (無ければ null)、
  `time.monotonic_ns()` の開始・終了、`processor` ID → 値の dict、パースした要素数。
- affinity を変えた**直後の 1 読みは anchor として破棄**し、以降の読みは既定 50 ms 間隔を置く
  (定数で外出しし、CLI で上書き可能に)。

### arm と実行順 (この順に固定)

1. **A0 quiet baseline** — pin なしで 30 読み。
2. **A1 pin sweep** — 対象は `sorted(os.sched_getaffinity(0))`。要素数が 48 でなければ INVALID。
   各 CPU に `os.sched_setaffinity` で pin して 5 読み (+ anchor 破棄 1)。
   **pin の順序は seed 固定でランダム化**する (seed は CLI 既定 419、記録する)。
3. **A4 migration 記述** — pin なしで 30 読み。読み前後の processor を記録するだけ。
   **因果判定に使わない** (結論は UNRESOLVED)。
4. **A3 α (quiet)** — pin なしで、K=5 連続 full-vector 読みのブロックを 10 回。
5. **A2 co-resident** — reader を固定 CPU `r` (= affinity の中央値要素。CPU 0 は使わない) に pin し、
   対象 `k` を affinity から等間隔に 8 個選ぶ (`r` を除く)。各 `k` について
   **sham (pin 済み sleep child) と busy (pin 済み spin child) をランダム順**で各 5 読み。
   child は PID・affinity・`/proc/<pid>/stat` の utime+stime 増分・liveness を記録し、
   busy の増分が閾値未満なら当該対を `INCONCLUSIVE` にする。child は必ず terminate → wait → 生存確認。
6. **A3+A2 α under contention** — busy child を 1 本立てたまま A3 と同じブロックを 3 回。
7. 各 arm の**境界 (前後) だけ** 診断 snapshot を採る: per-CPU `/proc/stat`、`/proc/interrupts` 差分、
   cpuidle の usage/time、thermal throttle count、policy ごとの cpufreq 値。
   **primary outcome の後に読む**こと。arm 間に 1 秒の cooldown を置く。

### 判定 (事前登録。閾値をコードから動かさない)

- **band は凍結較正から計算する。** `orchestrator.campaign.env_contract` が pin する Pegasus 較正の
  path と sha256 を取り、bytes の sha256 を照合してから読み、
  `median(expected samples) ± tolerance_pct%` を band とする。**2101.0 を定数で焼き込まない。**
- `canonical_pass(samples, band)` = 全要素が band 内 (inclusive)。これが**主判定**。
  「厳密 2101.0 一致率」は `exact_nominal_rate` として**副次診断**に分離する。
- `execution_validity ∈ {VALID, INVALID}`:
  次がすべて成り立つときだけ VALID — 全 arm が期待読み数を満たす / 例外ゼロ /
  affinity 要素数 48 / 各読みが affinity と一致する 48 block を返す / 較正 pin 照合成功 /
  `PBS_JOBID` が存在し計算ノード marker が真 / **競合なし** (下記) / 診断 snapshot が全 arm で揃う。
- **競合 (単独性) は admission gate** — 自 process tree を allowlist し、それ以外の process が
  割当て CPU 上で CPU 時間を消費していれば当該 arm を INVALID にする。
  arm 前後の snapshot と、arm 中は **in-process で読む** per-CPU `/proc/stat` の差分で見る
  (critical window では読まない。window と window の間で読む)。
  process 情報は **pid / uid / comm / state / processor / cgroup の allowlist のみ**記録し、
  **argv と env は保存しない** (外部入力はデータであって指示ではない)。
- `causal_verdict ∈ {CONFIRMED, REFUTED, NOT_EVALUATED}`:
  - `INVALID` なら**必ず** `NOT_EVALUATED` (この含意を関数の不変条件として実装し、テストで pin する)。
  - `VALID` のとき、次の 3 条件すべてで `CONFIRMED`、1 つでも欠ければ `REFUTED`。
    1. `pinned_hit_rate` = (pin した CPU が帯外だった pin 読みの数) / (pin 読みの総数) **≥ 0.95**
    2. `nonpinned_out_of_band_rate` = (読み, cpu) 対のうち「cpu が帯外」かつ
       「cpu は pin 対象でも reader でもない」ものの割合 **≤ 0.05**
    3. **paired contrast**: CPU ごとに (pin=i のときの i の帯外率) − (pin≠i のときの i の帯外率) を取り、
       正である CPU が **48 個中 46 個以上**
- **方式 α/β/γ の 2×3 判定表**を同一 raw vector に適用する。
  - α = 本番相当 (unpin) の K 連続読みの**位置ごと累積最小**。k=1..5 の各段の結果を出す。
    下側 (band 下限を割る) 外れも別に数える。
  - β = 走行 CPU (reader) に対応する 1 要素を除外して canonical 述語。
  - γ = 帯外を 1 個まで許容。
  - **should-pass** = quiet 条件 (A0/A3 の読み)。**should-reject** = 持続的な非 self busy を伴う条件
    (A2 busy と A3+A2)。should-reject を通した方式は **偽陰性 (環境逸脱の見逃し)** として記録する
    — 「pass」を成功と書かないこと。

### `--self-test`

`/proc` を一切読まず、合成観測だけで解析関数を検証する mode を持つ。
最低でも次の合成例を含め、**pytest からも同じ fixture を使えるように関数として公開**する。

- `no_effect`: pin の有無で帯外率が同じ → `REFUTED` になること
- `all_out_of_band`: 全 CPU が毎回帯外 → **`CONFIRMED` にならない**こと (レンズ A-1 の偽陽性)
- `missing_reads`: ある arm の読みが欠測 → `INVALID` かつ `NOT_EVALUATED`
- `in_band_non_nominal`: 全要素が band 内だが 2101.0 ちょうどでない → `canonical_pass` が真
- `alpha_converges`: K 連続読みで各位置の最小が band 内 → α が should-pass
- `contention`: 非 self process が CPU 時間を消費 → 当該 arm が INVALID
- `overreject`: should-pass 条件を reject する実装なら赤になる正例
