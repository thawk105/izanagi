## 親の裁定 (レビューの是正案と食い違う場合は本裁定が勝つ)

### H-1 (F2-01) child tick を全生存期間で帰属する

busy/sham child の tick は **fork から reap まで**を pin 先 CPU へ帰属させる。
readiness 後〜terminate 前だけでなく、fork→start snapshot と end snapshot→reap の端も含める。
非零 `start_cpu_ticks` と終了端 tick を持つ単一理由 fixture を追加し、
「端の 1 tick が COMPETITOR になる」経路が閉じたことを示せ。

### H-2 (F2-02) 境界の測定窓を親の指定順に固定する

**self の観測窓が CPU counter の窓を必ず包含する向き**に揃える。

- arm **開始**: process snapshot → その後に CPU counter。
- arm **終了**: CPU counter → その後に process snapshot。

これにより self delta の窓 ⊇ CPU delta の窓となり、**偽 COMPETITOR (単独 job の自滅) を作らない**。
代償として、窓のずれの中に隠れる競合が理論上ありうるので、両端の timestamp と
`window_skew_ns` を必ず結果へ記録し、docstring に「隠れうる量の上界は skew 区間である」と 1 行書け。
順序と skew 記録を固定する単一理由 fixture を追加する。

### H-3 (F2-03) CPU 横断相殺の禁止をテストで固定する

isolation の fixture を **複数 CPU** に跨がる形にし、「総和してから self を引く」実装へ変えると
赤になるようにする (現行 fixture は実質 1 CPU なのでこの回帰が生存している)。

### H-4 (F2-04) sham の inclusive 境界を固定する

sham の `1 tick` が**通る**ことと `2 tick` が拒否されることの両方をテスト側 literal で固定する。
busy 側も `5 tick` が通り `4 tick` が拒否されることを固定する。

### H-5 (F2-05) coercible な異常型を拒否する

CPU key と MHz 値は `int()` / `float()` へ変換する前に**厳密な型検査**を行う。
`"0"` / `"110.0"` のような str、`True` / `False` のような bool は拒否する
(bool は int の subclass なので明示的に弾くこと)。validity reason として扱い、例外にしない。
単一理由 fixture を追加する。

### H-6 (F2-06) final binding の INVALID を rc へ伝播する

final hash mismatch (driver / PBS / 較正 / `env_attestation.py` / HEAD) を検出したら:

- driver は **非零 rc** で終了する。
- PBS wrapper は その rc を `wrapper.rc` へ書き、**done-marker を作らない**。
- 「done-marker が無い出力は不採用」を PBS のコメントと driver の docstring に明記する
  (既に書いてあれば維持)。
