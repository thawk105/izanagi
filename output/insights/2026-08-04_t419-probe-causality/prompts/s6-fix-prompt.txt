### F-1 (R2-1、最重要) critical series の純度と固定間隔

- read と read の間に全 PID 走査・`/proc/stat` 読み・大きな dict 構築を挟まない。
  **isolation sampling と診断は arm 境界へ移す** (arm 前後だけ)。
- read の開始時刻を **monotonic deadline** で固定する (「後処理が終わってから 50 ms sleep」ではなく
  「前回開始 + 50 ms に次を開始」)。deadline を守れなかった read は記録に `late: true` を残す。
- どうしても系列内で sampling が要る場合は、sampling の**直後の 1 読みを anchor として破棄**する。

### F-2 (R1-2、R1-1) oracle をテスト側へ出し、M1 を殺す fixture を足す

- 期待 verdict・閾値・境界の assertion を `orchestrator/tests/test_t419_probe_causality.py` へ移す。
  driver 側には **fixture の構築だけ**を残し、`assert_synthetic_fixture` の期待値 literal に
  依存しない形にする (driver 側 self-test は残してよいが、pytest の正本はテストファイル)。
- テストで独立に固定する: 定数 `PINNED_HIT_RATE_MIN=0.95` / `NONPINNED_OUT_OF_BAND_RATE_MAX=0.05` /
  `POSITIVE_CONTRAST_CPU_MIN=46` の値そのもの、**境界ちょうど**の入力 (0.95 / 0.05 / 46 と
  band 上下限ちょうど)、偶数個 median、NaN/inf、空 vector。`>=`↔`>`、`<=`↔`<` の取り違えが
  必ず赤になるようにする。
- **M1 専用の単一理由 fixture** を足す (レビュー R1-1 の推奨をそのまま使う):
  3 CPU だけ pinned=1/5・control=47/235、残り 45 CPU は pinned=5/5・control=0。
  → pinned_hit_rate と nonpinned rate は条件を満たし、**paired contrast だけが偽**になる。
  この fixture が `REFUTED` を期待し、contrast を恒真化すると赤になること。

### F-3 (R1-3) A1 の掃引完全性を validity に入れる

CPU ごとに primary が正確に `PIN_REPEATS` 件、`pin_target` が allocated 集合内、
`reader_cpu_before == reader_cpu_after == pin_target`、CPU ごとに anchor が 1 件、
`pin_order` が allocated 48 CPU の permutation であること。いずれか欠ければ
`INVALID + NOT_EVALUATED`。欠落 CPU の合成 fixture を追加する。

### F-4 (R1-4) 介入成立を証拠から再計算する

busy/sham child の `status` を入力として信用しない。child 証拠 (PID・affinity・liveness・
utime+stime 増分) から**純粋関数**で成立を再計算し、証拠欠測または status との不一致は
当該 pair を `INCONCLUSIVE`、arm 全体としては validity を落とす。証拠欠測 fixture と
status 不一致 fixture を追加する。

### F-5 (R1-5、R2-4) fail-closed の穴を塞ぐ

- parser crosscheck は **保存した raw 3 件すべてが `match`** のときだけ VALID の必要条件を満たす。
  `unavailable` / `error` / 件数不足はすべて `INVALID`。
- `band` を validity 内で検証する。`band=None` や不正 band で未捕捉例外にせず
  `INVALID + NOT_EVALUATED` を返す。
- causal 解析中の例外も必ず `INVALID + NOT_EVALUATED` に落とす。

### F-6 (R1-6、R2-3) 単独性を本物の admission gate にする

- 自 process tree は **PID + start-time (`/proc/<pid>/stat` の starttime)** で束縛し、
  終了した child PID を永久 allowlist にしない (`disallow_child` の結果を判定へ反映する)。
- **`/proc/stat` の未帰属 tick 差分を判定に使う** — 自 tree に帰属できない CPU 時間が
  allocated CPU 上に出たら fail-closed で競合とする (短命 process の見逃し窓を塞ぐ)。
- 競合を検出したらその arm を INVALID にし、**後続 arm を走らせない**。
- 合成 fixture: 短命競合 (snapshot 両端に現れないが tick 差分に出る) と、
  active child 解除後の PID 再利用。

### F-7 (R1-7) 2×3 表の母集団を検査する

pair ごとに sham/busy 各 `CORESIDENT_REPEATS` 件、A3 の block 数と各 `ALPHA_K` 件、
flat reads との同一性を validity で照合する。期待件数 0 や不一致は「誤り 0 件」ではなく `INVALID`。
should-pass の母集団に **A2 の sham 条件 (quiet)** を含める。

### F-8 (R1-9、R2-2) anchor と cooldown を裁定どおりにする

- anchor は**全 instrumentation と介入開始の後**に取得して破棄する
  (A3+A2 は busy child 起動後、A2 は各 sham/busy condition 開始後)。
- A0/A3 quiet も **block ごとに初回を破棄**する。
- A2 は各 child の terminate → wait → liveness 確認の後、**次の condition の前に 1 秒 cooldown**。
  cooldown の実時刻を記録する。

### F-9 (R2-5) 完走の原子的な終端

- `compute_node_marker=false` なら **Python を起動する前に** PBS wrapper が fail-closed で終わる。
- wrapper は create-only の probe log と `probe.rc` を残す。
- **`done` marker は manifest 書き込み成功の後にだけ**発行する。`result.json` は
  provenance と manifest が揃った後に atomic に publish する (temp → rename)。
- `.o/.e` と qstat 会計の receipt 化は**親の作業**なので実装しない。ただし親が後から
  照合できるよう、`manifest.json` に wrapper rc・開始終了時刻・PBS_JOBID を残す。

### F-10 (R2-6) 投入時 binding

t293 の先例に揃え、次を **環境変数で受け取り、最初の outcome read の前に照合**する。
不一致・未設定は fail-closed (rc≠0) とする。

- `EXPECT_HEAD` (親が qsub 時に渡す commit)
- `EXPECT_DRIVER_SHA256` / `EXPECT_PBS_SHA256`
- `EXPECT_CALIBRATION_SHA256` (凍結較正 bytes)
- 関連ファイルが dirty なら拒否する (または exact bytes を成果物へ保存する)。
- `T419_QUEUE` / `T419_PROJECT` は hardcode でなく、渡された値を記録する。

### F-11 (R2-7) child 回収を bounded にする

outer scope の child registry と全出口の finally で回収する。
期限付き `WNOHANG` wait → SIGKILL → 再 wait → 生存確認を記録する。

### F-12 (R2-8) 時間予算

- PBS の `elapstim_req` を **00:20:00** へ引き上げる。
- driver に **hard deadline** (既定 900 秒、CLI で上書き可) を持たせ、超えたら
  measurement を止めて `INVALID` で publish する (無言で walltime kill されない)。
- arm ごとの所要時間を記録する。

### F-13 (親の erratum。実装側の対応)

段 4 の事前登録読み数は 430 と書いたが、arm 一覧には A3+A2 (3 ブロック × K=5 = 15 読み) が
含まれていた。**親が 445 = 430 + 15 として事前登録を訂正する**。実装は
`EXPECTED_PRIMARY_READS` の合計が 445 であることを明示的に assert し、
その定数を manifest に `preregistered_primary_reads: 445` として書け。
