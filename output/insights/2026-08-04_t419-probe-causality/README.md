### 機序の精密化 — 「reader だから」ではなく「busy だから」

A2 は同じ CPU に対し **sleep する子 (sham)** と **spin する子 (busy)** を置き分ける介入である。

| 条件 | 対象 CPU が帯外 | β 通過 | γ 通過 |
|---|---|---|---|
| sham (sleep) | **0/40** | 39/40 | 39/40 |
| busy (spin) | **40/40** | **0/40** | **0/40** |

**同じコアでも、他プロセスが sleep なら帯外にならず、spin させると 40/40 で帯外になる。**
したがって機序は「probe の走行 CPU であること」ではなく「**そのコアがその瞬間 busy であること**」で、
probe の走行 CPU は定義上必ず busy なので必ず帯外に出る。F108 の推定はこれで確定した。

## 方式 α / β / γ の 2×3 判定表 (実測)

`m` = 凍結較正の中央値 2101.0、`t` = 2.0、`B = [2058.98, 2143.02]`、`r` = probe の走行 CPU。

| 方式 | 受理式 | should-pass (静穏) | should-reject (真の逸脱) |
|---|---|---|---|
| **α** 走行 CPU を移しながら K 回読み位置ごと最小 | `∀i. min_k S_k[i] ∈ B` | **9/9 通過、過剰拒否 0** | **未測定** (下記) |
| α から巡回を抜いた形 | 同上 (reader 固定) | **0/24** — 全部を誤って拒否 | 0/11 |
| **β** 走行 CPU の 1 要素を除外 | `∀i≠r. S[i] ∈ B` | 119/120 (過剰拒否 1) | **0/55 = 正しく全拒否** |
| **γ** 帯外 1 個まで許容 | `#{i : S[i] ∉ B} ≤ 1` | 119/120 (過剰拒否 1) | **0/55 = 正しく全拒否** |

**読み取り。**

- **α の「走行 CPU を移しながら」は省略不能。** 巡回を抜くと 0/24 で全滅する — reader が動かない限り
  その CPU は K 回とも帯外で、位置ごと最小が下がらないためである。
- **β と γ は本機体の実データでは区別がつかない** (119/120 と 0/55 で一致)。静穏時は帯外が
  reader の 1 個だけなので両方通り、競合時は帯外が 2 個になるので両方落ちる。
  γ が懸念された「真の逸脱の見逃し」は、**この形の逸脱では起きなかった** (0/55)。
- **β と γ の過剰拒否 1/120 は第三者の一過性バーストによる。** 具体的には
  pin=40 の読みで CPU 25 が 3095.5 MHz へ跳ね、帯外が 2 個になった 1 件である。
  **α はこの読みを含む群でも通った** — 位置ごと最小が一過性を吸収するためで、これが α の実利である。
- **α の should-reject は未測定。** 巡回しながら競合下で読む arm が 445 読みの設計に無い。
  測るには専用 arm (reader を巡回させつつ busy child を置く) が要る。

## 副次診断 — `samples_mhz` はほぼ情報を運んでいない

21,360 標本の **97.6%** が厳密に 2101.0 (較正中央値ちょうど)。残りが「probe が走ったコア」を指す。
つまりこの field が運ぶ情報は実質「どのコアで測ったか」であり、実効クロックの測定ではない。
`cpuinfo_cur_freq` は 48 policy すべて非 root で読めず (EACCES)、
**`/proc/cpuinfo` 以外の独立した周波数源へ替える案は Pegasus では閉じている。**

### 閾値を 2 度動かした経緯 (監査のために明記する)

単独性 gate の閾値は本 wave で 2 度変えた。**因果判定の 3 条件 (0.95 / 0.05 / 46) は
一度も動かしていない** — 変えたのは「実験を有効と認める条件」だけである。

1. **6.7 → 25.0 tick/s** (erratum-4)。erratum-2 で**走行前に**「率の最大値を記録し、
   次の反復では推測でなく実測から引き直す」と事前登録しておいたものを実行した。
   実測 65 subwindow で背景ノイズは中央値 0.00 / 最大 11.86 tick/s、かつ
   **その活動は読み値を汚していなかった** (control 観測 11,280 件中の帯外は 1 件 = 0.0089%、
   率 7.9 tick/s の subwindow が 4 つあっても増えなかった)。A2 の busy child は約 100 tick/s なので、
   25.0 は背景最大の約 2 倍・1 コア占有の約 1/4 で両者を分離する。
2. **abort を signal CPU に限定** (erratum-5)。因果の比較に入らない CPU の一過性負荷で
   実験全体を捨てないため。非 signal の汚染は記録し、統計的な歯止めは既存の
   `nonpinned_out_of_band_rate <= 0.05` が担う (実測 1/11,280)。

いずれも「通すために緩めた」のではない — 変更前の走行 889310 の時点で、A1 の生データは
既に 240/240・1/11,280・48/48 を満たしていた。変更の目的は**特異度 (A2 の should-reject) を
測れるようにすること**である。歯止めとして erratum-5 に「次の走行でも VALID に到達しなければ
親側の解析と gate 設計を裁定へ返して閉じる」と明記したうえで実施した。
