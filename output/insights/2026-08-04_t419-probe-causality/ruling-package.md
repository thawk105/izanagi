## 2. 結論 — 因果は立証も反証もされていない

`execution_validity = INVALID` / `causal_verdict = NOT_EVALUATED` (probe_rc=3)。
実験は fail-closed で A0 の後に停止し、因果の本体である A1 (pin sweep) は走らなかった。

**停止理由は 2 件で、いずれも再実行では解消しない環境事実である。**

| # | 事実 | 影響 |
|---|---|---|
| E-1 | 計算ノードには NQSV 自身の常駐デーモン `nqs_shpd` (uid 0、cgroup `/system.slice/nqs-jsv.service`) が居る。今回は CPU 22 で正の CPU 時間を消費した | 「非自 process の CPU 時間ゼロ」を単独性の必要条件にすると、**計算ノードでは決して満たせない** |
| E-2 | `/sys/.../cpufreq/policyN/cpuinfo_cur_freq` は 48 policy すべてで Permission denied (非 root) | 診断 snapshot が常に incomplete になる。加えて「`/proc/cpuinfo` 以外の独立した周波数源を使う」案は **Pegasus では非 root で閉じている** |

E-1 は親の裁定 G-1 (「非自 PID が正の delta → COMPETITOR」) が、この機体では過剰に厳しいことを意味する。
E-2 は親の裁定 (段 4 の B-11「不在・不可読・値ありを区別する」) が実装で「不可読 = incomplete = 致命」に
なっていたための欠陥であり、裁定側の意図とずれている。

## 3. 予備データ (A0 30 読み、静穏な bnode138、非 pin)

**arm は INVALID なので判定には使わない。** ただし読み値そのものは無傷なので、方式選択の材料として残す。

- 帯外はどの読みでも**ちょうど 1 個**、しかも**毎回 CPU 44**。reader も 30/30 とも CPU 44 だった。
- 帯内値 1410 個は**すべて厳密に 2101.0** (ユニーク値 1 個)。厳密一致率 = 47/48 = 0.979。
- 帯外値は 3061.3〜3096.8 MHz (turbo 域)。
- **常駐デーモンが居た CPU 22 は一度も帯外にならなかった** (sleep 状態の同居は帯外化しない)。

**reader が一度も移動しなかったため、「reader の CPU だから帯外」と「CPU 44 が個体として特別」を
この データでは区別できない。** それを分けるのが A1 の pin sweep であり、走らなかった。
ログインノードでは帯外位置が毎回変わったが、別機体の観測なので因果の分母には入れない。

## 4. 方式 α / β / γ の受理集合 (要素数でなく式と反例で書く)

`S` = 観測 48 要素、`m` = 凍結較正の中央値 (2101.0)、`t` = `tolerance_pct` (2.0)、
`B = [m(1−t/100), m(1+t/100)] = [2058.98, 2143.02]`、`r` = probe の走行 CPU。

| 方式 | 受理式 | 最小反例 | 予備実測 (A0 30 読み) | 変更面 |
|---|---|---|---|---|
| **現行** | `∀i. S[i] ∈ B` | 1 要素でも帯外 | **0/30 通過** | — |
| **α** (走行 CPU を移しながら K 回読み、位置ごと最小) | `∀i. min_{k≤K} S_k[i] ∈ B` | ある CPU が全 K 回帯外 | 本体は未測定。**巡回を抜いた形は 0/6 ブロック** (K=5) | `method` 文字列、schema (K 回分の保持)、取得手続き (巡回)、凍結較正の再取得、pin |
| **β** (走行 CPU の 1 要素除外) | `∀i≠r. S[i] ∈ B` | `r` 以外に帯外が 1 個 | 30/30 通過 | 述語、schema (`r` の記録)、凍結較正、pin |
| **γ** (帯外 1 個許容) | `#{i : S[i] ∉ B} ≤ 1` | 帯外が 2 個 | 30/30 通過 | 述語のみ (最小)、凍結較正、pin |

**α の「走行 CPU を移しながら」は省略できない。** 裁定原文の α は
「走行 CPU を移しながら K 回読み論理 CPU ごとに最小値を採る」であり、巡回は最初から含まれている。
予備実測が 0/6 で落ちたのは**巡回を抜いた形**であり、これは α の否定ではなく
**巡回部分が load-bearing である**ことの証拠である。α 本体は A1 が走っていないため未測定。
なお α は本番 probe の取得手続き (走行 CPU を移す) を変えるため、変更面は述語だけに閉じない。

**β と γ の「通った」は成功を意味しない。** 静穏なノードで通ることは感度 (should-pass) を示すだけで、
**真の環境逸脱を拒否できるか (specificity, should-reject) は未測定**である。それを測るのが A2
(意図的な busy 同居) で、走らなかった。γ は「帯外 1 個」を無条件に許すため、**真に劣化した環境の
1 コアを見逃す**構造を持つ (規律 2 の観点では最も弱い)。

## 5. 追加で分かった、選択肢の空間を変える事実

- **`samples_mhz` は実効クロックをほぼ測っていない。** 47/48 が定数 2101.0 で、残る 1 個が
  「probe が走ったコア」を指す。**この field が運んでいる情報は実質「どのコアで測ったか」1 点**である。
  α を採ると全要素が 2101.0 の定数ベクトルへ収束し、field は情報量ゼロになる。
- **独立した周波数源 (δ) は非 root では使えない** (E-2)。`scaling_cur_freq` は要求 P-state であって
  実測値ではない。「別の測り方に替える」案は Pegasus では現実的でない。
