## 課題
`tools=[]` + JSON schema では 2 脅威を止められない。
- 脅威 α (coder injection): hole 内 1 行の C++ (`std::system`/`std::ofstream`/無限ループ等) が build/run される。
- 脅威 β (auditor echo): auditor が実 diff の digest を計算し verdict="pass"+violations=[] を返すと
  auditor_gate.py の全検査を通る (fail-open by construction)。

3 案を file:line 粒度で設計せよ。
- (i) coder 出力を「許可識別子・enum・論理演算だけの boolean-expression AST/DSL」へ落とす。
- (ii) build/run を credentialless・network 無し sandbox へ置く。
- (iii) 両方。

## 各案について必ず出すこと
1. **設置点 (seam)**: どのファイルのどの関数/行に gate が載るか。(i) は coder→diff→build のどこで
   AST を強制するか、DSL を C++ へ展開する compiler をどこに置くか。(ii) は build/run のどの呼び出し
   (buildcache.build / build_v2 / pipeline.evaluate / loop.run_campaign) を sandbox で包むか。
2. **脅威被覆**: α と β をそれぞれ「消す/絞る/塞がない」で判定し、根拠を file:line で示す。
3. **三軸適合 (最重要)**: backoff (スカラー値)・sort-strategy (comparator コード片)・
   trigger-gating (5-bit wire) の各軸に対し、その案が Phase3 の合成能力実証 (D39: coder が値/コードを
   自力合成する) をどう変えるか。特に (i) が sort 軸で「合成 → 事前 allowlist 選択」に化けるという
   D127 決定(1) の主張の真偽を、coder.md の契約と source_digest.py の hole 定義から検証せよ。
4. **コスト**: (i) は新軸ごとに文法追加が要るか (段8a onboarding との関係)。(ii) は計算ノードでの
   backend 実在に依存する (DW-G04)。docs 予算 ([T-664] で逼迫) への影響。
5. **残余の開いた境界**: その案を入れても塞がらない穴 (D127 決定(5) の cache class 束縛、
   in-process issuer、reward hack=規律2 本体 との区別)。

## 横断論点
- 脅威 β (auditor echo) は (i)/(ii) のどちらで「非 load-bearing 化」できるか。auditor の verdict を
  security credit から外す設計 (D127 決定(6) の advisory 化) との関係を述べよ。
- 「(iii) 両方」の正しい解釈: 全軸一律に (i)+(ii) か、それとも (ii) を全軸の security boundary とし
  (i) を scalar/wire 軸に限定する非対称構成か。coder.md の契約から論証せよ。
