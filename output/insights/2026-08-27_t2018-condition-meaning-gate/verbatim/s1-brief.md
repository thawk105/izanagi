# [T-2018] 段 1 brief — 要求した測定条件が実行側で要求どおりの意味を持つかの関門

## scope

**族の射程を経路 2 (define-decode) に置く。** 供給値をソース内の式が復号して条件にする経路のみ。
経路 1 (hole-literal、`p3_s4_loop.py`) は既に数値一致の機械照合があるので射程外。
対象 define は実測 3 の表の 9 個 (量 1・wire 1・enum 5・診断 0/1 2)。

**成果物は 3 つ。** (a) 族の射程表、(b) 関門の設計、(c) F707 と F718 を負例 fixture として
固定できる形の実証。実装するのは driver 非依存の関門 module と負例 fixture までとし、
**driver 群への義務化は行わない** ([T-1999] がユーザー裁定待ちのため)。設計上の接続だけ書く。

## 確定済みユーザー裁定と、その前提の実測

- [T-1999] (patch 供給 define を渡す driver 全体への正例検査の義務化) は**裁定待ち**。本 wave は実施しない。
- D955 — 証明の種別は届いた範囲そのもので命名する。関門の名前を実態より強くしない。
- D706 — 述語採用前に到達可能な値域を実測する。実測 1 で実施済み。
- D23 道 Y / D34 — 条件指令の供給集合を実 TU 供給集合へ揃える既存機構がある。再実装しない。

## 不変条件 (破ってはいけない)

1. **規律 2。** 関門は「宣言した文字列が実体に在る」で止めない。実測 1 が示すとおり、
   実 compiler で復号を評価する層を持つ。恒真な保証を名前で謳わない。
2. **凍結 bytes へ触らない。** `EXTENDED_SWEEP_US` (実測 2)、`patches/silo-backoff-fixed.patch`、
   `patches/ledger.json` は本 wave では変更しない。変更は裁定パッケージへ返す。
3. **repo 内の変異軸ソースを実装子に書かせない。** 関門は既存 patch を読むだけで、当てない。
4. **probe を repo の外で回した事実は残すが、成果物の関門は repo 内に置く。**

## 親の provisional 裁定 (攻撃対象。段 3 はここを狙え)

- **(P1)** 関門は 3 腕にする。A1 = 合成枝が適用後ソースに実在する (F707 を捕らえる)、
  A2 = 当該 define が実 build の供給集合に在る、A3 = 実 compiler で復号を評価し、
  宣言した意図と一致し、かつ格子内で単射である (F718 を捕らえる)。
- **(P2)** A3 の評価対象は patch bytes ではなく**適用後の worktree source**から抜く。
  patch を正としたら「当て方の誤り」を見逃す (F707 の恒久対応の但し書きと同じ理由)。
- **(P3)** 実現条件はスカラーでなく**集合**として扱う (実測 1 の v=1500 / v=2500)。
  宣言側は「決定的スカラー」か「集合」かを明示する。
- **(P4)** 宣言が無い driver には単射性だけを課す。単射性は一様な誤り (全点が µs でなく ns と
  解釈される等) を捕らえないので、**そう明記して名前に書く** (D955)。
- **(P5)** 本 wave は module と fixture までとし、driver への配線は 0 本。
- **(P6)** 符号化そのものの修正 (商/剰余) と格子定数の修正は**裁定パッケージ**へ返す。
  実測 1 で「上端を 999 にする」だけでは閉じないことが分かったので、択一は 2 案ではない。

## 成果物影響 (DW-G05)

- (a) 射程を書かない場合: 次に define を足す patch が同じ穴を再現し、どの driver が対象かを
  毎回一から数え直す。
- (b) 関門が無い場合: `EXTENDED_SWEEP_US` は 1000 を持ったまま main に在るので、
  この driver を次に走らせた campaign の「機序 profile」レポートに 0 µs の反復が
  1000 µs 点として記録される (F718 と同じ値・同じ場所)。
- (c) 負例 fixture が無い場合: 関門を後から緩めても赤にならない。
- (P6) を実装しない場合: 汚染点は格子に残り続けるが、(b) の関門が投入前に止める。
