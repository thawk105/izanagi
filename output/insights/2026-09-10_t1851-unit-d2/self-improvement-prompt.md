# dev-wave 自己改善用プロンプト — 復旧可能な検査赤で依頼全体を止めない

対象: docs/dev-wave/operations.md DW-O20 と docs/dev-wave/core.md DW-STOP の既存文言。
今回の実測: T-1851 D2 の継承 branch が main 137 commit を含まないため check_wave_startup.py --mode resume が rc=1。
checker 自身は main を取り込み clean にして再検査する復旧手順を示していた。
ユーザーは最初から継承 branch での D2 完成と main 統合を依頼しており、復旧のための merge は認可範囲内だった。
親は「非0で停止」を作業全体の終了と誤読してユーザーへ返し、ユーザーが継続を再指示する手間を生じさせた。

改善要求:
- 「停止」は、その検査を通過したことにして依存する後続段へ進まない意味と、作業全体を終了する意味を分ける。
- 既に依頼された範囲内の、原因を理解した復旧可能な状態不整合は自律的に修復し、同じ検査を再実行して継続する。
- main 未包含、通常の merge 競合、未初期化 submodule 等について、既存の復旧手順と D95 author 境界を使う。
- 所有不整合は勝手に解消せず、他 session の成果を保全する。権限拡大・検査弱体化・rebase/force・凍結改変で赤を隠さない。
- 新しいユーザー判断が実際に必要なときだけ具体的な差分・原因・必要判断を返す。認可済みの復旧を再承認待ちへ戻さない。
- 実装は既存 reference の最小文言修正だけとし、新しい gate・checker・台帳・一般化を作らない。
- 既存の赤処理、main 取込み、Codex author、独立レビュー、受入、provenance 契約を保ち、重複した手順を増やさない。

この wave では改善候補と本プロンプトを記録するだけ。本題の D2 と一括 land を優先し、改善実装や次 wave 起動は追加しない。
