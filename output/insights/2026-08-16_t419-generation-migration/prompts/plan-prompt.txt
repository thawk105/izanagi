## 本 wave が何をするか (親の実測結果)

pegasus 実行環境契約を g1 から g2 へ **活性化 (activate)** する。世代機構そのものは実装済みで、
未実施なのは活性化の実行と、それに追随して壊れる面の手当てである。

親が本 worktree で実測した確定事実 (brief に詳細):

- 活性化 record は `orchestrator/campaign/env_contract_activations/00000001.json` の serial=1、
  pegasus は g1 (`e576e9cd…`) が active。
- g2 (`1346c20b…`、較正 `calibration-94a4b79fa31bba3c.json`) は `GENERATIONS` に登録済み・
  `quality.status=accepted`・canonical clock 述語を自己充足 (帯外標本 0 件)。
  g1 は帯外 1 件 (3080.935) で自己不整合。
- 親が一時変異で serial=2 record (`activation_state_sha256 =
  398b192013e0e3996ca225454049a14cb2866ef256b581fc3dfbfda02476bed8`) を置き、
  `orchestrator/campaign/env_contract.py` の `_ACTIVATION_HEAD_SERIAL` と
  `_ACTIVATION_HEAD_STATE_SHA256` を進めたところ、`authorize("pegasus")` は g2 を返し
  `ever_active_contract_sha256s` は g1 を保持した。**record bytes は canonical JSON + 末尾 LF 必須。**
- 同じ一時変異下で、凍結済み `output/s8b-freeze/floor_protocol.json` (記録 hash = g1) は
  `s8b_floor_campaign.validate_protocol` (歴史検証) が **OK**、
  `s8b_floor_campaign.validate_protocol_against_current` (live admission) が
  **「protocol.contract_sha256 と resolver が返した env 契約が不一致」で拒否**した。
