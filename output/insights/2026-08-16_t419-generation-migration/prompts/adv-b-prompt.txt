## レンズ B の攻撃面 — 凍結 chain の生存と移行の到達可能性

1. **consumer の取り残しを探せ。** g1 期に凍結された成果物を読む経路を洗い出し、
   g2 活性化後に検証不能になるものが無いかを file:line で示せ。起点 (網羅ではない):
   `output/s8b-freeze/` 配下、`output/env/pegasus/silo_ladder_rung1/`、
   `orchestrator/campaign/s8b_ratified_freeze.py`、`s8b_oracle_report.py`、
   `s8b_selector_freeze.py`、`s8b_holdout_freeze.py`、`wal.py`、`reflux_source_closure.py`、
   `silo_ladder_rung1.py`、`floor_liveness.py`、`between_run_floor.py`、
   `autonomous_trial_completeness.py`、`orchestrator/qualification/`。
   **「path 検索で 0 件だから pin なし」と結論してはならない** — role 名・key 名でも探せ。

2. **移行の到達可能性 (循環) を検査せよ。** 親は (P1) で
   「live admission が g1 期 floor protocol を拒否するのは正しい縮小であり、
   通す道は床値 v2 の再測定だけ」と裁定している。これに対し:
   - 床値 v2 を測るために **g2 の下で floor campaign を起動する経路** が実在するか。
     起動時に `validate_protocol_against_current` を通る必要があるなら、
     g2 期の protocol を **最初に作る**経路が存在するかを実装で確かめよ。
     存在しないなら移行は自分自身を詰ませる (デッドロック) real 所見である。
   - `certified_writer_admission.py` の floor 投入 admission、
     `tools/pegasus/floor_campaign.sh`、その wrapper preflight を読み、
     どこで詰まるかを具体的に述べよ。

2b. **順序の争点に判定を下せ (最重要)。**
   段 2 プラン §6 P1 / §7 は「versioned protocol path/hash seam を **活性化より先に**」と主張する。
   親の対案は「活性化を先にせよ。移行前は壁 1 (F97 / D143) により Pegasus 計算ノードの campaign が
   全面的に落ちるので、活性化は厳密に改善であり、seam は後続段の最初の仕事でよい」である。
   **どちらが正しいかを実装の証拠で判定せよ。** 判定に要る具体的な問:
   - 活性化を先に行った場合、**後から** seam を作って g2 protocol を発行することは可能か。
     不可能にする機構 (create-only の不可逆性、FROZEN_MANIFEST、承認定数の凍結、
     `test_frozen_artifacts.py` の bytes pin) があるなら、それが「後戻りできない」型かを述べよ。
   - seam を先に作る場合、その seam は **g1 が active のまま**テストできるか。
     できないなら「先に作れ」は実行不能な助言である。
   - 中間状態 (活性化済み・seam 未実装) で main に land した場合、
     **他の wave や既存の受入全走が壊れるか**を判定せよ。
     壊れるなら件数と file:line を示せ。

3. **不可逆性を検査せよ。** 活性化 record は create-only で hard-link no-replace である。
